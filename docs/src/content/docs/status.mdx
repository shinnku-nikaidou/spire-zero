## 2. 主要缺口与风险

1. **CombatBuilder 的近似**。回合历史、内部计数器、费用修改的持续时间、眩晕后续动作都是近似的，而且从没用真实游戏的观测验证过（[模拟器 §3](/arch/simulator/#sec-3)）。
2. **怪物动作重采样**目前在「显示相同意图」的动作里均匀选取，需要改成根据怪物历史得到的后验（[Harness §3](/arch/harness/#sec-3)）。
3. **选牌提示缺少上下文**：策略不知道游戏为什么要它选牌。解决办法：`ChoiceContext`（[协议 §4](/arch/protocol/#sec-4)、[GameBridge §5](/arch/gamebridge/#sec-5)）。
4. **开局用的是 `UnlockState.all`**，不是用户自己的存档进度；进阶等级也没有限制在角色允许的最大值以内（[模拟器 §5.1](/arch/simulator/#sec-5.1)）。
5. **新增的游戏代码如果在事件之外（事件由 transpiler 覆盖）调用 Godot 节点**而没有 TestMode 保护，只会在 `run` 批量运行里以游戏错误的形式暴露出来（[模拟器 §5.2](/arch/simulator/#sec-5.2)）。
6. **真实游戏里的 Harmony 补丁与分层 JIT**：运行时可能重新编译某个方法，悄悄丢掉补丁（[Mod §10](/arch/mod/#sec-10)）。
