**宏觀大腦**負責戰鬥之外的所有決策：下一個去哪個地圖點、領取哪些獎勵、拿哪張牌、買什麼、在事件、休息處或財寶房裡選哪個選項。它和[戰鬥大腦](/zh-tw/arch/combat-brain/)一起執行在決策行程裡。Harness 把所有非戰鬥的決策介面都交給它（[Harness §4](/zh-tw/arch/harness/#sec-4)），並從 worker 池給它提供世界，所以它可以先在真實的遊戲程式碼裡把每個選項試一遍，再做選擇。所有選項都用同一個尺度評分：估計的整局勝率。

<Aside title="狀態">

L0 v0 已經實作：Brain 裡的 `MacroBrain`，用 `run --macro l0` 來跑（[模擬器 §5](/zh-tw/arch/simulator/#sec-5)）。它回答所有宏觀決策介面和戰鬥外的選牌提示，用 V 給選項估值：V v0，或網路檔案裡的 V v2 或純 V（[學習 §1](/zh-tw/arch/learning/#sec-1)）。加上 `--macro-explore T` 時，它改為按同樣的估值、以 softmax 溫度 T 抽取每個答案，供自我對弈用（[學習 §5](/zh-tw/arch/learning/#sec-5)）。加上 `--card-explore P` 時，它把 P 比例的卡牌獎勵的結果改為均勻抽取。NoSL 下對局世界還不存在（[模擬器 §6](/zh-tw/arch/simulator/#sec-6)），所以它根據介面上顯示的內容預測每個後狀態，而不是在世界裡把選項執行一遍（[§2](#sec-2) 的 L0 v0）。SL 下加上 `--afterstates clone` 時，它在節點複本上把每個選項真的打一遍，並在節點的各個畫面裡繼續往下搜尋（[§2](#sec-2) 的「L0 在複本上」）。規劃中：NoSL 下從對局世界得到後狀態和多步介面的搜尋、L1，以及 [§4](#sec-4) 的 `IMacroBrain` 介面。

</Aside>

## 1. 決策介面與特點

宏觀大腦處理的決策介面（surface）如下。「選擇後的隨機性」指選定之後才揭示的隨機結果；「影響範圍」指這個選擇的後果能延續多遠（「整局」指本局剩下的全部）。

| 決策介面 | 選項數 | 選擇後的隨機性 | 影響範圍 |
|---|---|---|---|
| 地圖（下一個點） | 1–4 | `?` 擲骰、遭遇、獎勵 | 本幕剩餘部分 |
| 獎勵（領取順序 / 跳過） | ≤6 | 無（金幣、藥水、遺物都已顯示） | 整局 |
| 卡牌獎勵 | 3–4 + 略過/重骰 | 重骰結果 | 整局 |
| 牌組提示：升級 / 刪除 / 附魔 | 牌組大小 | 無 | 整局 |
| 轉化（transform） | 牌組大小 | 變出的牌 | 整局 |
| 選一張牌 / 卡包（bundle） | ≤3 | 無 | 整局 |
| 事件 / Ancient 選項 | 1–4 | 事件結果、下一頁 | 整局 |
| 商店 | 貨品 + 刪牌服務 + 離開 | 無（貨品可見） | 整局 |
| 休息處 | 休息/鍛造（smith）/鍛鍊（lift）/挖掘（dig）/… | 挖掘等 | 整局 |
| 財寶房 | 選遺物/跳過 | 無 | 整局 |
| 藥水欄滿 | 丟棄/使用/跳過 | 無 | 短 |

這些介面的共同點：選項少、影響遠、執行成本低、難以估值。一個戰鬥回合可能有上千種動作序列；這裡只有幾個選項，每個都能在模擬世界裡以幾乎為零的成本試一遍。難的是，一個選擇的效果要過很多層才顯現出來。選項的價值永遠是整局勝率 P(win run)（定義見[學習](/zh-tw/arch/learning/)頁），絕不是用生命值或分數拼出來的塑形分數。

## 2. 方法

分兩級。L0 每次決策都執行；L1 是給難分高下的選擇加的複核。

### L0：後狀態 + V

L0 是預設方法，每次決策都執行。**後狀態**（afterstate）指一個選項剛執行完、還沒有發生任何新事情時的局面。給後狀態評分，意味著只要一個讀取單個觀測的價值函式 V，就能給所有決策介面上的所有選項評分：不需要為每個（狀態，選項）組合單獨估值，而在世界裡執行一個選項的成本又很低。

對每個選項 a，大腦在一個世界裡執行它並觀測結果。這個觀測就是後狀態 `s'_a`，它的價值是 `V(s'_a)`。

- **隨機的後狀態**（轉化、事件結果、重骰）：NoSL 取 K 個取樣世界上的平均值；SL 透過節點複本，直接用唯一的真實結果。
- 選價值最高的選項（argmax）。成本：選項數乘以（執行 + 觀測 + V），遠低於 1 秒。
- **多步介面**（商店：買幾樣再離開；獎勵：領取好幾項；事件的多頁）：像戰鬥大腦搜尋一個回合內的動作那樣，對這個介面的動作序列做深度優先搜尋（[戰鬥大腦 §2](/zh-tw/arch/combat-brain/#sec-2)）。葉節點估值是離開介面時的 V。到達相同觀測的序列只展開一次（按觀測去重）。

### L1：推演複核

L1 處理難分高下的選擇，使用評估時的預算。當 L0 排名前兩位的價值落在信賴區間之內（CI：根據目前的樣本，真實值大機率所在的範圍），L0 分不出誰更好，這時 L1 啟動。**推演**（rollout）就是用快速策略把遊戲往後模擬，看一個選項會把局面帶到哪裡。

對每個候選：

1. 從它的後狀態出發，在取樣的整局世界裡推演（[模擬器 §6](/zh-tw/arch/simulator/#sec-6)）。
2. 用快速策略往後走 H 個節點（預設：走到下一個頭目）：戰鬥用推演策略或淺層搜尋，宏觀決策用 L0。
3. 用**公共亂數**（CRN）給候選配對：每個候選都在同一組世界種子裡推演，遇到的運氣都一樣，所以它們之間的差值比各自獨立取樣時雜訊小得多。
4. 候選的價值是視野邊界處 V 的平均值；如果這一局先結束了，就用最終結果。
5. 按配對差值及其 CI 做選擇。

兩條路線都記入日誌供學習使用：這些反事實的配對推演，就是 V 在關鍵決策上的訓練訊號。

在 SL 中，越過當前節點的推演仍然使用取樣世界（[環境 §4](/zh-tw/arch/environments/#sec-4)）。

### 地圖

- 只決定下一個點；每走一步都重新決策。
- L0 的後狀態是到達所選地點、房間開始之前的觀測：房間型別已知，`?` 仍然未知。所以 V 必須同時評估當前位置和從這裡還能走到的地圖。早期的 V 做不到這一點，所以基線估值器要加上**路徑特徵**：對通往頭目的最佳 k 條路徑，統計菁英、休息處、商店、`?`、普通怪物各有幾個，再估計本幕的生命值預算。
- 難分高下時，同樣用上面的 L1 推演。

### L0 v0

在對局世界出現之前，`MacroBrain` 只根據介面上顯示的內容預測每個後狀態，不跑遊戲程式碼，然後選 V 最高的選項；打平時取第一個合法動作。

- **地圖**：把這個點加進路徑。V 的地圖特徵從這裡算起：如果之後每一步都隨機走，到頭目之前預計會遇到幾個菁英、休息處、商店、財寶房和 `?`（還不是上面說的最佳 k 條路徑特徵）。它的計畫是本幕剩下的路線：沿著地圖上的路徑，假設別的都不變，它在之後每一步會選哪個點，一直到頭目；Mod 會把它畫出來（[Mod §3](/zh-tw/arch/mod/#sec-3)）。用 V v0 時，它之後會一直按這條路線走：一次地圖決策的各個選項只在地圖特徵上不同，而只有位置會改變它們。
- **獎勵、選卡獎勵、卡包、財寶房、商店購買**：加上金幣、藥水、遺物或牌，並扣掉價格。
- **會開啟一次選擇的選項**（選卡獎勵、刪牌、鍛造）按其中最好的那一選估值，只在遊戲會提供的選項裡選（永恆（Eternal）牌刪不掉），所以一個開啟後會被跳過的選擇不會被開啟。選卡獎勵的牌列在獎勵畫面上：這些牌在介面出現之前就已經擲好，開啟看一眼也沒有任何代價（[協定 §3](/zh-tw/arch/protocol/#sec-3)）。
- **休息處**：選項上顯示的回復量；鍛造按其中最好的那次升級估值，和隨後的升級提示一樣。
- **事件**：選項給的遺物，或者按鈕警告會致死時記為死亡。其他選項一律當作沒有變化。
- **選牌提示**：貪心，每次加一選，只要 V 還在上升（或者提示還要求更多）。刪牌和轉化把這張牌拿掉，升級換上它的升級預覽（`CardView.upgraded`，[協定 §1](/zh-tw/arch/protocol/#sec-1)），帶著升級後的數值和費用，選一張牌就把它加進牌組。由 L0 自己的回答開啟的提示（鍛造、刪牌）至少要選估值時用的那一張：停下並不會讓局面保持不變，而是取消回到開啟它的介面，同樣的回答又會出現。篝火必須使用，於是一直迴圈到這一局被截斷：n2-b0.03 的門檻裡出現過兩次，當時的 V 認為什麼都不變比回血和任何升級都好。

它看不到的：事件選項的代價和收益不以資料形式出現在介面上，所以一個代價很高的選項會和離開打平，排在前面時就會被選中（事件 Tablet of Truth 每次破譯都要扣最大生命值，一直扣到 1）；遺物除了「多一件遺物」之外的效果；轉化會變出什麼。在對局世界裡執行選項，這三點都能解決。

在 `promotion-1`（200 局，Silent A0）上，無論戰鬥用哪個策略，L0 都勝過隨機的局外決策：戰鬥用 PIMC 時，平均層數 19.34、打到第 1 幕頭目 177 局（戰鬥內選牌提示交給 `p0`），對 13.68 層、73 局（選牌提示仍是隨機的）；用佔位策略 `play` 時，11.90 對 8.09，60 對 5（[戰鬥大腦 §7.2](/zh-tw/arch/combat-brain/#sec-7.2)）。它略過的卡牌獎勵更少（戰鬥用 PIMC 時 43% 對 58%），打的菁英也更少（每局 0.30 場對 0.94 場）。

### L0 在複本上（SL）

SL 下加上 `--afterstates clone`（配 `--macro l0`）時，Harness 在每個宏觀決策和每個戰鬥外的選牌提示處把節點複本交給 L0（[Harness §3](/zh-tw/arch/harness/#sec-3)），L0 就在真實遊戲裡把選項打出來，而不是去預測（`CloneSearch`，提交 `952cb04`）：

- **後狀態**：每個選項都在複本上打一遍，遊戲接著問的東西就是它的後狀態，由 V 估值。只有地圖上的移動仍像 L0 v0 那樣預測：移動就是離開節點，複本不能越過這一步。
- **在節點的畫面裡往下搜尋**：只要後狀態還是這個節點裡的畫面（不是地圖、戰鬥或對局結束），搜尋就在這個畫面自己的動作上繼續（藥水的動作除外）：逐層進行，束裡保留 V 估值最高的 16 個狀態，總共最多試探 1,024 次。到達兩次的狀態（按後狀態的雜湊）只搜尋一次。一個狀態的價值是它後面最好的狀態的價值，搜尋停下的地方就用 V 的估值；一個選項的價值就是它的後狀態的價值。所以商店裡的幾次購買、獎勵畫面上的幾次領取、事件的幾頁，都作為序列來搜尋，正如上面的多步介面所說。
- **選牌提示**：複本上的提示用局部搜尋回答：從不選（或它最少要選的張數）開始，每一步試一試只差一張的答案（多一張、少一張、換一張），每個都像上面那樣往下搜尋，只要比現有答案好就換成最好的那個。玩家分辨不出的牌算作同一張。需要選兩張或更多的提示，不從打開它的畫面往裡搜尋：由它自己的決策去搜尋。
- **試探**在 worker 行程池裡執行，每次都是載入複本、重播它的答案路徑（[模擬器 §8](/zh-tw/arch/simulator/#sec-8)）。

冠軍名字裡寫 `l0 NAME clone`，冠軍檔案裡寫 `"afterstates": "clone"`。NoSL 和 `--afterstates screen` 的打法不變（兩種環境下 4 個種子打出同樣的對局）。檢查：`run --check` 走傳輸協定時打得一樣，每個節點都完全一致地重播，沒有遊戲錯誤（戰鬥用 `play` 的 17 局，用 SL 規劃器和 c2 的 2 局）。用 SL 規劃器時，一個宏觀決策平均 40 ms（中位數 13 ms，最多 0.5 s），兩局共 187 s 裡佔 9 s。

## 3. NoSL 與 SL

兩種環境共用一個宏觀大腦和一個價值函式 V，只是結果的來源不同。

| | NoSL | SL |
|---|---|---|
| 節點內的隨機結果（事件結果、轉化、重骰、已經擲過的 `?`） | K 個樣本 | 確切結果（節點複本） |
| 節點內隨戰鬥打法變化的獎勵 | — | 已知（未決問題 1，[環境 §10](/zh-tw/arch/environments/#sec-10)） |
| 節點之外 | 取樣世界 | 取樣世界 |
| 價值函式 | V | 同一個 V |

Neow 等 Ancient 事件的選項：對隨機選項，SL 能看到確切結果，例如「隨機稀有卡」選項具體會給哪張牌（[環境 §1](/zh-tw/arch/environments/#sec-1)）。

理論上 SL 也會改變戰鬥之外的價值：從同一個狀態出發，SL 贏得更多，因為它在之後每個節點都打得更好，所以專為 SL 做的價值函式會更願意冒險（多打菁英、多選結果波動大的事件）。這一點被忽略：V 是共用的，在 SL 裡會偏保守（[環境 §5](/zh-tw/arch/environments/#sec-5)）。

## 4. 介面

規劃中的 C# 介面。所有非戰鬥決策介面共用一個入口；Harness 按決策介面名稱分派（[Harness §4](/zh-tw/arch/harness/#sec-4)）。

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness §4).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims), or of the act's route on the map
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` 是現在就要執行的動作，`Plan` 是這個介面剩下的步驟（在地圖上是本幕剩下的路線），`Candidates` 是每個可能的第一步的價值、CI 和樣本數，`Facts` 是用來解釋這個選擇的事實。

- 戰鬥外的選牌提示（升級 / 轉化 / 刪除）和戰鬥內的一樣，都經由 `card_choice` 決策介面到來；`ChoiceContext.Purpose` 說明這個提示的用途。Harness 按「是否在戰鬥中」分派。
- 推演裡使用的宏觀策略是 K 更小的 L0，它不會再遞迴呼叫 L1。

## 5. 預算

各模式能用多少搜尋：

- **自我對弈**：固定的分支數（模擬的打法路線數），保證可重現。L0 總是執行；L1 只在抽樣出來的一部分難分高下的選擇上執行，以控制成本。這些 L1 結果會成為訓練資料。
- **輔助模式**：L0 立即給出答案；玩家檢視的同時，L1 繼續細化。搜尋是*隨時可停*（anytime）的：任何時刻停下，都能給出目前最好的答案。
- **自動遊玩（R4）**：L0 + L1，有掛鐘時間上限。

## 6. 測試

1. 覆蓋：模擬對局能到達每一個宏觀決策介面，後備次數為 0。
2. 決策測試集（decision panel）：一組固定的（局面，選項）題目，標準答案來自大規模配對推演。按決策介面統計 L0 與標準答案的一致率，由此看出 V 在哪裡最弱。
3. NoSL 反事實：公開記錄相同、隱藏狀態不同（`RoomSet` 尾部、機率計數、亂數流）→ 決策相同。
4. 在固定預算下結果確定。

## 7. 未決問題

1. L1 的視野 H（到下一個頭目還是到下一幕），以及推演用的戰鬥策略需要多強。測量它們與整局結果的相關性。
2. 把商店當作一次決策還是一串決策（可能的購買組合數量隨選項組合式增長）。
3. V 自己能學會多少路徑規劃，與顯式的路徑特徵相比如何。
