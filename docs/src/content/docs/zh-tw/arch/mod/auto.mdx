輔助模式顯示大腦的答案，把每一次點選都留給玩家。另外還規劃了兩種模式：**自動遊玩**，由 Mod 自己打出答案；以及**半自動**，玩家按一個鍵時，它打出下一步。真實遊戲要靠自動遊玩來評估：模擬到實機階梯的最後一級 R4，就是在真實遊戲裡用和模擬器相同的種子跑完整局（[評估 §1](/zh-tw/arch/evaluation/#sec-1)）。本頁先描述規劃中的部分，再說明目前已經實作、而且成立的東西：日誌、安全規則、補丁和測試。

§1–§2 都還沒有實作：沒有執行器、沒有轉接器、沒有自動跑局驅動程式，除了 F8 也沒有別的按鍵。

## 1. 執行轉接器 <Badge text="規劃中" variant="caution" />

轉接器把一個決策介面的動作連到畫面上的 Godot 節點。GameBridge 從不碰 Godot 節點（[GameBridge §2](/zh-tw/arch/gamebridge/#sec-2)），所以這部分節點端的工作放在 Mod 裡。一個介面就能同時服務規劃中的標示和自動遊玩：標示問一個動作在畫面上的哪裡，自動遊玩則請轉接器去執行它。

```csharp
// One adapter per surface; highlight and auto-play share the action → node mapping.
interface ISurfaceAdapter
{
    string Surface { get; }
    bool Matches();                       // current screen/room is this surface
    Control? AnchorFor(string action);    // node to highlight; null = panel only
    bool Execute(string action);          // same entry point a human click reaches
}
```

`Execute` 在各類決策介面上會呼叫什麼：

| 決策介面 | `Execute` |
|---|---|
| 戰鬥 | `CombatActions.Start`（GameBridge）；只在 `CanTurnBeEnded` 時結束回合 |
| 按鈕 | 按鈕的處理函式，但要先檢查 `IsEnabled && IsVisibleInTree()`。`ForceClick` 兩者都不檢查 <Badge text="已核實" variant="success" /> |
| 商店 | `entry.OnTryPurchaseWrapper(inv)`。對商人節點呼叫 `ForceClick` 沒有任何效果 |
| 地圖 | `NMapScreen.OnMapPointSelectedLocally(point)` |
| 選牌提示 | 點選卡牌槽，再按確認。走這條 UI 路徑，`PlayerChoice` 會留在重播記錄裡（[GameBridge：各決策介面的動作 §7](/zh-tw/arch/gamebridge/actions/#sec-7)） |

要打的一步是推薦的 `action`；它的 `plan` 是之後的部分（[協定：線路 §7](/zh-tw/arch/protocol/wire/#sec-7)）。`Execute` 之後，Mod 會期待觀測的鍵在超時之內改變（遊戲速度為 Fast 時 10 秒，Instant 時 3 秒）；如果沒有改變，就重新觀測，連續失敗 3 次就暫停並記入日誌。如果沒有轉接器匹配，或者畫面空閒卻沒有合法動作，自動遊玩會暫停，面板會顯示「manual needed」（需要手動操作），Mod 會把它作為覆蓋率 bug 記入日誌：絕不執行隨機動作。

目前標記是自己找到它們的節點（`CombatMark`、`MapMark`），不經過轉接器（[輸出 §3](/zh-tw/arch/output/#sec-3)）。每個決策介面上 Mod 的路徑和模擬器的路徑，在 [GameBridge：各決策介面的動作](/zh-tw/arch/gamebridge/actions/)裡並排列出。

## 2. 自動跑局驅動程式 <Badge text="規劃中" variant="caution" />

驅動程式會在真實遊戲裡自己跑完整局，用於 R4。

- **按種子開局**：`NGame.StartNewSingleplayerRun(character, shouldSave: false, acts, modifiers, seed, GameMode.Standard, ascensionLevel)`（`Nodes/NGame.cs:1137`），幕的選擇與大廳會做的相同（[模擬器：整局 §2](/zh-tw/arch/simulator/runs/#sec-2)）。另一種做法是在按下確認（Confirm）按鈕之前設定 `NGame.DebugSeedOverride`，就像遊戲自己的 AutoSlayer 那樣（`AutoSlay/AutoSlayer.cs:501`）。用 `shouldSave: false` 時，`current_run.save` 不會被動到，參數的說明文件就是這麼寫的（`NGame.cs:1130`） <Badge text="已核實" variant="success" />。對局歷史和進度大概仍會寫入 <Badge text="推斷" variant="caution" />，所以自動跑局只會使用帶 Mod 的玩家檔案。
- **一局結束**：偵測到死亡（所有玩家都死了）或勝利；傳送 `run_end`；回到主選單；從預先登記的清單裡取下一個種子。
- **速度**：只在自動跑局進行期間把 `PrefsSave.FastMode` 設為 Instant（`Saves/PrefsSave.cs:21`）。有兩個遊戲行為要注意：編輯器以外的建置會在啟動時把 Instant 降為 Fast，而偏好設定會在結束遊戲時儲存。所以在自動跑局停止時和遊戲結束時，都要把玩家自己的設定值恢復回去。
- **放棄或崩潰**：這個種子記為 `aborted`，並附上原因。絕不為了挑更好的結果而重跑一個種子。

## 3. 日誌，以及 R3 = R4

**Mod 目前寫什麼**。它的每一行都寫進遊戲自己的日誌，所以會出現在遊戲的日誌檔裡（本機上是 `~/.local/share/SlayTheSpire2/logs/godot.log`，另有較早工作階段的帶日期副本）。每一行都以 `[Sts2Ai]` 開頭：

| 等級 | 內容 |
|---|---|
| info | 「assist mode, ENV, brain at PATH」；「environment ENV」；「connected to the brain」；「no brain: REASON」（每種不同的原因一次） |
| warning | 「off: game V, the mod is for v0.111.0」；「brain: MESSAGE」（一個 `error`）；「unexpected TYPE from the brain」；「a card prompt (TYPE) without its context, left to the player」；「SL record of node N broken after K steps: REASON」；設定檔的兩條警告 |
| error | 一個影格的例外，每種不同的文字一次；「SL record: EXCEPTION」；「no AI settings tab: EXCEPTION」 |

它唯一寫的檔案是自己的設定檔（[概覽 §5](/zh-tw/arch/mod/#sec-5)）。它沒有自己的決策日誌。真實遊戲裡的一個工作階段改由大腦那一側記錄：`brain --log FILE` 寫出 Harness 的決策日誌（每個決策的觀測、合法動作、選擇、計畫、候選、環境和時間，[Harness：決策日誌](/zh-tw/arch/harness/decision-log/)），`brain --wire FILE` 則寫出宿主傳來的每則訊息，包括帶有遊戲版本的 `hello`。2026-10-28 的擷取就是這樣的一對，保存在本機的 `tmp/assist/` 裡（[SL 紀錄 §8](/zh-tw/arch/mod/sl-record/#sec-8)）。

**規劃中：Mod 的決策日誌**。每個決策記下：觀測、合法動作、推薦、實際打出的動作、延遲、環境、遊戲和 Mod 的版本，以及必須為 0 的 `NumReloads`（[環境：資訊與節點 §8](/zh-tw/arch/environments/information/#sec-8)）。目前沒有東西讀 `NumReloads`。

**規劃中：R3 = R4**。同一個種子、同一串決策，在模擬器（R3）和遊戲（R4）裡打出來，必須得到相同的觀測；出現差異就是 GameBridge 或模擬器的 bug，測試會報告第一個差異。目前有的東西範圍較窄：`clones` 為 SL 紀錄逐個決策檢查，節點的複本問的是不是遊戲問過的那個決策（[SL 紀錄 §8](/zh-tw/arch/mod/sl-record/#sec-8)）。

## 4. 操作與安全

| 操作 | 狀態 | 作用 |
|---|---|---|
| F8 | 已實作 | 隱藏或顯示面板和所有標記；Mod 關閉時也有效 |
| SL / NoSL 開關 | 已實作 | 在面板的標頭和 AI 分頁裡（[概覽 §5](/zh-tw/arch/mod/#sec-5)） |
| AI 分頁 | 已實作 | Mod 的設定 |
| F9 | 規劃中 | 暫停或繼續自動遊玩 |
| 單步模式 | 規劃中 | 每按一次鍵執行一個動作 |
| 空白鍵（半自動） | 規劃中 | 標記顯示計畫；按空白鍵打出下一步 |

**規則**，目前都成立，規劃中的模式也必須遵守：

- **Mod 不對任何東西採取行動**。輔助模式下，它從不啟動任何遊戲動作。規劃中的自動遊玩只會打出決策合法清單裡的動作。大腦的答案由 Harness 對照這份清單檢查，遇到不合法的就拋出例外（[Harness：路由、預算與種子 §6](/zh-tw/arch/harness/routing/#sec-6)）。
- **不修改狀態、不用主控台、不讀檔、不寫存檔**。Mod 沒有做這些事的任何介面。
- **只限單人**。輔助在多人對局裡會自行關閉，規劃中的自動遊玩則會拒絕任何多人大廳。
- **什麼會離開遊戲**。socket 只傳輸協定訊息。對局 id 是種子的雜湊，觀測裡也不含種子（`RunView` 沒有種子），所以在 NoSL 下，種子從不離開宿主。SL 下則會：節點的檢查點是遊戲的完整存檔，帶有種子和每條亂數流的狀態，這是 SL 可以知道的（[SL 紀錄 §2](/zh-tw/arch/mod/sl-record/#sec-2)）。NoSL 從不傳送檢查點。
- **遊戲的設定畫面**是 Mod 唯一會改動遊戲節點的地方：它加上自己的分頁和面板，並把分頁列移動半格，讓它保持置中（[輸出 §2](/zh-tw/arch/output/#sec-2)）。它畫的其他所有東西都在自己的圖層裡。

## 5. 補丁與 JIT

**Harmony 補丁**在執行時改寫遊戲的方法：Harmony 是一個 .NET 函式庫，讓 Mod 能在原方法之前（*前綴*，prefix）、之後（*後綴*，postfix）或在它的例外周圍（*終結器*，finalizer）執行自己的程式碼。Mod 不訂閱任何遊戲事件：它每個影格輪詢一次（[主迴圈 §1](/zh-tw/arch/mod/loop/#sec-1)），只在必要的地方打補丁。它所有的補丁共用一個 Harmony id `sts2ai.mod`，在 `Host.Start` 裡按以下順序安裝：

| 補丁 | 種類 | 用途 |
|---|---|---|
| `CardSelectCmd.From*`，除 `FromChooseABundleScreen` 以外的 15 個公開靜態多載 | 前綴和終結器 | 每個選牌提示的上下文（[GameBridge：讀取遊戲 §6](/zh-tw/arch/gamebridge/observe/#sec-6)） |
| `SaveManager.SaveRun`、`RunManager.LoadIntoLatestMapCoord`，以及 SL 紀錄的 12 個入口 | 前綴；另有 6 個後綴，用於步驟的任務 | SL 紀錄（[SL 紀錄 §3](/zh-tw/arch/mod/sl-record/#sec-3)） |
| `NSettingsTabManager._Ready` | 後綴 | AI 分頁，在下一次空閒時加上（[輸出 §2](/zh-tw/arch/output/#sec-2)） |

**為什麼最先安裝**。上下文補丁要在任何其他東西編譯遊戲程式碼之前安裝：在補丁之前編譯的呼叫方，可能把入口內嵌進去而繞過補丁。這在無頭執行時見過：另一個補丁重新編譯 SapphireSeed 時，發生了這種內嵌。

**JIT**。遊戲在 .NET 的*分層編譯*下執行：方法先被快速編譯一次，常用的方法之後再帶最佳化重新編譯（「rejit」）。一次 rejit 可能悄悄丟掉一個補丁；這在無頭執行幾千場戰鬥之後見過，這也是模擬器關掉分層編譯的原因（[模擬器：無頭宿主 §6](/zh-tw/arch/simulator/headless/#sec-6)）。Mod 無法選擇遊戲如何編譯。它有的是：

- **缺少上下文會記入日誌**：沒有帶上下文就到來的提示會留給玩家，並在遊戲日誌裡寫一條警告（[主迴圈 §5](/zh-tw/arch/mod/loop/#sec-5)）。面板目前還不顯示警告。
- **規劃中：心跳**，每個補丁觸發時給一個計數器加一，用來發現補丁失效。
- **規劃中：啟動參數**：用 `DOTNET_TieredCompilation=0` 啟動遊戲 <Badge text="推斷" variant="caution" />，前提是遊戲託管的執行時認這個變數（未決問題 2，[§8](#sec-8)）。

## 6. 已有工作

STS2MCP（MIT 授權）是一個現成的 Mod，讓外部程式透過 HTTP 操控 STS2。

**照搬**：

- 在 `ProcessFrame` 上取空的主執行緒佇列（[主迴圈 §1](/zh-tw/arch/mod/loop/#sec-1)）；
- 它按畫面寫的動作程式碼，作為參考。

**避開**：

- 直接 `new PlayCardAction`：它會跳過 `CanPlayTargeting` 和出牌效果；
- 直接結束回合；
- 暴露種子或地圖的路徑；
- 帶 CORS `*` 的 HTTP：任何網頁都能操控遊戲。Mod 只用 Unix socket。

## 7. 測試

Mod 沒有單元測試。它和模擬器共用的部分在模擬器那邊測試：GameBridge 的觀測和動作，以及 Protocol 的訊息（[模擬器：參考 §7](/zh-tw/arch/simulator/reference/#sec-7)）。Mod 在方案（solution）裡，所以建置整個方案時會編譯它，但沒有任何東西執行它。在遊戲裡檢查的項目：

| 檢查 | 狀態 |
|---|---|
| **SL 往返**：`brain --wire` 和 `clones` | 已實作並執行過（[SL 紀錄 §8](/zh-tw/arch/mod/sl-record/#sec-8)） |
| **載入**：Mod 能初始化、版本守衛有效、面板會顯示 | 手動 |
| **真實遊戲裡的決策介面覆蓋**：腳本化的 R4 對局走遍每種決策介面，沒有任何決策因為缺少讀取器而留給玩家 | 規劃中 |
| **空閒**：動畫進行中從不送出決策；記錄決策時帶上影格編號，並檢查沒有一個與排隊中的動作重疊 | 規劃中 |
| **速度恢復**：停止時和結束遊戲時都把 Instant 或 Fast 恢復回去 | 規劃中，與驅動程式一起 |
