評估回答兩個問題：AI 有多強（排行榜），以及一個改動有沒有幫助（晉級門檻）。兩種環境走同一條管線，結果總是分開報告。評估在模擬器（SimWorker）裡跑整局，並透過 [Mod](/zh-tw/arch/mod/) 在真實遊戲裡做確認。

<Aside title="狀態">

R1 整局評估已經可用：`run --seeds FILE --records FILE` 跑完一個種子集，每局寫一條記錄；`report` 把這些記錄做成 [§6](#sec-6) 的報告，指標見 [§3](#sec-3)；第一組晉級種子和最終種子已經登記（[§4](#sec-4)）。戰鬥測試集也已就緒（[§5](#sec-5)，[戰鬥大腦 §7.1](/zh-tw/arch/combat-brain/#sec-7.1)），`leaderboard` 給報告排名（[§2](#sec-2)），整局門檻（`gate`）把通過的挑戰者寫進該環境的冠軍檔案（[§5](#sec-5)）。規劃中：幕級門檻，以及 R2–R4。

</Aside>

## 1. 模擬到實機階梯

模擬器裡的結果，只有能遷移到真實遊戲才算數。模擬到實機階梯分 R1 到 R4 四級，每級多加一步真實性。每個里程碑都跑全部四級，分開報告：

| 級 | 世界 | 測量什麼 | 現狀 |
|---|---|---|---|
| R1 | 在模擬器裡跑整局，由 Harness 驅動 | 策略 | 整局，NoSL（[§6](#sec-6)） |
| R2 | R1 + 觀測往返（決策只在由觀測建構的世界上做） | 觀測重建 | 戰鬥的往返已有 |
| R3 | 用真實 DLL 跑整局，帶真實解鎖、大廳的幕選擇和實際執行的協定 | 世界搭建 + 介面 | 無 |
| R4 | Steam 版遊戲 + Mod | 全部 | 無 |

**為什麼每級只加一個新變數**。每一級與下一級之間只差一處。如果勝率在相鄰兩級之間下降，只有一樣東西變了，差距就能歸因到它身上：

- R1 → R2：觀測重建；
- R2 → R3：世界搭建和介面；
- R3 → R4：動畫、時序、UI 狀態和執行器（在遊戲裡執行動作的 Mod 程式碼）。

如果從 R1 直接跳到真實遊戲，勝率變低可能出自上面任何一個原因，無從分辨。

- R4 很貴（按真實時間執行），所以用於確認，不用於調參。
- R1 的決策已經走 Build 路徑，即由觀測建構世界（[模擬器 §6](/zh-tw/arch/simulator/#sec-6)）。所以就決策而言，R1 約等於 R2；R2 增加的是宿主一側只來自觀測的狀態。

## 2. 兩個排行榜

排行榜記錄一個環境的冠軍（目前已接受的最好版本的 AI）在固定種子集上的成績。每個環境一個：

| | NoSL | SL |
|---|---|---|
| 種子 | 同一組預先登記的種子 | 相同 |
| 冠軍 | NoSL 冠軍 | SL 冠軍 |
| 允許的資訊 | [環境 §3](/zh-tw/arch/environments/#sec-3) | 同一張表 |
| 預算 | 按每個決策計，同一檔位 | 相同 |

- 兩個冠軍共用宏觀大腦和 V，只有戰鬥大腦不同（[環境 §5](/zh-tw/arch/environments/#sec-5)）。新的 V 會同時改變兩個冠軍，所以要在每種環境裡分別過門檻。
- 同時報告 SL − NoSL 的勝率差，也就是節點內資訊的價值。這是計畫 v1（本地筆記 `tmp/notes/plan.md`）裡「全知 vs 重取樣」消融實驗的正式版本。作為參考：spire-mentor（一個前人專案）去掉它的作弊（覆蓋整局）後，勝率下降了 22.8–25.5 個百分點（pp）；我們的作弊只到節點級，所以預計差值更小。
- `leaderboard [--character SILENT]` 從一個角色在 `eval/CHARACTER/reports/` 裡的報告生成它的排行榜，寫到 `eval/CHARACTER/leaderboard.md`：每個晉階等級、種子集和階梯級別下，每個環境一張表，按勝率、再按平均層數排名，作廢的報告排在最後，該環境冠軍檔案（`eval/CHARACTER/champions/`）指明的報告會被標出（[§5](#sec-5)）；不完整的報告不列入。表下面，對兩種環境都有報告的每個冠軍，給出同一組種子上按種子配對的 SL − NoSL 差值：勝率和到達層數，各帶 95% 區間。榜上列出所有報告，而不只是已接受的冠軍。排行榜和報告一起提交。

<Aside type="caution" title="不要混用環境">

絕不把兩種環境放進同一張表，或同一次晉級決定。

</Aside>

## 3. 指標

**主要指標**

- 勝率，附 Wilson 95% 區間；
- 平均到達層數；
- 進入每個頭目戰時的生命值。

Wilson 區間是比例（例如勝率）的信賴區間。與簡單的常態近似不同，它在樣本少、或比例接近 0 或 1 時依然可靠。

**必須為零**（否則本次評估作廢）

- 後備或隨機決策（[Harness §4](/zh-tw/arch/harness/#sec-4)）；
- 失敗的對局（驅動或大腦出錯）和被截斷的對局（觸及決策上限）；
- 遊戲錯誤（`Log.Error` 行）；
- `NumReloads`；
- NoSL 對局中的存檔匯出（[環境 §6](/zh-tw/arch/environments/#sec-6)）。

**輔助指標**

- 決策介面覆蓋計數；
- 每個決策的計算量（分支數、掛鐘時間、SL 複本查詢次數）；
- 宏觀校準：Brier 分數（預測勝率與 0/1 結果之間的均方誤差，越低越好）必須低於常數預測；
- 保守程度：打菁英次數、跳過率、到達頭目時的生命值、囤積金幣/藥水；
- 失敗和被截斷的對局在勝率裡也算作輸局；從不重跑。

## 4. 種子

- 三組互不相交的種子：訓練、晉級、最終。
- 最終種子事先生成並登記在儲存庫裡（註明方法和日期）。全部都跑，全部都報告，這樣誰也沒法挑那些碰巧好看的種子。正式結論至少需要 300 局。
- 種子就是遊戲的對局種子字串。R1–R3 由 worker 開局，R4 由 Mod 用同樣的種子開局（[Mod §7](/zh-tw/arch/mod/#sec-7)）。
- 訓練種子不限量。晉級種子定期輪換，避免過度擬合。

種子集是 `eval/seeds/` 下的一個文字檔案，每行一個種子，開頭的註解寫明生成方法和日期。`seeds --base B --n K` 輸出 K 個種子 `MakeSeed(B, i)`（i = 0…K−1）：每個種子是 12 個字元，取自一個以 B × 1,000,003 + i × 7,919（32 位元）為種子的亂數生成器。下表中任意兩個基數要到幾億個種子之後才會撞上同一個生成器種子，所以各組互不相交。基數是固定的：

| 種子集 | 基數 | 種子數 |
|---|---|---|
| 訓練 | 1 | 不限（即 `run --seed 1` 所跑的） |
| `promotion-1` | 2 | 200，2026-10-27 登記 |
| `final-1` | 3 | 300，2026-10-27 登記 |

一局的亂數生成器（佔位策略、大腦種子）以種子字串的穩定雜湊為種子，所以只要種子相同，對局就相同，與它在哪個種子集、排第幾無關。

## 5. 晉級門檻

晉級門檻是挑戰者取代冠軍之前必須通過的測試。整局很貴：勝率 p 約為 0.3 時，用非配對比較檢測 +5 pp 的提升，每邊約需 1,300 局；+2 pp 約需 8,000 局。所以門檻分層，從便宜而局部到昂貴而完整：

| 層級 | 用於 | 方法 | 成本 |
|---|---|---|---|
| 戰鬥測試集（combat panel） | 戰鬥搜尋 / 價值 | 固定的（遭遇，牌組，種子），CRN；平均掉血 + 死亡率 | 幾秒到幾分鐘 |
| 幕級 | 宏觀 | 從快照池開始打一幕；過幕率 + 幕末生命值 | 幾分鐘 |
| 整局 SPRT | 階段晉級 | 在晉級種子上配對，SPRT（H0：Δ ≤ 0，H1：Δ ≥ δ） | 幾小時 |

- **CRN**：挑戰者和冠軍共用對局種子，搜尋種子的派生方式也相同。整局跑通後，實測變異數到底降低了多少。
- **配對檢定**：McNemar 檢定或配對 SPRT。對晉級門檻做 A/A 測試。

上面用到的方法：

- **CRN**（公共亂數）：雙方用同樣的隨機種子來打，遇到的運氣相同，只有策略不同；雙方共有的運氣就從差值裡抵消了。
- **SPRT**（序列機率比檢定）每打完一對對局就檢查一次證據，一旦證據明確支援某個假設就停止：H0，挑戰者不比冠軍強（Δ ≤ 0）；或 H1，挑戰者至少強 δ（Δ ≥ δ）。Δ 是勝率差，挑戰者減冠軍。兩類錯誤率事先定好；得出明確結論所需的局數，通常比固定局數的檢定少得多。
- **McNemar 檢定**是配對的輸贏結果的標準檢定。它只看恰好一方贏、一方輸的那些種子，檢定它們在兩邊是否平分。
- **A/A 測試**：讓冠軍和它自己過晉級門檻。兩邊沒有真實差別，所以晉級的頻率不能高於門檻設計的偽陽性率；高於它就說明門檻有問題。

**已實作的整局門檻**：`gate --champion eval/CHARACTER/champions/ENV.json --records A[,B…] [挑戰者的對局選項] [--metric floor|win] [--delta D] [--alpha A] [--beta B] [--not-worse] [--promote PATH] [--env ENV]`。

- **冠軍檔案**：`eval/CHARACTER/champions/ENV.json`，每個角色每個環境一個，記錄冠軍在報告裡的名字、打出這個冠軍的對局選項（其中有它的角色和晉階等級，`character` 和 `asc`）、它的報告、成為冠軍的日期，以及它通過的門檻（第一個冠軍沒有）。`run --champion FILE` 和 `brain --champion FILE` 按它來打；命令列上給出的選項覆蓋檔案裡的。SL 冠軍的第一個檔案（2026-10-28）沒有經過門檻：由它在 promotion-1 上的基線定下，即 `--effort medium` 的 SL 規劃器 c2 加 L0 n2-b0.03（提交 `3699fc1`），平均 28.25 層，沒有獲勝，沒有遊戲錯誤（[§7](#sec-7)）。
- **冠軍一方**就是它的報告。一個種子決定整局（[§4](#sec-4)），再打一遍冠軍只會重複這些對局，所以門檻只打挑戰者。兩邊必須來自同一遊戲版本、同一環境、同一階梯級別，並且用同一個角色、在同一個晉階等級上打；`--env` 寫明挑戰者的環境，與冠軍檔案的環境不同就拒絕。
- **挑戰者一方**是它的對局記錄，由給出的對局選項命名；每條記錄都必須是用這些選項打出來的。帶探索的選項（`--macro-explore`、`--combat-explore`、`--card-explore`）會被拒絕：探索只用於自我對弈（[學習 §5](/zh-tw/arch/learning/#sec-5)）。頭目連戰的記錄（`auto_win`）也會被拒絕：它們的戰鬥從來沒打過。
- **配對**按種子，順序同種子集。SPRT 每對之後檢查一次，在第一個明確結論處停止。
- **指標**：`floor`（對局很少獲勝時的預設值）是平均層數差，挑戰者減冠軍，做高斯 SPRT，H0 為 0，H1 為 δ = 1.5 層；變異數由已有的配對估計（至少為 1），有 10 對不同之前不下結論。結果相同的配對不計入這 10 對：只改變部分對局的改動會讓大多數配對結果相同，只有這些配對時變異數停在下限 1，門檻在第 10 對就判這種改動失敗。一個讓十局中的一局多走 15 層（平均 +1.5）的改動，只要前 10 局結果相同就會這樣失敗，機率約 35%；頭目預算的門檻就遇到了這種情況（[戰鬥大腦 §5](/zh-tw/arch/combat-brain/#sec-5)）。`win` 只看恰好一方獲勝的那些配對，與 McNemar 檢定相同；檢定挑戰者在其中所佔的比例，H0 為 0.5，H1 為 0.5 + δ，δ = 0.1。α = β = 0.05。
- **結論**：通過（pass）、不通過（fail）、未定（open，配對用完仍無結論），或作廢（void，挑戰者的對局違反了必須為零的規則，[§3](#sec-3)）。通過時結束代碼為 0。
- **不更差**。目的是更省而不是更強的修改（少搜一些，打法其餘不變），只要不更差就晉級：`--not-worse` 把兩個假設都下移 δ，H0 在 −δ（差了 δ），H1 在 0（`win` 時 H0 在 0.5 − δ，H1 在 0.5）。門檻輸出的那一行和冠軍檔案裡的門檻結果會寫明是哪種檢定。`learn/challenge.py --not-worse` 會把它傳下去。
- **晉級**：通過時，`--promote PATH` 把挑戰者的報告寫到 PATH.json 和 PATH.md，並改寫冠軍檔案，寫入這次門檻的結果。冠軍檔案直接引用挑戰者的權重檔案所在的路徑，並帶上它打的角色和晉階等級。這些檔案必須在這個角色的權重資料夾 `weights/CHARACTER/` 裡，那裡一個名字永遠指同一個檔案；有檔案在別處的晉級，在寫任何東西之前就被拒絕（[學習 §6](/zh-tw/arch/learning/#sec-6)）。新報告要面對之後的挑戰者，所以必須覆蓋整個種子集。SPRT 可能提前通過：挑戰者分批打，每批之後過一次門檻，不通過就停；通過之後把種子集剩下的打完，再晉級。`learn/challenge.py` 就是這樣做的，用冠軍的角色和晉階等級（[學習 §2](/zh-tw/arch/learning/#sec-2)）。
- **重新基線**。冠軍的報告只有在程式碼還像原來那樣打這個冠軍時才代表它。改變它打法的修改（世界建構、搜尋或 L0 的修復）會讓報告過時，再拿它過門檻，就會把這次修改算到挑戰者頭上。這時冠軍在新程式碼上把整個種子集重打一遍（`run --champion FILE`），冠軍檔案改為指向新報告。這不是晉級：冠軍、它的日期和它通過的門檻都不變。2026-10-27 修了搜尋的備忘表、L0 的升級估值和 NoSL 世界裡怪物的出招日誌之後（提交 `432aa0c`），NoSL 冠軍在 promotion-1 上的平均層數從 21.88 變為 22.70（配對 +0.81 ± 0.89 層，95%；131 個種子到達的層數相同，42 個更高，27 個更低），打到第 3 幕頭目的局數從 1 變為 4。NoSL 世界補上盟友和被眩暈怪物的下一招之後（提交 `32a0160`），它又重打了一遍：22.58，200 個種子裡 197 個到達的層數相同（配對 −0.12 ± 0.18），3 局打到第 3 幕頭目。修復 NoSL 世界裡牌自身的費用和 Sozu 下的商店之後（提交 `c5ee8de`），它在接下來的門檻所用的建置上又打了一遍：200 個種子全部到達相同的層數。

## 6. 報告

每次評估輸出一個 JSON 檔案和一頁 Markdown 報告，內容包括：遊戲版本、提交（commit）、冠軍、環境、階梯級別、種子集、預算、全部指標、必須為零的指標，以及與上一次評估的差異。報告放在 `eval/CHARACTER/reports/`，檔名為 `日期-環境-階梯級別-種子集-名稱.json` 和 `.md`；報告背後的對局記錄和決策日誌不進 git，放在 `data/CHARACTER/ENV/`（[學習 §6](/zh-tw/arch/learning/#sec-6)）。

- `report --seeds FILE --records A[,B…] --out PATH [--previous OLD.json]` 寫出 PATH.json 和 PATH.md。記錄可以來自多個行程，但必須是同一套設定（遊戲、提交、冠軍、環境、階梯級別）、同一個角色和同一個晉階等級，並且每條記錄跑的是種子集裡不同的種子。跑的局數少於種子集時，報告會標為不完整。
- 對局記錄（`run --records`）裡還有對局 id，就是決策日誌裡這一局的 id（[Harness §6](/zh-tw/arch/harness/#sec-6)），學習時靠它把兩者對上。記錄還列出這一局進過的每場戰鬥：幕、層、遭遇、房間型別、第一個決策時的生命值、最大生命值和藥水數，以及 `end`，即它的結局：死亡，或剩下的生命值、最大生命值和藥水數。一局停在某場戰鬥裡而不是死在裡面（失敗、截斷）時，那場沒有 `end`。它是戰鬥結局頭的目標（[學習 §1](/zh-tw/arch/learning/#sec-1)）。頭目連戰的記錄在設定裡標明這一點（`auto_win`，[模擬器 §5](/zh-tw/arch/simulator/#sec-5)），`report` 拒收它們。
- 提交指建置所用的提交：`src/` 下有未提交改動的建置會在後面加上 `-dirty`，這樣的報告只用於開發。

## 7. 基線

前人專案的參考結果，以及我們自己的下限：

| 來源 | 結果 | 備註 |
