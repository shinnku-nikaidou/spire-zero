戰鬥網路讀一場戰鬥在一個回合開始時的狀態，預測戰鬥會怎樣結束。搜尋用這個預測給它走到的狀態排名（[葉節點](/zh-tw/arch/combat-brain/leaf/)）。本頁從輸入到輸出描述這個網路。程式碼是 `learn/combat/net.py` 裡的 `Net`，輸入的規格在 `learn/combat/encode.py`。它怎樣訓練，見[訓練戰鬥網路](/zh-tw/arch/learning/combat-net/)。想看每一步的真實數字，請讀[一個狀態走過網路](/zh-tw/arch/combat-brain/walkthrough/)。

## 1. 整個網路

集合編碼器讀牌、能力、敵人和盟友；學到的向量直接加總，讀遺物、藥水、上下文和充能球。它們的輸出接成一個 651 個數的向量。兩層的主幹把它變成 256 個數，兩個輸出頭讀這些數：**結局**和**藥水**。

一個網路打每一場戰鬥：五個角色、每個晉階、兩種環境，都用同一組權重（`weights/all/`）。角色是上下文詞元之一，晉階是數字之一，所以在它們的戰鬥有差別的地方，網路分得出它們。沒有任何輸入、輸出頭或層只為一個角色而設：一個角色需要的東西，例如充能球或星辰，是共用網路的一部分，對其他角色讀起來是空的。SL 和 NoSL 的差別只在呼叫網路的搜尋：SL 規劃器或 PIMC（[環境](/zh-tw/arch/environments/)）。

一路上的形狀，其中批次有 $B$ 個狀態，每個狀態有 $n$ 張牌、$q$ 個能力、$e$ 個敵人、一個槽裡 $i$ 個意圖、$r$ 件遺物和 $a$ 個盟友：

| 步驟 | 內容 | 形狀 |
|---|---|---|
| 牌 | 每張牌一個向量 | $B \times n \times 32$ |
| | $\varphi$，逐張計算 | $B \times n \times 64$ |
| | 每個牌堆加總 × 1/8，4 個牌堆串接 | $B \times 256$ |
| 玩家 | 8 個數 | $B \times 8$ |
| 能力 | 每個能力一個向量，經過 $\varphi$ | $B \times q \times 64$ |
| | 加總 | $B \times 64$ |
| 敵人 | id 和數字 | $B \times e \times 32$ |
| | 它們的能力，加總 | $B \times e \times 64$ |
| | 4 個意圖槽 | $B \times e \times 128$ |
| | 串接，經過 $\varphi$ | $B \times e \times 128$ |
| | 加總 | $B \times 128$ |
| 遺物、藥水、上下文、充能球 | 各是向量的總和 | 各 $B \times 32$ |
| 盟友 | 經過 $\varphi$，加總 | $B \times 64$ |
| 3 個數字 | 晉階、充能球欄位、金幣 | $B \times 3$ |
| 串接 | 全部 | $B \times 651$ |
| 主幹 | 兩層 | $B \times 256$ |
| 結局輸出頭 | 一個死亡和 50 個分桶 | $B \times 51$ |
| 藥水輸出頭 | 每個藥水 id 一個機率 | $B \times 66$ |

藥水輸出頭最後一維的寬度是藥水表的大小，66。

## 2. 它讀什麼

**規則：戰鬥的狀態都放進輸入；能從 id 推出的東西由網路去學**。一張牌印著的數字由它的 id 和升級決定，所以不讀。戰鬥在一張牌上累積的東西要讀，因為 id 說不出來：它目前的能量費用和星辰費用；它的傷害和格擋，會像爪擊的傷害那樣隨每打出一張爪擊而成長；它根據戰鬥算出的數字，例如謀殺的；它的額外打出次數；它的附魔累積的傷害，即動量的；它的附魔每場戰鬥一次的效果是否已用掉；它的關鍵字，包括某個效果只在這個回合給它的；以及 Tinker Time 把一張瘋狂科學做成的樣子。充能球的數字也要讀，它們會隨戰鬥進行而改變，還有它在佇列中的位置。關於怎麼打，什麼都沒有寫進去：沒有哪張牌被說成好牌，也沒有列出任何怪物的出招順序。

一切都來自觀測，即玩家看到或記得的東西，加上敵人至今出招的公開記錄（[提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)），由 `encode.tokens`（`learn/combat/encode.py:145-186`）取出：

| 輸入 | 讀什麼 |
|---|---|
| 牌 | id、升級次數（更高的次數讀作 3）、牌堆；它的修飾詞元：附魔、苦痛、關鍵字（它自己的和只在這個回合有的）、Tinker Time 給的卡牌類型和附加效果，以及表示附魔效果已用掉的 `spent`；它的附魔和苦痛的數值；它目前的能量費用（X 或沒有費用時為 0）和星辰費用；它的傷害（奧斯提攻擊的傷害是奧斯提的；沒有列出時為 0）、格擋、計算數字、額外打出次數，以及它的附魔累積的傷害 |
| 玩家 | 生命值比例、生命值、最大生命值、格擋、能量、最大能量、星辰、回合數 |
| 能力 | id、數值、提示框把它和圖示分開寫出的層數、它保存或偷走的牌（夢魘的、順手一揮的）、它的數字離開它原本的數值多遠（環狀韌性的格擋、炸彈的傷害） |
| 敵人 | id、生命值比例、生命值、最大生命值、格擋、它已經顯示過幾個回合、它的能力、它現在和最近 3 個回合的意圖；倒下、等著復活的敵人也讀 |
| 遺物 | id（用完之後加上 `:used`）、計數、熔化標記、狀態（它每場戰鬥一次或每回合一次的效果已用掉、又沒有其他狀態顯示時為 `Spent`） |
| 藥水 | 它們的 id |
| 充能球 | id、被動值、激發值、佇列中的位置 |
| 盟友 | id、生命值比例、生命值、最大生命值、格擋、能力 |
| 上下文 | 遭遇、角色 |
| 3 個數字 | 晉階、充能球欄位、金幣 |

**不讀**：牌和遺物上印著的數字、抽牌順序、暫時的改動結束後牌回到的費用，以及敵人不公開的東西：它的計數和它的招式狀態。牌的傷害和格擋是它自己的數字 `vars.Damage` 和 `vars.Block`，未計入力量和敏捷；牌根據戰鬥算出的數字是 `calc`（[協定：觀測與動作 §7](/zh-tw/arch/protocol/observation/#sec-7)）。牌堆按集合讀，就像玩家看到的那樣，即使在 SL 下也是。

**上下文**。餵入的詞元是 `character:ID`、`encounter:ID`、`room:ID` 和 `act:N`。詞元表列出角色和遭遇；房間和幕讀作未知的那一項，因為遭遇已經隱含了它們。

**詞元表**。網路檔案為每種 id 保存一張表：`cards`、`modifiers`、`powers`、`enemies`、`intents`、`relics`、`potions`、`context`、`orbs`、`allies`、`relic_status`。每張表列出這個遊戲版本的每個 id，已排序，排在第 0 項之後；第 0 項是同一個共用的 `<unk>`，讀任何其他 id，例如比檔案新的 id（`learn/game_ids.py`，來自 `learn/game_ids.json`，由模擬器的 `tables` 指令寫出）。所以表不取決於訓練資料。`modifiers` 列出附魔、苦痛和關鍵字、Tinker Time 的卡牌類型和附加效果，以及 `spent`；`relic_status` 列出遊戲的狀態和 `Spent`；`allies` 列出遊戲的怪物，因為盟友就是怪物。

**縮放**。數字縮放到大約 1，再截斷在 ±10 以內，因為少數狀態會出現極大的數（瀑布巨獸噴發時的生命值；`learn/combat/encode.py:71-143`）：

| 數字 | 縮放 |
|---|---|
| 生命值、最大生命值 | / 100 |
| 生命值比例 | 不變 |
| 格擋 | / 20 |
| 能量、最大能量 | / 3 |
| 星辰 | / 5 |
| 回合數、敵人已顯示的回合數 | / 10 |
| 能力的數值和層數、修飾的數值、遺物的計數 | / 10 |
| 牌的費用 | / 3 |
| 牌的星辰費用 | / 5 |
| 牌的傷害、格擋、計算數字、累積的傷害 | / 20 |
| 牌的額外打出次數 | / 2 |
| 能力移動的數字 | / 20 |
| 充能球的被動值和激發值 | / 10 |
| 意圖的每段傷害 | / 10 |
| 意圖的總傷害（傷害 × 段數） | / 20 |
| 金幣 | / 100 |
| 晉階、充能球欄位 | / 10，不截斷 |

死去的盟友不計入：它如果回來，生命值也是重新產生的。只有倒下、等著復活的敵人留在戰鬥的列表裡（遊戲會立刻移除其他的），並連同它的意圖一起讀，因為它的復活是一個招式。沒有 id 的敵人讀作 `<none>`，沒有 id 的盟友（玩家的）讀作 `<player>`。

**輸入張量**，按計算圖輸入的順序（`encode.INPUTS`，`learn/combat/encode.py:24-68`）。每個清單都補齊到批次裡最長的長度，且至少為 1，並有一個遮罩，存在的是 1，補齊的是 0：

| 名稱 | 形狀 | 內容 |
|---|---|---|
| `cards`、`ups`、`costs`、`damages` | $B \times n$ | 每張牌的項、升級次數、費用、傷害 |
| `piles` | $B \times n \times 4$ | 它的牌堆，one-hot：手牌、抽牌堆、棄牌堆、消耗堆 |
| `numbers` | $B \times n \times 5$ | 它的格擋、計算數字、額外打出次數、星辰費用、累積的傷害 |
| `mods`、`mod_mask`、`mod_amounts` | $B \times n \times m$ | 它的修飾詞元的項，$m$ 是一張牌最多有的個數，它們的遮罩，以及前兩個即附魔和苦痛的數值（其他詞元為 0） |
| `player` | $B \times 8$ | 玩家的數字 |
| `powers`、`power_amounts`、`power_stacks`、`power_details`、`power_mask` | $B \times q$ | 玩家的能力 |
| `power_cards`、`power_card_mask` | $B \times q$ | 能力保存或偷走的牌 |
| `enemies`、`enemy_mask` | $B \times e$ | 每個敵人的項和它的遮罩 |
| `enemy_scalars` | $B \times e \times 5$ | 它的數字 |
| `enemy_powers`、`enemy_power_amounts`、`enemy_power_stacks`、`enemy_power_details`、`enemy_power_mask`、`enemy_power_cards`、`enemy_power_card_mask` | $B \times e \times q$ | 它的能力 |
| `intents`、`intent_mask` | $B \times e \times 4 \times i$ | 每個槽的意圖類型 |
| `intent_values` | $B \times e \times 4 \times i \times 2$ | 它們的傷害和總傷害 |
| `relics`、`relic_mask`、`relic_status` | $B \times r$ | 每件遺物的項、遮罩和狀態 |
| `relic_values` | $B \times r \times 3$ | 它的計數、是否顯示計數（計算圖不用）、熔化 |
| `potions`、`potion_mask` | $B \times p$ | 每瓶持有藥水的項和它的遮罩 |
| `context`、`context_mask` | $B \times 4$ | 上下文詞元 |
| `orbs`、`orb_mask` | $B \times o$ | 每顆充能球的項和它的遮罩 |
| `orb_values` | $B \times o \times 2$ | 它的被動值和激發值 |
| `allies`、`ally_mask` | $B \times a$ | 每個盟友的項和遮罩 |
| `ally_scalars` | $B \times a \times 4$ | 它的數字 |
| `ally_powers`、`ally_power_amounts`、`ally_power_mask` | $B \times a \times q$ | 它的能力 |
| `extra` | $B \times 3$ | 晉階、充能球欄位、金幣 |

## 3. 牌

牌堆是一個多重集合：牌的順序沒有意義，大小也不固定。所以每張牌各自通過同一個小網路，再把結果加起來：這是一個 Deep Set（Zaheer 等人，2017）。總和能讀任意數量、任意順序的牌。下面所有的編碼器都是 `Net.encode`（`learn/combat/net.py:229-308`）。

**牌的向量**。一張 id 為 $c$、升級次數為 $u$、能量費用為 $k$、星辰費用為 $k^\star$、傷害為 $v$、格擋為 $b$、計算數字為 $z$、額外打出次數為 $r$、累積的傷害為 $j$、牌堆為 $l$、修飾詞元為 $m$ 且數值為 $a_m$ 的牌成為 32 個數：

$$
x = E[c] + u\, U[c] + k\, K + k^\star K^\star + v\,\big(D + D_c[c]\big) + b\, B[c] + z\, Z[c] + r\, R[c] + j\, J + P[l] + \sum_{m} \big(M[m] + a_m\, A[m]\big).
$$

$E$、$U$、$D_c$、$B$、$Z$、$R$、$M$ 和 $A$ 是學出來的表，每個 id 一個向量。$K$、$K^\star$、$D$ 和 $J$ 各是一個學到的向量，$P$ 每個牌堆一個向量。透過牌自己 id 的向量讀入的數字，在每張牌上可以有它自己的意思：計算數字在一張牌上是傷害，在另一張牌上是格擋或抽牌數。每一項都從標準差 0.1 的亂數開始。

**$\varphi$，牌的網路**。兩層，每張牌用同一組權重：

$$
\varphi(x) = \mathrm{ReLU}\big(W_2\, \mathrm{ReLU}(W_1 x + b_1) + b_2\big),
$$

其中 $W_1$ 是 32 → 64，$W_2$ 是 64 → 64。ReLU 是 $\max(0, x)$，逐個數地取。

**每個牌堆一個總和**。向量在每個牌堆內加總再縮放：

$$
h_l = \frac{1}{8} \sum_{\text{cards in pile } l} \varphi(x).
$$

係數 $1/8$ 讓一個牌堆的總和大約和平均值一樣大。總和說明某類牌有多少；網路分得出厚的手牌和薄的手牌。四個牌堆串接起來：$4 \times 64 = 256$ 個數。同一張牌在手牌裡和在棄牌堆裡讀起來不同，因為 $P[l]$ 是 $x$ 的一部分，也因為這兩個總和是串接裡分開的部分。

## 4. 能力

一個 id 為 $t$、數值為 $g$、層數為 $s$、移動的數字為 $d$、可能保存或偷走一張牌 $c$ 的能力成為 32 個數：

$$
y = T[t] + g\, G[t] + s\, S[t] + d\, X[t] + E[c].
$$

$G$、$S$ 和 $X$ 為每個能力 id 保存一個方向，所以一個數字可以對某個能力很要緊，對另一個無關緊要。移動的數字是提示框寫出的某個數字離開能力原本的數值多遠，沒有移動時為 0。牌的向量來自牌的表 $E$。一層帶 ReLU 的 32 → 64 映射每個能力，能力加總時不縮放：64 個數。同一組權重讀玩家的能力、每個敵人的能力和每個盟友的能力（盟友的沒有層數、牌，也沒有移動的數字）。

## 5. 敵人和它們的意圖

**一個意圖**有類型 $d$、每段傷害 $f$ 和總傷害 $v$：

$$
w = I[d] + f\, I_f[d] + v\, I_v[d].
$$

**一個意圖槽**是它各意圖的總和，加上一個學到的槽位向量。槽 0 是敵人現在顯示的；槽 1 到 3 是它最近 3 個回合顯示的，最近的在前。空槽就只有它的槽位向量。四個槽串接起來：$4 \times 32 = 128$ 個數。

**一個敵人**串接三個部分：它 id 的向量加上 5 個數字的線性投影（32）、它的能力的總和（64），以及它的槽（128）。一共 224 個數，經過 224 → 128 → 128 的 MLP，每個敵人用同一組權重。敵人們再加總：128 個數。

倒下、等著復活的敵人和其他敵人一樣讀：它的生命值比例是 0，它的槽 0 保存它的復活。

關於怪物的出招，沒有任何東西是手寫的。從怪物的 id、回合數和它最近的意圖，網路能學到怪物的出招順序，以及它目前在這個順序裡的位置。

## 6. 袋、盟友和數字

**一件遺物**是它 id 的向量，加上計數乘以它 id 的一個學到的向量，熔化時再加一個學到的向量，再加上它的狀態的向量：遊戲的狀態，或這場戰鬥或這個回合效果已用掉時的 `Spent`。遺物加總：32 個數。

**藥水和上下文**都是袋：每個 id 有一個學到的向量，把這些向量加起來，中間沒有層。上下文的詞元是遭遇和角色。空袋是零向量。同一種藥水兩瓶就算兩次。

**一顆充能球**的 id 為 $o$、被動值為 $g$、激發值為 $h$、在佇列中的位置為 $j$，它成為

$$
O[o] + g\, O_g[o] + h\, O_h[o] + O_j[j, o].
$$

$O_g$ 和 $O_h$ 為每個充能球 id 保存一個方向。$O_j$ 為每個位置和充能球 id 保存一個向量，所以佇列的順序能到達網路；第十個及之後的位置都讀作第十個（`MAX_ORBS`）。充能球加總，中間沒有層：32 個數。沒有充能球時是零向量。

**一個盟友**是它 id 的向量加上 4 個數字的投影，再和它的能力的總和串接，經過一層 96 → 64。盟友加總：64 個數。

**串接**。所有部分接在一起：

$$
\underbrace{256}_{\text{cards}} + \underbrace{8}_{\text{player}} + \underbrace{64}_{\text{powers}} + \underbrace{128}_{\text{enemies}} + \underbrace{4 \times 32}_{\text{bags}} + \underbrace{64}_{\text{allies}} + \underbrace{3}_{\text{numbers}} = 651.
$$

## 7. 主幹和兩個輸出頭

**主幹**是一個兩層的 MLP，各 256 個數。一切都在這裡相遇：串接之前，牌沒看過敵人，敵人也沒看過生命值。

**結局輸出頭**是一個 256 → 51 的線性層。類別 0 是**死亡**。類別 1 到 50 是分桶，每個寬 0.025，分的是從這個狀態到一場勝利的戰鬥結束時**還會失去**的最大生命值比例，範圍從 −0.25（會回血的戰鬥）到 1。

**遮罩**。有些分桶對一個狀態來說不可能。一場勝利結束時的生命值比例在 $(0, 1]$ 內，所以現在的生命值比例為 $s$ 時，失去的部分必須低於 $s$，且至少是 $s - 1$。分桶 $[l, l + 0.025)$ 開放的條件是

$$
l < s \quad\text{and}\quad l + 0.025 > s - 1.
$$

其他分桶的 logit 設為 $-10^4$，softmax 之後恰好為 0（`Net.reachable`，`learn/combat/net.py:221-227`）。這條規則在計算圖裡，所以 C# 不保存任何相關的東西。在開放的類別上做 softmax，就給出 51 個機率，即計算圖的輸出 `outcome`。

**為什麼是「還會失去」，而不是「結束時剩下」**。估值的形式是*狀態持有的東西，一點不差，加上網路說還會發生的事*（[葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）。所以現在持有的生命值完整計入，一個束裡的兩個狀態在網路開口之前，就已經按真實的生命值分出差別。每個輸出頭都遵守這條規則：它預測相對於這個狀態的變化，而狀態持有的東西完整計入。

**藥水輸出頭**是一個 256 → 66、帶 sigmoid 的線性層，即計算圖的輸出 `potion_used`：藥水表的每一項一個機率，表示到一場勝利的戰鬥結束時已經不在。訓練和估值都只按表裡的項讀持有的藥水。同一個 id 的兩瓶讀到同一個機率；它們的標籤（一瓶不在，一瓶還在）把它訓練到 0.5，而總和是對的。

藥水輸出頭寬度固定，沒有新的動態軸，它和結局只共用主幹。它只占損失的一小部分（[訓練戰鬥網路 §4](/zh-tw/arch/learning/combat-net/#sec-4)）。

## 9. 一次前向計算，兩種實作

訓練器用 PyTorch 計算網路；大腦用 C# 執行它。兩者必須一致，靠的是網路檔案（[學習：參考 §7](/zh-tw/arch/learning/reference/#sec-7)）：

- **匯出**。`learn/combat/export.py`（`net_file`，`:72-106`）把網路寫成檔案裡的一個 ONNX 計算圖，遮罩、softmax 和 sigmoid 都包含在內，輸入按 [§2](#sec-2) 命名，每個長度都不固定。旁邊是詞元表、分桶、訓練報告，以及 16 個留出的回合開始和訓練器給它們的輸出，其中有多段攻擊、持有藥水和低生命值的狀態。
- **推論**。`CombatNet`（`src/Sts2Ai.Brain/Combat/CombatNet.cs`）依照 `encode.py`：`Graph`（`:91-121`）建出同樣的張量，由 ONNX Runtime 執行計算圖。
- **核對**。除非這個檔案給這 16 個狀態的輸出和訓練器一樣（差距在 $10^{-3}$ 以內），否則 `CombatNet.Load`（`:55-72`） 拒收它。任何一邊讀狀態的方式有差異，檔案就載入不了。

## 10. 結構表達不了什麼

這些單從結構就能推出。

- **加總之前，牌看不到別的牌**。牌與牌之間的關係只能以撐過相加的數字到達主幹。
- **袋是線性的**。兩件遺物之間、一件遺物和一張牌之間的關係，只能由主幹算出來。
- **牌堆是集合**。抽牌順序不讀，所以接下來會抽到什麼，只能從牌堆裡有什麼去猜。
- **槽只保存 3 個回合**。敵人更早做過的事，只能透過它已顯示的回合數和它的能力到達網路。
- **敵人是總和**。網路能數出敵人們在做什麼，但哪個敵人站在哪裡不是輸入。
- **只有 id，沒有規則**。網路認識一張牌，只靠有它的那些戰鬥。訓練中從未出現的 id 什麼也沒學到，不管它做什麼。
- **沒有策略**。網路給狀態估值；它不說該打哪個動作。選擇的是搜尋。
