import walk from '../../../../../data/combat-walk.json';

export const v = (x) => '[' + x.join(', ') + ', …]';
export const pct = (x) => (100 * x).toFixed(2) + ' %';

本頁拿一個真實的狀態，用手帶它走過戰鬥網路，附上網路為它算出的數字。設計請讀[戰鬥網路](/zh-tw/arch/combat-brain/network/)；這裡每一步都顯示那個設計對一場戰鬥做了什麼。向量只顯示前四個數。

這個狀態是檔案自己留出的測試狀態之一，一個回合開始（`weights/all/c9-0.json`，`tests[10]`）。載入網路時會檢查它給這個狀態的正是這些輸出（[戰鬥網路 §9](/zh-tw/arch/combat-brain/network/#sec-9)）。數字來自 `docs/scripts/combat-walk.py`，如果它的各層算不出檔案裡的輸出，它就會停下。

## 4. 一張牌，然後是牌堆

這張牌的向量是 `Net.encode`（`learn/combat/net.py:229-308`）開頭的幾行。看棄牌堆裡的 **{walk.card.id}**。它在牌表裡的項是 {walk.card.entry}，升級次數 {walk.card.up}；費用 1 讀作 {walk.card.cost}，傷害 6 讀作 {walk.card.damage}。

| 部分 | 向量 |
|---|---|
| 它 id 的向量 $E[c]$ | <code>{v(walk.card.id_vector)}</code> |
| 它的升級方向 $U[c]$，乘以 {walk.card.up} | <code>{v(walk.card.up_vector)}</code> |
| 費用向量 $K$，乘以 {walk.card.cost} | <code>{v(walk.card.cost_vector)}</code> |
| 傷害向量 $D$，乘以 {walk.card.damage} | <code>{v(walk.card.damage_vector)}</code> |
| 棄牌堆的向量 $P[l]$ | <code>{v(walk.card.pile_vector)}</code> |
| 它們的總和 $x$ | <code>{v(walk.card.x)}</code> |

把第一個數加起來核對：0.060 + 0 + 0.144 − 0.007 + 0.192 = 0.389。這個檔案裡 $D$ 很小，所以傷害加得不多（[戰鬥網路 §8](/zh-tw/arch/combat-brain/network/#sec-8)）。

$\varphi$ 接著把 $x$ 映射到 128 個數，<code>{v(walk.card.phi.first)}</code>。這是 ReLU 的輸出，所以沒有一個低於 0，而 128 個裡有 {walk.card.phi.zeros} 個恰好為 0。

每張牌都經過同一個 $\varphi$，每個牌堆把它的牌加起來，再乘 1/8：

| 牌堆 | 牌數 | 開頭的數 | 長度 | 為 0 的數 |
|---|---|---|---|---|
| 手牌 | {walk.piles[0].cards} | <code>{v(walk.piles[0].vector.first)}</code> | {walk.piles[0].vector.norm} | {walk.piles[0].vector.zeros} |
| 抽牌堆 | {walk.piles[1].cards} | <code>{v(walk.piles[1].vector.first)}</code> | {walk.piles[1].vector.norm} | {walk.piles[1].vector.zeros} |
| 棄牌堆 | {walk.piles[2].cards} | <code>{v(walk.piles[2].vector.first)}</code> | {walk.piles[2].vector.norm} | {walk.piles[2].vector.zeros} |
| 消耗堆 | {walk.piles[3].cards} | <code>{v(walk.piles[3].vector.first)}</code> | {walk.piles[3].vector.norm} | {walk.piles[3].vector.zeros} |

空牌堆恰好是零向量。這四個串接成牌的 512 個數。

## 5. 能力

玩家有三個能力，荊棘、敏捷和毒霧，數值是 3、1 和 3，縮放成 0.3、0.1 和 0.3。各自的向量是它 id 的向量加上縮放後的數值乘以它的數值方向。一層 64 → 128 分別映射它們，三個輸出的總和是 <code>{v(walk.powers.first)}</code>，64 個裡有 {walk.powers.zeros} 個為 0。

## 6. 敵人

敵人串接三個部分，同一個 $\varphi$ 讀每個敵人：

| | 機甲騎士 |
|---|---|
| id + 數字（64） | <code>{v(walk.enemies[0].numbers_vector)}</code> |
| 能力的總和（128） | <code>{v(walk.enemies[0].powers_vector)}</code> |
| 槽 0，共 4 個槽（各 64） | <code>{v(walk.enemies[0].slot_vector)}</code> |
| 經過 $\varphi$ 後（256）：長度 | {walk.enemies[0].phi.norm} |
| 經過 $\varphi$ 後：為 0 的數 | {walk.enemies[0].phi.zeros} |

它在敵人表裡是第 {walk.enemies[0].entry} 項。敵人的部分是所有敵人的總和。只有一個敵人時就是這個向量：256 個數，長度 {walk.foes.norm}，其中 {walk.foes.zeros} 個為 0。

## 9. 主幹

兩層，一切第一次相遇：

| 層 | 開頭的數 | 長度 | 為 0 的數 |
|---|---|---|---|
| 1291 → 512 | <code>{v(walk.body[0].first)}</code> | {walk.body[0].norm} | {walk.body[0].zeros} |
| 512 → 512 | <code>{v(walk.body[1].first)}</code> | {walk.body[1].norm} | {walk.body[1].zeros} |

## 10. 結局輸出頭：51 個 logit

一個線性層給出 51 個原始的數。第一個是死亡的，{walk.head.death_logit}。單獨一個 logit 沒有意義：只有下一步的 softmax 比較它們，才讓它們成為機率。

## 11. 遮罩，然後是 softmax

生命值比例是 {walk.value.share}。分桶 $[l, l + 0.025)$ 開放的條件是 $l < 0.506$ 且 $l + 0.025 > 0.506 - 1$。這裡：

- 底部：一場戰鬥回的血不可能超過缺少的生命值。{walk.state.max_hp} 點裡缺 {walk.state.max_hp - walk.state.hp} 點，比例是 0.494，超過最低分桶的 {walk.head.open_from}，所以這裡沒有分桶關閉。
- 頂部：一場勝利不可能失去全部持有的生命值，所以從 {walk.head.open_to} 起往上的分桶都關閉。

於是 **50 個分桶中有 {walk.head.open} 個開放**。其他的 logit 是 $-10^4$（`Net.reachable`，`learn/combat/net.py:221-227`），softmax 給它們恰好 0。

對其餘的做 softmax，就給出機率。死亡是 {walk.head.death}。最可能的分桶：

| 還會失去的最大生命值比例 | 換算生命值 | 機率 |
|---|---|---|
| {walk.head.tops[0].low} 到 {walk.head.tops[0].high} | 0 到 2.1 | {pct(walk.head.tops[0].chance)} |
| {walk.head.tops[1].low} 到 {walk.head.tops[1].high} | 2.1 到 4.2 | {pct(walk.head.tops[1].chance)} |
| {walk.head.tops[2].low} 到 {walk.head.tops[2].high} | 4.2 到 6.2 | {pct(walk.head.tops[2].chance)} |
| {walk.head.tops[3].low} 到 {walk.head.tops[3].high} | 6.2 到 8.3 | {pct(walk.head.tops[3].chance)} |

網路預期這場戰鬥會贏，而且代價不大：超過一半的機率落在最多失去 2 點生命值的分桶上。敵人有 136 點生命值，帶著 25 層中毒，玩家的毒霧每回合還會加更多；網路讀到了這些數字，不過這裡沒有任何東西說明哪些輸入最影響它。

## 12. 藥水輸出頭

同樣的 512 個數經過第二個線性層，512 → {walk.potion.outputs}，藥水表的每一項一個輸出。藥水形狀的石頭是第 {walk.potion.entry} 項。它的 logit 是 {walk.potion.logit}，sigmoid 把它變成 **{walk.potion.chance}**：網路預期勝利後這瓶藥水還在。

其他 {walk.potion.outputs - 1} 個輸出會算出來，但不讀。這裡最大的是 {walk.potion.most_likely[0].id} 和 {walk.potion.most_likely[1].id}，分別是 {walk.potion.most_likely[0].chance} 和 {walk.potion.most_likely[1].chance}：這個狀態兩者都沒有，所以它們沒有意義，也不訓練任何東西。沒有哪次訓練有過的藥水，例如 {walk.potion.unheld}，保存的是 `<unk>` 那一列，顯示它的機率 {walk.potion.unk}。

## 13. 搜尋讀到的數字

`CombatNet.Value`（`src/Sts2Ai.Brain/Combat/CombatNet.cs:74-85`）給 51 個機率定價（[葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）：

$$
\text{value} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02 \sum_{\text{held}} (1 - u_{\text{id}})
$$

| 項 | 數字 |
|---|---|
| 結局，在開放的分桶上加總 | {walk.value.win_term} |
| 預期留下的藥水，$\sum (1 - u)$ | {walk.value.kept} |
| 它們的項，$(1 - p_0) \times 0.02 \times$ 上一列 | {walk.value.potion_term} |
| **估值** | **{walk.value.value}** |

規劃器給這個狀態的**上界**是一場沒有失去生命值或藥水的勝利：0.2 + 0.6 × {walk.value.share} + 0.02 = {walk.value.bound}。估值比它低 0.043，因為網路預期會失去約 5.5 點生命值，這瓶藥水也有不大的機會沒了。

## 14. 搜尋看到什麼

搜尋比較狀態。一次改一件事，再跑一次網路：

| 狀態 | 生命值比例 | 結局 | 藥水 | 估值 |
|---|---|---|---|---|
| 原樣 | {walk.value.share} | {walk.value.win_term} | {walk.value.potion_term} | {walk.value.value} |
| 少 {walk.lost_hp} 點生命值 | {walk.siblings.less_hp.share} | {walk.siblings.less_hp.win_term} | {walk.siblings.less_hp.potion_term} | {walk.siblings.less_hp.value} |
| 藥水不在了 | {walk.siblings.no_potion.share} | {walk.siblings.no_potion.win_term} | {walk.siblings.no_potion.potion_term} | {walk.siblings.no_potion.value} |

{walk.lost_hp} 點生命值是 83 的 0.120，乘以 0.6 是 0.072，而估值下降 0.073。持有的生命值完整計入（[戰鬥網路 §7](/zh-tw/arch/combat-brain/network/#sec-7)），網路的回答幾乎不變：最可能的分桶仍是 {walk.siblings.less_hp.tops[0].low} 到 {walk.siblings.less_hp.tops[0].high}，死亡的機率是 {pct(walk.siblings.less_hp.death)}。

藥水的統一價在這裡是 {walk.value.potion_term}。然而沒有它，估值降到 {walk.siblings.no_potion.value}，下降 0.038：死亡的機率從 {pct(walk.value.death)} 變成 {pct(walk.siblings.no_potion.death)}，最可能的分桶的機率從 {pct(walk.head.tops[0].chance)} 變成 {pct(walk.siblings.no_potion.tops[0].chance)}。網路是從持有它的對局的結局學到這一點的，儘管它預期這瓶藥水會留著；這裡沒有任何東西說明原因。

## 15. 兩個更難的狀態

同一個檔案裡的另外兩個狀態，展示了這個狀態沒有展示的東西：一場輸面大於贏面的頭目戰，以及關閉大多數分桶的低生命值：

| | {walk.others.danger.encounter} | {walk.others.mask.encounter} |
|---|---|---|
| 房間、回合 | {walk.others.danger.room}，第 {walk.others.danger.round} 回合 | {walk.others.mask.room}，第 {walk.others.mask.round} 回合 |
| 生命值 | {walk.others.danger.hp} / {walk.others.danger.max_hp} | {walk.others.mask.hp} / {walk.others.mask.max_hp} |
| 開放的分桶 | {walk.others.danger.open}（{walk.others.danger.open_from} 到 {walk.others.danger.open_to}） | {walk.others.mask.open}（{walk.others.mask.open_from} 到 {walk.others.mask.open_to}） |
| 死亡的機率 | {pct(walk.others.danger.death)} | {pct(walk.others.mask.death)} |
| 最可能的分桶 | {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，{pct(walk.others.danger.tops[0].chance)} | {walk.others.mask.tops[0].low} 到 {walk.others.mask.tops[0].high}，{pct(walk.others.mask.tops[0].chance)} |
| 估值 | {walk.others.danger.value} | {walk.others.mask.value} |
| 上界 | {walk.others.danger.bound} | {walk.others.mask.bound} |

在頭目戰裡，估值遠低於上界：死亡的機率拿走估值的那一份，勝利又分散在許多分桶上。在 {walk.others.mask.hp} 點生命值時只有 {walk.others.mask.open} 個分桶開放，所以機率不可能落在失去比持有更多生命值的勝利上。

[葉節點 §4](/zh-tw/arch/combat-brain/leaf/#sec-4) 畫出檔案的全部 16 個狀態。

## 16. 標籤

到這裡為止，網路都在預測。訓練時，這個狀態還有一個答案，來自它的戰鬥真正怎樣結束。檔案沒有保存那個結局，所以拿一個來舉例：**假設這場戰鬥以 83 點中的 {walk.label.end_hp} 點生命值獲勝，藥水還留著**。

- **結局的類別**。從這個狀態失去的比例是 42/83 − {walk.label.end_hp}/83 = {walk.label.lost}，落在 {walk.label.low} 到 {walk.label.high} 的分桶：類別 {walk.label.class}。那場戰鬥的每個回合開始都會得到自己的類別，來自它自己的生命值。
- **藥水的標籤**。它還在戰鬥後第一個整局觀測裡，所以標籤是 0。
- **損失**。類別 {walk.label.class} 的機率是 {walk.label.chance}，所以結局的交叉熵是 {walk.label.ending_loss}。藥水的是 {walk.label.potion_loss}。樣本的損失是它們的和，一步梯度會把那個分桶的機率往上推。

像結局這樣大的損失就是意外的樣子：在這個假設的結局下，網路對生命值錯得很厲害，對藥水則不然。整份對局清單的標籤怎樣產生，見[訓練戰鬥網路 §3](/zh-tw/arch/learning/combat-net/#sec-3)。
