import walk from '../../../../../data/combat-walk.json';

export const v = (x) => '[' + x.join(', ') + ', …]';
export const pct = (x) => (100 * x).toFixed(2) + ' %';

本頁拿一個真實的狀態，用手帶它走過戰鬥網路，附上網路為它算出的數字。設計請讀[戰鬥網路](/zh-tw/arch/combat-brain/network/)；這裡每一步都顯示那個設計對一場戰鬥做了什麼。向量只顯示前四個數。

這個狀態是檔案自己留出的測試狀態之一，一個回合開始（`weights/all/c9-1.json`，`tests[9]`）。載入網路時會檢查它給這個狀態的正是這些輸出（[戰鬥網路 §9](/zh-tw/arch/combat-brain/network/#sec-9)）。數字來自 `docs/scripts/combat-walk.py`，如果它的各層算不出檔案裡的輸出，它就會停下。

## 4. 一張牌，然後是牌堆

這張牌的向量是 `Net.encode`（`learn/combat/net.py:231-310`）開頭的幾行。看手牌裡的 **{walk.card.id}**。它在牌表裡的項是 {walk.card.entry}，升級次數 {walk.card.up}；費用 1 讀作 {walk.card.cost}，傷害 6 讀作 {walk.card.damage}。它的其他數字（格擋、計算數字、額外打出次數、星辰費用、累積的傷害）都是 0，也沒有修飾，所以只剩下這些部分：

| 部分 | 向量 |
|---|---|
| 它 id 的向量 $E[c]$ | <code>{v(walk.card.id_vector)}</code> |
| 它的升級方向 $U[c]$，乘以 {walk.card.up} | <code>{v(walk.card.up_vector)}</code> |
| 費用向量 $K$，乘以 {walk.card.cost} | <code>{v(walk.card.cost_vector)}</code> |
| 傷害向量 $D$，乘以 {walk.card.damage} | <code>{v(walk.card.damage_vector)}</code> |
| 它自己的傷害方向 $D_c[c]$，乘以 {walk.card.damage} | <code>{v(walk.card.card_damage_vector)}</code> |
| 手牌的向量 $P[l]$ | <code>{v(walk.card.pile_vector)}</code> |
| 它們的總和 $x$ | <code>{v(walk.card.x)}</code> |

把第一個數加起來核對：0.228 + 0 + 0.151 − 0.023 + 0.001 − 0.141 = 0.216。傷害的兩個部分給第一個數加上 −0.022，而 id 的是 0.228（[戰鬥網路 §3](/zh-tw/arch/combat-brain/network/#sec-3)）。

$\varphi$ 接著把 $x$ 映射到 128 個數，<code>{v(walk.card.phi.first)}</code>，長度 {walk.card.phi.norm}。這是 ReLU 的輸出，所以沒有一個低於 0，而 128 個裡有 {walk.card.phi.zeros} 個恰好為 0。

每張牌都經過同一個 $\varphi$，每個牌堆把它的牌加起來，再乘 1/8：

| 牌堆 | 牌數 | 開頭的數 | 長度 | 為 0 的數 |
|---|---|---|---|---|
| 手牌 | {walk.piles[0].cards} | <code>{v(walk.piles[0].vector.first)}</code> | {walk.piles[0].vector.norm} | {walk.piles[0].vector.zeros} |
| 抽牌堆 | {walk.piles[1].cards} | <code>{v(walk.piles[1].vector.first)}</code> | {walk.piles[1].vector.norm} | {walk.piles[1].vector.zeros} |
| 棄牌堆 | {walk.piles[2].cards} | <code>{v(walk.piles[2].vector.first)}</code> | {walk.piles[2].vector.norm} | {walk.piles[2].vector.zeros} |
| 消耗堆 | {walk.piles[3].cards} | <code>{v(walk.piles[3].vector.first)}</code> | {walk.piles[3].vector.norm} | {walk.piles[3].vector.zeros} |

消耗堆是空的，而空牌堆恰好是零向量。這四個串接成牌的 512 個數。

## 5. 能力

玩家有一個能力，雜耍，數值 1，縮放成 0.1。它的向量是它 id 的向量加上 0.1 乘以它的數值方向。一層 64 → 128 映射它，只有一個能力時，能力的總和就是那個輸出：<code>{v(walk.powers.first)}</code>，長度 {walk.powers.norm}，128 個裡有 {walk.powers.zeros} 個為 0。

## 10. 結局輸出頭：51 個 logit

一個線性層給出 51 個原始的數。第一個是死亡的，{walk.head.death_logit}。單獨一個 logit 沒有意義：只有下一步的 softmax 比較它們，才讓它們成為機率。

## 11. 遮罩，然後是 softmax

生命值比例是 {walk.ended.share}。分桶 $[l, l + 0.025)$ 開放的條件是 $l < 0.839$ 且 $l + 0.025 > 0.839 - 1$。這裡：

- 底部：一場戰鬥回的血不可能超過缺少的生命值。{walk.state.max_hp} 點裡缺 {walk.state.max_hp - walk.state.hp} 點，比例是 0.161，所以低於 {walk.head.open_from} 的 3 個分桶關閉。
- 頂部：一場勝利不可能失去全部持有的生命值，所以從 {walk.head.open_to} 起往上的分桶都關閉。

於是 **50 個分桶中有 {walk.head.open} 個開放**。其他的 logit 是 $-10^4$（`Net.reachable`，`learn/combat/net.py:223-229`），softmax 給它們恰好 0。

對其餘的做 softmax，就給出機率。死亡是 {walk.head.death}。最可能的分桶，其中低於 0 的比例是回復的生命值：

| 還會失去的最大生命值比例 | 換算生命值 | 機率 |
|---|---|---|
| {walk.head.tops[0].low} 到 {walk.head.tops[0].high} | 回復 4.7 到 7.0 | {pct(walk.head.tops[0].chance)} |
| {walk.head.tops[1].low} 到 {walk.head.tops[1].high} | 回復 2.3 到 4.7 | {pct(walk.head.tops[1].chance)} |
| {walk.head.tops[2].low} 到 {walk.head.tops[2].high} | 回復 7.0 到 9.3 | {pct(walk.head.tops[2].chance)} |
| {walk.head.tops[3].low} 到 {walk.head.tops[3].high} | 回復 0 到 2.3 | {pct(walk.head.tops[3].chance)} |

網路預期這場戰鬥會贏，而且結束時的生命值比現在多：將近三分之二的機率落在回復 4.7 到 7.0 點生命值上。燃燒之血在每場勝利的戰鬥後回復 6 點生命值，比例 0.065，正在那個分桶裡。網路在它的輸入中讀到了遺物，不過這裡沒有任何東西說明哪些輸入最影響它。

## 12. 藥水輸出頭

同樣的 512 個數經過第二個線性層，512 → {walk.potion.groups} × {walk.potion.outputs}：相鄰的每 {walk.potion.per_group} 個分桶為一組，共 {walk.potion.groups} 組，每組藥水表的每一項一個輸出（[戰鬥網路 §7](/zh-tw/arch/combat-brain/network/#sec-7)）。最可能的勝利，即還會失去 {walk.head.tops[0].low} 到 {walk.head.tops[0].high} 的比例，是分桶 {walk.head.tops[0].bucket}，在第 {walk.potion.group + 1} 組，即分桶 {walk.potion.group * walk.potion.per_group + 1} 到 {(walk.potion.group + 1) * walk.potion.per_group}；這裡的機率都是這一組的。瓶中精靈是第 {walk.potion.entry} 項。它的 logit 是 {walk.potion.logit}，sigmoid 把它變成 **{walk.potion.chance}**（到小數點後四位），約百萬分之 2.5：網路預期勝利後這瓶藥水還在。在這個檔案裡，五組的權重相同（[戰鬥網路 §8](/zh-tw/arch/combat-brain/network/#sec-8)），所以每一組給它的機率都一樣。玩家從不喝這瓶藥水；玩家將要死亡時，遊戲會自己用掉它，讓玩家以最大生命值的 30 % 復活。

每組的 {walk.potion.outputs} 個輸出裡只讀持有的那瓶藥水的；其他 {walk.potion.outputs - 1} 個會算出來，但不讀。這裡其中最大的是 {walk.potion.most_likely[0].id} 和 {walk.potion.most_likely[1].id}，分別是 {walk.potion.most_likely[0].chance} 和 {walk.potion.most_likely[1].chance}：這個狀態兩者都沒有，所以它們沒有意義，也不訓練任何東西。沒有哪次訓練有過的藥水，例如 {walk.potion.unheld}，保存的是 `<unk>` 那一列，顯示它的機率 {walk.potion.unk}。

## 13. 搜尋讀到的數字

搜尋不讀這 51 個機率，也不讀藥水的機率：它讀一個數字，也就是葉節點估值（[葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）。`CombatNet.Outcome`（`src/Sts2Ai.Brain/Combat/CombatNet.cs`）算出這個數字的方法，是把網路仍然允許的每種結局，按它會留下的那一局，用 V（宏觀大腦給出的贏下這一局的機率）定價：

$$
\text{value} = \sum_{k=1}^{50} p_k \sum_{S \subseteq H} \Big(\prod_{i \in S} (1 - u_{i,g(k)}) \prod_{i \in H \setminus S} u_{i,g(k)}\Big)\, V\big(\text{生命值為 } h_k \text{、持有 } S \text{ 的這一局}\big)
$$

這裡 $H$ 是持有的藥水，$u_{i,g}$ 是藥水輸出頭給出的、藥水 $i$ 在一場結束於第 $g$ 組的勝利後已經不在的機率，$g(k) = \lceil k/10 \rceil$ 是分桶 $k$ 所在的組，$h_k$ 是分桶 $k$ 之後玩家持有的生命值：現在的生命值比例減去分桶的中點，乘以最大生命值，限制在 1 到最大生命值之間。

在這個狀態，$H$ 只有瓶中精靈，所以每個開放的分桶給出兩局：帶著藥水的那一局，機率是 $1 - u_{i,g(k)}$，在每一組都只差約百萬分之 2.5 就是全部（[§12](#sec-12)），以及沒有藥水的那一局。{walk.head.open} 個開放的分桶讓 V 評估 {2 * walk.head.open} 局，而機率恰好為 0 的關閉分桶一局也不給。每一局的其餘部分，是戰鬥周圍那一局的現狀：牌組、遺物、最大生命值、金幣、前方的地圖。檔案裡的測試狀態只有一個回合開始，沒有那一局，所以本頁給不出 V 的數字，也給不出估值；同一次呼叫在估值之外回傳的東西不需要它們（[葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）：

| | 數字 |
|---|---|
| 獲勝機率，$1 - p_0$ | {walk.ended.win} |
| 勝利時保有的生命值，在勝利分桶上取平均 | {walk.state.max_hp} 點中的 {walk.ended.hp_at_win} 點 |
| 勝利時預期留下的藥水，$\sum_{i \in H} (1 - \bar u_i)$ | {walk.ended.kept} |

這裡 $\bar u_i = \sum_{k=1}^{50} p_k\, u_{i,g(k)} / (1 - p_0)$，即藥水 $i$ 在勝利時已經不在的機率：每個分桶那一組的機率，按分桶的機率加權。

所以 V 被問到的，是以 93 點中約 83 點生命值、仍然帶著藥水離開這場戰鬥的那些局，而估值接近那一局的 V。這是否比另一個狀態的結局更值錢，由 V 根據它從那一局讀到的一切來判斷。

## 14. 搜尋看到什麼

搜尋比較狀態。一次改一件事，再跑一次網路：

| 狀態 | 生命值比例 | 死亡的機率 | 最可能的分桶 | 勝利時保有的生命值 |
|---|---|---|---|---|
| 原樣 | {walk.ended.share} | {pct(walk.head.death)} | {walk.head.tops[0].low} 到 {walk.head.tops[0].high}，{pct(walk.head.tops[0].chance)} | {walk.ended.hp_at_win} |
| 少 {walk.lost_hp} 點生命值 | {walk.siblings.less_hp.share} | {pct(walk.siblings.less_hp.death)} | {walk.siblings.less_hp.tops[0].low} 到 {walk.siblings.less_hp.tops[0].high}，{pct(walk.siblings.less_hp.tops[0].chance)} | {walk.siblings.less_hp.hp_at_win} |
| 藥水不在了 | {walk.siblings.no_potion.share} | {pct(walk.siblings.no_potion.death)} | {walk.siblings.no_potion.tops[0].low} 到 {walk.siblings.no_potion.tops[0].high}，{pct(walk.siblings.no_potion.tops[0].chance)} | {walk.siblings.no_potion.hp_at_win} |

少 {walk.lost_hp} 點生命值時，網路的回答幾乎不變：同一個最可能的分桶，機率也差不多。分桶是從現在持有的生命值裡還會失去的比例，所以勝利時保有的生命值下降的量，約等於拿掉的生命值，從 {walk.ended.hp_at_win} 降到 {walk.siblings.less_hp.hp_at_win}：持有的生命值完整計入（[戰鬥網路 §7](/zh-tw/arch/combat-brain/network/#sec-7)），V 給這個狀態的每種結局定價時，生命值都少約 10 點。

沒有藥水時，結局稍微變動，最可能的分桶的機率從 {pct(walk.head.tops[0].chance)} 變成 {pct(walk.siblings.no_potion.tops[0].chance)}，勝利時保有的生命值幾乎不變。瓶中精靈只在死亡時起作用，而網路在這裡並不預期死亡；這裡沒有任何東西說明結局究竟為什麼會變動。於是兩個狀態的差別主要來自 V：生命值相同，一局帶著藥水，一局沒有。一瓶藥水值多少，不是為這場戰鬥設定的一個數字，而是 V 對在這一局裡持有它的看法。

## 15. 兩個更難的狀態

同一個檔案裡的另外兩個狀態，展示了這個狀態沒有展示的東西：一場滿血的頭目戰，勝利要付出約一半的最大生命值，以及關閉大多數分桶的低生命值：

| | {walk.others.danger.encounter} | {walk.others.mask.encounter} |
|---|---|---|
| 房間、回合 | {walk.others.danger.room}，第 {walk.others.danger.round} 回合 | {walk.others.mask.room}，第 {walk.others.mask.round} 回合 |
| 生命值 | {walk.others.danger.hp} / {walk.others.danger.max_hp} | {walk.others.mask.hp} / {walk.others.mask.max_hp} |
| 開放的分桶 | {walk.others.danger.open}（{walk.others.danger.open_from} 到 {walk.others.danger.open_to}） | {walk.others.mask.open}（{walk.others.mask.open_from} 到 {walk.others.mask.open_to}） |
| 死亡的機率 | {pct(walk.others.danger.death)} | {pct(walk.others.mask.death)} |
| 最可能的分桶 | {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，{pct(walk.others.danger.tops[0].chance)} | {walk.others.mask.tops[0].low} 到 {walk.others.mask.tops[0].high}，{pct(walk.others.mask.tops[0].chance)} |
| 勝利時保有的生命值 | {walk.others.danger.hp_at_win} | {walk.others.mask.hp_at_win} |

在對眷族的頭目戰裡，網路預期一場勝利要付出 0.55 的最大生命值，即 {walk.others.danger.max_hp} 點中的約 53 點，分散在許多分桶上，沒有一個超過 6 %。V 按各自的生命值給這 {walk.others.danger.open} 種結局定價，所以估值分散在從滿血到只剩幾點生命值的許多局上，而死亡的機率以 0 的價格拿走它那一份。對異蛙寄生蟲，在 {walk.others.mask.hp} 點生命值時只有 {walk.others.mask.open} 個分桶開放，所以機率不可能落在失去比持有更多生命值的勝利上，而死亡拿走將近三分之一的機率。

[葉節點 §4](/zh-tw/arch/combat-brain/leaf/#sec-4) 畫出檔案的全部 16 個狀態。

## 16. 標籤

到這裡為止，網路都在預測。訓練時，這個狀態還有一個答案，來自它的戰鬥真正怎樣結束。檔案沒有保存那個結局，所以拿一個來舉例：**假設這場戰鬥以 93 點中的 {walk.label.end_hp} 點生命值獲勝，藥水還留著**。

- **結局的類別**。從這個狀態失去的比例是 78/93 − {walk.label.end_hp}/93 = {walk.label.lost}，落在 {walk.label.low} 到 {walk.label.high} 的分桶：類別 {walk.label.class}。那場戰鬥的每個回合開始都會得到自己的類別，來自它自己的生命值。
- **藥水的標籤**。它還在戰鬥後第一個整局觀測裡，所以標籤是 0。類別 {walk.label.class} 在第 {Math.floor((walk.label.class - 1) / walk.potion.per_group) + 1} 組，所以這個標籤只訓練那一組的機率。
- **損失**。類別 {walk.label.class} 的機率是 {walk.label.chance}，所以結局的交叉熵是 {walk.label.ending_loss}。藥水的，按那一組的機率，是 {walk.label.potion_loss}。樣本的損失是它們的和，一步梯度會把那個分桶的機率往上推。

像結局這樣大的損失就是意外的樣子：在這個假設的結局下，網路對生命值錯得很厲害，對藥水則不然。整份對局清單的標籤怎樣產生，見[訓練戰鬥網路 §3](/zh-tw/arch/learning/combat-net/#sec-3)。
