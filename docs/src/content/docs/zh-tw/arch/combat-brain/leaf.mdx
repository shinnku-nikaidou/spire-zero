每個搜尋都會在某處停下。PIMC 停在回合結束處；SL 規劃器通常會搜到戰鬥結束，但在知道戰鬥接下來怎麼發展之前，它也得給各回合結束處的狀態排名（[SL 規劃器：束搜尋 §1](/zh-tw/arch/sl-planner/beam/#sec-1)）。搜尋停下的狀態是**葉節點**（leaf），說出它值多少的函式是**葉節點估值**（leaf value）。一句話：葉節點是網路給出的結局分布，逐個結局定價，再加上它預期留下的藥水的一點小價格。

## 1. 葉節點是什麼

葉節點要麼是一個回合開始時的狀態，此時敵方回合已經真實地打完；要麼是戰鬥的結束，贏或輸。兩者由同一個函式估值，`ICombatLeaf.Value(status, observation, history)`：輸掉的戰鬥一文不值，贏下的戰鬥按它留下的東西估值，進行中的戰鬥按它預期會留下的東西估值。

- **只讀觀測**。葉節點讀玩家看得到的東西，加上敵人至今出招的公開記錄（[提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。它從不讀抽牌順序或亂數流，所以在兩種環境裡都不可能洩漏隱藏狀態。
- **排序比水準重要**。搜尋用葉節點來比較路線：重要的是更好的狀態得到更高的估值。一個把每個狀態都高估 0.1 的葉節點，打起來和沒有高估的一樣。

## 2. 結局的價格

價格是 `LeafValue`（`LeafValue.Of`，`src/Sts2Ai.Brain/Combat/LeafValue.cs:50-77`）裡手工設定的數字：

- 輸掉的戰鬥為 0。
- 贏下的戰鬥，剩下生命值比例 $s$（生命值除以最大生命值）、持有 $q$ 瓶藥水時，值

$$
\text{Win}(s, q) = 0.2 + 0.6\,s + 0.02\,q.
$$

它們是帶網路的葉節點裡僅有的手工設定的數字。已經結束的戰鬥直接由它們估值，不經過網路：每條打完的路線的結尾，也就是每個計畫的最終分數，都是這條公式套在路線結束時的狀態上。

沒有 `--combat-net` 時，進行中的戰鬥也交給 `LeafValue`（`HandLeaf`，`src/Sts2Ai.SimWorker/Brains/LeafChoice.cs:20`）：它從畫面上的內容投影戰鬥剩下的部分，另外多用幾個手工設定的數字。沒有冠軍這樣打。

## 3. 戰鬥網路

對還在進行的戰鬥，葉節點去問戰鬥網路。它讀一個回合的開始，預測在打出它訓練對局的那個策略下，戰鬥會怎樣結束。它的輸入和各層見[戰鬥網路](/zh-tw/arch/combat-brain/network/)，一個真實狀態走過它的全程見[一個狀態走過網路](/zh-tw/arch/combat-brain/walkthrough/)，它的訓練見[訓練戰鬥網路](/zh-tw/arch/learning/combat-net/)。

`--combat-net FILE` 讓它上場，在規劃器裡（顯示為 `plan NAME`）或在 PIMC 裡（`pimc NAME`）。

## 4. 兩個輸出

**結局**。51 個機率：一個死亡，或 50 個分桶之一，分的是從這個狀態到一場勝利的戰鬥結束時還會失去的最大生命值比例，範圍從 −0.25（會回血的戰鬥）到 1。持有的生命值排除掉的分桶是關閉的，機率恰好為 0（[戰鬥網路 §7](/zh-tw/arch/combat-brain/network/#sec-7)）。

**藥水**。勝利後，每瓶持有的藥水已經不在的機率。

## 5. 給結局定價

一個分布還不是一個數字。葉節點按 [§2](#sec-2) 給每種結局定價。設現在的生命值比例為 $s$，死亡的機率為 $p_0$，中點為 $m_k$ 的分桶 $k$ 的機率為 $p_k$，一瓶持有的藥水在勝利後已經不在的機率為 $u_{\text{id}}$：

$$
\text{value} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02 \sum_{\text{held}} (1 - u_{\text{id}})
$$

死亡不增加任何東西，因為它值 0（`CombatNet.Value`，`src/Sts2Ai.Brain/Combat/CombatNet.cs:74-86`）。在一個真實狀態上逐項計算，見[一個狀態走過網路 §13](/zh-tw/arch/combat-brain/walkthrough/#sec-13)。

這個形式是**狀態持有的東西，一點不差，加上網路說還會發生的事**。$s$ 一點不差地進入公式，所以同一個束裡的狀態在網路開口之前，就已經按真實的生命值分出差別。喝掉的藥水也一點不差地從總和裡消失。

**上界**。規劃器剪枝用的是在這個狀態的生命值和藥水下一場勝利的價值，也就是 [§2](#sec-2) 的 $\text{Win}(s, q)$，不經過網路（[SL 規劃器：束搜尋 §2](/zh-tw/arch/sl-planner/beam/#sec-2)）。一個分桶的中點可能超過持有的生命值半個桶寬，網路也可能預測回血，所以進行中的狀態可能略微高過它的上界：訓練資料裡獲勝的回合開始，有 1.84 % 回過血，而滿血時遮罩不允許這樣。

**網路在哪裡起作用**。剪枝和在打完的路線之間做選擇，只讀價格。網路決定束的順序、束留下什麼、輸掉的路線之間怎麼分高下，以及停在回合上限的路線。在 PIMC 裡，它給回合結束處的每個葉節點估值。

## 6. 一個網路，兩種環境

SL 和 NoSL 打同一個網路檔案。它從 SL 的對局學習，所以它的結局是規劃器的結局，而規劃器看得到 NoSL 的搜尋必須猜的東西，從同一個狀態出發贏得更多。因此在 NoSL 下，同一個狀態是按一個更強的玩家的結局來評分的。

## 7. 這個估值看不到什麼

這些都由價格和標籤推出。

- **每瓶藥水統一價**。一瓶藥水不管是哪種、在哪場戰鬥，都值 0.02，相當於最大生命值 70 時的 2.3 點生命值。所以沒有任何輸出頭能讓規劃器把藥水留給頭目；只有別的價格才能做到。藥水輸出頭學的是藥水什麼時候用掉，而估值只讀它們的總和。
- **金幣**。它是一個輸入，但一場戰鬥裡金幣的變化沒有價格，在這裡或打完的路線上都一樣。偷竊和黃金印記不花任何代價。
- **最大生命值**。它只透過比例進入：從 70/70 變成 66/66 讀起來什麼都沒失去，所以紙片割傷和至明烈焰是免費的，打完的路線上也一樣。
- **這一局剩下的部分**。打完的路線只看到生命值和藥水。一場戰鬥的牌組、遺物或獎勵對這一局意味著什麼，都在葉節點之外。
- **同層的兄弟狀態**。日誌裡每場戰鬥只有一個結局，所以沒有標籤能分開搜尋在同一個回合裡比較的兩個狀態。分開它們的是完整計入的持有生命值，以及網路跨戰鬥學到的東西。
- **它自己的玩家**。結局屬於打出訓練對局的策略：較早的網路，帶探索，用的是打門檻時同樣的 medium 預算（[訓練戰鬥網路 §3](/zh-tw/arch/learning/combat-net/#sec-3)）。
