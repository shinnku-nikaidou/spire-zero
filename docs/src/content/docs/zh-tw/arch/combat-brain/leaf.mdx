每個搜尋都會在某處停下。PIMC 停在回合結束處；SL 規劃器通常會搜到戰鬥結束，但在知道戰鬥接下來怎麼發展之前，它也得給各回合結束處的狀態排名（[SL 規劃器：束搜尋 §1](/zh-tw/arch/sl-planner/beam/#sec-1)）。搜尋停下的狀態是**葉節點**（leaf），說出它值多少的函式是**葉節點估值**（leaf value）。一句話：葉節點是網路的結局分布乘以每種結局的價格。本頁解釋大腦有的兩種葉節點，手寫的 `LeafValue`，以及兩種環境的冠軍都用的戰鬥網路 c2（[§2](#sec-2)–[§6](#sec-6)）；c2 的已知問題（[§7](#sec-7)）；以及還沒實作的規劃中網路（[§8](#sec-8)）。

## 1. 葉節點是什麼

葉節點要麼是一個回合開始時的狀態，此時敵方回合已經真實地打完；要麼是戰鬥的結束，贏或輸。兩者由同一個函式估值，`ICombatLeaf.Value(status, observation, history)`：輸掉的戰鬥一文不值，贏下的戰鬥按它留下的東西估值，進行中的戰鬥按它預期會留下的東西估值。

- **只讀觀測**。葉節點讀玩家看得到的東西，加上敵人至今出招的公開記錄（[提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。它從不讀抽牌順序或亂數流，所以在兩種環境裡都不可能洩漏隱藏狀態。
- **同一個尺度**。它的單位就是整局的單位：贏下這一局的份額，也就是設計所說的 P(win run)（[宏觀大腦：從風險值到價值 §1](/zh-tw/arch/macro-brain/value/#sec-1)）。下面的權重只能大致做到這一點；用 V 的價格時，它就是 V 的單位（[§5](#sec-5)）。
- **排序比水準重要**。搜尋用葉節點來比較路線：重要的是更好的狀態得到更高的估值。一個把每個狀態都高估 0.1 的葉節點，打起來和沒有高估的一樣。

## 2. 手工葉節點：LeafValue

`LeafValue`（v0，`src/Sts2Ai.Brain/Combat/LeafValue.cs`）根據畫面上的東西推算戰鬥剩下的部分，用到幾個手工設定的數字。

- 輸掉的戰鬥為 0。贏下的戰鬥剩下生命值比例 $s$（生命值除以最大生命值）時，值 $\mathrm{Win}(s) = 0.2 + 0.6\,s$，每瓶還留著的藥水再加 0.02。
- 進行中的戰鬥推算到它結束。每個活著的敵人 $i$ 有一個**有效生命值** $e_i$（它的生命值加格擋，減去它身上的中毒還會造成的傷害的 0.8 倍，$n$ 層中毒是 $n + (n-1) + \dots + 1$）和一個**傷害速率** $r_i$（它本回合顯示的攻擊，傷害 × 段數，至少為 3）。玩家每回合造成 $d = 10 + 2 \times \text{力量}$ 的傷害，一個接一個地殺死敵人。
- 擊殺順序取掉血最少的那一個。敵人 $i$ 一直出手到它死去，即第 $t_i = \sum_{j \preceq i} e_j / d$ 回合（對在它之前被殺的敵人和它自己求和），所以受到的傷害是 $\sum_i r_i\, t_i$。**Smith 規則**來自排程理論，它讓這種完成時間的加權和最小：按每單位長度的權重遞減的順序處理工作，這裡就是 $r_i / e_i$。超出當前格擋的傷害，一半從生命值裡扣掉，剩下的生命值按勝利評分：

$$
\text{價值} = \mathrm{Win}\!\left(\frac{\text{生命值} - 0.5\,\max\!\big(0,\ \sum_i r_i t_i - \text{格擋}\big)}{\text{最大生命值}}\right) + 0.02 \times \text{藥水數}
$$

- 推算出死亡（比例低於 0）時，估值向 0 衰減而不是變成負數，$s < 0$ 時 $\mathrm{Win}(s) = 0.2\, e^{3 s}$，在 0 處斜率相同。它始終高於輸掉，無論局面多絕望都能給路線排序：用一個平的下限時，所有會輸的路線看起來都一樣，大腦就會過早結束回合。

所以，打在出手重、死得快的敵人身上的傷害更值錢，溢位傷害（overkill）毫無價值，而進行中的狀態永遠不會勝過它以相同生命值能達到的勝利。最後這個性質正是 SL 規劃器的上界所依賴的（[SL 規劃器：束搜尋 §2](/zh-tw/arch/sl-planner/beam/#sec-2)）。

它的盲區是它不讀的一切：敵人身上除中毒以外的能力、玩家身上除力量以外的能力、抽牌堆，以及本回合之後的每個意圖。這些數字（`LeafWeights`：WinBase 0.2、PerHp 0.6、PerPotion 0.02、Dps 10、Unblocked 0.5、MinIncoming 3、PoisonShare 0.8）是假設，從沒調過：`--leaf FILE` 讓一局、一次測試集或大腦用別的權重（`weights --leaf` 把預設值輸出成這種檔案，名為 `leaf0`），但已經沒有工具再調它們，因為策略交給學到的價值（[學習：循環 §6](/zh-tw/arch/learning/loop/#sec-6)）。

## 3. 戰鬥網路

戰鬥網路（`CombatNet`，`--combat-net FILE`）用一個從打過的戰鬥學到的預測，取代上面的推算。它讀一個回合的開始，預測在打出它訓練對局的那個策略下，戰鬥會怎樣結束。

**它讀什麼**。觀測顯示的關於這場戰鬥的一切，以詞元的形式：

- 四個牌堆（手牌、抽牌堆、棄牌堆、消耗堆）裡的每張牌：它的 id、升級次數、附魔和詛咒，以及它在哪個牌堆；
- 玩家：生命值比例、生命值、最大生命值、格擋、能量、最大能量、星辰、回合數，以及它的能力（id 和層數）；
- 每個活著的敵人：它的 id、生命值比例、生命值、最大生命值、格擋、它已經顯示過幾個回合、它的能力，以及它的**意圖槽**：它現在顯示的意圖，接著是它最近 3 個回合的意圖，最近的在前；
- 遺物、藥水，以及上下文（角色、遭遇、房間、幕）。

關於怪物的出招，沒有任何東西是手寫的。從怪物的 id、回合數和它最近的意圖，網路能從資料學到每個怪物的出招順序，以及怪物目前在這個順序裡的位置。一個實驗性的下一意圖輸出頭對 57.7% 的敵人說中了下一回合的意圖類型，重複當前意圖只有 28.9%，而它猜錯的大多是遊戲隨機擲出的招式（[NoSL PIMC §1](/zh-tw/arch/pimc/#sec-1)）。

**它怎麼讀**。一個集合編碼器（*Deep Set*，Zaheer 等人，2017：以元素向量之和為輸入的函式，對每種順序都給出相同的輸出，也能讀任意大小的集合）：每張牌是幾個學到的向量之和（它 id 的向量、升級次數乘以它 id 的升級向量、它的修飾的向量和它所在牌堆的向量），一個小 MLP 逐張處理每張牌，每個牌堆是其中各牌之和（× 1/8）。一個敵人的槽是它的意圖之和（類型的向量，加上傷害 / 10 和總傷害 / 20 分別乘以該類型的向量）；一個 MLP 處理每個敵人連同它的能力和槽，再把各個敵人加總。遺物、藥水和上下文是各自向量之和。接著兩層 256 寬的網路給出輸出頭。求和不管順序，也能讀任意數量的牌或敵人，這正是一個牌堆和一場戰鬥所需要的。

## 4. 輸出頭：戰鬥怎樣結束

輸出頭是 51 個類別上的機率分布：一個**死亡**類別，或 50 個分桶之一，分的是從這個狀態到一場勝利的戰鬥結束時**還會失去**的最大生命值比例，範圍從 −0.25（會回血的戰鬥）到 1。第二個輸出給出勝利後還會用掉的藥水數。

為什麼是「還會失去」，而不是「結束時剩下」？一個預測結束時剩下比例的網路，只學到了現在持有的生命值在那裡價值的大約一半：現在少 1 點生命值，它的估值只降 0.0038，而現在少 1 點，結束時就少整整 1 點，按 `LeafValue` 的價格是 0.0078。它的搜尋把生命值換得太便宜，沒有通過晉級門檻。預測還會發生的部分，讓現在持有的生命值完整計入，因為形成估值時正好把它加回去（同樣的狀態上每點生命值 0.0083），估值的誤差也從 0.0090 降到 0.0077（[訓練戰鬥網路 §6](/zh-tw/arch/learning/combat-net/#sec-6)）。

下圖顯示 c2 的輸出頭在它檔案裡附帶的八個回合開始上的輸出，都是留出對局裡的真實狀態；載入網路時會檢查它給出的正是這些結局，和訓練器算出的一樣（[學習：參考 §7](/zh-tw/arch/learning/reference/#sec-7)）。左邊的兩場頭目戰是難的：結局中分別有 86% 和 77% 是死亡。

在它的留出對局上，c2 的交叉熵是 1.32 nats，而總是預測訓練集頻率的是 2.00；頭目戰上最低（1.13），菁英戰上最高（2.64），菁英戰的樣本很少。它所隱含的估值和真實結局的估值相關係數是 0.959，`LeafValue` 是 0.790。

這張圖也顯示了一個缺陷。一場贏下的戰鬥不可能失去比玩家持有的更多的生命值，所以虛線右邊的每個分桶對勝利來說都不可能；但沒有任何東西告訴輸出頭這一點。在容易的狀態上它不往那裡放權重，但在兩場頭目戰裡會：眷族的勝利機率質量有 83% 在那裡，墨影幻靈的有 21%。按 `LeafValue` 的價格（戰鬥網路線性地套用它們），這些不可能的勝利算得比以 0 點生命值獲勝（0.2）還低，最深的甚至低於死亡（0）（[§7](#sec-7)）。

## 5. 給結局定價

一個分布還不是一個數字。葉節點用每種結局的價格把它變成一個數字。按 `LeafValue` 的價格（預設），設現在的生命值比例為 $s$，死亡的機率為 $p_0$，中點為 $m_k$ 的分桶 $k$ 的機率為 $p_k$，持有 $q$ 瓶藥水、勝利後用掉 $u$ 瓶：

$$
\text{價值} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02\,(q - u)
$$

死亡沒有額外的代價：它值 0。已經結束的戰鬥按 `LeafValue` 的方式估值。

**V 的價格**（`--leaf-prices v`，已實作，未使用）。對 SL 規劃器，結局也可以改用宏觀大腦的 V 來定價。每次規劃時，宿主根據決策當下的整局觀測算出價格（`EndPrices`），規劃器的 worker 用它們給每個葉節點定價（`PricedLeaf`），單位是 V 自己的單位：

- 死亡值這一局的層數（`PricedLeaf.Of` 設定 `Death = run.Floor`），這適合預測層數的 V，對今天目標是獲勝的 V 則是錯的：死亡的價格會高過任何勝利（[§7](#sec-7)）；
- 剩 $h$ 點生命值的勝利，值這一局在剩 $h$ 點生命值時的 V，取 $h$ 及以下的最大值，讓生命值較多的勝利永遠不會值得更少，這是規劃器的上界所需要的；
- 一瓶藥水的價值是少持有一瓶時 V 減少的量，對所持的各瓶取平均，至少為 0。

換一個 V 時不用重新訓練網路：只有價格改變。它需要 `--policy plan`、一個戰鬥網路和網路形式的 `--value`；NoSL 的搜尋仍用葉節點權重的價格。

**設計中的 V 價格** <Badge text="規劃中" variant="caution" />。價格在網路之外：死亡值 0，勝利值剩下生命值時的 V，一瓶藥水值少一瓶時 V 減少的量。`Death` 必須先修好，這些價格要先通過自己的門檻，才會有冠軍使用，這是[戰鬥大腦 §6](/zh-tw/arch/combat-brain/#sec-6) 順序的最後一步。第一個網路 `sl-c1` 保留今天的手工價格。這些價格只看生命值和藥水數量，所以戰鬥改變的其他東西都沒有計價：被偷的金幣、被拿走的牌、最大生命值的變化，以及用掉的是哪一瓶藥水。用 V 為 SL 的確切結束狀態定價是一個選項，放在這同一步權衡。

## 6. 每個環境一個網路

網路預測的是打出它那些對局的策略下的結局。SL 的規劃器看得到 NoSL 的搜尋必須猜的東西，從同一個狀態出發贏下的戰鬥更多，所以權重屬於單一環境，而結構共用：網路檔案寫明它的環境，另一個環境的對局會拒絕它。c1–c4 早於這個欄位，沒有寫明任何環境。

這留下一處沒有接好的縫：c2 是從 PIMC 用 `LeafValue` 打的 NoSL 戰鬥學來的，卻也是 SL 規劃器的葉節點。它的結局是一個比規劃器弱的玩家的結局。還沒有任何 SL 訓練的網路過過門檻。<Badge text="規劃中" variant="caution" /> SL 自己的第一個網路是 `sl-c1`，來自 SL 自我對弈（[訓練戰鬥網路 §7](/zh-tw/arch/learning/combat-net/#sec-7)）；NoSL 目前仍用 c2。

## 7. c2 的已知問題

c2 由提交 `b4480a1` 時的 `train_combat.py`（此後已移除）在 315 局 NoSL 對局上寫出。對照冠軍的整局 SL（v7-1f，`promotion-1-100` 上 100 局，60 次死亡：52 次在頭目戰，6 次在菁英戰，2 次在普通戰鬥），它有這些缺口：

- **第 3 幕不在它的詞表裡**。它的訓練對局只到第 1 和第 2 幕，所以榮耀的 18 個遭遇沒有一個有自己的 id，而 60 次死亡裡有 32 次發生在它詞表之外的遭遇。121 個怪物裡也缺 46 個，268 個能力裡缺 195 個；其中並非全都碰得到寂靜獵手，它們多常出現也沒有量測過。
- **未知的能力會相撞**。詞表外的每個能力都讀作同一個未知詞元，所以塗毒、爆發、行家工具和計畫妥當給出相同的輸出。在墨影幻靈的測試狀態上，這值 0.0083 的估值，約 1 點生命值。
- **全未知的戰鬥還讀得到什麼**。幕、遭遇和敵人都未知時，生命值和中毒的斜率仍保持正負號：30 層中毒加 0.167，已知時是 0.278。
- **不可能的分桶可能讓估值低於死亡**。沒有任何東西遮掉超過持有生命值的分桶（[§4](#sec-4)）。
- **它沒看過規劃器打**。它的標籤是 PIMC 的結局（[§6](#sec-6)）。
- **手牌好壞幾乎不影響估值（只測了一個狀態）**。在 Vantom 測試狀態上，用 torch 重建的 c2，手裡 5 張打擊對比 5 張傷口，估值只變 0.007，而敵人少 30 生命值，估值變 0.051。原因是資料還是結構，尚無定論。中毒相對敵人生命值學得合理。這只是一個狀態的結果。

沒有量測的：c2 在 SL 回合開始上的校準、真實牌組裡未知 id 的比例，以及更大的束或別的葉節點能把多少死亡變成勝利。

## 8. 規劃中的網路 <Badge text="規劃中" variant="caution" />

本節的內容都沒有實作，也沒有量測過。結構是 `learn/combat/net.py` 加上小改動。

### 8.1 它讀什麼

輸入規則：**只讀無法從 id 學到、又會改變未來的東西**。

| 輸入 | 讀 | 相對於 `learn/combat/encode.py` |
|---|---|---|
| 牌 | id、升級、牌堆、修飾的 id 和數值、當前費用 | 加上當前費用，它會被效果改變，id 也看不出來；加上每個修飾的數值（`ModifierView.Amount`），23 種附魔中有 11 種用到它，例如鋒利 |
| 玩家 | 生命值比例、生命值、最大生命值、格擋、能量、最大能量、星辰、回合數 | 相同 |
| 能力 | id、數值、層數、保存的牌 | 相同 |
| 敵人 | id、生命值比例、生命值、最大生命值、格擋、已顯示的回合數、能力、當前意圖 | 如果留出交叉熵允許，拿掉 3 個滯後的意圖槽；否則保留 |
| 遺物 | id、計數、狀態 | 加上計數和狀態（42 種遺物會設定狀態），id 都看不出來。狀態是獨立的輸入，不是 id 的後綴 |
| 藥水、遭遇、充能球、盟友 | 它們的 id；盟友的數字和能力 | 上下文縮小到遭遇 |
| 2 個數字 | 晉階、充能球槽數 | 拿掉金幣 |

**不讀**：印著的數字，它們由 id 和升級決定；金幣，直到量測證明它有用；幕、房間和角色，遭遇和牌已隱含它們；抽牌順序，因為網路讀的是玩家看得到的東西（SL 的有序抽牌是另一個較晚的實驗）。

修飾的數值和遺物狀態經由計算圖輸入 `mod_amounts` 和 `relic_status` 進入，`NetNumbers` 已經在提供它們。對寂靜獵手，牌的 `Vars` 仍然不讀：只有 Claw、Rampage、Maul、Thrash、KinglyPunch、SovereignBlade 和 TheBall 會在戰鬥中改變自己的數值，它們都不在寂靜獵手的牌池裡。

**觀察的限制**。每場戰鬥的遺物旗標（例如百年積木的）根本不在觀察裡，所以任何輸入規則都讀不到。

詞表從會到達第 3 幕的 v7g1 重建。訓練時加一點 id dropout，讓 `<unk>` 成為網路學過的詞元，於是它沒見過的 id 不再表現得毫無章法。

嵌入 32 維。一張牌經過 32 → 64 → 64 的 MLP，按牌堆求和再 × 1/8：一共 256 個數字。玩家是 8 個數字。能力經過 32 → 64 的 MLP 後求和：64。一個敵人是 128 個數字（32 + 64 + 32），經過 128 → 128 → 128 的 MLP，再求和：128；如果滯後的槽留下，輸入是 224。遺物、藥水、遭遇和充能球各 32，盟友 64，外加 2 個額外的數字。主幹 650 → 256 → 256 讀入它們。

輸出頭有 51 個類別，一個死亡和 50 個還要失去的生命值比例分桶，和現在一樣，但超過持有生命值的分桶**在訓練和估值時都遮掉**，所以 [§4](#sec-4) 的缺陷不可能出現。藥水輸出頭給出一個數字。沒有策略輸出頭。

在假定的詞表上約 340,000 個參數，這是估算。寬度會在更大的資料上以這個大小的 1、2、4 倍重新量測，因為寬度無關緊要的舊結果來自 315–505 局，而且只依據交叉熵（[§8.4](#sec-8.4)）（[訓練戰鬥網路 §6](/zh-tw/arch/learning/combat-net/#sec-6)）。新增的兩個輸入併入牌和遺物的 32 維加總，所以維度不變；它們的小表不改變約 340,000 這個估算。

### 8.3 搜尋裡的網路

網路一次讀一個狀態。`TurnEnds` 列出一個回合的各個結束狀態，葉節點給每個估值：搜尋和網路只在那裡相遇（[戰鬥大腦 §3](/zh-tw/arch/combat-brain/#sec-3)）。它花多少時間不是問題：遊戲模擬的開銷遠大於網路（[提示、招式與 worker §3](/zh-tw/arch/combat-brain/shared/#sec-3)）。

### 8.4 如何比較網路

整體的留出交叉熵主要反映這是哪場戰鬥、玩家有多少生命值，而束要排序的是同一場戰鬥裡的狀態。所以比較時在它之外再報告兩項：**(遭遇, 回合) 分組內的等級相關**，以及一組**固定探針**：改變一個狀態的手牌、抽牌堆、能力和中毒，看估值怎麼變化。這兩項只作參考，由配對門檻決定。
