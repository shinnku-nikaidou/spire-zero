每個搜尋都會在某處停下。PIMC 停在回合結束處；SL 規劃器通常會搜到戰鬥結束，但在知道戰鬥接下來怎麼發展之前，它也得給各回合結束處的狀態排名（[SL 規劃器：束搜尋 §1](/zh-tw/arch/sl-planner/beam/#sec-1)）。搜尋停下的狀態是**葉節點**（leaf），說出它值多少的函式是**葉節點估值**（leaf value）。本節解釋大腦有的兩種葉節點：手寫的 `LeafValue`，以及從打過的戰鬥學到的戰鬥網路。兩種環境的冠軍都用戰鬥網路 c2。

## 1. 葉節點是什麼

葉節點要麼是一個回合開始時的狀態，此時敵方回合已經真實地打完；要麼是戰鬥的結束，贏或輸。兩者由同一個函式估值，`ICombatLeaf.Value(status, observation, history)`：輸掉的戰鬥一文不值，贏下的戰鬥按它留下的東西估值，進行中的戰鬥按它預期會留下的東西估值。

- **只讀觀測**。葉節點讀玩家看得到的東西，加上敵人至今出招的公開記錄（[提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。它從不讀抽牌順序或亂數流，所以在兩種環境裡都不可能洩漏隱藏狀態。
- **同一個尺度**。它的單位就是整局的單位：贏下這一局的份額，也就是設計所說的 P(win run)（[學習 §1](/zh-tw/arch/learning/#sec-1)）。下面的權重只能大致做到這一點；用 V 的價格時，它就是 V 的單位（[§5](#sec-5)）。
- **排序比水準重要**。搜尋用葉節點來比較路線：重要的是更好的狀態得到更高的估值。一個把每個狀態都高估 0.1 的葉節點，打起來和沒有高估的一樣。

## 2. 手工葉節點：LeafValue

`LeafValue`（v0，`src/Sts2Ai.Brain/Combat/LeafValue.cs`）根據畫面上的東西推算戰鬥剩下的部分，用到幾個手工設定的數字。

- 輸掉的戰鬥為 0。贏下的戰鬥剩下生命值比例 $s$（生命值除以最大生命值）時，值 $\mathrm{Win}(s) = 0.2 + 0.6\,s$，每瓶還留著的藥水再加 0.02。
- 進行中的戰鬥推算到它結束。每個活著的敵人 $i$ 有一個**有效生命值** $e_i$（它的生命值加格擋，減去它身上的中毒還會造成的傷害的 0.8 倍，$n$ 層中毒是 $n + (n-1) + \dots + 1$）和一個**傷害速率** $r_i$（它本回合顯示的攻擊，傷害 × 段數，至少為 3）。玩家每回合造成 $d = 10 + 2 \times \text{力量}$ 的傷害，一個接一個地殺死敵人。
- 擊殺順序取掉血最少的那一個。敵人 $i$ 一直出手到它死去，即第 $t_i = \sum_{j \preceq i} e_j / d$ 回合（對在它之前被殺的敵人和它自己求和），所以受到的傷害是 $\sum_i r_i\, t_i$。**Smith 規則**來自排程理論，它讓這種完成時間的加權和最小：按每單位長度的權重遞減的順序處理工作，這裡就是 $r_i / e_i$。超出當前格擋的傷害，一半從生命值裡扣掉，剩下的生命值按勝利評分：

$$
\text{價值} = \mathrm{Win}\!\left(\frac{\text{生命值} - 0.5\,\max\!\big(0,\ \sum_i r_i t_i - \text{格擋}\big)}{\text{最大生命值}}\right) + 0.02 \times \text{藥水數}
$$

- 推算出死亡（比例低於 0）時，估值向 0 衰減而不是變成負數，$s < 0$ 時 $\mathrm{Win}(s) = 0.2\, e^{3 s}$，在 0 處斜率相同。它始終高於輸掉，無論局面多絕望都能給路線排序：用一個平的下限時，所有會輸的路線看起來都一樣，大腦就會過早結束回合。

所以，打在出手重、死得快的敵人身上的傷害更值錢，溢位傷害（overkill）毫無價值，而進行中的狀態永遠不會勝過它以相同生命值能達到的勝利。最後這個性質正是 SL 規劃器的上界所依賴的（[SL 規劃器：束搜尋 §2](/zh-tw/arch/sl-planner/beam/#sec-2)）。

它的盲區是它不讀的一切：敵人身上除中毒以外的能力、玩家身上除力量以外的能力、抽牌堆，以及本回合之後的每個意圖。這些數字（`LeafWeights`：WinBase 0.2、PerHp 0.6、PerPotion 0.02、Dps 10、Unblocked 0.5、MinIncoming 3、PoisonShare 0.8）是假設，從沒調過：`--leaf FILE` 讓一局、一次測試集或大腦用別的權重（`weights --leaf` 把預設值輸出成這種檔案，名為 `leaf0`），但已經沒有工具再調它們，因為策略交給學到的價值（[學習 §2](/zh-tw/arch/learning/#sec-2)）。

## 3. 戰鬥網路

戰鬥網路（`CombatNet`，`--combat-net FILE`）用一個從打過的戰鬥學到的預測，取代上面的推算。它讀一個回合的開始，預測在打出它訓練對局的那個策略下，戰鬥會怎樣結束。

**它讀什麼**。觀測顯示的關於這場戰鬥的一切，以詞元的形式：

- 四個牌堆（手牌、抽牌堆、棄牌堆、消耗堆）裡的每張牌：它的 id、升級次數、附魔和詛咒，以及它在哪個牌堆；
- 玩家：生命值比例、生命值、最大生命值、格擋、能量、最大能量、星辰、回合數，以及它的能力（id 和層數）；
- 每個活著的敵人：它的 id、生命值比例、生命值、最大生命值、格擋、它已經顯示過幾個回合、它的能力，以及它的**意圖槽**：它現在顯示的意圖，接著是它最近 3 個回合的意圖，最近的在前；
- 遺物、藥水，以及上下文（角色、遭遇、房間、幕）。

關於怪物的出招，沒有任何東西是手寫的。從怪物的 id、回合數和它最近的意圖，網路能從資料學到每個怪物的出招順序，以及怪物目前在這個順序裡的位置。在帶有下一意圖輸出頭時（此後已拿掉），它對 57.7% 的敵人說中了下一回合的意圖類型，重複當前意圖只有 28.9%，而它猜錯的大多是遊戲隨機擲出的招式（[NoSL PIMC §1](/zh-tw/arch/pimc/#sec-1)）。

**它怎麼讀**。和宏觀大腦的 V 一樣的集合編碼器（[宏觀大腦：價值網路 §2](/zh-tw/arch/macro-brain/network/#sec-2)）：每張牌是幾個學到的向量之和（它 id 的向量、升級次數乘以它 id 的升級向量、它的修飾的向量和它所在牌堆的向量），一個小 MLP 逐張處理每張牌，每個牌堆是其中各牌之和（× 1/8）。一個敵人的槽是它的意圖之和（類型的向量，加上傷害 / 10 和總傷害 / 20 分別乘以該類型的向量）；一個 MLP 處理每個敵人連同它的能力和槽，再把各個敵人加總。遺物、藥水和上下文是各自向量之和。接著兩層 256 寬的網路給出輸出頭。求和不管順序，也能讀任意數量的牌或敵人，這正是一個牌堆和一場戰鬥所需要的。

## 4. 輸出頭：戰鬥怎樣結束

輸出頭是 51 個類別上的機率分布：一個**死亡**類別，或 50 個分桶之一，分的是從這個狀態到一場勝利的戰鬥結束時**還會失去**的最大生命值比例，範圍從 −0.25（會回血的戰鬥）到 1。第二個輸出給出勝利後還會用掉的藥水數。

為什麼是「還會失去」，而不是「結束時剩下」？第一個網路 c1 預測的是結束時剩下的比例。它只學到了現在持有的生命值在那裡價值的大約一半：現在少 1 點生命值，它的估值只降 0.0038，而現在少 1 點，結束時就少整整 1 點，按 `LeafValue` 的價格是 0.0078。它的搜尋於是把生命值換得太便宜，在普通戰和菁英戰裡掉的血比冠軍多（每場勝利 7.8 對 6.5、26.4 對 18.0 點生命值），沒有通過晉級門檻。預測還會發生的部分，讓現在持有的生命值完整計入，因為形成估值時正好把它加回去（同樣的狀態上每點生命值 0.0083），估值的誤差也從 0.0090 降到 0.0077。

下圖顯示 c2 的輸出頭在它檔案裡附帶的八個回合開始上的輸出，都是留出對局裡的真實狀態；載入網路時會檢查它給出的正是這些結局，和訓練器算出的一樣（[學習 §7](/zh-tw/arch/learning/#sec-7)）。左邊的兩場頭目戰是難的：結局中分別有 86% 和 77% 是死亡。

在它的留出對局上，c2 的交叉熵是 1.32 nats，而總是預測訓練集頻率的是 2.00；頭目戰上最低（1.13），菁英戰上最高（2.64），菁英戰的樣本很少。它所隱含的估值和真實結局的估值相關係數是 0.959，`LeafValue` 是 0.790。

這張圖也顯示了一個缺陷。一場贏下的戰鬥不可能失去比玩家持有的更多的生命值，所以虛線右邊的每個分桶對勝利來說都不可能；但沒有任何東西告訴輸出頭這一點。在容易的狀態上它不往那裡放權重，但在兩場頭目戰裡會：眷族的勝利機率質量有 83% 在那裡，墨影幻靈的有 21%。按 `LeafValue` 的價格（戰鬥網路線性地套用它們），這些不可能的勝利算得比以 0 點生命值獲勝（0.2）還低，最深的甚至低於死亡（0），所以這個狀態的估值保持很低，在那裡這是應該的，但理由不對。一個知道這個限制的輸出頭（遮掉超過持有生命值的分桶）會把這部分質量放到它該在的地方：死亡，或險勝。

## 5. 給結局定價

一個分布還不是一個數字。葉節點用每種結局的價格把它變成一個數字。按 `LeafValue` 的價格（預設），設現在的生命值比例為 $s$，死亡的機率為 $p_0$，中點為 $m_k$ 的分桶 $k$ 的機率為 $p_k$，持有 $q$ 瓶藥水、勝利後用掉 $u$ 瓶：

$$
\text{價值} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02\,(q - u)
$$

死亡沒有額外的代價：它值 0。已經結束的戰鬥按 `LeafValue` 的方式估值。

**V 的價格**（`--leaf-prices v`，已實作，尚未通過晉級門檻）。對 SL 規劃器，結局也可以改用宏觀大腦的 V 來定價。每次規劃時，宿主根據決策當下的整局觀測算出價格（`EndPrices`），規劃器的 worker 用它們給每個葉節點定價（`PricedLeaf`），單位是 V 自己的單位：

- 死亡值這一局的層數（這一局在那裡結束）；
- 剩 $h$ 點生命值的勝利，值這一局在剩 $h$ 點生命值時的 V，取 $h$ 及以下的最大值，讓生命值較多的勝利永遠不會值得更少，這是規劃器的上界所需要的；
- 一瓶藥水的價值是少持有一瓶時 V 減少的量，對所持的各瓶取平均，至少為 0。

換一個 V 時不用重新訓練網路：只有價格改變。它需要 `--policy plan`、一個戰鬥網路和網路形式的 `--value`；NoSL 的搜尋仍用葉節點權重的價格。

## 6. 每個環境一個網路

網路預測的是打出它那些對局的策略下的結局。SL 的規劃器看得到 NoSL 的搜尋必須猜的東西，從同一個狀態出發贏下的戰鬥更多，所以每個環境都需要自己的網路：網路檔案寫明它的環境，另一個環境的對局會拒絕它。c1–c4 早於這個欄位，沒有寫明任何環境。

這留下一處沒有接好的縫：c2 是從 PIMC 用 `LeafValue` 打的 NoSL 戰鬥學來的，卻也是 SL 規劃器的葉節點。它的結局是一個比規劃器弱的玩家的結局，所以它對困難狀態的評分往往比規劃器實際打出來的低。SL 自己的第一個網路（`sl-c1`，來自列為 `sl-combat` 的 819 局 SL 對局）還沒有訓練（[SL 規劃器：預算 §6](/zh-tw/arch/sl-planner/budget/#sec-6)）。

另外兩種葉節點規劃過，但沒有實作：手工特徵乘以線性權重，以 bottled_ai 的 42 個特徵為起點，用 SPSA 調校；以及從葉節點推演到戰鬥結束，這在 r33hab 裡小預算下勝過了價值輸出頭（[NoSL PIMC：預算 §7](/zh-tw/arch/pimc/budget/#sec-7)）。
