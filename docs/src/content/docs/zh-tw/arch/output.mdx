大腦用一個動作、一份計畫，以及它打過分的那些選項來回答一個決策。**輸出層**把這個答案變成玩家看得到的東西，或者在玩家要求時，變成遊戲實際做出的事。它在遊戲行程裡的 [Mod](/zh-tw/arch/mod/) 中執行，每種輸出模式讀的都是同一個 `Recommendation`：大腦從不知道開著的是哪種模式。本頁寫給想改變玩家所見內容的人。[Mod：主迴圈](/zh-tw/arch/mod/loop/)說明何時詢問答案，以及答案顯示多久。

<Aside title="狀態">

已實作：**面板**（[§2](#sec-2)），蓋在遊戲上的一張卡片，有一個讓 AI 來打的工具列，顯示 V 對贏下這一局的機率、下一個動作連同預期這場戰鬥或這一局在它之後會怎麼走、之後的計畫，以及大腦打過分的選項和它們的獲勝機率（在地圖上連同每個選項的路線）；它的**設定**，在 Mod 加進遊戲設定畫面的「AI」分頁裡；六種語言的 Mod 用語；兩種**標記**（[§3](#sec-3)）：在地圖上，推薦的點上有一個圓圈，大腦在它之後規劃的路線上有一條線，一直到頭目；在戰鬥中，計畫在本回合要打的卡牌上、它的目標上和結束回合按鈕上，標出步驟編號；以及**自動**（[§4](#sec-4)），玩家要求時由 AI 打出答案。規劃中：其他決策介面上的標示、解說（[§5](#sec-5)），以及它所需要的事實。Godot 節點類別（`N*` 型別）只按類別名稱引用：每個名稱在反編譯原始碼裡都是唯一的，按名稱就能找到檔案。

</Aside>

## 1. 約定

輸出層讀取一則訊息 `Recommendation`（[協定：線路 §7](/zh-tw/arch/protocol/wire/#sec-7)），目前實作的樣子如下（`Sts2Ai.Protocol/Wire.cs:64-65`）：

| 欄位 | 內容 | 由誰提供 |
|---|---|---|
| `decision_id`、`obs_hash` | 它回答的決策 | |
| `action` | 現在要採取的動作 | 每個大腦 |
| `brain` | 回答的大腦，用 Harness 給它的名字（[Harness：路由、預算與種子 §1](/zh-tw/arch/harness/routing/#sec-1)） | |
| `plan`? | 大腦在 `action` 之後規劃的內容 | PIMC：本回合剩下的部分，取第一個世界的；SL 規劃器：這場戰鬥剩下的部分；地圖上的 L0：通往頭目的路線；其他畫面都沒有，選牌提示也沒有 |
| `candidates`? | 大腦打過分的選項，選中的排第一：每個帶有它的估值、95% 信賴區間的半寬和樣本數；SL 規劃器的還帶有贏下這場戰鬥的機率和剩下的 HP；在地圖上還帶有這個選項的路線（[協定：線路 §7](/zh-tw/arch/protocol/wire/#sec-7)） | 戰鬥大腦；戰鬥外的 L0（V 對贏下這一局的機率），它探索時沒有 |

`plan` 排在 `action` *之後*：下一步是 `action`，`plan[0]` 是再下一步。

**消費者**。大腦從不知道開著的是哪種模式。

| 模式 | 消費者 | 狀態 |
|---|---|---|
| 面板（輔助，簡單版） | 所有決策介面共用一張卡片（[§2](#sec-2)） | 已實作 |
| 標記（輔助） | 地圖的圓圈和路線；戰鬥計畫的編號和圓圈（[§3](#sec-3)） | 已實作 |
| 工具列 | AI 打出 `action`：一步、打到回合或房間結束，或者自己一直打（[§4](#sec-4)） | 已實作 |
| 自動 | 執行器打出 `action`，每個狀態一次，然後 Mod 重新觀測（[§4](#sec-4)、[Mod：自動遊玩與安全 §1](/zh-tw/arch/mod/auto/#sec-1)） | 已實作 |
| 標示（輔助，進階版） | 其他決策介面的節點，像執行器找到它們的按鈕那樣找到（[§3](#sec-3)） | 規劃中 |

*決策介面*（surface）是正在顯示的決策畫面的種類（戰鬥、地圖、商店、選牌提示等）。*錨點*（anchor）是畫面上某個動作所屬的 Godot 節點，例如要打出的那張牌的卡牌槽。

**過期的答案**。答案按 id 和開著的決策配對，並為被詢問的那個鍵保存：觀測的雜湊加上它的合法動作。它只在這個鍵持續的影格上畫出來；畫面往前走時，面板為新的狀態顯示「思考中…」，Mod 重新詢問（[Mod：主迴圈 §3](/zh-tw/arch/mod/loop/#sec-3)）。Mod 從不讀答案的 `obs_hash`。

**規劃中**。

- **事實**：解釋可以引用的數字，作為推薦的一個欄位；這是解說唯一的來源（[§5](#sec-5)）。程式碼裡還沒有任何 `Facts`。
- **隨時可答**：輔助模式下，大腦先送出目前最好的答案，再陸續送出更好的，每一個替換前一個（[Harness：路由、預算與種子 §4](/zh-tw/arch/harness/routing/#sec-4)）。目前大腦每個決策只送一個答案，Mod 收到第一個時就結束這個決策。

## 2. 面板

面板是蓋在遊戲上的一張卡片，靠近左上角（`UI/Panel.cs`）。它有自己的 `CanvasLayer`，這是 Godot 的一種節點，把它的子節點畫在單獨的一層上：第 100 層，在遊戲的 UI 之上，所有標記都共用這一層。除了它的按鈕上的點選之外，卡片不接收任何點選，所以點選會傳到它下面的遊戲。F8 會連同所有標記一起隱藏和顯示它。

<PanelMock client:visible lang="zh-TW" />

**版面**，從上到下（`UI/Panel.cs`）：

- **卡片**：位於 (24, 132)，至少 340 px 寬，12 px 的內距（左右兩側 14），圓角半徑 14，深紫色邊框，一層陰影，以及按不透明度設定填上的近黑色底色。一行很長的文字可以把它撐寬。它的文字是 11 到 17 px，用遊戲為它的語言所用的字型（`UI/Fonts.cs`），戰鬥標記上的數字也是：中文、日文、韓文、俄文和泰文用遊戲的替代字型，其他語言用 Kreon。遊戲在 1920×1080 的畫布上排版，再拉伸到視窗大小，並關閉字型的超取樣；它自己的字型是 MSDF 字型，在任何縮放下都保持清晰，而引擎的預設字型會以 1080p 畫出再被拉伸，變得模糊。
- **標頭**：一個紫色的「AI」徽標；冠軍的名字，以及它下面的狀態，各佔一行，空間不夠的地方以省略號截斷；SL/NoSL 開關，選中的一邊填上紫色（多人模式下兩邊都不選，Mod 關閉時沒有開關）；還有「F8」。大腦接下這一局之後，狀態就是這一局自己的那一行：角色、晉階、層數和 HP（[Mod §6](/zh-tw/arch/mod/#sec-6)）。
- **工具列**，除錯器的樣式，在大腦接下這一局之後出現：三個按鈕，32 px 高，每個是一個圖示加一個詞。Mod 自己畫這些圖示（`UI/Icons.cs`：播放、暫停、單步、完成），畫成顯示大小 15 px 的三倍，所以畫布的縮放不會讓它們變糊。第一個是「自動」（F5），自動遊玩進行時是「暫停」；第二個打一步（F10）：戰鬥中是「打一張」，地圖上是「走一步」，其他地方是「幫我選」；第三個打完（F11）：「打完回合」、「打完下一房」、「走完房間」。自動遊玩進行時，另外兩個停用（[Mod：自動遊玩與安全 §2](/zh-tw/arch/mod/auto/#sec-2)）。
- **力度那一列**，在工具列下方：「思考深度」和五個切換鈕，大腦自己的，以及 SL 規劃器的四個等級（[Mod §5](/zh-tw/arch/mod/#sec-5)）。
- **自動遊玩進行時**，再多兩列：「速度」，慢、中或快；以及「停在」，兩個切換鈕，「菁英、頭目前」和「勝率掉 3 點」。
- **橫條**：「本局勝率」和 V 對贏下這一局的機率，以大字顯示，連同它相對於上一個戰鬥外答案的變化，以百分點計：綠色的「+0.6」或紅色的「-2.6」。它的右邊是一個顯示 AI 狀態的膠囊：「等你操作」、「自動中」（一個綠點）、目標進行時的「執行中」，或琥珀色的「AI 停下了：原因」。這個機率是最近一個戰鬥外答案裡選中選項的值（V 的，[宏觀大腦：搜尋 §1](/zh-tw/arch/macro-brain/search/#sec-1)），所以它在每個戰鬥外的決策處變動，整場戰鬥中保持不變；在這一局的第一個這類答案之前，橫條上只有膠囊。
- **答案**：「下一步」，然後是下一個動作，以大字顯示在一個實心的「1」徽標之後（在地圖上用圓圈代替徽標）。它下面有一行較淡的文字：在戰鬥外是「整局勝率 87.7%」，V 對這個動作之後贏下這一局的機率；在戰鬥中是「這場勝率 100% · 剩 53 HP」，SL 規劃器在它選中的路線上贏下這場戰鬥的機率，以及勝利時保有的 HP，只要照著計畫打就一直保留。接著，在地圖上是「到頭目的路線」和以圓點連起來的路線房間，除非下面的選項已經顯示了各條路線；其他地方是計畫的各個步驟，在空心圓徽標裡從 2 開始編號；然後是計畫後面的回合，「之後還規劃 11 回合」（[Mod：主迴圈 §6](/zh-tw/arch/mod/loop/#sec-6)）。
- **考慮過的選項**，在一條分隔線下方：大腦打過分的選項中最多五個，選中的排第一，用淡紫色，其餘最好的在前。欄位取決於值是什麼：

  | 答案 | 欄位 |
  |---|---|
  | SL 規劃器回答的戰鬥（它的候選帶有 `win`） | 「勝率」，在這個選項的最佳路線上贏下這場戰鬥的機率，以整數百分比表示；「剩 HP」，那次勝利時保有的 HP，沒有獲勝機率時是「—」 |
  | 戰鬥外（L0，由 V 估值） | 「勝率」，V 對選了這個選項之後贏下這一局的機率，到小數點後一位；「差」，它和最好的選項相差的百分點，選中的和最好的是「—」 |
  | PIMC 回答的戰鬥 | 「分數 ±CI」，平均分數到小數點後三位，以及它 95% 區間的半寬 |

  開啟長條時，每一列還有一條 56 px 的軌道，估值處有一道短標記，選中的那個是紫色；PIMC 的標記橫跨整個區間，估值處再畫一道標線。各列共用同一個比例尺：從最低的值到最高的值（包括區間），兩側各放寬這段跨度的 15%，而且至少半個百分點；戰鬥的比例尺會延伸到 100%。PIMC 的答案只在它為不只一個動作打分時才顯示這份清單；另外兩種只有一個選項也會顯示。照著計畫打出的一步沒有選項。
- **在地圖上**，每個選項在「到頭目的路線」底下佔一列：路線畫成 16 px 的房間小方塊，從這個選項自己的點一直到頭目，然後是它的獲勝機率和差距，沒有長條；在這些列下方，有一份所顯示房間種類的圖例，用地圖圖例的名字。小方塊是一個用它種類的顏色描邊的小正方形，裡面是它圖例名字的第一個字（未知房間是「?」），頭目的填成紅色；選中路線上的普通房間比其他路線的亮。藥水欄的藥水在地圖上也是選項，它沒有路線：它那一列只有一個「?」小方塊。
- **底部**：回答的大腦，以及 Mod 從送出到收到為止等了它幾秒。
- **訊息**（代替答案）：一個圓點、訊息本身，以及較淡的第二行；玩家能自行解決或等它過去的情況用琥珀色，錯誤用紅色。所有訊息都列在 [Mod §6](/zh-tw/arch/mod/#sec-6)。
- **最近**：AI 打過之後，「剛才做了」和它最近的四個動作，最新的在前：層數、動作，以及它的答案的值，V 的獲勝機率或這場戰鬥的。

橫條和最近動作在顯示訊息時也會出現。內文只在它顯示的內容改變，或者繪製它所用的設定改變時才重建；工具列的標籤在遊戲的語言改變時立刻跟著改變；標記則每個影格都跟著它們的節點。

**設定**。玩家的選擇存在 `$XDG_STATE_HOME/sts2ai`（預設是 `~/.local/state/sts2ai`）裡的 `settings.json`，和大腦的日誌放在一起，不在遊戲的玩家檔案裡；每一列、它的值和預設值都在 [Mod §5](/zh-tw/arch/mod/#sec-5)。面板和標記即時讀取設定，所以改動會立刻生效。

**AI 分頁**（`UI/SettingsTab.cs`）位於遊戲的設定畫面裡，排在一般、圖形、聲音和輸入之後。遊戲在 `NSettingsTabManager._Ready` 裡用它場景中的節點建出四個分頁。那裡的一個後綴在下一次空閒時執行，好讓畫面已經完整；它複製輸入分頁作為新分頁的按鈕，複製聲音面板並清空作為它的面板，所以兩者的外觀和切換方式都和遊戲自己的一樣；複製的是節點和它們的腳本，不包括遊戲的訊號連接。它把分頁列向左移半格，讓它保持置中，把按鈕接到管理器自己的分頁切換上，並把這一對加進管理器的分頁裡。各列是 Mod 自己的控制項，用的是遊戲設定列的字型，分在兩個標題底下，「輔助」和「自動打」：`<  value  >` 切換器、一個不透明度滑桿，以及一個重設它們的按鈕。所有東西都在加入畫面之前建好，所以萬一建置失敗，畫面會保持遊戲建出的樣子，錯誤則記入日誌。

**語言**（`UI/L10n.cs`）。Mod 自己的用語跟隨遊戲設定的語言：英文、法文、西班牙文（遊戲的兩種西班牙文都算）、簡體中文、繁體中文和日文；其他任何語言都顯示英文。每一行按它的英文文字查找，表裡缺少的行也就顯示這段英文。名字（卡牌、遺物、藥水、怪物、角色、事件、休息選項、地圖圖例的房間種類）則來自遊戲自己的表（[Mod：主迴圈 §6](/zh-tw/arch/mod/loop/#sec-6)）。不是 Mod 寫的東西照它來的樣子顯示：大腦的名字和它的錯誤訊息、例外的文字，以及版本守衛的那一行。

**面板規劃中的內容**：每個答案 1–2 條事實（與替代打法相比的預期 HP 損失、下回合能否斬殺），也是解說唯一會用的數字（[§5](#sec-5)）；以及 [§3](#sec-3) 的各決策介面標示，例如把每個卡牌獎勵的獲勝機率標在它的牌上。

## 3. 標示

**跟隨式覆蓋層**。標記由 Mod 自己的節點畫出，這些節點只存在於 Mod 的 `CanvasLayer` 裡，蓋在遊戲上面。每個影格，每個標記讀取目標節點在畫面上的變換（`GetGlobalTransformWithCanvas()`）和節點的尺寸，所以能跟著一張旋轉、展開或縮放的牌，隨它移動；目標消失或隱藏時，標記也隱藏。Mod 從不為了繪製而寫入遊戲的節點，原因有二：`NHandCardHolder.UpdateCard()` 在每次狀態變化時都會重設 `CardHighlight` <Badge text="已核實" variant="success" />；而且青色、金色和紅色的光暈在遊戲裡已經各有含義（`NCardHighlight`）。Mod 唯一會為了繪製而改動遊戲節點的地方是設定畫面（[§2](#sec-2)）；AI 來打時，執行器像點選那樣按下遊戲自己的按鈕（[Mod：自動遊玩與安全 §1](/zh-tw/arch/mod/auto/#sec-1)）。

**樣式**：紫色，遊戲自己的光暈不用這個顏色：描邊、圓圈，以及帶有普通數字和深色外圈的紫色圓形徽標。

**在地圖上**（`UI/MapMark.cs`）：下一個點上有一個脈動的紫色圓圈，在它之後路線的每段路徑上各有一條紫色的線，從玩家所在之處一直到路線的終點。地圖畫面把它的點節點和每段路徑的小點存在私有字典裡，新的一幕會換掉它們；一條線從一段路徑的第一個小點畫到最後一個，所以會在點的圖示之前停住。圓圈的半徑是點的較長邊的一半再加 14，隨地圖縮放，每秒脈動一次，幅度 ±10%。路線設定可以顯示整條路線、只顯示圓圈，或什麼都不顯示：

**在戰鬥中**（`UI/CombatMark.cs`）：面板所顯示的計畫，從 `action` 到本回合結束。

- 計畫要打的每張牌，在它的卡牌槽的點選範圍（hitbox）上畫紫色描邊，右上角標出它那一步的編號；
- 每個目標（敵人或盟友）在它的生物節點的點選範圍上描邊，向外 10 px，所有瞄準它的步驟的編號放在上緣中間的一個徽標裡；
- 結束回合按鈕描邊，並標出它那一步的編號。

已經不在的牌或生物沒有標記。「卡牌上的出牌順序」會把卡牌的描邊和編號一起關掉；「目標與結束回合標記」管其餘的部分。藥水沒有自己的標記，但它的目標會得到它那一步的編號。

**錨點**。每個決策介面的節點，都在反編譯的遊戲原始碼裡核實過 <Badge text="已核實" variant="success" />：

- 螢幕解析度、UI 縮放和手把操作：只用畫面上的變換，絕不用局部座標。
- 每個動作之後大腦都會重新規劃，所以每個答案的編號都從 1 重新開始。

## 4. 自動

玩家要求時，AI 自己打出答案（`Assist.cs`，[Mod：自動遊玩與安全 §2](/zh-tw/arch/mod/auto/#sec-2)）。這個迴圈建立在 Mod 的每影格迴圈上（[Mod：主迴圈 §1](/zh-tw/arch/mod/loop/#sec-1)）：

<Steps>

1. 等到畫面上的決策已經保持 3 個影格。
2. 詢問大腦，或者取得它對這個鍵的答案：觀測的雜湊加上它的合法動作。
3. 如果目標已經達成（回合結束了，或房間離開了而下一個是地圖決策），就停下；自動遊玩時，如果玩家保留了這些停止條件，在菁英或頭目之前，以及 V 的獲勝機率下降時停下。
4. 從答案顯示起，等速度設定的延遲：1.5、0.8 或 0.2 秒。
5. 透過執行器打出 `action`，只打這一個，對這個鍵只打一次（[Mod：自動遊玩與安全 §1](/zh-tw/arch/mod/auto/#sec-1)）；送出 `executed`。
6. 下一個狀態是一個新的鍵：重複。一個鍵在它的動作之後 10 秒仍然存在，AI 就停下。

</Steps>

每個動作都是一個新的決策：每個動作之後都會再問大腦，因為抽到的牌和隨機結果會影響下一個。照計畫打的大腦，只要遊戲顯示的正是計畫預期的，就從計畫回答，不經搜尋（[SL 規劃器 §4](/zh-tw/arch/sl-planner/#sec-4)）。遊戲自己的速度設定保持原樣；規劃中的自動跑局驅動程式會把它設為 Instant（[Mod：自動遊玩與安全 §2](/zh-tw/arch/mod/auto/#sec-2)）。

## 5. 解說 <Badge text="規劃中" variant="caution" />

解說是用來解釋一條推薦的文字。

- 它只由事實和候選生成，從不對狀態做自由推理。NoSL 的事實是機率和期望值；SL 的事實可以是確切的（「先打 A 再打 B 會抽到 X」）。
- 優先用範本，每種事實一個。
- 可選：由便宜的 LLM 潤飾文字，離線或非同步進行。它的輸入是 JSON 格式的事實和範本的文字。它的輸出要經過檢查：文字裡的每個數字都必須等於某個事實的值（格式化之後做字串比對）；不符合時，改為顯示範本的文字。
- LLM 除了事實之外看不到任何遊戲狀態，也從不影響動作。

這些都還沒有實作：推薦目前還不帶任何事實（[§1](#sec-1)）。

## 6. 輸出中的公平性

| 規則 | 狀態 |
|---|---|
| AI 只在玩家要求時打，而且只打大腦對畫面上那個決策的答案，每個狀態一次。答案由 Harness 對照決策的合法清單檢查（[Harness：路由、預算與種子 §6](/zh-tw/arch/harness/routing/#sec-6)） | 成立 |
| 除了答案之外，自動遊玩只按不是決策的畫面：寶箱、繼續按鈕、遠古之民的對話（[Mod：自動遊玩與安全 §1](/zh-tw/arch/mod/auto/#sec-1)） | 成立 |
| 沒有修改狀態、使用主控台或讀檔的介面 | 成立 |
| 線路（大腦的 stdin 和 stdout）只傳輸協定訊息。SL 匯出只在 SL 下傳送，帶有節點的存檔，包括種子和亂數流（[Mod：自動遊玩與安全 §4](/zh-tw/arch/mod/auto/#sec-4)） | 成立 |
| Mod 只寫自己的設定檔、大腦的日誌（`brain.log`，大腦寫到它的 stderr 的內容），以及它在遊戲日誌裡的那幾行；設定的 `Record` 開啟時，它啟動的大腦還會把收到的訊息和決策日誌寫到它們旁邊的 `captures/` 裡 | 成立 |
| `NumReloads` 記入日誌，而且必須為 0 | 規劃中 |

協定訊息新增的欄位如果改變了可以離開遊戲的內容，就在這裡加一列。
