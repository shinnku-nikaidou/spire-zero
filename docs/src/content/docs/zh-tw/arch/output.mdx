輸出層把大腦的答案變成玩家能看到的東西，或者遊戲裡實際發生的動作。它執行在遊戲行程裡的 [Mod](/zh-tw/arch/mod/) 中。所有輸出模式讀的都是 Harness 發來的同一條 `Recommendation` 訊息，大腦從不知道當前開著哪種模式。

<Aside title="狀態">

先有了一個臨時替代：Mod 的文字面板在每個決策介面上顯示推薦的動作、本回合剩下的計畫和得分最高的幾個候選，名字和遊戲裡一致（[Mod §3](/zh-tw/arch/mod/#sec-3)）。第一個標示也已經做好：在地圖上，推薦的地圖點上有一個圓圈，大腦在它之後規劃的路線上有一條線，一直畫到頭目（[§3](#sec-3)）。其餘部分仍在規劃中。背景筆記在本地筆記 `tmp/notes/output-design.md` 裡，其中的 Godot 節點名都在遊戲原始碼裡核實過。Godot 節點類別（`N*` 型別）只按類別名稱引用：每個類別名稱在反編譯原始碼裡都是唯一的，按名字就能找到檔案。

</Aside>

## 1. 約定

三個消費者讀同一條 `Recommendation`（[協定 §6](/zh-tw/arch/protocol/#sec-6)），半自動模式是其中兩個的組合。大腦從不知道當前開著哪種模式。它們用到推薦裡的這些部分：

- `Plan`：本回合或本畫面剩下的動作序列，在地圖上是本幕剩下的路線（`plan[0]` 是下一個動作）；
- `Candidates`：考慮過的各個動作，每個帶有估值、信賴區間和樣本數；
- `Facts`：解說可以引用的數字，是解說的唯一來源。

| 模式 | 消費者 | 需要 |
|---|---|---|
| 面板（輔助模式，簡單版） | 一個文字面板，適用於所有決策介面 | `Plan`、`Candidates`、`Facts` |
| 標示（輔助模式，進階版） | 每個決策介面各自的 `ISurfaceAdapter.AnchorFor`（[Mod §4](/zh-tw/arch/mod/#sec-4)） | 動作 → 節點 |
| 自動 | `ISurfaceAdapter.Execute(plan[0])`，然後重新觀測 | 動作 → 入口 |
| 半自動 | 標示 + 按空白鍵執行 `plan[0]` | 兩者都要 |

決策介面（surface）指當前顯示的決策畫面的種類（戰鬥、地圖、商店、選牌提示等）。**錨點**（anchor）是螢幕上某個動作所對應的 Godot 節點，比如要打出的那張牌所在的卡牌槽。

**過期守衛**。推薦只有在它的 `obs_hash` 等於當前雜湊時才會被渲染或執行，否則清空輸出。等待期間面板顯示「thinking…」（思考中）。輔助模式下大腦是**隨時可答**（anytime）的：先發出目前最好的答案，再陸續發出更好的（[Harness §5](/zh-tw/arch/harness/#sec-5)），每次更新都替換面板內容。

## 2. 面板

面板有自己的 `CanvasLayer`。`CanvasLayer` 是 Godot 的一種節點，把它的子節點畫在單獨的一層上；這裡用的是高層，位於遊戲 UI 之上。裡面放一個 `PanelContainer` 和一個 `RichTextLabel`。可以拖曳一角；F8 切換顯示。

顯示內容隨決策介面而變，全部來自 `Recommendation`。ΔP(win) 是估計的整局勝率之差。

| 決策介面 | 面板內容 |
|---|---|
| 戰鬥 | 帶目標的編號計畫；1–2 條事實（與另一種打法相比的預期掉血、下回合能否斬殺）；最佳備選及其 ΔP(win) |
| 卡牌獎勵 / 選擇 | 各個選項，每項帶有相對略過或基線的 ΔP(win) |
| 地圖 | 下一個點和路線預覽 |
| 事件 / 休息處 / 商店 | 同樣的格式 |

- 對每個還沒有標示轉接器的決策介面，面板就是後備的顯示方式。
- 可選的零 UI 變體：大腦在本機提供一個網頁，顯示在第二塊螢幕上。只用於最早期的測試；與遊戲的連線仍然是 Unix socket。

## 3. 標示

**跟隨式覆蓋層**。標示由 Mod 自己的節點來畫，這些節點只存在於 Mod 自己的 `CanvasLayer` 裡，蓋在遊戲上面。每一個影格，每個標記讀取目標節點在螢幕上的矩形（`GetGlobalRect()`）並跟著移動；目標消失或隱藏時，標記也隱藏。Mod 從不寫入遊戲節點，原因有二：`NHandCardHolder.UpdateCard()` 在每次狀態變化時都會重置 `CardHighlight`（`Nodes.Cards.Holders/NHandCardHolder.cs:613-640`） <Badge text="已核實" variant="success" />；而且青色、金色、紅色的光效在遊戲裡已經各有含義（`NCardHighlight`）。

**樣式**。順序徽標 ①②③，外加一種遊戲沒用過的描邊顏色（紫色）。

**錨點**。每個決策介面的標記掛在哪個節點上，已核實（本地筆記 `tmp/notes/output-design.md` §3.2） <Badge text="已核實" variant="success" />：

| 決策介面 | 節點 | 標記 |
|---|---|---|
| 手牌 | `NPlayerHand.Instance.GetCardHolder(card)` | 徽標 + 描邊；游標停留時顯示理由 |
| 目標 | `NCombatRoom.Instance.GetCreatureNode(creature)` | 帶該牌編號的準星 |
| 藥水 | `NPotionHolder` | 徽標 |
| 結束回合 | `NEndTurnButton` | 計畫打完時閃動 |
| 戰鬥內選牌 | 手牌選擇模式、`NCombatPileCardSelectScreen` | 勾選標記 |
| 卡牌獎勵 | `NCardRewardSelectionScreen` 的卡牌槽 + 略過 | 每張牌的 ΔP，最佳項描邊 |
| 獎勵 | `NRewardButton` | 領取順序 / 跳過 |
| 地圖 | `NMapScreen` 裡的 `NMapPoint` + 我們自己的 `Line2D` 路線（不用 `NMapDrawings`：它在多人模式下共享） | 下一個點 + 路線 |
| 事件 | `NEventOptionButton` | 最佳項描邊，其他項標 ΔP |
| 休息處 | `NRestSiteButton` | 同上 |
| 商店 | `NMerchantCard/Relic/Potion/CardRemoval` | 購買順序 |
| 網格選牌 | `NCardGridSelectionScreen` 一族、`NCardGrid` | 勾選標記 |

**工作順序**：

1. 手牌 + 目標；
2. 卡牌獎勵；
3. 地圖；
4. 事件 / 休息處 / 商店；
5. 網格選牌提示。

**容易踩的坑**：

- 卡牌槽節點會被池化（重複使用）、換父節點，還帶動畫。跟隨式覆蓋層能處理這些。
- 螢幕解析度、UI 縮放和手把操作：只使用全域矩形。
- 每個動作之後都會重新規劃，徽標編號會隨之改變。

## 4. 自動

自動迴圈建立在 Mod 的每影格迴圈之上（[Mod §3](/zh-tw/arch/mod/#sec-3)）：

<Steps>

1. 等到當前決策介面空閒。
2. 觀測。
3. 拿到推薦。
4. 檢查它的雜湊與當前觀測一致，且它的動作合法。
5. 執行 `plan[0]`，只執行這一個。
6. 等待雜湊變化，或者超時。
7. 重複。

</Steps>

每個動作之後大腦都重新規劃，因為抽到的牌和隨機結果會影響下一次決策。速度來自把遊戲的 FastMode 設為 Instant，外加可選的每步延遲（[Mod §7](/zh-tw/arch/mod/#sec-7)）。

## 5. 解說

解說是解釋一條推薦的文字。

- 它只由 `Facts` 和 `Candidates` 生成，從不對狀態做自由推理。NoSL 的事實是機率和期望；SL 的事實可以是確切結果（「先打 A 再打 B → 會抽到 X」）。
- 優先用範本，每種事實一個範本。
- 可選：由便宜的 LLM 潤色文字，離線或非同步進行（透過專案的 LLM 閘道器，只用便宜的模型）。輸入是事實 JSON 和範本文字。輸出要經過檢查：文字裡的每個數字都必須等於某個事實的值（格式化之後按字串比較）；不滿足就改為顯示範本文字。
- LLM 除了事實之外看不到任何遊戲狀態，也從不影響動作。

## 6. 輸出中的公平性

- 執行器只接受 `legal[]` 裡的動作。
- 沒有修改狀態、主控台或讀檔的介面。
- `NumReloads` 記入日誌。
- Mod 除了協定訊息之外從不匯出任何東西；SL 匯出按環境開關（[Mod §6](/zh-tw/arch/mod/#sec-6)）。

## 7. 測試

- **逐個決策介面的錨點解析**：每個已支援的決策介面的每個合法動作，都能對應到一個可見節點（在除錯覆蓋層模式下檢查）。
- **過期**：延遲到達的推薦在狀態變化之後從不渲染。
- **解說數字檢查**。
