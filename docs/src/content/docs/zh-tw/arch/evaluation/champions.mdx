**冠軍**是某個環境中已接受的最好版本的 AI：大腦、它們的預算和權重，以及代表它們的報告。本頁說明指明冠軍的檔案，列出冠軍的報告，並列出其他專案達到了什麼。門檻如何運作見[晉級門檻](/zh-tw/arch/evaluation/gates/)。

## 1. 冠軍檔案

`eval/champions/ENV.json`（`nosl.json`、`sl.json`）為每個環境保存一個冠軍，涵蓋每個角色，格式為 `ChampionFile` 記錄（`Harness/Gate.cs:91-92`）。冠軍是兩個網路和它們的打法，對每個角色都一樣；角色和晉階等級由每個作業自己給（`--character`、`--asc`）。SL 冠軍的檔案：

```json
{
  "env": "SL",
  "champion": "combat plan c9-2 beam 8x300 easy 4 loss plans 3, combat prompts first, macro l0 v9-2 clone, macro prompts l0 v9-2 clone",
  "options": {
    "env": "SL", "policy": "plan", "macro": "l0", "effort": "medium",
    "value": "weights/all/v9-2.json", "afterstates": "clone", "combat-net": "weights/all/c9-2.json"
  },
  "reports": {
    "SILENT": "eval/silent/reports/DATE-sl-a0-SET-NAME.json",
    "IRONCLAD": "eval/ironclad/reports/DATE-sl-a0-SET-NAME.json",
    "DEFECT": "…", "REGENT": "…", "NECROBINDER": "…"
  },
  "since": "DATE"
}
```

（檔案裡是一行，這裡展開排版，各報告的路徑和日期寫成樣式）。

| 欄位 | 內容 |
|---|---|
| `env` | `NoSL` 或 `SL`；挑戰者的 `--env` 與它不同時，門檻會拒絕 |
| `champion` | 冠軍在報告裡顯示的名稱，即路由表每一側的大腦加上預算（[Harness：路由、預算與種子 §1](/zh-tw/arch/harness/routing/#sec-1)） |
| `options` | 打出這個冠軍的對局選項，不帶 `--`，不含角色和晉階等級；權重檔案寫成它們在 `weights/all/` 裡的路徑 |
| `reports` | 按角色，該角色的挑戰者與之配對的報告：每次門檻中冠軍那一方。一份報告是一個角色在一個晉階等級上的，所以沒有報告的角色還不能對這個檔案過門檻 |
| `since` | 它成為冠軍的日期（晉級報告的日期，或人工寫入的日期） |
| `gate` | 它通過的門檻，沒有經過門檻而定下的冠軍則沒有這一欄：`delta`、`alpha`、`beta`、`pairs`、`decided`、`llr`、`lower`、`upper`、`floor_diff_mean`、`challenger_only_wins`、`champion_only_wins`、`verdict`，有的話還有 `void_reason`，以及 `not_worse` |

**誰讀它**。

- `run` 和 `brain` 接受 `--champion FILE`，打它指明的冠軍（`SimWorker/Commands/Args.cs:166-194`，[模擬器：參考 §3](/zh-tw/arch/simulator/reference/#sec-3)）。檔案的選項排在給定的選項之後，所以給定的優先；指令沒有的選項會被略過（`brain` 沒有 `--env`：每個宿主自己指明）；給定了與檔案不同的 `--policy` 時，保留它自己的預算。
- `brain` 用一個檔案服務兩種宿主：NoSL 宿主得到檔案裡的戰鬥大腦，SL 宿主得到 SL 規劃器（`--sl-policy`，預設 `plan`），兩者都用檔案裡的兩個網路和 L0，L0 的後狀態由宿主的環境決定：NoSL 下從畫面預測，SL 下在節點的複本上打出（`BrainCommand.Champions`，`SimWorker/Commands/BrainCommand.cs:72-79`）。Mod 的大腦就是這樣打 NoSL 檔案的（[Mod §4](/zh-tw/arch/mod/#sec-4)）。
- `gate --champion FILE` 是要打敗的冠軍：它讀取檔案的 `env`，以及它對記錄所屬角色的報告（[晉級門檻 §6](/zh-tw/arch/evaluation/gates/#sec-6)）。
- `leaderboard --character C` 在檔案所屬環境的榜上，標出每個檔案為 C 指明的報告（[指標、種子與報告 §9](/zh-tw/arch/evaluation/metrics/#sec-9)）。

**由 `--promote` 寫入，或由人工寫入**。`gate --promote` 寫入每個欄位，選項按挑戰者的選項產生（`ChampionOptions.Options`，`SimWorker/Brains/ChampionOptions.cs:79-95`）：對 SL 規劃器是 `beam`、`easy-beam`、`replan`、`loss-plans` 和 `nodes`，而不是 `effort`。勝局門檻什麼也不寫，所以它晉級的網路由人工寫入（[晉級門檻 §10](/zh-tw/arch/evaluation/gates/#sec-10)），SL 檔案寫著 `"effort": "medium"`，打的是同樣的預算（[SL 規劃器：預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。重定基線只改 `reports`（[晉級門檻 §9](/zh-tw/arch/evaluation/gates/#sec-9)）。

**兩個檔案**。兩個檔案都指明同樣兩個網路：`weights/all/v9-2.json`（V）和 `weights/all/c9-2.json`（戰鬥網路）。SL 打的是 medium 力度的 SL 規劃器，加上在複本上的 L0；NoSL 打的是 8 個世界 × 300 個節點的 PIMC，加上用從畫面預測的後狀態的 L0（`"policy": "pimc", "worlds": "8", "nodes": "300"`）。SL 檔案指明五份報告，每個角色一份，都是這個冠軍自己的：在 `promotion-1-100` 上以 medium 打的 100 局晉階 0。NoSL 檔案一份也不指明：兩個網路都沒有在 NoSL 下打過任何報告，所以對它的 NoSL 門檻對每個角色都會被拒絕（[晉級門檻 §6](/zh-tw/arch/evaluation/gates/#sec-6)）。兩個網路都只從 SL 的對局學習：NoSL 目前不訓練。

每個角色都有自己的資料夾 `eval/CHARACTER/` 和 `data/CHARACTER/`，有自己的報告、排行榜和對局（[學習：參考 §3](/zh-tw/arch/learning/reference/#sec-3)），因為一個結果只對一個角色成立。其餘的是共用的：`weights/all/` 裡的網路、`eval/champions/` 裡的冠軍檔案，以及 `eval/seeds/` 裡的種子集。

## 2. 報告

`eval/CHARACTER/reports/` 保存一個角色已提交的報告，有 JSON 和 Markdown 兩種（[指標、種子與報告 §7](/zh-tw/arch/evaluation/metrics/#sec-7)），`eval/CHARACTER/leaderboard.md` 為這些報告排名，按晉階、種子集和環境分（[指標、種子與報告 §9](/zh-tw/arch/evaluation/metrics/#sec-9)）。

**冠軍的報告**。SL 檔案指明五份，每個角色一份：冠軍在該角色每次門檻裡的那一方。每份是冠軍的兩個網路在 `promotion-1-100` 上以晉階 0、medium 預算打的 100 局 SL 對局。沒有一份有隨機決策、失敗或截斷的對局或遊戲錯誤，所以沒有一份作廢（[指標、種子與報告 §2](/zh-tw/arch/evaluation/metrics/#sec-2)）：

| 角色 | 100 局中贏下 | 95 % Wilson 區間 | 平均層數 | 每個決策 ms | 每局 s |
|---|---|---|---|---|---|
| 寂靜獵手 | 92 | 85.0–95.9 % | 46.45 | 405 | 336 |
| 鐵甲戰士 | 82 | 73.3–88.3 % | 46.00 | 431 | 286 |
| 儲君 | 71 | 61.5–79.0 % | 45.57 | 1,202 | 906 |
| 故障機器人 | 68 | 58.3–76.3 % | 46.44 | 560 | 423 |
| 縛亡者 | 47 | 37.5–56.7 % | 41.55 | 1,358 | 1,046 |

NoSL 檔案不指明任何報告（[§1](#sec-1)）。

**晉級怎樣改寫這兩個檔案**。

- `gate --promote PATH` 改寫給它的那一個檔案（[晉級門檻 §8](/zh-tw/arch/evaluation/gates/#sec-8)）：挑戰者的名稱和選項，它的新報告作為唯一的一份，放在它的角色下，`since` 為報告的日期，`gate` 為結果。舊冠軍的其他報告是別的網路打的，所以都拿掉。
- 勝局門檻通過的一對網路以人工寫進兩個檔案，因為兩個檔案打同樣的兩個網路（[晉級門檻 §10](/zh-tw/arch/evaluation/gates/#sec-10)）。在每個檔案裡，`value` 和 `combat-net` 指明新的一對在 `weights/all/` 裡的檔案，`champion` 是它的選項組成的名稱，`since` 是日期。SL 檔案的 `reports` 指明用新的一對在門檻中自己打的對局做成的五份報告；NoSL 檔案不指明任何報告，因為新網路沒有在 NoSL 下打過報告。舊網路的檔案留在 `weights/all/` 裡，名稱永不重用（[學習：參考 §6](/zh-tw/arch/learning/reference/#sec-6)）。

## 4. 未決問題

1. **R4 的吞吐量**：在遊戲的 Instant 速度下一局要幾分鐘，由此能負擔多少局 R4。
2. **不一致種子很少時的勝局門檻**：它的下界讓 3 勝對 0 勝通過（[晉級門檻 §10](/zh-tw/arch/evaluation/gates/#sec-10)）；是否要求最少的不一致種子數，或改用精確檢定。
3. **門檻的錯誤率**：兩種門檻的誤通過率都沒有量過；A/A 測試需要一種只改變冠軍自身隨機性的方法（[晉級門檻 §4](/zh-tw/arch/evaluation/gates/#sec-4)）。
4. **冠軍的 NoSL 報告**，讓 NoSL 榜有冠軍，也讓同一個 V 的 SL − NoSL 能被量出。
5. **`final-1`**：何時在它上面做出第一個正式結論。
