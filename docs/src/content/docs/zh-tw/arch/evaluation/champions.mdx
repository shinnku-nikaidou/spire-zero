**冠軍**是某個環境中已接受的最好版本的 AI：大腦、它們的預算和權重，以及代表它們的報告。本頁說明指明冠軍的檔案，說明結果的紀錄放在哪裡，並列出其他專案達到了什麼。門檻如何運作見[晉級門檻](/zh-tw/arch/evaluation/gates/)。

## 1. 冠軍檔案

`eval/CHARACTER/champions/ENV.json`（`nosl.json`、`sl.json`）為每個角色和環境保存一個冠軍，格式為 `ChampionFile` 記錄（`Harness/Gate.cs:116-117`）。SL 冠軍的檔案：

```json
{
  "env": "SL",
  "champion": "combat plan c7-2 beam 8x300 easy 4 loss plans 3, combat prompts p0, macro l0 v7-1f clone, macro prompts l0 v7-1f clone",
  "options": {
    "env": "SL", "policy": "plan", "macro": "l0", "effort": "medium",
    "value": "weights/silent/v7-1f.json", "afterstates": "clone", "combat-net": "weights/silent/c7-2.json",
    "character": "SILENT", "asc": "0"
  },
  "report": "eval/silent/reports/DATE-sl-r1-SET-NAME.json",
  "since": "DATE"
}
```

（檔案裡是一行，這裡展開排版，報告的路徑和日期寫成樣式）。

| 欄位 | 內容 |
|---|---|
| `env` | `NoSL` 或 `SL`；挑戰者的 `--env` 與它不同時，門檻會拒絕 |
| `champion` | 冠軍在報告裡顯示的名稱，即路由表每一側的大腦加上預算（[Harness：路由、預算與種子 §1](/zh-tw/arch/harness/routing/#sec-1)） |
| `options` | 打出這個冠軍的對局選項，不帶 `--`，其中包括角色和晉階等級；權重檔案寫成它們在 `weights/CHARACTER/` 裡的路徑 |
| `report` | 挑戰者與之配對的報告：每次門檻中冠軍那一方 |
| `since` | 它成為冠軍的日期（晉級報告的日期，或人工寫入的日期） |
| `gate` | 它通過的門檻，沒有經過門檻而定下的冠軍則沒有這一欄：`metric`、`delta`、`alpha`、`beta`、`pairs`、`decided`、`llr`、`lower`、`upper`、`floor_diff_mean`、`challenger_only_wins`、`champion_only_wins`、`verdict`，有的話還有 `void_reason`，以及 `not_worse` |

**誰讀它**。

- `run`、`brain`、`afterstates` 和 `fork` 接受 `--champion FILE`，打它指明的冠軍（`SimWorker/Commands/Args.cs:172-201`，[模擬器：參考 §3](/zh-tw/arch/simulator/reference/#sec-3)）。檔案的選項排在給定的選項之後，所以給定的優先；指令沒有的選項會被略過（`brain` 沒有 `--env`：每個宿主自己指明）；給定了與檔案不同的 `--policy` 時，保留它自己的預算。
- `gate --champion FILE` 是要打敗的冠軍：它讀取檔案的 `env` 和 `report`（[晉級門檻 §6](/zh-tw/arch/evaluation/gates/#sec-6)）。
- `leaderboard` 在檔案所屬環境的榜上，標出每個檔案指明的報告（[指標、種子與報告 §9](/zh-tw/arch/evaluation/metrics/#sec-9)）。

**由 `--promote` 寫入，或由人工寫入**。`gate --promote` 寫入每個欄位，選項按挑戰者的選項產生（`ChampionOptions.Options`，`SimWorker/Brains/ChampionOptions.cs:83-108`）：對 SL 規劃器是 `beam`、`easy-beam`、`replan`、`loss-plans` 和 `nodes`，而不是 `effort`。勝局門檻什麼也不寫，所以它晉級的網路由人工寫入（[晉級門檻 §10](/zh-tw/arch/evaluation/gates/#sec-10)），SL 檔案寫著 `"effort": "medium"`，打的是同樣的預算（[SL 規劃器：預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。重定基線只改 `report`（[晉級門檻 §9](/zh-tw/arch/evaluation/gates/#sec-9)）。

**兩個檔案**。兩個檔案都指明同樣兩個網路：`weights/silent/v7-1f.json`（V）和 `weights/silent/c7-2.json`（戰鬥網路），這也是 `weights/silent/` 裡僅有的檔案。SL 打的是 medium 力度的 SL 規劃器，加上在複本上的 L0；NoSL 打的是 8 個世界 × 300 個節點的 PIMC，加上用從畫面預測的後狀態的 L0（`"policy": "pimc", "worlds": "8", "nodes": "300"`）。兩個檔案指明的 `report` 是一份較舊的 SL 報告，用較早的戰鬥網路打的；在這個冠軍有自己的報告之前，它繼續算數。因為它是 SL 報告，對 NoSL 檔案的 NoSL 門檻會被拒絕（[評估 §3](/zh-tw/arch/evaluation/#sec-3)）。

每個角色都有自己的資料夾 `eval/CHARACTER/`、`weights/CHARACTER/` 和 `data/CHARACTER/`，所有晉階等級共用一個大腦（[學習：參考 §3](/zh-tw/arch/learning/reference/#sec-3)）；`eval/seeds/` 裡的種子集是共用的。

## 2. 歷史與報告

這些頁面只描述現在的冠軍。之前的紀錄另外保存：

- `eval/silent/ledger.md` 是歷史：每個網路、它在什麼上訓練、它的門檻，以及它後來怎麼樣了。
- `eval/silent/reports/` 保存每一份已提交的報告，有 JSON 和 Markdown 兩種（[指標、種子與報告 §7](/zh-tw/arch/evaluation/metrics/#sec-7)）。
- `eval/silent/leaderboard.md` 為這些報告排名，按種子集和環境分（[指標、種子與報告 §9](/zh-tw/arch/evaluation/metrics/#sec-9)）。

## 4. 未決問題

1. **R4 的吞吐量**：在遊戲的 Instant 速度下一局要幾分鐘，由此能負擔多少局 R4。
2. **不一致種子很少時的勝局門檻**：它的下界讓 3 勝對 0 勝通過（[晉級門檻 §10](/zh-tw/arch/evaluation/gates/#sec-10)）；是否要求最少的不一致種子數，或改用精確檢定。
3. **門檻的錯誤率**：兩種門檻的誤通過率都沒有量過；A/A 測試需要一種只改變冠軍自身隨機性的方法（[晉級門檻 §4](/zh-tw/arch/evaluation/gates/#sec-4)）。
4. **冠軍的 NoSL 報告**，讓 NoSL 榜重新有冠軍，也讓同一個 V 的 SL − NoSL 能被量出。
5. **`final-1`**：何時在它上面做出第一個正式結論。
