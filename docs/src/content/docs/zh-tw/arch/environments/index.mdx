殺戮尖塔 2 會對玩家隱藏一些東西：抽牌堆的順序、怪物在它顯示的那一招之後會做什麼、事件會給出哪張牌、一個未知的地圖點最後會變成什麼。人類只看得到螢幕。執行遊戲本身程式碼的程式則看得到一切，連每個亂數產生器的狀態都看得到；一個可以讀取這些狀態的搜尋，玩的是另一個、容易得多的遊戲。

所以這個專案的每個部分都接受一個參數，說明 AI 可以知道多少：**環境**。環境有兩種。**NoSL**（「no save & load」，不存讀檔）只允許螢幕上出現過的東西。**SL**（「save & load」，存讀檔）還允許知道玩家所在地圖點內部的真實結果，就像玩家可以在那裡隨意存檔、讀檔任意多次。本章定義這兩種環境，解釋為什麼有兩種，並說明這個選擇延伸到系統其他部分的哪些地方。之後的每一章都以它為前提。

<Aside title="狀態">

已實作，並在程式碼的每個部分生效。NoSL 下，搜尋在由觀測建構的世界上進行（[世界與兩種戰鬥演算法 §2](/zh-tw/arch/environments/worlds/#sec-2)）；SL 下，搜尋在當前節點的精確複本上進行，這個複本由工作行程根據檢查點和節點內的各步做出，自我對弈時如此，透過 Mod 在真實遊戲裡也是如此（[資訊與節點 §7](/zh-tw/arch/environments/information/#sec-7)）。在守住這些規則的十項守護中，有四項已有測試（程式碼邊界、沒有後備、觀測往返和封存）；反事實測試和讀檔次數還在規劃中（[資訊與節點 §8](/zh-tw/arch/environments/information/#sec-8)）。

## 1. 問題：一個資訊隱藏的遊戲

戰鬥中的一個回合會向玩家顯示手牌、能量、每個生物的生命值和能力，以及每個怪物頭上的*意圖*：一個圖示，表示它下一步打算做什麼，例如攻擊 12 點。它不顯示的有：

- 抽牌堆的順序（玩家知道裡面有哪些牌，但不知道順序）；
- 怪物在顯示出來的那一招之後的招式，以及對招式看起來相似的怪物來說，它到底選了哪一招；
- 任何還沒發生的隨機事情的結果：打中隨機敵人的牌、隨機生成的牌、下一次獎勵的牌、事件選項的結果。

戰鬥之外也是如此，而且範圍更大：地圖會顯示一個 `?` 點，但不顯示它會是事件、戰鬥、商店還是寶箱；地圖會顯示一個菁英，但不顯示是哪個菁英。

這些在遊戲裡都只是普通的狀態：牌堆是串列，怪物把下一招存在一個欄位裡，每一次隨機抽取都來自一組固定的、帶種子的亂數產生器（RNG）之一，而存檔檔案會把它們存下來。模擬器（[模擬器](/zh-tw/arch/simulator/)）執行的是遊戲的真實程式碼，所以在其中執行的搜尋可以讀到這一切，或者乾脆試一種打法，看看會發生什麼。因此需要一條規則來說明什麼是公平的。

還有一件事讓這條線很難畫：遊戲本身就允許玩家偷看。退回主選單再按「繼續」會重新載入上一次的存檔，而重新載入會原樣重演這個房間：相同的遭遇、相同的起手牌、相同的怪物招式（[資訊與節點 §4](/zh-tw/arch/environments/information/#sec-4)）。有耐心的玩家可以退出、看一眼、再回來。所以「玩家能知道什麼」並不是一條固定的線，這個專案畫了兩條。

## 2. 一分鐘看懂兩種環境

**NoSL：只用公開資訊**。決策可以依據到目前為止螢幕上顯示過的一切、能從中推斷出的東西、遊戲規則，以及離線學到的任何東西。搜尋看不到隱藏狀態，所以它進行*確定化*：抽取幾個對隱藏狀態的具體猜測（K 個*世界*），每一個都與看到的一切一致，把每一個都當作真相來搜尋，再取平均（[世界與兩種戰鬥演算法 §2](/zh-tw/arch/environments/worlds/#sec-2)）。

**SL：在當前節點內存讀檔**。SL 可以知道 NoSL 能知道的一切，再加上在**節點**內任何一種打法的真實結果；節點就是當前的地圖點，從到達開始，直到玩家在地圖上選定下一個點為止。這等同於一個玩家可以在節點內隨意存檔、讀檔任意多次，並記得每一次嘗試。搜尋得到節點的一份精確複製，也就是*複本*，它在節點的出口處封存。對於之後的地圖點，SL 知道的並不比 NoSL 多。

| | NoSL | SL |
|---|---|---|
| 在當前節點內知道什麼 | 已經顯示的東西，以及從中得出的推斷 | 任何一種打法的真實結果 |
| 對之後的節點知道什麼 | 不知道任何隱藏的東西 | 不知道任何隱藏的東西（和 NoSL 一樣） |
| 搜尋所在的世界 | K 個取樣世界，由觀測建構 | 節點的一個精確複本 |
| 戰鬥大腦 | PIMC：把每個世界搜到回合結束，再取平均 | SL 規劃器：在唯一的世界裡規劃整場戰鬥 |
| 宏觀大腦與價值 V | 一個大腦、一個 V | 同一個大腦和 V |
| 戰鬥網路 | 一個網路，搜尋的葉節點 | 同一個網路 |
| 冠軍與排行榜 | NoSL 自己的 | SL 自己的，從不與 NoSL 的混在一起 |

宏觀大腦是負責戰鬥之外每個決策的部分（[宏觀大腦](/zh-tw/arch/macro-brain/)）；V 是它用來給選項評分的、學到的價值。兩者都是共用的，戰鬥網路也是：它是戰鬥搜尋葉節點上學到的價值，兩種環境用同樣的權重打同樣的兩個網路。只有戰鬥網路前面的戰鬥搜尋不同，因為只有在戰鬥中，兩種環境提出的問題才不一樣（[世界與兩種戰鬥演算法 §5](/zh-tw/arch/environments/worlds/#sec-5)）。

## 3. 為什麼有兩種環境

**NoSL 是目標**。它是一個公平的玩家所知道的東西，Mod 的輔助模式可以把它提供給一個從不退出重讀的玩家。

**SL 是訓練用的環境，也是一把尺**。在節點內，SL 完全不面對隨機性：複本握有真實的亂數流，所以一場戰鬥是一個可以搜到底的確定性謎題，每條路線都只有一個結果，而不是一個分布。這讓 SL 的戰鬥大腦在相同運算量下強得多（[戰鬥大腦](/zh-tw/arch/combat-brain/)），SL 的對局也能打到後面幾幕，而 V 正需要在那裡學會給局面估值。V 用戰鬥由 SL 規劃器來打的對局訓練，並為兩種環境服務（[世界與兩種戰鬥演算法 §6](/zh-tw/arch/environments/worlds/#sec-6)）。

兩種環境打同一組預先登記的種子，所以它們在相同種子上的差距，乾淨地量出了節點內資訊值多少：按種子配對的 SL − NoSL 勝率差與到達樓層差。排行榜會為每個在兩種環境下都有同名報告的冠軍計算這個差值（[評估 §3](/zh-tw/arch/evaluation/#sec-3)）；兩個冠軍的戰鬥大腦不同，所以它不顯示任何差值。這是「全知對重取樣」比較的正式版本。作為參考：spire-mentor（一個前人做的殺戮尖塔機器人）去掉它能看到整局的作弊之後，勝率下降了 22.8–25.5 個百分點；SL 只看到一個節點，所以它的增益應該更小。

**沒有整局視野的環境**。一種知道整局全部順序（之後的每場遭遇、每次獎勵和每家商店）的環境，會讓整局本身變成一個確定性謎題，學到的東西也無法沿用到公平的遊玩中。

## 4. 兩種環境共用的東西

- **只支援單人模式**，使用固定的遊戲版本 v0.111.0。
- **相同的程式碼與規則**：相同的規則知識，相同的 Brain、Harness 和 Protocol。只有戰鬥大腦和世界的來源按環境選擇。
- **相同的種子**：兩者打同一組預先登記的種子集，每個結果都按環境分開報告（[評估：指標、種子與報告 §5](/zh-tw/arch/evaluation/metrics/#sec-5)）。
- **AI 從不真正讀檔**。兩種環境都從不重新載入玩家看到的那個遊戲。SL 的「存讀檔」只發生在複本上，由搜尋在工作行程裡載入。遊戲在存檔欄位 `SerializableRun.NumReloads` 中計算讀檔次數：在真實遊戲裡它必須保持為 0，這項檢查計畫放在 Mod 的日誌裡（[資訊與節點 §8](/zh-tw/arch/environments/information/#sec-8)）。複本本身就是一份載入的存檔，所以在複本裡這個次數是 1 或更多，而那裡沒有任何東西讀它。
- **一局之內固定**。環境在一局開始時、在宿主的 `hello` 裡選定，並維持到這一局的 `run_end`。它記錄在這一局的對局記錄裡（`RunConfig.Env`），也記錄在決策日誌的每一行裡（`env`）。在 Mod 裡，玩家可以隨時切換環境；切換會結束大腦所看到的這一局，並開始新的一局（[Mod：主迴圈 §8](/zh-tw/arch/mod/loop/#sec-8)）。
- **兩者都只用觀測**。大腦讀取的是協定觀測，從不讀取遊戲物件；SL 比 NoSL 多知道的東西只能經由複本傳到它們手上，而複本存在於工作行程中（[世界與兩種戰鬥演算法 §1](/zh-tw/arch/environments/worlds/#sec-1)）。

## 5. 一局如何選定環境

環境在哪裡設定，以程式碼為準：

| 位置 | 方式 | 預設 |
|---|---|---|
| `run`（在模擬器裡打整局） | `--env NoSL\|SL`，大小寫皆可（`Commands/RunCommand.cs:23`）；冠軍檔案的 `env` 會填入它 | NoSL |
| 線路上 | `hello{env: "NoSL"\|"SL"}`，由宿主在每一局開始時送出（[協定：線路 §3](/zh-tw/arch/protocol/wire/#sec-3)） | – |
| `brain`（單獨的決策行程） | 兩者都服務：NoSL 宿主用 `--policy` 的戰鬥大腦和畫面預測後狀態的 L0，SL 宿主用 `--sl-policy` 的戰鬥大腦和在節點複本上的 L0（`Commands/BrainCommand.cs:20`、`BrainCommand.Champions`） | `--sl-policy plan` |
| Mod | 面板頂部的 SL/NoSL 切換，保存在 `$XDG_STATE_HOME/sts2ai`（預設 `~/.local/state/sts2ai`）的 `settings.json` 裡（[Mod §5](/zh-tw/arch/mod/#sec-5)） | SL |
| 冠軍檔案 | 每個環境一個，涵蓋每個角色，`eval/champions/nosl.json` 和 `sl.json`；`gate --env` 必須與檔案的一致（[評估：冠軍與基線 §1](/zh-tw/arch/evaluation/champions/#sec-1)） | – |
| 戰鬥網路訓練 | `combat.train --env SL\|NoSL`，必填；網路檔案會記錄它（`learn/combat/train.py`、`export.py`） | – |

拒絕錯誤環境的地方：

- `--policy plan`（SL 規劃器）和 `--afterstates clone`（L0 在複本上打選項）只在 SL 下打，`--policy pimc` 只在 NoSL 下打：另一個環境的 `hello` 會被拒絕（`Brains/ChampionOptions.cs:39-41`），`run` 也會在開始之前拒絕在 SL 之外用規劃器（`Commands/RunCommand.cs:61`）。
- SL 和 NoSL 打同一個戰鬥網路檔案，它從 SL 的對局學習（[戰鬥大腦：葉節點 §6](/zh-tw/arch/combat-brain/leaf/#sec-6)）。
- 在 NoSL 的一局裡，Harness 拒絕 SL 訊息 `node_checkpoint` 和 `node_action`（`Harness/Dispatcher.cs:173`、`:182`）；大腦伺服器保留這個拒絕，對這一局的下一個決策回覆錯誤，宿主把這一局當作失敗結束，`run` 以結束代碼 1 結束，而失敗的一局不計入它的報告（`Harness/BrainServer.cs:61`、`:71-81`、`Harness/RunRecords.cs:32`）。
- 戰鬥網路訓練器只讀給定環境的日誌，遇到另一個環境的日誌就失敗（`learn/combat/data.py`）。
- 晉級門檻拒絕把在不同環境或不同遊戲中打的對局配對（`Harness/Gate.cs:40-41`）。
