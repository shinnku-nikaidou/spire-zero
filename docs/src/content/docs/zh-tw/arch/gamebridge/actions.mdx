每種決策介面（surface）在 `src/Sts2Ai.GameBridge/Actions/` 裡都有一個靜態類別。它們的形狀相同：

| 成員 | 做什麼 |
|---|---|
| `Screen(…)` | 這個決策介面的畫面，即它的協定檢視（[協定：觀測與動作 §5](/zh-tw/arch/protocol/observation/#sec-5)） |
| `Legal(…)` | 合法動作，以文字表示，順序固定 |
| `Start(…, action)` | 透過遊戲按鈕所做的那個呼叫執行這個動作；動作不合法時拋出例外 |

每個類別讀取的東西（當前事件、商店的庫存、休息處的選項）由宿主取得，哪個畫面在提問也由宿主判斷。`Start` 開始遊戲的工作之後就返回；宿主讓遊戲一直執行到穩定下來（[模擬器：整局 §3](/zh-tw/arch/simulator/runs/#sec-3)）。如果這份工作是畫面會 await 的一個任務，`Start` 就回傳它。

## 1. 戰鬥

`CombatActions`（`Actions/CombatActions.cs`）：

- **`WaitingForInput(player)`**：玩家可以行動。有戰鬥正在進行、輪到玩家一方、處於出牌階段、動作執行器空閒，而且玩家動作沒有被停用。無頭時這樣就夠了；在真實遊戲裡，畫面也必須準備好，這由 Mod 在它自己的節點上檢查（[Mod：主迴圈 §4](/zh-tw/arch/mod/loop/#sec-4)）。
- **`Legal(state, player)`**：先是手牌，按手牌順序，然後是藥水，按槽位，最後是 `end_turn`。
  - 每張牌用 `CanPlay()` 檢查一次（它會執行四次鉤子分派，所以不按目標重複檢查）。以任一敵人為目標的牌，對它可以瞄準的每個敵人各合法一次；以任一盟友為目標的牌，對每個盟友各合法一次；其他的牌則不帶目標，只合法一次。
  - 藥水合法的條件是：玩家可以使用藥水，這個槽裡有一瓶還沒排入佇列的藥水，它通過自己的可用性檢查，並且可在戰鬥中使用（限戰鬥使用或隨時可用）；目標的處理方式相同，敵人只在活著時才算。
  - `end_turn` 永遠合法。
- **`Start(state, player, action)`**：出牌經過 `CardModel.TryManualPlay(target)`，也就是從手牌拖出時所做的呼叫，它檢查目標並把這次出牌排入佇列，拒絕時拋出例外；藥水經過 `PotionModel.EnqueueManualUse(target)`；結束回合則經過一個帶有回合編號的 `EndPlayerTurnAction`，像結束回合按鈕那樣排入佇列。
- **`PlayOf(card, target)`、`PotionOf(player, slot, target)`**：照 `Legal` 的命名方式來命名一次出牌或一次藥水使用，只有在牌或藥水會選目標時才保留目標。Mod 用它們記錄玩家做了什麼：畫面對其他牌也會傳入一個目標（對自身生效的牌傳入的是玩家）。
- **`HandCard(pcs, uid)`、`Creature(state, uid)`**：找出一個 uid 所指的東西；遇到未知的 uid 時拋出例外。

## 2. 地圖

`MapActions`（`Actions/MapActions.cs`）。動作是 `map:COL,ROW`；畫面列出的是同樣的點。

- **合法動作**（`Travelable`，即地圖畫面 `RecalculateTravelability` 的規則）：還沒走過任何點時是起點；雙頭目幕裡打完頭目之後，緊接著是第二個頭目；最後一列之後是頭目；其他情況用遊戲自己的 `MapTravel.GetTravelablePointsFrom`，即這個點的子節點，或者在某個鉤子允許自由移動時（`Hook.ShouldAllowFreeTravel`），下一列的每個點。先按列、再按行排序，因為遊戲的子節點是一個雜湊集合。
- **執行**：為這個點排入一個 `VoteForMapCoordAction`，和點擊一個點時地圖畫面把它排入佇列的方式一樣。
- `Text(coord)` 照動作的方式命名一個座標；Mod 用它來記錄玩家的移動。

## 3. 獎勵、卡牌獎勵與卡包

**`RewardActions`**（`Actions/RewardActions.cs`），動作是 `reward:i` 和 `rewards_done`：

- **畫面**：每份還沒領取的獎勵，按它在這組獎勵裡的索引，帶上它的種類：`gold` 和它的數額，`potion` 或 `relic` 和它的 id，`card` 和打開時會顯示的牌，`special_card` 和它的牌（在遊戲裡是私有的，從按鈕的懸停提示讀取），`remove_card`。
- **合法動作**：每份還沒領取的獎勵，按它的索引，但藥水欄滿時的藥水獎勵除外（它留在畫面上，但要等空出一個槽才能領取）；`rewards_done`，除非這組獎勵不允許跳過且並非每份都已領取。連結的獎勵組（多選一）會拋出例外：這個遊戲版本沒有用到任何一組。
- **執行**：`RewardsSetSynchronizer.SelectLocalReward`，和獎勵按鈕的做法一樣；任務在獎勵處理完畢時結束。
- **`Proceed(run, set)`** 就是 `rewards_done`，即「繼續」按鈕：不是房間最後一組的獎勵組，會跳過剩下的並關閉（`SkipLocalRewardsSet`）；在頭目之後或勝利房間裡（雙頭目幕的兩個頭目之間除外），它讓換幕準備就緒（`ActChangeSynchronizer.SetLocalPlayerReady`）；其他情況下，這個房間的獎勵就此結束（`ProceedFromTerminalRewardsScreen`）。`IsTerminal(set)` 判斷一組獎勵是否為房間的最後一組：它的房間是戰鬥房間。

**卡牌獎勵**不由 start 執行，而是由遊戲來詢問。卡牌獎勵從獎勵內部開啟它自己的畫面，由遊戲的選牌器回答：`CardRewardLegal` 為每張牌列出 `card:i`，為每個還沒用掉的替代按鈕（跳過、重骰、遺物新增的按鈕）列出 `card_alt:ID`；`CardRewardAnswer` 把選中的動作轉成選牌器的回答。重骰會讓畫面保持開啟，也仍然列著，但第二次就不起作用了（`KeepsScreenOpen`），所以宿主為每個畫面保存一組已用掉的替代選項。

**`BundleActions`**：卡包選擇（卷軸箱的卡包）也用同樣的方式、透過選牌器回答：`Legal(n)` 是每個卡包一個 `bundle:i`，不能跳過；`Index` 把動作轉成卡包的索引。無頭時，遊戲的測試模式總是拿第一個卡包；模擬器給 `CardSelectCmd.FromChooseABundleScreen` 打補丁，改走畫面自己的路徑（保留這次選擇、詢問驅動程式、同步答案）（[模擬器：無頭宿主 §4](/zh-tw/arch/simulator/headless/#sec-4)）。

## 4. 事件與水晶球

**`EventActions`**（`Actions/EventActions.cs`），動作是 `event:i` 和 `proceed`：

- **合法動作**：事件結束之後只有 `proceed`；否則是每個未鎖定的選項，作為 `event:i`。被標記為繼續按鈕的選項是 UI 按鈕，不是選擇：遠古之民的 PROCEED 列為 `proceed`，其他任何這類選項（Trial 的 DOUBLE_DOWN，它會開啟放棄這一局的彈出視窗）永遠不合法。
- **執行**：`EventSynchronizer.ChooseLocalOption(i)`，它在背景執行這個選項。`proceed` 不改變遊戲裡的任何東西：由宿主打開地圖。
- **畫面**：事件的 id、它目前頁面的本地化鍵，以及每個選項，帶上它的文字鍵、`locked`、遠古之民的選項所給的遺物、它懸停提示的 id（升級過的牌加上 `+`），以及它的按鈕是否警告會殺死玩家。

**`CrystalSphereActions`**（`Actions/CrystalSphereActions.cs`），CRYSTAL_SPHERE 事件的小遊戲：一個由隱藏格子組成的網格，占卜次數只有幾次，每次占卜用掉一次：

- **合法動作**：每個 3×3 區塊（在邊緣處截斷）裡有隱藏格子的格子，提供 `big:X,Y`；然後每個隱藏的格子提供 `small:X,Y`。提供小工具，是為了讓玩家可以避免揭開詛咒。
- **執行**：用這個工具呼叫 `SetTool`，然後在這個格子上呼叫 `CellClicked`，和畫面的做法一樣；小遊戲結束之後會拋出例外，而最後一次占卜之後它就結束了。
- **畫面**：每一列是一個字串，`#` 表示隱藏，`.` 表示空，或是揭開的格子顯示其一部分的那件物品的字母（`R` 遺物、`P` 藥水、`C` 卡牌獎勵、`G` 金幣、`X` 詛咒；不認得的物品類型會拋出例外），以及剩餘的占卜次數。一件物品的所有格子都揭開時，就贏得它。`Of(game, cell)` 照動作的方式命名一次點擊，供 Mod 記錄用。

## 5. 商店、休息處與財寶

**`ShopActions`**（`Actions/ShopActions.cs`），動作是 `buy:SLOT`、`remove`、`leave`：

- **槽位**為商店的商品編上索引，即除了刪牌之外的所有條目，按遊戲的順序（角色牌、無色牌、遺物、藥水），賣完的也包括在內，所以一個槽位在購買之後仍保有它的編號。
- **畫面**：按槽位列出有貨的商品，每件是一張牌（它的檢視、價格、是否在特價）、一個遺物或一瓶藥水（它的 id 和價格）；以及刪牌的價格，除非已經用過了。
- **合法動作**：有貨且買得起的條目；藥水還需要藥水欄有空槽，以及遊戲允許拿藥水（`Hook.ShouldProcurePotion`；添水禁止這一點），因為少了這兩者，購買會失敗，什麼也不會改變；刪牌有貨且買得起時提供 `remove`；`leave` 一律合法。
- **執行**：條目的 `OnTryPurchaseWrapper(inventory)`，也就是點擊商品時所做的呼叫；刪牌的這個呼叫會透過選牌器詢問要刪哪張牌。在遊戲裡，之後由商店的刪牌按鈕把刪牌標記為已用，不管是誰買的（玩家或領主陽傘）；無頭時沒有按鈕，所以由一個補丁在購買成功後標記它（`Choices.CardRemovalUsed`）。`leave` 不改變任何東西：由宿主打開地圖。

**`RestActions`**（`Actions/RestActions.cs`），動作是 `rest:ID` 和 `leave`：

- **合法動作**：每個可用的選項，按它的 id（`rest:HEAL`、`rest:SMITH`）；某個選項成功之後，或沒有任何可用選項時，提供 `leave`。某個選項是否成功由宿主來說：模擬器按房間保存它，Mod 則讀取繼續按鈕。
- **執行**：`RestSiteSynchronizer.ChooseLocalOption(i)`；任務結束時給出這個選項是否成功（在提示裡取消的鍛造就不算成功）。
- **畫面**：每個選項的 id、是否可用，HEAL 還有它回復的生命值（`HealRestSiteOption.GetHealAmount`），這個值會被遺物改變。

**`TreasureActions`**（`Actions/TreasureActions.cs`），動作是 `relic:i` 和 `relic_skip`：合法的是寶箱裡的每個遺物和跳過；`Start` 像遺物按鈕那樣投票（`PickRelicLocally`、`SkipRelicLocally`）。打開寶箱不是一個決策：模擬器自己打開它，玩家則是點擊它（[模擬器：整局 §3](/zh-tw/arch/simulator/runs/#sec-3)）。

## 6. 藥水欄

`PotionActions`（`Actions/PotionActions.cs`）是戰鬥外的藥水欄，套用遊戲藥水彈出選單的規則：隨時可用且通過自身檢查的藥水提供 `potion:S`，任何還沒排入佇列的藥水提供 `discard_potion:S`；玩家不能使用藥水或已經死亡時，什麼都不提供。`Start` 透過 `EnqueueManualUse` 喝下藥水，或透過排入佇列的 `DiscardPotionGameAction` 丟掉它。`Handles(action)` 分辨藥水欄的動作和畫面自己的動作，讓宿主可以把藥水欄加進一個畫面的合法清單，並把回答轉給正確的一方。

哪些畫面帶有藥水欄由宿主選擇：模擬器和 Mod 把它加到地圖、獎勵、事件、商店、休息處、財寶和水晶球畫面上（[模擬器：整局 §4](/zh-tw/arch/simulator/runs/#sec-4)）。

## 7. 命名動作作用的對象

| 對象 | 命名方式 | 原因 |
|---|---|---|
| 手牌中的一張牌 | 它的 uid，即它在這場戰鬥的卡牌資料庫裡的 id | 手牌變動時仍然成立；在模擬器和遊戲裡相同 |
| 一個生物 | 它的 uid，即它的 `CombatId` | 同上 |
| 選牌提示的一個選項 | 它的標準索引 | 遊戲的順序可能跟著隱藏狀態（[讀取遊戲 §5](/zh-tw/arch/gamebridge/observe/#sec-5)） |
| 一份獎勵、一個事件選項、一個商店槽位、一個寶箱遺物、卡牌獎勵裡的一張牌 | 它在畫面自己清單裡的索引 | 順序是公開的，和畫面顯示的一樣 |
| 一個休息選項、一個卡牌獎勵替代選項 | 它的 id | 選項被停用或新增時，id 保持不變 |
| 一個地圖點 | `col,row` | |
| 一個水晶球格子 | `x,y`，加上工具 | |

戰鬥以外的文字動作由 `ActionText`（`Actions/ActionText.cs`，internal 類別）解析：一個動詞和它的參數，索引只接受純數字。

**SL 記錄**。Mod 只在玩家要 AI 來打時才執行動作，而且走的也是這些入口（[Mod：自動遊玩與安全 §1](/zh-tw/arch/mod/auto/#sec-1)）；在 SL 下，它必須照模擬器的命名方式記錄每一步，不論是玩家的還是 AI 的，讓大腦能為這個節點做出複本（[Mod：SL 紀錄 §3](/zh-tw/arch/mod/sl-record/#sec-3)）。它給模擬器的 start 所呼叫的那些遊戲入口打補丁，並用 GameBridge 自己的輔助函式為每一步命名，所以記錄下來的一步，就是模擬器本來會打出的動作（`Sts2Ai.Mod/NodeRecord.cs`）：

| 入口 | 記錄什麼 |
|---|---|
| `ActionQueueSynchronizer.RequestEnqueue` | 出牌、藥水和結束回合（`PlayOf`、`PotionOf`）、地圖投票（`MapActions.Text`）、藥水欄的丟棄 |
| `PlayerChoiceSynchronizer.SyncLocalChoice` | 選牌提示（遊戲的索引）、卡牌獎勵、卡包 |
| `EventSynchronizer.ChooseLocalOption`、`RestSiteSynchronizer.ChooseLocalOption` | 事件和休息處的選項 |
| `RewardsSetSynchronizer.SelectLocalReward`；`SkipLocalRewardsSet`、`ProceedFromTerminalRewardsScreen`、`SetLocalPlayerReady` | 領取一份獎勵；`rewards_done` |
| `TreasureRoomRelicSynchronizer.PickRelicLocally` | 一個寶箱遺物 |
| 商店條目或刪牌的 `OnTryPurchaseWrapper` | 一次購買（`ShopActions.Of`） |
| `CrystalSphereMinigame.CellClicked` | 一次占卜（`CrystalSphereActions.Of`） |

模擬器沒有對應決策的一步，例如在戰鬥中丟掉藥水，或沒有回答就關掉卡牌獎勵，會讓這個節點剩下部分的記錄中斷。

**兩種宿主裡的選牌提示**。在遊戲裡，提示的畫面回傳選中的牌，遊戲再透過 `PlayerChoiceSynchronizer.SyncLocalChoice`，把它們作為自己清單裡的索引同步出去，Mod 就是在那裡讀取它們的。無頭時，模擬器透過 `CardSelectCmd.Selector` 回答，這是遊戲為取代畫面的選牌器所留的鉤子；這條路徑會跳過同步（`Commands/CardSelectCmd.cs`）<Badge text="已核實" variant="success" />。
