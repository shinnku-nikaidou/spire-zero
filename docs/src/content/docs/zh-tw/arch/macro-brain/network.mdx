V 是一個神經網路，讀一局並預測它會怎麼結束。本節描述目前的版本，**純 V**（`learn/v/`），以 v6-3-2 的樣子為準：它讀什麼，每一層怎麼轉換它，以及為什麼這樣建構。接著 §4 描述**編碼器網路**，也就是下一個計畫要和它並列訓練的架構。它的輸出怎麼變成一個價值、它怎麼訓練，見[下一節](/zh-tw/arch/macro-brain/value/)。

## 1. V 讀什麼

純 V 讀**這一局是什麼和它的原始狀態，別的都不讀**。沒有手寫的特徵，沒有牌的傷害或費用，沒有遺物的效果：一張牌、一件遺物或一副牌組裡什麼要緊，由網路從對局的結局中自己學。

輸入全部讀自 Harness 在每個決策處記錄的整局觀測（[Harness §6](/zh-tw/arch/harness/#sec-6)）：

- **牌組的每張牌**：它的 id、升級次數（最多 3）以及它附魔和詛咒的 id（如果有）。
- **每件遺物**：它的 id，用完之後加上 `:used`。**每瓶藥水**：它的 id。
- **上下文**：角色、本幕的 id、本幕的一個或兩個頭目，以及本幕的 Ancient。
- **地圖**：從玩家所在的點（最後去過的點，還沒去過任何點時就是起點）沿路徑走得到的每個點，各是一個詞元：它的類型加上還有幾層，比如 `Elite+3`，有任務標記的再加 `:quest`。
- **六個數字**：樓層、生命值、最大生命值、金幣、晉階和藥水槽數。每個都用訓練資料的平均值和標準差標準化，$(x - \mu)/\sigma$，網路檔案保存這兩個值。

在訓練資料裡出現不到 3 次的 id，讀作同一個共用的*未知* id。v6-3-2 的表裡有 509 個卡牌 id、21 個修飾、260 個遺物 id、53 種藥水、26 個上下文詞元和 133 個地圖詞元，每個都把未知 id 算在內。這一切唯一的規格是 `learn/v/encode.py`；大腦的 `RunNet`（它的 `Tokens`、`MapTokens` 和 state）以及本頁的圖都照它對應。

圖中的地圖是本幕的點構成的圖，第 0 列在最下面。帶圈的點是玩家所在的位置；彩色的點是沿地圖路徑還走得到的，V 讀的就是這些；灰色的點在身後，或不在前方任何一條路徑上。把指標移到一個節點上，可以看到它的詞元。地圖是以這些詞元的*袋*（bag）來讀的：V 知道三層之後有一個菁英、四層之後有一個休息處，但不知道那個休息處是不是在同一條路徑上、排在菁英之後。編碼器網路讀的是這些路徑（[§4](#sec-4)）。

**為什麼不用手寫的知識**。第一個 V（V v0，`RunValue`）是 17 個手寫的整局特徵乘以以 1 點生命值為單位的權重：一瓶藥水值 8 點生命，一件遺物 8，一張升級過的牌 3，一枚金幣 0.1，牌組裡每張牌 −0.3，再加上牌組的平均傷害、格擋和抽牌。後來的網路 n2-b0.03 把這 17 個特徵當作輸入，訓練時又被拉向 V v0 的選擇。它的選擇跟著這些價格走。在 `promotion-1` 的 SL 對局上（n2-b0.03 是 160 局，其他是 200 局）：

|---|---|---|---|

| 生命 85–99% 時的休息處：選休息的比例 | 35% | 7% | 53% |
| 買下的藥水 | 417 | 330 | 92 |
| 買下的牌 | 55 | 313 | 162 |
| 離開商店時剩下的金幣（平均） | 89 | 27 | 36 |

一瓶值 8 點生命的藥水賣 50–75 金幣（按金幣的價格是 5–7.5 點生命），看起來永遠划算；回 21 點生命也永遠勝過值 3 的升級。手寫的價格就是手寫的策略，它錯的地方對局無法糾正，因為網路照抄它。純 V 沒有價格；它唯一的老師是這一局的結局。

## 2. 架構

網路把詞元變成每張牌一個向量，把牌組匯聚起來，把每個袋加總，接上那些數字，再把結果送過兩層的主幹（body），到達它的輸出頭。下圖從最下面的輸入畫到最上面的輸出；把指標移到一個區塊上，可以看到它計算什麼。

<ArchDiagram client:visible lang="zh-TW" net="pure" />

用公式寫，對一副 $n$ 張牌的牌組：

**卡牌向量**。第 $k$ 張牌有一個 id $c_k$、一個升級次數 $u_k \le 3$ 和修飾 id $m$（它的附魔和詛咒）。它的輸入向量有 32 個數：

$$
x_k = E[c_k] + u_k\, U[c_k] + \sum_{m \in \mathrm{mods}(k)} M[m],
$$

其中 $E$、$U$ 和 $M$ 是學出來的表（*嵌入*）：每個卡牌 id 一個向量，每個卡牌 id 一個*升級方向*，每個修飾一個向量。升級讓一張牌沿著網路為那張牌學到的方向移動。

**集合編碼器**。一個小網路 $\varphi$（32 → 128 → 128，ReLU）逐張處理每張牌，牌組用兩種方式匯聚：

$$
h_k = \varphi(x_k), \qquad \bar h = \frac{1}{n}\sum_{k=1}^{n} h_k, \qquad \tilde h = \frac{1}{16}\sum_{k=1}^{n} h_k .
$$

平均值 $\bar h$ 說明牌組由什麼組成；縮放後的總和 $\tilde h$ 還說明有多少（係數 $1/16$ 讓它大約和平均值一樣大）。

**詞元袋**。遺物、藥水、上下文和地圖，各自是它們詞元的 32 維向量之和：$r = \sum_i R[\text{relic}_i]$，其他三個也一樣。

**主幹**。牌組的兩個匯聚、四個袋和六個標準化後的數字串接成一個 $128 + 128 + 4 \cdot 32 + 6 = 390$ 個數的向量 $z$，然後

$$
b_1 = \mathrm{ReLU}(W_1 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_2 b_1 + c_2),
$$

各有 256 個數。**輸出頭**讀 $b_2$：對從 0 到 63 的每一層 $g$，一個*風險值* $h_g = \sigma(w_g^\top b_2 + a_g)$，即這一局活著到達第 $g$ 層時在那一層結束的機率；連戰的 V 還有用另一組權重得到的*比例* $s_g$（[從風險值到價值 §1](/zh-tw/arch/macro-brain/value/#sec-1)）。第三個輸出頭只在訓練時使用，不在網路檔案裡（[從風險值到價值 §3](/zh-tw/arch/macro-brain/value/#sec-3)）。

| 部分 | 形狀 | 權重數 |
|---|---|---|
| 卡牌、升級、修飾嵌入 | 509 × 32、509 × 32、21 × 32 | 33,248 |
| 遺物、藥水、上下文、地圖嵌入 | 260、53、26、133 × 32 | 15,104 |
| $\varphi$ | 32 → 128 → 128 | 20,736 |
| 主幹 | 390 → 256 → 256 | 165,888 |
| 風險值和比例輸出頭 | 256 → 64，兩個 | 32,896 |
| **總計** | | **267,872** |

## 3. 為什麼用集合編碼器

牌組是一個*多重集合*：牌的順序沒有意義，大小從大約 10 到 40 不等。按序列讀牌的網路得學會每種順序都一樣；每種牌一個計數的定長向量會有幾百個大多空著的格子，相似的牌之間也沒有任何共享。上面的架構是一個 **Deep Set**（Zaheer 等人，2017）：形如 $\rho\left(\sum_k \varphi(x_k)\right)$ 的函式對輸入的每種順序都給出相同的輸出，能讀任意大小的集合，而且每個具有這種性質的函式都能寫成這種形式。這裡 $\varphi$ 是單牌網路，$\rho$ 是主幹。

每個卡牌 id 都有自己學出來的向量，所以網路一開始對任何牌都一無所知。它對一張牌學到的東西，來自牌組裡有這張牌的那些對局，經由那些對局的每個決策。這就是出現不到 3 次的 id 讀作未知的原因：只用一兩局訓練出來的向量是雜訊。

這個設計有一個已知的限制。牌與牌之間、牌與遺物之間，只有在主幹裡才相遇，那時牌組已經被兩次匯聚成 128 個數。像「有手裏劍和苦無時小刀更值錢」這樣的關係，必須先穿過這些匯聚後的數字，才能遇到遺物袋。在匯聚之前於牌和遺物之間加一層注意力，就能讓它們直接互動；這就是編碼器網路的構築編碼器（[§4](#sec-4)）。

### 構築編碼器

這一局的每張牌、每件遺物和每瓶藥水，都成為同一個集合裡的一個元素，一個 64 個數的向量：

$$
x =
\begin{cases}
E[c] + u\, U[c] + \sum_{m} M[m] + v_{\text{card}} & \text{a card,}\\[2pt]
R[r] + v_{\text{relic}} & \text{a relic,}\\[2pt]
P[p] + v_{\text{potion}} & \text{a potion.}
\end{cases}
$$

對一張 id 為 $c$、升級次數為 $u$、修飾為 $m$ 的牌，第一行就是純 V 的卡牌向量（[§2](#sec-2)），現在寬 64 個數；$r$ 和 $p$ 是一件遺物和一瓶藥水的 id。$v_{\text{card}}$、$v_{\text{relic}}$ 和 $v_{\text{potion}}$ 是學出來的*種類向量*：它們告訴網路一個元素是三種中的哪一種。

接著，這個集合通過兩個**自注意力區塊**（Vaswani 等人，2017）。自注意力讓每個元素看集合裡的其他每個元素，並吸收它們的一個加權混合。權重由這個元素根據它自己的向量和它們的向量算出。一個區塊做兩次更新，每次都加回到元素上：

$$
x \leftarrow x + W_o\, \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{FF}(\mathrm{LN}(x)).
$$

- **LN** 是層正規化：每個向量被平移和縮放到平均值 0、變異數 1。
- **FF** 是一個小網路（64 → 128 → 64，ReLU），對每個元素單獨作用。
- **MHA** 是多頭注意力：4 個注意力頭，各 16 個數，並排執行，再串接回 64 個數。

在一個頭之內，元素 $i$ 形成一個查詢 $q_i$，每個元素 $j$ 形成一個鍵 $k_j$ 和一個值 $v_j$，各是 $\mathrm{LN}(x)$ 的一個學出來的線性映射。於是

$$
a_{ij} = \frac{\exp\!\big(q_i^\top k_j / 4\big)}{\sum_{j'} \exp\!\big(q_i^\top k_{j'} / 4\big)}, \qquad y_i = \sum_j a_{ij}\, v_j .
$$

所以 $a_{ij}$ 是元素 $i$ 對元素 $j$ 的注意程度，而 4 是 $\sqrt{16}$，常用的縮放。

一個批次把大小不同的對局用空位補齊到同一個長度。每個空位的分數在 softmax 之前減去 $10^9$，所以沒有元素會注意它。

兩個區塊之後再做最後一次層正規化，然後集合像純 V 匯聚牌組那樣匯聚：它的平均值，和它的總和乘以 $1/16$，共 128 個數。

在純 V 裡，一張牌只有在主幹裡才遇到遺物，那時牌組已經被匯聚成再也分不出哪張是哪張的數字（[§3](#sec-3)）。在這裡，任何東西被匯聚之前，小刀的向量就能因為集合裡有手裏劍和苦無而改變。這是 Set Transformer 的想法（Lee 等人，2019），套用到整套配裝上。輸出仍然不取決於元素的順序，因為注意力和匯聚對每個元素一視同仁。它和純 V 一樣只讀 id，沒有手寫的「攻擊」或「技能」標記。

### 路線編碼器

地圖袋告訴純 V：三層之後有一個菁英，四層之後有一個休息處。它分不出那個休息處是在同一條路徑上、排在菁英之後，還是在另一條、玩家得改選的路徑上。路線編碼器讀的是路徑本身。

**節點**（`encode.route`）。節點 0 是玩家所在的點。接著是還走得到的點，先按列、再按欄排序。每個節點有四個欄位：
- 它的類型（怪物、菁英、休息處、商店、未知、財寶房、遠古之民、頭目）；
- 它在玩家前方幾層，最多 16；
- 有沒有任務標記它；
- 它的連線通往的那些節點的索引。

在低預算整局對局的 1,242 個狀態上，一個狀態最多有 69 個可到達的點（平均 22 個），沒有一個點通往超過 5 個點。頭目是最後一個點，在本幕地圖的第 15 或 16 列。

**起點**。每個節點從 $s_i = T[\text{type}_i] + A[\text{ahead}_i] + q_i\, v_{\text{quest}}$ 開始，32 個數，其中有任務標記時 $q_i$ 為 1，否則為 0。

**各輪**。接著重複 16 次，每個節點都根據它的起點和它通往的那些節點重新算出：

$$
h_i \leftarrow \mathrm{ReLU}\Big( W \big[\, s_i \,;\; \max_{j \in \mathrm{next}(i)} h_j \,;\; \operatorname{mean}_{j \in \mathrm{next}(i)} h_j \,\big] + b \Big),
$$

- $[\,\cdot\,;\cdot\,]$ 把向量首尾串接。
- 最大值逐個數地取。
- 第一輪之前 $h = s$。
- 頭目不通往任何點，所以它的最大值和平均值都是 0。
- 每一輪都用同一組 $W$ 和 $b$。

經過 $k$ 輪，一個節點的向量取決於前方 $k$ 步以內的節點。於是資訊每輪從頭目往回移動一層。一幕的地圖在起點之上有 16 列，所以 16 輪能把頭目的資訊帶到任何節點。

這是一個從頭目往回、學出來的**動態規劃**。經典的動態規劃從頭目往回，對每個點算出從它出發的最佳路徑的價值，$\text{value}(i) = \text{reward}(i) + \max_{j \in \text{next}(i)} \text{value}(j)$。每一輪的形狀相同：
- 向量取代單一的值；
- 學出來的 $W$ 取代加法；
- 在最大值之外，再加上下一批點的平均值。一局不一定能走它的最佳路徑，所以其他路徑上有什麼也要緊。

用圖網路的術語來說，這是沿著地圖連線的**訊息傳遞**（Gilmer 等人，2017），只往回傳，所有輪共用同一個更新。

**輸出**。玩家節點的向量 $h_0$，以及所有節點的平均，總共 64 個數。前者是「沿著路徑，我前方有什麼」；後者概括本幕剩下的部分。

### 主幹、大小與成本

主幹讀 $128 + 64 + 64 + 6 = 262$ 個數：構築、上下文（現在寬 64 個數）、路線，以及六個數字。之後就是純 V 的主幹：256 → 256，ReLU，然後是風險值輸出頭。下一個計畫的 objective 為 `win`，價值就是獲勝的機率 $S_{63}$（[從風險值到價值 §1](/zh-tw/arch/macro-brain/value/#sec-1)）。

多出來的成本大多在 16 輪和注意力上。在大腦裡，`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）只在網路檔案的計算圖宣告了 `route` 輸入時，才建出路線的張量並餵進去，所以每個舊網路都和以前一樣載入。一個完整大小的編碼器網路在 C# 裡每次呼叫花 0.44 ms，v6-3-2 是 0.093 ms。複本上的一個宏觀決策要 70–90 ms，所以這個差別無關緊要。

**測試**。[§2](#sec-2) 的 ONNX 核對照舊適用：除非網路檔案給測試對局的值和訓練器一樣，否則大腦拒收它。此外，一個很小、沒訓練過的編碼器網路（寬度小、權重放大，`src/Sts2Ai.Tests/Fixtures/pure-v-tiny-encoders.json`）在三個真實的整局觀測上執行。路線失去連線或前方層數時，它的值變動達載入核對容差的 10 倍；每個類型都讀作未知時，達 3 倍。所以一個默默忽略地圖的路線編碼器會通不過測試。

有兩個細節來自匯出，而不是來自設計。層正規化沒有自己的縮放和平移，由它後面的線性層承擔。種類向量和任務向量從隨機值開始，而不是從零。兩者都有必要，因為 ONNX 匯出會合併數值相等的權重，那會讓它們的名字從檔案裡消失。
