V 是一個神經網路，讀一局並預測它會怎麼結束。本節從輸入到輸出描述它：它讀什麼，每一層怎麼轉換它，以及為什麼這樣建構。程式碼是 `learn/v/net.py` 裡的 `Net`，輸入的規格在 `learn/v/encode.py`。它的輸出是什麼意思、它怎麼訓練，見[下一節](/zh-tw/arch/macro-brain/value/)。想先看每一步的真實數字，請到 [§9](#sec-9)。

## 1. 整個網路

六個部分各自讀一種輸入：**牌組**、**遺物**、**藥水**、**上下文**、**地圖**和**六個數字**。它們的輸出接成一個 390 個數的向量，由一個 MLP（*多層感知器*：線性層之間夾著非線性）變成每層一個風險值。這些風險值給出價值，P(win)。

只有牌組有自己的層。其他幾個袋只是學出來的向量直接加總，部分與部分之間的一切關係都在串接之後才算出來。

五個角色都用這一個結構，一層不差，詞元表也相同；只有權重是各角色自己的（`weights/CHARACTER/`）。

## 2. 它讀什麼

V 讀**這一局是什麼和它的原始狀態，別的都不讀**。沒有手寫的特徵，沒有牌的傷害或費用，沒有遺物的效果：一張牌、一件遺物或一副牌組裡什麼要緊，由網路從對局的結局中自己學。手寫的價格（「一瓶藥水值 8 點生命」）就是手寫的策略，讀它的網路會照抄它，而它錯的地方對局無法糾正。

輸入全部來自 Harness 在每個決策處記錄的整局觀測（[Harness：決策日誌 §7](/zh-tw/arch/harness/decision-log/#sec-7)），由 `encode.tokens` 和 `encode.state` 取出：

- **牌組的每張牌**：它的 id、升級次數（更高的次數讀作 3），以及它附魔和詛咒的 id（如果有），寫作 `enchant:ID` 和 `affliction:ID`。
- **每件遺物**：它的 id，用完之後加上 `:used`。
- **每瓶持有的藥水**：它的 id。空的藥水槽不是詞元；藥水槽數是六個數字之一。
- **上下文**：`character:ID`、`act:ID`、`boss:ID`，本幕有兩個頭目時再一個 `boss:ID`，本幕有遠古之民時還有 `ancient:ID`。
- **地圖**：路徑還走得到的每個點，寫成它的類型和在前方幾層（[§4](#sec-4)）。
- **六個數字**：樓層、生命值、最大生命值、金幣、晉階和藥水槽數。

**它不讀什麼**。牌的費用和數值、附魔的數值、遺物的計數器和其他狀態。只在這些地方不同的兩局是同一個輸入。

**詞元表**。網路檔案為每種詞元保存一張 id 表。每張表列出這個遊戲版本的每個 id，已排序，排在第 0 項之後；第 0 項是同一個共用的*未知* id，讀任何其他 id，例如比檔案新的 id（`learn/game_ids.py`，來自 `learn/game_ids.json`，由模擬器的 `tables` 指令寫出）。所以表不取決於訓練資料，每個角色的網路都用同樣的表。上下文的表列出遊戲的幕、遠古之民、頭目和角色；地圖的表列出每種類型的點在前方 0 到 20 層的情形，各有帶和不帶 `:quest` 的一項。

**數字**用訓練樣本的平均值和標準差標準化，$(x - \mu)/\sigma$，每個樣本的權重是它那一局樣本數的倒數。標準差低於 $10^{-9}$ 時讀作 1。網路檔案保存 $\mu$ 和 $\sigma$。

**輸入張量**，按計算圖輸入的順序（`encode.INPUTS`）。每個清單都補齊到批次裡最長的長度，且至少為 1，並有一個遮罩，存在的是 1，補齊的是 0：

| 名稱 | 形狀 | 類型 | 內容 |
|---|---|---|---|
| `cards` | $B \times n$ | int | 每張牌在表裡的項 |
| `ups` | $B \times n$ | float | 它的升級次數，0 到 3 |
| `card_mask` | $B \times n$ | float | 存在或補齊 |
| `mods` | $B \times n \times 2$ | int | 它的修飾在表裡的項，最多 2 個 |
| `mod_mask` | $B \times n \times 2$ | float | 哪些修飾存在 |
| `relics`、`relic_mask` | $B \times r$ | int、float | 每件遺物的項，以及它的遮罩 |
| `potions`、`potion_mask` | $B \times p$ | int、float | 每瓶藥水的項，以及它的遮罩 |
| `context`、`context_mask` | $B \times c$ | int、float | 每個上下文詞元的項，以及它的遮罩 |
| `map`、`map_mask` | $B \times m$ | int、float | 每個地圖詞元的項，以及它的遮罩 |
| `state` | $B \times 6$ | float | 六個數字，標準化後 |

## 3. 牌組

牌組是一個*多重集合*：牌的順序沒有意義，大小從大約 10 到 40 不等。按序列讀，網路得學會每種順序都一樣；每種牌一個計數的向量會有幾百個大多空著的格子，相似的牌之間也沒有任何共享。所以每張牌各自通過同一個小網路，再把結果加起來：這是一個 Deep Set（Zaheer 等人，2017）。

**牌的向量**。一張 id 為 $c$、升級次數為 $u$、修飾為 $m$ 的牌成為 32 個數：

$$
x = E[c] + u\, U[c] + \sum_{m} M[m].
$$

$E$、$U$ 和 $M$ 是學出來的表（*嵌入*）：每個卡牌 id 一個向量，每個卡牌 id 一個*升級方向*，每個修飾一個向量。升級讓一張牌沿著為這張牌學到的方向移動，所以升級對一張牌可以很要緊，對另一張牌可以無關緊要。表的每一項都從標準差 0.1 的亂數開始。

**$\varphi$，牌的網路**。兩層，每張牌用同一組權重：

$$
\varphi(x) = \mathrm{ReLU}\big(W_2\, \mathrm{ReLU}(W_1 x + b_1) + b_2\big),
$$

其中 $W_1$ 是 32 → 128，$W_2$ 是 128 → 128。ReLU 是 $\max(0, x)$，逐個數地取，所以 128 個輸出都不小於 0。這裡 $\varphi$ 只看到一張牌：一張牌的兩個複製品得到相同的向量，沒有一張牌知道牌組裡還有什麼。

**匯聚**。把向量加起來，補齊的空位不算，再用兩種方式讀：

$$
\bar h = \frac{1}{n}\sum_{k=1}^{n} \varphi(x_k), \qquad \tilde h = \frac{1}{16}\sum_{k=1}^{n} \varphi(x_k).
$$

平均值說明牌組由什麼組成。只有它的話，一副牌組和它翻倍後的牌組讀起來一樣，所以縮放後的總和說明有多少（係數 $1/16$ 讓它大約和平均值一樣大）。兩者是同一個向量的兩種比例，所以這 256 個數裡是 128 個數的方向，再加上牌組的大小。

**牌與牌怎麼關聯**。匯聚後的向量是總和，所以牌與牌之間的關係不在 $\varphi$ 裡算。它分兩步得到：$\varphi$ 可以給某類牌一個專屬的數，讓總和數出這類牌有多少；然後串接之後的主幹再把這些計數互相組合，或者和遺物組合。「很多小刀加一個手裏劍」只需要這些。它的代價見 [§8](#sec-8)。

## 4. 袋：遺物、藥水、上下文、地圖

這四者都是一個**袋**：每個詞元有一個學出來的 32 個數的向量，把這些向量加起來。中間沒有層，也不取平均。一個詞元出現兩次就算兩次。

$$
\text{bag}(t_1, \dots, t_k) = \sum_{i=1}^{k} T[t_i].
$$

每個袋有自己的表 $T$：遺物 id、藥水 id、上下文詞元和地圖詞元。空袋是零向量。

**地圖的詞元**（`encode.map_tokens`）。玩家的點是最後去過的點，還沒去過任何點時就是起點（先按列、再按欄排序的第一個點）。從那裡，網路順著地圖的連線找出路徑還走得到的每個點，每個點成為一個詞元：它的類型和在前方幾層，寫作 `Elite+3`，有任務標記它時加上 `:quest`。所以這個袋說明的是，每個距離上各有多少種房間。它不含連線（[§8](#sec-8)）。

**正要進入的點**。在地圖上，V 比較選項的方式是給每個選項的後狀態估值：把這個點加進路徑，別的都不變（[搜尋 §1](/zh-tw/arch/macro-brain/search/#sec-1)）。兩個選項之後的點常常相同，所以選項只能靠這個點本身來區分。因此選路的後狀態帶一個標記（`MapView.Entering`），它的袋以進入的點開頭，寫作 `Elite+0`。

這個標記的意思是*正要進入*，僅此而已。玩家已經站著的房間不是詞元，原因很要緊：在房間裡記錄的整局觀測都在它的戰鬥之後，死在那裡的對局記錄不下來。目前房間的詞元在訓練時只會被活下來的對局讀到，V 就會把進入菁英當成已經打贏了它。

所以每次選路還會給出一個自己的訓練樣本，也就是選中的點的後狀態，加上那一局真實的結局（[從風險值到價值 §3](/zh-tw/arch/macro-brain/value/#sec-3)）。於是 V 學到的是，在這個生命值下進入菁英值多少，死在這場菁英戰裡的對局也算在內。

## 5. 主幹和輸出頭

**數字**以標準化後的值直接讀入（[§2](#sec-2)）。

**串接**。六個輸出串接成一個 $256 + 32 + 32 + 32 + 32 + 6 = 390$ 個數的向量 $z$。

**主幹**是一個兩層的 MLP，各 256 個數：

$$
b_1 = \mathrm{ReLU}(W_3 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_4 b_1 + c_2).
$$

一切都在這裡相遇。牌組沒看過遺物，地圖沒看過生命值；一條有兩個菁英的路徑適不適合這副牌組、這個生命值，要由主幹算出來。

**風險值輸出頭**是 $b_2$ 上的一個線性層，後面接一個 sigmoid：對從 0 到 63 的每一層 $g$，一個*風險值*

$$
h_g = \sigma(w_g^\top b_2 + a_g),
$$

即這一局若還在進行、在第 $g$ 層結束的機率。價值是從這一局目前的樓層 $f$ 起撐過每一層的機率：

$$
\text{P(win)} = \prod_{g = f}^{63} (1 - h_g).
$$

$f$ 之前各層的風險值會算出來，但不使用（[從風險值到價值 §2](/zh-tw/arch/macro-brain/value/#sec-2)）。

**第二個輸出頭**是 $b_2$ 上一個 7 個輸出的線性層，只在訓練時使用。它預測接下來幾場戰鬥的生命值花費，用來塑造主幹；它從不用來做決定，也不在網路檔案裡（[從風險值到價值 §4](/zh-tw/arch/macro-brain/value/#sec-4)）。

## 6. 大小與成本

| 部分 | 形狀 | 權重數 |
|---|---|---|
| 卡牌、升級、修飾嵌入 | 597 × 32、597 × 32、31 × 32 | 39,200 |
| 遺物、藥水、上下文、地圖嵌入 | 310、66、32、379 × 32 | 25,184 |
| $\varphi$ | 32 → 128 → 128 | 20,736 |
| 主幹 | 390 → 256 → 256 | 165,888 |
| 風險值輸出頭 | 256 → 64 | 16,448 |
| **總計** | | **267,456** |

詞元表是固定的，所以在這個遊戲版本上，每個角色的網路都是這些大小。只在訓練時使用的輸出頭多 1,799 個。

**這個檔案保存什麼**。檔案是 `weights/silent/v8-2.json`。它的 $\mu$ 和 $\sigma$ 是它接著訓練的那個網路的，那個網路的訓練對局全在晉階 0：晉階的 $\mu$ 是 0，$\sigma$ 讀作 1，所以 A10 讀作 10。兩次訓練都沒有過的 id，例如 `DEFEND_IRONCLAD`，保存的是未知 id 那一列；這樣的正要進入的點的地圖詞元，例如 `Unassigned+0`，則為零。

在 C# 裡，單執行緒、批次大小 1，一次呼叫大約花 0.09 ms。複本上的一個宏觀決策要 70–90 ms，大部分花在遊戲裡（[搜尋 §6](/zh-tw/arch/macro-brain/search/#sec-6)），所以 V 自身的成本無關緊要。

## 7. 一次前向計算，兩種實作

訓練器用 PyTorch 計算網路；大腦用 C# 執行它。兩者必須完全一致，靠的是網路檔案（`weights/silent/NAME.json`，[學習：參考 §7](/zh-tw/arch/learning/reference/#sec-7)）：

- **匯出**：`learn/v/export.py` 把網路寫成檔案裡的一個 ONNX 計算圖，sigmoid 包含在內，輸入按 [§2](#sec-2) 命名，每個長度都不固定。旁邊是詞元表、$\mu$ 和 $\sigma$、objective `win`、訓練報告，以及 8 個留出的樣本和訓練器給它們的值。
- **推論**：`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）依照 `encode.py`：它的 `Tokens` 和 state 建出同樣的張量，由 ONNX Runtime 執行計算圖。只有計算圖宣告了的輸入才餵進去。`Value` 把目前樓層起的風險值連乘起來。
- **核對**：除非這個檔案給這 8 個樣本的值和訓練器一樣（差距在 0.1% 以內，最小的那些值用 $10^{-6}$，那裡浮點數的雜訊更大），否則 `RunNet.Load` 拒收它。任何一邊讀一局的方式有差異，檔案就載入不了。P(win) 的值大多低於 0.01，所以不是相對值的容差幾乎什麼都放得過。

## 8. 結構表達不了什麼

這些單從結構就能推出。

- **加總之前，牌看不到別的牌**：牌與牌之間的關係只能以撐過相加的數字到達主幹。數出一類牌很容易；特定幾張牌之間的關係，得在所有牌共用的 128 個數裡找到自己的數。
- **遺物的袋是線性的**：310 件遺物共用 32 個數，串接之前沒有任何層。兩件遺物之間、一件遺物和一張牌之間的關係，只能由主幹算出來。
- **地圖的袋不含連線**：它列出每個距離上有什麼，不說明哪個點通往哪個點。分別在兩條路徑上的一個菁英和一個休息處，讀起來和兩者同在一條路徑上一樣。玩家面前的選擇靠每個選項自己的袋看到；更前面的選擇看不到。
- **地圖隨本幕結束**：網路讀目前這一幕剩下的點。對之後的幕，它只知道樓層暗示的東西；它們的地圖、頭目和遠古之民不在整局觀測的地圖裡。
- **身後的就沒了**：已經走過的點，以及不在前方任何路徑上的點，都不是詞元。這一局在那裡得到的東西，留在它的配裝、生命值和金幣裡。
- **只有 id，沒有規則**：網路認識一張牌，只靠牌組裡有它的那些對局。訓練資料裡從未有過的牌什麼也沒學到，不管它做什麼。
- **每種風險一個數**：風險值說明這一局在每一層結束的可能性，不說明原因。單一的輸出頭必須承載每一種死法。
