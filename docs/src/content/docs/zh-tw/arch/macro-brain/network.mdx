V 是一個神經網路，讀一局並預測它會怎麼結束。本節從輸入到輸出描述它：它讀什麼，每一層怎麼轉換它，以及為什麼這樣建構。程式碼是 `learn/v/net.py` 裡的 `EncoderNet`，輸入的規格在 `learn/v/encode.py`。它的輸出是什麼意思、它怎麼訓練，見[下一節](/zh-tw/arch/macro-brain/value/)。

## 1. 整個網路

四個部分各自讀四種輸入：讀配裝的**構築編碼器**、讀地圖的**路線編碼器**、一袋**上下文**詞元，以及**六個數字**。它們的輸出接成一個 262 個數的向量，由一個 MLP（*多層感知器*：線性層之間夾著非線性）變成每層一個風險值。這些風險值給出價值，P(win)。

這張圖仿照 Transformer 論文的圖來畫：輸入在最下面，框表示重複的區塊（×2：兩個區塊，各有自己的權重；×16：同一輪，用同一組權重跑 16 次），⊕ 表示殘差相加，旁邊的線是越過區塊、直接往上送的輸入。把指標移到一個區塊上，可以看到它計算什麼。

一路上的形狀，其中批次有 $B$ 局，$n$ 張牌、$r$ 件遺物、$p$ 瓶藥水、$e = n + r + p$ 個元素、$c$ 個上下文詞元、$m$ 個路線節點，下一批節點最多 $f$ 個：

| 步驟 | 內容 | 形狀 |
|---|---|---|
| 構築 | 每張牌、每件遺物和每瓶藥水各一個向量 | $B \times e \times 64$ |
| | 兩個注意力區塊，再一次層正規化 | $B \times e \times 64$ |
| | 平均值和總和 ÷ 16，串接 | $B \times 128$ |
| 路線 | 每個節點的起點 | $B \times m \times 32$ |
| | 一輪裡下一批節點的向量 | $B \times m \times f \times 32$ |
| | 起點、最大值和平均值，串接 | $B \times m \times 96$ |
| | 一輪之後的每個節點 | $B \times m \times 32$ |
| | 玩家的節點和全部節點的平均，串接 | $B \times 64$ |
| 上下文 | 各詞元的向量，加總 | $B \times 64$ |
| 數字 | 標準化 | $B \times 6$ |
| 串接 | 全部四個 | $B \times 262$ |
| 主幹 | 兩層 | $B \times 256$ |
| 輸出頭 | 每層一個風險值 | $B \times 64$ |

## 2. 它讀什麼

V 讀**這一局是什麼和它的原始狀態，別的都不讀**。沒有手寫的特徵，沒有牌的傷害或費用，沒有遺物的效果：一張牌、一件遺物或一副牌組裡什麼要緊，由網路從對局的結局中自己學。手寫的價格（「一瓶藥水值 8 點生命」）就是手寫的策略，讀它的網路會照抄它，而它錯的地方對局無法糾正。

輸入全部來自 Harness 在每個決策處記錄的整局觀測（[Harness：決策日誌 §7](/zh-tw/arch/harness/decision-log/#sec-7)），由 `encode.tokens` 和 `encode.state` 取出：

- **牌組的每張牌**：它的 id、升級次數（更高的次數讀作 3），以及它附魔和詛咒的 id（如果有），寫作 `enchant:ID` 和 `affliction:ID`。
- **每件遺物**：它的 id，用完之後加上 `:used`。
- **每瓶持有的藥水**：它的 id。空的藥水槽不是詞元；藥水槽數是六個數字之一。
- **上下文**：`character:ID`、`act:ID`、`boss:ID`，本幕有兩個頭目時再一個 `boss:ID`，本幕有遠古之民時還有 `ancient:ID`。
- **路線**：玩家所在的位置，以及路徑還走得到的每個點（[§4](#sec-4)）。
- **六個數字**：樓層、生命值、最大生命值、金幣、晉階和藥水槽數。

**詞元表**。網路檔案為每種詞元保存一張 id 表。表是從訓練樣本建出來的：在那裡出現不到 3 次的 id 讀作第 0 項，同一個共用的*未知* id。次數按決策計算，所以一局裡在三個決策處出現過的牌就有自己的一項。從先前的網路接著訓練的網路沿用那個網路的表，它沒見過的 id 讀作未知。

**數字**用訓練樣本的平均值和標準差標準化，$(x - \mu)/\sigma$，每個樣本的權重是它那一局決策數的倒數。標準差低於 $10^{-9}$ 時讀作 1。網路檔案保存 $\mu$ 和 $\sigma$。

**輸入張量**，按計算圖輸入的順序（`encode.ENCODER_INPUTS`）。每個清單都補齊到批次裡最長的長度，且至少為 1，並有一個遮罩，存在的是 1，補齊的是 0：

| 名稱 | 形狀 | 類型 | 內容 |
|---|---|---|---|
| `cards` | $B \times n$ | int | 每張牌在表裡的項 |
| `ups` | $B \times n$ | float | 它的升級次數，0 到 3 |
| `card_mask` | $B \times n$ | float | 存在或補齊 |
| `mods` | $B \times n \times 2$ | int | 它的修飾在表裡的項，最多 2 個 |
| `mod_mask` | $B \times n \times 2$ | float | 哪些修飾存在 |
| `relics`、`relic_mask` | $B \times r$ | int、float | 每件遺物的項，以及它的遮罩 |
| `potions`、`potion_mask` | $B \times p$ | int、float | 每瓶藥水的項，以及它的遮罩 |
| `context`、`context_mask` | $B \times c$ | int、float | 每個上下文詞元的項，以及它的遮罩 |
| `route` | $B \times m$ | int | 每個節點類型的項 |
| `route_ahead` | $B \times m$ | int | 在玩家前方幾層，0 到 16 |
| `route_quest` | $B \times m$ | float | 有任務標記這個節點時為 1 |
| `route_mask` | $B \times m$ | float | 存在或補齊 |
| `route_next` | $B \times m \times f$ | int | 它通往的節點的索引 |
| `route_next_mask` | $B \times m \times f$ | float | 其中哪些存在 |
| `state` | $B \times 6$ | float | 六個數字，標準化後 |

## 3. 構築編碼器

牌組是一個*多重集合*：牌的順序沒有意義，大小從大約 10 到 40 不等。遺物和藥水也是集合，它們的價值取決於牌，也取決於彼此：有手裏劍和苦無時，小刀更值錢。所以三者都進入**同一個集合**，集合的元素在匯聚之前就彼此作用。按序列讀，網路得學會每種順序都一樣；每種牌一個計數的向量會有幾百個大多空著的格子，相似的牌之間也沒有任何共享。

**元素**。每張牌、每件遺物和每瓶藥水都成為一個 64 個數的向量：

$$
x =
\begin{cases}
E[c] + u\, U[c] + \sum_{m} M[m] + v_{\text{card}} & \text{a card,}\\[2pt]
R[r] + v_{\text{relic}} & \text{a relic,}\\[2pt]
P[p] + v_{\text{potion}} & \text{a potion.}
\end{cases}
$$

$E$、$U$、$M$、$R$ 和 $P$ 是學出來的表（*嵌入*）：每個卡牌 id 一個向量，每個卡牌 id 一個*升級方向*，每個修飾、每個遺物 id 和每個藥水 id 各一個向量。一張 id 為 $c$、升級次數為 $u$ 的牌，沿著為這張牌學到的方向移動 $u$ 步。$v_{\text{card}}$、$v_{\text{relic}}$ 和 $v_{\text{potion}}$ 是學出來的*種類向量*，告訴網路一個元素是三種中的哪一種。表的每一項都從標準差 0.1 的亂數開始，種類向量也是。

**自注意力區塊**（Vaswani 等人，2017）讓每個元素看集合裡的其他每個元素，並吸收它們的一個加權混合。權重由這個元素根據它自己的向量和它們的向量算出。這樣的區塊有兩個，各有自己的權重，每個做兩次更新，都加回到元素上：

$$
x \leftarrow x + W_o\, \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{FF}(\mathrm{LN}(x)).
$$

- **LN** 是層正規化：每個向量被平移和縮放到平均值 0、變異數 1。正規化在每次更新之前做（*pre-norm*）。
- **MHA** 是多頭注意力，見下。
- **$W_o$** 是注意力輸出上一個 64 → 64 的線性層。
- **FF** 是一個小 MLP（64 → 128 → 64，中間有一個 ReLU），對每個元素單獨作用。

**多頭注意力**。一個線性層把每個正規化後的元素從 64 個數映射到 192 個，再切成 4 個頭各自的查詢、鍵和值，各 16 個數。在一個頭之內，元素 $i$ 有一個查詢 $q_i$，每個元素 $j$ 有一個鍵 $k_j$ 和一個值 $v_j$。於是

$$
a_{ij} = \frac{\exp\!\big(q_i^\top k_j / 4 + \text{pad}_j\big)}{\sum_{j'} \exp\!\big(q_i^\top k_{j'} / 4 + \text{pad}_{j'}\big)}, \qquad y_i = \sum_j a_{ij}\, v_j .
$$

$a_{ij}$ 是元素 $i$ 對元素 $j$ 的注意程度，而 4 是 $\sqrt{16}$，常用的縮放。$\text{pad}_j$ 對存在的元素是 0，對補齊的空位是 $-10^9$，所以沒有元素會注意空位。四個 $y_i$ 串接回 64 個數，再通過 $W_o$。

**沒有位置**。句子上的 Transformer 會把每個詞的位置加到它的向量上。這裡沒有：元素沒有順序。注意力和匯聚對每個元素一視同仁，所以輸出不取決於集合的順序。一張牌的兩個複製品有相同的向量，經過每一層都保持相同。

**匯聚**。兩個區塊之後再做最後一次層正規化，補齊的空位設為零，然後集合用兩種方式匯聚：

$$
\bar x = \frac{1}{e}\sum_{k=1}^{e} x_k, \qquad \tilde x = \frac{1}{16}\sum_{k=1}^{e} x_k .
$$

平均值說明配裝由什麼組成；縮放後的總和還說明有多少（係數 $1/16$ 讓它大約和平均值一樣大）。兩者共 128 個數。這種集合的匯聚函式是 Deep Set（Zaheer 等人，2017），而匯聚之前先做注意力是 Set Transformer 的想法（Lee 等人，2019），這裡套用到整套配裝上。它只讀 id，沒有手寫的「攻擊」或「技能」標記。

## 4. 路線編碼器

地圖上的選擇是路徑的選擇：同一條路徑上、排在菁英之後的休息處，和另一條、玩家得改選的路徑上的休息處並不一樣。所以路線編碼器讀的是路徑本身。

**節點**（`encode.route`）。節點 0 是玩家所在的位置：最後去過的點，還沒去過任何點時就是起點（先按列、再按欄排序的第一個點）。接著是從那裡沿路徑還走得到的點，順著地圖的連線找出，先按列、再按欄排序。每個節點有四個欄位：

- 它的類型（怪物、菁英、休息處、商店、未知、財寶房、遠古之民、頭目）；
- 它在玩家前方幾層，最多 16；
- 有沒有任務標記它；
- 它的連線通往的那些節點在這份清單裡的索引。

在低預算整局對局的 1,242 個狀態上，一個狀態最多有 69 個可到達的點（平均 22 個），沒有一個點通往超過 5 個點。頭目是最後一個點，在本幕地圖的第 15 或 16 列。

**起點**。每個節點從 $s_i = T[\text{type}_i] + A[\text{ahead}_i] + q_i\, v_{\text{quest}}$ 開始，32 個數，其中 $T$ 和 $A$ 是學出來的表，$v_{\text{quest}}$ 是學出來的向量，有任務標記時 $q_i$ 為 1，否則為 0。

**各輪**。接著重複 16 次，每個節點都根據它的起點和它通往的那些節點重新算出：

$$
h_i \leftarrow \mathrm{ReLU}\Big( W \big[\, s_i \,;\; \max_{j \in \mathrm{next}(i)} h_j \,;\; \operatorname{mean}_{j \in \mathrm{next}(i)} h_j \,\big] + b \Big),
$$

- $[\,\cdot\,;\cdot\,]$ 把向量首尾串接，共 96 個數。
- 最大值逐個數地取。
- 第一輪之前 $h = s$。
- 頭目不通往任何點，所以它的最大值和平均值都是 0（程式碼用 `leads` 把它們設為 0，並用 `route_next_mask` 把補齊的下一批節點排除在兩者之外）。
- 每一輪都用同一組 $W$ 和 $b$，每一輪也都重新讀起點 $s_i$。

經過 $k$ 輪，一個節點的向量取決於前方 $k$ 步以內的節點。於是資訊每輪從頭目往回移動一層。一幕的地圖在起點之上有 16 列，所以 16 輪能把頭目的資訊帶到任何節點。

這是一個從頭目往回、學出來的**動態規劃**。經典的動態規劃從頭目往回，對每個點算出從它出發的最佳路徑的價值，$\text{value}(i) = \text{reward}(i) + \max_{j \in \text{next}(i)} \text{value}(j)$。每一輪的形狀相同：

- 向量取代單一的值；
- 學出來的 $W$ 取代加法；
- 在最大值之外，再加上下一批點的平均值。一局不一定能走它的最佳路徑，所以其他路徑上有什麼也要緊。

用圖網路的術語來說，這是沿著地圖連線的**訊息傳遞**（Gilmer 等人，2017），只往回傳，所有輪共用同一個更新。

**輸出**。玩家節點的向量 $h_0$，以及所有節點的平均，總共 64 個數。前者是「沿著路徑，我前方有什麼」；後者概括本幕剩下的部分。

## 5. 主幹和輸出頭

**上下文和數字**。上下文是一個袋：它的詞元的向量，各 64 個數，加總起來。六個標準化後的數字直接讀入。

**串接**。四個輸出串接成一個 $128 + 64 + 64 + 6 = 262$ 個數的向量 $z$。

**主幹**是一個兩層的 MLP，各 256 個數：

$$
b_1 = \mathrm{ReLU}(W_1 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_2 b_1 + c_2).
$$

一切都在這裡相遇。路線沒看過生命值，配裝沒看過地圖；一條有兩個菁英的路徑適不適合這副牌組、這個生命值，要由主幹算出來。

**風險值輸出頭**是 $b_2$ 上的一個線性層，後面接一個 sigmoid：對從 0 到 63 的每一層 $g$，一個*風險值*

$$
h_g = \sigma(w_g^\top b_2 + a_g),
$$

即這一局若還在進行、在第 $g$ 層結束的機率。價值是從這一局目前的樓層 $f$ 起撐過每一層的機率：

$$
\text{P(win)} = \prod_{g = f}^{63} (1 - h_g).
$$

$f$ 之前各層的風險值會算出來，但不使用（[從風險值到價值 §2](/zh-tw/arch/macro-brain/value/#sec-2)）。

**第二個輸出頭**是 $b_2$ 上一個 7 個輸出的線性層，只在訓練時使用。它預測接下來幾場戰鬥的生命值花費，用來塑造主幹；它從不用來做決定，也不在網路檔案裡（[從風險值到價值 §4](/zh-tw/arch/macro-brain/value/#sec-4)）。

## 6. 大小與成本

| 部分 | 形狀 | 權重數 |
|---|---|---|
| 卡牌、升級、修飾嵌入 | 509 × 64、509 × 64、21 × 64 | 66,496 |
| 遺物、藥水、上下文嵌入 | 260、53、26 × 64 | 21,696 |
| 種類向量和任務向量 | 3 × 64、32 | 224 |
| 類型和前方層數嵌入 | 9 × 32、17 × 32 | 832 |
| 兩個自注意力區塊 | 寬 64、4 個頭、前饋 128 | 66,432 |
| 路線更新 $W, b$ | 96 → 32 | 3,104 |
| 主幹 | 262 → 256 → 256 | 133,120 |
| 風險值輸出頭 | 256 → 64 | 16,448 |
| **總計** | | **308,352** |

嵌入的大小取決於詞元表，詞元表又取決於訓練資料；這張表按資料給出的大致大小計算，類型則是八種點類型加上未知 id。一個自注意力區塊的注意力有 16,608 個權重（64 → 192、64 → 64），前饋有 16,576 個（64 → 128 → 64）。只在訓練時使用的輸出頭多 1,799 個。

在 C# 裡，單執行緒、批次大小 1，一次呼叫花 0.44 ms。大部分花在注意力和 16 輪上。複本上的一個宏觀決策要 70–90 ms，大部分花在遊戲裡（[搜尋 §6](/zh-tw/arch/macro-brain/search/#sec-6)），所以 V 自身的成本無關緊要。

## 7. 一次前向計算，兩種實作

訓練器用 PyTorch 計算網路；大腦用 C# 執行它。兩者必須完全一致，靠的是網路檔案（`weights/silent/NAME.json`，[學習：參考 §7](/zh-tw/arch/learning/reference/#sec-7)）：

- **匯出**：`learn/v/export.py` 把網路寫成檔案裡的一個 ONNX 計算圖，sigmoid 包含在內，輸入按 [§2](#sec-2) 命名，每個長度都不固定。旁邊是詞元表、$\mu$ 和 $\sigma$、objective `win`、訓練報告，以及 8 個留出的對局和訓練器給它們的值。
- **推論**：`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）依照 `encode.py`：它的 `Tokens`、`Route` 和 state 建出同樣的張量，由 ONNX Runtime 執行計算圖。只有計算圖宣告了的輸入才餵進去。`Value` 把目前樓層起的風險值連乘起來。
- **核對**：除非這個檔案給這 8 局的值和訓練器一樣（差距在 $10^{-3}$ 以內），否則 `RunNet.Load` 拒收它。任何一邊讀一局的方式有差異，檔案就載入不了。
- **默默失效的路線**：一個很小、沒訓練過的網路（寬度小、權重放大，`src/Sts2Ai.Tests/Fixtures/pure-v-tiny-encoders.json`）在三個真實的整局觀測上執行。路線失去連線或前方層數時，它的值必須變動達載入核對容差的 10 倍；每個類型都讀作未知時，達 3 倍。所以一個默默忽略地圖的路線編碼器會通不過測試。

網路有兩個細節來自匯出，而不是來自設計。層正規化沒有自己的縮放和平移，由它後面的線性層承擔。種類向量和任務向量從隨機值開始，而不是從零。兩者都有必要，因為 ONNX 匯出會合併數值相等的權重，那會讓它們的名字從檔案裡消失，而從一個網路檔案接著訓練時，正是按這些名字把權重讀回來。

## 8. 結構表達不了什麼

這些單從結構就能推出；每一點在實戰中代價多大，還沒有量測。

- **路線看不到構築**：一個節點的向量只從地圖算出。一條路徑對這副牌組、這個生命值值多少，只能在主幹裡算出來，根據的是概括整條路線的 64 個數。
- **最大值混合了路徑**：下一批節點上的最大值逐個數地取，所以一個節點的向量可以在不同的數裡保存不同路徑的最佳。它不是任何一條路徑的向量。
- **路線隨本幕結束**：網路讀目前這一幕剩下的點。對之後的幕，它只知道樓層暗示的東西；它們的地圖、頭目和遠古之民不在整局觀測的地圖裡。
- **身後的就沒了**：已經走過的點，以及不在前方任何路徑上的點，都不是節點。這一局在那裡得到的東西，留在它的配裝、生命值和金幣裡。
- **匯聚是瓶頸**：配裝不管多大，到達主幹時都是 128 個數。兩個元素之間的關係，要嘛在兩個注意力區塊裡算出來，要嘛撐過匯聚。
- **兩個區塊**：一個元素的向量吸收其他元素兩次。需要更多步的關係必須擠進這兩次裡。
- **只有 id，沒有規則**：網路認識一張牌，只靠牌組裡有它的那些對局。訓練資料裡出現不到 3 次的牌讀作共用的未知 id，不管它做什麼。
- **每種風險一個數**：風險值說明這一局在每一層結束的可能性，不說明原因。單一的輸出頭必須承載每一種死法。
