規劃器的工作單位是從一個狀態出發的一個回合。[束](/zh-tw/arch/sl-planner/beam/)決定搜尋哪些狀態；本節講的是一次這樣的搜尋內部發生了什麼（`SlPlanner.SearchTurn`）。無論它在宿主裡還是在 worker 裡執行，搜尋都是同一個，正因如此，一個回合才能成為送給 worker 行程池的一個請求（[戰鬥大腦：提示、招式與 worker §3](/zh-tw/arch/combat-brain/shared/#sec-3)）。

## 1. 對回合做深度優先搜尋

從這個狀態出發，搜尋嘗試每個合法動作，再從每個結果狀態出發嘗試每個合法動作，深度優先：沿一個序列走到底，再回溯去試下一個。每個狀態上的順序是固定的：**先結束回合**，再按手牌順序出牌，最後是藥水。每一步都可以結束回合，這個做法來自 bottled_ai（一個前人做的殺戮尖塔機器人），所以一條路線可以在打出任意張牌之後停下。

一條路線以兩種方式之一結束：

- **回合結束**。接下來的敵方回合在同一個世界裡真實地打完，所以回合的結束是下一回合第一個決策處的狀態，敵人已經行動過（而且在 SL 下，正是它們將會怎樣行動）。
- **戰鬥結束**，贏或輸，在路線的任何一點。

途中的選牌提示交給 `p0`，和對局裡一樣（[戰鬥大腦：提示、招式與 worker §1](/zh-tw/arch/combat-brain/shared/#sec-1)）。打出的每個動作是預算的一個**節點**。

## 2. 置換和完整的隱藏狀態

同樣的牌換個順序打，常常到達同一個狀態，把每種順序都展開的搜尋，會把大部分節點花在重複上（[戰鬥大腦 §2](/zh-tw/arch/combat-brain/#sec-2)）。所以每個狀態只搜尋一次：搜尋把見過的狀態記下來，鍵是

$$
\text{鍵}(s) = \big(\,\mathrm{hash}(\text{觀測}),\ \mathrm{hash}(\text{隱藏狀態})\,\big),
$$

見過的狀態不再展開。在 SL 下，隱藏部分是完整的那一份（`HiddenState.Full`）：抽牌堆的順序、每條亂數流的位置、每個怪物排好的招式和它至今的出招，以及戰鬥歷史裡本回合的內容，作為多重集。

為什麼要完整的隱藏狀態，而不只是觀測？兩種順序可能到達同一個觀測，而亂數流在不同的位置：洗過一次牌、一個隨機目標或一張生成的牌之後，一種順序從某條流裡抽過，另一種沒有。它們之後就會抽到不同的未來。只以觀測為鍵時，先搜到的那一個會把自己的估值給另一個。把隱藏狀態也放進鍵裡，它們就保持分開，搜尋也就免費看到哪種順序把亂數流安排得最好：這正是 SL 允許的亂數流操縱（[概覽 §1](/zh-tw/arch/sl-planner/#sec-1)）。回合的歷史作為多重集進入鍵，不帶順序，所以同樣的出牌換個順序仍然會合併。

只合併一個回合內的置換。所以回合結束時保留的狀態，永遠是從決策出發的一條具體動作路線的終點，計畫在它被搜尋的那個世界裡能精確重播。

## 3. 在各個第一動作之間分享節點

一個回合的搜尋有 $N$ 個節點的預算，每個力度等級都是 300（低預算時是 150，[預算 §2](/zh-tw/arch/sl-planner/budget/#sec-2)）。深度優先時，不設限的搜尋會把節點全花在它試的第一張牌下面。所以在回合開始處，節點分給它的 $m$ 個第一動作：其中第 $k$ 個可以一直搜尋，直到總共用掉

$$
\text{上限}_k = \max\!\Big(\text{已用} + 1,\ \Big\lfloor \frac{N k}{m} \Big\rfloor\Big)
$$

個節點。用不完自己份額的第一動作，把剩下的留給後面的動作。在第一動作之下，子樹深度優先地花它的份額；一旦到達上限，那個狀態上剩下的動作就不再嘗試，這個回合被標記為**截斷**（cut）。截斷的回合可能錯過了更好的結束，這對證明很重要（[束搜尋 §5](/zh-tw/arch/sl-planner/beam/#sec-5)）。

下圖在一個小到能整個畫出來的虛構回合上執行這個搜尋：兩點能量、四張牌（其中一張免費）、一個敵人。每一列是一個節點，按搜尋打出它的順序排列，按深度縮排，按它的第一動作著色。標著*合併*的列到達一個見過的狀態，就停在那裡；標著*結局相同*的列到達另一種順序已經找到的回合結束。調低預算可以看到份額如何截掉後面的第一動作，也可以改變保留幾個狀態。

## 4. 一個回合的搜尋回傳什麼

在每個回合結束處，葉節點為狀態估值，並算出一個**上界**（bound）：以那個狀態現有的生命值和藥水贏下戰鬥的價值；只要戰鬥既不回血也不給藥水，它的任何後續都勝不過這個值（[束搜尋 §2](/zh-tw/arch/sl-planner/beam/#sec-2)）。搜尋回傳（`TurnSearch`）：

- 這個回合能到達的最好的**戰鬥**結束，贏或輸，如果有的話；
- **在下一回合開始處**按葉節點估值最好的 `keep` 個不同狀態；
- 其中不含上界勝不過所給下限（目前最好的完整路線）的狀態；
- 它用掉的節點，以及它是否被截斷（節點用完，或找到的結束狀態比保留的多）。

每個結束狀態帶著它的路線（動作，以及計畫將要依循的觀測雜湊）、它的戰鬥狀態、估值、上界和鍵，以及直到它為止的敵人出招記錄，下一回合的搜尋和它的葉節點就從那裡接著走（[戰鬥大腦：提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。

貪婪下潛向它的每個回合要求所有結束狀態，不給下限（[束搜尋 §3](/zh-tw/arch/sl-planner/beam/#sec-3)）。之後完整的束來到同一個狀態時，不會再搜尋那個回合：它取下潛的結束狀態，保留自己的寬度和下限允許的那些（`Narrow`）。下限只會丟掉結束狀態，而保留的都是最好的、順序也相同，所以結果和重新搜尋一次給出的一樣。
