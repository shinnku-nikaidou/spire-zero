[回合搜尋](/zh-tw/arch/sl-planner/turn-search/)從一個狀態出發，完整搜尋一個回合。一場戰鬥有許多回合，若把每條路線的每個回合都完整搜尋，數量會無止境地成倍增長。規劃器在每個回合只保留最有希望的狀態，並剪掉那些不可能影響結果的狀態。[§1](#sec-1)–[§6](#sec-6) 是執行中的程式碼：跨回合的束（`SlPlanner.Search`）、剪枝用的上界，以及選擇、證明和重新規劃一條路線的規則。[§7](#sec-7) 是規劃中的搜尋，它取代下潛和束的位置。

## 1. 跨回合的束

**束搜尋**（beam search）是一種廣度優先搜尋：在每一層深度只保留最好的 $B$ 個狀態，也只展開它們。這裡的一層深度就是一個回合。設 $S_0 = \{s_0\}$ 為決策的狀態，$v^{\star}$ 為到目前為止已結束戰鬥的路線中最好那條的估值：

$$
S_{t+1} = \operatorname{top}_B \Big\{\, e \in \bigcup_{s \in S_t} \operatorname{ends}(s) \ :\ e \text{ 仍在進行中},\ \ \operatorname{bound}(e) > v^{\star} \Big\}
$$

其中 $\operatorname{ends}(s)$ 是從 $s$ 出發的回合搜尋所回傳的結束狀態，$\operatorname{top}_B$ 按葉節點估值取最好的 $B$ 個、按鍵彼此不同，而每個已結束戰鬥的結束狀態則改為更新 $v^{\star}$。排序是穩定的，所以打平的狀態保持它們被搜尋的順序，束也不取決於哪個 worker 先回覆。束一直走到沒有狀態剩下，最多 40 個回合。

$B$ 是 `Budget.Beam`（`--beam`）：除了 max 是 16，每個力度等級都是 8（[預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。每個保留狀態的這一回合，用預算裡每個狀態每回合的節點數來搜尋。在菁英戰和頭目戰裡，`--elite-x` 和 `--boss-x` 把 $B$ 和 [§4](#sec-4) 的簡易束 $E$ 乘上倍數；兩者預設都是 1。

一個回合結束時的狀態通常比束保留的多得多：一個回合各種不同的結束狀態，在全部 8 個保留狀態之間合起來只有最好的 8 個留下。這是規劃器主要的近似，也是它大多數計畫沒有被證明的原因（[§5](#sec-5)）。

## 2. 上界

一個仍在進行中的狀態有一個**上界**（bound）：以它現有的生命值和藥水打贏這場戰鬥時，葉節點給的估值。按 `LeafValue` 的價格，生命值比例為 $s$、藥水 $q$ 瓶時，它是 $0.2 + 0.6\,s + 0.02\,q$（[戰鬥大腦：葉節點 §2](/zh-tw/arch/combat-brain/leaf/#sec-2)）。如果戰鬥剩下的部分只會失去生命值、用掉藥水，那麼經過這個狀態的路線，結束時都不可能高於它的上界。所以一旦有一條路線以估值 $v^{\star}$ 結束了戰鬥，每個上界不超過 $v^{\star}$ 的狀態都會被丟掉，不只從束裡丟掉，在回合搜尋內部就已經丟掉：它最多只能打平。

**決策的上界**是決策本身那個狀態的上界：一場不失去任何生命值、也不用掉任何藥水的勝利。達到它的路線不可能被超越。

上界假設這場戰鬥既不回血也不給藥水。少數牌、藥水和遺物會打破這個假設（回血、戰鬥中生成的藥水），這時剪枝可能丟掉一條本來更好的路線。除此之外，讓上界成立的是葉節點自身的形狀：`LeafValue` 給進行中狀態的估值，從不高於以相同生命值所能達到的勝利；V 的價格也出於同樣的理由，被做成隨生命值單調（[戰鬥大腦：葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）。 沒有任何東西讓它們隨藥水單調：V 可能給少一瓶藥水的勝利更高的價格，這時上界也可能丟掉更好的路線。

## 3. 貪婪下潛

剪枝需要一個下限，而完整的束在它的第一個回合還沒有下限。所以在完整的束之前，規劃器先跑一個寬度為 1 的束：每個回合只按葉節點保留最好的那一個狀態。這個**貪婪下潛**（greedy dive）用一條路線打到戰鬥結束，通常是勝利（在 v6-3-2 的評估裡，贏下的普通戰鬥有 99.8% 是第一個計畫就贏下的，[預算 §3](/zh-tw/arch/sl-planner/budget/#sec-3)）。它的估值就是下限，從完整束的第一個回合起就用來剪枝。

- 下潛達到決策的上界時，沒有什麼能超越它，完整的束就跳過。
- 下潛要求它的每個回合回傳所有結束狀態，不設下限，並把它們留著。完整的束在前期會經過同樣的狀態（它的第一個回合必定如此），就直接取下潛那些回合的結束狀態，而不再搜尋一遍（[回合搜尋 §4](/zh-tw/arch/sl-planner/turn-search/#sec-4)）。在測試集上沒有證明的計畫裡，這省下 14–16% 的節點，而每個計畫都沒有改變。

## 4. 簡易束

下潛贏了但沒達到上界時，這場戰鬥已經能贏；完整的束只可能找到一場留下更多生命值或藥水的勝利。所以它每回合保留 $E$ 個狀態，而不是 $B$ 個（`Budget.EasyBeam`，`--easy-beam`；medium 力度是 4，low 是 2）。下潛輸了時，完整的束保留 $B$ 個：這時它要找的是究竟能不能贏。

medium 力度比 high 省下的時間大多來自簡易束，high 則始終保留 $B$ 個：贏一場普通戰鬥，medium 花 9.5 s，high 花 13.8 s，而兩者到達同樣的層數（[預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。在每場普通戰鬥都用較窄的束，省下的時間一樣多，但在低生命值或最大生命值只有 1 的普通戰鬥裡，會錯過不掉血的那條路線；簡易束只要下潛輸了，就保留完整的寬度。

## 5. 選出路線，並證明它

選中的是結束戰鬥的最好路線，除非束在回合上限處停在一個葉節點估值更高的狀態上。每場失敗都值 0，所以在會輸的路線裡，選中的是死前那個回合開始時葉節點估值最高的那條：以最好的狀態撐下去的路線，如果計畫錯了，戰鬥最可能在這條路線上出現轉機。

在上界成立的範圍內，不可能存在更好的計畫時，計畫就**已證明**（proved）：

- 它的路線達到決策的上界；或者
- 完整的束沒有遺漏任何東西：沒有哪個回合的搜尋被截斷（節點用完，或結束狀態比它保留的多），沒有狀態被擠出束，每條路線都結束了戰鬥或被剪掉。

證明很少見。在 2026-10-28 的測試集上，第 1 幕普通戰鬥有 18% 的搜尋得到證明，菁英戰 3%，第 2 幕的戰鬥 1%：一個回合產生的狀態比束保留的多得多。在下面的測試集裡，21 個計畫沒有一個得到證明。

## 6. 失敗計畫

一個會輸而且沒有證明的計畫可能是錯的：束也許丟掉了通往勝利的那個狀態。規劃器把這樣的計畫當成一個猜測：

- **重新規劃**。沒有證明的失敗計畫只打它的前 `--replan` 個回合（預設 1），然後下一個回合重新規劃。從那裡出發，戰鬥剩下的部分更短，所以同樣的束能看得更深。
- **連續最多 L 個**。同一場戰鬥裡連續第 $L$ 個沒有證明的失敗計畫會一直打到結束（`--loss-plans`，low 和 medium 都是 3）。每回合都重新規劃一場輸掉的戰鬥，曾花掉一局的大部分時間：在沒有上限的 high 力度下，一場輸掉的頭目戰平均規劃 6.2 次、用時 241 s，而它的 200 局裡只有 12 場戰鬥在失敗計畫之後贏下，其中 7 場在第三個計畫或更早就贏了。
- **已證明的失敗**打到結束：沒有哪條路線更好。

計數由路由保存（`SlRoute`）：一場戰鬥一旦出現第一個不是「未證明的失敗」的計畫，它的連續失敗計畫就到此結束。

## 7. 迭代加寬 <Badge text="規劃中" variant="caution" />

這個設計用一個迴圈取代下潛、束和它們周圍的規則。這裡的內容都沒有實作，也沒有量測過。

```text
best = none
for width in 1, 2, 4, 8, ...:              # each pass runs to the fight's end
    states = [decision]
    while states:
        ends = TurnEnds of each state       # shared table: a state is searched once
        best = the better of best and the lines that ended the fight
        drop every end with bound(end) <= best.value
        states = the top `width` ends by the leaf
    stop if proved, or best wins and width >= 4, or the fight's nodes are spent
play best
```

寬度 1 就是今天的下潛；後面的一輪是那個寬度的束，用先前各輪找到的東西剪枝。下圖在 [§4](#sec-4) 的虛構戰鬥上執行這個迴圈。先前某一輪搜尋過的回合不必再花節點，所以更寬的一輪只為新的部分付出。

### 7.1 規則

- **剪枝**。上界不超過最好路線的結束狀態被丟掉（[§2](#sec-2)）。上界的假設不變：會回血或給藥水的戰鬥可能打破它。
- **按葉節點取前「寬度」個**。網路給上界留下的東西排名（[戰鬥大腦：葉節點](/zh-tw/arch/combat-brain/leaf/)）。
- **停止**：路線已證明，或在寬度至少 4 時贏了，或戰鬥的節點用完。被預算截斷的一輪，仍會用它打完的任何路線改進 `best`。
- **失敗的計畫**打一個回合再重新規劃，直到戰鬥的節點用完；然後最後一個計畫打到結束。不計算計畫的數量。
- **證明**的意思和 [§5](#sec-5) 相同：路線達到決策的上界，或者一輪沒有遺漏任何東西。

### 7.2 為什麼加寬，而不是深度

任何寬度的一輪都以一條完整、真實的路線結束，所以搜尋在任何預算下都能停下，手上有東西可打。替代方案是深度優先的分支定界，它可能很久都沒有比第一條更好的完整路線，而這裡的節點很貴：每秒約 460 個（測試集的異鳥成鳥戰，24.7 s 用 11,345 個節點，[§6](#sec-6)），恢復佔 worker 忙碌時間的約 88%（[預算 §3](/zh-tw/arch/sl-planner/budget/#sec-3)）。Alpha-beta 也幫不上忙，因為它的收益來自對手的回應，而戰鬥沒有對手回應：敵人的招式在這唯一的世界裡是固定的。深度優先搜尋以後可以再比較。

### 7.3 它取代什麼

| 今天 | 設計中 |
|---|---|
| 貪婪下潛（[§3](#sec-3)） | 寬度 1 的那一輪 |
| 束 $B$（[§1](#sec-1)）、`Elite` 和 `Boss` 倍數 | 寬度一直增加到停止；困難的戰鬥因為不會提早停止而花得更多 |
| 簡易束 $E$（[§4](#sec-4)） | 在寬度至少 4 時贏了就停止 |
| `--replan`、`--loss-plans`（[§6](#sec-6)） | 失敗的計畫打一個回合，直到戰鬥的節點用完 |
| 一個回合的置換（[回合搜尋 §2](/zh-tw/arch/sl-planner/turn-search/#sec-2)）、下潛的回合留給束 | 跨回合和跨輪的一張表 |
