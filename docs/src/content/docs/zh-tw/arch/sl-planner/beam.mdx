[回合搜尋](/zh-tw/arch/sl-planner/turn-search/)從一個狀態出發，完整搜尋一個回合。一場戰鬥有許多回合，若把每條路線的每個回合都完整搜尋，數量會無止境地成倍增長。規劃器在每個回合只保留最有希望的狀態，按葉節點的估值挑選。[§1](#sec-1)–[§6](#sec-6) 是執行中的程式碼：跨回合的束（`SlPlanner.Search`）、為什麼沒有別的東西截斷它，以及選擇、證明和重新規劃一條路線的規則。[§7](#sec-7) 是規劃中的搜尋，它取代下潛和束的位置。

## 1. 跨回合的束

**束搜尋**（beam search）是一種廣度優先搜尋：在每一層深度只保留最好的 $B$ 個狀態，也只展開它們。這裡的一層深度就是一個回合。設 $S_0 = \{s_0\}$ 為決策的狀態：

$$
S_{t+1} = \operatorname{top}_B \Big\{\, e \in \bigcup_{s \in S_t} \operatorname{ends}(s) \ :\ e \text{ 仍在進行中} \Big\}
$$

其中 $\operatorname{ends}(s)$ 是從 $s$ 出發的回合搜尋所回傳的結束狀態，$\operatorname{top}_B$ 按葉節點估值取最好的 $B$ 個、按鍵彼此不同，而每個已結束戰鬥的結束狀態，則改為一條供挑選的路線（[§5](#sec-5)）。排序是穩定的，所以打平的狀態保持它們被搜尋的順序，束也不取決於哪個 worker 先回覆。束一直走到沒有狀態剩下，最多 40 個回合。

$B$ 是 `Budget.Beam`（`--beam`）：除了 max 是 16，每個力度等級都是 8（[預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。每個保留狀態的這一回合，用預算裡每個狀態每回合的節點數來搜尋；每個房間的 $B$ 和節點數都一樣。

一個回合結束時的狀態通常比束保留的多得多：一個回合各種不同的結束狀態，在全部 8 個保留狀態之間合起來只有最好的 8 個留下。這是規劃器主要的近似，也是它大多數計畫沒有被證明的原因（[§5](#sec-5)）。

## 2. 沒有上界

束的寬度是唯一的截斷。一個狀態永遠不會因為它的路線勝不過目前找到的最好路線而被丟掉，因為一個狀態的任何估值都限制不了它的路線能達到多高。葉節點按戰鬥留下的那一局的 V 給勝利定價（[戰鬥大腦：葉節點 §2](/zh-tw/arch/combat-brain/leaf/#sec-2)），而一條路線還能憑這個狀態手上的東西，把它提高到超過現在就獲勝的估值：戰鬥中獲得的最大生命值或金幣、一張成長了的牌、喝掉一瓶 V 評得比空槽還低的藥水。假設戰鬥只會失去生命值、用掉藥水的上界，會剪掉比最好路線更好的路線（`SlPlanner`，`src/Sts2Ai.Brain/Combat/SlPlanner.cs`）。

所以束保留的每個狀態都會繼續往下搜尋，每條結束戰鬥的路線都納入挑選的權衡，而計畫只有在一個完整、沒有遺漏任何東西的束之下才得到證明（[§5](#sec-5)）。

## 3. 貪婪下潛

在完整的束之前，規劃器先跑一個寬度為 1 的束：每個回合只按葉節點保留最好的那一個狀態。這個**貪婪下潛**（greedy dive）用一條路線打到戰鬥結束。它為完整的束做兩件事：

- 下潛贏了時，這場戰鬥已經能贏，完整的束就收窄成簡易束（[§4](#sec-4)）。下潛證明了它的路線時（這需要每個回合都完整搜尋過、而且各只留下一個繼續下去的狀態），完整的束就跳過。
- 下潛要求它的每個回合回傳所有結束狀態，並把它們留著。完整的束在前期會經過同樣的狀態（它的第一個回合必定如此），就直接取下潛那些回合的結束狀態，而不再搜尋一遍；計畫和重新搜尋得到的一樣（[回合搜尋 §4](/zh-tw/arch/sl-planner/turn-search/#sec-4)）。

## 4. 簡易束

下潛贏了時，完整的束只可能找到一場讓這一局處境更好的勝利。所以它每回合保留 $E$ 個狀態，而不是 $B$ 個（`Budget.EasyBeam`，`--easy-beam`；medium 力度是 4，low 是 2）。下潛輸了時，完整的束保留 $B$ 個：這時它要找的是究竟能不能贏。

medium 力度比 high 省下的時間大多來自簡易束，high 則始終保留 $B$ 個（[預算 §1](/zh-tw/arch/sl-planner/budget/#sec-1)）。它只收窄下潛已經贏下的戰鬥：只要下潛輸了，完整的束就保留完整的寬度。

## 5. 選出路線，並證明它

選中的是結束戰鬥的最好路線，除非束在回合上限處停在一個葉節點估值更高的狀態上。每場失敗都值 0，所以在會輸的路線裡，選中的是死前那個回合開始時葉節點估值最高的那條：以最好的狀態撐下去的路線，如果計畫錯了，戰鬥最可能在這條路線上出現轉機。

不可能存在更好的計畫時，計畫就**已證明**（proved）：最後一個束沒有遺漏任何東西。沒有哪個回合的搜尋被截斷（節點用完，或結束狀態比它保留的多），沒有狀態被擠出束，每條路線都結束了戰鬥（`Beam.Proved`）。

**宿主看到什麼**。除了選中的動作，規劃器還為它保留的路線開頭的每個第一動作，保留這些路線中最好的那條。它們就是它的候選，選中的排第一：每個帶著路線的值、贏下這場戰鬥的機率和勝利時保有的生命值；路線打到戰鬥結束處時是 1 或 0 和確切的生命值，其他地方是葉節點的期望（[回合搜尋 §4](/zh-tw/arch/sl-planner/turn-search/#sec-4)）。Mod 把它們顯示為這場戰鬥的獲勝機率和剩下的生命值（[輸出 §2](/zh-tw/arch/output/#sec-2)）。

證明很少見：一個回合產生的狀態比束保留的多得多。

## 6. 失敗計畫

一個會輸而且沒有證明的計畫可能是錯的：束也許丟掉了通往勝利的那個狀態。規劃器把這樣的計畫當成一個猜測：

- **重新規劃**。沒有證明的失敗計畫只打它的前 `--replan` 個回合（預設 1），然後下一個回合重新規劃。從那裡出發，戰鬥剩下的部分更短，所以同樣的束能看得更深。
- **連續最多 L 個**。同一場戰鬥裡連續第 $L$ 個沒有證明的失敗計畫會一直打到結束（`--loss-plans`，low 和 medium 都是 3）。每個計畫都是又一次完整的搜尋，而一場一直規劃為輸的戰鬥多半已經輸了：沒有上限的話，一場輸掉的戰鬥每回合都會重新規劃，輸掉的戰鬥會佔去一局的大部分時間。
- **已證明的失敗**打到結束：沒有哪條路線更好。

計數由路由保存（`SlRoute`）：一場戰鬥一旦出現第一個不是「未證明的失敗」的計畫，它的連續失敗計畫就到此結束。

所以在 low 或 medium 力度下，一場計畫一直是輸的戰鬥會規劃三次：兩個計畫各打一個回合，第三個打到結束。

## 7. 迭代加寬 <Badge text="規劃中" variant="caution" />

這個設計用一個迴圈取代下潛、束和它們周圍的規則。這裡的內容都沒有實作，也沒有量測過。

```text
best = none
for width in 1, 2, 4, 8, ...:              # each pass runs to the fight's end
    states = [decision]
    while states:
        ends = TurnEnds of each state       # shared table: a state is searched once
        best = the better of best and the lines that ended the fight
        states = the top `width` ends by the leaf
    stop if proved, or best wins and width >= 4, or the fight's nodes are spent
play best
```

寬度 1 就是 [§3](#sec-3) 的下潛；後面的一輪是那個寬度的束，先前各輪搜尋過的回合，它直接從那些輪取用。下圖在 [§4](#sec-4) 的虛構戰鬥上執行這個迴圈。先前某一輪搜尋過的回合不必再花節點，所以更寬的一輪只為新的部分付出。

### 7.1 規則

- **按葉節點取前「寬度」個**。葉節點給結束狀態排名，沒有任何東西按估值剪掉（[§2](#sec-2)、[戰鬥大腦：葉節點](/zh-tw/arch/combat-brain/leaf/)）。
- **停止**：路線已證明，或在寬度至少 4 時贏了，或戰鬥的節點用完。被預算截斷的一輪，仍會用它打完的任何路線改進 `best`。
- **失敗的計畫**打一個回合再重新規劃，直到戰鬥的節點用完；然後最後一個計畫打到結束。不計算計畫的數量。
- **證明**的意思和 [§5](#sec-5) 相同：一輪沒有遺漏任何東西。

### 7.2 為什麼加寬，而不是深度

任何寬度的一輪都以一條完整、真實的路線結束，所以搜尋在任何預算下都能停下，手上有東西可打。替代方案是深度優先的分支定界，它可能很久都沒有比第一條更好的完整路線，而這裡的節點很貴：每個節點都是遊戲自己的程式碼打出的一個動作，每退回一步都是一次恢復（[預算 §3](/zh-tw/arch/sl-planner/budget/#sec-3)）。Alpha-beta 也幫不上忙，因為它的收益來自對手的回應，而戰鬥沒有對手回應：敵人的招式在這唯一的世界裡是固定的。和深度優先搜尋的比較是一個未決問題。

### 7.3 它取代什麼

| 已實作 | 設計中 |
|---|---|
| 貪婪下潛（[§3](#sec-3)） | 寬度 1 的那一輪 |
| 束 $B$（[§1](#sec-1)） | 寬度一直增加到停止；困難的戰鬥因為不會提早停止而花得更多 |
| 簡易束 $E$（[§4](#sec-4)） | 在寬度至少 4 時贏了就停止 |
| `--replan`、`--loss-plans`（[§6](#sec-6)） | 失敗的計畫打一個回合，直到戰鬥的節點用完 |
| 一個回合的置換（[回合搜尋 §2](/zh-tw/arch/sl-planner/turn-search/#sec-2)）、下潛的回合留給束 | 跨回合和跨輪的一張表 |
