在 NoSL 下，戰鬥大腦只知道玩家知道的東西：畫面，以及能從畫面推斷出的資訊。它不知道抽牌堆的順序、隨機效果會擲出什麼，也不知道怪物在意圖背後排好的是它的哪一招。它不能在真實的戰鬥上規劃，因為它不可以看真實的戰鬥。

所以它在自己建構的戰鬥上規劃。**PIMC**（perfect-information Monte Carlo，完美資訊蒙地卡羅）抽取 $K$ 個完整的世界，包括隱藏的部分，每個都與玩家看到的一切一致；把每個世界當作沒有任何隱藏的普通遊戲來搜尋；再把結果取平均。答案是在各世界上平均最好的動作。NoSL 冠軍用 8 個世界、每個 300 個節點來打，葉節點是戰鬥網路 c2（`run --policy pimc`）。

本章分三節：隱藏的是什麼、世界怎麼做出來（本頁），每個世界裡的搜尋和平均（[搜尋](/zh-tw/arch/pimc/search/)），以及預算和結果（[預算](/zh-tw/arch/pimc/budget/)）。這個想法在兩種環境之間的位置，見[環境](/zh-tw/arch/environments/)。

## 1. NoSL 看不到什麼

一場戰鬥的**隱藏狀態** $s$ 有三樣東西：抽牌堆的順序、每條亂數流的位置（遊戲所有的隨機性都取自帶種子的亂數流），以及每個怪物在顯示其當前意圖的那幾招裡排好的是哪一招。**公開記錄** $h$ 是觀測，加上每個敵人在每回合開始時顯示過的意圖（[戰鬥大腦：提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。

微妙的是怪物。每個怪物用遊戲程式碼裡的一個出招狀態機來選招，混合三種規則：

- **固定循環**（攻擊、防禦、攻擊……；或者蓄力，然後大招），給定已出過的招就是確定的；
- **帶約束的加權擲骰**：例如 60% 攻擊、40% 增益，但同一招不能連出三次，或者某招之後必接另一招；
- **條件**：生命值低於一半時換一套招，或者幾個敵人輪流行動。

擲骰用的是怪物自己的亂數流，由這一局的種子決定：同一個種子給出同樣的招，這是 SL 可以利用的。玩家永遠看不到這條流，所以一次擲骰在它的意圖顯示出來之前都是未知的。本回合的招總是已知的，因為它的意圖顯示著。玩家很快就能摸清一個怪物，是因為約束給擲骰留下的餘地很小，而仍然未知的正是這些擲骰。戰鬥網路也呈現同樣的情況：它從記錄猜中 57.7% 的敵人下一回合的意圖型別，重複當前意圖只有 28.9%，而它猜錯的大多落在擲骰上（[戰鬥大腦：葉節點 §3](/zh-tw/arch/combat-brain/leaf/#sec-3)）。

## 2. 取樣世界

一個世界是與 $h$ 一致的一個 $s$ 的樣本：一場完整的戰鬥，建在 worker 自己的那份遊戲裡，顯示的觀測和玩家看到的完全一樣。做出它要兩步。

**建構**（`CombatBuilder.Setup(observation, seed)`，[模擬器：戰鬥 §5](/zh-tw/arch/simulator/combat/#sec-5)）做出一場顯示這個觀測的戰鬥：

1. 用觀測裡的牌組、遺物和生命值開始這個遭遇；
2. 覆寫可見狀態（`Apply`）：回合數、敵人（加入、移除、重新排序）、生命值和格擋、能量、金幣、藥水、充能球、遺物計數、能力及其層數、四個牌堆連同每張牌的修改，以及意圖；
3. 抽取隱藏狀態（`Resample`）；
4. 把重建後戰鬥的觀測和輸入逐條路徑比較（`BuildDifferences`）：沒有差異就表示完全一致。

畫面顯示的東西，往往是它沒顯示的數字的函式，而且每個能力和遺物都不一樣，所以一個**旋鈕求解器**（knob solver）會嘗試內部的數字（數量、欄位、能力的私有資料），直到顯示相符為止。意圖的配對方式是，為每個怪物在顯示這些意圖的招裡做選擇；每個怪物的**出招日誌**則從公開記錄重建，讓它的狀態機像真實的那個一樣繼續下去：較早的回合配對到顯示相同意圖的招（否則是型別和段數相同的，再否則是型別相同的）。

接著**確定化**（`Determinize(seed)`，[模擬器：戰鬥 §3](/zh-tw/arch/simulator/combat/#sec-3)）把玩家無法知道的一切換成一個樣本，可見狀態則保持原樣：

- 每條亂數流都重新播種；
- 抽牌堆先按卡牌鍵排序，這個順序只取決於玩家看到的東西，然後洗牌（Fisher–Yates）；
- 手牌以外的牌重新編號，因為遊戲按抽牌順序給牌編號，舊的 id 會洩漏這個順序；
- 每個怪物排好的招，在顯示相同意圖的招裡均勻抽取。

世界 $k$ 就是建構好的戰鬥加上 `Determinize(seed_k)`，其中 $\text{seed}_k$ 由搜尋的種子和 $k$ 混合而成。之後的一切，出牌、擲骰和敵方回合，都由真正的遊戲程式碼來打；沒有任何網路去模擬什麼，葉節點只給路線停下的地方估值。

下圖取一個真實的 NoSL 決策，對恐鰻的菁英戰的第一個回合（[搜尋 §3](/zh-tw/arch/pimc/search/#sec-3)），用同樣的方式排出它的抽牌堆：先排序，再用每個世界的種子洗牌。這些世界由頁面用它自己的產生器抽出，所以不是那一局搜尋過的 8 個世界，但它們是同一種世界。一張牌出現在接下來幾次抽牌裡的機率，在很多個世界上會趨近確切的機率；只有 8 個時就很粗略，這就是[搜尋 §3](/zh-tw/arch/pimc/search/#sec-3) 的雜訊。

## 3. 世界有多忠實

從觀測建構出來的世界，除了 `Determinize` 有意取樣的部分以外，應當和真實戰鬥打起來一樣。`fidelity` 量的就是這個：在測試集戰鬥中每隔一個決策，讓真實戰鬥用一個佔位策略繼續打到回合結束，包括敵方回合；同時從這個決策的觀測和記錄建構一場戰鬥，給它真實戰鬥的取樣狀態，打同樣的動作；第一個不同的觀測被計數（[模擬器：戰鬥 §6](/zh-tw/arch/simulator/combat/#sec-6)）。用寂靜獵手的起始牌組（2026-10-27）：

| 戰鬥 | 決策數 | 直到敵方回合結束都相同，沒有記錄 → 有記錄 |
|---|---|---|
| 第 0 幕普通戰鬥，30 場 | 459 | 82.4% → 96.3%；算上暈眩的後續招式為 97.4% |
| 第 1 幕普通戰鬥，30 場 | 478 | 88.7% → 98.1%；算上暈眩的後續招式為 99.0% |
| 第 0 幕頭目，9 場 | 201 | 96.5% → 96.5% |
| 第 0 幕菁英，15 場 | 289 | 99.0% → 99.0% |

沒有一場戰鬥建構錯誤，在建構出的戰鬥裡也沒有任何動作不合法。在回合之內，最多 1% 不同。其餘的不同都出現在回合結束之後，在少數怪物內部的計數上（一隻老鼠的召喚、一個巨人不斷增長的傷害），這些是任何觀測都看不到的。出招記錄讓普通戰鬥從 82–89% 提升到 96–98%。建構器仍然只是近似的有：本回合的歷史以及能力和怪物內部的計數、費用修改持續多久、玩家身上減益的消退，以及把牌組當作見過的每一張牌。

在整局裡，建構錯誤的世界會讓決策失敗。最早的 400 局 PIMC 裡有 5 局這樣失敗：用完的白銀坩堝的隱藏計數（三局）、玻璃充能球的數值，以及怠惰的上限，它只寫在提示框裡（世界裡每回合能打的牌比真實戰鬥少，一張合法的牌在世界裡變得不合法）。這三處都已修復（[模擬器：戰鬥 §6](/zh-tw/arch/simulator/combat/#sec-6)）。

## 4. 公平規則

NoSL 的規則是：一個決策只取決於公開記錄（[環境](/zh-tw/arch/environments/)）。搜尋的構造讓它不可能違反這條規則：

- **離開宿主的只有觀測**。worker 拿到的是觀測、記錄和種子，從不是真實的戰鬥（[戰鬥大腦：提示、招式與 worker §3](/zh-tw/arch/combat-brain/shared/#sec-3)）。每個世界都從觀測建構，從不從真實戰鬥建構，所以世界裡的隱藏狀態是世界自己的樣本，其中沒有任何東西來自真實遊戲。
- **種子屬於呼叫方**。`Determinize` 的種子取自搜尋，從不取自這一局。
- **葉節點讀的是觀測**。`LeafValue` 和戰鬥網路都不讀隱藏狀態（[戰鬥大腦：葉節點 §1](/zh-tw/arch/combat-brain/leaf/#sec-1)）。
- **處處同一條路徑**。評估階梯的第一級，也就是模擬器，建構世界的方式和 Mod 將來從真實遊戲建構的一樣：沒有任何捷徑會為決策確定化真實狀態（[評估 §1](/zh-tw/arch/evaluation/#sec-1)）。確定化真實狀態只留給測試和效能基準使用。
- **規劃中**：一個反事實測試，公開記錄相同、隱藏狀態不同，在大腦種子固定時必須給出相同的選擇。
