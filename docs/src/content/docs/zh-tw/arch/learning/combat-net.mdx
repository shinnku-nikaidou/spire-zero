戰鬥網路是戰鬥搜尋學到的葉節點：從一個回合的開始，它預測在打出它訓練對局的那個策略下，戰鬥會怎樣結束。它讀什麼、它的各層怎樣組合這些輸入，見[戰鬥網路](/zh-tw/arch/combat-brain/network/)；搜尋怎樣使用它的輸出，見[葉節點](/zh-tw/arch/combat-brain/leaf/)。本頁講它怎樣訓練、用哪些資料，以及訓練出的網路量測到什麼。

## 1. 它預測什麼

從一個回合的開始，預測兩件事：

- **結局**：51 個類別上的分布，一個死亡，或 50 個分桶之一，分的是從這個狀態起還會失去的最大生命值比例；持有的生命值排除掉的分桶是關閉的。
- **藥水**：勝利後，每瓶持有的藥水已經不在的機率。

`learn/combat/` 訓練它（`combat.train`，`learn/combat/train.py:40`）。`--combat-net FILE` 讓它上場，在 SL 規劃器裡（顯示為 `plan NAME`）或在 PIMC 裡（`pimc NAME`）。

## 2. 它讀什麼

全部見[戰鬥網路 §2](/zh-tw/arch/combat-brain/network/#sec-2)。`learn/combat/encode.py` 是唯一的規格，C# 的 `CombatNet` 依照它。

## 3. 樣本和標籤

`learn/combat/data.py` 從一份決策日誌和對局記錄的清單產生樣本，每個角色的都讀（[參考 §4](/zh-tw/arch/learning/reference/#sec-4)）。

- **一個樣本是一個回合的開始**：日誌裡每個回合的第一個戰鬥決策，也就是搜尋的葉節點所代表的狀態，因為搜尋的葉節點是下一個回合的開始（[葉節點 §1](/zh-tw/arch/combat-brain/leaf/#sec-1)）。一場戰鬥的決策在下一個宏觀決策處結束，或在回合數倒退時結束；選牌提示的行會跳過（`combats`，`learn/combat/data.py:33-67`）。
- 在它之前的**敵人歷史**由先前各回合的開始重建，按每個活著的敵人的 uid 取它的意圖，和 Harness 的 `Dispatcher` 建出的方式一樣（`witness`，`learn/combat/data.py:70-77`）。
- **結局的標籤相對於這個狀態**：死亡，或這個狀態的生命值比例減去戰鬥結束時的比例所落入的分桶（`ending`，`learn/combat/data.py:97-102`）。回血超過最低分桶的，落在最低分桶。所以一場戰鬥的每個回合開始都有同一個結局，但各有自己的標籤。這是蒙地卡羅：標籤就是在打出對局的那個策略下真正發生的事（[循環 §3](/zh-tw/arch/learning/loop/#sec-3)）。
- **藥水的標籤**來自戰鬥後第一個整局觀測，按每一瓶計算：這個狀態持有、那裡已經沒有的藥水算作不在了（`potions_used`，`learn/combat/data.py:80-90`）。不取自動作，因為動作漏掉不經任何動作就用掉的瓶中精靈，它占所有用掉藥水的 6.2 %。也不取自最後一個回合開始，因為那會漏掉最後一個動作喝掉的藥水。戰鬥後來才得到的藥水不算這個狀態的藥水。死亡只訓練結局。
- **不用的資料**（`read`，`learn/combat/data.py:131-157`）：失敗的對局；記錄中沒有 `end` 的戰鬥，除非它是一局輸掉的對局的最後一場，那樣算作死亡；勝利之後沒有整局觀測的戰鬥；還有日誌中的戰鬥與記錄在數量或遭遇上對不上的每一局，訓練器會計數並報告。
- **單一環境**。`--env SL|NoSL` 只讀那個環境的行；遇到另一個環境的日誌行，訓練就會失敗。這個網路用 `--env SL` 訓練（[葉節點 §6](/zh-tw/arch/combat-brain/leaf/#sec-6)）。
- **權重和劃分**。每個回合開始的權重都相同，按對局 id 每五局留出一局，連同它所有的回合開始，用於提前停止和報告。每 1,000 個留出的回合開始中有一個保留觀測和歷史，用作網路檔案的測試狀態（`KEEP`）。

冠軍的權重最近一次學習的**資料**是晉階 10 的完整 SL 自我對弈，即 `v8g2` 的 10,038 局，每場戰鬥都打了，用 medium 預算。合計 736,075 個回合開始，其中 153,718 個留出。自我對弈和晉級門檻的種子從不相遇，`--list` 也拒絕含有評估作業對局的清單（`common.train_lists`）。c8-3 接續 c8-2 訓練，c8-2 學自 `v8g1` 的 8,087 局 A10 對局，接續 c8-1 訓練，而 c8-1 的權重學自晉階 0：21,263 局自我對弈，大多用 low 預算（[SL 規劃器：預算 §2](/zh-tw/arch/sl-planner/budget/#sec-2)），再加上種子 `promotion-301-500` 上 600 局 medium 預算對局，所以 `promotion-1-500` 不再用作測試集（[評估：指標、種子與報告 §5](/zh-tw/arch/evaluation/metrics/#sec-5)）。

在這些權重的 `c7` 集上，勝利的回合開始中，遮罩從未關閉真實的分桶，1,479,991 個裡有 98 個回血超過最低分桶。9.4 % 的回合開始持有藥水。

## 4. 損失和訓練

```bash
uv run python -m combat.train --list data/silent/lists/v8g2 --env SL --name NAME --test-list data/silent/lists/medium
```

一個樣本的損失是（`loss`，`learn/combat/net.py:326-333`）

$$
\text{loss} = \text{CE}(\text{masked endings}, \text{class}) + \text{won} \sum_{\text{held}} \text{BCE}(u_{\text{id}}, \text{gone}).
$$

藥水項的權重是 1（`POTION_WEIGHT`），大約占損失的 1 %：每個勝利樣本 0.051 個藥水列，約 0.33 nats，而交叉熵約 1.24。所以主幹仍然屬於結局。

設定固定在程式碼裡（`learn/combat/train.py:34-36`）：AdamW，學習率 10⁻³，權重衰減 10⁻⁴；批次大小 256；最多 20 個 epoch，連續 3 個 epoch 留出損失沒有降低 10⁻⁴ 就停止。做實驗就改程式碼，只有得到結果，改動才會保留。詞元表是遊戲的，固定不變（[戰鬥網路 §2](/zh-tw/arch/combat-brain/network/#sec-2)）。

**從一個網路接著訓練**（`--init FILE`）。訓練可以從一個網路檔案的權重開始，權重從它的 ONNX 計算圖讀回（`export.weights`），學習率降為 3 × 10⁻⁴。除非某個 epoch 勝過它們的留出損失，否則檔案的權重保持不變。表和遊戲的不同的檔案會被拒絕。c8-3 就是這樣從 c8-2 接著訓練的，只用 `v8g2` 的 10,038 局：最好的是 6 個 epoch 中的第 2 個，留出損失從 c8-2 的 1.2913 降到 1.2579。

**報告**（`learn/combat/report.py`）是 stdout 上的一行 JSON，也保存為網路檔案的 `fit`：`env`、`runs`、`held_out_runs`、`samples`、`held_out_samples`、`vocab`，接著是 `held_out`，以及同樣內容按幕、房間、遭遇、生命值（是否低於 30 %）和藥水 id 分開。有 `--test-list` 時，`medium` 保存整份清單的同樣內容，它們只報告，從不用於訓練。

| 欄位 | 它說什麼 |
|---|---|
| `ce`、`ce_prior` | 結局的交叉熵，以及訓練集頻率的交叉熵 |
| `death`、`predicted_death` | 平均值，實際的和預測的 |
| `rank_within`、`rank_within_share` | 在每個 10 個或更多樣本的（遭遇, 回合）內與結局價格的等級相關，按大小加權；旁邊是生命值比例的 |
| `rank_lost`、`rank_lost_share` | 同樣的等級相關，但對象是失去的生命值，只算勝利：網路在持有的生命值之外增加了什麼 |
| `auc_death`、`auc_death_share` | 在每個死亡和存活各有 3 個或更多的（遭遇, 回合）內，死亡的回合開始得分高於存活的回合開始的機率；旁邊是生命值比例的 |
| `potions` | `rows`、`used`、`predicted`、`log_loss`，以及 `log_loss_id` 和 `log_loss_id_room`，即按 id、按 id 和房間取比率時的對數損失 |

**網路檔案**寫到 `weights/all/NAME.json`，從不覆蓋（[參考 §6](/zh-tw/arch/learning/reference/#sec-6)）。它的欄位見[參考 §7](/zh-tw/arch/learning/reference/#sec-7)。

## 5. 它量測到什麼

數字是 `weights/all/c9-0.json` 裡的報告，它保留的是 c8-3 的：c9-0 沿用它的權重。「留出」是訓練清單裡每五局一局，2,044 局，都在晉階 10，有 153,718 個回合開始，以 medium 預算打。

| 指標 | 留出 | 只用生命值比例 |
|---|---|---|
| 結局的交叉熵（先驗） | 1.242（2.110） | – |
| 死亡，實際和預測 | 5.15 %、5.16 % | – |
| 與結局價格的等級相關 | 0.927 | 0.833 |
| 失去生命值的等級相關，只算勝利 | 0.662 | 0.148 |
| 死亡的 AUC | 0.923 | 0.693 |
| 藥水的對數損失（按 id 和房間） | 0.328（0.575） | – |

**怎麼讀**。與結局價格的等級相關說明不了多少：只用生命值比例就有大部分，因為結局的價格跟著持有的生命值走。失去生命值的等級相關和死亡的 AUC，才是網路在持有的生命值之外增加的東西。

按房間，在留出對局上：

| 房間 | 回合開始數 | 交叉熵（先驗） | 死亡，實際和預測 | 失去生命值的等級相關 | 死亡的 AUC（生命值比例） |
|---|---|---|---|---|---|
| 普通戰鬥 | 101,898 | 0.957（1.671） | 0.6 %、0.6 % | 0.627 | 0.956（0.887） |
| 菁英 | 28,893 | 1.740（2.758） | 7.0 %、7.3 % | 0.747 | 0.949（0.727） |
| 頭目 | 22,927 | 1.881（3.243） | 23.0 %、22.6 % | 0.737 | 0.909（0.661） |

**低生命值**，低於最大生命值的 30 %，那裡 12.2 % 的留出回合開始會死亡：死亡的 AUC 是 0.896，生命值比例是 0.576。

**按 id 看藥水輸出頭**。在留出對局上，瓶中精靈有 21.3 % 的時候被用掉，預測為 22.3 %，對數損失 0.182，按 id 和房間是 0.434。所有列合計，29.5 % 被用掉，預測 29.4 %。

**最難的戰鬥**。在實驗體上，56.0 % 的留出回合開始會死亡，網路預測 52.3 %，死亡的 AUC 是 0.881，對 0.662。失去生命值的等級相關（只算勝利）是 0.747，對 0.432。

這些之中哪個能轉化成更多的勝局，要由門檻來說（[評估：晉級門檻 §5](/zh-tw/arch/evaluation/gates/#sec-5)）。在晉階 10，涵蓋兩個 V，它在 medium 下比 c8-2 多到達 0.45 層，± 0.71，勝局沒有增加，+0.00 ± 1.47 百分點（[評估：冠軍與基線 §2](/zh-tw/arch/evaluation/champions/#sec-2)）。
