戰鬥網路是戰鬥搜尋學到的葉節點：從一個回合的開始，它預測在打出它訓練對局的那個策略下，這場戰鬥的結果：c1–c4 預測怎樣結束；c7-1v 預測 V 對結局的估價。它讀什麼、它的各層怎樣組合這些輸入、它的輸出頭預測什麼，在戰鬥大腦一章裡有解釋（[戰鬥大腦：葉節點 §3](/zh-tw/arch/combat-brain/leaf/#sec-3)、[§4](/zh-tw/arch/combat-brain/leaf/#sec-4)）；本頁講它怎樣訓練、用哪些資料，以及訓練出的網路量測到什麼。

<Aside title="狀態">

`learn/combat/`（`combat.train`，提交 `d290783`、`3a95439`、`64f514b`）從單一環境的對局訓練戰鬥網路。它的第一個網路，SL 的 c7-1v，正在訓練，還沒有過門檻（[§7](#sec-7)）。現有的網路 c1–c4 由 `learn/train_combat.py` 訓練，這個腳本已在 `455d437` 移除；c2 由它在提交 `b4480a1` 時寫出，自 2026-10-27 起是兩個冠軍的葉節點，用在 NoSL 的 PIMC 和 SL 的規劃器裡。它的已知問題見[戰鬥大腦：葉節點 §7](/zh-tw/arch/combat-brain/leaf/#sec-7)。

</Aside>

## 1. 網路讀什麼、預測什麼

**輸入**，以一個回合開始的詞元形式（[戰鬥大腦：葉節點 §3](/zh-tw/arch/combat-brain/leaf/#sec-3)）：四個牌堆裡的每張牌（它的 id、升級次數、附魔、苦痛和所在牌堆）；玩家（生命值比例、生命值、最大生命值、格擋、能量、最大能量、星辰、回合數）和它的能力；每個活著的敵人（它的 id、生命值比例、生命值、最大生命值、格擋、它已經顯示過幾個回合、它的能力，以及四個意圖槽：它現在顯示的意圖，接著是它最近 3 個回合的意圖，最近的在前）；遺物、藥水和上下文（角色、遭遇、房間、幕）；以及在較新的網路裡，充能球、活著的盟友、晉階、充能球槽數和金幣。敵人先前的意圖來自 Harness 保存的敵人出招紀錄（[戰鬥大腦：提示、招式與 worker §2](/zh-tw/arch/combat-brain/shared/#sec-2)）。 c7-1v 還讀每張牌的目前費用和修飾的數值，以及每件遺物的計數、熔化標記和狀態；它的幕、房間和角色讀作 `<unk>`（[戰鬥大腦：葉節點 §8](/zh-tw/arch/combat-brain/leaf/#sec-8)）。

**輸出**：`learn/combat/` 的網路是一個數字，即戰鬥的價值（worth）：戰鬥後第一個整局觀測的 V 占戰鬥前最後一個的 V 的比例，上限 4，死亡為 0（[§3](#sec-3)）；規劃器把它乘以戰鬥前的 V（[戰鬥大腦：葉節點 §5](/zh-tw/arch/combat-brain/leaf/#sec-5)）。c2 的輸出是 51 個類別上的分布，即死亡或還要失去的最大生命值比例的 50 個桶之一，以及勝利後還要用掉的藥水；葉節點給每種結局定價，把它們變成一個數字（[戰鬥大腦：葉節點 §4](/zh-tw/arch/combat-brain/leaf/#sec-4)）。

**每個環境一個網路**。網路學的是在打出那些戰鬥的策略下戰鬥怎樣結束，而 SL 的規劃器看得到 NoSL 的搜尋必須猜的東西，從同一個狀態出發贏得更多。所以網路檔案寫明它的環境（`env`，SL 或 NoSL），另一個環境的對局、大腦、晉級門檻或戰鬥測試集都會拒絕它（`LeafChoice.Check`，`SimWorker/Brains/LeafChoice.cs:25-30`）。c1–c4 早於這個欄位，在兩種環境裡都能用，兩個冠軍正是這樣都用上了 c2（[戰鬥大腦：葉節點 §6](/zh-tw/arch/combat-brain/leaf/#sec-6)）。

`--combat-net FILE` 讓它在 PIMC 裡（顯示為 `pimc NAME`）或在 SL 規劃器裡（`plan NAME`）上場。

## 2. 每一代網路讀什麼

各網路的差別在於它們在 id 之外讀哪些數字。`CombatNet` 只餵給計算圖它宣告的輸入（`NetNumbers.Declared`，`Brain/Combat/CombatNet.cs:256`），所以每一代的檔案都能載入。

| 網路 | 訓練者 | 在 id 之外讀的 | 不讀的 |
|---|---|---|---|
| c1、c2 | `train_combat.py` | 每張牌的費用 / 3 乘以一個費用向量（`costs`）；玩家的 8 個數字；能力的數值；敵人的 5 個數字和意圖 | 牌、遺物和充能球的數值，充能球，盟友，晉階，金幣 |
| c3、c4 | `train_combat.py`（自 2026-10-27 起） | c2 讀的全部，加上每張牌的修飾數值 / 10、星費 / 3、是否 X 費，以及它的每個數值（`vars`）/ 10 乘以該數值名稱的向量；能力的層數，在提示框把它和圖示分開寫出時（怠惰），以及能力保存的牌（夢魘）；遺物的計數 / 10 乘以它 id 的計數向量（鋼筆尖、雙節棍、開心小花、石製日曆），是否顯示計數、是否熔化、它的狀態；充能球（id、被動和激發數值 / 10）和盟友；晉階 / 10、充能球槽數 / 10、金幣 / 100 | – |
| `learn/combat/` 的 | `combat.train` | c3 的輸入減去其他印在牌、遺物或充能球上的數字：id、升級、修飾及其數值 / 10、目前費用 / 3 和牌堆；玩家的數值；能力的 id、層數、堆疊數和保留的牌；敵人的 id、數值、能力和意圖；遺物的 id、計數 / 10、熔化標記和狀態；藥水、充能球和盟友的 id；遭遇；晉階、充能球欄位和金幣（`learn/combat/encode.py`） | `vars`、星辰費用、X、是否顯示計數（在 `relic_values` 裡，計算圖不讀）、充能球的數值；幕、房間和角色讀作 `<unk>` |

c3 為什麼加上這些數字：兩個狀態如果只差牌上印的數字或遺物的計數，網路不讀它們，再多資料也分不開。`learn/combat/` 為什麼不讀其餘的：印著的數字由 id 和升級決定，由網路去學，V 也是這樣（[宏觀大腦：價值網路 §2](/zh-tw/arch/macro-brain/network/#sec-2)）；而牌的目前費用、修飾的數值、遺物的計數和狀態是戰鬥的狀態，id 說不出來。c3 新增的每個輸入都用隨機權重的網路檢查過一致性，權重經過縮放，使每個輸入都能改變輸出：訓練器的測試狀態能載入，而改動任何一個輸入後的狀態副本在載入時檢查不通過。

**`learn/combat/encode.py` 是唯一的規格**，定義較新網路的輸入，`CombatNet.Predict` 依照它。它的縮放（`learn/combat/encode.py:62-155`）：生物的生命值比例、生命值 / 100、最大生命值 / 100 和格擋 / 20；玩家的能量 / 3、最大能量 / 3、星辰 / 5 和回合數 / 10；敵人已顯示的回合數 / 10；能力的數值 / 10 和層數 / 10；意圖的每段傷害 / 10 和總傷害 / 20。這些都截斷在 ±10 以內，因為少數狀態會出現極大的數（瀑布巨獸 WATERFALL_GIANT 噴發時的生命值）。三個額外的數字裡，金幣 / 100 有截斷；晉階 / 10 和充能球槽數 / 10 沒有。死去的敵人或盟友不計入；沒有 id 的敵人讀作 `<none>`，沒有 id 的盟友（玩家的）讀作 `<player>`。 牌的費用 / 3，X 或沒有費用時為 0；修飾的數值和遺物的計數 / 10，有上限。

**網路**（`learn/combat/net.py:136-246`）和 V 同樣是集合編碼器的風格：嵌入維度 32；一張牌是它 id 的向量，加上升級等級乘以它 id 的升級向量，加上費用乘以一個學到的費用向量，再加上牌堆的向量和每個修飾的向量及其數值乘以該修飾的向量，經過 φ（32 → 64 → 64），按牌堆加總並乘 1/8；一個能力是它 id 的向量，加上層數和堆疊數各乘以它 id 的向量，再加上保留的牌的向量，經過 φ（32 → 64）後加總；一個意圖槽是它各意圖之和（類型的向量，加上傷害和總傷害各乘以該類型的向量），加上一個學到的槽位向量；一個敵人是它 id 的向量加上 5 個數值的投影、它的能力和 4 個槽，經過 φ（224 → 128 → 128），敵人們再加總；一個盟友是它 id 的向量加上 4 個數值的投影和它的能力，經過 φ（96 → 64）後加總；一件遺物是它 id 的向量，加上計數乘以它 id 的向量，熔化時加一個學到的向量，再加狀態的向量；遺物、藥水、上下文和充能球都是加總。主體讀 651 個數字（4 × 64 + 8 + 64 + 128 + 4 × 32 + 64 + 3），經過兩層 256；輸出頭給出一個數字。c2 的計算圖畫在[戰鬥大腦：葉節點 §3](/zh-tw/arch/combat-brain/leaf/#sec-3)，沒有充能球、盟友和額外的數字：它的主體讀 552 個數字，輸出頭給出 51 個類別和用掉的藥水。

## 3. 樣本和標籤

`learn/combat/data.py` 從一份決策日誌和對局記錄的清單產生樣本（[參考 §4](/zh-tw/arch/learning/reference/#sec-4)）。

- **一個樣本是一個回合的開始**：日誌裡每個回合的第一個戰鬥決策，也就是搜尋的葉節點所代表的狀態，因為搜尋的葉節點是下一個回合的開始（[戰鬥大腦：葉節點 §1](/zh-tw/arch/combat-brain/leaf/#sec-1)）。一場戰鬥的決策在下一個宏觀決策處結束，或在回合數倒退時結束；選牌提示的行會跳過（`combats`，`learn/combat/data.py:31-67`）。
- 在它之前的**敵人歷史**由先前各回合的開始重建，按每個活著的敵人的 uid 取它的意圖，和 Harness 的 `Dispatcher` 建出的方式一樣（`witness`，`learn/combat/data.py:70-77`）。
- **標籤是 V 對那場戰鬥結局的估價**，那場戰鬥的每個回合開始都相同：戰鬥後第一個宏觀決策處這一局的 V，占戰鬥前最後一個宏觀決策處的 V 的比例，上限 4（`WORTH_CAP`，`learn/combat/data.py:22`：99 % 的勝利低於 3.4，因為一局的勝率在戰鬥前可能幾乎為零）。死亡為 0（[評估：指標、種子與報告 §8](/zh-tw/arch/evaluation/metrics/#sec-8)），贏下整局的戰鬥結束時 V = 1（`read`，`learn/combat/data.py:124-125`）。`--value` 指定這個 V；所有標籤都由它算出，它本身不訓練。這是在打出那場戰鬥的策略下的蒙地卡羅目標（[循環 §3](/zh-tw/arch/learning/loop/#sec-3)）。
- **不用的資料**（`read`，`learn/combat/data.py:96-131`）：失敗的對局；`--skip-seeds` 給的種子檔案裡的對局；記錄中沒有 `end` 的戰鬥，除非它是一局輸掉的對局的最後一場，那樣算作死亡；戰鬥前沒有整局觀測的戰鬥，以及對局繼續、戰鬥後卻沒有整局觀測的戰鬥；還有日誌中的戰鬥與記錄在數量或遭遇上對不上的每一局（日誌被截斷、戰鬥被分開記錄），訓練器會計數並報告。菁英挑戰的對局記錄列出了它的普通戰鬥，這些戰鬥一開始就判贏，沒有決策，所以這類對局對不上，不產生樣本。
- **單一環境**。`--env SL|NoSL` 只讀那個環境的行；遇到另一個環境的日誌行，訓練就會失敗（`learn/combat/data.py:42-43`）。
- **權重和劃分**。每個回合開始的權重都相同（不像 V 的樣本那樣按局加權），按對局 id 每五局留出一局，連同它所有的回合開始，用於提前停止和報告。 `read` 只保留樣本的詞元，只有每 1,000 個留出的回合開始中的一個（`KEEP`）保留觀測和歷史，用作網路檔案的測試狀態：帶上它們一個樣本占 55 KB，v7g1 全部要 88 GB。

## 4. 損失和訓練

`uv run python -m combat.train --list PREFIX --env SL|NoSL --name NAME --value V_FILE [--skip-seeds FILE] [--out FILE] [--character SILENT] [--seed 0]`（`learn/combat/train.py:129-139`）。

一個樣本的損失是戰鬥價值的平方誤差（`loss`，`learn/combat/net.py:249-251`）。設定固定在程式碼裡（`learn/combat/train.py:37-41`）：在訓練對局裡出現不到 3 次的 id 讀作未知，沒有 id dropout；AdamW，學習率 10⁻³，權重衰減 10⁻⁴；批次大小 256；最多 20 個 epoch，連續 3 個 epoch 留出損失沒有降低 10⁻⁴ 就停止；讀最近 3 個回合的意圖，也讀回合數。`train_combat.py` 的下一意圖輸出頭、它和 `LeafValue` 的比較，以及它做消融用的選項（`--width`、`--train-share`、`--fold`、`--lags`、`--no-round`）都已拿掉：做實驗就改程式碼，只有得到結果，改動才會保留。

**報告**是 stdout 上的一行 JSON（`learn/combat/train.py:225-238`）：`env`、`value`、`runs`、`held_out_runs`、`samples`、`held_out_samples`、`vocab`（每張表的大小）、`held_out`，以及同樣內容按幕、房間和遭遇分開（`by_act`、`by_room`、`by_encounter`）。每部分給出 `samples`、`mse`（平方誤差）、`mse_mean`（訓練集平均值的平方誤差）、`rank_within`（在每個 10 個或更多樣本的 (遭遇, 回合) 內與戰鬥價值的等級相關，按大小加權，因為束要排序的是同一場戰鬥的狀態）、`worth` 和 `predicted`（平均值）。

**網路檔案**寫到 `weights/CHARACTER/NAME.json`，從不覆蓋（[參考 §6](/zh-tw/arch/learning/reference/#sec-6)）。它包含 ONNX 格式的網路（輸出 `worth`）、詞元表、`env`、`target`（`worth`）、`worth_cap`、`lags`、`round`、報告，以及最多 16 個留出的回合開始和訓練器對每個給出的數字，其中至少一個顯示多段攻擊；`CombatNet.Load` 重新計算它們，只要任何一個偏差超過 10⁻³ 就拒絕這個檔案（`Brain/Combat/CombatNet.cs:70-92`）。它的欄位列在[參考 §7](/zh-tw/arch/learning/reference/#sec-7)。

## 5. c1 到 c4

到目前為止的每個戰鬥網路，數據取自它們檔案的 `fit` 和帳本（`eval/silent/ledger.md`）。四個都是 NoSL 的，由 `train_combat.py` 訓練；數字是每個檔案的報告，取它的第 0 折。

| 網路 | 訓練資料 | 回合開始數 | 輸出頭 | 留出交叉熵（先驗） | 估值與真實結局的相關係數（`LeafValue` 的） | 權重數 | 晉級門檻 |
|---|---|---|---|---|---|---|---|
| c1 | g0，315 局（NoSL，PIMC 配 `LeafValue`） | 13,954 | 20 個「剩餘生命值比例」分桶 | 1.590（2.487） | 0.949（0.790） | 296,054 | 2026-10-27 在 32 對之後未通過（−1.41 層） |
| c2 | 同上 | 13,954 | 51 個類別：死亡，以及 50 個「還要失去的生命值」分桶 | 1.320（2.003） | 0.959（0.790） | 303,764 | 2026-10-27 在 77 對之後通過（+2.36 層）；兩個冠軍的葉節點 |
| c3 | g1，505 局（由 c2 打） | 27,909 | 同 c2；讀數值 | 1.346（2.041） | 0.960（0.829） | 351,124 | 在 200 對中的第 160 對時作廢（+0.58 層，未定） |
| c4 | g1 + g2，844 局 | 46,466 | 同 c3 | 1.356（2.098） | 0.957（0.833） | 353,300 | 未經門檻 |

c2 的留出交叉熵在頭目戰最低（597 個回合開始上 1.130），在菁英戰最高（106 個上 2.640），怪物戰是 1,819 個上 1.306；它估值的平方誤差是 0.00766，c1 是 0.00905；它的死亡機率和實際死亡的相關係數是 0.787。c1 的檔案是較舊的輸出頭：20 個結束時*剩餘*生命值比例的分桶，沒有 `loss_min`，輸出是 `potions_left`。`CombatNet` 按位置讀輸出，所以現在它會把 c1 的分桶當作失去的生命值來定價；c1 不在任何作業裡上場。

## 6. 量測

**在 315 局 NoSL 自我對弈上**（g0，13,954 個回合開始；`train_combat.py`，三折）：

- **限制網路的是資料，不是大小**。用四分之一、一半和全部的訓練對局，留出交叉熵分別是 1.446、1.379 和 1.337。寬度減半時一樣（1.337），寬度加倍也沒有更好（1.340）。
- **網路從資料學到怪物的出招**。加上下一意圖輸出頭時，它對 57.7% 的敵人說中了下一回合的意圖類型，重複當前意圖只有 28.9%；下一回合總傷害平均誤差 4.15，後者是 7.65。大部分只需要知道是哪個怪物和它當前的意圖：去掉歷史和回合數後是 56.7%。歷史對少數幾個怪物幫助最大，例如樂加維林族母（LAGAVULIN_MATRIARCH，43% 對 33%）和啃咬獸（NIBBIT，41% 對 35%）。猜錯的很多是遊戲隨機挑選的招式。這個輸出頭沒有讓結局的留出交叉熵或估值的誤差產生超出雜訊的改變，所以它預設關閉，`learn/combat/` 也拿掉了它。
- **預測之後還會發生的，而不是最後剩下的**。c1 預測的是結束時剩下的生命值比例，只學到現在持有的生命值大約一半的價值：現在少一點生命值，它的估值只降 0.0038，而這會讓結束時整整少一點生命值，按 `LeafValue` 的價格是 0.0078。它的搜尋把生命值換得太便宜，在普通戰和菁英戰裡掉的血比冠軍多（每場勝利 7.8 對 6.5、26.4 對 18.0 點生命值），過門檻時在 32 對之後未通過（−1.41 層）。改成預測從這裡起的損失（c2）後，現在持有的生命值完整計入（同樣的狀態上每點生命值 0.0083），估值的留出平方誤差也從 0.0090 降到 0.0077（[戰鬥大腦：葉節點 §4](/zh-tw/arch/combat-brain/leaf/#sec-4)）。

**在 g1 的 505 局上**（27,909 個回合開始，由 c2 打；c3 的資料；三折）：

- **寬度仍然無關緊要**。寬度 1 時留出交叉熵是 1.348、1.348 和 1.334，寬度減半時是 1.356、1.327 和 1.317（先驗：2.041、1.973 和 2.014），在各折的離散範圍內相同。寬度也不改變搜尋的速度：在一個 8 場戰鬥的第 1 幕戰鬥測試集上並排比較，寬度 0.5、1、2 的網路和 c2 每個動作都花 1.58–1.76 s，因為遊戲模擬的開銷遠大於網路。c3 保持寬度 1，讓它的門檻只檢驗資料。
- **最佳化器的設定也無關緊要**。在第 0 折上，學習率用 3 × 10⁻⁴ 或 10⁻⁴ 代替 10⁻³，或權重衰減用 10⁻² 代替 10⁻⁴，得到 1.346–1.348，原設定是 1.348。
- 網路所隱含的**估值**和真實結局的估值相關係數是 0.960，`LeafValue` 的是 0.829。
- **c3 的門檻**（其餘選項同冠軍）在 200 個種子中的 160 個之後作廢：它有一局在添水之下於商店裡反覆買同一瓶藥水，直到被截斷，這是一個此後已修復的框架 bug（提交 `c5ee8de`）。到那時為止，它平均比冠軍多到 0.58 層（LLR −0.65，未定），遠低於門檻的 δ，即 1.5 層（[評估：晉級門檻 §6](/zh-tw/arch/evaluation/gates/#sec-6)）。

## 7. 規劃中

- **SL 的網路 c7-1v** <Badge text="訓練中" variant="caution" />。還沒有任何 SL 訓練的網路過過門檻，而 c2 是從 PIMC 用 `LeafValue` 打的 NoSL 戰鬥學來的（[戰鬥大腦：葉節點 §6](/zh-tw/arch/combat-brain/leaf/#sec-6)）。c7-1v 是這一步唯一的網路：`uv run python -m combat.train --list data/silent/lists/c7 --env SL --name c7-1v --value ../weights/silent/v7-1f.json --skip-seeds ../eval/seeds/promotion-1-300.txt`。它的訓練資料是 SL 的自我對弈 v7g1（`sl/selfplay/v7g1/`：21,263 局，1,566,757 個回合開始，全部三檔，沒有探索過的戰鬥路線），加上 `promotion-301-500` 上 600 局 medium 預算對局（v7-1、v7-1e 和 v6-3-2；57,697 個回合開始；Test Subject 72 場，贏 10 場，v7g1 是 348 和 16）。門檻的種子 `promotion-1-300` 從不用於訓練；medium 測試集是這些種子上 v7-1f 的 100 局和 v7-1 的 300 局。寬度 1 倍，保留滯後意圖。它的標籤大多是規劃器在自我對弈的 low 預算下打出的結局（[SL 規劃器：預算 §2](/zh-tw/arch/sl-planner/budget/#sec-2)）。它必須通過自己的門檻（[戰鬥大腦：葉節點 §8.4](/zh-tw/arch/combat-brain/leaf/#sec-8.4)）。
- **權重分環境，結構共用** <Badge text="規劃中" variant="caution" />。網路的程式碼只有一份，網路檔案寫明它的環境，`combat.train` 拒絕另一個環境的日誌（[§3](#sec-3)）。NoSL 目前仍用 c2。
- **讓沒選中的束狀態繼續打來取得標籤** <Badge text="規劃中" variant="caution" />，只在 c7-1v 的門檻顯出網路的效果時才做：搜尋保留但沒打出的狀態繼續打下去，用它的結局當標籤，這就得到已打路線之外的標籤。其他目標（戰鬥內的 TD(λ)、和搜尋分布的混合）不屬於這個設計（[循環 §4](/zh-tw/arch/learning/loop/#sec-4)）。
- **以搜尋的估值作標籤，並學一個先驗**（專家迭代）也不屬於這個設計，它沒有策略輸出頭（[循環 §5](/zh-tw/arch/learning/loop/#sec-5)）。
