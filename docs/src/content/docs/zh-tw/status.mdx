## 2. 主要缺口與風險

1. **CombatBuilder 的近似**。回合歷史、內部計數器、費用修改的持續時間、眩暈後續動作都是近似的，而且從沒用真實遊戲的觀測驗證過（[模擬器 §3](/zh-tw/arch/simulator/#sec-3)）。
2. **怪物動作重取樣**目前在「顯示相同意圖」的動作裡均勻選取，需要改成根據怪物歷史得到的後驗（[Harness §3](/zh-tw/arch/harness/#sec-3)）。
3. **選牌提示的上下文依賴非同步入口上的 Harmony 前綴**：內嵌或 rejit 都可能繞過它們（[GameBridge §5](/zh-tw/arch/gamebridge/#sec-5)、[Mod §10](/zh-tw/arch/mod/#sec-10)）。
4. **開局用的是 `UnlockState.all`**，不是使用者自己的存檔進度；晉階等級也沒有限制在角色允許的最大值以內（[模擬器 §5.1](/zh-tw/arch/simulator/#sec-5.1)）。
5. **新增的遊戲程式碼如果在事件之外（事件由 transpiler 覆蓋）呼叫 Godot 節點**而沒有 TestMode 保護，只會在 `run` 批次執行裡以遊戲錯誤的形式暴露出來（[模擬器 §5.2](/zh-tw/arch/simulator/#sec-5.2)）。
6. **真實遊戲裡的 Harmony 補丁與分層 JIT**：執行時可能重新編譯某個方法，悄悄丟掉補丁（[Mod §10](/zh-tw/arch/mod/#sec-10)）。
7. **戰鬥大腦 v0 的盲區**。選牌提示按固定規則（`p0`）回答，搜尋內和真實戰鬥裡都是如此，不經過搜尋；NoSL 的搜尋只看本回合；SL 的規劃器看得到整場戰鬥，但被證明的計畫很少，時間大多花在每回合都要重新規劃的失敗上（[戰鬥大腦 §7.1](/zh-tw/arch/combat-brain/#sec-7.1)）；葉節點是手工的，忽略了大多數能力（[戰鬥大腦 §4](/zh-tw/arch/combat-brain/#sec-4)）。
