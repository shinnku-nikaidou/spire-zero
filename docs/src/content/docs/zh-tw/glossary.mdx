術語按領域分組；每個條目都連結到深入介紹它的頁面。最後一節是名稱索引：本書提到的網路、種子集、檔案和資料夾。

## 1. 遊戲

| 術語 | 含義 |
|---|---|
| 一局（run） | 一次完整的遊玩，從遠古之民涅奧開始，到最後一個頭目被打倒或玩家死亡為止（[遊戲 §1](/zh-tw/arch/game/#sec-1)）。 |
| 幕（act）、層（floor） | 一局有三幕，每幕是一張以頭目結尾的地圖。一層就是一個房間；獲勝的一局結束在第 48 層（[遊戲 §1](/zh-tw/arch/game/#sec-1)）。 |
| 地圖點（map point）、`?` | 一幕地圖上的一個點：怪物、菁英、休息處、商店、財寶、未知（`?`）、遠古之民或頭目。`?` 在玩家進入時才擲骰決定成為事件、戰鬥、商店或財寶（[遊戲 §2](/zh-tw/arch/game/#sec-2)、[§3](/zh-tw/arch/game/#sec-3)）。 |
| 房間（room） | 地圖點在進入後所裝的東西：一場戰鬥、一個事件、一個休息處、一個商店、一份財寶。 |
| 遭遇（encounter）、意圖（intent） | 遭遇是一場戰鬥的怪物組合。意圖是怪物顯示它接下來要做什麼：攻擊及其傷害、格擋、增益……（[遊戲 §4](/zh-tw/arch/game/#sec-4)）。 |
| 抽牌堆 / 棄牌堆 / 消耗堆（draw / discard / exhaust pile） | 戰鬥中卡牌去的地方。抽牌堆的順序對玩家隱藏。 |
| 遺物（relic）、藥水（potion）、能力（power） | 遺物是永久的物品；藥水是放在欄位裡（藥水欄）的一次性物品；能力是生物身上持續的效果，例如力量或中毒。 |
| 附魔（enchantment）、苦痛（affliction） | 附魔是卡牌上持續的修飾（鋒利、靈巧……）；苦痛是敵人放到卡牌上、只在戰鬥中有效的負面修飾（禁縛、糾纏……）。 |
| Sly（奇巧） | 一個卡牌關鍵字：在回合結束前從手牌被棄掉的 Sly 牌會被免費打出。 |
| 遠古之民（Ancient） | 每幕開始時的那位存在，會為玩家回復生命並提供三份禮物：第 1 幕是涅奧。 |
| 晉階（Ascension，A0） | 難度等級 1–10；A0 是基礎遊戲（[遊戲 §6](/zh-tw/arch/game/#sec-6)）。 |
| 寂靜獵手（Silent） | 這個專案最先訓練的角色（[遊戲 §5](/zh-tw/arch/game/#sec-5)）。 |
| 選牌提示（card prompt） | 遊戲要求玩家選牌：棄牌、消耗、升級、轉化……（[協定：觀測與動作 §6](/zh-tw/arch/protocol/observation/#sec-6)）。 |
| 種子（seed）、亂數流（random stream） | 一局的 12 字元種子固定了每一條亂數流（洗牌、`?` 擲骰、怪物招式……），所以一局是它的種子和選擇的固定函數（[遊戲 §7](/zh-tw/arch/game/#sec-7)）。 |
| TestMode | 遊戲內建的測試開關。它會關掉表現層，但也會改變少數規則，模擬器用補丁把這些規則改回來（[模擬器：無頭宿主 §5](/zh-tw/arch/simulator/headless/#sec-5)）。 |

## 2. 專案元件

| 術語 | 含義 |
|---|---|
| Protocol | 每個行程共用的型別：訊息和觀測。只有玩家看得到的東西才能成為欄位（[協定](/zh-tw/arch/protocol/)）。 |
| GameBridge | 唯一把遊戲物件轉成觀測、把動作轉成遊戲呼叫的程式碼：observe、legal、start（[GameBridge](/zh-tw/arch/gamebridge/)）。 |
| Brain | 各種策略：戰鬥大腦和宏觀大腦。只引用 Protocol，從不引用遊戲。 |
| Harness | 宿主和大腦之間的函式庫：每一局的 dispatcher、大腦伺服器、工作行程池、對局記錄、報告和門檻（[Harness](/zh-tw/arch/harness/)）。 |
| dispatcher | 一局的 `Dispatcher`：把每個決策路由給一個大腦，保存這一局顯示過的東西，抽出種子，檢查並記錄答案（[Harness §2](/zh-tw/arch/harness/#sec-2)）。 |
| 大腦伺服器（brain server）、`brain` | Harness 在線路上的那一端，以及單獨執行它、供 Mod 和 `run --brain` 使用的 SimWorker 指令（[Harness §5](/zh-tw/arch/harness/#sec-5)）。 |
| SimWorker | 以無頭方式執行真實遊戲 DLL 的程式：戰鬥、整局、大腦、worker、評估（[模擬器](/zh-tw/arch/simulator/)）。 |
| worker、工作行程池（worker pool）、`serve` | 一個透過 JSON 行回答搜尋請求的 SimWorker 行程；行程池負責啟動和重啟它們（[模擬器：工作行程池](/zh-tw/arch/simulator/pool/)）。 |
| Mod | 真實遊戲裡的宿主：讀取畫面上的決策，詢問大腦，顯示答案（[Mod](/zh-tw/arch/mod/)）。 |
| 輔助模式（assist mode）、面板（panel）、標示（marks） | Mod 目前的模式：玩家自己打，面板顯示答案，標示在地圖上畫出路線、在戰鬥中畫出計畫的數字（[輸出](/zh-tw/arch/output/)）。 |
| RunSession | SimWorker 中以無頭方式經過每個決策畫面打完整局的類別（[模擬器：整局 §1](/zh-tw/arch/simulator/runs/#sec-1)）。 |
| CombatBuilder | 從一個觀測建構模擬器裡的戰鬥（[模擬器：戰鬥 §5](/zh-tw/arch/simulator/combat/#sec-5)）。 |
| Pump | 單執行緒的排程器，把遊戲所有的非同步程式碼放在同一個執行緒上、按同一個順序執行，所以結果是確定的（[模擬器：無頭宿主 §7](/zh-tw/arch/simulator/headless/#sec-7)）。 |
| 宿主（host） | 持有真實這一局並詢問大腦的那一方：真實遊戲裡是 Mod，自我對弈時是一個 SimWorker。 |
| 無頭（headless） | 執行遊戲的邏輯，沒有圖形、視窗或輸入。 |

## 3. 環境與資訊

| 術語 | 含義 |
|---|---|
| NoSL | 只有公開資訊的環境（[環境：資訊與節點 §1](/zh-tw/arch/environments/information/#sec-1)）。 |
| SL | NoSL 加上當前節點內的真實結果，就像在那裡允許存檔讀檔一樣（[環境：資訊與節點 §2](/zh-tw/arch/environments/information/#sec-2)）。 |
| 節點（node） | 在 SL 中：一個地圖點，從到達開始，直到離開它的移動為止（[環境：資訊與節點 §3](/zh-tw/arch/environments/information/#sec-3)）。不要與 Godot 的 UI 節點（`N*` 類別）混淆。 |
| 公開歷史（public history）、敵人出招紀錄（record of enemy moves） | 到目前為止顯示過的一切。Harness 保存搜尋需要的那部分：每個敵人每一輪的意圖（[Harness §4](/zh-tw/arch/harness/#sec-4)）。 |
| 確定化（determinization） | 抽出一個與公開歷史相符的具體隱藏狀態（抽牌順序、怪物招式、亂數流）（[環境：世界 §2](/zh-tw/arch/environments/worlds/#sec-2)）。 |
| 世界（world） | 搜尋可以探索的模擬器狀態：NoSL 中是取樣的世界，SL 中是精確的節點複本（[模擬器：世界與 SL 複本 §1](/zh-tw/arch/simulator/worlds/#sec-1)）。 |
| 檢查點（checkpoint）、複本（clone）、封存（seal） | SL 的世界是節點的檢查點，在到達時取得，再重播節點內的各個步驟：這就是它的複本。複本在節點出口處封存：再走一步就會拋出例外（[模擬器：世界與 SL 複本 §3](/zh-tw/arch/simulator/worlds/#sec-3)–[§5](/zh-tw/arch/simulator/worlds/#sec-5)）。 |
| 視野邊界（horizon） | 從 SL 世界內部看到的節點出口（`AtHorizon`）。 |
| SL 紀錄（SL record） | Mod 保存的東西，讓大腦能在真實遊戲裡複製節點：檢查點和每一步，在遊戲提交它們的地方讀出（[Mod：SL 紀錄](/zh-tw/arch/mod/sl-record/)）。 |
| 白名單（whitelist） | 觀測欄位只有在遊戲顯示它時才存在的規則；每個欄位都有一個測試（[協定 §3](/zh-tw/arch/protocol/#sec-3)）。 |

## 4. 決策與搜尋

| 術語 | 含義 |
|---|---|
| 決策介面（surface） | 決策畫面的一種：戰鬥、地圖、獎勵、商店、選牌提示……決策介面決定一個決策路由給哪個大腦（[協定：觀測與動作 §5](/zh-tw/arch/protocol/observation/#sec-5)）。 |
| 決策點（decision point）、空閒（idle） | 遊戲等待玩家、可以詢問下一個決策的時刻；在真實遊戲裡，是一個靜止了 3 個影格的畫面（[Mod：主迴圈 §4](/zh-tw/arch/mod/loop/#sec-4)）。 |
| 觀測（observation） | 玩家在決策點能看到的東西，以協定型別表示（[協定：觀測與動作](/zh-tw/arch/protocol/observation/)）。 |
| 合法動作（legal actions） | 玩家現在能採取的每個動作，寫成文字，如 `play:C:T` 或 `map:col,row`。 |
| uid | 戰鬥中一張卡牌或一個生物的穩定 id，讓動作可以指名它們。 |
| 推薦（recommendation） | 大腦的回答：動作、它之後的計畫，在戰鬥中還有它評分過的候選（[輸出 §1](/zh-tw/arch/output/#sec-1)）。 |
| 候選（candidate） | 搜尋評分過的一個第一步動作，帶有它的價值、信賴區間和樣本數（[協定：世界與工作行程訊息 §3](/zh-tw/arch/protocol/worlds/#sec-3)）。 |
| 後備（fallback） | 沒有大腦負責某個決策時選一個（例如隨機選）。這是禁止的：這一局改為帶著錯誤停下。 |
| 佔位策略（placeholder） | 不搜尋的策略（`play`、`random`），用於測試和基線；由 `random` 做的決策會讓一次評估作廢。 |
| PIMC | 完美資訊蒙地卡羅（Perfect Information Monte Carlo）：取樣幾個確定化世界，在每個世界裡當作一切已知去搜尋，再按第一步動作取平均（[NoSL PIMC](/zh-tw/arch/pimc/)）。 |
| 策略融合（strategy fusion） | 在每個取樣世界裡挑一條不同的最佳路線的錯誤，好像玩家知道哪個世界是真的。按第一步動作取平均，讓它不進入選擇（[環境：世界 §3](/zh-tw/arch/environments/worlds/#sec-3)）。 |
| SL 規劃器（SL planner） | SL 的戰鬥大腦：在節點複本上對整個回合做束搜尋，一直到戰鬥結束（[SL 規劃器](/zh-tw/arch/sl-planner/)）。 |
| 束搜尋（beam search）、分支定界（branch-and-bound） | 每一步只保留最好的 B 個狀態；丟掉每個上界贏不了已找到的最佳路線的分支，所以達到上界的路線就被證明是最佳的（[SL 規劃器：束搜尋](/zh-tw/arch/sl-planner/beam/)）。 |
| TurnEnds | 規劃中：兩種環境共用的一個搜尋步驟，列舉一個回合可能結束在哪些狀態（[戰鬥大腦 §3.1](/zh-tw/arch/combat-brain/#sec-3.1)）。 |
| 迭代加寬（iterative widening） | 為 SL 規劃器規劃中：寬度 1、2、4、8、…的多輪，每輪都打到戰鬥結束，並用目前最好的路線剪枝（[SL 規劃器：束搜尋 §7](/zh-tw/arch/sl-planner/beam/#sec-7)）。 |
| 葉節點（leaf）、戰鬥網路（combat net） | 在搜尋停下的地方，由葉節點給狀態評分：戰鬥網路的結局，按 `LeafValue` 手設的數字定價（[戰鬥大腦：葉節點](/zh-tw/arch/combat-brain/leaf/)）。 |
| 後狀態（afterstate） | 剛做完選擇、新的隨機性出現之前的狀態。宏觀大腦按選項的後狀態給它們估值（[宏觀大腦：後狀態與單一 V](/zh-tw/arch/macro-brain/afterstates/)）。 |
| L0 | 宏觀大腦：它用 V 給每個選項的後狀態估值，取最好的那個；在地圖上，它規劃通往頭目的路線（[宏觀大腦：搜尋](/zh-tw/arch/macro-brain/search/)）。 |
| 預算（budget）、力度（effort） | 一個決策可以用多少搜尋：PIMC 是世界數和節點數，SL 規劃器是束；規劃器的力度指名一個預算（[Harness：路由、預算與種子 §4](/zh-tw/arch/harness/routing/#sec-4)）。 |
| 冠軍名稱（champion name） | 報告為一局的大腦取的名字：`combat B, combat prompts B, macro B, macro prompts B`（[Harness：路由、預算與種子 §1](/zh-tw/arch/harness/routing/#sec-1)）。 |
| 決策日誌（decision log） | 一局的每個決策一行 JSON：給大腦看了什麼，它選了什麼、規劃了什麼、評分了什麼、花了多少（[Harness：決策日誌](/zh-tw/arch/harness/decision-log/)）。 |

## 5. 學習

| 術語 | 含義 |
|---|---|
| 價值函數 V（value function V） | 宏觀大腦對一個對局狀態的評判：從那裡贏下這一局的機率（[宏觀大腦：從風險值到價值](/zh-tw/arch/macro-brain/value/)、[宏觀大腦：價值網路](/zh-tw/arch/macro-brain/network/)）。 |
| 自我對弈（self-play） | 冠軍在模擬器裡打完整局，產生訓練資料（[宏觀大腦：自我對弈](/zh-tw/arch/macro-brain/selfplay/)）。 |
| 冠軍（champion）、挑戰者（challenger） | 冠軍是一種環境中目前最好的版本；挑戰者必須通過門檻才能取代它（[評估：冠軍與基線](/zh-tw/arch/evaluation/champions/)）。 |
| MC、TD(λ) | 設定價值目標的方法：從最終結果（蒙地卡羅），或與之後幾個狀態的價值混合（時間差分）（[學習：循環 §3](/zh-tw/arch/learning/loop/#sec-3)）。 |
| ExIt | 專家迭代（expert iteration）：訓練學出來的部分去模仿搜尋選擇的東西（[學習：循環 §5](/zh-tw/arch/learning/loop/#sec-5)）。 |
| SPSA | 同時擾動隨機逼近（simultaneous perturbation stochastic approximation）：把許多參數一起擾動，同時調整它們；本專案不使用它（[學習：循環 §6](/zh-tw/arch/learning/loop/#sec-6)）。 |
| 特權資訊（privileged information） | 只在訓練時用來降低雜訊的隱藏狀態；從不是部署後策略的輸入。 |
| 探索（exploration）、均勻抽取（even draws）、ε | 自我對弈的探索（`run --explore ε`）：一個宏觀決策以機率 ε 在它的選項中均勻抽取，不管 V 怎麼說。 |

## 6. 評估

| 術語 | 含義 |
|---|---|
| R1–R4 | 模擬到實機的階梯：從模擬器對局（R1）到裝了 Mod 的 Steam 遊戲（R4）的四級，每級多一個新變數（[評估 §2](/zh-tw/arch/evaluation/#sec-2)）。 |
| 排行榜（leaderboard） | 按角色、晉階、種子集和環境分開的成績；NoSL 和 SL 從不放在一起排名（`eval/silent/leaderboard.md`）。 |
| 報告（report）、對局記錄（run record） | 一批對局的結果，以 JSON 表示，帶有每一局的記錄：它的種子、結果、層數、戰鬥和大腦（[評估：指標、種子與報告 §8](/zh-tw/arch/evaluation/metrics/#sec-8)）。 |
| 晉級門檻（gate） | 挑戰者要晉升必須通過的配對檢驗（[評估：晉級門檻](/zh-tw/arch/evaluation/gates/)）。 |
| CRN、配對（pairing） | 共同亂數（common random numbers）：冠軍和挑戰者打同樣的種子，所以兩者的差異雜訊更小。 |
| SPRT | 序列機率比檢定：一旦證據在任一方向上夠強，就停止比較。 |
| Wilson 區間（Wilson interval） | 勝率的一種信賴區間，在 0% 和 100% 附近仍然合理。 |
| 種子集（seed sets） | 用於晉級和最終檢查的固定種子清單，與訓練種子分開（`eval/seeds/`）。 |

## 7. 名稱

| 名稱 | 是什麼 |
|---|---|
| v9-0 | V，每個角色共用的那一個價值網路，兩個冠軍都在用（[宏觀大腦：價值網路](/zh-tw/arch/macro-brain/network/)）。 |
| c9-0 | 戰鬥網路，每個角色共用的那一個，兩個冠軍都在用（[戰鬥網路](/zh-tw/arch/combat-brain/network/)）。 |
| 詞元表（token table） | 網路裡一種 id（牌、遺物……）的清單，每個 id 有學到的列：這個遊戲版本的每個 id；第 0 項 `<unk>` 讀任何其他 id（[戰鬥網路 §2](/zh-tw/arch/combat-brain/network/#sec-2)）。 |
| `weights/all/NAME.json` | 一個網路的檔案；冠軍打 `v9-0.json` 和 `c9-0.json`（[學習：參考 §6](/zh-tw/arch/learning/reference/#sec-6)）。 |
| `promotion-1`, `promotion-1-300`, `final-1`, `a10-check-1` | `eval/seeds/` 裡的種子集：200 和 300 個晉級種子（較長的以較短的開頭），一個在任何對局用到它之前就登記好的、300 個種子的最終集合，以及 200 個用來測 A10 勝率的種子，不在任何訓練資料裡。 |
| `eval/champions/sl.json`, `nosl.json` | 冠軍檔案：打出每種環境冠軍的選項，涵蓋每個角色，以及它在每個角色上的報告。 |
