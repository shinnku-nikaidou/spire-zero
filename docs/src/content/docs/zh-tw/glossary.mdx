術語按領域分組。每個條目都連結到詳細介紹它的頁面。

## 遊戲術語

| 術語 | 英文 | 含義 |
|---|---|---|
| 一局 | run | 從開局（Neow）到勝利或死亡的一次完整遊玩。 |
| 幕、層數 | act, floor | 一局分為若干幕，每幕有自己的地圖和頭目。層數是總層數，與頂欄顯示的一致。 |
| 地圖點、`?` | map point | 幕地圖上的一個點：戰鬥、菁英、休息處、商店、財寶、事件，或 `?`（進入前未知，到達時遊戲才擲骰決定它是什麼）。 |
| 遭遇、意圖 | encounter, intent | 遭遇是一場戰鬥裡的怪物組合。意圖是怪物頭上表示下一步打算的圖示（攻擊及傷害、格擋、增益……）。 |
| 抽牌堆 / 棄牌堆 / 消耗堆 | draw / discard / exhaust pile | 戰鬥中卡牌所在的位置。抽牌堆的順序對玩家是隱藏的。 |
| 遺物、藥水、能力 | relic, potion, power | 遺物是永久道具；藥水是放在藥水欄格子裡的一次性道具；能力是生物身上持續的效果（如力量）。 |
| Ancient 事件（Neow） | Ancient | 提供若干恩賜供選擇的特殊事件。每局都以 Neow 開始。 |
| 晉階等級（A0） | ascension | 難度等級；A0 是基礎難度。 |
| Silent（寂靜獵手）、Ironclad（鐵甲戰士） | | 可玩角色。專案從 Silent 開始。 |
| 選牌提示 | card prompt | 遊戲要求玩家選牌的時刻（棄牌、消耗、升級、轉化……）。 |
| TestMode | | 遊戲自帶的測試開關。它會關掉表現層，但也會改變少數規則，模擬器用補丁把這些規則改回來（[模擬器 §1](/zh-tw/arch/simulator/#sec-1)）。 |

## 專案元件

| 術語 | 含義 |
|---|---|
| Protocol | 所有行程共享的通訊型別。只有遊戲 UI 顯示的內容才能成為欄位（[協定](/zh-tw/arch/protocol/)）。 |
| GameBridge | 唯一負責把遊戲物件轉成協定觀測、把協定動作轉成遊戲呼叫的程式碼（[GameBridge](/zh-tw/arch/gamebridge/)）。 |
| Brain | 策略：戰鬥大腦和宏觀大腦。只引用 Protocol，從不引用遊戲。 |
| SimWorker | 以無頭方式執行真實遊戲 DLL 的行程，用於搜尋世界和自我對弈（[模擬器](/zh-tw/arch/simulator/)）。 |
| Mod | 真實遊戲裡的輕量宿主：觀測、提問、顯示或執行（[Mod](/zh-tw/arch/mod/)）。 |
| Harness | 決策行程裡的排程器：記錄、路由、預算、日誌（[Harness](/zh-tw/arch/harness/)）。 |
| RunSession | SimWorker 裡的類別，以無頭方式經過所有決策介面跑完整局（[模擬器 §5](/zh-tw/arch/simulator/#sec-5)）。 |
| CombatBuilder | 根據一個觀測建構模擬器裡的戰鬥（[模擬器 §3](/zh-tw/arch/simulator/#sec-3)）。 |
| Pump | 單執行緒排程器，讓遊戲的所有非同步程式碼都在同一個執行緒上執行，從而保證結果確定。 |
| 宿主（host） | 持有真實這一局的那一方：真實遊戲裡是 Mod，自我對弈時是一個 SimWorker。 |
| 無頭（headless） | 只執行遊戲邏輯，沒有畫面、視窗和輸入。 |

## 環境與資訊

| 術語 | 英文 | 含義 |
|---|---|---|
| NoSL | | 只用公開資訊的環境（[環境 §1](/zh-tw/arch/environments/#sec-1)）。 |
| SL | | NoSL 加上當前節點內的真實結果，相當於允許在節點內存檔讀檔。 |
| 節點 | node | 在 SL 中指一個地圖點，從到達開始，到離開它的移動動作為止（[環境 §4](/zh-tw/arch/environments/#sec-4)）。不要與 Godot 的 UI 節點（`N*` 類別）混淆。 |
| 公開歷史、公開記錄 | public history / record | 到目前為止螢幕上顯示過的一切，加上能從中推斷出的資訊。Harness 把它儲存為公開記錄。 |
| 確定化 | determinization | 抽取一個與公開歷史一致的具體隱藏狀態（抽牌順序、怪物動作、亂數流）。 |
| 世界 | world | 搜尋可以探索的模擬器狀態：NoSL 中是取樣世界，SL 中是精確的節點複本。 |
| 複本、檢查點、封存 | clone, checkpoint, seal | SL 的世界由節點入口處的檢查點加上之後的動作建構。世界在節點出口處封存：之後的動作會拋出例外。 |
| 視野邊界 | horizon | 從 SL 世界內部看到的節點出口（`AtHorizon`）。 |
| 白名單 | whitelist | 觀測欄位只有在 UI 顯示時才能存在的規則；每個欄位都有測試。 |
| 公平規則 | fair play | AI 能看什麼、能做什麼的規則，彙總在本地筆記 `fair-play-spec.md` 裡。 |

## 決策與搜尋

| 術語 | 英文 | 含義 |
|---|---|---|
| 決策介面 | surface | 決策畫面的種類（戰鬥、地圖、獎勵、商店……）。介面名稱決定一個決策交給哪個大腦（[協定 §3](/zh-tw/arch/protocol/#sec-3)）。 |
| 決策點 | decision point | 遊戲在等玩家操作、可以提出下一個決策的時刻。 |
| 觀測 | observation | 玩家在決策點能看到的內容，用協定型別表示。 |
| 合法動作 | legal actions | 玩家此刻能做的所有動作，寫成文字，如 `play:C:T` 或 `map:col,row`。 |
| uid | | 手牌中的卡牌或戰鬥中生物的穩定編號，動作用它來指明目標。 |
| 推薦、事實 | recommendation, fact | 大腦的回答：一個動作、背後的計畫、比較過的候選，以及用來生成解釋的事實（數字）。 |
| 後備 | fallback | 沒有大腦負責某個決策時隨便選一個（比如隨機）。禁止這樣做：遊戲改為暫停。 |
| 分支、推演 | branch, rollout | 分支是在某個世界裡嘗試的一條動作序列。推演是從那裡用快速策略繼續往下玩，以估計結果。 |
| 完美資訊蒙地卡羅 | PIMC | 取樣若干個確定化世界，在每個世界裡假裝一切已知去搜尋，然後取平均（[戰鬥大腦 §2](/zh-tw/arch/combat-brain/#sec-2)）。 |
| 策略融合 | strategy fusion | 在每個取樣世界裡各自挑最佳路線的錯誤，好像玩家知道哪個世界是真的。按第一步動作取平均可以避免它。 |
| ISMCTS | | 資訊集蒙地卡羅樹搜尋：如果 PIMC 殘留的融合誤差確實造成問題，就改用它。 |
| 分支定界 | branch-and-bound | 保留目前找到的最好路線，丟掉上界比不過它的分支；達到上界的路線就被證明是最佳的。SL 戰鬥規劃器用它來剪自己的束（[戰鬥大腦 §3](/zh-tw/arch/combat-brain/#sec-3)）。 |
| 束搜尋（集束搜尋） | beam search | 每一步只保留最好的 B 個狀態，只展開它們。SL 規劃器的一步是一個回合：它保留最好的 B 個回合結束狀態（[戰鬥大腦 §3](/zh-tw/arch/combat-brain/#sec-3)）。 |
| 後狀態 | afterstate | 剛做完選擇、新的隨機結果出現之前的狀態。宏觀大腦用後狀態給選項估值（[宏觀大腦 §2](/zh-tw/arch/macro-brain/#sec-2)）。 |
| L0、L1 | | 宏觀大腦的兩個層級：L0 用 V 給每個後狀態估值；L1 對難分高下的選擇用成對推演複核。 |
| 預算 | budget | 一次決策能用多少搜尋：固定的分支數（可重現）或掛鐘時間（[Harness §5](/zh-tw/arch/harness/#sec-5)）。 |

## 學習

| 術語 | 英文 | 含義 |
|---|---|---|
| 價值函式 V、P(win) | value function | V(觀測) = 從這裡出發贏下這一局的估計機率。所有決策共用這一個尺度（[學習 §1](/zh-tw/arch/learning/#sec-1)）。 |
| 葉節點估值 | leaf value | 在搜尋停止的地方（例如回合結束）使用的 V。 |
| 自我對弈 | self-play | 當前冠軍在模擬器裡打完整局，產生訓練資料。 |
| 冠軍、挑戰者 | champion, challenger | 冠軍是當前最好的版本；挑戰者必須通過晉級門檻才能取代它。 |
| MC、TD(λ) | | 設定價值目標的兩種方法：用最終結果（蒙地卡羅），或與下一個狀態的價值混合（時間差分）。 |
| ExIt | Expert Iteration | 專家迭代：把搜尋結果當作訓練標籤，讓價值函式學會搜尋發現的東西。 |
| SPSA | | 同時擾動隨機逼近：同時擾動許多參數，一次調好它們。 |
| 特權資訊 | privileged information | 只在訓練時使用、用來降低雜訊的隱藏狀態；永遠不是部署後策略的輸入（[學習 §4](/zh-tw/arch/learning/#sec-4)）。 |

## 評估

| 術語 | 英文 | 含義 |
|---|---|---|
| R1–R4（模擬到實機階梯） | sim-to-real ladder | 從純模擬器對局（R1）到裝了 Mod 的 Steam 遊戲（R4）的四級階梯，每級只多一個新變數（[評估 §1](/zh-tw/arch/evaluation/#sec-1)）。 |
| 排行榜 | leaderboard | 每種環境各自的成績；NoSL 和 SL 從不混在一起（[評估 §2](/zh-tw/arch/evaluation/#sec-2)）。 |
| 晉級門檻 | gate | 挑戰者要晉級必須通過的檢驗（[評估 §5](/zh-tw/arch/evaluation/#sec-5)）。 |
| 公共亂數 | CRN | 冠軍和挑戰者用相同的種子和亂數來打，兩者的差別雜訊更小。 |
| SPRT | | 序列機率比檢定：只要證據足夠強（無論哪個方向）就停止比較。 |
| 種子集 | seed sets | 互不相交的訓練、晉級、最終種子；最終種子在使用前登記（[評估 §4](/zh-tw/arch/evaluation/#sec-4)）。 |
