## 1. 游戏

| 术语 | 含义 |
|---|---|
| 一局（run） | 一次完整的游玩，从先古之民涅奥开始，到打败最后一个 Boss 或玩家死亡为止（[游戏 §1](/arch/game/#sec-1)）。 |
| 幕（act）、层（floor） | 一局有三幕，每幕是一张以 Boss 结尾的地图。一层是一个房间；赢下的一局结束在第 48 层（[游戏 §1](/arch/game/#sec-1)）。 |
| 地图点（map point）、`?` | 一幕地图上的一个点：怪物、精英、休息处、商店、宝箱、未知（`?`）、先古之民或 Boss。`?` 在玩家进入时才掷成事件、战斗、商店或宝箱（[游戏 §2](/arch/game/#sec-2)、[§3](/arch/game/#sec-3)）。 |
| 房间（room） | 地图点进入之后里面的东西：一场战斗、一个事件、一个休息处、一个商店、一个宝箱。 |
| 遭遇（encounter）、意图（intent） | 遭遇是一场战斗的怪物组合。意图是怪物显示的它下一步要做的事：攻击及其伤害、格挡、增益……（[游戏 §4](/arch/game/#sec-4)）。 |
| 抽牌堆 / 弃牌堆 / 消耗牌堆（draw / discard / exhaust pile） | 战斗中卡牌所去的地方。抽牌堆的顺序对玩家隐藏。 |
| 遗物（relic）、药水（potion）、能力（power） | 遗物是永久的道具；药水是放在栏位里（药水栏）的一次性道具；能力是生物身上的持续效果，例如力量或中毒。 |
| 附魔（enchantment）、苦痛（affliction） | 卡牌上的持久修饰（锋利、灵巧……）；敌人加在卡牌上、只在战斗中有效的负面修饰（魂缚、缠身……）。 |
| Sly | 一个卡牌关键词：Sly 牌在回合结束前从手牌中被弃掉时，会被免费打出。 |
| 先古之民（Ancient） | 每一幕开头的存在，会治疗玩家并提供三份礼物：第 1 幕是涅奥。 |
| 进阶（Ascension，A0） | 难度等级 1–10；A0 是基础游戏（[游戏 §6](/arch/game/#sec-6)）。 |
| 静默猎手（Silent） | 这个项目最先训练的角色（[游戏 §5](/arch/game/#sec-5)）。 |
| 选牌提示（card prompt） | 游戏要求玩家选牌：弃牌、消耗、升级、变化……（[协议：观测与动作 §6](/arch/protocol/observation/#sec-6)）。 |
| 种子（seed）、随机数流（random stream） | 一局的 12 位种子决定每一条随机数流（洗牌、`?` 的掷骰、怪物招式……），所以一局是它的种子和选择的确定函数（[游戏 §7](/arch/game/#sec-7)）。 |
| TestMode | 游戏自带的测试开关。它关掉表现层，但也改变少数规则，模拟器用补丁把它们改回来（[模拟器：无头宿主 §5](/arch/simulator/headless/#sec-5)）。 |

## 2. 项目组件

| 术语 | 含义 |
|---|---|
| Protocol | 每个进程共享的类型：消息和观测。只有玩家能看到的东西才能成为字段（[协议](/arch/protocol/)）。 |
| GameBridge | 唯一把游戏对象变成观测、把动作变成游戏调用的代码：observe、legal、start（[GameBridge](/arch/gamebridge/)）。 |
| Brain | 策略：战斗大脑和宏观大脑。只引用 Protocol，从不引用游戏。 |
| Harness | 宿主和大脑之间的库：每一局的调度器、大脑服务器、工作进程池、对局记录、报告和晋级门槛（[Harness](/arch/harness/)）。 |
| 调度器（dispatcher） | 一局的 `Dispatcher`：把每个决策路由给一个大脑，保存这一局显示过的东西，抽取种子，检查答案并记入日志（[Harness §2](/arch/harness/#sec-2)）。 |
| 大脑服务器（brain server）、`brain` | Harness 在线路上的那一端，也是为 Mod 和 `run --brain` 单独运行它的 SimWorker 命令（[Harness §5](/arch/harness/#sec-5)）。 |
| SimWorker | 以无头方式运行真实游戏 DLL 的程序：战斗、整局、大脑、worker、评估（[模拟器](/arch/simulator/)）。 |
| 工作进程（worker）、工作进程池（worker pool）、`serve` | 一个通过 JSON 行回答搜索请求的 SimWorker 进程；工作进程池负责启动和重启它们（[模拟器：工作进程池](/arch/simulator/pool/)）。 |
| Mod | 真实游戏里的宿主：读取屏幕上的决策，询问大脑，显示答案（[Mod](/arch/mod/)）。 |
| 辅助模式（assist mode）、面板（panel）、标记（marks） | Mod 目前的模式：玩家自己打，面板显示答案，标记在地图上画出路线、在战斗中画出计划的序号（[输出](/arch/output/)）。 |
| RunSession | SimWorker 里的类，以无头方式经过每个决策画面打完整局（[模拟器：整局 §1](/arch/simulator/runs/#sec-1)）。 |
| CombatBuilder | 根据一个观测构建模拟器里的战斗（[模拟器：战斗 §5](/arch/simulator/combat/#sec-5)）。 |
| Pump | 单线程调度器，在一个线程上、按同一种顺序运行游戏的所有异步代码，从而让结果确定（[模拟器：无头宿主 §7](/arch/simulator/headless/#sec-7)）。 |
| 宿主（host） | 持有真实这一局并询问大脑的一方：真实游戏里是 Mod，自我对弈时是一个 SimWorker。 |
| 无头（headless） | 只运行游戏的逻辑，没有画面、窗口和输入。 |

## 3. 环境与信息

| 术语 | 含义 |
|---|---|
| NoSL | 只有公开信息的环境（[环境：信息与节点 §1](/arch/environments/information/#sec-1)）。 |
| SL | NoSL 加上当前节点里的真实结果，就好像在那里允许存档和读档（[环境：信息与节点 §2](/arch/environments/information/#sec-2)）。 |
| 节点（node） | 在 SL 中指一个地图点，从到达开始，到离开它的那次移动为止（[环境：信息与节点 §3](/arch/environments/information/#sec-3)）。不要与 Godot 的 UI 节点（`N*` 类）混淆。 |
| 公开历史（public history）、敌人出招记录（record of enemy moves） | 到目前为止显示过的一切。Harness 保存搜索需要的部分：每个敌人每一回合的意图（[Harness §4](/arch/harness/#sec-4)）。 |
| 确定化（determinization） | 抽取一个与公开历史一致的具体隐藏状态（抽牌顺序、怪物招式、随机数流）（[环境：世界 §2](/arch/environments/worlds/#sec-2)）。 |
| 世界（world） | 搜索可以探索的模拟器状态：NoSL 中是一个抽样的世界，SL 中是精确的节点克隆（[模拟器：世界与 SL 克隆 §1](/arch/simulator/worlds/#sec-1)）。 |
| 检查点（checkpoint）、克隆（clone）、封存（seal） | SL 的世界是节点的检查点（到达时取下），再重播这个节点的各个步骤：这就是它的克隆。克隆在节点出口处封存：再走一步就会抛出异常（[模拟器：世界与 SL 克隆 §3](/arch/simulator/worlds/#sec-3)–[§5](/arch/simulator/worlds/#sec-5)）。 |
| 视野边界（horizon） | 从 SL 世界内部看到的节点出口（`AtHorizon`）。 |
| SL 记录（SL record） | Mod 为了让大脑能在真实游戏里克隆节点而保存的东西：检查点和每一步，在游戏提交它的地方读取（[Mod：SL 记录](/arch/mod/sl-record/)）。 |
| 白名单（whitelist） | 观测字段只有在游戏显示它时才存在的规则；每个字段都有一个测试（[协议 §3](/arch/protocol/#sec-3)）。 |

## 4. 决策与搜索

| 术语 | 含义 |
|---|---|
| 决策界面（surface） | 决策画面的一种：战斗、地图、奖励、商店、选牌提示……决策界面决定一个决策交给哪个大脑（[协议：观测与动作 §5](/arch/protocol/observation/#sec-5)）。 |
| 决策点（decision point）、空闲（idle） | 游戏在等玩家、可以询问下一个决策的时刻；在真实游戏里，就是一个已经静止了 3 帧的画面（[Mod：主循环 §4](/arch/mod/loop/#sec-4)）。 |
| 观测（observation） | 玩家在决策点能看到的东西，用协议类型表示（[协议：观测与动作](/arch/protocol/observation/)）。 |
| 合法动作（legal actions） | 玩家此刻能做的每一个动作，写成文本，例如 `play:C:T` 或 `map:col,row`。 |
| uid | 战斗中一张牌或一个生物的稳定编号，动作用它来指明对象。 |
| 推荐（recommendation） | 大脑的回答：动作、它之后的计划，以及对一场战斗而言它打过分的候选（[输出 §1](/arch/output/#sec-1)）。 |
| 候选（candidate） | 搜索打过分的一个第一步动作，带着它的价值、置信区间和样本数（[协议：世界与工作进程消息 §3](/arch/protocol/worlds/#sec-3)）。 |
| 兜底（fallback） | 没有大脑负责一个决策时，（比如随机地）选一个。这是禁止的：这一局改为报错停止。 |
| 占位策略（placeholder） | 不搜索的策略（`play`、`random`），用于测试和基线；由 `random` 做出的决策会让一次评估作废。 |
| PIMC | 完美信息蒙特卡洛（Perfect Information Monte Carlo）：抽样若干确定化的世界，在每个世界里当作一切已知去搜索，再按第一步动作取平均（[NoSL PIMC](/arch/pimc/)）。 |
| 策略融合（strategy fusion） | 在每个抽样世界里各挑一条不同的最佳路线的错误，就好像玩家知道哪个世界是真的。按第一步动作取平均，让它不进入选择（[环境：世界 §3](/arch/environments/worlds/#sec-3)）。 |
| SL 规划器（SL planner） | SL 的战斗大脑：在节点的克隆上以整个回合为单位做束搜索，一直到战斗结束（[SL 规划器](/arch/sl-planner/)）。 |
| 束搜索（beam search）、分支定界（branch-and-bound） | 每一步只保留最好的 B 个状态；丢掉上界比不过已找到的最佳路线的每个分支，所以达到上界的路线就被证明是最好的（[SL 规划器：束搜索](/arch/sl-planner/beam/)）。 |
| TurnEnds | 规划中：两种环境共用的一个搜索步骤，枚举一个回合可能结束的各个状态（[战斗大脑 §3.1](/arch/combat-brain/#sec-3.1)）。 |
| 迭代加宽（iterative widening） | 为 SL 规划器规划：宽度为 1、2、4、8……的多轮，每轮都打到战斗结束，并由目前最好的路线剪枝（[SL 规划器：束搜索 §7](/arch/sl-planner/beam/#sec-7)）。 |
| 叶子（leaf）、战斗网络（combat net） | 在搜索停下的地方，由叶子给状态打分：战斗网络的结局，按 `LeafValue` 手设的数定价（[战斗大脑：叶子](/arch/combat-brain/leaf/)）。 |
| 后状态（afterstate） | 刚做完选择、新的随机性出现之前的状态。宏观大脑按后状态给选项估值（[宏观大脑：后状态与单一 V](/arch/macro-brain/afterstates/)）。 |
| L0 | 宏观大脑：它用 V 给每个选项的后状态估值，取最好的；在地图上它规划通往 Boss 的路线（[宏观大脑：搜索](/arch/macro-brain/search/)）。 |
| 预算（budget）、力度（effort） | 一个决策可以用多少搜索：PIMC 是世界数和节点数，SL 规划器是束；规划器的力度是某个预算的名字（[Harness：路由、预算与种子 §4](/arch/harness/routing/#sec-4)）。 |
| 冠军名称（champion name） | 报告给一局的各个大脑起的名字：`combat B, combat prompts B, macro B, macro prompts B`（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)）。 |
| 决策日志（decision log） | 一局的每个决策一行 JSON：大脑看到了什么，选了什么、计划了什么、打了什么分、花了多少（[Harness：决策日志](/arch/harness/decision-log/)）。 |

## 5. 学习

| 术语 | 含义 |
|---|---|
| 价值函数 V（value function V） | 宏观大脑对一局状态的评判：从那里赢下这一局的概率（[宏观大脑：从风险值到价值](/arch/macro-brain/value/)、[宏观大脑：价值网络](/arch/macro-brain/network/)）。 |
| 自我对弈（self-play） | 冠军在模拟器里打完整局，产生训练数据（[宏观大脑：自我对弈](/arch/macro-brain/selfplay/)）。 |
| 冠军（champion）、挑战者（challenger） | 冠军是某个环境里当前最好的版本；挑战者必须通过晋级门槛才能取代它（[评估：冠军与基线](/arch/evaluation/champions/)）。 |
| MC、TD(λ) | 设定价值目标的方法：用最终结果（蒙特卡洛），或与下一个状态的价值混合（时序差分）（[学习：循环 §3](/arch/learning/loop/#sec-3)）。 |
| ExIt | 专家迭代（expert iteration）：训练学到的部分去模仿搜索选出的东西（[学习：循环 §5](/arch/learning/loop/#sec-5)）。 |
| SPSA | 同时扰动随机逼近（simultaneous perturbation stochastic approximation）：把许多参数一起扰动，一次调好它们；本项目不使用它（[学习：循环 §6](/arch/learning/loop/#sec-6)）。 |
| 特权信息（privileged information） | 只在训练中用来降低噪声的隐藏状态；永远不是部署后策略的输入。 |
| 探索（exploration）、均匀抽取（even draws）、ε | 自我对弈的探索（`run --explore ε`）：一个宏观决策以概率 ε 在它的选项中均匀抽取，不管 V 怎么说。 |

## 6. 评估

| 术语 | 含义 |
|---|---|
| R1–R4 | 仿真到实机阶梯：从模拟器对局（R1）到装了 Mod 的 Steam 游戏（R4）的四级，每级只多一个新变量（[评估 §2](/arch/evaluation/#sec-2)）。 |
| 排行榜（leaderboard） | 按角色、进阶、种子集和环境分开的成绩；NoSL 和 SL 从不放在一起排名（`eval/silent/leaderboard.md`）。 |
| 报告（report）、对局记录（run record） | 一批对局的结果，JSON 格式，带每一局的记录：它的种子、结果、层数、战斗和大脑（[评估：指标、种子与报告 §8](/arch/evaluation/metrics/#sec-8)）。 |
| 晋级门槛（gate） | 挑战者要晋级必须通过的配对检验（[评估：晋级门槛](/arch/evaluation/gates/)）。 |
| CRN、配对（pairing） | 共同随机数（common random numbers）：冠军和挑战者打相同的种子，所以两者的差别噪声更小。 |
| SPRT | 序贯概率比检验（sequential probability ratio test）：只要证据在任一方向上足够强，就停止比较。 |
| Wilson 区间（Wilson interval） | 胜率的一种置信区间，在接近 0% 和 100% 时仍然合理。 |
| 种子集（seed sets） | 用于晋级和最终检验的固定种子列表，与训练种子分开（`eval/seeds/`）。 |

## 7. 名称

| 名称 | 是什么 |
|---|---|
| v9-1 | V，每个角色的那一个价值网络，两个冠军都打它（[宏观大脑：价值网络](/arch/macro-brain/network/)）。 |
| c9-1 | 战斗网络，每个角色的那一个，两个冠军都用它来打（[战斗网络](/arch/combat-brain/network/)）。 |
| 词元表（token table） | 一个网络里某一种 id（牌、遗物……）的列表，每个 id 有学到的行：这个游戏版本的每个 id；第 0 项 `<unk>` 读任何其他 id（[战斗网络 §2](/arch/combat-brain/network/#sec-2)）。 |
| `weights/all/NAME.json` | 一个网络的文件；冠军打的是 `v9-1.json` 和 `c9-1.json`（[学习：参考 §6](/arch/learning/reference/#sec-6)）。 |
| `promotion-1-100`、`promotion-1-200`、`promotion-1-300`、`final-1`、`a10-check-1` | `eval/seeds/` 里的种子集：100、200 和 300 个晋级种子（每个较长的都以较短的开头；`promotion-1` 和 `promotion-1-200` 是同样的 200 个），一个 300 个种子的最终集，在它上面的任何对局之前就已登记，以及 200 个用来测 A10 胜率的种子，不在任何训练数据里。 |
| `eval/champions/sl.json`、`nosl.json` | 冠军文件：让每种环境的冠军上场的选项，所有角色共用，以及它为每个角色存的报告。 |
| `eval/ledger.md` | 谱系，也是网络唯一的历史，所有角色共用：哪个大脑打出了哪些数据，哪些数据训练出了哪些权重。 |
| `data/silent/{sl,nosl}/…` | 数据目录里的自我对弈和评估文件夹，在存储主机上，不在 git 里。 |
| `tmp/build.sh REV`、`sim.sh` | 本地启动器，构建一个固定的提交并运行它（[模拟器：参考 §1](/arch/simulator/reference/#sec-1)）。 |
| `run`、`brain`、`serve`、`clones`、`gate`、`report`、`leaderboard` | SimWorker 命令（[模拟器：参考 §4](/arch/simulator/reference/#sec-4)）。 |
| `v.train`、`combat.train`、`gate.py` | 训练 V 和战斗网络的 Python，以及胜局门槛的报告和判定（[学习：参考 §9](/arch/learning/reference/#sec-9)）。 |
| `0SSL7NS01MU6` | 本书例子那一局的种子，在第 48 层赢下（[游戏 §1](/arch/game/#sec-1)）。 |
