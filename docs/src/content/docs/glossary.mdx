术语按领域分组。每个条目都链接到详细介绍它的页面。

## 游戏术语

| 术语 | 英文 | 含义 |
|---|---|---|
| 一局 | run | 从开局（Neow）到胜利或死亡的一次完整游玩。 |
| 幕、层数 | act, floor | 一局分为若干幕，每幕有自己的地图和 Boss。层数是总层数，与顶栏显示的一致。 |
| 地图点、`?` | map point | 幕地图上的一个点：战斗、精英、休息处、商店、宝箱、事件，或 `?`（进入前未知，到达时游戏才掷骰决定它是什么）。 |
| 遭遇、意图 | encounter, intent | 遭遇是一场战斗里的怪物组合。意图是怪物头上表示下一步打算的图标（攻击及伤害、格挡、增益……）。 |
| 抽牌堆 / 弃牌堆 / 消耗堆 | draw / discard / exhaust pile | 战斗中卡牌所在的位置。抽牌堆的顺序对玩家是隐藏的。 |
| 遗物、药水、能力 | relic, potion, power | 遗物是永久道具；药水是放在药水栏格子里的一次性道具；能力是生物身上持续的效果（如力量）。 |
| Ancient 事件（Neow） | Ancient | 提供若干恩赐供选择的特殊事件。每局都以 Neow 开始。 |
| 进阶等级（A0） | ascension | 难度等级；A0 是基础难度。 |
| Silent（静默猎手）、Ironclad（铁甲战士） | | 可玩角色。项目从 Silent 开始。 |
| 选牌提示 | card prompt | 游戏要求玩家选牌的时刻（弃牌、消耗、升级、变化……）。 |
| TestMode | | 游戏自带的测试开关。它会关掉表现层，但也会改变少数规则，模拟器用补丁把这些规则改回来（[模拟器 §1](/arch/simulator/#sec-1)）。 |

## 项目组件

| 术语 | 含义 |
|---|---|
| Protocol | 所有进程共享的通信类型。只有游戏 UI 显示的内容才能成为字段（[协议](/arch/protocol/)）。 |
| GameBridge | 唯一负责把游戏对象转成协议观测、把协议动作转成游戏调用的代码（[GameBridge](/arch/gamebridge/)）。 |
| Brain | 策略：战斗大脑和宏观大脑。只引用 Protocol，从不引用游戏。 |
| SimWorker | 以无头方式运行真实游戏 DLL 的进程，用于搜索世界和自我对弈（[模拟器](/arch/simulator/)）。 |
| Mod | 真实游戏里的轻量宿主：观测、提问、显示或执行（[Mod](/arch/mod/)）。 |
| Harness | 决策进程里的调度器：记录、路由、预算、日志（[Harness](/arch/harness/)）。 |
| RunSession | SimWorker 里的类，以无头方式经过所有决策界面跑完整局（[模拟器 §5](/arch/simulator/#sec-5)）。 |
| CombatBuilder | 根据一个观测构建模拟器里的战斗（[模拟器 §3](/arch/simulator/#sec-3)）。 |
| Pump | 单线程调度器，让游戏的所有异步代码都在同一个线程上运行，从而保证结果确定。 |
| 宿主（host） | 持有真实这一局的那一方：真实游戏里是 Mod，自我对弈时是一个 SimWorker。 |
| 无头（headless） | 只运行游戏逻辑，没有画面、窗口和输入。 |

## 环境与信息

| 术语 | 英文 | 含义 |
|---|---|---|
| NoSL | | 只用公开信息的环境（[环境 §1](/arch/environments/#sec-1)）。 |
| SL | | NoSL 加上当前节点内的真实结果，相当于允许在节点内存档读档。 |
| 节点 | node | 在 SL 中指一个地图点，从到达开始，到离开它的移动动作为止（[环境 §4](/arch/environments/#sec-4)）。不要与 Godot 的 UI 节点（`N*` 类）混淆。 |
| 公开历史、公开记录 | public history / record | 到目前为止屏幕上显示过的一切，加上能从中推断出的信息。Harness 把它保存为公开记录。 |
| 确定化 | determinization | 抽取一个与公开历史一致的具体隐藏状态（抽牌顺序、怪物动作、随机数流）。 |
| 世界 | world | 搜索可以探索的模拟器状态：NoSL 中是采样世界，SL 中是精确的节点克隆。 |
| 克隆、检查点、封存 | clone, checkpoint, seal | SL 的世界由节点入口处的检查点加上之后的动作构建。世界在节点出口处封存：之后的动作会抛异常。 |
| 视野边界 | horizon | 从 SL 世界内部看到的节点出口（`AtHorizon`）。 |
| 白名单 | whitelist | 观测字段只有在 UI 显示时才能存在的规则；每个字段都有测试。 |
| 公平规则 | fair play | AI 能看什么、能做什么的规则，汇总在本地笔记 `fair-play-spec.md` 里。 |

## 决策与搜索

| 术语 | 英文 | 含义 |
|---|---|---|
| 决策界面 | surface | 决策画面的种类（战斗、地图、奖励、商店……）。界面名称决定一个决策交给哪个大脑（[协议 §3](/arch/protocol/#sec-3)）。 |
| 决策点 | decision point | 游戏在等玩家操作、可以提出下一个决策的时刻。 |
| 观测 | observation | 玩家在决策点能看到的内容，用协议类型表示。 |
| 合法动作 | legal actions | 玩家此刻能做的所有动作，写成文本，如 `play:C:T` 或 `map:col,row`。 |
| uid | | 手牌中的卡牌或战斗中生物的稳定编号，动作用它来指明对象。 |
| 推荐、事实 | recommendation, fact | 大脑的回答：一个动作、背后的计划、比较过的候选，以及用来生成解释的事实（数字）。 |
| 兜底 | fallback | 没有大脑负责某个决策时随便选一个（比如随机）。禁止这样做：游戏改为暂停。 |
| 分支、推演 | branch, rollout | 分支是在某个世界里尝试的一条动作序列。推演是从那里用快速策略继续往下玩，以估计结果。 |
| 完美信息蒙特卡洛 | PIMC | 采样若干个确定化世界，在每个世界里假装一切已知去搜索，然后取平均（[NoSL PIMC §2](/arch/pimc/#sec-2)）。 |
| 策略融合 | strategy fusion | 在每个采样世界里各自挑最优路线的错误，好像玩家知道哪个世界是真的。按第一步动作取平均可以避免它。 |
| ISMCTS | | 信息集蒙特卡洛树搜索：如果 PIMC 残留的融合误差确实造成问题，就改用它。 |
| 分支定界 | branch-and-bound | 保留目前找到的最好路线，丢掉上界比不过它的分支；达到上界的路线就被证明是最优的。SL 战斗规划器用它来剪自己的束（[SL 规划器：束搜索 §2](/arch/sl-planner/beam/#sec-2)）。 |
| 束搜索 | beam search | 每一步只保留最好的 B 个状态，只展开它们。SL 规划器的一步是一个回合：它保留最好的 B 个回合结束状态（[SL 规划器：束搜索 §1](/arch/sl-planner/beam/#sec-1)）。 |
| 后状态 | afterstate | 刚做完选择、新的随机结果出现之前的状态。宏观大脑用后状态给选项估值（[宏观大脑：后状态 §1](/arch/macro-brain/afterstates/#sec-1)）。 |
| L0、L1 | | 宏观大脑的两个层级：L0 用 V 给每个后状态估值；L1 对难分高下的选择用成对推演复核。 |
| 预算 | budget | 一次决策能用多少搜索：固定的分支数（可复现）或墙钟时间（[Harness §5](/arch/harness/#sec-5)）。 |

## 学习

| 术语 | 英文 | 含义 |
|---|---|---|
| 价值函数 V、P(win) | value function | V(观测) = 从这里出发赢下这一局的估计概率。所有决策共用这一个尺度（[学习 §1](/arch/learning/#sec-1)）。 |
| 叶子估值 | leaf value | 在搜索停止的地方（例如回合结束）使用的 V。 |
| 自我对弈 | self-play | 当前冠军在模拟器里打完整局，产生训练数据。 |
| 冠军、挑战者 | champion, challenger | 冠军是当前最好的版本；挑战者必须通过晋级门槛才能取代它。 |
| MC、TD(λ) | | 设定价值目标的两种方法：用最终结果（蒙特卡洛），或与下一个状态的价值混合（时序差分）。 |
| ExIt | Expert Iteration | 专家迭代：把搜索结果当作训练标签，让价值函数学会搜索发现的东西。 |
| SPSA | | 同时扰动随机逼近：同时扰动许多参数，一次调好它们。 |
| 特权信息 | privileged information | 只在训练时使用、用来降低噪声的隐藏状态；永远不是部署后策略的输入（[学习 §4](/arch/learning/#sec-4)）。 |
| Boss 连战试点、门口状态 | boss gauntlet pilot, door state | 每场战斗一开始就判赢的对局（`run --auto-win`），所以很快就走到每个 Boss 的门口；门口状态是对局在那里的整套配置，由 SL 规划器去打，给 V 当作 Boss 分数的标签（[学习 §2](/arch/learning/#sec-2)）。 |
| 精英连战、进度 | elite gauntlet, progress | 2026-10-29 起 V 训练所用的玩法（`run --gauntlet`）：普通怪物战斗一开始就判赢，精英和 Boss 用这一局当时的生命去打，死了这一局就结束。进度是到达的层数，加上这一局死去的那场战斗里打掉的敌人生命比例（[学习 §2](/arch/learning/#sec-2)）。 |
| 均匀抽取、ε | even draws | 自我对弈里 V 用的探索（`run --explore ε`）：一个宏观决策以概率 ε 在它的选项中均匀抽取答案，不管 V 怎么说（[学习 §5](/arch/learning/#sec-5)）。 |

## 评估

| 术语 | 英文 | 含义 |
|---|---|---|
| R1–R4（仿真到实机阶梯） | sim-to-real ladder | 从纯模拟器对局（R1）到装了 Mod 的 Steam 游戏（R4）的四级阶梯，每级只多一个新变量（[评估 §1](/arch/evaluation/#sec-1)）。 |
| 排行榜 | leaderboard | 每种环境各自的成绩；NoSL 和 SL 从不混在一起（[评估 §2](/arch/evaluation/#sec-2)）。 |
| 晋级门槛 | gate | 挑战者要晋级必须通过的检验（[评估 §5](/arch/evaluation/#sec-5)）。 |
| 公共随机数 | CRN | 冠军和挑战者用相同的种子和随机数来打，两者的差别噪声更小。 |
| SPRT | | 序贯概率比检验：只要证据足够强（无论哪个方向）就停止比较。 |
| 种子集 | seed sets | 互不相交的训练、晋级、最终种子；最终种子在使用前登记（[评估 §4](/arch/evaluation/#sec-4)）。 |
