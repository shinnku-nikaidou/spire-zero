## 2. Main gaps and risks

1. **CombatBuilder approximations.** Turn history, internal counters, durations of cost modifiers and stun follow-ups are approximated, and the builder has never been checked against observations from the real game ([Simulator §3](/en/arch/simulator/#sec-3)).
2. **Monster move resampling** picks uniformly among moves that show the same intent. It needs a posterior built from the monster's history ([Harness §3](/en/arch/harness/#sec-3)).
3. **The card prompt context relies on Harmony prefixes over async entries:** inlining or a rejit can bypass them ([GameBridge §5](/en/arch/gamebridge/#sec-5), [Mod §10](/en/arch/mod/#sec-10)).
4. **Run start uses `UnlockState.all`,** not the user's profile, and ascension is not clamped to the character's maximum ([Simulator §5.1](/en/arch/simulator/#sec-5.1)).
5. **New game code that touches Godot nodes** without the TestMode guard, outside events (where the transpiler covers it), shows up only as game errors in `run` batches ([Simulator §5.2](/en/arch/simulator/#sec-5.2)).
6. **Harmony patches in the real game vs tiered JIT:** the runtime may recompile a method and silently drop a patch ([Mod §10](/en/arch/mod/#sec-10)).
7. **Combat brain v0 blind spots.** Card prompts are answered by a fixed rule (`p0`), both inside search and in the real combat, not searched; NoSL's search sees this turn only; SL's planner sees the whole combat but proves few of its plans; an unproved loss gets at most 3 plans in a row by default, the third played to its end, so a combat that only a later plan would win is lost ([Combat brain §3](/en/arch/combat-brain/#sec-3), [§7.1](/en/arch/combat-brain/#sec-7.1)); the leaf is hand-made and ignores most powers ([Combat brain §4](/en/arch/combat-brain/#sec-4)).

## 3. Implementation order

<Steps>

1. <Badge text="done 2026-10-26" variant="success" /> Run session with every surface headless, using a placeholder macro policy; coverage, determinism and cross-process map tests ([Simulator §5](/en/arch/simulator/#sec-5), [§9](/en/arch/simulator/#sec-9)).

2. <Badge text="done 2026-10-26" variant="success" /> Protocol run-level types and `ChoiceContext`; GameBridge observe and legal for every surface.

3. <Badge text="done 2026-10-26" variant="success" /> The combat world API in process, combat brain v0 (PIMC with a v0 leaf value) and the combat panel; v0 beats the placeholders on every pool ([Combat brain §7.1](/en/arch/combat-brain/#sec-7.1)).

4. <Badge text="done 2026-10-27" variant="success" /> Worker pool and IPC: PIMC's NoSL worlds are searched in worker processes beside the process that holds the run, and the combat brain plays the combats of whole runs ([Simulator §8](/en/arch/simulator/#sec-8), [Combat brain §7.2](/en/arch/combat-brain/#sec-7.2)).

5. <Badge text="done 2026-10-27" variant="success" /> Harness dispatch: routing, brain seeds and the decision log, for every run ([Harness §4](/en/arch/harness/#sec-4)–[§6](/en/arch/harness/#sec-6)). The public record comes with the first inference that needs it ([Harness §3](/en/arch/harness/#sec-3)).

6. Macro brain L0 and a v0 value function; R1/R2 full runs; the evaluation pipeline. L0 v0, V v0, R1 full runs and the pipeline are done, with the first reports in `eval/silent/reports/` ([Evaluation §6](/en/arch/evaluation/#sec-6)); R2 is left.

7. Mod: the executor and the auto-run driver, giving the R4 pipeline; the R3 ≡ R4 equivalence test. Loading, the brain link and the assist panel on every surface are done, in both environments, with the SL export and its round trip ([Mod §2](/en/arch/mod/#sec-2)–[§6](/en/arch/mod/#sec-6), [§12](/en/arch/mod/#sec-12)).

8. SL worlds in the worker pool, loaded from the clone; the SL leaderboard. The node checkpoint, the SL clone, its seal, SL worlds in runs and the SL planner, which plans whole combats on the clone in the worker pool, are done ([Simulator §7](/en/arch/simulator/#sec-7), [§8](/en/arch/simulator/#sec-8), [Combat brain §3](/en/arch/combat-brain/#sec-3)); the SL leaderboard is left.

9. The learning loop (fit V, ExIt, SPSA, gates), then the LLM patch loop. Fitting V from self-play, SPSA on V's and the leaf's weights, the full-run gate, with a champion file per environment, the elite and boss budget multiples ([Combat brain §5](/en/arch/combat-brain/#sec-5)), and the ExIt data in the decision log and run records ([Harness §6](/en/arch/harness/#sec-6)) are done ([Learning §2](/en/arch/learning/#sec-2), [Evaluation §5](/en/arch/evaluation/#sec-5)). So are V v2 (the macro V net) and its training, and exploration for self-play ([Learning §1](/en/arch/learning/#sec-1), [§2](/en/arch/learning/#sec-2)), moved ahead of the combat items because card picks were the weakest part. The combat outcome head is built too, as the combat net, PIMC's learned leaf, which reads the enemies' intents in the rounds so far ([Learning §1](/en/arch/learning/#sec-1)). The combat net's first generation passed the gate (c2, [Combat brain §7.2](/en/arch/combat-brain/#sec-7.2)), and self-play's second generation runs with it, exploring by value ([Learning §5](/en/arch/learning/#sec-5)). V v2's first promoted generation is n2-b0.03 ([Learning §2](/en/arch/learning/#sec-2)). Next, in order: the combat net's next generation (c4, trained on the second and third) through the gate; tuning K and nodes per world, and trying the multiples; the fusion panel's measurement over 300–500 decisions from self-play logs (the tool is built, [Combat brain §8](/en/arch/combat-brain/#sec-8)); sequential halving at the root ([Combat brain §5](/en/arch/combat-brain/#sec-5)); the prior net; then the closed loop with PCR and Reanalyse ([Learning §2](/en/arch/learning/#sec-2)). A shared tree, multi-turn search and the v2 encoder wait on what these measure.

</Steps>
