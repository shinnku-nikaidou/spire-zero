Assist mode shows the brain's answer and leaves every click to the player. Two more modes are planned: **auto-play**, where the mod plays the answer itself, and **semi-auto**, where it plays the next step when the player presses a key. Auto-play is how the real game would be evaluated: the last rung of the sim-to-real ladder, R4, plays whole runs in the real game with the same seeds as the simulator ([Evaluation §2](/en/arch/evaluation/#sec-2)). This page describes the planned parts, and then what is built and holds today: the logs, the safety rules, the patches and the tests.

None of §1–§2 is built: there is no executor, no adapter, no auto-run driver, and no key but F8.

## 1. Executor adapters <Badge text="planned" variant="caution" />

An adapter connects one surface's actions to the Godot nodes on screen. GameBridge never touches Godot nodes ([GameBridge §2](/en/arch/gamebridge/#sec-2)), so this node-side work lives in the mod. One interface would serve the planned highlights and auto-play: highlighting asks where an action is on screen, auto-play asks the adapter to perform it.

```csharp
// One adapter per surface; highlight and auto-play share the action → node mapping.
interface ISurfaceAdapter
{
    string Surface { get; }
    bool Matches();                       // current screen/room is this surface
    Control? AnchorFor(string action);    // node to highlight; null = panel only
    bool Execute(string action);          // same entry point a human click reaches
}
```

What `Execute` would call on each kind of surface:

| surface | `Execute` |
|---|---|
| combat | `CombatActions.Start` (GameBridge); ends the turn only if `CanTurnBeEnded` |
| buttons | the button's handler, but only after checking `IsEnabled && IsVisibleInTree()`. `ForceClick` checks neither <Badge text="verified" variant="success" /> |
| shop | `entry.OnTryPurchaseWrapper(inv)`. `ForceClick` on merchant nodes does nothing |
| map | `NMapScreen.OnMapPointSelectedLocally(point)` |
| card prompts | clicks the card holders, then confirm. This UI path keeps `PlayerChoice` in the replay record ([GameBridge: actions per surface §7](/en/arch/gamebridge/actions/#sec-7)) |

The step to play is the recommendation's `action`; its `plan` is what comes after it ([Protocol: the wire §7](/en/arch/protocol/wire/#sec-7)). After `Execute`, the mod would expect the observation's key to change within a timeout (10 s at game speed Fast, 3 s at Instant); if it does not, observe again, and after 3 failures in a row pause and log. If no adapter matches, or the screen is idle but has no legal action, auto-play would pause, the panel would say "manual needed", and the mod would log a coverage bug: never a random action.

Today the marks find their nodes themselves (`CombatMark`, `MapMark`), not through adapters ([Output §3](/en/arch/output/#sec-3)). For each surface, the mod's path and the simulator's are listed side by side in [GameBridge: actions per surface](/en/arch/gamebridge/actions/).

## 2. The auto-run driver <Badge text="planned" variant="caution" />

The driver would play whole runs by itself in the real game, for R4.

- **Seeded start:** `NGame.StartNewSingleplayerRun(character, shouldSave: false, acts, modifiers, seed, GameMode.Standard, ascensionLevel)` (`Nodes/NGame.cs:1137`), with the act selection the lobby would make ([Simulator: whole runs §2](/en/arch/simulator/runs/#sec-2)). The alternative is to set `NGame.DebugSeedOverride` before the Confirm button is pressed, as the game's own AutoSlayer does (`AutoSlay/AutoSlayer.cs:501`). With `shouldSave: false`, `current_run.save` stays untouched, as the parameter's doc says (`NGame.cs:1130`) <Badge text="verified" variant="success" />. Run history and progress are probably still written <Badge text="inferred" variant="caution" />, so auto-runs would use the modded profile only.
- **Run end:** detect death (all players dead) or the win; send `run_end`; return to the main menu; take the next seed from the pre-registered list.
- **Speed:** set `PrefsSave.FastMode` to Instant only while auto-run is active (`Saves/PrefsSave.cs:21`). Two game behaviors matter: builds outside the editor downgrade Instant to Fast at startup, and the preferences are saved on quit. So the user's own value is restored both when auto-run stops and when the game quits.
- **Abandon or crash:** the seed is recorded as `aborted`, with the reason. A seed is never run again to pick a better result.

## 3. Logs, and R3 = R4

**What the mod writes today.** Its lines go to the game's own log, so they land in the game's log file (on this machine `~/.local/share/SlayTheSpire2/logs/godot.log`, with dated copies of earlier sessions). Every line starts with `[Sts2Ai]`:

| level | lines |
|---|---|
| info | "assist mode, ENV, brain at PATH"; "environment ENV"; "connected to the brain"; "no brain: REASON" (once per distinct reason) |
| warning | "off: game V, the mod is for v0.111.0"; "brain: MESSAGE" (an `error`); "unexpected TYPE from the brain"; "a card prompt (TYPE) without its context, left to the player"; "SL record of node N broken after K steps: REASON"; the settings file's two warnings |
| error | a frame's exception, once per distinct text; "SL record: EXCEPTION"; "no AI settings tab: EXCEPTION" |

The only file it writes is its settings file ([The overview §5](/en/arch/mod/#sec-5)). It keeps no decision log of its own. A session in the real game is recorded on the brain's side instead: `brain --log FILE` writes Harness's decision log (each decision's observation, legal actions, pick, plan, candidates, environment and time, [Harness: the decision log](/en/arch/harness/decision-log/)), and `brain --wire FILE` every message the host sent, `hello` with its game version included. The 2026-10-28 capture is such a pair, kept locally in `tmp/assist/` ([The SL record §8](/en/arch/mod/sl-record/#sec-8)).

**Planned: the mod's decision log.** Per decision: the observation, the legal actions, the recommendation, the action played, the latency, the environment, the game's and the mod's versions, and `NumReloads`, which must be 0 ([Environments: information §8](/en/arch/environments/information/#sec-8)). Nothing reads `NumReloads` today.

**Planned: R3 = R4.** The same seed and the same decisions, played in the simulator (R3) and in the game (R4), must give the same observations; a difference is a bug in the bridge or the simulator, and the test would report the first one. What exists is narrower: `clones` checks that the node's clone asks what the game asked, decision by decision, for the SL record ([The SL record §8](/en/arch/mod/sl-record/#sec-8)).

## 4. Controls and safety

| control | state | effect |
|---|---|---|
| F8 | built | hides or shows the panel and every mark; works when the mod is off too |
| SL / NoSL switch | built | in the panel's head and the AI tab ([The overview §5](/en/arch/mod/#sec-5)) |
| AI tab | built | the mod's settings |
| F9 | planned | pause or resume auto-play |
| step mode | planned | one action per key press |
| Space (semi-auto) | planned | the marks show the plan; Space plays the next step |

**The rules**, which hold today and bind the planned modes:

- **The mod acts on nothing.** In assist mode it never starts a game action. Planned auto-play would play only actions from the decision's legal list. The brain's answer is checked against that list by Harness, which throws on an illegal one ([Harness: routing, budgets and seeds §6](/en/arch/harness/routing/#sec-6)).
- **No state edits, console, reloads or save writes.** The mod has no interface for any of them.
- **Single player only.** Assist turns itself off in a multiplayer run, and planned auto-play would refuse any multiplayer lobby.
- **What leaves the game.** The socket carries only protocol messages. The run id is the seed's hash, and the observation leaves out the seed (`RunView` has none), so in NoSL the seed never leaves the host. In SL it does: the node's checkpoint is the game's whole save, with the seed and every random stream's state, which SL may know ([The SL record §2](/en/arch/mod/sl-record/#sec-2)). NoSL never sends a checkpoint.
- **The game's settings screen** is the one place the mod changes the game's nodes: it adds its tab and panel, and moves the tab row half a step to keep it centred ([Output §2](/en/arch/output/#sec-2)). Everything else it draws lives in its own layer.

## 5. Patches and the JIT

A **Harmony patch** rewrites a game method at runtime: Harmony is a .NET library that lets a mod run its own code before the original method (a *prefix*), after it (a *postfix*), or around its exceptions (a *finalizer*). The mod subscribes to no game event: it polls each frame ([The main loop §1](/en/arch/mod/loop/#sec-1)) and patches where it must. All its patches share one Harmony id, `sts2ai.mod`, and are installed in `Host.Start`, in this order:

| patches | kind | for |
|---|---|---|
| `CardSelectCmd.From*`, the 15 public static overloads other than `FromChooseABundleScreen` | prefix and finalizer | each card prompt's context ([GameBridge: reading the game §6](/en/arch/gamebridge/observe/#sec-6)) |
| `SaveManager.SaveRun`, `RunManager.LoadIntoLatestMapCoord`, and the 12 entry points of the SL record | prefixes; 6 postfixes for the steps' tasks | the SL record ([The SL record §3](/en/arch/mod/sl-record/#sec-3)) |
| `NSettingsTabManager._Ready` | postfix | the AI tab, added at the next idle ([Output §2](/en/arch/output/#sec-2)) |

**Why first.** The context patches are installed before anything else compiles game code: a caller compiled before the patch can inline an entry and bypass it. This was seen headless, where SapphireSeed was inlined while another patch recompiled it.

**The JIT.** The game runs with .NET *tiered compilation*: a method is first compiled quickly, and frequently used methods are later compiled again with optimizations (a "rejit"). A rejit can drop a patch silently; this was seen headless after a few thousand combats, which is why the simulator turns tiering off ([Simulator: headless host §6](/en/arch/simulator/headless/#sec-6)). The mod cannot choose how the game is compiled. What it has:

- **Missing context is logged**: a prompt that arrives without its context is left to the player, with a warning in the game's log ([The main loop §5](/en/arch/mod/loop/#sec-5)). The panel shows no warning yet.
- **Planned: a heartbeat**, a counter each patch bumps, to see a patch go silent.
- **Planned: a launch flag**: launching the game with `DOTNET_TieredCompilation=0` <Badge text="inferred" variant="caution" />, if the game's hosted runtime honors it (open question 2, [§8](#sec-8)).

## 6. Prior art

STS2MCP (MIT license) is an existing mod that lets outside programs drive STS2 over HTTP.

**Copied:**

- the main-thread queue drained on `ProcessFrame` ([The main loop §1](/en/arch/mod/loop/#sec-1));
- its per-screen action code, as a reference.

**Avoided:**

- a raw `new PlayCardAction`: it skips `CanPlayTargeting` and the play effects;
- ending the turn directly;
- exposing the seed or the map's path;
- HTTP with CORS `*`: any web page could drive the game. The mod uses a Unix socket only.

## 7. Tests

The mod has no unit tests. What it shares with the simulator is tested there: GameBridge's observations and actions, and Protocol's messages ([Simulator: reference §7](/en/arch/simulator/reference/#sec-7)). The mod is in the solution, so a solution build compiles it, but nothing runs it. What is checked in the game:

| check | state |
|---|---|
| **SL round trip**: `brain --wire` and `clones` | built and run ([The SL record §8](/en/arch/mod/sl-record/#sec-8)) |
| **Load**: the mod initializes, the version guard works, the panel shows | by hand |
| **Surface coverage in the real game**: scripted R4 runs hit every surface, with no decision left to the player for lack of a reader | planned |
| **Idle**: no decision sent mid-animation; log decisions with the frame index, and check that none overlaps queued actions | planned |
| **Speed restore**: Instant or Fast put back on stop and on quit | planned, with the driver |
