A *value function* estimates how good a situation is. The macro brain uses one, V, to choose among the options of every decision outside combat: it plays each option, and V scores the situation right after it ([Macro brain: afterstates and one value function §1](/en/arch/macro-brain/afterstates/#sec-1)). This page defines V, says why its value has so far been a stand-in for the chance to win, and specifies every version the project has built or planned. How the current V's network computes, and how its labels and loss work, are explained step by step in the macro brain chapter ([Macro brain: the value network](/en/arch/macro-brain/network/), [Macro brain: from hazards to value](/en/arch/macro-brain/value/)); this page links there.

## 1. What V is

**V(s) = P(win this run from s, playing the current champion).** As a definition, V of a situation is the chance that the run is won from there if the *champion*, the best version of the AI accepted so far, plays the rest of it.

- **One scale.** Every value is a probability of the same event, so an HP heal at a rest site, a card at a reward and a path on the map are compared directly, with no exchange rate written by hand ([Macro brain: afterstates and one value function §2](/en/arch/macro-brain/afterstates/#sec-2)). The same unit would price how a combat ends ([The loop §10](/en/arch/learning/loop/#sec-10)).
- **Observation only.** V reads the run view, what the player sees outside combat ([Harness: the decision log §7](/en/arch/harness/decision-log/#sec-7)). Hidden state could help at training time only, as an extra input of a branch that is not deployed; that is planned ([The loop §12](/en/arch/learning/loop/#sec-12)).
- **One V for both environments.** An SL policy plays every later node better than a NoSL one, so from the same observation its true chance to win is higher; the shared V ignores that on purpose ([Environments: worlds and two combat algorithms §6](/en/arch/environments/worlds/#sec-6)). V is trained on SL runs, whose combats the SL planner plays; since 2026-10-30 both champion files name the same V, v6-3-2 (`eval/silent/champions/sl.json`, `nosl.json`).
- **Under a policy.** "Playing the current champion" matters: the same situation is worth more under a stronger player. A V learned from a weaker champion's runs values situations lower than the next champion will play them, which is one reason plan v6's third generation was trained on its own runs alone ([The experiment log §9](/en/arch/learning/experiments/#sec-9)).

**As built,** V's value is what its net file's `objective` says (`RunNet.Value`, `Brain/Macro/RunNet.cs:93-106`):

| objective | value | nets |
|---|---|---|
| `floor` | the expected floor reached | n1, n2-\*, n3-\*, pure-1, pure-1-b, pure-1-d, pure-1-g |
| `progress` | the expected floor plus the expected share of the enemies' HP taken where the run ends | v6-1, v6-2, v6-3-1, v6-3-2 |
| `win` | the chance to survive every floor, P(win) | none yet: plan v7's |

All three are read from the same head, one *hazard* per floor (the chance that the run ends on that floor if it is still going there); [Macro brain: from hazards to value §1](/en/arch/macro-brain/value/#sec-1) derives each. `RunNet` reads any objective other than `win` or `progress` as `floor` (`RunNet.cs:105`). V v0, which is not a net, returns a weighted sum in units of one HP ([§4](#sec-4)).

## 2. The value while no run wins

A target is only useful if it varies. While no run wins, every run's outcome is a loss, every label of P(win) is 0, and a V trained on them predicts 0 everywhere: it cannot tell a good option from a bad one. So V's value has been a *proxy*, a quantity that every run measures and that grows with the chance to win:

1. **The expected floor reached** (`floor`), from the first net on. Every run measures it, losses included, and the hazards over the floors give it a label at every floor ([Macro brain: from hazards to value §1](/en/arch/macro-brain/value/#sec-1)). Its flaw: it weighs every floor the same, so it can prefer a safe line that reliably reaches act 2 to a riskier one that sometimes wins. It is a stopgap.
2. **The expected progress** (`progress`), the elite gauntlet's (plan v6). Most gauntlet runs end at a boss, so the floor cannot tell a run that took 60% of a boss's HP from one that took 10%; the share of the enemies' HP taken in the fight the run ended in can ([§7](#sec-7)).
3. **P(win)** (`win`), plan v7's, once runs win now and then. With v6-3-2, whole SL runs win 23 of 300 (7.7%), so the condition holds, and plan v7 trains V on whole runs to decide by its chance to win ([§8](#sec-8)).

A proxy is never trusted by itself: a change is kept only if it wins the gate, which is measured on real outcomes ([The loop §8](/en/arch/learning/loop/#sec-8)). The gate itself moved with the objective: the floor (the simulator's SPRT), then the gauntlet's progress, now the runs won.

One side effect of how whole runs are labelled: a won run is labelled as surviving every floor up to 63 (`learn/v/net.py:97`), so a `floor` net trained on whole runs that win would value a won state's expected floor near 64, not the real last floor. No such net exists; plan v7's nets are `win` nets, whose value that label is made for.

## 3. The versions

| version | form | training | status |
|---|---|---|---|
| V v0 | 17 hand-written features times linear weights | weights set by hand; a ridge fit and SPSA were tried, none promoted | built (`RunValue`); NoSL champion's V until 2026-10-28 |
| V v1 | hand-written features and a small MLP | MC + TD(λ) | <Badge text="planned" variant="caution" /> never built |
| V v2 | a set encoder over the run's ids plus V v0's features and the card and relic numbers; one hazard per floor | MC on the floor reached, a second head, a pull towards V v0's choices; forks in the report | trainer removed (`9b9d170`); its nets load; n2-b0.03 was a champion's V 2026-10-28 to 2026-10-30 |
| pure V | V v2's encoder over ids and the raw state alone | MC on the floor reached, the second head, optional boss labels | built (`learn/v/`); pure-1-g was the SL champion's V 2026-10-29 to 2026-10-30 |
| the gauntlet's V | pure V with a share head; value: progress | MC on the elite gauntlet's runs | built (`v.train --gauntlet`); v6-3-2 is both champions' V |
| plan v7's V | pure V, value P(win); or the encoders' net | MC on whole runs, won runs survive every floor | built (`--objective win`, `--encoders`); no net trained yet |

The sections below take them in order. A *feature* is a number computed from the run by hand code (the HP, the mean damage of the cards); an *MLP* (multi-layer perceptron) is a small fully connected neural network; an *embedding* is a learned vector, one per id (card, relic, potion), so that a net can read any deck.

## 4. V v0: hand-written features

`RunValue` (`Brain/Macro/RunValue.cs`) is V v0: 17 features of the run view times linear weights, the macro brain's V when `run --value` names no file.

**The features** (`RunValue.Features`, `RunValue.cs:68-92`): the floor, HP, max HP, gold, the potions held, the relics, the cards in the deck, the unplayable cards, the upgraded cards; the mean damage (poison included), block and draw of the playable cards (from each card's numbers, `vars`); and the expected number of elites, rest sites, shops, treasures and `?` points from the current point (included) to the boss, if each step took a random path.

**The initial weights**, in units of one HP (`RunValue.cs:27-45`): HP 1, max HP 0.5, gold 0.1, potions 8, relics 8, cards −0.3, unplayable −15, upgrades 3, damage 3, block 2, draw 4, elites ahead −5, rest sites ahead 4, shops ahead 1, treasures ahead 6, `?` ahead 1. The floor has no initial weight: every option of a decision shares it, but a fit needs it, so that progress is not credited to what comes with it (relics, gold).

**Lexicographic intent.** The starting feature list came from bottled_ai, a prior-art Slay the Spire bot that ranks features in a strict order of importance: compare by the first, and use the next only to break ties ([Combat brain: the leaf §6](/en/arch/combat-brain/leaf/#sec-6)). Linear weights that start far apart reproduce such an order. V v0's weights are not far apart: run-level features trade against each other (a relic against HP), which a strict order cannot express. They were hypotheses for fitting and tuning to replace, and none were: a ridge fit of them to the floor reached explained no more than the floor alone ([The experiment log §2](/en/arch/learning/experiments/#sec-2)), and SPSA tuning was removed before it promoted any ([The loop §6](/en/arch/learning/loop/#sec-6)).

V v0's features are still written on every macro line of the decision log and into every afterstate, whatever V decides (`RunValue.cs:15-16`; [Harness: the decision log §7](/en/arch/harness/decision-log/#sec-7)); no champion has played V v0 since 2026-10-28. Its value is a logit-like score, not a probability: only its order within one decision matters to the macro brain.

## 5. V v1 and V v2

**V v1** <Badge text="planned" variant="caution" /> was to be V v0's features into a small MLP, trained on MC and TD(λ) targets. It was never built: V v2 replaced it in the plan.

**V v2** was trained by `learn/train_value.py`, removed in `9b9d170` (it stays in git's history). `RunNet` still reads its files (the code marked `OLD NETS`, [Reference §8](/en/arch/learning/reference/#sec-8)).

- **Its inputs.** Tokens of the run view, plus V v0's 17 features (n3-free-ctl: 9 of them, the floor, HP, max HP, gold and the map counts), standardized by the training data's mean and standard deviation. A card's vector is its id's vector, plus its upgrade level (at most 3) times its id's upgrade vector, plus its enchantment's and affliction's vectors. A small MLP (φ) maps each card, and the deck is the mean and the sum (× 1/16) of the results: a *set encoder*, which reads a deck of any size and ignores the order of its cards ([Macro brain: the value network §3](/en/arch/macro-brain/network/#sec-3)). Relics (a used-up one as an id of its own), potions and the context (character, act, boss or bosses, the act's ancient) are sums of their vectors. A card adds its numbers: its cost, its modifiers' amounts, its star cost and whether it costs X, and each of its numbers by name; a relic its counter, whether one shows, whether it is melted, and its status; the ascension joins as an extra number. V v2 has no map tokens: the map reaches it only through V v0's map counts.
- **Its head.** Two layers of 256, then one logit per floor, the hazard. Ids seen fewer than 3 times in training read as one unknown id. 229,216 weights (n1) to 236,576 (n3-ctl).
- **Its value**, `floor`: the start floor plus the chance to survive each floor from there.
- **Its training** fitted the hazards to the floor each run died on and a second head to the next combats' HP costs, as pure V's does ([§9](#sec-9)), and had two more terms:
  - **the pull** (`--afterstates FILES --kl-weight β`): V's softmax over each logged decision's options was pulled towards the policy that played the logs, the softmax of the logging V's values at the log's exploration temperature. This is a *conservative update*, as offline reinforcement learning uses with narrow data (BCQ, CQL, TD3+BC): it keeps V's best option near what the data covers. V's own softmax was at the temperature that matches the logs' policy (`--kl-temperature`, in floors, for V v0's logs; a V v2 log's own). The afterstates had to be valued by the V the log names; a pick the log says did not explore is within T / 100 of the best, so a warning named every brain for which more than 1% of those picks were not the afterstates' best: g1's and g2's were at 0.1% and 0%, g0's at 12%, since its observations had gained fields since;
  - **forks** (`--forks FILES`, `--fork-weight`, `--pair-weight`): each branch of a counterfactual pair as a sample, censored at the act's end if it lived, and the difference of the two branches' expected floors fitted to the pair's played difference ([The loop §10](/en/arch/learning/loop/#sec-10)). The promoted nets n2-b0.1 and n2-b0.03 had both weights at 0 (`fork_weight 0.0, pair_weight 0.0` in their files' `fit`): forks entered only their reports.

  Its other options and its report are in [Reference §9](/en/arch/learning/reference/#sec-9); its nets n1, n2 and n3 and what they measured are in [The experiment log §3](/en/arch/learning/experiments/#sec-3)–[§7](/en/arch/learning/experiments/#sec-7).

## 6. Pure V

Pure V (`learn/v/`, commits `d5e4fe1`, `59af0bf`, `4a0e215`) is V v2's net with only what the run is and its raw state as input. What matters in a card's or a relic's numbers, or in the deck as a whole, is the net's to learn; the project accepted that this might first play worse than a net helped by hand-written features ([The experiment log §8](/en/arch/learning/experiments/#sec-8)).

- **Inputs** ([Macro brain: the value network §1](/en/arch/macro-brain/network/#sec-1)): each card's id, upgrade level (at most 3) and its enchantment's and affliction's ids; each relic's id, with `:used` once used up; each potion's id; the context (the character, the act's id, the boss or bosses, the act's ancient); the map, each point still reachable from where the player stands as one token of its type and floors ahead (`Elite+3`, with `:quest` where a quest marks it; floors ahead are not capped in these tokens); and six numbers, the floor, HP, max HP, gold, the ascension and the potion slots, standardized by the training data's mean and standard deviation, each sample weighted by one over its run's decisions (a standard deviation under 10⁻⁹ reads as 1; `learn/v/train.py:276-280`). No V v0 feature and no card or relic number.
- **The net** ([Macro brain: the value network §2](/en/arch/macro-brain/network/#sec-2)): embeddings of 32, the cards through φ (32 → 128 → 128) and pooled as mean and sum × 1/16, the relic, potion, context and map bags summed, the six numbers; 390 inputs to a body of two layers of 256; a hazard head of 64 floors. 234,784 weights with pure-1's tables, 267,872 with v6-3-2's.
- **One specification.** `learn/v/encode.py` is the only definition of the inputs; `RunNet` (its `Tokens`, `MapTokens`, `Route` and the state) builds the same tensors, and each net file carries 8 held-out runs with the trainer's values, which `RunNet` checks on load ([Reference §8](/en/arch/learning/reference/#sec-8)).
- **Labels and training** ([Macro brain: from hazards to value §2](/en/arch/macro-brain/value/#sec-2)–[§4](/en/arch/macro-brain/value/#sec-4)): the floor reached as masked hazard labels (died, won or censored), every run weighing the same, every fifth run held out; the second head ([§9](#sec-9)); optionally the boss labels ([§10](#sec-10)). Nothing else enters the loss: no pull and no forks. The trainer's options and constants are in [Reference §9](/en/arch/learning/reference/#sec-9).

## 7. The gauntlet's V

`v.train --gauntlet` (commit `dd4b71e`) trains V for the elite gauntlet (plan v6, [Macro brain: self-play §1](/en/arch/macro-brain/selfplay/#sec-1)) on its runs alone. The net and inputs are pure V's, with a third head, the **share head**: per floor, the share of the enemies' HP taken in the combat the run ends in there (`learn/v/net.py:135-139`).

- **Its target is the run's progress** (`learn/v/data.py:79-82`): the floor reached, plus that share for a run lost in a combat (0 for one lost outside combat); a won run ends on its last floor with its last boss all taken, +1. Every ended run, won or lost, is labelled as ending on its last floor; the share head learns that floor's share by binary cross-entropy (`share_loss`, `learn/v/net.py:330-335`), and starts at the training runs' mean share.
- **Its value** is the progress expected: the expected floor plus, per floor, the chance to end there times its share (objective `progress`, which `RunNet.Value` computes the same way).
- **Why the share.** The bosses of acts 2 and 3 are seldom beaten in the gauntlet, so many runs end on the same floor; a run that took 60% of a boss's HP before it died did better than one that took 10%.
- **Its second head** learns the HP costs of the next six fought combats only (elites and bosses); the gauntlet's monster fights cost nothing.
- **Kept apart.** A whole run's V refuses gauntlet runs, and the gauntlet's V whole runs (`learn/v/data.py:101-104`); `--gauntlet` takes no boss labels, no afterstates and no `--objective`, and `--init` must name a `progress` net (`learn/v/train.py:213-232`). Its graph's one output, `hazards`, holds the 64 hazards and then the 64 shares.

v6-1, v6-2, v6-3-1 and v6-3-2 are gauntlet nets; v6-3-2 is the V of both champions since 2026-10-30, though in whole runs its `progress` decides as if monster fights were free ([Macro brain: weaknesses and next steps §1](/en/arch/macro-brain/next/#sec-1)).

## 8. Plan v7's V

Plan v7 (2026-10-30) trains V on whole runs again and decides by its chance to win. Two kinds of net are built and none is trained yet.

**V by its chance to win** (`v.train --objective win`, commit `7ce03bd`). The net and the loss are `floor`'s; only the file's objective changes, and with it what `RunNet.Value` returns. A won run is labelled as surviving every floor up to 63, so the chance to survive them all, $S_{63} = \prod_{g \ge f}(1 - h_g)$ from the current floor $f$, is P(win) (`learn/v/net.py:303-307`). Refused with `--gauntlet` and with boss sims, whose targets are floors (`learn/v/train.py:211-216`). The report's `explore_temperature` is then in P(win)'s units.

**The Brier score.** Whatever the objective, a whole run's report gives the held-out Brier score of the chance to win: the weighted mean of (predicted chance − won)² over the held-out decisions, each weighted by one over its run's decisions, against whether their run was won (`brier_held_out`), next to the same for the baseline's hazards, which know only the floor (`brier_held_out_floor_only`), and how many held-out runs won (`won_held_out_runs`; `learn/v/train.py:424-449`). It is the first check of P(win)'s calibration; a reliability plot is not built ([Reference §11](/en/arch/learning/reference/#sec-11)).

**Going on from the gauntlet's V.** `--init FILE` (commit `b4dabfa`; across objectives since `7ce03bd`) reads a net file's token tables, state scaling and weights back from its ONNX graph. A whole run's V may go on from any 64-floor net, a `progress` net's share head dropped: v7-1 is to go on from v6-3-2. The gauntlet's V cannot go on from a whole-run net; `--init` and `--encoders` must match; the state's names must match (`learn/v/train.py:220-228`, `learn/v/export.py:86-104`).

**The encoders' net** (`--encoders`, commit `b0ec4b7`, `net.EncoderNet`): the build encoder (cards, relics and potions as one set with kind vectors, two masked self-attention blocks) and the route encoder (the reachable map points as a graph, 16 rounds back from the boss) in place of the deck's set encoder and the relic, potion and map bags; the body, heads, labels and loss are pure V's. Refused with `--gauntlet`. Its architecture, sizes and cost are in [Macro brain: the value network §4](/en/arch/macro-brain/network/#sec-4). Its first net, v7-1e, is to be trained from scratch on generation 1, later ones going on from the previous encoders' net.

## 9. Heads

A *head* is one output layer of a network whose body is shared with the other outputs. A head that is never used to decide can still help: its targets shape the body that the deciding head reads.

**Built:**

- **The hazard head** (every net since V v2): one logit per floor, from which the value is read ([§1](#sec-1)).
- **The second head** (V v2 and pure V, training only): the share of max HP each of the run's next six combats cost (a death costs what was left; in the gauntlet the fought combats only), as 6 sigmoid outputs, plus a seventh for the boss score of the boss labels ([§10](#sec-10)); its squared error joins the loss at weight 3 (`learn/v/net.py:21-22`, `learn/v/train.py:72`). It is not in the net file. A combat's HP cost is measured several times a run, so it gives the body many more targets than the one outcome ([Macro brain: from hazards to value §3](/en/arch/macro-brain/value/#sec-3)).
- **The share head** (the gauntlet's V, [§7](#sec-7)).
- **The combat net's outcome head**: on a net of its own, a death or 50 buckets of HP still to be lost, and the potions still to be used ([Training the combat net §1](/en/arch/learning/combat-net/#sec-1)).

**Planned, not built** <Badge text="planned" variant="caution" />: a head for the distribution of the floor reached (the hazards already give it), a kill probability for each boss (the boss score comes closest), and for the combat head two other training targets: TD(λ) inside the fight, and a mix of the search's distribution with the outcome ([Training the combat net §7](/en/arch/learning/combat-net/#sec-7)).

## 10. Boss labels: boss sims and door states

Two kinds of simulated boss fight can join pure V's training as labels. Both are built (`learn/bosslab.py`, [Reference §9](/en/arch/learning/reference/#sec-9)); since plan v6 fights its elites and bosses in every run, neither is used, and plan v7's whole-run V refuses boss sims.

**Boss sims** (`v.train --boss-sims FILES --boss-afterstates FILES`; `bosslab.py tasks`, `play`, `collect`, commit `7b5ed23`). At a card reward, each option's afterstate (its deck, relics and potions) fights its act's boss a few times with the SL planner, at a fixed share of max HP about what runs enter that boss with (96% in act 1, 81% in act 2, 60% in act 3; `bosslab.py:39`), with the same seeds for every option of a decision, so that the options share their luck.

- The simulated fights' absolute odds are far from real play's: the planner plays at a low budget, the HP is fixed, and the deck is the one at the decision, not the one at the boss ([The experiment log §8](/en/arch/learning/experiments/#sec-8)). So the sims give no hazard label, and only the options' differences within a decision count (commit `a2071ca`).
- **The boss score** has one definition (`bosslab.py:378-383`): a win is 0.5 plus half the share of max HP left, a loss half the share of the boss's HP taken, so a win against a loss is about half a unit.
- **The fit.** Each option's fights have a mean boss score. V's expected floors less the decision's mean are fitted to the scores less the decision's mean, times $2k$ floors per unit of score, where $k$, one per act, is what beating that act's boss is worth in the training runs: the mean floor reached by the runs that beat it, less the boss floor (`boss_worth`, `learn/v/data.py:149-156`). The squared error is in units of the targets' mean square, a decision's options weighing one decision together; the score is also the second head's seventh target.
- **The report** adds `boss_worth`, the held-out loss on the sims (`held_out_boss_loss`), how often V's best option is the sims' best on held-out decisions with one best (`boss_agree`), and the correlation of V's centred values with the targets (`boss_corr`).

**Door states** (`v.train --boss-states FILES`; `bosslab.py doors` and `states`, commits `bba40ed`, `e044abd`). A run's whole loadout at an act boss's door (its last decision of the act before the boss fight) fights the boss at the HP it entered with and at shares of max HP (0.4, 0.7 and 1 by default). The second head learns their boss scores, in units of the scores' variance, a door's HP levels weighing one door together; this shapes the body only. The report adds, per act, the correlation of the sims' scores with the second head's and with V's chance to live through the boss floor (`door_corr`).

- `doors` writes boss-sim tasks where each card-reward option fights at the boss's door instead: the run's loadout before its boss fight, at the HP it entered with, the decision's pick swapped for the option.
- Door states came mostly from the **boss gauntlet pilot** (`run --auto-win`, [Simulator: whole runs §7](/en/arch/simulator/runs/#sec-7)): every combat is won at its start, so a run reaches each act's boss door in about a second, its picks free to explore; only the bosses are fought, by `bosslab.py states`. The pilot's runs are labels only: their records never count as runs (`v.train` refuses `auto_win` records, `learn/v/data.py:99-100`), and `--door-logs FILES` reads their decision logs only as the views of their door states (commit `f91307b`).
- `bosslab.py compare` says how often the option V valued best is the fights' best. It scores each fight against the HP it started with, which keeps the order of a decision's options since they all start with the same HP.

The boss labels' budget is the SL planner's low effort from before `c8d45b3` (`--effort low --nodes 150 --beam 4 --easy-beam 0 --loss-plans 0 --replan 0`), about 9 s a fight; it later became plan v6's and v7's self-play budget ([The SL planner: budget, cost and results §2](/en/arch/sl-planner/budget/#sec-2)).

## 11. `ranks`: V's card sense

`ranks --logs LOGS [--value FILE] [--per-act 200] [--top 30]` (`SimWorker/Commands/EvalCommands.cs:175-232`) reads a V's taste in cards: per act, each card's mean change of V when one more copy of it joins the decks of a sample of the logs' card rewards (200 per act by default), the top 30 shown. A card is added unupgraded, and only cards some deck held are ranked. What a card is worth depends on the deck, so this is a mean for reading, not a test. With no `--value` it reads V v0. V v0 ranks GRAND_FINALE first by far (its damage is large, and it can only be played once the draw pile is empty) and powers such as FOOTWORK near zero, since they carry no damage, block or draw. V v2's n1 put the poison cards first in act 0 ([The experiment log §3](/en/arch/learning/experiments/#sec-3)).
