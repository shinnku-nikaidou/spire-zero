The combat brain answers two kinds of question during a fight: (a) on the player's turn, what to do next (a card and its target, a potion, or end turn); (b) the prompts that come up during play (discard, exhaust, choose, …). It runs in the decision process; [Harness](/en/arch/harness/) calls it with a set of worlds and a budget. The search code is the same in both environments; only the worlds it is given differ ([Environments §5](/en/arch/environments/#sec-5)).

<Aside title="Status">

v0 exists (`src/Sts2Ai.Brain/CombatBrain.cs`, `LeafValue.cs`): PIMC over K worlds with a search over this turn ([§2](#sec-2)), the same search on the one SL world ([§3](#sec-3)), a hand-made leaf value ([§4](#sec-4)) and the fixed combat panel with its results ([§7](#sec-7)). Not built yet: card prompts as search branches, search past this turn, CI-based allocation and `Facts`. The placeholders stay, for bench and as the panel's baselines: `PlayPolicy` (plays a random playable card) and `RandomPolicy` (uniform over the legal actions).

</Aside>

## 1. Problem shape

- A turn is a sequence of actions that ends with `end_turn`. Uncertainty inside a turn comes from draws and from random generation. The enemy turn is deterministic once the monsters' moves are fixed.
- Branching: a hand of 5–10 cards, targeted cards times the number of enemies, plus potions; a sequence is 3–8 actions long. That gives up to 10⁴ sequences per turn, with many **transpositions**: different action orders that reach the same state (A then B gives the same state as B then A).
- Horizon: a combat lasts 3–15 turns. Searching only one turn is greedy: it sees nothing past the turn. Searching the whole combat is expensive, because in NoSL it crosses many chance nodes (points where the game resolves something random, so the search has to branch over the outcomes). So the search is cut at the end of the turn, and the state there is scored by a leaf value in P(win run) units ([§4](#sec-4)).
- Cost ([Simulator §4](/en/arch/simulator/#sec-4)): a restore takes 0.28 ms plus 0.073 ms per replayed action; a branch takes about 2.8 ms (median), about 330 per second per core; 8 workers give about 6.8 times that.

## 2. NoSL: PIMC

In NoSL the AI does not know the hidden state (draw order, monster moves). The design handles this with **PIMC** (perfect-information Monte Carlo): draw K determinized worlds, i.e. complete hidden states that agree with the public record; search each one as an ordinary game with nothing hidden; and average the results. The answer is an expectation over the worlds.

PIMC has one known weakness, **strategy fusion**: inside one world the search knows that world's future, so if it may choose a different line in each world, the plan acts as if it already knew which world is the real one. The alternative that avoids this is **ISMCTS** (information-set Monte Carlo tree search). It builds one search tree over information sets (groups of states the player cannot tell apart) and samples a different world on each pass, so no choice in the tree can depend on hidden information. The design starts with PIMC and keeps fusion small: it aggregates over the first action only and re-plans after every action (step 3). ISMCTS is held in reserve in case fusion is measured to be a problem (open question 2, [§8](#sec-8)).

<Steps>

1. **Worlds.** Harness supplies K worlds: start with 8, and add more when the top two candidates are within their confidence intervals (v0: a fixed K, 8 by default). Each world has a different draw order, different random streams and different monster moves, all consistent with the public record.
2. **Search inside the turn.** Depth-first search (DFS: follow one action sequence to its end, then back up and try the next) over action sequences. At every node of the search, ending the turn is one of the options, an idea from bottled_ai, a prior-art project this design learned from. Within a world, states are deduplicated by a canonical observation hash, so each transposition is expanded once (v0: the hash of the observation's JSON).
3. **Aggregate by first action.** In each world, take the best value reachable after the first action; then take the mean over the K worlds. Never take the max across worlds: that is strategy fusion. Execute the first action only, observe again, and plan again.
   - Residual fusion: after the first action, each world's plan is still clairvoyant, so lines like "play X, then see what's drawn" are overvalued. If this is measured to be a problem, switch to ISMCTS.
4. **Enemy turn.** The enemy turn is simulated for real, with the world's sampled monster moves. The leaf is taken at the start of the next player turn, so the value sees the state after the enemies have acted. A line also ends when the combat does.
5. **More turns** (planned) when the budget allows: expand the top first actions one more turn, with a cheap policy or with beam search for turn 2 (beam search: at each step keep only the B best states and expand only those).

</Steps>

Two more rules:

6. Potions are ordinary actions. Their timing is not hard-coded.
7. Prompts: inside search, the simulator's selector (the code that answers card prompts) is driven by the search, so each option is a branch. A lone prompt in the real game is handled by evaluating each option with the same search (this needs `ChoiceContext`, [Protocol §4](/en/arch/protocol/#sec-4)). v0 does neither yet: a prompt inside a world is answered at random from the world's seed, and the panel answers real prompts at random for every player.

## 3. SL: deterministic planning

In SL there is one exact world and no chance nodes, so combat becomes deterministic planning on that one world. v0 runs the search of [§2](#sec-2) on that world, so it plans this turn only; items 2 and 5 below are planned. With a one-turn horizon SL plays no better than NoSL on the panel ([§7](#sec-7)): knowing the future helps only a search that looks past the turn.

1. Inside a turn: the same enumeration, but with 1 world, so deduplication works better.
2. Across turns: beam search, one step per turn (keep the top B end-of-turn states), until the combat ends or the budget runs out. After a win the node goes on (rewards), so the search may continue to the node exit (open question 1 in [Environments §10](/en/arch/environments/#sec-10)).
3. RNG manipulation comes for free: different action orders consume the random streams differently, and the search sees the results.
4. Leaf: V_SL(obs) at the end of the combat or at the node exit; at the end of the turn if the budget runs out.
5. The world is sealed at the node exit (`AtHorizon`).

## 4. Leaf value

The leaf value scores a state where the search stops. It uses one scale: the estimated probability of winning the run, P(win run) ([Learning](/en/arch/learning/)).

- The input is the observation only, in both environments, so it cannot leak hidden state.
- v0 (built, `LeafValue`) projects the rest of the fight from the observation:
  - A lost combat is 0. A won combat scores `WinBase + PerHp × (HP / max HP)`, plus `PerPotion` for each potion still held.
  - Mid-combat, each enemy alive gets an effective HP (HP + block − `PoisonShare` × the poison's remaining damage n + (n−1) + … + 1) and a damage rate (its shown attack this turn, damage × hits, at least `MinIncoming`). The player deals `Dps` + 2 × Strength per turn and kills the enemies one after another, the highest rate per HP first. That is Smith's rule, the order that minimizes the total of (rate × time until dead). Each enemy hits until it dies; `Unblocked` of the damage beyond the player's current block is taken off the HP, and the HP left is scored like a win.
  - So damage is worth more on an enemy that hits hard and dies soon, overkill is worth nothing, and a mid-combat state never beats the win it could reach at the same HP.
  - A projected death (HP share below 0) decays toward 0 exponentially, with the same slope at 0, so it stays above a loss and still orders lines. A flat floor made every losing line look the same, and the brain then ended its turns early.
  - The weights are hand-set (`LeafWeights`: WinBase 0.2, PerHp 0.6, PerPotion 0.02, Dps 10, Unblocked 0.5, MinIncoming 3, PoisonShare 0.8). Blind spots: powers other than poison on enemies and Strength on the player, the draw pile, and intents after this turn.
- Next: hand-made features times linear weights. The feature list is seeded from bottled_ai's 42 features (player HP, block, enemy HP, powers, draw-pile quality, turns to kill, …). bottled_ai compares them in lexicographic order (the first feature decides, the next one only breaks ties); that order becomes linear weights spaced far apart, which are then tuned by SPSA (simultaneous perturbation stochastic approximation: tunes all weights at once from noisy results by perturbing them together). It must value block, overkill and lethal next turn without saturating.
- Later: a small neural net on the encoded observation. Its head predicts the end-of-combat HP distribution plus a death class (an idea from r33hab, another prior-art project this design learned from), and this is mapped to P(win). The training target is a λ-mix: 0.3 × search value + 0.7 × outcome ([Learning §2](/en/arch/learning/#sec-2)).
- The mid-combat leaf (at turn end) and the post-combat leaf (combat won, before rewards) are the same function; in the post-combat case the combat part is empty.

## 5. Budget and pruning

The levers below keep the search inside its budget. The one that decides when to stop is **CI-based allocation**: each first action's value is a mean over worlds, with a confidence interval (CI), a range that very likely contains the true mean. Once the two best first actions are clearly apart, more samples will not change the choice, so the search stops; otherwise it spends more worlds on those two.

| lever | effect | v0 |
|---|---|---|
| canonical obs-hash dedup | each distinct observation is expanded once per world | yes |
| move ordering + early stop | expand high-prior actions first (a heuristic first, a policy net later) | end turn first, then cards in hand order, then potions; stop when the share is spent |
| CI-based allocation over first actions | stop when the top two are separated; otherwise give them more worlds | no: every first action gets every world |
| trivial decisions | one legal action, or all sequences equivalent → no search | one legal action |
| restore cost | DFS order reuses prefixes and restores only on backtrack; deep copy later ([Simulator §4](/en/arch/simulator/#sec-4)) | yes |

v0's budget is `Budget(Worlds, NodesPerWorld)`, 8 × 300 by default; a node is one executed action. In each world the nodes are split evenly over the first actions, so each gets a fair look. Inside a subtree, once its share is spent, the search stops expanding and the state there is scored as ending the turn, which is the option tried first. On one core this costs about 0.55–0.75 s per action in NoSL and 0.13–0.19 s in SL (one world). In NoSL the worlds are independent, so the worker pool searches one world per worker ([Simulator §8](/en/arch/simulator/#sec-8)): with 8 workers an action takes about 70 ms, with the same result.

Rough numbers: 1–2 s per decision times 8 workers gives about 5,000 branches. With K=16 that is about 300 branches per world, enough for a deduplicated enumeration inside one turn.

## 6. Interface

```csharp
public sealed record Budget(int Worlds = 8, int NodesPerWorld = 300);

public interface ICombatBrain
{
    // Player's turn: search the worlds, return the first action and the rest of the plan.
    CombatDecisionResult Decide(CombatObservation observation, IReadOnlyList<CombatAction> legal,
                                IWorldSource worlds, Budget budget, ulong seed);
}

public sealed record CombatDecisionResult(
    CombatAction First,                    // one of legal
    IReadOnlyList<CombatAction> Plan,      // rest of this turn in the first world (narration, highlight)
    IReadOnlyList<Candidate> Candidates);  // every first action, best first
```

`PimcBrain` implements it. Planned: `Choose(request, worlds, budget)` for a prompt during play (chosen canonical indexes plus a value per option), and `Facts` on the result (expected HP loss, turns to kill, P(draw X), …).

- `Facts` will be the only source of narration ([Output §5](/en/arch/output/#sec-5)). NoSL facts are probabilities and expectations; SL facts may be exact.
- `ICombatPolicy` / `IChoicePolicy` stay, for the placeholders and for rollout policies (fast policies that play a line out inside search).

## 7. Tests

1. Tactics suite: positions cut from simulated games that have clear answers (take lethal, exact block, apply vulnerable before attacking); record found / not found.
2. Fixed combat panel (encounter, deck, seed) with CRN (common random numbers: every version plays the same random draws, so differences come from the brain, not from luck): mean HP loss and death rate. First beat the placeholders; version gates as in [Evaluation §5](/en/arch/evaluation/#sec-5). Built: `panel` ([§7.1](#sec-7.1)).
3. NoSL counterfactual: same record, different hidden state → same recommendation (fixed brain seed).
4. SL seal: any execute past the node exit throws.
5. Reproducible with a fixed branch budget. Holds: two panel runs give the same moves and results.

### 7.1 Panel results

Silent with the starter deck and full HP, one combat per seed, each encounter of the pool in turn. The same combats for every player. Prompts in the real combat are answered at random for every player. Brain budget 8 worlds × 300 nodes.

```bash
Sts2Ai.SimWorker panel --n 60 --player pimc --env NoSL --act 0 --rooms weak,regular
```

| pool | combats | `random` | `play` | PIMC NoSL | PIMC SL |
|---|---|---|---|---|---|
| act 1 (`--act 0`) weak + regular | 60 | 40.0% (42.5) | 85.0% (29.5) | 100% (15.4) | 100% (16.2) |
| act 1 (`--act 0`) elites | 30 | – | 16.7% (33.2) | 36.7% (43.7) | 40.0% (45.5) |
| act 2 (`--act 1`) weak + regular | 30 | – | 16.7% (35.0) | 50.0% (38.3) | 46.7% (35.9) |

Each cell is the win rate, with the mean HP lost per win in brackets. HP lost is comparable only between players with similar win rates: a player that wins harder fights loses more HP in them. Time per combat on one core: about 0.2–0.4 s for the placeholders, 17–28 s for PIMC NoSL and 4–7 s for PIMC SL. Game errors and failures: 0.

### 7.2 Whole runs

The brain also plays the combats of whole runs: `run --policy pimc` ([Simulator §5](/en/arch/simulator/#sec-5)) keeps the run live in the host and searches each combat decision in the worker pool ([Simulator §8](/en/arch/simulator/#sec-8)). Every out-of-combat decision is random (map, rewards, card rewards, events, shop, rest), and so are the card prompts, for both players. Silent A0, seeds 0–23, budget 8 × 300.

```bash
Sts2Ai.SimWorker run --n 24 --policy pimc
```

| combat policy | runs | mean floor | median | reached the act 1 boss (floor 17) | won |
|---|---|---|---|---|---|
| `play` | 24 | 8.6 | 7.5 | 1 | 0 |
| PIMC NoSL | 24 | 12.7 | 12.5 | 8 | 0 |

Every run ends in act 1, most often at an elite or at the boss, so the random macro decisions now limit the result: the deck never grows into one that can win act 1. PIMC took about 17.5 s per run (two runs at a time, 8 workers each). `--check` on one seed gives the same run twice, and the batches had 0 game errors and 0 worker restarts.
