The combat brain answers two kinds of question during a fight: (a) on the player's turn, what to do next (a card and its target, a potion, or end turn); (b) the prompts that come up during play (discard, exhaust, choose, …). It runs in the decision process; [Harness](/en/arch/harness/) calls it with a set of worlds and a budget. The two environments pose different problems, so they get different algorithms behind one interface: NoSL averages over sampled worlds ([§2](#sec-2)), SL plans on one exact world ([§3](#sec-3)). Harness picks the brain by environment ([Environments §5](/en/arch/environments/#sec-5)).

<Aside title="Status">

v0 exists (`src/Sts2Ai.Brain/CombatBrain.cs`, `LeafValue.cs`): PIMC over K worlds with a search over this turn ([§2](#sec-2)), a hand-made leaf value ([§4](#sec-4)), a fixed rule for card prompts (`p0`, [§2](#sec-2), rule 7) and the fixed combat panel with its results ([§7](#sec-7)). Until the SL planner exists, SL runs the same PIMC search on its one world ([§3](#sec-3)). Not built yet: the SL planner, card prompts as search branches, search past this turn, CI-based allocation and `Facts`. The placeholders stay, for bench and as the panel's baselines: `PlayPolicy` (plays a random playable card) and `RandomPolicy` (uniform over the legal actions).

</Aside>

## 1. Problem shape

- A turn is a sequence of actions that ends with `end_turn`. Uncertainty inside a turn comes from draws and from random generation. The enemy turn is deterministic once the monsters' moves are fixed.
- Branching: a hand of 5–10 cards, targeted cards times the number of enemies, plus potions; a sequence is 3–8 actions long. That gives up to 10⁴ sequences per turn, with many **transpositions**: different action orders that reach the same state (A then B gives the same state as B then A).
- Horizon: a combat lasts 3–15 turns. Searching only one turn is greedy: it sees nothing past the turn. Searching the whole combat is expensive, because in NoSL it crosses many chance nodes (points where the game resolves something random, so the search has to branch over the outcomes). So the search is cut at the end of the turn, and the state there is scored by a leaf value in P(win run) units ([§4](#sec-4)).
- Cost ([Simulator §4](/en/arch/simulator/#sec-4)): a restore takes 0.28 ms plus 0.073 ms per replayed action; a branch takes about 2.8 ms (median), about 330 per second per core; 8 workers give about 6.8 times that.

## 2. NoSL: PIMC

In NoSL the AI does not know the hidden state (draw order, monster moves). The design handles this with **PIMC** (perfect-information Monte Carlo): draw K determinized worlds, i.e. complete hidden states that agree with the public record; search each one as an ordinary game with nothing hidden; and average the results. The answer is an expectation over the worlds.

PIMC has one known weakness, **strategy fusion**: inside one world the search knows that world's future, so if it may choose a different line in each world, the plan acts as if it already knew which world is the real one. The alternative that avoids this is **ISMCTS** (information-set Monte Carlo tree search). It builds one search tree over information sets (groups of states the player cannot tell apart) and samples a different world on each pass, so no choice in the tree can depend on hidden information. The design starts with PIMC and keeps fusion small: it aggregates over the first action only and re-plans after every action (step 3). ISMCTS is held in reserve in case fusion is measured to be a problem (open question 2, [§8](#sec-8)).

<Steps>

1. **Worlds.** Harness supplies K worlds: start with 8, and add more when the top two candidates are within their confidence intervals (v0: a fixed K, 8 by default). Each world has a different draw order, different random streams and different monster moves, all consistent with the public record.
2. **Search inside the turn.** Depth-first search (DFS: follow one action sequence to its end, then back up and try the next) over action sequences. At every node of the search, ending the turn is one of the options, an idea from bottled_ai, a prior-art project this design learned from. Within a world, states are deduplicated by a canonical observation hash, so each transposition is expanded once (v0: the hash of the observation's JSON).
3. **Aggregate by first action.** In each world, take the best value reachable after the first action; then take the mean over the K worlds. Never take the max across worlds: that is strategy fusion. Execute the first action only, observe again, and plan again.
   - Residual fusion: after the first action, each world's plan is still clairvoyant, so lines like "play X, then see what's drawn" are overvalued. If this is measured to be a problem, switch to ISMCTS.
4. **Enemy turn.** The enemy turn is simulated for real, with the world's sampled monster moves. The leaf is taken at the start of the next player turn, so the value sees the state after the enemies have acted. A line also ends when the combat does.
5. **More turns** (planned) when the budget allows: expand the top first actions one more turn, with a cheap policy or with beam search for turn 2 (beam search: at each step keep only the B best states and expand only those).

</Steps>

Two more rules:

6. Potions are ordinary actions. Their timing is not hard-coded.
7. Prompts: inside search, the simulator's selector (the code that answers card prompts) is driven by the search, so each option is a branch. A lone prompt in the real game is handled by evaluating each option with the same search (this needs `ChoiceContext`, [Protocol §4](/en/arch/protocol/#sec-4)). v0 does neither yet. Every card prompt in a combat, in the real combat and inside a world, goes to `PromptBrain` (`p0`, in Brain), a fixed rule by what happens to the picked cards:
   - Picks that leave the hand this turn (a discard, an exhaust, a card put on top of the draw pile) are the least useful cards, Sly cards first in a discard, since discarding plays them. Past its minimum such a prompt takes only the cards better gone: unplayable ones, and Sly ones in a discard.
   - A prompt that makes a card free takes the dearest one.
   - Any other prompt adds or improves cards (a card into the hand, a copy, an upgrade), so it takes the most useful ones, as many as it may.

   A card's use is its numbers summed (damage, block, poison, draw, energy, Weak and Vulnerable, upgrades) plus a flat part; an unplayable card has none. `p0` reads the prompt alone and never draws at random, so a world answers as the run will.

## 3. SL: deterministic planning

In SL the combat brain gets one exact world, the node clone. The clone holds every random stream, so the same action sequence always gives the same outcome. There is no hidden state and no chance node, so the combat is a deterministic planning problem. That is a different problem from NoSL's, and it gets its own algorithm, the **SL planner** (planned): a second implementation of `ICombatBrain` ([§6](#sec-6)).

**What optimal means.** With one world, taking the best line is correct: strategy fusion needs several worlds to fuse, so knowing the future is not an error here. A combat has finitely many lines, so a best line exists and exhaustive search finds it. It is best with respect to V at the end of the combat (or at the node exit): once the search reaches the end, the fight itself holds no estimate, and the only error left is in V of the end state (HP, potions, max HP, gold, …).

**How hard it is.** In general, with hand, energy and turns unbounded, the problem is NP-hard: choosing a turn's cards under an energy limit already contains a knapsack problem. The real instances are bounded (a hand of at most 10 cards, 3–15 turns) but large: up to 10⁴ sequences per turn ([§1](#sec-1)), over many turns. So the planner aims at the optimum and proves it when it can, but does not need it.

<Steps>

1. **Search the whole combat.** Depth-first branch-and-bound over the actions of every turn until the combat ends; card prompts are branches too. **Branch-and-bound** keeps the best line found so far and drops every branch whose upper bound cannot beat it.
2. **Bound.** A branch's upper bound is the best end it could still reach: a win at its current HP (plus what the fight can still add, such as healing) with every potion it still holds. Once the best line found reaches the root's bound, it is proved optimal and the search stops. In easy hallway fights a win with no HP lost is often found early.
3. **Anytime.** For long fights (elites, bosses) a beam search gives a good first line quickly: one step per turn, keeping the top B end-of-turn states. Branch-and-bound then improves it until the budget runs out. The result says either "proved optimal" or "best found, at most Δ below the bound".
4. **Key by full state.** Two action orders can reach the same observation with the random streams in different states (after a reshuffle, a random target or a generated card), and then they draw different futures. That is the RNG manipulation SL allows, and the search sees it for free. So transpositions are keyed by the full state, random streams included, not by the observation as in NoSL. Only the SL world offers this key: a NoSL world that offered it would leak hidden state.
5. **Plan once.** The world is exact, so the plan for the whole combat is computed once and then played as computed. A real outcome that differs from the plan means the clone is wrong ([§7](#sec-7)).
6. **Past the combat.** After a win the node goes on (rewards), so the search may continue to the node exit (open question 1 in [Environments §10](/en/arch/environments/#sec-10)). The leaf is V(obs) at the end of the combat or at the node exit, the same V as in NoSL and in the macro brain ([§4](#sec-4)).
7. **Workers.** There is only one world, so the worker pool splits the tree by action prefix instead of by world, and the workers share the best value found so far for pruning.
8. **Seal.** The world is sealed at the node exit (`AtHorizon`).

</Steps>

v0 has no planner yet: SL runs the PIMC search of [§2](#sec-2) on its one world, so it plans this turn only. With a one-turn horizon SL plays no better than NoSL on the panel ([§7](#sec-7)): knowing the future helps only a search that looks past the turn.

## 4. Leaf value

The leaf value scores a state where the search stops. It uses one scale: the estimated probability of winning the run, P(win run) ([Learning](/en/arch/learning/)).

- The input is the observation only, in both environments, so it cannot leak hidden state.
- It is one function for both environments, shared with the macro brain ([Learning §1](/en/arch/learning/#sec-1)). NoSL uses it at the end of the turn; SL mostly at the end of the combat ([§3](#sec-3)).
- v0 (built, `LeafValue`) projects the rest of the fight from the observation:
  - A lost combat is 0. A won combat scores `WinBase + PerHp × (HP / max HP)`, plus `PerPotion` for each potion still held.
  - Mid-combat, each enemy alive gets an effective HP (HP + block − `PoisonShare` × the poison's remaining damage n + (n−1) + … + 1) and a damage rate (its shown attack this turn, damage × hits, at least `MinIncoming`). The player deals `Dps` + 2 × Strength per turn and kills the enemies one after another, the highest rate per HP first. That is Smith's rule, the order that minimizes the total of (rate × time until dead). Each enemy hits until it dies; `Unblocked` of the damage beyond the player's current block is taken off the HP, and the HP left is scored like a win.
  - So damage is worth more on an enemy that hits hard and dies soon, overkill is worth nothing, and a mid-combat state never beats the win it could reach at the same HP.
  - A projected death (HP share below 0) decays toward 0 exponentially, with the same slope at 0, so it stays above a loss and still orders lines. A flat floor made every losing line look the same, and the brain then ended its turns early.
  - The weights are hand-set (`LeafWeights`: WinBase 0.2, PerHp 0.6, PerPotion 0.02, Dps 10, Unblocked 0.5, MinIncoming 3, PoisonShare 0.8). Blind spots: powers other than poison on enemies and Strength on the player, the draw pile, and intents after this turn.
  - `--leaf FILE` gives the brain other weights, in `run`, `brain` and `panel`, and passes them on to the workers (`serve --leaf`). `weights --leaf` prints the default ones as such a file, named `leaf0`; other weights show in the champion's name (`combat pimc NAME`). `learn/spsa.py --param leaf` tunes them ([Learning §2](/en/arch/learning/#sec-2)).
- Next: hand-made features times linear weights. The feature list is seeded from bottled_ai's 42 features (player HP, block, enemy HP, powers, draw-pile quality, turns to kill, …). bottled_ai compares them in lexicographic order (the first feature decides, the next one only breaks ties); that order becomes linear weights spaced far apart, which are then tuned by SPSA (simultaneous perturbation stochastic approximation: tunes all weights at once from noisy results by perturbing them together). It must value block, overkill and lethal next turn without saturating.
- Later: a small neural net on the encoded observation. Its head predicts the combat's outcome distribution: a death class plus buckets of the HP left at the end (an idea from r33hab, another prior-art project this design learned from, and from ytcs). The macro V prices each outcome once per combat, and the leaf is the priced mean ([Learning §3](/en/arch/learning/#sec-3)), so the net is not retrained for a new V. Two training targets are compared through the gate ([Learning §1](/en/arch/learning/#sec-1)).
- The mid-combat leaf (at turn end) and the post-combat leaf (combat won, before rewards) are the same function; in the post-combat case the combat part is empty.

## 5. Budget and pruning

The levers below keep the search inside its budget. The one that decides when to stop is **CI-based allocation**: each first action's value is a mean over worlds, with a confidence interval (CI), a range that very likely contains the true mean. Once the two best first actions are clearly apart, more samples will not change the choice, so the search stops; otherwise it spends more worlds on those two.

| lever | effect | v0 |
|---|---|---|
| canonical obs-hash dedup | each distinct observation is expanded once per world | yes |
| move ordering + early stop | expand high-prior actions first (a heuristic first, a policy net later) | end turn first, then cards in hand order, then potions; stop when the share is spent |
| CI-based allocation over first actions | stop when the top two are separated; otherwise give them more worlds | no: every first action gets every world |
| trivial decisions | one legal action, or all sequences equivalent → no search | one legal action |
| restore cost | DFS order reuses prefixes and restores only on backtrack; deep copy later ([Simulator §4](/en/arch/simulator/#sec-4)) | yes |
| sequential halving at the root | instead of the even split: ⌈log₂ m⌉ rounds; each round splits every world's nodes evenly over the first actions left, then drops the worse half by their mean over the same worlds (CRN) | built (`--halving`), off by default. Workers keep nothing between requests, so each round searches the actions left again from the root with all the nodes they have had so far: up to about 1.5 times the nodes of resuming (1.25 at 4 first actions, 1.4 at 8, 1.5 at 16) |
| budget by combat | an elite's or a boss's decisions get a multiple of the nodes per world (`--elite-x`, `--boss-x`, by the observation's room type) | built, × 1 by default; × 2 and × 4 to try first, then SPSA |
| K and nodes per world | SPSA parameters | no: planned; 8 × 300 for every combat |

v0's budget is `Budget(Worlds, NodesPerWorld)`, 8 × 300 by default; a node is one executed action. In each world the nodes are split evenly over the first actions, so each gets a fair look. Inside a subtree, once its share is spent, the search stops expanding and the state there is scored as ending the turn, which is the option tried first. On one core this costs about 0.55–0.75 s per action in NoSL and 0.13–0.19 s in SL (one world). In NoSL the worlds are independent, so the worker pool searches one world per worker ([Simulator §8](/en/arch/simulator/#sec-8)): with 8 workers an action takes about 70 ms, with the same result.

**The newer levers.** Sequential halving (SH) is the root selection of Gumbel AlphaZero when the prior is uniform; assist mode, whose time is open-ended, uses its anytime variant. SH and CI-based allocation share the per-world means: SH decides which first action gets the nodes, CI when to stop. The boss multiplier has the strongest evidence on STS: in spire-mentor, raising the boss budget from 1,000 to 4,000 lifted the act 1 clear rate from 21.5% to over 65%, and our runs end mostly at the act 1 boss or in act 2 ([§7.2](#sec-7.2)). K is tuned rather than grown: LoCM (a card-game study) saturates beyond 32 worlds, and ytcs gained 0.018 from K = 64.

Rough numbers: 1–2 s per decision times 8 workers gives about 5,000 branches. With K=16 that is about 300 branches per world, enough for a deduplicated enumeration inside one turn.

## 6. Interface

```csharp
public sealed record Budget(int Worlds = 8, int NodesPerWorld = 300, double Elite = 1, double Boss = 1, bool Halving = false);

public interface ICombatBrain
{
    // Player's turn: search the worlds, return the first action and the rest of the plan.
    CombatDecisionResult Decide(CombatObservation observation, IReadOnlyList<CombatAction> legal,
                                IWorldSource worlds, Budget budget, ulong seed);
}

public sealed record CombatDecisionResult(
    CombatAction First,                    // one of legal
    IReadOnlyList<CombatAction> Plan,      // rest of this turn in the first world (narration, highlight)
    IReadOnlyList<Candidate> Candidates);  // every first action, best first
```

`PimcBrain` implements it for NoSL; the SL planner ([§3](#sec-3)) will be a second implementation, and Harness picks one by environment. Planned: `Choose(request, worlds, budget)` for a prompt during play (chosen canonical indexes plus a value per option), and `Facts` on the result (expected HP loss, turns to kill, P(draw X), …).

- `Facts` will be the only source of narration ([Output §5](/en/arch/output/#sec-5)). NoSL facts are probabilities and expectations; SL facts may be exact.
- `ICombatPolicy` / `IChoicePolicy` stay, for the placeholders and for rollout policies (fast policies that play a line out inside search).

## 7. Tests

1. Tactics suite: positions cut from simulated games that have clear answers (take lethal, exact block, apply vulnerable before attacking); record found / not found.
2. Fixed combat panel (encounter, deck, seed) with CRN (common random numbers: every version plays the same random draws, so differences come from the brain, not from luck): mean HP loss and death rate. First beat the placeholders; version gates as in [Evaluation §5](/en/arch/evaluation/#sec-5). Built: `panel` ([§7.1](#sec-7.1)).
3. NoSL counterfactual: same record, different hidden state → same recommendation (fixed brain seed).
4. SL seal: any execute past the node exit throws.
5. Reproducible with a fixed branch budget. Holds: two panel runs give the same moves and results.
6. SL plan fidelity: the real combat follows the plan; a divergence means the clone is wrong.

### 7.2 Whole runs

The brain also plays the combats of whole runs: `run --policy pimc` ([Simulator §5](/en/arch/simulator/#sec-5)) keeps the run live in the host and searches each combat decision in the worker pool ([Simulator §8](/en/arch/simulator/#sec-8)). Card prompts in combat go to `p0`, for both players; the results below were measured while they were still answered at random. The seed set is `promotion-1` (200 runs, Silent A0, [Evaluation §4](/en/arch/evaluation/#sec-4)), the budget 8 × 300, and the macro decisions come from the random placeholder or from L0 ([Macro brain §2](/en/arch/macro-brain/#sec-2)):

```bash
Sts2Ai.SimWorker run --seeds eval/seeds/promotion-1.txt --policy pimc --macro l0 --records pimc-l0.jsonl
```

|---|---|---|---|---|---|---|
| `play` | random | 8.09 | 7 | 5 | 0 | 0 |

| `play` | L0 | 11.72 | 12 | 54 | 0 | 0 |

PIMC raises the floor under either macro brain, and L0 under either combat policy. With both, the runs that reach the act 1 boss enter it with 93% of their HP on average (58% with random macro decisions), and 15 reach the act 2 boss. No run wins yet. PIMC took 41–50 s per run, four runs at a time with 8 workers each.

The reports are in `eval/reports/` ([Evaluation §6](/en/arch/evaluation/#sec-6)), from commit `18fdb07`. Five of the 400 PIMC runs failed, each in a world built wrong from the observation: a spent Silver Crucible's hidden counter (three runs), a Glass orb's numbers, and Sloth's limit, which only its tooltip shows (the world allowed fewer cards a turn than the real combat, and a legal play was illegal in it). All three are fixed since ([Simulator §3](/en/arch/simulator/#sec-3), [Protocol §1](/en/arch/protocol/#sec-1)). The 4 game errors come from the game: a card that Mayhem plays can stop early without taking itself off the stack of its choice context, and the game logs the mismatch when Mayhem takes itself off.

## 8. Open questions

1. K and nodes per world: SPSA tunes them ([§5](#sec-5)); the panel shows the marginal HP-loss gain per added world.
2. How bad fusion is, which a fusion panel decides: 300–500 NoSL decisions from the evaluation logs, rich in reveals within the turn (draws, random targets, generated cards), K = 32–64 worlds, the turn enumerated in full. For each first action it compares the PIMC value (the mean over worlds of each world's best) with the value when backups are merged by observation history (max over actions, mean over the worlds consistent with that history). If they disagree on fewer than about 3% of the decisions and the loss is within the noise, there is no ISMCTS. Why: αμ changed only 1.3–3% of decisions, EPIMC gained nothing in games whose information is mostly public, and one tree simulation costs about 3–4 DFS nodes (estimated).
   The panel is built: `fusion --log FILE[,…] [--k 32] [--max-nodes 5000]` takes the logs' NoSL combat decisions, with the observation and seed each one logged, and builds its worlds as pimc does. Worlds count as showing the same observation when they differ only in uids: a drawn card's uid is its place in that world's shuffle, so it differs between worlds that draw the same card. For the same reason actions are compared by the card's place in the hand. PIMC's pick loses the merged value of the merged pick less its own; the panel reports how often that is above 0, overall and over the decisions with a reveal inside the turn. A decision with a world over `--max-nodes` states is skipped and counted. A first try on 36 decisions from two runs (K = 16): 8 with a reveal, one pick worse, mean loss 0.00002; a complex turn takes about a minute.
3. NoSL leaf: the turn-end `LeafValue`, a rollout to the end of the combat, and the outcome head ([§4](#sec-4)), at equal wall-clock time. A rollout at every leaf is too expensive, since almost every DFS node carries an end-turn leaf: only the two first actions SH keeps last get one rollout per world, from their best line, as a confirmation.
4. SL: beam width B, and how often the planner proves the optimum within the budget, per room type; equal wall-clock time with NoSL (open question 2 in [Environments §10](/en/arch/environments/#sec-10)).
5. Leaf v0 against the feature leaf tuned by SPSA, on the panel.
