Slay the Spire 2 hides things from the player: the order of the draw pile, what a monster will do after the move it shows, which card an event will hand out, what an unknown map point will turn out to be. A human sees only the screen. A program that runs the game's own code sees everything, down to the state of every random number generator, and a search that may read that state is playing a different and much easier game.

So every part of this project takes one parameter that says how much the AI may know: the **environment**. There are two. **NoSL** ("no save & load") allows only what has been on screen. **SL** ("save & load") also allows the true outcomes inside the map point the player stands on, as if the player could save and reload there as often as they like. This chapter defines both, explains why there are two, and shows where the choice reaches into the rest of the system. Every later chapter takes it as given.

<Aside title="Status">

Decided, and in force in every part of the code that exists. In NoSL, search plays on worlds built from the observation ([Worlds §2](/en/arch/environments/worlds/#sec-2)); in SL, on an exact clone of the current node, which a worker makes from a checkpoint and the node's steps, in self-play as in the real game through the mod ([Information and the node §7](/en/arch/environments/information/#sec-7)). Of the ten guards that keep the rules true, four have tests today (the code boundary, no fallback, the observation round trip and the seal); the counterfactual tests and the reload count are planned ([Information and the node §8](/en/arch/environments/information/#sec-8)).

</Aside>

## 1. The problem: a game of hidden information

A turn of combat shows the player their hand, their energy, every creature's HP and powers, and an *intent* over each monster: an icon saying what it plans to do next, such as an attack of 12. What it does not show:

- the order of the draw pile (the player knows which cards are in it, not their order);
- the monster's moves after the one it shows, and, for a monster whose moves look alike, which of them it has picked;
- the outcome of anything random that has not happened yet: a card that hits a random enemy, a card generated at random, the cards of the next reward, the result of an event's option.

Outside combat the same holds on a larger scale: the map shows a `?` point, but not whether it will be an event, a fight, a shop or a chest; it shows an elite, but not which elite.

All of this lives in the game as ordinary state: piles are lists, monsters keep their next move in a field, and every random draw comes from one of a fixed set of seeded random number generators (RNGs) that the save file stores. The simulator ([Simulator](/en/arch/simulator/)) runs the game's real code, so a search running in it could read all of it, or simply try a line of play and see what happens. A rule is needed that says what is fair.

One more thing makes the line hard to draw: the game itself lets a player peek. Quitting to the menu and continuing reloads the last save, and a reload replays the room exactly, with the same encounter, the same opening hand and the same monster moves ([Information and the node §4](/en/arch/environments/information/#sec-4)). A patient player could quit, look, and come back. So "what a player can know" is not one fixed line, and the project draws two.

## 2. The two environments in one minute

**NoSL: public information only.** A decision may depend on everything shown on screen so far, on what can be inferred from it, on the game's rules, and on anything learned offline. Search cannot see the hidden state, so it *determinizes*: it draws several concrete guesses of the hidden state (K *worlds*), each one consistent with everything seen, searches each as if it were the truth, and averages ([Worlds §2](/en/arch/environments/worlds/#sec-2)).

**SL: save & load inside the current node.** SL may know everything NoSL may, plus the true outcome of any line of play inside the **node**: the current map point, from arrival until the player chooses the next point on the map. It is the same as a player who may save and reload inside the node as often as they like and remembers every attempt. Search gets one exact copy of the node, the *clone*, sealed at the node's exit. SL knows nothing more than NoSL about later map points.

| | NoSL | SL |
|---|---|---|
| what is known inside the current node | what has been shown, and inferences from it | the true outcome of any line of play |
| what is known about later nodes | nothing hidden | nothing hidden (the same as NoSL) |
| the worlds search plays in | K sampled worlds, built from the observation | one exact clone of the node |
| combat brain | PIMC: search each world to the end of the turn, average | the SL planner: plan the whole combat in the one world |
| macro brain and value V | one brain, one V | the same brain and V |
| champions and leaderboards | NoSL's own | SL's own, never mixed with NoSL's |

The macro brain is the part that makes every decision outside combat ([Macro brain](/en/arch/macro-brain/)); V is the learned value it scores options with. Both are shared, and only the combat brain differs, because only in combat do the two environments pose different problems ([Worlds §5](/en/arch/environments/worlds/#sec-5)).

## 3. Why two environments

**NoSL is the goal.** It is what a fair player knows, and the mod's assist mode can offer it to a player who never quits and reloads.

**SL is a stepping stone, and a measure.** Inside a node SL faces no chance at all: the clone holds the true random streams, so a combat is a deterministic puzzle that can be searched to its end, and every line has one outcome instead of a distribution. That makes SL's combat brain much stronger for the same compute ([Combat brain](/en/arch/combat-brain/)), and SL's runs reach the late acts where V has to learn to value them. V is trained on runs whose combats the SL planner played, and serves both environments ([Worlds §6](/en/arch/environments/worlds/#sec-6)).

The two environments play the same pre-registered seeds, so their difference on the same seeds is a clean measurement of what in-node information is worth: the SL − NoSL difference in win rate and floor reached, paired by seed. The leaderboard computes it for every champion that has a report in both environments under the same name ([Evaluation §3](/en/arch/evaluation/#sec-3)); today's two champions differ in their combat brains, so it shows none yet. It is the formal version of the "omniscient against resampled" comparison that plan v1 (the project's first plan, a local note) called for. For scale: spire-mentor, a prior-art Slay the Spire bot, lost 22.8–25.5 percentage points of win rate without its cheat, which saw the whole run; SL sees one node, so its gain should be smaller.

**A whole-run horizon was rejected.** An environment that knew the whole order of the run (every future encounter, reward and shop) was considered and rejected: it would make the run itself a deterministic puzzle, and teach nothing that carries over to fair play. It is not to be built.

## 4. What both environments share

- **Single-player only,** on the pinned game version, v0.111.0.
- **The same code and rules:** the same rule knowledge, and the same Brain, Harness and Protocol. Only the combat brain and the source of worlds are picked by environment.
- **The same seeds:** both play the same pre-registered seed sets, and every result is reported per environment ([Evaluation: metrics, seeds and reports §5](/en/arch/evaluation/metrics/#sec-5)).
- **No real reload by the AI.** Neither environment ever reloads the game the player sees. SL's "save & load" happens only on clones, which a search loads in a worker process. The game counts loads in the save field `SerializableRun.NumReloads`: in the real game it must stay 0, a check that is planned for the mod's logs ([Information and the node §8](/en/arch/environments/information/#sec-8)). A clone is itself a loaded save, so inside a clone the count is 1 or more, and nothing reads it there.
- **Fixed for a run.** The environment is chosen when a run starts, in the host's `hello`, and holds until its `run_end`. It is logged in the run's record (`RunConfig.Env`) and in every line of its decision log (`env`). In the mod the player may switch it at any time; a switch ends the run as the brain sees it and starts a new one ([Mod: the main loop §8](/en/arch/mod/loop/#sec-8)).
- **Observations only, in both.** The brains read protocol observations, never game objects; what SL knows beyond NoSL reaches them only through the clone, which lives in a worker process ([Worlds §1](/en/arch/environments/worlds/#sec-1)).

## 5. How a run picks its environment

Where the environment is set, as the code has it:

| where | how | default |
|---|---|---|
| `run` (whole runs in the simulator) | `--env NoSL\|SL`, in any case (`Commands/RunCommand.cs:23`); a champion file's `env` fills it | NoSL |
| `panel` (the fixed combat panel) | `--env NoSL\|SL`; `--player plan` needs SL, `--workers` needs NoSL with pimc (`Commands/Panel.cs:29-58`) | NoSL |
| the wire | `hello{env: "NoSL"\|"SL"}`, which the host sends at the start of each run ([Protocol: the wire §3](/en/arch/protocol/wire/#sec-3)) | – |
| `brain` (the decision process alone) | serves both: NoSL hosts with `--policy`'s combat brain, SL hosts with `--sl-policy`'s (`Commands/BrainCommand.cs:19`) | `--sl-policy plan` |
| the mod | the SL/NoSL switch in the panel's head, kept in `~/.local/state/sts2ai/settings.json` ([Mod §5](/en/arch/mod/#sec-5)) | SL |
| champion files | one per character and environment, `eval/CHARACTER/champions/nosl.json` and `sl.json`; `gate --env` must match the file's ([Evaluation: champions and baselines §1](/en/arch/evaluation/champions/#sec-1)) | – |
| combat net training | `combat.train --env SL\|NoSL`, required; the net file records it (`learn/combat/train.py`, `export.py`) | – |

What refuses the wrong environment:

- `--policy plan` (the SL planner) and `--afterstates clone` (L0 playing options on the clone) play in SL only: a NoSL `hello` is refused (`Brains/ChampionOptions.cs:40-42`), and so is `run --env NoSL` with a champion that plays them (`Commands/RunCommand.cs:74`).
- A combat net file names the environment whose combats it learned, and is refused in the other one (`Brains/LeafChoice.cs:25`); c1–c4, made before nets had one, play in either.
- Harness refuses the SL messages `node_checkpoint` and `node_action` in a NoSL run (`Harness/Dispatcher.cs:184`, `:193`); the brain server keeps the refusal and answers the run's next decision with an error, the host ends the run as failed, and a failed run voids its report (`Harness/BrainServer.cs:112-123`, `Harness/Reports.cs:38`). The SL planner refuses worlds that are not SL's (`Brain/Combat/SlPlanner.cs:82`).
- The combat net trainer reads only the logs of the environment it is given, and fails on the other's (`learn/combat/data.py`).
- The gate refuses to pair runs played in different environments, rungs or games (`Harness/Gate.cs:51`).
