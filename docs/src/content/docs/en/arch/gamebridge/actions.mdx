Each surface has one static class in `src/Sts2Ai.GameBridge/Actions/`. They share a shape:

| member | what it does |
|---|---|
| `Screen(…)` | the surface's screen, its Protocol view ([Protocol: observations and actions §5](/en/arch/protocol/observation/#sec-5)) |
| `Legal(…)` | the legal actions, as text, in a fixed order |
| `Start(…, action)` | carries the action out through the call the game's button makes; throws if the action is not legal |

The hosts fetch what each class reads (the current event, the shop's inventory, the rest site's options) and decide which screen is asking. `Start` begins the game's work and returns; the host lets the game run until it settles ([Simulator: whole runs §3](/en/arch/simulator/runs/#sec-3)). Where the work is a task the screen would await, `Start` returns it.

## 1. Combat

`CombatActions` (`Actions/CombatActions.cs`):

- **`WaitingForInput(player)`**: the player can act. A combat is in progress, it is the player's side, in the play phase, the action executor is idle, and player actions are not disabled. Headless this is enough; in the real game the screen also has to be ready, which the mod checks on its own nodes ([Mod: the main loop §4](/en/arch/mod/loop/#sec-4)).
- **`Legal(state, player)`**: the cards in hand, in hand order, then the potions by slot, then `end_turn`.
  - A card is checked once with `CanPlay()` (it runs four hook dispatches, so it is not repeated per target). A card that targets any enemy is legal at each enemy it may target, one that targets any ally at each ally, any other once with no target.
  - A potion is legal if the player may use potions, the slot holds one that is not already queued, passes its own usability check, and is usable in combat (combat-only or any-time); targeted the same way, enemies only while alive.
  - `end_turn` is always legal.
- **`Start(state, player, action)`**: a play goes through `CardModel.TryManualPlay(target)`, the call a drag from the hand makes, which checks the target and enqueues the play, and throws if it refuses; a potion through `PotionModel.EnqueueManualUse(target)`; the end of the turn through an `EndPlayerTurnAction` with the turn's number, enqueued as the end-turn button does.
- **`PlayOf(card, target)`, `PotionOf(player, slot, target)`**: name a play or a potion use as `Legal` names it, the target kept only when the card or potion picks one. The mod uses them to record what the player did: the screen passes a target for other cards too (the player for a self card).
- **`HandCard(pcs, uid)`, `Creature(state, uid)`**: find what a uid names; throw on an unknown one.

## 2. Map

`MapActions` (`Actions/MapActions.cs`). The actions are `map:COL,ROW`; the screen lists the same points.

- **Legal** (`Travelable`, the rules of the map screen's `RecalculateTravelability`): the start point if nothing is visited; the second boss right after the boss of a double-boss act; the boss after the last row; otherwise the game's own `MapTravel.GetTravelablePointsFrom`, the point's children, or every point of the next row when a hook allows free travel (`Hook.ShouldAllowFreeTravel`). Sorted by row, then column, since the game's children are a hash set.
- **Start**: an enqueued `VoteForMapCoordAction` for the point, as the map screen enqueues it when a point is clicked.
- `Text(coord)` names a coordinate as the action does; the mod uses it to record the player's travel.

## 3. Rewards, card rewards and bundles

**`RewardActions`** (`Actions/RewardActions.cs`), actions `reward:i` and `rewards_done`:

- **Screen**: each reward not taken yet, by its index in the set, with its kind: `gold` and its amount, `potion` or `relic` and its id, `card` and the cards it would show if opened, `special_card` and its card (private in the game, read from the button's hover tip), `remove_card`.
- **Legal**: each reward not taken yet, by its index, except a potion reward while the belt is full (it stays on screen but cannot be taken until a slot frees); `rewards_done` unless the set disallows skipping and not every reward is taken. A linked reward set (a choice of one among several) throws: none is used in this game version.
- **Start**: `RewardsSetSynchronizer.SelectLocalReward`, as the reward's button does; the task ends when the reward is resolved.
- **`Proceed(run, set)`** is `rewards_done`, the proceed button: a set that is not the room's last skips what is left and closes (`SkipLocalRewardsSet`); after a boss or in the victory room, except between the two bosses of a double-boss act, it readies the act change (`ActChangeSynchronizer.SetLocalPlayerReady`); otherwise the room's rewards end (`ProceedFromTerminalRewardsScreen`). `IsTerminal(set)` says whether a set is the room's last: its room is a combat room.

**Card rewards** are not started; the game asks for them. A card reward opens its own screen from inside the reward, and the game's card selector answers it: `CardRewardLegal` lists `card:i` for each card and `card_alt:ID` for each alternative button not spent (skip, reroll, ones relics add); `CardRewardAnswer` turns the chosen action into the selector's answer. A reroll keeps the screen open and stays listed but does nothing a second time (`KeepsScreenOpen`), so the host keeps a set of spent alternatives per screen.

**`BundleActions`**: a bundle choice (Scroll Boxes' packs) is answered the same way, through the selector: `Legal(n)` is `bundle:i` for each pack, with no skip; `Index` turns the action into the pack's index. Headless, the game's test mode would always take the first pack; the simulator patches `CardSelectCmd.FromChooseABundleScreen` to take the screen's own path instead (reserve the choice, ask the driver, sync the answer) ([Simulator: headless host §4](/en/arch/simulator/headless/#sec-4)).

## 4. Events and the crystal sphere

**`EventActions`** (`Actions/EventActions.cs`), actions `event:i` and `proceed`:

- **Legal**: once the event is finished, only `proceed`; otherwise each option that is not locked, as `event:i`. Options flagged as proceed buttons are UI buttons, not choices: an Ancient's PROCEED is listed as `proceed`, and any other (Trial's DOUBLE_DOWN, which opens the abandon-run popup) is never legal.
- **Start**: `EventSynchronizer.ChooseLocalOption(i)`, which runs the option in the background. `proceed` changes nothing in the game: the host opens the map.
- **Screen**: the event's id, its page's loc key, and each option with its text key, `locked`, the relic an Ancient's option gives, its hover tips' ids (`+` for an upgraded card), and whether its button warns that it kills the player.

**`CrystalSphereActions`** (`Actions/CrystalSphereActions.cs`), the minigame of the CRYSTAL_SPHERE event, a grid of hidden cells, each divination costing one of a few charges:

- **Legal**: `big:X,Y` for every cell whose 3×3 block (clipped at the edges) has a hidden cell, then `small:X,Y` for every hidden cell. The small tool is offered so the player can avoid uncovering a curse.
- **Start**: `SetTool` with the tool, then `CellClicked` on the cell, as the screen does; throws once the minigame is finished, which it is after the last divination.
- **Screen**: each row as a string, `#` hidden, `.` empty, or the letter of the item the uncovered cell shows part of (`R` relic, `P` potion, `C` card reward, `G` gold, `X` curse; an item type it does not know throws), and the divinations left. An item is won once all its cells are uncovered. `Of(game, cell)` names a click as the action does, for the mod's record.

## 5. Shop, rest site and treasure

**`ShopActions`** (`Actions/ShopActions.cs`), actions `buy:SLOT`, `remove`, `leave`:

- **Slots** index the shop's goods, all its entries but the removal, in the game's order (character cards, colorless cards, relics, potions), sold-out ones included, so a slot keeps its number after a purchase.
- **Screen**: the stocked goods by slot, each a card (its view, its price, whether it is on sale), a relic or a potion (its id and price); the removal's price unless it is used.
- **Legal**: an entry that is stocked and affordable; a potion also needs a free belt slot and the game's leave to take potions (`Hook.ShouldProcurePotion`; Sozu forbids it), since without them the purchase fails and nothing changes; `remove` when the removal is stocked and affordable; `leave` always.
- **Start**: the entry's `OnTryPurchaseWrapper(inventory)`, the call a click on the item makes; the removal's asks for the card through the card selector. In the game the removal is then marked used by the shop's removal button, whoever bought it (the player or Lord's Parasol); headless there is no button, so a patch marks it once the purchase succeeds (`Choices.CardRemovalUsed`). `leave` changes nothing: the host opens the map.

**`RestActions`** (`Actions/RestActions.cs`), actions `rest:ID` and `leave`:

- **Legal**: each enabled option by its id (`rest:HEAL`, `rest:SMITH`); `leave` once an option has succeeded, or when none is enabled. Whether one succeeded is the host's to say: the simulator keeps it per room, the mod reads the proceed button.
- **Start**: `RestSiteSynchronizer.ChooseLocalOption(i)`; the task ends with whether the option succeeded (a smith cancelled in its prompt did not).
- **Screen**: each option's id, whether it is enabled, and for HEAL the HP it restores (`HealRestSiteOption.GetHealAmount`), which relics change.

**`TreasureActions`** (`Actions/TreasureActions.cs`), actions `relic:i` and `relic_skip`: legal are each relic in the chest and the skip; `Start` votes as the relic buttons do (`PickRelicLocally`, `SkipRelicLocally`). Opening the chest is not a decision: the simulator opens it, the player clicks it ([Simulator: whole runs §3](/en/arch/simulator/runs/#sec-3)).

## 6. The potion belt

`PotionActions` (`Actions/PotionActions.cs`) is the belt outside combat, with the rules of the game's potion popup: `potion:S` for a potion usable at any time that passes its own check, `discard_potion:S` for any potion not already queued; nothing when the player cannot use potions or is dead. `Start` drinks through `EnqueueManualUse` or throws away through an enqueued `DiscardPotionGameAction`. `Handles(action)` tells a belt action from a screen's own, so a host can add the belt to a screen's legal list and route the answer.

Which screens get the belt is the host's choice: the simulator and the mod add it to the map, rewards, event, shop, rest, treasure and crystal sphere screens ([Simulator: whole runs §4](/en/arch/simulator/runs/#sec-4)).

## 7. Naming what an action acts on

| thing | named by | why |
|---|---|---|
| a card in hand | its uid, its id in the combat's card database | stays true while the hand changes; the same in the simulator and the game |
| a creature | its uid, its `CombatId` | the same |
| a card prompt's option | its canonical index | the game's order may follow hidden state ([Reading the game §5](/en/arch/gamebridge/observe/#sec-5)) |
| a reward, an event option, a shop slot, a chest relic, a card reward card | its index in the screen's own list | the order is public, as the screen shows it |
| a rest option, a card reward alternative | its id | ids stay put when options are disabled or added |
| a map point | `col,row` | |
| a crystal sphere cell | `x,y` with the tool | |

Text actions other than combat's are parsed by `ActionText` (`Actions/ActionText.cs`, internal): a verb and its argument, indexes as plain digits only.

**The SL record.** The mod does not start actions, but in SL it must record the player's as the simulator names them, so the brain can clone the node ([Mod: the SL record §3](/en/arch/mod/sl-record/#sec-3)). It patches the game entry points that the simulator's starts call, and names each step with GameBridge's own helpers, so a recorded step is the action the simulator would have played (`Sts2Ai.Mod/NodeRecord.cs`):

| entry point | records |
|---|---|
| `ActionQueueSynchronizer.RequestEnqueue` | plays, potions and the end of a turn (`PlayOf`, `PotionOf`), map votes (`MapActions.Text`), the belt's discards |
| `PlayerChoiceSynchronizer.SyncLocalChoice` | card prompts (the game's indexes), card rewards, bundles |
| `EventSynchronizer.ChooseLocalOption`, `RestSiteSynchronizer.ChooseLocalOption` | event and rest options |
| `RewardsSetSynchronizer.SelectLocalReward`; `SkipLocalRewardsSet`, `ProceedFromTerminalRewardsScreen`, `SetLocalPlayerReady` | a reward taken; `rewards_done` |
| `TreasureRoomRelicSynchronizer.PickRelicLocally` | a chest relic |
| `OnTryPurchaseWrapper` of a shop entry or the removal | a purchase (`ShopActions.Of`) |
| `CrystalSphereMinigame.CellClicked` | a divination (`CrystalSphereActions.Of`) |

A step the simulator has no decision for, such as a potion thrown away in combat or a card reward closed unanswered, breaks the record for the rest of the node.

**Card prompts in the two hosts.** In the game, a prompt's screen returns the picked cards and the game syncs them as indexes into its own list through `PlayerChoiceSynchronizer.SyncLocalChoice`, which is where the mod reads them. Headless, the simulator answers through `CardSelectCmd.Selector`, the game's hook for a selector that takes the screen's place; that path skips the sync (`Commands/CardSelectCmd.cs`) <Badge text="verified" variant="success" />.
