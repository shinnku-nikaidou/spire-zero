The brain speaks Protocol and knows no game ([Protocol](/en/arch/protocol/)). Something has to read the game's objects into Protocol's observations, list what the player may do, and carry a chosen action back into the game. That is GameBridge (`src/Sts2Ai.GameBridge`), a library of static classes that both game hosts use: the simulator, which runs the game headless, and the mod inside the real game. Because they share it, a decision in the simulator and the same decision in the game are read and named by the same code.

<Aside title="Status">

Exist: observations of every screen, the legal actions of every surface and the potion belt, the start of every action the simulator plays, card prompts in canonical order with their context, the SL checkpoint, and the hidden-state keys search uses. Planned: the event stream of the public history ([§5](#sec-5)).

</Aside>

## 1. Three jobs

For each kind of decision screen, GameBridge has the same three jobs:

| job | in | out | example |
|---|---|---|---|
| **observe** | the game's objects | a Protocol observation | `Observe.Combat(state, player)` → `CombatObservation` |
| **legal** | the game's objects | the legal actions, as text | `MapActions.Legal(run)` → `["map:0,1", "map:3,1"]` |
| **start** | one legal action | the game call that a click on the screen would make, started | `MapActions.Start(run, player, "map:0,1")` → a vote for the map point, as the map screen enqueues it |

What it does not do is decide **which** screen is asking, or wait for the game to finish an action. Both depend on what the screen shows, which only the host tracks: the simulator plays the screens' part itself ([Simulator: whole runs §3](/en/arch/simulator/runs/#sec-3)), and the mod looks at the screen on display ([Mod: the main loop §4](/en/arch/mod/loop/#sec-4)). GameBridge keeps only pure predicates the hosts build on, such as `CombatActions.WaitingForInput` and `RewardActions.IsTerminal`.

## 2. The rules

- **It sits between two worlds, and touches neither more than it must.** GameBridge references Protocol and the game's assemblies (`sts2.dll`, `GodotSharp.dll`, `SmartFormat.dll`, and the game's `0Harmony.dll` for its one patch, [Reading the game §6](/en/arch/gamebridge/observe/#sec-6)). Never Brain, so a decision cannot reach into the game. It uses no Godot nodes (the game's screen objects, the `N*` classes), which a headless game does not create; its doc comments name them only to say where the screen shows a value.
- **Observe what the screen shows.** Each field is read from what the screen binds to: a power's `DisplayAmount` and `IsVisible`, a relic's `ShowCounter`, an intent's damage through the same `GetSingleDamage` the icon uses. Two places read further, because the screen does show the value but keeps it privately: a power's held card, read by reflection (`HeldCards`), and the upgrade preview, made on a copy of the card ([Reading the game §3](/en/arch/gamebridge/observe/#sec-3)).
- **Start through the screen's own entry point.** An action is carried out by the call the game's button makes: a card is played through `TryManualPlay`, as a drag from the hand does; a map point is chosen by a `VoteForMapCoordAction`, as the map screen enqueues it. Never by editing state, and never through calls that skip the game's checks (`CardCmd.AutoPlay`, a bare `new PlayCardAction`, `PlayerCmd.EndTurn`). A start that the game refuses throws.
- **Illegal is an error.** Every `Start` throws on an action that is not in its legal list, and the lists never offer what would fail: a potion with no free slot, a purchase without the gold.

## 3. Who uses it

| host | observe | legal | start |
|---|---|---|---|
| the simulator (`Sts2Ai.SimWorker`) | every decision | every decision | every action it plays ([Simulator: whole runs §4](/en/arch/simulator/runs/#sec-4)) |
| the mod (`Sts2Ai.Mod`) | every decision it asks the brain about | the same | only when the player asks the AI to play: GameBridge's start where that is the call the click makes (combat, a purchase, a chest's relic, the crystal sphere, the potion belt), else the screen's own handler or the task it awaits ([Mod: auto-play and safety §1](/en/arch/mod/auto/#sec-1)). It records every step, the player's or the AI's, by patching the same game entry points the simulator's starts call, so an SL record names a step exactly as the simulator would ([Mod: the SL record §3](/en/arch/mod/sl-record/#sec-3)) |

The mod compiles GameBridge's source files into itself and runs inside the game. The simulator references it as a project. CombatBuilder, the simulator's way of building a combat from an observation, reuses GameBridge's intent reader to match monsters' moves to the intents shown ([Simulator: combats §5](/en/arch/simulator/combat/#sec-5)).

## 4. Following the game

Everything this project knows about the game's code lives in three places: GameBridge, the simulator's patches ([Simulator: headless host §4](/en/arch/simulator/headless/#sec-4)), and the mod's screen readers and hooks ([Mod: the main loop §4](/en/arch/mod/loop/#sec-4)). On a game update:

1. decompile the new game and rebuild against it (`Sts2BinDir`, [Simulator: reference §1](/en/arch/simulator/reference/#sec-1));
2. run `selftest`, then `run --check` batches, which fail on any screen the driver does not know, any illegal answer, any game error, and list the surfaces never reached ([Simulator: whole runs §5](/en/arch/simulator/runs/#sec-5));
3. read the diff of the game's signatures that GameBridge touches; the card prompt entries are found by reflection, so a new one is patched without a change, but its arguments still need a look.

The mod refuses to run on a game version it was not built for ([Mod §3](/en/arch/mod/#sec-3)).

## 5. Planned: the event stream

The public history of a run (cards drawn and moved, plays, intents shown, screens seen) would come from the game's own hooks <Badge text="inferred" variant="caution" />:

- `CardPile.CardAdded` and `CardRemoved` on the hand, draw, discard and exhaust piles (`Entities.Cards/CardPile.cs:35-37`) give draws, moves and generated cards, with the position of an insert into the draw pile;
- `ActionExecutor.AfterActionExecuted` (`GameActions/ActionExecutor.cs:56`) gives plays;
- `CombatManager.TurnStarted` (`Combat/CombatManager.cs:273`), with a snapshot of the intents, gives the turns;
- a reshuffle shows as the draw pile refilled from the discard pile; the shuffle command itself is still to be found.

Only what the player could have watched would go in: an insert at a random position is logged without the position. The format is in [Protocol: observations and actions §8](/en/arch/protocol/observation/#sec-8).

## 6. Tests

| what | where |
|---|---|
| GameBridge does reach the game (the control of the boundary check) | `BoundaryTests` |
| every combat observation and action round-trips; builds from observations show them exactly | `selftest` ([Simulator: reference §5](/en/arch/simulator/reference/#sec-5)) |
| every surface's observation round-trips; every answer the brains give is legal and starts without error; runs replay exactly, nodes included | `run --check` ([Simulator: whole runs §6](/en/arch/simulator/runs/#sec-6)) |
| the mod's SL records, captured in the game with the mod's `Record` setting, replay on their clones with the same observations as the game showed | `clones` ([Mod: the SL record §8](/en/arch/mod/sl-record/#sec-8)) |

Planned: a check in the mod that every enabled control on screen is one legal action, and the same seed and decisions giving the same observations in the game and in the simulator ([Evaluation §2](/en/arch/evaluation/#sec-2)).
