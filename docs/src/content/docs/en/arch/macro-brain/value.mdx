[The value network](/en/arch/macro-brain/network/) ends in one number per floor. This section turns those numbers into the value that decides, then goes the other way: how a logged decision becomes a training sample, the loss, and how a net is trained.

## 1. What V is

**V(s) = P(win this run from s, playing the current champion).** V of a situation is the chance that the run is won from there if the *champion*, the best version of the AI accepted so far, plays the rest of it.

- **One scale.** Every value is a probability of the same event, so an HP heal at a rest site, a card at a reward and a path on the map are compared directly, with no exchange rate written by hand ([Afterstates §2](/en/arch/macro-brain/afterstates/#sec-2)).
- **Observation only.** V reads the run view, what the player sees outside combat ([Harness: the decision log §7](/en/arch/harness/decision-log/#sec-7)).
- **One V for both environments.** An SL policy plays every later node better than a NoSL one, so from the same observation its true chance to win is higher; the shared V ignores that on purpose ([Environments: worlds and two combat algorithms §6](/en/arch/environments/worlds/#sec-6)). V is trained on SL runs, whose combats the SL planner plays.
- **Under a policy.** "Playing the current champion" matters: the same situation is worth more under a stronger player. That is why a net trains on the newest generation's runs alone ([Self-play §4](/en/arch/macro-brain/selfplay/#sec-4)).

## 2. From hazards to a value

V does not predict the chance to win directly. Its head predicts, for each floor $g$ from 0 to 63, a **hazard**

$$
h_g = P(\text{the run ends on floor } g \mid \text{it is still going on floor } g),
$$

which is the discrete-time survival model of statistics (a *hazard* is the chance of the event at a time, given that it has not happened before), here with a neural network computing every floor's hazard from the run (as in Gensheimer and Narasimhan, 2019). Everything else follows by multiplication. From the run's current floor $f$:

$$
S_g = \prod_{j=f}^{g} (1 - h_j), \qquad e_g = S_{g-1}\, h_g \quad (S_{f-1} = 1).
$$

$S_g$ is the chance to be still going after floor $g$, and $e_g$ the chance that the run ends exactly on floor $g$. Then:

- **P(win)** is the chance to survive every floor: $S_{63}$. A won run is labelled as surviving them all ([§3](#sec-3)), so this is the chance that the run is won. This is V's value: the net file's `objective` is `win`, and `RunNet.Value` computes the product.
- **The expected floor reached** comes from the same hazards: $\mathbb{E}[F] = f + \sum_{g \ge f} S_g$. The training report uses it ([§6](#sec-6)); nothing decides by it.

Why hazards rather than one output for the chance to win:

- **Every floor gets a label.** Few runs are won: 286 of the 21,275 runs of a generation's self-play ([Self-play §4](/en/arch/macro-brain/selfplay/#sec-4)). As a single target, almost every sample would say only "lost". A sample that survived floors 5 to 32 and died on 33 says something about each of those floors.
- **Stopped runs still count.** A run cut short (*censored*: truncated, or its time box ended) says nothing about the floors after it stopped, and the mask simply leaves them out. A single target would have to guess.
- **The whole distribution.** The same head gives where the run is likely to end, which a report can read.

Why the chance to win rather than the floor reached: the floor weighs every floor the same, so it can prefer a safe line that reliably reaches act 2 to a riskier one that sometimes wins. Winning is the goal, and runs win often enough for it to be measured.

## 3. From a logged decision to a sample

`learn/v/data.py` builds the samples. Every macro decision in the self-play logs is one: the run view at that decision ([Harness: the decision log §7](/en/arch/harness/decision-log/#sec-7)), joined by run id to the run's record, which says where the run ended ([Evaluation: metrics, seeds and reports §8](/en/arch/evaluation/metrics/#sec-8)). A failed run's decisions are left out. A map move gives a second sample, the chosen point's afterstate, since that is what V reads when it values a map option and no logged view shows it ([The value network §4](/en/arch/macro-brain/network/#sec-4)). Its targets are the run's real outcome, a **Monte Carlo (MC) target**: no estimate, no bootstrap, only what happened.

A sample holds:

- its **tokens and numbers**, read from the view ([The value network §2](/en/arch/macro-brain/network/#sec-2)). The view itself is dropped: as Python objects a view is about ten times larger. A held-out sample keeps its view as JSON, for the net file's test runs.
- its **start** $s$, the view's floor, and its run's **end** $e$, the floor reached, each at most 63;
- its run's **kind**: died, won or censored;
- the **next combats' HP costs**, for the second head ([§4](#sec-4));
- its **weight** ([below](#sec-3)).

**Labels: only what was measured.** For a sample taken on floor $s$ whose run ended on floor $e$, each floor $g$ gets a label $y_g$ or none:

| the run | $g < s$ | $s \le g < e$ | $g = e$ | $g > e$ |
|---|---|---|---|---|
| died on floor $e$ | none | 0 (survived) | 1 (ended) | none |
| won | none | 0 | 0 | 0 |
| censored on floor $e$ | none | 0 | none | none |

For example, a decision on floor 5 of a run that died on floor 33 has 29 labels: 0 on floors 5 to 32 and 1 on floor 33. A decision on floor 5 of a won run has 59: 0 on floors 5 to 63.

**The loss** of a sample is the binary cross-entropy of the hazards over its labelled floors, plus the second head's:

$$
\mathcal{L} = -\sum_{g \,\text{labelled}} \Big[ y_g \log h_g + (1 - y_g) \log(1 - h_g) \Big] \;+\; 3 \sum_{k} \big( \hat c_k - c_k \big)^2 ,
$$

where $c_k$ is the share of max HP the $k$-th next combat cost, and $\hat c_k$ the second head's prediction of it.

**Every run weighs the same.** All the decisions of one run share one outcome, and a run has well over a hundred of them. Each sample is weighted by one over its run's number of decisions, so a long run counts once, not 180 times, and a batch's loss is the weighted mean. The same concern is why AlphaGo's value network was trained on one position per game (Silver et al., 2016): positions of one game are strongly correlated, and a net trained on all of them memorizes games.

**Held out by run.** Every fifth run, by its run id (`int(run_id, 16) % 5 == 0`), is held out, with all its decisions, for early stopping and for the report. Splitting by decision instead would put decisions of the same run on both sides and overstate how well the net does.

<Aside>

**What MC means here.** The label is how the run ended under the policy that played it, including everything after the decision: the combat planner's luck, and in self-play the later exploration draws ([Self-play §3](/en/arch/macro-brain/selfplay/#sec-3)). That makes it unbiased for that policy and noisy for any one decision.

</Aside>

## 4. The second head

A second head, used only in training, predicts the share of max HP each of the run's next six combats cost, as six sigmoid outputs. A death costs what was left; a run with fewer than six combats ahead has targets for those it has. Its squared error joins the loss at weight 3. Its seventh output serves simulated boss fights as extra labels, which whole-run training does not use, so it has no target there.

It never decides and is not in the net file. Its job is to shape the body: a combat's HP cost is measured several times per run, so it gives the body many more targets than the one outcome, all about the same thing V must judge, how strong the run is for the fights ahead.

## 5. Training

```text
uv run python -m v.train --list PREFIX --name NAME --objective win [--init FILE]
```

`learn/v/train.py`. The sizes and settings are fixed in the code, not options; an experiment changes them there, and only a result keeps the change:

| setting | value |
|---|---|
| floors | 64, from floor 0 |
| optimizer | AdamW, learning rate $3 \times 10^{-5}$, weight decay $10^{-4}$ |
| batch | 256 samples, shuffled anew each epoch |
| epochs | at most 40, stopping after 5 without a held-out hazard loss lower by $10^{-4}$; the best epoch's weights are kept |
| unknown ids | ids seen fewer than 3 times |
| second head | weight 3 |
| start | the hazard head's biases at the baseline ([below](#sec-5)) |

**Why such a small learning rate, from the baseline.** The data holds few outcomes for its size, and a net overfits fast: it can memorize which run a state came from within an epoch. So the hazard head's biases start at each floor's hazard over the training runs,

$$
\frac{\text{deaths}_g + 0.5}{\text{alive}_g + 1},
$$

both counted by the samples' weights, and the net only has to learn how the run moves each floor's hazard away from that average. It moves slowly enough for held-out runs to say when to stop.

**Going on from a net (`--init`).** Training can start from an earlier net file instead of from scratch: its token tables, its standardization and its weights, read back from its ONNX graph (`export.weights`). The second head, not in the file, starts anew. A net of this structure goes on only from a net of this structure.

**On the GPU**, a batch's tensors are built from the samples as lists, then one tensor each. Each training runs on one GPU.

## 6. The report

The trainer prints a report and writes it into the net file (`fit`). All of it is measured on the held-out runs:

| field | what |
|---|---|
| `runs`, `held_out_runs`, `samples`, `won` | what the training read |
| `vocab` | each token table's size |
| `held_out_loss`, `held_out_loss_floor_only` | the hazards' loss, against the baseline's, which knows only the floor |
| `held_out_next_combats` | the second head's error |
| `r2_held_out`, `r2_held_out_floor_only` | the $R^2$ of the expected floor against the floor reached, and the baseline's |
| `brier_held_out`, `brier_held_out_floor_only` | the Brier score of P(win): the weighted mean of (predicted chance − won)², and the baseline's |
| `won_held_out_runs` | how many held-out runs were won |

$R^2$ and the Brier score measure how well V tells apart states of different runs. A decision only needs V to order the options of one state correctly, which neither measures. That is why every net is judged by playing ([Self-play §5](/en/arch/macro-brain/selfplay/#sec-5)).
