## 1. Known weaknesses

- **Labels carry the later draws.** A state's label in a run that explores more is lower, and V is not told the run's ε ([Self-play §3](/en/arch/macro-brain/selfplay/#sec-3)). A cut point per run would remove this ([§3](#sec-3)).
- **What the net cannot express.** The route sees no build, the max mixes paths, and the route ends with the act ([The value network §8](/en/arch/macro-brain/network/#sec-8)).
- **One outcome per run.** A run's decisions share one label, so telling which decision made the difference takes many runs ([From hazards to value §3](/en/arch/macro-brain/value/#sec-3)).

## 2. Planned, not built

These parts of the macro brain's design are not built.

### L1: rollout check

L0 decides every time; L1 would be an extra check for close calls, with the evaluation-time budget. It would start when the top two L0 values are within their confidence interval, so L0 cannot tell them apart. A **rollout** plays the game forward with fast policies to see where an option leads. For each candidate:

1. Start from its afterstate in sampled run worlds ([Simulator: worlds and the SL clone §8](/en/arch/simulator/worlds/#sec-8)).
2. Play forward for H nodes (by default up to the next boss) with fast policies: in combat the rollout policy or a shallow search, outside combat L0.
3. Pair the candidates with common random numbers: every candidate is played in the same world seeds, so the difference between them is far less noisy than with independent samples.
4. A candidate's value is the mean of V at the horizon, or the terminal outcome if the run ends first.
5. Choose by the paired difference and its confidence interval.

These counterfactual paired rollouts would also be training signal for V at key decisions. In SL, rollouts past the current node still use sampled worlds ([Environments: information §3](/en/arch/environments/information/#sec-3)). On the map, the decision is the next point only, decided again at every step; close calls there are L1's first use.

### NoSL: run worlds

NoSL has no run worlds yet, so its L0 predicts afterstates from the screen ([Search §1](/en/arch/macro-brain/search/#sec-1)). With run worlds, it would apply each option in K sampled worlds and average V over them, and search multi-step screens as SL's clone does, deduplicating states by observation.

### Interface

The planned C# interface. One entry point serves every non-combat surface; Harness routes by surface name ([Harness: routing, budgets and seeds §1](/en/arch/harness/routing/#sec-1)).

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness §4).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims), or of the act's route on the map
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` is the action to execute now, `Plan` the rest of this screen (on the map, the rest of the act's route), `Candidates` the value, confidence interval and sample count of each first action, and `Facts` the statements used to explain the choice. Out-of-combat card prompts arrive through the same `card_choice` surface as in-combat prompts; `ChoiceContext.Purpose` says what a prompt is for, and Harness routes by whether a combat is running. The macro policy inside rollouts is L0 with a smaller K, never L1.

### Budget

- **Self-play:** a fixed number of branches, so runs are reproducible; L0 always, L1 only on a sampled subset of close calls, whose results become training data.
- **Assist:** L0 answers at once; L1 refines the answer while the player looks at it. The search is *anytime*: it can stop at any moment and still return its best answer so far.
- **Auto:** L0 + L1 under a wall-clock cap.

### Tests

1. Coverage: every macro surface is reached in simulated runs, and the fallback count is 0.
2. Decision panels: a fixed set of (run state, options) cases whose ground truth comes from large paired rollouts; how often L0 agrees, per surface, shows where V is weakest.
3. NoSL counterfactual: the same public record with different hidden state (`RoomSet` tails, odds, streams) gives the same decision.
4. Determinism with a fixed budget.

## 3. Open questions

1. A cut point per run, so that a decision's label carries no later draws: draws before it, V's best after it, training only on the decisions after it, as AlphaGo's value network was trained.
2. How to check P(win)'s calibration: of the states V gives 30%, about 30% should be won ([Learning: reference §12](/en/arch/learning/reference/#sec-12)).
3. How much path planning V can learn from a map bag that holds no links ([The value network §8](/en/arch/macro-brain/network/#sec-8)).
4. The horizon H of L1 (the next boss or the next act), and how strong the rollout's combat policy must be.
5. In NoSL, the shop as one decision or a sequence; in SL the clone searches it as a sequence.
