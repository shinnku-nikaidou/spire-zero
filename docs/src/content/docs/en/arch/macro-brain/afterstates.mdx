A decision outside combat is a choice among a few options whose effects last for the rest of the run. This section explains the one idea the macro brain is built on: value the *situation right after* each option with a single learned function, instead of valuing the options themselves.

## 1. From Q(s, a) to V(s′)

The textbook way to choose an action $a$ in a state $s$ is an *action value* $Q(s, a)$: the expected outcome of taking $a$ in $s$ and playing well afterwards. A brain that learns $Q$ must learn one function of two arguments, and the second one, the action, means something different on every surface: a card on a card reward, a map point on the map, a shop slot in a shop.

Many decisions in Slay the Spire 2 have a structure that removes the second argument. Taking an option first changes the run in a way that is known in advance (a card joins the deck, gold is paid, a map point is chosen), and only after that does anything random happen (the next combat, the event's roll). The situation right after the known part, before the random part, is the option's **afterstate** $s'_a$ (Sutton and Barto, *Reinforcement Learning*, §6.8; TD-Gammon valued backgammon positions the same way). Then

$$
Q(s, a) = V(s'_a), \qquad a^\ast = \arg\max_a V(s'_a),
$$

where $V$ is a function of one argument: how good a situation is. Two options that lead to the same afterstate have the same value, whatever their names. Taking a card from a reward, buying the same card in a shop and receiving it from an event are one afterstate, and V learns its value once.

Three properties follow:

- **One function for every surface.** V reads a run (deck, relics, potions, HP, gold, the map ahead) and nothing about the screen it came from, so the same V scores a map, a shop and a rest site ([§2](#sec-2)).
- **Cheap options.** A decision has a handful of options, and applying one costs a few milliseconds in the real game ([Search §6](/en/arch/macro-brain/search/#sec-6)). Every option can be tried; nothing has to be guessed or pruned.
- **Data from every decision.** Each logged decision's run view, whatever the surface, is a training sample for the same V ([From hazards to value §2](/en/arch/macro-brain/value/#sec-2)).

## 2. One scale for every surface

Every option is scored by the same V in the same unit, so options of different kinds are compared directly: an upgrade against a heal, a relic against a potion and a card removal, a monster fight against a rest site. Nothing converts HP into gold or a relic into HP by hand. That conversion is what V learns from how runs end.

The unit is V's *objective*. For the current V it is the expected **progress**: the floor the run is expected to reach, plus, for a run that ends in a combat, the share of the enemies' HP taken in it ([From hazards to value §1](/en/arch/macro-brain/value/#sec-1)). A difference of 0.5 between two options means V expects the run to end half a floor later with one than with the other.

## 3. Random afterstates and the two environments

Some options are followed at once by something random: a transform's new card, an event's outcome, a reward reroll. The afterstate is then not one situation but a distribution over situations, and the option's value is the expected value over it:

$$
Q(s, a) = \mathbb{E}\left[\,V(s'_a)\,\right].
$$

The two environments ([Environments](/en/arch/environments/)) estimate this expectation differently. SL may see the true outcomes inside the current node (the map point it stands on, from arrival to the travel action); NoSL may not, and must average over worlds that agree with what is public.

| | NoSL | SL |
|---|---|---|
| in-node random outcomes (event result, transform, reroll, a `?` already rolled) | mean over K sampled worlds (planned) | exact: the node's clone |
| in-node rewards that depend on how the combat was played | – | known (open question 1, [Environments: information §9](/en/arch/environments/information/#sec-9)) |
| beyond the node | sampled worlds | sampled worlds |
| value function | V | the same V |

Neow and the other Ancients' options are the clearest case: SL sees the exact outcome of a random option, such as which card "a random rare card" gives ([Environments: information §2](/en/arch/environments/information/#sec-2)).

In principle SL would also value states differently: from the same state SL wins more often, because it plays every later node better, so a value made for SL would accept more risk (more elites, high-variance events). This is ignored. One V serves both environments; it is trained on runs the SL combat brain played, so in NoSL it is somewhat optimistic ([Environments: worlds §6](/en/arch/environments/worlds/#sec-6)).

## 4. Why one V

Two other designs come up naturally, and both were weighed against the single V.

**Two networks, one for the deck and one for the route.** Card picks feel like a different problem from paths and potions: the first is about combinations (does this card work with the relics I have), the second about resources and risk (can I survive the next elite). But no line separates them. Relics come from elites (a route decision) and shops (a purchase), and their value depends on the deck; a shop sells cards, relics, potions and a removal for one purse of gold; a rest site trades HP against an upgrade; events trade HP for cards or relics. Splitting the value in two needs either an exchange rate between the two networks' outputs, written by hand, which is what V v0 had (a potion worth 8 HP, an upgrade 3) and what made n2-b0.03, a net that read V v0's features, rest at 70–85% HP 99% of the time ([The value network §1](/en/arch/macro-brain/network/#sec-1)), or a third network that learns to combine them from the run's outcome, which is a single V again. Each half would also see only part of the data while needing to read the whole run.

**A policy network.** A network that maps a screen directly to a choice, as AlphaZero's policy does, would need a teacher. Imitating L0 can at best match L0; a policy gradient on run outcomes is far noisier than V's targets; and a search stronger than the policy, which AlphaZero relies on, is what L0 already does by trying every option. A policy would save the clone's cost (about a fifth of a gauntlet run's time, [Search §6](/en/arch/macro-brain/search/#sec-6)) and lose what the clone shows. It becomes useful when NoSL needs a fast brain without a clone: distilling SL's L0 into a policy is a candidate then.

So the macro brain keeps one V and one score. The distinction between building a deck and choosing a route moves inside V, as two encoders feeding one body, which is a next step ([Weaknesses and next steps §2](/en/arch/macro-brain/next/#sec-2)).
