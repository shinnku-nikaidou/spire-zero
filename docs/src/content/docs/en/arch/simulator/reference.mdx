## 1. Build and run

The simulator is the .NET project `src/Sts2Ai.SimWorker` (target `net9.0`), one program with many commands. It references the game's own assemblies, `sts2.dll`, `GodotSharp.dll`, `SmartFormat.dll` and the `0Harmony.dll` the game ships for mods, from a read-only snapshot of the game, without copying them into its output (`src/GameReferences.props:8-19`).

| setting | where | what it does |
|---|---|---|
| `Sts2BinDir` | MSBuild property, default `tmp/gamebin/v0.111.0` | the game snapshot the build references, stamped into the program |
| `STS2_BIN_DIR` | environment, at run time | overrides the stamped snapshot; the program refuses to start if `sts2.dll` is not there (`Program.cs:35-48`) |
| `TieredCompilation` | `Sts2Ai.SimWorker.csproj:12-20`, off | every method compiled once, fully optimized: tiering re-JITs hot methods in the background, and a Harmony patch can silently drop off (seen after a few thousand combats); it was also 2× slower on short runs |
| `DOTNET_ReadyToRun=0` | environment, set by the launcher | framework code is JIT-compiled fully optimized too, about 20% more combats per second; the first output line says so when it is missing |
| `SourceRevisionId` | MSBuild, from git | the commit stamped into the program, which records and reports carry; a build with uncommitted changes under `src/` gets `-dirty` (`Sts2Ai.SimWorker.csproj:36-48`) |

The game's assemblies are found by a resolver installed before any game type is compiled, which is why the entry point that uses them, `Cli.Run`, must not be inlined into `Main` (`Program.cs:10-12`, `Commands/Cli.cs:44`).

**The launcher.** Batches and the fleet run a build of a fixed commit, not the working tree: `tmp/build.sh REV` (a local script) archives the commit, builds it in Release with `SourceRevisionId` set to the commit, and writes `tmp/builds/REV/sim.sh`, which runs that build's dll with `DOTNET_ReadyToRun=0` and `HOME` pointed at `tmp/home`. So a `brain` started through it listens at `tmp/home/.local/state/sts2ai/brain.sock` unless `--socket` says otherwise ([Whole runs §7](/en/arch/simulator/runs/#sec-7)). The fleet's hosts get the same build and a launcher of their own (the fleet skill, `.claude/skills/fleet/SKILL.md`).

## 2. The command line

```text
Sts2Ai.SimWorker COMMAND [options]
```

- **Parsing** is System.CommandLine 2.0.14. `--help` works on the root and on every command. `--verbose` works after any command. There are no response files: an argument that starts with `@` is an argument (`Commands/Cli.cs:24`).
- **stdout carries results only**, which scripts read; logs go to stderr, one line each, `12:34:56 INFO    sim: message`, with an exception's text on the lines after (`Runtime/Logs.cs:43-60`). The level is Information and up, Debug with `--verbose`. The game's own log goes to the category `game`: its errors and warnings at Error and Warning, its other lines at Debug ([Headless host §8](/en/arch/simulator/headless/#sec-8)).
- **Booting.** Only commands that need the game boot it (`Cli.Game`); `brain`, `report`, `gate`, `leaderboard` and `seeds` do not.

**Exit codes** (`Commands/Cli.cs:45-67`):

| code | meaning |
|---|---|
| 0 | done |
| 1 | done, with failures: combats or runs that failed, a replay that differed, game errors, a gate that did not pass |
| 2 | a mistake in the command line or in a file it names (also an I/O error, a file that is not valid JSON or not valid data) |
| 70 | a bug; its stack is logged |

By command: `run`, `bench`, `selftest` and `clones` exit 1 on failures, and `gate` when it does not pass; `list`, `tables` and `combat` always exit 0 when they finish; `serve` exits 1 after its first failed request.

## 3. Option groups

Several commands share groups of options, defined in `Commands/Args.cs`.

**Loadout** (`Args.cs:43-58`): replaces the starting loadout.

| option | default | meaning |
|---|---|---|
| `--character` | `SILENT` | the character |
| `--deck` | the starting deck | `A*5,B+,C+2@SHARP:2`: `*N` repeats, `+` or `+N` upgrades, `@ENCHANT:AMOUNT` enchants (`Simulation/Loadout.cs`) |
| `--relics` | the starting relics | `A,B`; replaces them, their potion slots apply, and in a run they skip `FinalizeStartingRelics` |
| `--potions` | none | `A,B`; throws if no slot is free |
| `--hp` | the character's | start HP, clamped to max HP |
| `--max-hp` | the character's | start max HP |

**Pool** (`Args.cs:61-96`): which combats, then the loadout.

| option | default | meaning |
|---|---|---|
| `--act` | 0 | the act, counted from 0 |
| `--rooms` | `weak,regular` | room kinds, from `weak`, `regular`, `elite`, `boss` |
| `--encounter` | none | one encounter instead; it also sets the act |

**Budget** (`Args.cs:108-151`): the combat brain's budget. The plan options need `--policy plan`.

| option | default | meaning |
|---|---|---|
| `--worlds` | 8 | PIMC's worlds per decision |
| `--nodes` | 300 | nodes per world; for plan, per state and turn |
| `--effort` | `medium` | plan's preset: `low` beam 8, easy beam 2, loss plans 3; `medium` beam 8, easy 4, loss plans 3; `high` beam 8; `max` beam 16; all 300 nodes and replan 1 (`src/Sts2Ai.Brain/Combat/CombatBrain.cs:20-27`) |
| `--beam` | the preset's | plan's states kept per turn (at least 1) |
| `--easy-beam` | the preset's | states kept when the greedy dive wins (0: `--beam`) |
| `--replan` | the preset's | turns an unproved losing plan is followed before planning again (0: to its end) |
| `--loss-plans` | the preset's | unproved losing plans in a row per combat (0: no limit) |

**Leaf** (`Args.cs:154-162`): what values a search's unfinished lines.

| option | meaning |
|---|---|
| `--combat-net FILE` | the combat net file, which values the leaves still in progress; a finished combat is scored at `LeafValue`'s prices. `pimc` and `plan` need it, and so does `selftest` |

**Champion** (`Args.cs:197-238`): the options that make a champion, in `run`, `brain` and `gate`.

| option | default | meaning |
|---|---|---|
| `--policy` | `play` | the combat brain: `pimc` (NoSL only), `plan` (SL only), or the placeholder `play` |
| `--macro` | `random` | the brain outside combat: `l0` (the macro brain with V) or `random` |
| the budget options | | above |
| `--workers` | `--worlds` | worker processes, for `pimc`, `plan` or `--afterstates clone` |
| `--value FILE` | none | l0's V, a net file; `--value` and `--macro l0` go together |
| `--afterstates` | `screen` | `clone` plays each option on the node's clone (SL, `l0`) |
| the leaf options | | above; `pimc` and `plan` need them, and only they take them |
| `--explore ε` | 0 | l0 draws a share ε of its decisions evenly among their options, for self-play; needs `l0`, and `gate` refuses it |

**Champion file**, `--champion FILE` (`Args.cs:165-192`), in `run` and `brain`: plays the champion a champion file names ([Evaluation: champions and baselines §1](/en/arch/evaluation/champions/#sec-1)). The file's options come after the ones given, so given ones win; they include its `character` and `asc`. A command without `--env` (`brain`) skips the file's `env`, and a `--policy` given that differs from the file's keeps its own budget. `gate`'s `--champion` is a different option: the champion to beat.

## 5. `selftest`

`selftest` plays `--n` combats of the pool (20 by default) and runs these checks, by the names it reports (`Checks/SelfTest*.cs`; the order is `Checks/SelfTest.cs:73-145`). Its searches value their leaves with the net `--combat-net` names, which it requires. Exit 1 if any check fails.

The boundary, that Brain, Protocol and Harness reach no game assembly, is checked without the game by the unit test `BoundaryTests` ([§7](#sec-7)).

**Per combat**, played twice: determinism (observations, hidden state and trace), the protocol round trip (observations, and actions as text and as JSON), no exceptions, no game errors.

**At up to three random cut points per combat** (so 60 build checks at the default `--n 20`): restore; restore of the hidden state, byte for byte; fast hook listeners give the game's results; determinize keeps the observation (seeds 11 and 22); determinize replays; play goes on after determinize; then `CombatBuilder` at the cut's observation: the build shows the observation, the built combat restores, and play goes on after the build.

**Builds of numbers only a model holds** (Defect): a worn Glass orb (3 of 6), a used-up Silver Crucible, Pael's Tooth keeping 2 cards, Sloth with 1 of 3, Nightmare, a Hardened Shell at 14 of 20; the build keeps a power's stacks (Sloth still lets a card be played) and a power's card (Nightmare's copies next turn). Then: a player built at 3 HP with Royal Poison survives the start; the Waterfall Giant's eruption past 100 (`DeathBlow` 150) is found.

**Rules**: Rolling Boulder hits one enemy after another (Ironclad with 10 Rolling Boulders against the pool's first multi-enemy encounter; the check fails if the pool has none); Thorns kill during a Sly play with no game error; a loadout's relics give their potion slots, in a combat and in a run at ascension 4; a death inside the player's own action, or as the first turn starts, still ends its combat in the record; the observation shows what a card gathers in a combat: Murder's number, a Spiral's replay, a Glam spent once its card is played.

**Worlds and clones**: a world restores after card prompts (Toasty Mittens and Survivor, 6 worlds); the SL world shows the run's combat, plays as the run does, and restores; the SL clone stops at its node's exit and refuses to step past it; the SL clone keeps relic state the save drops (the first relic set to disabled by hand).

**Cycles** (the Silent against 535 HP, 300 nodes): Monologue and two Flash of Steel draw each other; the SL planner (beam 8) repeats the cycle to a win and the SL world ends the combat as planned, and PIMC over 2 worlds finds that its line repeats. Then the same with a prompt in front of the cycle: Particle Wall costs stars until Touch of Insanity makes it free, which `p0` would give to Haze.

**The SL plan holds** (the second combat of a run, 150 nodes, beam 4): the SL world ends its combat as planned (a win) and refuses to step past it; the run, played again to that decision, follows the plan step for step; the combat ends as the plan's value says, within 1e-9.

**With `--workers N`**: pooled PIMC matches in-process PIMC on 4 decisions, each with a budget of 4 worlds × 120 nodes; the pooled planner plans what the planner plans in one process; no game errors in workers; no worker restarts.

At the end it prints draw-order statistics, which are not a check. Results of 2026-10-27: every check passed, with 60 of 60 builds for the Silent, 58 of 58 for the Ironclad, and 57, 57 and 58 for the Silent's elite and boss fights of acts 1, 2 and 3 ([Combats §5](/en/arch/simulator/combat/#sec-5)).

## 6. `run --check`

What `run --check` compares, for every run it plays ([Whole runs §6](/en/arch/simulator/runs/#sec-6)):

| check | required |
|---|---|
| each observation's JSON round trip | exact |
| a second play over the wire, to an in-process brain or the `--brain` given | the same trace, observation hashes, summary, map hashes, run record, and decision log (timings aside) |
| every node of the first play, loaded from its checkpoint with its decisions replayed | the run's observations one for one; at the horizon after the travel; refuses another step |
| game errors | none |

The run line then ends with `obs <digest>`, one hash of the run's observation hashes, to compare runs across processes; the summary adds the `determinism:` line. With `--brain`, the brain's decision log is not in this process, so the log comparison compares two empty logs.

## 7. The xUnit tests

`src/Sts2Ai.Tests` holds what runs without the game, 19 classes and 97 test methods: `dotnet test src/Sts2Ai.Tests`. One folder per project tested (`Brain/`, `Harness/`, `SimWorker/`), `BoundaryTests.cs` at the root, and the shared JSON fixtures in `Fixtures.cs` and `Fixtures/`.

| class | what it checks |
|---|---|
| `BoundaryTests` | Brain, Protocol and Harness reach no game assembly, and the check does see GameBridge's `sts2` |
| `Brain/BudgetTests` | names show only what is not the default |
| `Brain/CloneSearchTests` | L0 on a toy clone: a shop is worth its best basket; an event option is worth what its next page gives; a map move is not played; a two-pick prompt finds the best pair; a skipped card reward is not opened again; a state reached twice is searched once |
| `Brain/CombatNetTests` | reads c9-0's test states and a tiny net's (`combat-tiny.json`) as their trainers did; a state in progress is its endings and the potions kept; a bucket the HP held rules out has no weight; a finished state and the bound are `LeafValue`'s |
| `Brain/LeafValueTests` | a loss is 0; a win scores by HP and potions; a combat still going is the combat net's to value, and `LeafValue` refuses it |
| `Brain/LoopSearchTests` | 13 tests: a card that comes back is played again until it kills in one turn, whatever it does to the piles, and the cycle ends where the game ends it; a card that runs out is an ordinary line; a cycle with no lethal stays on its budget; another answer to a prompt is taken if it opens a cycle, and left if not; PIMC repeats a cycle too, and takes such an answer; PIMC's turn plan keeps only a plan that repeats; a prompt is answered by the policy unless the action carries an answer; a prompt that takes cards away or asks for more is no choice for cycles; a pick is part of an action's text |

| `Brain/PimcMemoTests` | lines that look the same but rolled differently are not merged |

## 8. Open questions

1. **Copy or replay.** A snapshot is a recipe, and a restore replays it ([Combats §2](/en/arch/simulator/combat/#sec-2)). A deep copy of the game's object graph would remove the replay's cost, which AlphaZero-style search would need. Decided once profiles show that restoring dominates a search's time.
2. **Run worlds**: how much of the room pools and the odds counters can be inferred from the public record, and how much must come from a prior ([Worlds and the SL clone §8](/en/arch/simulator/worlds/#sec-8)).
3. **Inline execution**: whether running actions inline headless, instead of once per frame, changes anything a player sees; open until runs in the game can be compared with runs here ([Whole runs §6](/en/arch/simulator/runs/#sec-6)).
