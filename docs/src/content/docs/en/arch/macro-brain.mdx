The **macro brain** makes every decision outside combat: the next map point, which rewards to claim, which card to take, what to buy, which event, rest-site or treasure option to pick. It runs in the decision process next to the [combat brain](/en/arch/combat-brain/). Harness routes every non-combat surface to it ([Harness §4](/en/arch/harness/#sec-4)) and gives it worlds from the worker pool, so it can try each option in the real game code before choosing. Every option is scored on one scale: the estimated probability of winning the run.

<Aside title="Status">

L0 v0 exists: `MacroBrain` in Brain, played with `run --macro l0` ([Simulator §5](/en/arch/simulator/#sec-5)). It answers every macro surface and the card prompts outside combat, and values options with V: V v0, or V v2 or pure V from a net file ([Learning §1](/en/arch/learning/#sec-1)); both champions' V is the pure V net v6-3-2 since 2026-10-30 ([Learning §2](/en/arch/learning/#sec-2)). For self-play, `--explore ε` draws the answer of a share ε of its decisions evenly instead, and `--macro-explore T` draws each answer by the same values at softmax temperature T ([Learning §5](/en/arch/learning/#sec-5)). In NoSL, run worlds do not exist yet ([Simulator §6](/en/arch/simulator/#sec-6)), so it predicts each afterstate from the screen instead of applying the option in a world ([§2](#sec-2), L0 v0). In SL, with `--afterstates clone`, it plays each option on the node's clone and searches on through the node's screens ([§2](#sec-2), L0 on the clone). Planned: afterstates from run worlds and multi-step screen search in NoSL, L1, and the `IMacroBrain` interface of [§4](#sec-4).

</Aside>

## 1. Surfaces and shape

The decision screens (surfaces) the macro brain handles. "Randomness after choice" is what is revealed only once the option is taken. "Consequence horizon" is how far the effect of the choice reaches ("run" means the rest of the run).

| surface | options | randomness after choice | consequence horizon |
|---|---|---|---|
| map (next point) | 1–4 | `?` roll, encounter, rewards | rest of act |
| rewards (claim order / skip) | ≤6 | none (gold, potion, relic shown) | run |
| card reward | 3–4 + skip/reroll | reroll result | run |
| deck prompts: upgrade / remove / enchant | deck size | none | run |
| transform | deck size | result card | run |
| choose-a-card / bundle | ≤3 | none | run |
| event / ancient option | 1–4 | event outcome, next page | run |
| shop | stock + removal + leave | none (stock visible) | run |
| rest | rest/smith/lift/dig/… | dig etc. | run |
| treasure | relic choice/skip | none | run |
| potion full | discard/use/skip | none | short |

What these surfaces have in common: few options, a long horizon, cheap to apply, hard to value. A combat turn can have thousands of action sequences; here there are a handful of options, and each one can be tried in a simulated world at almost no cost. The hard part is that the effect of a choice shows up many floors later. The value of an option is always P(win run), as defined on the [Learning](/en/arch/learning/) page, never a shaped score built from HP or points.

## 2. Method

There are two levels. L0 decides every time; L1 is an extra check for close calls.

### L0: afterstate + V

L0 is the default and runs on every decision. An **afterstate** is the situation right after an option has been applied, before anything new happens. Scoring afterstates means that one value function V, which reads a single observation, can score every option on every surface: no separate value per (state, option) pair is needed, and applying an option in a world is cheap.

For each option a, the brain applies it in a world and observes the result. That observation is the afterstate `s'_a`, and its value is `V(s'_a)`.

- **Random afterstates** (transform, event outcome, reroll): NoSL takes the mean over K sampled worlds; SL uses the one true outcome, through the node clone.
- The brain picks the option with the highest value (argmax). Cost: the number of options times (apply + observe + V), far below 1 s.
- **Multi-step screens** (shop: buy several items, then leave; rewards: claim several; event pages): the brain searches the screen's action sequence the way the combat brain searches the actions inside one turn, depth-first ([Combat brain §2](/en/arch/combat-brain/#sec-2)). The leaf value is V at the screen exit. Sequences that reach the same observation are expanded once (deduplicated by observation).

### L1: rollout check

L1 handles close calls and uses the evaluation-time budget. It starts when the top two L0 values are within their confidence interval (CI: the range the true value probably lies in, given the samples so far), so L0 cannot tell them apart. A **rollout** plays the game forward with fast policies to see where an option leads.

For each candidate:

1. Start from its afterstate in sampled run-worlds ([Simulator §6](/en/arch/simulator/#sec-6)).
2. Play forward for H nodes (default: up to the next boss) with fast policies: in combat, the rollout policy or a shallow search; for macro decisions, L0.
3. Pair the candidates with **CRN** (common random numbers): every candidate is played in the same world seeds, so all of them meet the same luck, and the difference between them is far less noisy than with independent samples.
4. The candidate's value is the mean of V at the horizon, or the terminal outcome if the run ends first.
5. Choose by the paired difference and its CI.

Both lines are logged for learning: these counterfactual paired rollouts are the training signal for V at key decisions.

In SL, rollouts that go past the current node still use sampled worlds ([Environments §4](/en/arch/environments/#sec-4)).

### Map

- The decision is the next point only; the brain decides again at every step.
- The L0 afterstate is the observation at the chosen point, before its room starts: the room type is known, but a `?` is still unknown. So V must value the position plus the map still reachable from it. An early V cannot do this, so the baseline evaluator gets **path features**: for the best k paths to the boss, the counts of elite, rest, shop, `?` and monster points, and an estimate of the HP budget for the act.
- Close calls use L1 rollouts, as above.

### L0 v0

Until run worlds exist, `MacroBrain` predicts each afterstate from what the screen shows, with no game code, and takes the option with the highest V; a tie goes to the first legal action.

- **map:** the point is added to the path. V's map features count from there: the expected number of elites, rest sites, shops, treasures and `?` points up to the boss if each next step were picked at random (not yet the best-k path features above). Its plan is the rest of the act's route: each next point along the map's paths as it would choose it if nothing else changed, up to the boss; the mod draws it ([Mod §3](/en/arch/mod/#sec-3)). With V v0 it then keeps to that route: a map decision's options differ only in their map features, and only the position changes those.
- **rewards, card reward, bundle, treasure, shop purchase:** the gold, potion, relic or cards are added and the price is paid.
- **an option that opens a choice** (a card reward, a card removal, smithing) is worth the best pick in it, among the picks the game will offer (an Eternal card cannot be removed), so a choice that would be skipped is not opened. A card reward's cards are listed on the rewards screen, since they are rolled before it shows and opening one to look costs nothing ([Protocol §3](/en/arch/protocol/#sec-3)).
- **rest:** the heal the option shows; smithing is worth its best upgrade, as at the prompt that follows.
- **event:** the option's relic, or death if the button warns of it. Any other option is valued as no change.
- **card prompts:** greedy, one pick at a time while V rises (or while the prompt needs more picks). Removal and transform take the card out, upgrade puts in its upgrade preview (`CardView.upgraded`, [Protocol §1](/en/arch/protocol/#sec-1)), with the numbers and cost it will have, choose-a-card adds it. A prompt that L0's own answer opened (smithing, a removal) takes at least the one pick that answer was valued by: stopping it would not leave the run as it is but cancel back to the screen that opened it, where the same answer comes again. At a rest site, which must be used, that looped until the run was truncated: twice in n2-b0.03's gate, with a V that valued the run unchanged above both the heal and every upgrade.

What it cannot see: an event option's costs and gains are not on the screen as data, so a costly option ties with leaving and wins when listed first (Tablet of Truth takes max HP for every decipher, down to 1); what a relic does beyond being one more relic; what a transform gives. Applying options in run worlds removes all three.

On `promotion-1` (200 runs, Silent A0) L0 beats random macro decisions under both combat policies: with PIMC, floor 19.34 on average and the act 1 boss in 177 runs (combat prompts by `p0`), against 13.68 and 73 (prompts still random); with the `play` placeholder, 11.90 against 8.09 and 60 against 5 ([Combat brain §7.2](/en/arch/combat-brain/#sec-7.2)). It skips fewer card rewards (43% against 58%, with PIMC) and fights fewer elites (0.30 per run against 0.94).

### L0 on the clone (SL)

In SL, with `--afterstates clone` (and `--macro l0`), Harness hands L0 the node's clone at each macro decision and at each card prompt outside combat ([Harness §3](/en/arch/harness/#sec-3)), and L0 plays the options in the real game instead of predicting them (`CloneSearch`, commit `952cb04`):

- **Afterstates.** Each option is played on the clone, and what the game asks next is its afterstate, valued by V. Only the map's moves are still predicted, as in L0 v0: travel is the node's exit, which the clone cannot play past.
- **Search through the node's screens.** While an afterstate is still a screen of the node (not the map, a combat or the run's end), the search goes on over that screen's own actions, potions left out: level by level, a beam keeps the 16 states V values best, up to 1,024 probes in all. A state reached twice (by its afterstate's hash) is searched once. A state is worth the best state after it, or V's value where the search stops; an option, its afterstate's worth. So a shop's purchases, a rewards screen's claims and an event's pages are searched as sequences, as the multi-step screens above describe.
- **Card prompts.** A prompt on the clone is answered by a local search: from no pick (or the fewest picks it needs), each step tries the answers one pick away (one more, one fewer, one swapped), each searched on as above, and moves to the best while it beats the answer it has. Cards the player cannot tell apart count as one. A prompt that needs two or more picks is not searched into from the screen that opens it: its own decision searches it.
- **No way back.** L0 keeps the keys of the run's decisions on the clone, macro decisions and card prompts both. An option whose afterstate is one of them, or the decision itself, is never taken, and deeper in the search such an answer adds nothing (commit `f9b9655`). Without it, skipping a card reward returned to the rewards screen that opened it, the card reward still on it; there the search reached the picks a level later than it first had and valued that card reward at V's value of a state in the middle of the node, above every pick's true end. So skipping won, and back on the rewards screen opening won again: a run of promotion-1 looped from its second decision, and one of pure-1's 3,877 times at the act 1 boss's rewards. Without exploring, only answers that would repeat a decision change.
- **Probes** run in the worker pool, each a load of the clone and a replay of its path of answers ([Simulator §8](/en/arch/simulator/#sec-8)).

The champion's name says `l0 NAME clone`, and a champion file `"afterstates": "clone"`. NoSL and `--afterstates screen` play as before (the same runs on 4 seeds in both environments). Checked: `run --check` plays the same over the wire and replays every node exactly, with no game error (17 runs with `play` in combat, 2 with the SL planner and c2). With the SL planner, a macro decision took 40 ms on average (median 13 ms, at most 0.5 s), 9 s of a 187 s two-run total.

## 3. NoSL vs SL

One macro brain serves both environments, with one value function V; only the source of outcomes differs.

| | NoSL | SL |
|---|---|---|
| in-node random outcomes (event result, transform, reroll, a `?` already rolled) | K samples | exact (node clone) |
| in-node rewards that depend on how the combat was played | — | known (open question 1, [Environments §10](/en/arch/environments/#sec-10)) |
| beyond the node | sampled worlds | sampled worlds |
| value function | V | the same V |

Neow and other Ancient options: SL sees the exact outcome of random options, for example which card the "random rare card" option gives ([Environments §1](/en/arch/environments/#sec-1)).

SL does change values outside combat in principle: from the same state SL wins more often, because it plays every later node better, so a value made for SL would accept more risk (more elites, high-variance events). This is ignored: V is shared, and in SL it is somewhat conservative ([Environments §5](/en/arch/environments/#sec-5)).

## 4. Interface

The planned C# interface. One entry point serves every non-combat surface; Harness routes by surface name ([Harness §4](/en/arch/harness/#sec-4)).

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness §4).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims), or of the act's route on the map
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` is the action to execute now, `Plan` the rest of this screen (on the map, the rest of the act's route), `Candidates` the value, CI and sample count of each possible first action, and `Facts` the statements used to explain the choice.

- Out-of-combat card prompts (upgrade / transform / remove) arrive through the same `card_choice` surface as in-combat prompts; `ChoiceContext.Purpose` says what the prompt is for. Harness routes them by whether a combat is running.
- The macro policy used inside rollouts is L0 with a smaller K. It never recurses into L1.

## 5. Budget

How much search each mode gets:

- **Self-play:** a fixed number of branches (simulated lines of play), so runs are reproducible. L0 always; L1 only on a sampled subset of close calls, to control cost. Those L1 results become training data.
- **Assist:** L0 answers instantly; L1 refines the answer while the human looks at it. The search is *anytime*: it can be stopped at any moment and still returns its best answer so far.
- **Auto (R4):** L0 + L1 under a wall-clock cap.

## 6. Tests

1. Coverage: every macro surface is reached in simulated runs, and the fallback count is 0.
2. Decision panels: a fixed set of (run state, options) cases whose ground truth comes from large paired rollouts. Track how often L0 agrees with the ground truth, per surface; this shows where V is weakest.
3. NoSL counterfactual: same public record, different hidden state (`RoomSet` tails, odds, streams) → the same decision.
4. Determinism with a fixed budget.

## 7. Open questions

1. The horizon H for L1 (next boss or next act), and how strong the rollout combat policy must be. Measure how well each correlates with full-run outcomes.
2. The shop as one decision or as a sequence (the number of possible buy sets grows combinatorially).
3. How much path planning V can learn by itself, compared with explicit path features.
