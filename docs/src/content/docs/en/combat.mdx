In SL, the environment that allows saving and loading, the AI holds a **copy** of the current room: an identical combat, down to which card is drawn next and what each enemy does next turn. So it does not have to guess. Before the fight starts, it plays the combat through many times on the copy, finds the line with the best outcome, and then follows that line in the real combat.

Below is floor 17 of the book's example run: Vantom, the act 1 boss, with the player down to 39/70 HP. The AI thought for 7 seconds at the first decision and got a line of 9 turns and 34 actions. It then followed the line all the way and never thought a second time. At the end of the combat, HP was still 39.

## The copy: why it can try before it plays

The seed decides every random result in the game. Save once on entering the room, replay every action taken since, and the game is back at the present moment, exact down to where its random numbers stand. That is the copy. On the copy, the same actions always give the same results.

The copy goes only as far as leaving this room. What the next room holds, or what the next "?" room turns into, the copy does not show. This boundary is the rule of SL.

So a combat is no longer a gamble but a search for a path: many lines lead from here to the end of the combat, and the task is to find the best one.

## What best means

When a line has been played out, it leaves a run behind: how much HP remains, whether the potions are still there, whether the deck has changed. **V** says what that run is worth. V is a learned function that reads the current state of a run and estimates the chance of winning the whole run in the end. If the combat is lost, the run is over and worth 0.

So the best line is the one with the highest V once it is played out. It need not lose the least HP or kill the fastest: losing a few more HP to keep a potion is the better line whenever V judges the trade worth it. The plan for the boss fight above is worth 0.89, meaning that after playing it out, V gives the run an 89% chance of winning to the end.

Positions in the middle of the search, where the combat is not over, also need a value before they can be compared. That value comes from the combat net: it predicts how the combat will end, and the same V turns that into a chance of winning the whole run.

## One turn: try everything that can be played

A turn is a string of actions: playing cards, using potions and, last, ending the turn. Search starts from the position at the start of the turn, tries every action it can take, and then keeps trying from each new position.

1. **The turn can end at any move.** So a line can stop after any number of cards and does not have to spend all its Energy.
2. **A position seen before is not worked out again.** Strike then Defend and Defend then Strike often reach the same position. Search records the positions it has seen and stops when it reaches one a second time. Otherwise most of its effort would go into repeats.
3. **Two positions are the same only if the hidden parts match too.** Two orders of play may look as if they give the same result, yet one of them used one more random number, so the cards drawn afterwards differ. Treating them as two positions lets search find by itself which order leads to better cards later. Arranging the random numbers this way is exactly what a player who saves and loads can do.
4. **When cards must be chosen, each choice is a branch.** For example, when a card makes you discard a card from your hand, search tries each discard once.
5. **The game really plays out the enemies' turn.** So a turn's result is the position at the start of the next turn: the enemies have made their moves and the new hand is drawn.

Search tries at most 300 moves in a turn. It splits the 300 evenly among the actions that can open the turn, and what an earlier action leaves unused passes to the later ones, so that the budget is not all spent under the first card.

Some cards return to the hand or draw each other, so a turn can go on without end. When search finds that the hand has come back unchanged while the position has moved forward, it does not follow the loop move by move. It treats the loop as one unit: it repeats it 1, 2, 4, 8 … times and sees which number of repeats ends best.

## One combat: keep only the best eight each turn

A turn can end in many ways, and a combat has several turns. If search went on from every one of them, the number would soon be too large to try. So at the end of each turn, search keeps only the 8 positions with the highest value, and the next turn starts from those 8 alone. This method is called beam search.

**Nothing is given up early.** Search does not drop a position because it seems unable to beat the best line so far. A combat can still make the run better along the way, for example by gaining max HP or gold or by growing a card, so a value from the middle of the combat cannot serve as an upper limit. The only cut is that 8.

**First, one line played to the end.** Before the main search, a first pass keeps only 1 position per turn and plays straight through to the end of the combat, so there is a playable line at once. If that line already wins, all that is left is to find a line that wins better, and keeping 4 per turn is enough. If it loses, search uses the full 8 to find out whether a win is possible at all.

**Choosing the plan.** Among all the lines played to the end of the combat, the one with the highest V is the plan. If every line loses, search picks the one that holds out best before dying: if search has missed something, this line has the best chance of a turnaround.

Keeping only 8 is the biggest approximation in this method. A better line may hide among the positions that were pushed out, so most plans are only the best of the lines found, with no guarantee that they are the best of all lines.

## Following the plan

A plan is a string of actions, and each action also records the position the AI should see before playing it. In the real combat, as long as the current position matches the one the plan recorded, the AI plays the next move directly and does not search again. The copy and the real combat run the same game program with the same seed, so every move should match. If one does not, the AI plans again from the current position.

**A losing plan is handled differently.** When the plan expects to lose and search has not looked at every line, it may simply have missed the line that wins. In that case the AI follows the plan for one turn only and then plans again: the rest of the combat is now shorter, so the same search can see deeper. It does this at most three times in a row in one combat, and it plays the third plan to the end, so that a combat bound to be lost is not thought through again every turn.
