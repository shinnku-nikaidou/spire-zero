SL 下，大脑在当前节点的精确克隆上规划战斗：也就是玩家到达这个地图点时的游戏，重播到当前决策（[环境：信息与节点 §7](/arch/environments/information/#sec-7)）。模拟器白白就有这个，因为对局就在它手里。Mod 没有：对局属于真实游戏，而大脑是另一个进程。所以 Mod 保存一份节点的记录，即节点的检查点和玩家此后在节点里走过的每一步，并在每个 SL 决策之前把它发给大脑。然后由一个工作进程载入检查点并重播这些步骤，和它对待自己的节点完全一样（[模拟器：世界与 SL 克隆 §3](/arch/simulator/worlds/#sec-3)–[§4](/arch/simulator/worlds/#sec-4)）。本页讲的是 `NodeRecord.cs`，以及它是如何检查的。

记录在两种环境下都会保存，辅助关闭、没有大脑时也一样，所以在玩家所在的房间里切到 SL 也能用。只有 SL 会把它发出去。

## 1. 记录是什么

| 成员 | 含义 |
|---|---|
| `Node` | 节点的编号：这一局里 Mod 运行期间游戏进入的第一个节点为 0（新的 `RunState` 对象会从 −1 重新开始）；在此之前为 −1 |
| `Checkpoint` | 节点的 SL 检查点，一个 JSON 字符串；节点没有检查点时为 null |
| `Steps` | 节点到目前为止的步骤，每一步是一行轨迹 `surface action`，与模拟器自己的轨迹写法相同：`combat play:3:1`、`map map:4,10`、`card_choice 0,2` |
| `Broken` | 节点无法克隆的原因，或者 null |
| `Running(surface)` | 在这个决策界面上走的一步是否还在进行（[§4](#sec-4)） |
| `Seen(asking)` | 每一帧告诉它画面上的决策，玩家的下一个回答对照它来读 |

只有在节点有检查点且没有中断时，才会加入新的步骤。

## 2. 检查点

**在哪里**。玩家到达一个地图点时，游戏会保存这一局：调用不带已完成房间的 `SaveManager.SaveRun`，调用者是 `RunManager.EnterMapCoordInternal`，此时它已经离开旧房间、清空画面并同步了战斗状态。模拟器也在同一时刻取它的检查点（[模拟器：世界与 SL 克隆 §3](/arch/simulator/worlds/#sec-3)）。Mod 在 `SaveRun` 上的前缀（`Saving`）在已完成房间为 null 时开始一个节点；房间内部的存档（事件的、战斗的）会传入一个房间，不是节点的开始。一局开始时，游戏以同样的方式进入它的第一个点。

**取什么**。`GameBridge.Checkpoint.Take(me)`：游戏的完整存档，即 `SaveManager.ToJson(RunManager.ToSave(null))` 构建出的样子，再加上存档会丢掉的每个遗物的状态（[GameBridge：读取游戏 §7](/arch/gamebridge/observe/#sec-7)）。除了模拟器，它对谁都是不透明的。存档里带着这一局的种子和每条随机数流的状态；SL 可以知道它们，因为克隆重播的是这个房间的真实结果（[环境：信息与节点 §2](/arch/environments/information/#sec-2)）。

**继续的一局**。载入一局存档时，游戏会重新进入存档所在的点，但不存档（`RunManager.LoadIntoLatestMapCoord`），所以 Mod 也给它打了补丁（`Continuing`）：

- 到达时存的档（存档里没有已完成房间）：节点像到达时那样开始，在这里取检查点；
- 房间里更晚时候存的档（打完战斗后、见过先古之民后）：房间的开头已经不在了，节点从一开始就是中断的：「the run was continued from a save made after this room began」（这一局是从本房间开始之后的存档继续的）。

**开始一个节点**（`Enter`，`NodeRecord.cs:149-158`）：只在单人对局里；`Node` 加一；清空步骤和画面；取检查点，或者把节点标为中断。取检查点时抛异常，节点就没有检查点（「no checkpoint was taken」），并把错误记进日志。

Mod 从不写会被云同步的 `current_run.save`，也不写档案下的任何其他文件：这个前缀只读。

## 3. 每一步，在游戏提交它的地方

玩家的每个决策都在游戏提交它的地方读取：也就是模拟器自己启动动作时也调用的那些入口（[GameBridge：各决策界面的动作 §7](/arch/gamebridge/actions/#sec-7)）。所以在游戏执行之前，这一步就被精确地知道了，并用 GameBridge 自己的辅助函数命名，因此记录下来的一步，就是模拟器本来会打出的那个动作。

| 玩家 | 挂钩的方法（Harmony 前缀） | 步骤 |
|---|---|---|
| 出牌、使用或丢弃药水、结束回合、移动 | `ActionQueueSynchronizer.RequestEnqueue`，动作为 `PlayCardAction`、`UsePotionAction`、`DiscardPotionGameAction`、`EndPlayerTurnAction`、`VoteForMapCoordAction` | `combat play:C[:T]`、`combat potion:S[:T]`、`combat end_turn`；在战斗外，是药水栏的 `potion:S` 或 `discard_potion:S`，记在使用它的那个画面上；`map map:C,R` |
| 回答选牌提示、卡牌奖励、卡包 | `PlayerChoiceSynchronizer.SyncLocalChoice` | `card_choice I,J`（游戏自己的序号）、`card_reward card:I` 或 `card_alt:ID`、`bundle bundle:I` |
| 选择事件选项、休息处选项 | `EventSynchronizer.ChooseLocalOption`、`RestSiteSynchronizer.ChooseLocalOption` | `event event:I`、`rest rest:ID` |
| 领取奖励、从奖励画面继续 | `RewardsSetSynchronizer.SelectLocalReward`；在奖励画面上的 `SkipLocalRewardsSet`、`RunManager.ProceedFromTerminalRewardsScreen`、`ActChangeSynchronizer.SetLocalPlayerReady` | `rewards reward:I`、`rewards rewards_done` |
| 拿取或跳过宝箱的遗物 | `TreasureRoomRelicSynchronizer.PickRelicLocally` | `treasure relic:I`、`treasure relic_skip` |
| 购买、删牌 | `MerchantEntry.OnTryPurchaseWrapper`、`MerchantCardRemovalEntry.OnTryPurchaseWrapper` | `shop buy:I`、`shop remove` |
| 占卜 | `CrystalSphereMinigame.CellClicked` | `crystal_sphere big:X,Y`、`crystal_sphere small:X,Y` |
| 离开事件、商店、休息处 | 地图要求选择移动时（[§5](#sec-5)） | `event proceed`、`shop leave`、`rest leave` |

让每一步都精确的细节（`NodeRecord.cs:162-271`）：

- **出牌的卡牌**取自动作的 `NetCombatCard`：动作要到执行时才去找它的卡牌，所以在加入队列时读 `PlayCardAction.Card` 会读不到。只有需要选目标的牌和药水才保留目标，与合法动作的写法一致（`CombatActions.PlayOf`、`PotionOf`）。
- **药水**在战斗中使用（`WasEnqueuedInCombat`）时是战斗的一步；在战斗外，它是药水栏在使用它的那个画面上的动作，前提是那个画面提供这个动作。
- **移动**必须是地图提供的一个。
- **选牌提示的选择**是游戏自己的序号，指向按游戏顺序排列的选项，即读取提示时保存下来的 `Source`；跳过的单选（−1）表示什么都不选。大脑用规范序号回答（[主循环 §5](/arch/mod/loop/#sec-5)）；轨迹保存游戏的序号，和模拟器的轨迹一样。
- **卡牌奖励**的选择是一个序号，先数画面上的卡牌，再数它的替代选项，游戏和合法动作都是这样列出的。
- **奖励**的序号是它在奖励画面的奖励组里的位置。
- **不算一步**：什么都没改变的购买（金币不够、已售罄），或者免费的购买（`ignoreCost`，由遗物替玩家购买）；什么都没揭开的占卜；离开宝箱、离开没有奖励的战斗时的调用，它们和奖励画面上「继续」用的是同样的调用：只有在奖励画面上的才算步骤，而有些画面会调用其中两个，所以由第一个调用清掉记下的画面。
- **比画面稳定得还快**。钩子在提交时触发，而不是在空闲检查时，所以玩家间隔不到 3 帧走出的几步也照样按顺序记下。

为什么用钩子，而不是比较前后的状态：比较分不出同一张牌的两份副本，也会漏掉玩家在画面稳定之前就排进队列的动作。这解决了如何捕获玩家动作这个未决问题。

## 4. 还在进行的步骤

事件选项、休息处选项、奖励、购买和占卜都作为游戏自己的任务运行，画面要等任务结束才显示这一步的结果。在那之前，画面显示的仍是它回答过的那个决策：例如事件在选项之前的金币。所以同样这些入口上的后缀补丁（postfix）会按这一步所在的决策界面记下它的任务（事件的任务取自同步器里待完成的选项任务），`Running(surface)` 说明是否还有任务在运行；在它结束之前，`Assist` 不在那个决策界面上发问（[主循环 §7](/arch/mod/loop/#sec-7)）。模拟器在下一个决策之前，也以同样的方式等待它正在运行的任务（[模拟器：整局 §3](/arch/simulator/runs/#sec-3)）。

## 5. 离开房间

在模拟器里，离开事件、商店或休息处本身就是一个决策：`proceed` 或 `leave`。在游戏里，玩家只是打开地图然后移动。所以 Mod 在地图要求选择移动时记下离开：在这些画面之后第一次看到地图时，或者在最后看到的画面不是地图的情况下有一次移动被加入队列时，就为这个房间的决策界面加上离开这一步，前提是那个画面提供了它（`Leave`，`NodeRecord.cs:116-133`）。移动本身随后记为 `map map:C,R`。

## 6. 中断的记录

如果某一步在模拟器里没有对应的决策，这个节点余下的记录就到此为止：克隆无法越过它继续重播。

| 日志里的原因 | 发生了什么 |
|---|---|
| 「a potion thrown away in combat」 | 模拟器在战斗中不提供丢弃 |
| 「a turn end taken back」（收回了结束回合） | `UndoEndPlayerTurnAction` |
| 「a travel to X, which the map does not offer」（移动到地图不提供的 X） | |
| 「potion:S on a screen that does not offer it」 | 在战斗外、在不提供它的画面上使用药水栏动作 |
| 「a card picked outside the prompt's options」（选了提示选项之外的牌） | |
| 「a card reward closed unanswered」（卡牌奖励没有回答就关掉了） | |
| 「a T choice on S」 | 在 Mod 不读的画面上做出的选择，或者一个没带上下文的选牌提示 |
| 「a reward taken from no rewards screen」（不是从奖励画面领取的奖励） | |
| 「Type: message」 | 受保护的钩子内部抛出的异常，也作为错误记进日志 |
| 「no checkpoint was taken」、「the run was continued from a save made after this room began」 | 节点从来没有检查点（[§2](#sec-2)） |

每次中断只记一次日志，带上节点和它的步数：「SL record of node N broken after K steps: …」。

**钩子从不让异常传到游戏里**。钩子运行在游戏自己的调用内部，所以由 `Guard` 捕获异常，改为让记录中断：它包住存档和继续游戏的钩子、动作队列、各种选择、休息处选项、购买和占卜。事件选项、奖励、继续和遗物的钩子以及任务的后缀补丁只是加一行或一个任务，没有包住。

**节点中断意味着什么**。这个节点里不询问 SL 的战斗决策：面板显示「No SL clone of this room」（这个房间没有 SL 克隆），附上原因和「the next room has one」（下一个房间会有）。选牌提示和战斗以外的决策照常询问，询问时不发送节点消息。这正适合 Mod 通常连的那种大脑：NoSL 冠军的文件加 SL 规划器（选牌提示用 `p0`，L0 用画面上的后状态，都不需要克隆）。宏观一侧在克隆上下的大脑（`--afterstates clone`，即 SL 冠军的）这时会用上一个节点的检查点和步骤来构建克隆，而在还没有任何检查点之前，则会以「an SL decision before any node checkpoint」失败，这会让 Mod 关闭到下一个 `hello` 为止（`Harness/Dispatcher.cs:200-206`）。把中断节点里的每个 SL 决策都扣下不问，就能补上这个缺口。

## 7. 发送什么，何时发送

每个 SL 决策之前，`Assist.SendNode`（`Assist.cs:165-174`）发送大脑还没收到的东西（[协议：线路 §6](/arch/protocol/wire/#sec-6)）：

1. `node_checkpoint`，带上节点的编号和检查点，每个节点一次：当这个节点与这一局里上一次发送的节点不同时；
2. 每个还没发送的步骤一条 `node_action`，带上节点的编号和这一步在节点里的编号（从 0 开始）。

然后才是 `decision`。节点最后一个决策之后的步骤（例如它的移动）永远用不到，也从不发送。没有检查点的节点什么都不发。`gauntlet` 从不设置：真实游戏里没有连战（[模拟器：整局 §7](/arch/simulator/runs/#sec-7)）。重新连接或新的 `hello` 之后，当前节点会从它的检查点开始重新发送。

大脑里的 Harness 保存最新的检查点和它的轨迹，并要求一局之内节点编号递增（[Harness §4](/arch/harness/#sec-4)）。NoSL 下照样保存记录，但从不发送；如果宿主真的发了，会收到 `error`，因为 Harness 在 NoSL 下拒绝节点检查点。

## 8. 在游戏里检查

**往返**。`brain --wire FILE` 写下宿主发来的每条消息。`clones --wire FILE` 把它们读回来：`hello` 设定环境，`node_checkpoint` 开始一个节点，`node_action` 行必须按顺序跟在后面。对每个 SL `decision`，它载入克隆，即检查点加上这个决策之前发出的步骤（`RunSession.Load`），并检查克隆接下来问的是同一个决策，观测逐项相同；不同时，指出第一个不同的 JSON 路径、游戏的值和克隆的值。在任何检查点之前的决策单独计数。它打印有多少个 SL 决策问的相同，只要不是全部相同就以 1 退出（`Commands/Clones.cs`；[模拟器：参考 §4](/arch/simulator/reference/#sec-4)）。

**结果**。

- 在模拟器自己的导出上（一局连到 `brain` 上打的 SL 对局，455 个决策），每个决策都相同。
- 在真实游戏里，开着辅助打的一局 SL 对局的第 2–5 层（4 个节点：3 场战斗和 1 个事件），90 个 SL 决策中有 89 个相同。另一个是在事件选项还在运行时问的，所以画面上显示的还是选项之前的金币；Mod 现在会等这一步的任务结束（[§4](#sec-4)）。
- 更早一次第 1–2 层的记录曾发现出牌没有被记下来，因为排进队列的出牌要到执行时才去找它的卡牌（[§3](#sec-3)）。
- 加上任务等待之后的一次更晚的记录（2026-10-28，`tmp/assist/`，本地）包含大脑眼中的三局：SL、NoSL，再一局 SL：150 个决策，其中 149 个是 SL（战斗 87、奖励 21、地图 11、选牌提示 11、卡牌奖励 6、事件 5、商店 4、休息处 2、卡包 1、宝箱 1），12 个节点检查点和 137 个节点动作；最后那局 SL 走了 11 个节点，到第 11 层。有没有对它运行过 `clones`，没有记录。

**SL 规划器的等待时间**，取自把第 2–5 层的记录在运行游戏的那台机器上对一个新启动的大脑重播（`plan` c2，8 个工作进程上 beam 8×300）：一场战斗的第一个决策要 3–15 秒，因为它规划整场战斗；抽牌或敌人偏离计划时的重新规划要 1–11 秒；66 个战斗决策中其余的 56 个按计划走，不到 50 毫秒。战斗以外的决策不到 20 毫秒。
