NoSL 下，战斗大脑只知道玩家知道的东西：屏幕，以及能从屏幕推断出的内容。它不知道抽牌堆的顺序、一个随机效果会掷出什么，也不知道怪物在意图背后排好的是哪一招。它不能在真实战斗上规划，因为它不许看真实战斗。

所以它在自己构建的战斗上规划。**PIMC**（完美信息蒙特卡洛）抽取 $K$ 个完整的世界，包括隐藏的部分，每个都与玩家见过的一切相符；把每个世界当作没有隐藏信息的普通游戏来搜索；再把结果取平均。答案就是在这些世界上平均最好的动作。NoSL 冠军用 8 个世界、每个世界 300 个节点，以战斗网络 c2 为叶子（`run --policy pimc`）。

本章分三节：什么是隐藏的、世界怎样做出来（本页），每个世界里的搜索和平均（[搜索](/arch/pimc/search/)），以及预算和结果（[预算](/arch/pimc/budget/)）。这个思路在两种环境中的位置，见[环境](/arch/environments/)。

## 1. NoSL 看不到什么

一场战斗的**隐藏状态** $s$ 有三样：抽牌堆的顺序，每条随机数流的位置（游戏的所有随机性都取自带种子的随机数流），以及每个怪物在显示它当前意图的几招里排好的是哪一招。**公开记录** $h$ 是观测，加上每个敌人在每回合开始时显示过的意图（[战斗大脑：提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)）。

怪物是最微妙的部分。每个怪物用游戏代码里的一个出招状态机来选招，混合了三种规则：

- **固定循环**（攻击、防御、攻击……；或者蓄力，然后大招），给定已出过的招就是确定的；
- **带约束的加权掷骰**：例如 60% 攻击、40% 增益，但同一招不能连出三次，或者某一招之后必接另一招；
- **条件**：生命值低于一半时换一套招，或者几个敌人轮流行动。

掷骰用的是这个怪物自己的随机数流，由这一局的种子决定：同一个种子给出同样的招，这是 SL 可以利用的。玩家永远看不到这条流，所以一次掷骰在它的意图显示出来之前都是未知的。本回合的招总是已知的，因为它的意图显示着。玩家很快就能摸清一个怪物，是因为约束给掷骰留下的余地很小；仍然未知的，正是这些掷骰。战斗网络也是同样的情况：根据记录，它对 57.7% 的敌人说中了下一回合的意图类型，而重复当前意图只有 28.9%，它猜错的大多落在掷骰上（[战斗大脑：叶子 §3](/arch/combat-brain/leaf/#sec-3)）。

## 2. 采样世界

一个世界是与 $h$ 相符的 $s$ 的一个样本：一场完整的战斗，在 worker 自己的游戏副本里构建出来，显示的正是玩家看到的观测。它由两步做成。

**构建**（`CombatBuilder.Setup(observation, seed)`，[模拟器：战斗 §5](/arch/simulator/combat/#sec-5)）做出一场显示这个观测的战斗：

1. 用观测里的牌组、遗物和生命值开始这场遭遇；
2. 覆盖可见状态（`Apply`）：回合数，敌人（增、删、排序），生命值和格挡，能量，金币，药水，充能球，遗物计数器，能力及其层数，四个牌堆及每张牌的修改，以及意图；
3. 抽取隐藏状态（`Resample`）；
4. 按路径逐一比较重建的战斗的观测和输入（`BuildDifferences`）：为空表示完全一致。

屏幕显示的东西常常是它不显示的数字的函数，每种能力和遗物都不同，所以一个**旋钮求解器**（knob solver）逐个尝试内部的数字（数值、字段、能力的私有数据），直到显示一致。意图的匹配方式是：为每个怪物在显示这些意图的招里选一个。每个怪物的**出招日志**由公开记录重建，让它的状态机像真实的那个一样继续下去：之前的一个回合匹配显示相同意图的招（否则匹配类型和段数相同的，再否则只匹配类型相同的）。

然后**确定化**（`Determinize(seed)`，[模拟器：战斗 §3](/arch/simulator/combat/#sec-3)）把玩家不可能知道的一切换成一个样本，可见状态保持不变：

- 每条随机数流重新播种；
- 抽牌堆先按卡牌键排序（这个顺序只取决于玩家看得到的东西），再洗牌（Fisher–Yates）；
- 手牌以外的牌重新编号，因为游戏按抽牌顺序给牌编号，旧的 id 会把顺序泄漏出去；
- 每个怪物排好的招在显示相同意图的招里均匀抽取。

世界 $k$ 就是构建好的战斗加上 `Determinize(seed_k)`，其中 $\text{seed}_k$ 由搜索的种子和 $k$ 混合而成。之后所有这些，打牌、掷骰和敌方回合，都由真正的游戏代码来执行；没有任何网络去模拟什么，叶子只给路线停下的地方估值。

下图取一个真实的 NoSL 决策，即对骇鳗的精英战的第一个回合（[搜索 §3](/arch/pimc/search/#sec-3)），用同样的方式给它的抽牌堆排顺序：先排序，再用每个世界的种子洗牌。这些世界是页面用自己的随机数生成器抽的，所以不是对局里搜索的那 8 个世界，但属于同一种世界。一张牌出现在接下来几张里的概率，在很多个世界上会趋近精确值；只有 8 个世界时它很粗糙，这就是[搜索 §3](/arch/pimc/search/#sec-3) 讲的噪声。

## 3. 世界有多忠实

从观测构建的世界，除了 `Determinize` 有意采样的部分以外，打起来应该和真实战斗一样。`fidelity` 衡量这一点：在测试集战斗里每隔一个决策，真实战斗用一个占位策略继续打到回合结束，包括敌人的回合；从这个决策的观测和记录构建出来的战斗，拿到真实战斗的采样状态，打同样的动作；统计第一个不同的观测（[模拟器：战斗 §6](/arch/simulator/combat/#sec-6)）。用静默猎手的初始牌组（2026-10-27）：

| 战斗 | 决策数 | 直到敌人回合结束都相同：无记录 → 有记录 |
|---|---|---|
| 第 0 幕普通战斗，30 | 459 | 82.4% → 96.3%；加上眩晕的后续是 97.4% |
| 第 1 幕普通战斗，30 | 478 | 88.7% → 98.1%；加上眩晕的后续是 99.0% |
| 第 0 幕 Boss，9 | 201 | 96.5% → 96.5% |
| 第 0 幕精英，15 | 289 | 99.0% → 99.0% |

没有构建错的战斗，构建出的战斗里也没有不合法的动作。回合内不同的最多 1%。其余在回合结束之后才出现不同，原因是少数怪物内部的计数器（一只老鼠的召唤、一个巨人不断增长的伤害），任何观测都看不到它们。把普通战斗从 82–89% 提到 96–98% 的，正是出招记录。构建器仍在近似的部分：本回合的历史，能力和怪物内部的计数器，费用修正的持续时间，玩家减益的衰减，以及把见过的每张牌都当作牌组。

整局里，构建错的世界会让这个决策失败。最早的 400 局 PIMC 对局里有 5 局这样失败：用完的白银熔炉的隐藏计数（三局），玻璃充能球的数值，以及只有提示框里才写出的懒惰的上限（世界里每回合能打的牌比真实战斗少，一张合法的牌在世界里变得不合法）。这三处都已修复（[模拟器：战斗 §6](/arch/simulator/combat/#sec-6)）。

## 4. 公平规则

NoSL 的规则是：一个决策只取决于公开记录（[环境](/arch/environments/)）。搜索的构造使它不可能违反这条规则：

- **只有观测离开宿主**。worker 拿到的是观测、记录和种子，从不拿到真实的战斗（[战斗大脑：提示、招式与 worker §3](/arch/combat-brain/shared/#sec-3)）。每个世界都从观测构建，从不从真实战斗构建，所以世界里的隐藏状态是这个世界自己的样本，其中没有任何东西来自真实的游戏。
- **种子来自调用方**。`Determinize` 的种子来自搜索，从不来自这一局。
- **叶子读的是观测**。`LeafValue` 和战斗网络都不读隐藏状态（[战斗大脑：叶子 §1](/arch/combat-brain/leaf/#sec-1)）。
- **处处走同一条路径**。评估阶梯的第一级，即模拟器，构建世界的方式和 Mod 将来从真实游戏构建的方式相同：决策时没有「对真实状态做确定化」的捷径（[评估 §2](/arch/evaluation/#sec-2)）。对真实状态做确定化只保留给测试和基准测试。
- **规划中**：一个反事实测试，公开记录相同而隐藏状态不同，在固定的大脑种子下必须给出相同的选择。
