每个决策界面（surface）在 `src/Sts2Ai.GameBridge/Actions/` 里有一个静态类。它们的形状相同：

| 成员 | 做什么 |
|---|---|
| `Screen(…)` | 这个决策界面的画面，即它的协议视图（[协议：观测与动作 §5](/arch/protocol/observation/#sec-5)） |
| `Legal(…)` | 合法动作，以文本表示，顺序固定 |
| `Start(…, action)` | 通过游戏按钮所发出的调用来执行这个动作；动作不合法时抛异常 |

宿主取来每个类要读的东西（当前事件、商店的库存、休息处的选项），并判断是哪个画面在提问。`Start` 开始游戏的工作然后返回；宿主让游戏运行，直到它稳定下来（[模拟器：整局 §3](/arch/simulator/runs/#sec-3)）。如果这项工作是画面会 await 的一个任务，`Start` 就返回这个任务。

## 1. 战斗

`CombatActions`（`Actions/CombatActions.cs`）：

- **`WaitingForInput(player)`**：玩家可以行动。有战斗正在进行，轮到玩家一方，处于出牌阶段，动作执行器空闲，且玩家动作没有被禁用。无头时这就够了；在真实游戏里画面也必须准备好，这由 Mod 在它自己的画面节点上检查（[Mod：主循环 §4](/arch/mod/loop/#sec-4)）。
- **`Legal(state, player)`**：先是手牌，按手牌顺序；然后是药水，按槽位；最后是 `end_turn`。
  - 每张牌只用 `CanPlay()` 检查一次（它要做四次钩子分发，所以不按目标重复）。以任意敌人为目标的牌，对它可以瞄准的每个敌人都合法；以任意盟友为目标的牌，对每个盟友都合法；其他牌合法一次，不带目标。
  - 药水合法的条件是：玩家可以使用药水，槽位里有一瓶还没排进队列的药水，它通过自己的可用性检查，并且可以在战斗中使用（仅限战斗或随时可用）；目标的处理方式相同，敌人只在存活时才算。
  - `end_turn` 永远合法。
- **`Start(state, player, action)`**：出牌经过 `CardModel.TryManualPlay(target)`，即从手牌拖出时发出的调用，它检查目标并把出牌加入队列，拒绝时抛异常；药水经过 `PotionModel.EnqueueManualUse(target)`；结束回合则经过一个带回合编号的 `EndPlayerTurnAction`，像结束回合按钮那样加入队列。
- **`PlayOf(card, target)`、`PotionOf(player, slot, target)`**：按 `Legal` 的命名方式给一次出牌或一次药水使用命名，只在卡牌或药水需要选目标时才保留目标。Mod 用它们记录玩家做了什么：画面对其他卡牌也会传入一个目标（对自身生效的牌传入玩家）。
- **`HandCard(pcs, uid)`、`Creature(state, uid)`**：找到一个 uid 指代的东西；遇到未知的 uid 时抛异常。

## 2. 地图

`MapActions`（`Actions/MapActions.cs`）。动作是 `map:COL,ROW`；画面列出的是同样那些点。

- **Legal**（`Travelable`，即地图画面的 `RecalculateTravelability` 的规则）：还没有去过任何点时，是起点；在双 Boss 的一幕里，打完 Boss 之后紧接着是第二个 Boss；最后一行之后是 Boss；其他情况用游戏自己的 `MapTravel.GetTravelablePointsFrom`，即这个点的子节点，或者在某个钩子允许自由移动时（`Hook.ShouldAllowFreeTravel`），下一行的每个点。先按行、再按列排序，因为游戏里的子节点是一个哈希集合。
- **Start**：为这个点加入队列的一个 `VoteForMapCoordAction`，与点击一个点时地图画面把它加入队列的方式相同。
- `Text(coord)` 按动作的方式命名一个坐标；Mod 用它记录玩家的移动。

## 3. 奖励、卡牌奖励和卡包

**`RewardActions`**（`Actions/RewardActions.cs`），动作是 `reward:i` 和 `rewards_done`：

- **Screen**：每个还没领取的奖励，按它在这组奖励里的索引，带上它的种类：`gold` 及其数额，`potion` 或 `relic` 及其 id，`card` 及打开时会显示的牌，`special_card` 及它的牌（在游戏里是私有的，从按钮的悬停提示读取），`remove_card`。
- **Legal**：每个还没领取的奖励，按它的索引，但药水栏满时的药水奖励除外（它留在画面上，但要等空出一个槽才能领取）；`rewards_done`，除非这组奖励不允许跳过且还有奖励没领。链接的奖励组（多选一）会抛异常：这个游戏版本里没有用到。
- **Start**：`RewardsSetSynchronizer.SelectLocalReward`，与奖励按钮的做法相同；奖励结算完时任务结束。
- **`Proceed(run, set)`** 就是 `rewards_done`，即继续按钮：不是房间最后一组的奖励，跳过剩下的并关闭（`SkipLocalRewardsSet`）；Boss 之后或在胜利房间里（双 Boss 一幕的两个 Boss 之间除外），它为换幕做好准备（`ActChangeSynchronizer.SetLocalPlayerReady`）；其他情况下，这个房间的奖励结束（`ProceedFromTerminalRewardsScreen`）。`IsTerminal(set)` 说明一组奖励是不是房间的最后一组：它的房间是战斗房间。

**卡牌奖励**不用启动：是游戏来提问。卡牌奖励从奖励内部打开自己的画面，由游戏的选牌器回答：`CardRewardLegal` 为每张牌列出 `card:i`，为每个还没用掉的替代按钮列出 `card_alt:ID`（跳过、重抽、遗物添加的按钮）；`CardRewardAnswer` 把选中的动作变成选牌器的回答。重抽让画面保持打开，也仍然列在其中，但第二次什么都不做（`KeepsScreenOpen`），所以宿主为每个画面保存一组已用掉的替代选项。

**`BundleActions`**：卡包选择（卷轴箱的卡包）用同样的方式、经过选牌器回答：`Legal(n)` 是每个卡包一个 `bundle:i`，不能跳过；`Index` 把动作变成卡包的索引。无头时，游戏的测试模式总是拿第一个卡包；模拟器给 `CardSelectCmd.FromChooseABundleScreen` 打补丁，让它改走画面自己的路径（预留这次选择，询问驱动程序，同步回答）（[模拟器：无头宿主 §4](/arch/simulator/headless/#sec-4)）。

## 4. 事件和水晶球

**`EventActions`**（`Actions/EventActions.cs`），动作是 `event:i` 和 `proceed`：

- **Legal**：事件结束之后只有 `proceed`；否则是每个没有锁定的选项，记作 `event:i`。标记为继续按钮的选项是 UI 按钮，不是选择：先古之民的 PROCEED 列为 `proceed`，其他的（Trial 的 DOUBLE_DOWN，它会打开放弃本局的弹窗）永远不合法。
- **Start**：`EventSynchronizer.ChooseLocalOption(i)`，它在后台运行这个选项。`proceed` 不改变游戏里的任何东西：由宿主打开地图。
- **Screen**：事件的 id，当前页的本地化键，以及每个选项，带它的文本键、`locked`、先古之民的选项给的遗物、它的悬停提示的 id（升级过的牌带 `+`），以及它的按钮是否警告它会杀死玩家。

**`CrystalSphereActions`**（`Actions/CrystalSphereActions.cs`），水晶球（CRYSTAL_SPHERE）事件的小游戏：一张由隐藏格子组成的网格，每次占卜消耗为数不多的次数中的一次：

- **Legal**：先是 `big:X,Y`，用于其 3×3 区域（在边缘处截断）里有隐藏格子的每个格子；然后是 `small:X,Y`，用于每个隐藏格子。提供小工具，是为了让玩家能避免揭开诅咒。
- **Start**：先用这个工具调用 `SetTool`，再对这个格子调用 `CellClicked`，与画面的做法相同；小游戏结束后会抛异常，最后一次占卜之后它就结束了。
- **Screen**：每一行是一个字符串，`#` 表示隐藏，`.` 表示空，或者是已揭开格子露出了一部分的那件物品的字母（`R` 遗物，`P` 药水，`C` 卡牌奖励，`G` 金币，`X` 诅咒；不认识的物品类型会抛异常），以及剩余的占卜次数。物品的所有格子都揭开之后就赢得它。`Of(game, cell)` 按动作的方式命名一次点击，供 Mod 记录。

## 5. 商店、休息处和宝箱

**`ShopActions`**（`Actions/ShopActions.cs`），动作是 `buy:SLOT`、`remove`、`leave`：

- **槽位**给商店的商品编号，即除删牌以外的所有条目，按游戏的顺序（角色卡牌、无色卡牌、遗物、药水），售罄的也算在内，所以购买之后槽位保持原来的编号。
- **Screen**：按槽位列出有货的商品，每件是一张卡牌（它的视图、价格、是否打折），或者一件遗物或一瓶药水（它的 id 和价格）；删牌服务的价格，除非已经用过。
- **Legal**：有货且买得起的条目；药水还需要药水栏有空槽，并且游戏允许获得药水（`Hook.ShouldProcurePotion`；添水禁止获得），因为不满足时购买会失败，什么都不会改变；删牌有货且买得起时提供 `remove`；`leave` 总是合法。
- **Start**：条目的 `OnTryPurchaseWrapper(inventory)`，即点击商品时发出的调用；删牌的这个调用会通过选牌器询问要删哪张牌。在游戏里，删牌随后由商店的删牌按钮标记为已用，不管是谁买的（玩家或领主阳伞）；无头时没有按钮，所以由一个补丁在购买成功后标记它（`Choices.CardRemovalUsed`）。`leave` 什么都不改变：由宿主打开地图。

**`RestActions`**（`Actions/RestActions.cs`），动作是 `rest:ID` 和 `leave`：

- **Legal**：每个可用的选项，按它的 id（`rest:HEAL`、`rest:SMITH`）；某个选项成功之后，或者没有可用选项时，提供 `leave`。有没有选项成功由宿主来说：模拟器按房间记录，Mod 读取继续按钮。
- **Start**：`RestSiteSynchronizer.ChooseLocalOption(i)`；任务结束时给出这个选项是否成功（在提示里取消的锻造不算成功）。
- **Screen**：每个选项的 id、是否可用，对 HEAL 还有它恢复的生命值（`HealRestSiteOption.GetHealAmount`），这个值会被遗物改变。

**`TreasureActions`**（`Actions/TreasureActions.cs`），动作是 `relic:i` 和 `relic_skip`：合法的是宝箱里的每件遗物，以及跳过；`Start` 像遗物按钮那样投票（`PickRelicLocally`、`SkipRelicLocally`）。打开宝箱不是一个决策：模拟器自己打开它，玩家则点击它（[模拟器：整局 §3](/arch/simulator/runs/#sec-3)）。

## 6. 药水栏

`PotionActions`（`Actions/PotionActions.cs`）是战斗外的药水栏，遵循游戏药水弹出菜单的规则：随时可用且通过自身检查的药水给出 `potion:S`，任何还没排进队列的药水给出 `discard_potion:S`；玩家不能使用药水或已经死亡时什么都没有。`Start` 通过 `EnqueueManualUse` 喝下药水，或者通过加入队列的 `DiscardPotionGameAction` 扔掉它。`Handles(action)` 区分药水栏动作和画面自己的动作，这样宿主就能把药水栏加进一个画面的合法清单，并把回答转给正确的一方。

哪些画面带药水栏由宿主选择：模拟器和 Mod 把它加到地图、奖励、事件、商店、休息处、宝箱和水晶球画面上（[模拟器：整局 §4](/arch/simulator/runs/#sec-4)）。

## 7. 指代动作作用的对象

| 对象 | 指代方式 | 原因 |
|---|---|---|
| 手牌里的一张牌 | 它的 uid，即它在这场战斗的卡牌数据库里的 id | 手牌变化时仍然成立；在模拟器和游戏里相同 |
| 一个生物 | 它的 uid，即它的 `CombatId` | 同上 |
| 选牌提示的一个选项 | 它的规范索引 | 游戏的顺序可能跟随隐藏状态（[读取游戏 §5](/arch/gamebridge/observe/#sec-5)） |
| 一个奖励、一个事件选项、一个商店槽位、一件宝箱遗物、卡牌奖励里的一张牌 | 它在画面自己的列表里的索引 | 顺序是公开的，就是画面显示的顺序 |
| 一个休息选项、一个卡牌奖励替代选项 | 它的 id | 选项被禁用或增加时，id 不变 |
| 一个地图点 | `col,row` | |
| 一个水晶球格子 | `x,y` 加上工具 | |

战斗以外的文本动作由 `ActionText`（`Actions/ActionText.cs`，internal）解析：一个动词加它的参数，索引只能是纯数字。

**SL 记录**。Mod 不启动动作，但在 SL 下，它必须按模拟器的命名方式记录玩家的动作，这样大脑才能克隆这个节点（[Mod：SL 记录 §3](/arch/mod/sl-record/#sec-3)）。它给模拟器的 start 所调用的那些游戏入口打补丁，并用 GameBridge 自己的辅助函数给每一步命名，所以记录下来的一步，就是模拟器本来会打出的那个动作（`Sts2Ai.Mod/NodeRecord.cs`）：

| 入口 | 记录 |
|---|---|
| `ActionQueueSynchronizer.RequestEnqueue` | 出牌、药水和结束回合（`PlayOf`、`PotionOf`），地图投票（`MapActions.Text`），药水栏的丢弃 |
| `PlayerChoiceSynchronizer.SyncLocalChoice` | 选牌提示（游戏的索引）、卡牌奖励、卡包 |
| `EventSynchronizer.ChooseLocalOption`、`RestSiteSynchronizer.ChooseLocalOption` | 事件选项和休息选项 |
| `RewardsSetSynchronizer.SelectLocalReward`；`SkipLocalRewardsSet`、`ProceedFromTerminalRewardsScreen`、`SetLocalPlayerReady` | 领取一个奖励；`rewards_done` |
| `TreasureRoomRelicSynchronizer.PickRelicLocally` | 宝箱里的一件遗物 |
| 商店条目或删牌的 `OnTryPurchaseWrapper` | 一次购买（`ShopActions.Of`） |
| `CrystalSphereMinigame.CellClicked` | 一次占卜（`CrystalSphereActions.Of`） |

模拟器没有对应决策的一步，例如在战斗中扔掉一瓶药水，或者没有作答就关闭了卡牌奖励，会让这个节点剩下部分的记录中断。

**两种宿主里的选牌提示**。在游戏里，提示的画面返回选中的牌，游戏通过 `PlayerChoiceSynchronizer.SyncLocalChoice` 把它们作为自己列表里的索引同步出去，Mod 就是在那里读取它们的。无头时，模拟器通过 `CardSelectCmd.Selector` 回答，这是游戏给代替画面的选牌器留的钩子；这条路径跳过了同步（`Commands/CardSelectCmd.cs`） <Badge text="已核实" variant="success" />。
