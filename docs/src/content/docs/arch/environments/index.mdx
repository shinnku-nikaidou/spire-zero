杀戮尖塔 2 对玩家隐藏了一些东西：抽牌堆的顺序、怪物在它显示的这一步之后会做什么、事件会给出哪张牌、一个未知地图点最后会变成什么。人类玩家只能看到屏幕。运行游戏自身代码的程序却能看到一切，连每个随机数生成器的状态都看得到；而一个允许读取这些状态的搜索，玩的是另一种、容易得多的游戏。

所以这个项目的每个部分都接受一个参数，说明 AI 可以知道多少：**环境**。环境有两种。**NoSL**（no save & load，不存读档）只允许屏幕上出现过的东西。**SL**（save & load，存读档）还允许知道玩家所在地图点内部的真实结果，就好像玩家可以在那里任意多次地存档、读档。本章定义这两种环境，解释为什么有两种，并说明这个选择延伸到系统其余部分的哪些地方。之后的每一章都把它当作前提。

已定，并且在现有代码的每个部分都已生效。NoSL 下，搜索在根据观测构建的世界上进行（[世界与两种战斗算法 §2](/arch/environments/worlds/#sec-2)）；SL 下，搜索在当前节点的一个精确克隆上进行，克隆由工作进程根据检查点和节点的步骤做出来，自我对弈中如此，通过 Mod 在真实游戏中也是如此（[信息与节点 §7](/arch/environments/information/#sec-7)）。在守住这些规则的十项守护中，四项如今已有测试（代码边界、没有兜底、观测往返和封存）；反事实测试和读档计数还在规划中（[信息与节点 §8](/arch/environments/information/#sec-8)）。

## 1. 问题：一个隐藏信息的游戏

战斗的一个回合会向玩家展示手牌、能量、每个生物的生命值和能力，以及每个怪物头上的*意图*：一个图标，表示它下一步打算做什么，比如一次 12 点的攻击。它不展示的是：

- 抽牌堆的顺序（玩家知道里面有哪些牌，不知道它们的顺序）；
- 怪物在它展示的这一步之后的行动，以及对于几种行动看起来一样的怪物，它选的是其中哪一种；
- 任何还没发生的随机事件的结果：随机打中某个敌人的牌、随机生成的牌、下一次奖励的卡牌、事件选项的结果。

在战斗之外，同样的情况在更大的尺度上存在：地图上显示一个 `?` 点，但不显示它会是事件、战斗、商店还是宝箱；地图显示一个精英，但不显示是哪个精英。

所有这些在游戏里都是普通的状态：牌堆是列表，怪物把下一步行动存在一个字段里，每一次随机抽取都来自一组固定的、有种子的随机数生成器（RNG）之一，而存档文件会保存这些生成器。模拟器（[模拟器](/arch/simulator/)）运行的是游戏的真实代码，所以在其中运行的搜索可以读到所有这些，或者干脆试一条打法，看看会发生什么。需要一条规则来说明什么是公平的。

还有一件事让这条线很难划：游戏本身就允许玩家偷看。退到菜单再继续，会重新载入最后一次存档，而重新载入会原样重演这个房间：相同的遭遇、相同的起手牌、相同的怪物行动（[信息与节点 §4](/arch/environments/information/#sec-4)）。有耐心的玩家可以退出、看一眼、再回来。所以「玩家能知道什么」不是一条固定的线，本项目划了两条。

## 2. 一分钟看懂两种环境

**NoSL：只用公开信息**。一个决策可以依赖到目前为止屏幕上显示过的一切、能从中推断出的东西、游戏规则，以及离线学到的任何东西。搜索看不到隐藏状态，所以它做*确定化*：抽取几个对隐藏状态的具体猜测（K 个*世界*），每一个都与看到的一切一致，把每一个都当作真相来搜索，然后取平均（[世界与两种战斗算法 §2](/arch/environments/worlds/#sec-2)）。

**SL：在当前节点内存档、读档**。SL 可以知道 NoSL 能知道的一切，外加**节点**内任何一条打法的真实结果；节点就是当前地图点，从抵达开始，到玩家在地图上选定下一个点为止。这相当于一个玩家可以在节点内任意多次地存档、读档，并且记得每一次尝试。搜索得到节点的一份精确拷贝，即*克隆*，它在节点的出口处封存。关于之后的地图点，SL 并不比 NoSL 多知道任何东西。

| | NoSL | SL |
|---|---|---|
| 关于当前节点知道什么 | 显示过的东西，以及从中得出的推断 | 任何一条打法的真实结果 |
| 关于后面的节点知道什么 | 不知道任何隐藏的东西 | 不知道任何隐藏的东西（与 NoSL 相同） |
| 搜索所在的世界 | K 个采样世界，根据观测构建 | 节点的一个精确克隆 |
| 战斗大脑 | PIMC：把每个世界搜到回合结束，取平均 | SL 规划器：在这一个世界里规划整场战斗 |
| 宏观大脑与价值 V | 一个大脑，一个 V | 同一个大脑和 V |
| 战斗网络 | 一个网络，搜索的叶子 | 同一个网络 |
| 冠军与排行榜 | NoSL 自己的 | SL 自己的，从不与 NoSL 的混在一起 |

宏观大脑负责战斗之外的每一个决策（[宏观大脑](/arch/macro-brain/)）；V 是它用来给选项打分的、学到的价值。两者都是共享的，战斗网络也是，它是战斗搜索叶子上学到的价值：两种环境用同样的权重打同样的两个网络。只有战斗网络前面的战斗搜索不同，因为只有在战斗里，两种环境提出的问题才不一样（[世界与两种战斗算法 §5](/arch/environments/worlds/#sec-5)）。

## 3. 为什么要两种环境

**NoSL 是目标**。它是一个公平的玩家所知道的东西，Mod 的辅助模式可以把它提供给从不退出重载的玩家。

**SL 是一块垫脚石，也是一把尺子**。在节点内，SL 完全不面对随机：克隆持有真实的随机数流，所以一场战斗是一个可以搜到底的确定性谜题，每条打法只有一个结果，而不是一个分布。这让 SL 的战斗大脑在同样的算力下强得多（[战斗大脑](/arch/combat-brain/)），SL 的对局也能打到靠后的几幕，而 V 正需要学会给那里的局面估值。V 用战斗由 SL 规划器来打的对局训练，并服务两种环境（[世界与两种战斗算法 §6](/arch/environments/worlds/#sec-6)）。

两种环境打同一组预先登记的种子，所以它们在同一批种子上的差值，干净地衡量了节点内信息的价值：按种子配对的 SL − NoSL 胜率差和到达层数差。排行榜为每个在两种环境下都有同名报告的冠军计算这个差值（[评估 §3](/arch/evaluation/#sec-3)）；如今两个冠军的战斗大脑不同，所以它还没有显示任何差值。这是「全知 vs 重采样」对比的正式版本。作为参考：spire-mentor（一个前人做的杀戮尖塔机器人）去掉它那能看到整局的作弊后，胜率下降了 22.8–25.5 个百分点；SL 只看到一个节点，所以它的收益应该更小。

**整局视野已被否决**。曾经考虑过一种知道整局顺序（每一场未来的遭遇、奖励和商店）的环境，并已否决：它会让整局本身变成一个确定性谜题，学不到任何能迁移到公平游玩的东西。不要实现它。

## 4. 两种环境共享什么

- **只支持单人模式**，使用固定的游戏版本 v0.111.0。
- **相同的代码和规则**：相同的规则知识，相同的 Brain、Harness 和 Protocol。只有战斗大脑和世界的来源按环境选择。
- **相同的种子**：两者打同一组预先登记的种子集，每个结果都按环境分别报告（[评估：指标、种子与报告 §5](/arch/evaluation/metrics/#sec-5)）。
- **AI 从不真正读档**。两种环境都从不重新载入玩家看到的那局游戏。SL 的「存档与读档」只发生在克隆上，由搜索在工作进程里载入。游戏在存档字段 `SerializableRun.NumReloads` 里统计读档次数：在真实游戏里它必须保持为 0，这项检查计划放进 Mod 的日志里（[信息与节点 §8](/arch/environments/information/#sec-8)）。克隆本身就是一个载入的存档，所以在克隆里这个计数是 1 或更多，而那里没有任何东西读它。
- **一局之内固定**。环境在一局开始时、在宿主的 `hello` 里选定，一直保持到这一局的 `run_end`。它记录在这一局的对局记录里（`RunConfig.Env`），也记录在它的决策日志的每一行里（`env`）。在 Mod 里玩家可以随时切换；一次切换会结束大脑眼中的这一局，并开始新的一局（[Mod：主循环 §8](/arch/mod/loop/#sec-8)）。
- **两者都只读观测**。大脑读的是协议观测，从不读游戏对象；SL 比 NoSL 多知道的东西，只通过克隆到达它们，而克隆存在于工作进程里（[世界与两种战斗算法 §1](/arch/environments/worlds/#sec-1)）。

## 5. 一局如何选定环境

按代码中的实现，环境在这些地方设定：

| 位置 | 方式 | 默认 |
|---|---|---|
| `run`（在模拟器里打完整的对局） | `--env NoSL\|SL`，大小写不限（`Commands/RunCommand.cs:23`）；冠军文件里的 `env` 会填上它 | NoSL |
| 线路上 | `hello{env: "NoSL"\|"SL"}`，由宿主在每局开始时发送（[协议：线路 §3](/arch/protocol/wire/#sec-3)） | – |
| `brain`（单独的决策进程） | 两种都服务：NoSL 宿主用 `--policy` 的战斗大脑，SL 宿主用 `--sl-policy` 的（`Commands/BrainCommand.cs:20`） | `--sl-policy plan` |
| Mod | 面板顶部的 SL/NoSL 开关，保存在 `~/.local/state/sts2ai/settings.json`（[Mod §5](/arch/mod/#sec-5)） | SL |
| 冠军文件 | 每种环境一个，所有角色共用，`eval/champions/nosl.json` 和 `sl.json`；`gate --env` 必须与文件的环境一致（[评估：冠军与基线 §1](/arch/evaluation/champions/#sec-1)） | – |
| 战斗网络训练 | `combat.train --env SL\|NoSL`，必填；网络文件会记录它（`learn/combat/train.py`、`export.py`） | – |

拒绝错误环境的地方：

- `--policy plan`（SL 规划器）和 `--afterstates clone`（L0 在克隆上把选项打出来）只在 SL 里使用，`--policy pimc` 只在 NoSL 里使用：另一种环境的 `hello` 会被拒绝（`Brains/ChampionOptions.cs:39-41`），`run` 也会在开始之前拒绝在 SL 之外用规划器（`Commands/RunCommand.cs:66`）。
- SL 和 NoSL 打同一个战斗网络文件，它学自 SL 的对局（[战斗大脑：叶子 §6](/arch/combat-brain/leaf/#sec-6)）。
- 在 NoSL 对局里，Harness 拒绝 SL 消息 `node_checkpoint` 和 `node_action`（`Harness/Dispatcher.cs:173`、`:174`）；大脑服务器记下这次拒绝，用一个错误回应这一局的下一个决策，宿主把这一局作为失败结束，`run` 以退出码 1 结束，而失败的一局不计入它的报告（`Harness/BrainServer.cs:112-123`、`Harness/RunRecords.cs:32`）。
- 战斗网络训练器只读给定环境的日志，遇到另一个环境的日志就失败（`learn/combat/data.py`）。
- 晋级门槛拒绝把在不同环境或不同游戏版本下打的对局配对（`Harness/Gate.cs:40-41`）。
