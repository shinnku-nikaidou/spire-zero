**冠军**是 AI 在一种环境里已接受的最好版本：各个大脑、它们的预算和权重，以及代表它们的那份报告。本页讲指明冠军的文件，说明结果的记录放在哪里，并列出其他项目达到了什么成绩。门槛如何运作见[晋级门槛](/arch/evaluation/gates/)。

## 1. 冠军文件

`eval/CHARACTER/champions/ENV.json`（`nosl.json`、`sl.json`）为每个角色、每种环境存一个冠军，格式是 `ChampionFile` 记录（`Harness/Gate.cs:116-117`）。SL 冠军的文件：

```json
{
  "env": "SL",
  "champion": "combat plan c8-1 beam 8x300 easy 4 loss plans 3, combat prompts p0, macro l0 v8-1 clone, macro prompts l0 v8-1 clone",
  "options": {
    "env": "SL", "policy": "plan", "macro": "l0", "effort": "medium",
    "value": "weights/silent/v8-1.json", "afterstates": "clone", "combat-net": "weights/silent/c8-1.json",
    "character": "SILENT", "asc": "0"
  },
  "report": "eval/silent/reports/DATE-sl-r1-SET-NAME.json",
  "since": "DATE"
}
```

（在文件里是一行，这里展开了，报告的路径和日期写成了模式。）

| 字段 | 内容 |
|---|---|
| `env` | `NoSL` 或 `SL`；挑战者的 `--env` 与它不同时，门槛会拒绝 |
| `champion` | 报告里显示的冠军名字，即路由表每一侧的大脑加上预算（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)） |
| `options` | 打出这个冠军的对局选项，去掉了 `--`，其中包括角色和进阶等级；权重文件用它在 `weights/CHARACTER/` 里的路径表示 |
| `report` | 与挑战者配对的报告：每道门槛的冠军一方 |
| `since` | 成为冠军的日期（晋级报告的日期，或手写的日期） |
| `gate` | 它通过的门槛，没有经过门槛就确定的冠军没有这一项：`metric`、`delta`、`alpha`、`beta`、`pairs`、`decided`、`llr`、`lower`、`upper`、`floor_diff_mean`、`challenger_only_wins`、`champion_only_wins`、`verdict`，有的话还有 `void_reason`，以及 `not_worse` |

**谁读取它**。

- `run`、`brain`、`afterstates` 和 `fork` 接受 `--champion FILE`，打它指明的冠军（`SimWorker/Commands/Args.cs:172-201`，[模拟器：参考 §3](/arch/simulator/reference/#sec-3)）。文件里的选项排在命令行给出的选项之后，所以给出的优先；命令没有的选项会被跳过（`brain` 没有 `--env`：每个宿主自己指明）；给出的 `--policy` 若与文件里的不同，就保留它自己的预算。
- `gate --champion FILE` 是要击败的冠军：它读取文件的 `env` 和 `report`（[晋级门槛 §6](/arch/evaluation/gates/#sec-6)）。
- `leaderboard` 在文件所属环境的榜上，标出每个文件指明的报告（[指标、种子与报告 §9](/arch/evaluation/metrics/#sec-9)）。

**由 `--promote` 写入，或手工写入**。`gate --promote` 写入每一个字段，选项按挑战者的选项生成（`ChampionOptions.Options`，`SimWorker/Brains/ChampionOptions.cs:83-108`）：对 SL 规划器来说是 `beam`、`easy-beam`、`replan`、`loss-plans` 和 `nodes`，而不是 `effort`。胜局门槛什么也不写，所以由它晋级的网络靠手工写入（[晋级门槛 §10](/arch/evaluation/gates/#sec-10)），SL 文件写的是 `"effort": "medium"`，打的是同样的预算（[SL 规划器：预算 §1](/arch/sl-planner/budget/#sec-1)）。重定基线只修改 `report`（[晋级门槛 §9](/arch/evaluation/gates/#sec-9)）。

**两个文件**。两个文件都指明同样的两个网络，`weights/silent/v8-1.json`（V）和 `weights/silent/c8-1.json`（战斗网络）。SL 打的是 medium 力度的 SL 规划器，加上在克隆上的 L0；NoSL 打的是 8 个世界 × 300 个节点的 PIMC，加上用按画面所示的后状态的 L0（`"policy": "pimc", "worlds": "8", "nodes": "300"`）。两者指明的 `report` 是一份较早的 SL 报告，用更早的战斗网络打的；在有这个冠军的报告之前，它继续有效。由于它是 SL 报告，针对 NoSL 文件的 NoSL 门槛会被拒绝（[评估 §3](/arch/evaluation/#sec-3)）。

每个角色有自己的文件夹，`eval/CHARACTER/`、`weights/CHARACTER/` 和 `data/CHARACTER/`，所有进阶等级共用一个大脑（[学习：参考 §3](/arch/learning/reference/#sec-3)）；`eval/seeds/` 里的种子集是共用的。

## 2. 历史和报告

这些页面只描述当前的冠军。之前的记录另外保存：

- `eval/silent/ledger.md` 是历史：每个网络，它用什么训练，它的门槛，以及它后来怎样了。
- `eval/silent/reports/` 存放每一份已提交的报告，有 JSON 和 Markdown 两种（[指标、种子与报告 §7](/arch/evaluation/metrics/#sec-7)）。
- `eval/silent/leaderboard.md` 按种子集和环境给这些报告排名（[指标、种子与报告 §9](/arch/evaluation/metrics/#sec-9)）。

**冠军的网络和它们的门槛**。v8-1 和 c8-1 就是 v7-1f 和 c7-2，换上游戏的完整词元表，新输入的权重为零，没有训练。在 A10 的相同种子上与那两个网络对打，覆盖全部五个角色，也包括 NoSL，它们做出的决策全都相同（medium 2,864 个，低预算 3,490 个），所以它们没有单独过门槛，c7-2 的门槛就算 c8-1 的。

c7-2 的门槛（2026-11-01；ledger 里它那一行）是部分结果：`promotion-1-300` 的 300 个种子里，medium 打完了 150 个，低预算打完了 188 个，后者只作参考。其余的随两台机器一起丢失，没有重打，所以结果读自记录，没有报告。每一方都用克隆上的 V v7-1f，在相同种子上配对；打完的对局没有一局失败。

| c7-2 对 | 预算 | 种子 | 胜局，c7-2 : 对方 | 百分点 | 95 % 下界 | 平均层数，c7-2 : 对方 |
|---|---|---|---|---|---|---|
| c7-1 | medium | 150 | 88 : 88 | +0.0 ± 3.9 | −6.4 | 44.45 : 44.71 |
| c2 | medium | 150 | 88 : 53 | +23.3 ± 3.9 | +16.8 | 44.45 : 41.13 |
| c7-1 | low | 188 | 82 : 85 | −1.6 ± 4.0 | −8.2 | 42.01 : 42.09 |
| c2 | low | 188 | 82 : 37 | +23.9 ± 3.8 | +17.7 | – |

对 c7-1（同样数据上的网络），c7-2 没有被证明更好，所以没有达到门槛的规则。对 c2（它取代的冠军战斗网络），下界远高于 0。c7-2 在这个结果之前就成了冠军，这个结果不改变这一点。

## 4. 未决问题

1. **R4 的吞吐量**：在游戏的 Instant 速度下一局要几分钟，由此能负担多少局 R4。
2. **不一致种子很少时的胜局门槛**：它的下界让 3 胜对 0 胜通过（[晋级门槛 §10](/arch/evaluation/gates/#sec-10)）；是否要求一个最少的不一致种子数，或者改用精确检验。
3. **门槛的错误率**：两种门槛的误通过率都没有测量过；A/A 测试需要一种只改变冠军自身随机性的办法（[晋级门槛 §4](/arch/evaluation/gates/#sec-4)）。
4. **冠军的 NoSL 报告**，让 NoSL 榜重新有冠军，也让同一个 V 的 SL − NoSL 能够测量。
5. **`final-1`**：何时在它上面做出第一个正式结论。
