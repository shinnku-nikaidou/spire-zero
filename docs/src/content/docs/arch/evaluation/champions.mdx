**冠军**是 AI 在一种环境里已接受的最好版本：各个大脑、它们的预算和权重，以及代表它们的那份报告。本页讲指明冠军的文件，说明结果的记录放在哪里，并列出其他项目达到了什么成绩。门槛如何运作见[晋级门槛](/arch/evaluation/gates/)。

## 1. 冠军文件

`eval/champions/ENV.json`（`nosl.json`、`sl.json`）为每种环境存一个冠军，所有角色共用，格式是 `ChampionFile` 记录（`Harness/Gate.cs:114-115`）。冠军是两个网络和它们的打法，对每个角色都一样；角色和进阶等级由每个任务自己给出（`--character`、`--asc`）。SL 冠军的文件：

```json
{
  "env": "SL",
  "champion": "combat plan c9-1 beam 8x300 easy 4 loss plans 3, combat prompts p0, macro l0 v9-1 clone, macro prompts l0 v9-1 clone",
  "options": {
    "env": "SL", "policy": "plan", "macro": "l0", "effort": "medium",
    "value": "weights/all/v9-1.json", "afterstates": "clone", "combat-net": "weights/all/c9-1.json"
  },
  "reports": {
    "SILENT": "eval/silent/reports/DATE-sl-a0-SET-NAME.json",
    "IRONCLAD": "eval/ironclad/reports/DATE-sl-a0-SET-NAME.json",
    "DEFECT": "…", "REGENT": "…", "NECROBINDER": "…"
  },
  "since": "DATE"
}
```

（在文件里是一行，这里展开了，各份报告的路径和日期写成了模式。）

| 字段 | 内容 |
|---|---|
| `env` | `NoSL` 或 `SL`；挑战者的 `--env` 与它不同时，门槛会拒绝 |
| `champion` | 报告里显示的冠军名字，即路由表每一侧的大脑加上预算（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)） |
| `options` | 打出这个冠军的对局选项，去掉了 `--`，不含角色和进阶等级；权重文件用它在 `weights/all/` 里的路径表示 |
| `reports` | 按角色分，与该角色的挑战者配对的报告：每道门槛的冠军一方。一份报告是一个角色在一个进阶等级上的结果，所以没有报告的角色暂时还不能对这个文件过门槛 |
| `since` | 成为冠军的日期（晋级报告的日期，或手写的日期） |
| `gate` | 它通过的门槛，没有经过门槛就确定的冠军没有这一项：`metric`、`delta`、`alpha`、`beta`、`pairs`、`decided`、`llr`、`lower`、`upper`、`floor_diff_mean`、`challenger_only_wins`、`champion_only_wins`、`verdict`，有的话还有 `void_reason`，以及 `not_worse` |

**谁读取它**。

- `run` 和 `brain` 接受 `--champion FILE`，打它指明的冠军（`SimWorker/Commands/Args.cs:164-192`，[模拟器：参考 §3](/arch/simulator/reference/#sec-3)）。文件里的选项排在命令行给出的选项之后，所以给出的优先；命令没有的选项会被跳过（`brain` 没有 `--env`：每个宿主自己指明）；给出的 `--policy` 若与文件里的不同，就保留它自己的预算。
- `gate --champion FILE` 是要击败的冠军：它读取文件的 `env`，以及文件里记录所属角色的那份报告（[晋级门槛 §6](/arch/evaluation/gates/#sec-6)）。
- `leaderboard --character C` 在文件所属环境的榜上，标出每个文件为 C 指明的报告（[指标、种子与报告 §9](/arch/evaluation/metrics/#sec-9)）。

**由 `--promote` 写入，或手工写入**。`gate --promote` 写入每一个字段，选项按挑战者的选项生成（`ChampionOptions.Options`，`SimWorker/Brains/ChampionOptions.cs:75-91`）：对 SL 规划器来说是 `beam`、`easy-beam`、`replan`、`loss-plans` 和 `nodes`，而不是 `effort`。胜局门槛什么也不写，所以由它晋级的网络靠手工写入（[晋级门槛 §10](/arch/evaluation/gates/#sec-10)），SL 文件写的是 `"effort": "medium"`，打的是同样的预算（[SL 规划器：预算 §1](/arch/sl-planner/budget/#sec-1)）。重定基线只修改 `reports`（[晋级门槛 §9](/arch/evaluation/gates/#sec-9)）。

**两个文件**。两个文件都指明同样的两个网络，`weights/all/v9-1.json`（V）和 `weights/all/c9-1.json`（战斗网络）。SL 打的是 medium 力度的 SL 规划器，加上在克隆上的 L0；NoSL 打的是 8 个世界 × 300 个节点的 PIMC，加上用按画面所示的后状态的 L0（`"policy": "pimc", "worlds": "8", "nodes": "300"`）。两者指明同样的五份报告，每个角色一份，都是这个 SL 冠军自己的：在 `promotion-1-100` 上以进阶 0、medium 打了 100 局。由于它们是 SL 报告，针对 NoSL 文件的 NoSL 门槛会被拒绝（[评估 §3](/arch/evaluation/#sec-3)）；这两个网络都没有在 NoSL 下过过门槛。

每个角色有自己的文件夹，`eval/CHARACTER/` 和 `data/CHARACTER/`，里面有它自己的报告、排行榜和对局（[学习：参考 §3](/arch/learning/reference/#sec-3)），因为一个结果只对一个角色成立。其余的都是共用的：`weights/all/` 里的网络、`eval/champions/` 里的冠军文件、账本 `eval/ledger.md`，以及 `eval/seeds/` 里的种子集。

## 2. 历史和报告

这些页面只描述当前的冠军。之前的记录另外保存：

- `eval/ledger.md` 是历史，所有角色共用：每个网络，它用什么训练，它的门槛，以及它后来怎样了。
- `eval/CHARACTER/reports/` 存放一个角色已提交的报告，有 JSON 和 Markdown 两种（[指标、种子与报告 §7](/arch/evaluation/metrics/#sec-7)）。
- `eval/CHARACTER/leaderboard.md` 按进阶、种子集和环境给它们排名（[指标、种子与报告 §9](/arch/evaluation/metrics/#sec-9)）。

**冠军的网络和它们的门槛**。v9-1 和 c9-1 从 v9-0 和 c9-0 接着训练，只用 `v9g0` 训练：全部五个角色的第一批 SL 自我对弈，进阶 0、低预算，29,987 局，其中赢下 2,057 局，1,981 局是静默猎手赢的（[学习：循环 §2](/arch/learning/loop/#sec-2)）。v9-0 和 c9-0 就是 v8-3 和 c8-3，它们学过静默猎手在进阶 10 的对局，再不经训练搬到所有角色共用的网络上。门槛让 v9-0 + c9-0 对 v9-1 + c9-1，在每个角色上以进阶 0 来打，双方用同样的种子、冠军的规划器，不做探索：medium 在 `promotion-1-100` 上 100 个种子，低预算在 `promotion-1-200` 上 200 个。V 和战斗网络一起评判：一对网络对另一对。3,000 局中没有一局失败，也没有游戏错误。medium 下，按种子配对（新的一对减去旧的）：

## 4. 未决问题

1. **R4 的吞吐量**：在游戏的 Instant 速度下一局要几分钟，由此能负担多少局 R4。
2. **不一致种子很少时的胜局门槛**：它的下界让 3 胜对 0 胜通过（[晋级门槛 §10](/arch/evaluation/gates/#sec-10)）；是否要求一个最少的不一致种子数，或者改用精确检验。
3. **门槛的错误率**：两种门槛的误通过率都没有测量过；A/A 测试需要一种只改变冠军自身随机性的办法（[晋级门槛 §4](/arch/evaluation/gates/#sec-4)）。
4. **冠军的 NoSL 报告**，让 NoSL 榜重新有冠军，也让同一个 V 的 SL − NoSL 能够测量。
5. **`final-1`**：何时在它上面做出第一个正式结论。
