**晋级门槛**是挑战者取代冠军之前必须通过的检验。本页先从零讲起门槛所依据的统计学，再逐个选项讲每一种门槛。门槛读取的数字见[指标、种子与报告](/arch/evaluation/metrics/)；指明冠军的文件见[冠军与基线](/arch/evaluation/champions/)。

## 1. 为什么要门槛，为什么要配对

在少数几局里看起来更好的挑战者，可能只是运气好。整局又慢（按冠军的 medium 预算每局 5 到 17 分钟，视角色而定）又嘈杂，所以问题在于：要多少局才能把真正的提升和运气分开。

**不配对**的话，答案是很多。两组独立的对局样本，每边一组，按胜率比较：胜率约 30% 时，要把 +5 pp 和没有差别分开，每边约需 1,300 局，+2 pp 约需 8,200 局（双侧 α = 0.05，检验功效 0.8，两个比率之差的方差 2p(1−p)）。胜率 7.7% 时，+3 pp 每边约需 1,240 局。

有两个想法能把这个数字降下来。这里的每一种门槛都配对；整局 SPRT 还做序贯检验，而胜局门槛打的是一个固定的种子集：

1. **按种子配对对局**（[§2](#sec-2)）：让挑战者在冠军的种子上打，逐个种子比较，这样双方共有的运气就从差值里消掉了。
2. **序贯检验**（[§3](#sec-3)）：每一对之后看一次，一旦证据明确就停下，而不是事先定好局数。

此外，门槛是分层的，从便宜而局部到昂贵而完整（[§5](#sec-5)）。

## 2. 共同随机数

**思路**。共同随机数（CRN）是指比较的双方遇到同样的随机事件，于是只有策略不同。在这里它是免费的：种子决定游戏，一局自己的随机性来自种子的哈希（[指标、种子与报告 §6](/arch/evaluation/metrics/#sec-6)），而一局是它的设置和它的回答的函数（[模拟器：整局 §6](/arch/simulator/runs/#sec-6)）。所以在冠军的种子上打的挑战者，面对的是同样的地图、同样的最初几场遭遇、同样的最初几次卡牌选择。两者一旦做出不同的选择，各自的游戏就会渐渐分开，但地图和之后的很多东西仍然是共有的。

种子决定整局，所以冠军一方不必重打：它的报告里已经逐条存着它的对局，SPRT 门槛只打挑战者。胜局门槛仍然让双方都打，而且在同一个提交上，免得任何一方的对局来自更旧的代码（[§10](#sec-10)）。

**配对差**。对种子 $i$，令 $d_i$ 为挑战者的层数减冠军的层数。在 $n$ 个种子上，提升用均值 $\bar d$ 估计，标准误为 $\mathrm{sd}(d)/\sqrt n$。不配对时，两个均值之差的标准误是 $\sqrt{(s_a^2 + s_b^2)/n}$。由于 $\mathrm{var}(d) = s_a^2 + s_b^2 - 2\,\mathrm{cov}(a, b)$，配对带来的好处，恰好取决于双方在同一种子上的层数有多同向变化。

在已提交的报告上**实测**（在这里算出；代码不记录这样的数字）。A、B 和 C 是三个网络，在 SL 下打 `promotion-1-300`；D 和 E 是两个 NoSL 大脑，打 `promotion-1`：

| 配对，同样的种子 | n | 层数的相关系数 | 配对标准误 | 不配对标准误 | 方差比 |
|---|---|---|---|---|---|
| C − A，`promotion-1-300` | 300 | 0.34 | 0.618 | 0.757 | 1.50 |
| B − A，`promotion-1-300` | 300 | 0.23 | 0.695 | 0.790 | 1.29 |
| C − B，`promotion-1-300` | 300 | 0.36 | 0.687 | 0.855 | 1.55 |
| E − D，`promotion-1` | 200 | 0.46 | 0.627 | 0.853 | 1.85 |
| 同一个 V 在 SL 和 NoSL 下，`promotion-1` | 200 | 0.60 | 0.548 | 0.865 | 2.49 |

最后一行的两边战斗大脑不同。方差比 1.5 意味着不配对的比较要得到同样的宽度，每边需要 1.5 倍的局数。**在胜局上，胜局稀少时配对带来的好处很小**：C 的 23 个胜局和 A 的 1 个胜局没有共同的种子，胜局差的配对标准误 1.58 pp 与不配对的 1.57 pp 无异；C 的 23 个和 B 的 13 个之间有 2 个种子相同。胜局多了之后它就有用了：两个网络在已退役的种子集 `promotion-1-500` 上（[指标、种子与报告 §5](/arch/evaluation/metrics/#sec-5)），分别赢 145 局和 74 局，其中 35 局在共同的种子上，配对标准误 2.36 pp，不配对为 2.58 pp，方差比 1.19。

## 3. 序贯概率比检验

**思路**。固定局数的检验会把所有局都打完，即使前五十局就已经能回答问题。**序贯概率比检验**（SPRT，Wald 1945）在每一对之后都看一次，一旦证据明确支持两个假设之一，就停下。

**按胜局**。整局门槛检验的是胜局。与 McNemar 检验一样（[§4](#sec-4)），只有恰好一方获胜的配对能说明哪一方更强：$n$ 对之后，有 $k$ 对只有挑战者赢，$m$ 对只有冠军赢。设挑战者在这类配对中所占的比例为 $p$，

- H0，挑战者不比冠军强：$p_0 = 0.5$；
- H1，它强 $\delta$：$p_1 = 0.5 + \delta$（$\delta$ 默认为 0.1）。

**证据**是对数似然比：到目前为止的这些配对，在 H1 下比在 H0 下可能多少，

$$
\Lambda_n = k \ln\frac{p_1}{p_0} + m \ln\frac{1-p_1}{1-p_0} = 0.1823\,k - 0.2231\,m \quad (\delta = 0.1).
$$

只有挑战者赢的一对推向 H1，只有冠军赢的一对推向 H0，双方都赢或都输的一对不增加任何东西。

**边界**。事先定好 $\alpha$，即让一个并不更强的挑战者通过的概率，以及 $\beta$，即让一个强 $\delta$ 的挑战者失败的概率。Wald 的边界是

$$
A = \ln\frac{1-\beta}{\alpha}, \qquad B = \ln\frac{\beta}{1-\alpha};
$$

第一次出现 $\Lambda_n \ge A$ 时通过，第一次出现 $\Lambda_n \le B$ 时失败。$\alpha = \beta = 0.05$ 时，$A = \ln 19 = 2.944$，$B = -2.944$：通过需要 $k - 1.224\,m \ge 16.15$，即 17 对只有挑战者赢、对方一对也没有；失败需要 $m - 0.817\,k \ge 13.2$。如果配对先用完，判定为未定。这两个边界是 Wald 的近似；真实的错误率还没有被测量过（[§4](#sec-4)）。

**实现**（`Gate.Sprt`，`Harness/Gate.cs:52-83`）：它在第一个越过边界的配对处停下，结果记下这一对（`decided`）、此时的 LLR、$k$ 和 $m$，以及到这一对为止的平均层数差（`floor_diff_mean`）。层数列在判定旁边，不做检验。没有最少配对数的要求。

**一道门槛能分辨什么**。在 15% 的配对只有一方获胜的虚构配对上，1,000 次模拟门槛给出：100 对时，这样的配对约有 15 对，少于一次通过所需，几乎每道门槛都停在未定；300 对时，拿下其中 60% 的挑战者有 8% 的时候通过，拿下 70% 的有 47% 的时候通过，而没有差别时 0.6% 通过、11% 失败，其余未定。不更差检验在 300 对这样的配对上，让各占一半的挑战者有 10% 的时候通过。在本项目打的胜率和种子集下，按胜局的 SPRT 大多停在未定；胜局门槛改用配对的下界来读同样的配对（[§10](#sec-10)）。

## 4. McNemar 检验与 A/A 测试

**McNemar 检验**是配对的是/否结果（例如同一种子上是否获胜）的标准检验。把每个种子放进四个格子之一：

| | 冠军赢 | 冠军输 |
|---|---|---|
| **挑战者赢** | 都赢 | $k$ |
| **挑战者输** | $m$ | 都输 |

「都赢」和「都输」格子里的种子，对哪一方更强什么也说明不了。在没有差别的假设下，$k + m$ 个不一致的种子每一个都像一枚公平的硬币，所以 $k$ 服从试验次数为 $k + m$、概率为二分之一的二项分布，由此得到精确的 p 值。[§2](#sec-2) 的 C 对 A，在 `promotion-1-300` 上：$k$ = 23，$m$ = 1，没有双方都赢的种子；公平硬币下 24 次里出现 23 次或更多的概率是 25 / 2²⁴ ≈ 1.5 × 10⁻⁶。

代码里没有 McNemar 检验 <Badge text="规划中" variant="caution" />。已有的检验用的是同样的两个计数：C# 的胜局 SPRT 序贯地检验 $k$ 对 $m$（[§3](#sec-3)），胜局门槛给逐种子差值的均值定一个下界，它取决于 $k$、$m$ 和配对数（[§10](#sec-10)）。

**A/A 测试**让冠军和它自己过一道门槛。两边没有真实差别，所以通过的频率不能高于门槛设计的 α；高于它就说明门槛有问题。在这里，同样种子上的 A/A 测试根本算不上测试：种子决定整局，所以副本在每个种子上结果都相同，而没有一对是只有一方获胜的 SPRT 会一直停在未定。有用的 A/A 测试应当只改变冠军自己的随机性（搜索种子、探索的抽取），其余一切不变；没有哪个选项能改变这些，也还没有跑过 A/A 测试 <Badge text="规划中" variant="caution" />。所以门槛真实的误通过率没有被测量过。

## 5. 分层的门槛

| 层级 | 用于 | 方法 | 状态 |
|---|---|---|---|
| 战斗测试集 | 战斗搜索及其叶子 | 每个参评者都打同样的战斗（遭遇、牌组、种子），所以是 CRN；胜率和每场胜利损失的生命值 | 代码里没有；冠军的战斗大脑见 [SL 规划器：预算 §5](/arch/sl-planner/budget/#sec-5) 和 [NoSL PIMC：预算 §6](/arch/pimc/budget/#sec-6) |
| 幕级 | 宏观决策 | 从一个快照池开始打一幕；过幕率和幕末生命值 | 规划中 <Badge text="规划中" variant="caution" /> |
| 整局 SPRT，`gate` | 按序贯方式评判的改动，例如更省的预算或去掉一个手写部分 | 在晋级种子集上按种子配对；按胜局做 SPRT | 已实现（[§6](#sec-6)） |
| 整局胜局下界 | 新的一对网络，V 和战斗网络 | 在整局上用 `learn/gate.py --against`：两对网络都用每个角色、按 medium 力度打 `promotion-1-100`，按种子配对；胜局的下界 | 使用中（[§10](#sec-10)） |

测试集每场战斗花几秒到几分钟；一道整局门槛要花几个小时的算力。版本门槛用整局：测试集能说明一个搜索在一场战斗里更强，却不能说明一局能走得更远（[战斗大脑 §5](/arch/combat-brain/#sec-5)）。

## 6. 整局门槛

```text
gate --champion eval/champions/ENV.json --records A[,B…] [the challenger's run options]
     [--delta D] [--alpha A] [--beta B] [--not-worse] [--promote PATH] [--env ENV]
```

（`SimWorker/Commands/EvalCommands.cs:62-128`，`Harness/Gate.cs`）

| 选项 | 默认 | 作用 |
|---|---|---|
| `--champion FILE` | 必填 | 要击败的冠军文件；它为记录所属角色存的那份报告就是冠军一方，它没有报告的角色会被拒绝 |
| `--records A[,B…]` | 必填 | 挑战者的对局记录文件，用逗号分隔 |
| `--delta D` | 0.1（`:66`） | SPRT 要与无差别区分开的差值：在只有一方获胜的配对中，挑战者所占比例超出一半的部分（[§3](#sec-3)） |
| `--alpha A` | 0.05 | 让并不更强的挑战者通过的概率（加 `--not-worse` 时：差 δ 的挑战者） |
| `--beta B` | 0.05 | 让强 δ 的挑战者失败的概率（加 `--not-worse` 时：不更差的挑战者） |
| `--not-worse` | 关 | 非劣效检验（[§7](#sec-7)） |
| `--promote PATH` | 无 | 通过时写出挑战者的报告并让它成为冠军（[§8](#sec-8)） |
| `--env ENV` | 无 | 挑战者的环境，与文件的环境不同就拒绝 |
| 挑战者的对局选项 | | `--policy`、`--macro`、预算（其中包括精英战和 Boss 战自己的力度级别）、`--workers`、`--value`、`--afterstates`、`--combat-net`、`--explore`、`--macro-explore`（[模拟器：参考 §3](/arch/simulator/reference/#sec-3)）；挑战者没有 `--champion FILE`，它完全由自己的选项命名 |

**两方**。冠军一方是它报告里的对局。挑战者一方是它的记录，每条记录都必须是用给出的选项打出来的：这些选项组成的名字必须等于每条记录的 `config.champion`（`:96-97`）。配对是冠军报告里那些挑战者也打过其种子的对局，按冠军报告的顺序，也就是种子集的顺序（`Gate.Pairs`，`Harness/Gate.cs:37-50`）。只打了种子集开头一部分的挑战者，就按它已有的配对过门槛。

**拒绝**以下情况，当作命令行错误（退出码 2）：

- 带探索的选项（`--explore` 或 `--macro-explore` 大于 0，`:95`）：探索只用于自我对弈（[学习：循环 §9](/arch/learning/loop/#sec-9)）；
- 按自动胜利规则打的记录（`Harness/Gate.cs:40`）：这样的对局在某些幕里只打精英和 Boss，是训练用的数据，不是一局游戏（[模拟器：整局 §8](/arch/simulator/runs/#sec-8)）；报告也拒收它（[指标、种子与报告 §7](/arch/evaluation/metrics/#sec-7)）；
- 某条记录的冠军名称与选项给出的不同，或记录来自不止一个冠军名称；
- 某条记录的游戏版本或环境与冠军的报告不同，或者用的是另一个角色、另一个进阶等级（`Harness/Gate.cs:41-46`）；
- 冠军文件没有为其指明报告的角色（`:92-93`），在 NoSL 文件里就是每个角色；
- 一个种子打了两次；`--env` 与文件的环境不同。

**不检查**：提交。在另一个提交上构建的挑战者照样和冠军的报告配对，所以当代码改变了冠军的打法时，冠军要重定基线（[§9](#sec-9)）。冠军报告自身是否作废也不检查，种子不在冠军报告里的挑战者对局会被悄悄略过。

**判定**。`pass`、`fail`、`open`（配对先用完了），或 `void`：配对的挑战者对局违反了必须为零的规则，不管 SPRT 怎么说（`Harness/Gate.cs:57-59, 81`）。

**输出和退出码**。三行，晋级时再加第四行：

```text
champion: NAME (eval/silent/reports/REPORT.json)
challenger: NAME, 300 runs
gate pass: wins, delta 0.1, after 234 of 300 pairs; LLR 3.06 in [-2.94, 2.94]; floor difference +2.53; wins only by the challenger 18, only by the champion 1
promoted: eval/champions/sl.json now names NAME
```

（`Summary` 的格式，`Harness/Gate.cs:28-31`，数字取自 [§3](#sec-3) 里网络 C 对网络 A 的重放，略去了名字和路径。）通过时退出码为 0，不论是否晋级；失败、未定或作废时为 1；命令行错误、晋级被拒绝或文件读不出来时为 2（`SimWorker/Commands/Cli.cs:49-60`）。

## 7. 不更差

目的是更省而不是更强的改动（少搜一些，其余打法不变），只要**不更差**就晋级。`--not-worse` 把两个假设都下移 δ：H0，挑战者更差，在只有一方获胜的配对中占 0.5 − δ；H1，它不更差，各占一半（`Harness/Gate.cs:62`）。门槛输出的那一行和存下的结果会写明是哪种检验（行里是 `not worse`，冠军文件里是 `not_worse`）。

本项目还把它用在另一种情形：只去掉一个手写部分的挑战者，打平就算通过，因为在不更差时更简单的大脑更受青睐。

## 8. 晋级

通过时，`--promote PATH`（`SimWorker/Commands/EvalCommands.cs:113-125`）：

1. 用挑战者的记录在冠军的种子集（`eval/seeds/SET.txt`）上生成它的报告，日期为当天；不完整的报告会被拒绝，因为新报告要面对之后的挑战者，必须覆盖整个种子集；
2. 生成冠军文件里的选项：挑战者在该文件所属环境下的选项，不含角色和进阶等级，它们由每个任务给出。每个权重文件（`value`、`combat-net`）都必须在共用的权重文件夹 `weights/all/` 里，那里一个名字永远指同一个文件；有文件放在别处的晋级，会在写入任何东西之前就被拒绝（`SimWorker/Brains/ChampionOptions.cs:107-121`，[学习：参考 §6](/arch/learning/reference/#sec-6)）；
3. 写出 `PATH.json` 和 `PATH.md`，Markdown 里有一节针对冠军报告的「Against」；
4. 改写冠军文件：环境、挑战者的名字和选项、新报告，作为唯一的一份，记在它的角色下（旧冠军的其他报告是别的网络打的），`since` 为报告的日期，`gate` 为这次的结果（[冠军与基线 §1](/arch/evaluation/champions/#sec-1)）。

SPRT 可能提前通过，而晋级需要整个种子集。所以挑战者可以分批打，每批之后过一次门槛：失败就停；通过之后把种子集剩下的打完，再带 `--promote` 过一次门槛。
## 9. 重定基线

冠军的报告只有在代码还像原来那样打这个冠军时才代表它。让它打法改变的改动（世界构建器、搜索或 L0 里的修复）会让报告过时，再拿它过门槛，就会把这个改动算到挑战者头上；门槛并不检查提交（[§6](#sec-6)）。这时冠军在新代码上把整个种子集重打一遍（`run --champion FILE`），冠军文件改为指向新报告。这不是晋级：冠军、它的日期和它的门槛都不变。

## 10. 胜局门槛

胜局门槛在 SL 整局上按胜局评判新的一对网络，用的是 `learn/gate.py` 的配对下界，而不是 `gate`（[评估 §4](/arch/evaluation/#sec-4)）。

```text
uv run python gate.py --records R1,R2 [--logs L1,L2] [--against C1,C2]
```

（`learn/gate.py:158-174`，在 `learn/` 下运行。）它打印一个 JSON 对象。它的报告：

| 字段 | 内容 |
|---|---|
| `runs`、`won`、`floor`、`floor_se` | 打完的局数、获胜局数、平均层数及其标准误 |
| `boss` | 每一幕 `"0"`、`"1"`、`"2"`：`{reached, beaten, rate}`，统计这一幕的每场 Boss 战，以及其中没有以死亡结束的 |
| `elites_per_run`、`elite_deaths` | 每局精英战场数，以及以死亡结束的精英战 |
| `died_in` | 每一幕，输局按死在哪里分：如果最后一场战斗在这一局结束的层上并以死亡结束，就是那场战斗的房间，否则是 `outside combat`（没有 end 的战斗算作战斗之外，[指标、种子与报告 §8](/arch/evaluation/metrics/#sec-8)） |
| `rest`、`monster_or_rest`、`shop` | 加 `--logs` 时：休息处的选择，按做出选择时的生命比例分组（0–40%、40–70%、70–90%、90–100%），地图上在怪物和休息处之间的选择，按同样的区段分组，以及商店卖出了什么（遗物、卡牌、药水或其他，由 `buy:` 之后下一个决策时这一局多了什么来判断；`remove`、`leave`）；只统计有记录的、记过日志的对局（`:105-131`） |
| `against` | 加 `--against` 时，下面的配对 |

**规则**。`--against` 指明冠军的记录。配对是双方都打完的种子。对每一对，$d_i$ 是挑战者的结果减冠军的结果：按胜局时每局 1 或 0，按层数时就是层数。设有 $n$ 对，$\bar d$ 为它们的均值，$\mathrm{SE} = \mathrm{sd}(d)/\sqrt n$（样本标准差，分母 $n-1$），

$$
\text{lower} = \bar d - 1.645\,\mathrm{SE}, \qquad \text{promote if lower} > 0,
$$

即均值差的 95% 单侧下界（1.645 是正态分布的 95% 分位数）。`against` 包含 `pairs`、`won`、`champion_won`、`wins_diff`、`wins_diff_se`、`wins_lower_95`、`floor_diff`、`floor_diff_se` 和 `promote`，按胜局决定（`learn/gate.py:134-155`）。只有一对时 SE 没有定义，不晋级；所有配对都相同时下界为 0，也不晋级。

**怎样才能通过**。用不一致的种子来表示（[§4](#sec-4)），$\bar d = (k - m)/n$，下界大致在 $k - m > 1.645\sqrt{k + m}$ 时大于 0。按这条规则在 300 对上精确计算：

| 只有冠军赢的种子数 $m$ | 0 | 1 | 5 | 10 | 20 | 30 | 40 | 60 |
|---|---|---|---|---|---|---|---|---|
| 只有挑战者赢的种子数 $k$ 至少要 | 3 | 6 | 12 | 19 | 32 | 45 | 57 | 80 |
| 它增加的胜率 | +1.0 pp | +1.7 pp | +2.3 pp | +3.0 pp | +4.0 pp | +5.0 pp | +5.7 pp | +6.7 pp |

所需的差距随冠军自己的胜局增长。不一致的种子很少时，正态下界很宽松：只有挑战者赢的种子 3 个、只有冠军赢的 0 个就能通过，而精确的 McNemar（符号）检验给出的单侧 p 值是 1/8。

**它不检查什么**。`gate.py` 在做任何事之前就丢掉每条带 `failure` 的记录（`:43`），所以它没有作废规则，并拒收按自动胜利规则打的记录（`:44-45`）；它没有最少配对数，也不比较双方的配置、冠军、环境、提交或探索。它只按种子配对记录，所以一次只读一个角色。其余的由下面的流程来保证。

**流程**。网络是共用的，所以新的一对网络，一个 V 和一个战斗网络，作为一对在全部五个角色上过门槛。两对网络都要打，冠军的和挑战者的：用每个角色在进阶 0（冠军报告的进阶）打 `eval/seeds/promotion-1-100.txt` 的每个种子，并且在同一个提交上，所以哪一方都不会沿用更旧的代码打出的对局。每一方都用 SL 冠军文件的选项，只换 `--value` 和 `--combat-net`：冠军的 medium 预算、`--afterstates clone`、不带 `--explore`。每个角色每一方一个作业，然后在 `learn/` 里按角色跑 `gate.py`：

```text
# the champion's pair
run --champion eval/champions/sl.json --character CHARACTER --asc 0 \
    --seeds eval/seeds/promotion-1-100.txt --records CHAMPION-rec.jsonl --log CHAMPION-log.jsonl
# the challenger's pair: the same options, with its two net files
run --champion eval/champions/sl.json --character CHARACTER --asc 0 \
    --seeds eval/seeds/promotion-1-100.txt --value weights/all/V.json --combat-net weights/all/C.json \
    --records NEW-rec.jsonl --log NEW-log.jsonl
# the challenger against the champion, paired by seed
uv run python gate.py --records NEW-rec.jsonl --logs NEW-log.jsonl --against CHAMPION-rec.jsonl
```

一个作业的种子可以分给几个进程，各有自己的记录和日志文件；`--records`、`--logs` 和 `--against` 用逗号分隔接收它们。

**判定**。每个角色的对局单独读，按配对胜局评判，层数列在旁边，层数更少并不阻止一对赢得更多的网络：后期的强度是用前面的层数换来的。V 和战斗网络不分开评判。结论把五个角色放在一起读：一个冠军打它们全部，所以在大多数角色上遥遥领先的一对网络，即使在某一个角色上退步，也会成为冠军。冠军的报告见[冠军与基线 §2](/arch/evaluation/champions/#sec-2)。

**晋级**靠手工：脚本什么也不写。通过的一对网络替换两个冠军文件里冠军的网络，SL 文件指明它在门槛中自己打的对局用 `report` 做成的五份报告（[指标、种子与报告 §7](/arch/evaluation/metrics/#sec-7)），它们列上每个角色的排行榜（[冠军与基线 §2](/arch/evaluation/champions/#sec-2)）。

**在已提交的报告上**（在这里算出；并没有真的跑过这样的门槛），用 [§2](#sec-2) 的 A、B 和 C，在 `promotion-1-300` 上：C 对 A，300 对，23 胜对 1 胜，胜局 +0.073 ± 0.016，下界 +0.047，所以它会通过（层数：+2.20 ± 0.62）。B 对 A 也会通过，13 对 1，下界 +0.020，而它的层数是 −0.26 ± 0.70：层数和胜局可能不一致。C 对 B，21 对 11，另有 2 个种子双方都赢，以 +0.0024 通过。

## 11. 测试
