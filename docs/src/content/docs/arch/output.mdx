大脑用一个动作、一个计划和它打过分的那些选项回答一个决策。**输出层**把这个答案变成玩家看得到的东西，或者在玩家要求时，变成游戏里做的事。它运行在游戏进程里的 [Mod](/arch/mod/) 中，每种输出模式读的都是同一条 `Recommendation`：大脑从不知道开着哪种模式。本页写给想改变玩家所见内容的人。[Mod：主循环](/arch/mod/loop/)讲何时询问答案、答案显示多久。

<Aside title="状态">

已实现：**面板**（[§2](#sec-2)），一张盖在游戏上的卡片，带有让 AI 来打的工具栏、V 给出的这一局的胜率、下一个动作及预计在它之后这场战斗或这一局会怎样、之后的计划，以及大脑打过分的选项及其胜率（在地图上还带每个选项的路线）；它的**设置**，在 Mod 加到游戏设置画面里的「AI」标签页中；六种语言的 Mod 用语；两种**标记**（[§3](#sec-3)）：在地图上，推荐的点上有一个圆圈，大脑在它之后规划的路线上有一条线，一直到 Boss；在战斗中，计划的步骤编号显示在它本回合要打出的卡牌上，以及它的目标和结束回合按钮上；以及**自动**（[§4](#sec-4)），AI 在玩家要求时打出答案。规划中：其他决策界面上的高亮、解说（[§5](#sec-5)），以及解说需要的事实。Godot 节点类（`N*` 类型）只按类名引用：每个类名在反编译源码里都是唯一的，按名字就能找到文件。

</Aside>

## 1. 约定

输出读一条消息 `Recommendation`（[协议：线路 §7](/arch/protocol/wire/#sec-7)），按已实现的样子（`Sts2Ai.Protocol/Wire.cs:64-65`）：

| 字段 | 含义 | 由谁给出 |
|---|---|---|
| `decision_id`、`obs_hash` | 它回答的决策 | |
| `action` | 现在要做的动作 | 每个大脑 |
| `brain` | 给出回答的大脑，用 Harness 给它起的名字（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)） | |
| `plan`? | 大脑在 `action` 之后规划的内容 | PIMC：本回合剩下的部分，取自第一个世界；SL 规划器：这场战斗剩下的部分；地图上的 L0：通往 Boss 的路线；其他画面和选牌提示都没有 |
| `candidates`? | 大脑打过分的选项，选中的在前：每个带有它的值、95% 置信区间的半宽和样本数；SL 规划器的还带赢下这场战斗的概率和剩下的生命值；地图上的还带这个选项的路线（[协议：线路 §7](/arch/protocol/wire/#sec-7)） | 战斗大脑；战斗外的 L0（V 给出的这一局的胜率），探索时没有 |

`plan` 在 `action` *之后*：下一步是 `action`，`plan[0]` 是再下一步。

**消费者**。大脑从不知道开着哪种模式。

| 模式 | 消费者 | 状态 |
|---|---|---|
| 面板（辅助模式，简单版） | 一张卡片，适用于所有决策界面（[§2](#sec-2)） | 已实现 |
| 标记（辅助模式） | 地图上的圆圈和路线；战斗计划的编号和圆圈（[§3](#sec-3)） | 已实现 |
| 工具栏 | AI 打出 `action`：一步，打到本回合或这个房间结束，或者自己一直打（[§4](#sec-4)） | 已实现 |
| 自动 | 执行器打出 `action`，每个状态一次，然后 Mod 重新观测（[§4](#sec-4)、[Mod：自动游玩与安全 §1](/arch/mod/auto/#sec-1)） | 已实现 |
| 高亮（辅助模式，进阶版） | 其他决策界面的节点，像执行器找它们的按钮那样找到（[§3](#sec-3)） | 规划中 |

*决策界面*（surface）是当前显示的决策画面的种类（战斗、地图、商店、选牌提示等）。*锚点*（anchor）是画面上一个动作所属的 Godot 节点，例如要打出的那张牌所在的卡牌槽。

**过期的答案**。答案按 id 与开着的决策对应，并按它被问到时的键保存：观测的哈希加上它的合法动作。它只在这个键持续的那些帧上画出来；画面往前走了，面板就为新状态显示「思考中…」，Mod 再次询问（[Mod：主循环 §3](/arch/mod/loop/#sec-3)）。Mod 从不读答案的 `obs_hash`。

**规划中**。

- **事实**：一段解释可以使用的数字，作为推荐的一个字段；也是解说唯一的来源（[§5](#sec-5)）。代码里还没有 `Facts`。
- **随时可答**（anytime）：辅助模式下，大脑先发出目前最好的答案，再陆续发出更好的，每一个替换上一个（[Harness：路由、预算与种子 §4](/arch/harness/routing/#sec-4)）。如今大脑每个决策只发一个答案，Mod 收到第一个答案就了结这个决策。

## 2. 面板

面板是盖在游戏上、靠近左上角的一张卡片（`UI/Panel.cs`）。它有自己的 `CanvasLayer`，这是一种 Godot 节点，把它的子节点画在单独的一层上：第 100 层，在游戏的 UI 之上，所有标记都共用这一层。卡片除了它的按钮之外不接收点击，所以点击会落到它下面的游戏上。F8 连同所有标记一起隐藏和显示它。

<PanelMock client:visible lang="zh-CN" />

**布局**，从上到下（`UI/Panel.cs`）：

- **卡片**：位于 (24, 132)，宽至少 340 px，内边距 12 px（左右两侧 14），圆角半径 14，深紫色边框，一层阴影，以及按不透明度设置填充的近黑色底色。很长的一行可以把它撑宽。它的文字是 11 到 17 px，用游戏自己为它的语言准备的字体（`UI/Fonts.cs`），战斗标记上的数字也是：中文、日文、韩文、俄文和泰文用游戏的替代字体，其他语言用 Kreon。游戏按 1920×1080 的画布排版，再拉伸到窗口大小，并关闭字体的超采样；它自己的字体是 MSDF 字体，在任何缩放下都保持清晰，而引擎的默认字体会在 1080p 下画出、再被拉伸，变得模糊。
- **头部**：一个紫色的「AI」徽标；冠军的名字，下面是状态，各占一行，超出空间处用省略号截断；SL/NoSL 开关，选中的一侧填成紫色（多人模式下两侧都不选中，Mod 关闭时没有开关）；以及「F8」。大脑接下这一局之后，状态就是这一局自己的那一行：角色、进阶、层数和生命值（[Mod §6](/arch/mod/#sec-6)）。
- **工具栏**，调试器的样式，在大脑接下这一局之后出现：三个按钮，高 32 px，每个是一个图标加一个词。图标由 Mod 自己画（`UI/Icons.cs`：播放、暂停、单步、完成），画成显示尺寸 15 px 的三倍大，这样画布的缩放不会让它们变糊。第一个是「自动」（F5），自动游玩进行时变成「暂停」；第二个打一步（F10）：战斗中是「打一张」，地图上是「走一步」，别处是「帮我选」；第三个是完成（F11）：「打完回合」「打完下一房」「走完房间」。自动游玩进行时，另外两个不可用（[Mod：自动游玩与安全 §2](/arch/mod/auto/#sec-2)）。
- **力度那一排**，在工具栏下方：「思考深度」和五个切换按钮，即大脑自己的和 SL 规划器的四个预设（[Mod §5](/arch/mod/#sec-5)）。
- **自动游玩进行时**，再多两排：「速度」，慢、中或快；以及「停在」，两个切换按钮，「精英、Boss 前」和「胜率掉 3 点」。
- **横条**：「本局胜率」和 V 给出的这一局的胜率，用大号字，附上它与之前一个战斗外的回答相比的变化，以百分点计：绿色的「+0.6」或红色的「-2.6」。它的右边是一个显示 AI 状态的胶囊：「等你操作」，「自动中」（一个绿点），一个目标在打时为「执行中」，或者琥珀色的「AI 停下了：原因」。胜率是最近一个战斗外的回答里选中选项的值（V 的，[宏观大脑：搜索 §1](/arch/macro-brain/search/#sec-1)），所以它在每个战斗外的决策处变化，在一场战斗中保持不变；这一局的第一个这样的回答之前，横条上只有胶囊。
- **答案**：「下一步」，然后是实心「1」徽标后面用大号字显示的下一个动作（在地图上用一个圆圈代替徽标）。它下面是较淡的一行：在战斗外是「整局胜率 65.7%」，即 V 给出的、做这个动作之后的胜率；在战斗中是「这场胜率 100% · 剩 64 HP」，即 SL 规划器在它选中的路线上赢下这场战斗的概率和赢下时持有的生命值，在照着计划打的期间保持不变。然后，在地图上是「到 Boss 的路线」和用圆点连起来的路线上的房间，除非下面的选项已经显示了路线；在别处是计划的各步，用空心圆徽标从 2 开始编号；然后是计划后面的回合，「之后还规划 6 回合」（[Mod：主循环 §6](/arch/mod/loop/#sec-6)）。
- **考虑过的选项**，在一条分隔线下面：大脑打过分的选项中最多五个，选中的在前，用淡紫色，其余从好到差。列取决于值是什么：

  | 答案 | 列 |
  |---|---|
  | SL 规划器回答的战斗（它的候选带 `win`） | 「胜率」，在这个选项的最佳路线上赢下这场战斗的概率，取整数百分比；「剩 HP」，赢下时持有的生命值，没有胜算时为「—」 |
  | 战斗外（L0，由 V 估值） | 「胜率」，V 给出的、选这个选项之后赢下这一局的概率，保留一位小数；「差」，它与最好选项的差距，以百分点计，选中的和最好的显示「—」 |
  | PIMC 回答的战斗 | 「分数 ±CI」，平均得分保留三位小数，以及它的 95% 区间的半宽 |

  开启条形时，每一行还有一条 56 px 的轨道，在值的位置有一个短标记，选中那一行的是紫色；对 PIMC，标记横跨区间，并在值的位置有一个刻度。各行共用一个刻度范围：从最低的值到最高的值（含区间），两侧各放宽这段跨度的 15%，且至少半个百分点；战斗的刻度范围延伸到 100%。PIMC 的回答只有在给不止一个动作打过分时才显示这个列表；另外两种只有一个选项也显示。照着沿用的计划打出的一步没有选项。
- **在地图上**，每个选项占「到 Boss 的路线」下的一行：路线画成 16 px 的房间小方块，从这个选项自己的点一直到 Boss，然后是它的胜率和差距，没有条形；在这些行下面是一份图例，列出出现过的房间类型，用地图图例里的名字。一个小方块是用它的类型颜色描边的小正方形，里面是它图例名字的第一个字（未知房间用「?」），Boss 的填成红色；选中路线上的普通房间比其他路线上的更亮。药水栏的药水在地图上也是选项，它没有路线：它那一行只有一个「?」小方块。
- **底部**：给出回答的大脑，以及 Mod 等它的秒数，从发出到收到。
- 没有答案时显示**一条消息**：一个圆点、消息本身和较淡的第二行；玩家可以修正或等它过去的情况用琥珀色，错误用红色。所有消息都列在 [Mod §6](/arch/mod/#sec-6) 里。
- **最近**：AI 打过之后，「刚才做了」和它最近的四个动作，最新的在前：层数、动作，以及它的答案的值，即 V 给出的胜率或这场战斗的胜率。

横条和最近动作在显示消息时也会出现。只有当显示的内容或绘制它所用的设置变化时，主体才会重新搭建；工具栏的标签在游戏语言改变时立即跟着变；标记则每一帧都跟着它们的节点走。

**设置**。玩家的选择保存在 `$XDG_STATE_HOME/sts2ai`（默认是 `~/.local/state/sts2ai`）里的 `settings.json`，在大脑的日志旁边，不在游戏的档案里；每一行、它的取值和默认值见 [Mod §5](/arch/mod/#sec-5)。面板和标记实时读取设置，所以改动立即生效。

**AI 标签页**（`UI/SettingsTab.cs`）位于游戏的设置画面里，排在通用、图形、声音和输入之后。游戏在 `NSettingsTabManager._Ready` 里用场景中的节点搭出它的四个标签页。那里的一个后缀补丁在下一次空闲时运行，这时画面已经完整：它复制输入标签页作为这个标签页的按钮，复制声音面板并清空作为它的面板，所以两者的外观和切换都和游戏自己的一样；副本带上节点和它们的脚本，但不带游戏的信号连接。它把标签栏向左移半格，让它保持居中，把按钮接到管理器自己的标签页切换上，并把这一对加进管理器的标签页。各行是 Mod 自己的控件，用游戏设置行的字体，分在两个标题「辅助」和「自动打」之下：`<  value  >` 式的步进器和一个不透明度滑块，以及一个把它们重置的按钮。所有东西都在加入画面之前搭好，所以搭建失败时，画面保持游戏搭出的样子，错误写进日志。

**语言**（`UI/L10n.cs`）。Mod 自己的用语随游戏设定的语言而变：英语、法语、西班牙语（游戏的两种西班牙语都算）、简体中文、繁体中文和日语；其他任何语言都显示英语。一行文字按它的英文查找，表里缺的行也显示这段英文。名字（卡牌、遗物、药水、怪物、角色、事件、休息处选项、地图图例的房间类型）则来自游戏自己的文本表（[Mod：主循环 §6](/arch/mod/loop/#sec-6)）。Mod 没有写的东西按原样显示：大脑的名字和它的错误消息、异常的文本，以及版本守卫的那一行。

**面板的规划**：每个答案 1–2 条事实（与另一种打法相比的预期掉血、下回合能否斩杀），也是解说唯一会用的数字（[§5](#sec-5)）；以及 [§3](#sec-3) 的各决策界面高亮，例如在每张卡牌奖励的牌上显示它的胜率。

## 3. 高亮

**跟随式覆盖层**。标记由 Mod 自己的节点来画，这些节点只存在于 Mod 的 `CanvasLayer` 里，盖在游戏上面。每一帧，每个标记读取它的目标节点在屏幕上的变换（`GetGlobalTransformWithCanvas()`）和节点的尺寸，所以它能跟住一张会转动、展开成扇形或缩放的牌，并随它移动；目标消失或隐藏时，标记也隐藏。Mod 从不为了绘制而写入游戏的节点，原因有二：`NHandCardHolder.UpdateCard()` 在每次状态变化时都会重置 `CardHighlight` <Badge text="已核实" variant="success" />；而且青色、金色和红色的光效在游戏里已经各有含义（`NCardHighlight`）。Mod 唯一为了绘制而改动游戏节点的地方是设置画面（[§2](#sec-2)）；AI 打的时候，执行器像点击那样按下游戏自己的按钮（[Mod：自动游玩与安全 §1](/arch/mod/auto/#sec-1)）。

**样式**：紫色，一种游戏自己的光效不用的颜色：描边、圆圈，以及带普通数字和深色外圈的紫色圆形徽标。

**在地图上**（`UI/MapMark.cs`）：下一个点上有一个脉动的紫色圆圈，它之后路线上的每段路径都有一条紫色的线，从玩家所在的位置一直到路线的终点。地图画面把它的点节点和每段路径的小点存在私有字典里，新的一幕会替换它们；一条线从路径的第一个小点画到最后一个，所以在点的图标前就停住了。圆圈的半径是点的较长边的一半再加 14，随地图缩放，每秒脉动一次，幅度 ±10%。路线设置显示整条路线、只显示圆圈，或者什么都不显示：

<MapRoute client:visible lang="zh-CN" />

**在战斗中**（`UI/CombatMark.cs`）：面板上显示的那份计划，从 `action` 到本回合结束。

- 计划打出的每张牌，在它的卡牌槽的点击区域上画紫色描边，右上角标出它那一步的编号；
- 每个目标（敌人或盟友）在它的生物节点的点击区域外 10 px 处画描边，瞄准它的每一步的编号放在顶边中间的一个徽标里；
- 结束回合按钮画上描边，并标出它那一步的编号。

已经不在的卡牌或生物没有标记。「卡牌上的出牌顺序」把卡牌的描边和编号一起关掉；「目标与结束回合标记」管其余的。药水没有自己的标记，但它的目标会得到它那一步的编号。

| 休息处 | `NRestSiteButton` | 同上 | 规划中 |
| 商店 | `NMerchantCard/Relic/Potion/CardRemoval` | 购买顺序 | 规划中 |
| 网格选牌 | `NCardGridSelectionScreen` 一族、`NCardGrid` | 勾选标记 | 规划中 |

**容易踩的坑**：

- 卡牌槽节点会被池化（重复使用）、换父节点，还带动画：跟随式覆盖层每一帧都重新查找它们，以此应对。
- 屏幕分辨率、UI 缩放和手柄输入：只用屏幕变换，从不用局部位置。
- 每个动作之后大脑都重新规划，所以每个答案的编号都从 1 重新开始。

## 4. 自动

玩家要求时，AI 自己打出答案（`Assist.cs`，[Mod：自动游玩与安全 §2](/arch/mod/auto/#sec-2)）。这个循环建立在 Mod 的每帧循环之上（[Mod：主循环 §1](/arch/mod/loop/#sec-1)）：

<Steps>

1. 等到画面上的决策保持了 3 帧。
2. 询问大脑，或者取它对这个键的答案：观测的哈希加上它的合法动作。
3. 如果目标已经达成（回合结束了，或者离开了房间、下一个是地图决策），就停下；自动游玩时，如果玩家开着这些停止条件，就在精英或 Boss 之前、以及 V 给出的胜率下降时停下。
4. 从答案显示出来起，按速度等待：1.5、0.8 或 0.2 秒。
5. 通过执行器打出 `action`，只打这一个，这个键只打一次（[Mod：自动游玩与安全 §1](/arch/mod/auto/#sec-1)）；发送 `executed`。
6. 下一个状态是一个新的键：重复。动作之后 10 秒仍然没变的键会让 AI 停下。

</Steps>

每个动作都是一个新的决策：每个动作之后都会再问一次大脑，因为抽到的牌和随机结果会影响下一个决策。照着计划打的大脑，只要游戏显示的正是计划预期的，就从计划里回答，不搜索（[SL 规划器 §4](/arch/sl-planner/#sec-4)）。游戏自己的速度设置保持原样；规划中的自动跑局驱动会把它设为 Instant（[Mod：自动游玩与安全 §2](/arch/mod/auto/#sec-2)）。

## 5. 解说 <Badge text="规划中" variant="caution" />

解说是用来解释一条推荐的文字。

- 它只由事实和候选生成，从不对状态做自由推理。NoSL 的事实是概率和期望；SL 的事实可以是确切的（「先打 A 再打 B 会抽到 X」）。
- 优先用模板，每种事实一个模板。
- 可选：由一个便宜的 LLM 润色文字，离线或异步进行。它的输入是 JSON 形式的事实和模板的文字。它的输出要经过检查：文字里的每个数字都必须等于某个事实的值（格式化之后按字符串匹配）；不满足就改为显示模板的文字。
- LLM 除了事实之外看不到任何游戏状态，也从不影响动作。

这些都还没有实现：推荐里还没有事实（[§1](#sec-1)）。

## 6. 输出中的公平性

| 规则 | 状态 |
|---|---|
| AI 只在玩家要求时打，而且只打出大脑对画面上那个决策的回答，每个状态一次。这个回答由 Harness 对照决策的合法列表检查（[Harness：路由、预算与种子 §6](/arch/harness/routing/#sec-6)） | 成立 |
| 除了回答之外，自动游玩只按那些不是决策的画面：宝箱、继续按钮、先古之民的对话（[Mod：自动游玩与安全 §1](/arch/mod/auto/#sec-1)） | 成立 |
| 没有修改状态、使用控制台或读档的接口 | 成立 |
| 线路（大脑的 stdin 和 stdout）只传输协议消息。SL 导出只在 SL 下发送，带着节点的存档，其中包括种子和随机数流（[Mod：自动游玩与安全 §4](/arch/mod/auto/#sec-4)） | 成立 |
| Mod 只写它的设置文件、大脑的日志（`brain.log`，大脑写到它的 stderr 的内容）和它在游戏日志里的行；设置的 `Record` 打开时，它启动的大脑还会把收到的消息和决策日志写到它们旁边的 `captures/` 里 | 成立 |
| `NumReloads` 记入日志，且必须为 0 | 规划中 |

协议消息里的一个新字段，如果改变了什么可以离开游戏，就在这里加一行。
