## 1. 构建与运行

模拟器是 .NET 项目 `src/Sts2Ai.SimWorker`（目标框架 `net9.0`），一个程序，有很多命令。它引用游戏自己的程序集：`sts2.dll`、`GodotSharp.dll`、`SmartFormat.dll`，以及游戏为 Mod 附带的 `0Harmony.dll`，取自游戏的一份只读快照，不复制到自己的输出目录里（`src/GameReferences.props:8-19`）。

| 设置 | 在哪里 | 作用 |
|---|---|---|
| `Sts2BinDir` | MSBuild 属性，默认 `tmp/gamebin/v0.111.0` | 构建所引用的游戏快照，写进程序里 |
| `STS2_BIN_DIR` | 环境变量，运行时 | 覆盖写进程序的快照；`sts2.dll` 不在那里时程序拒绝启动（`Program.cs:35-48`） |
| `TieredCompilation` | `Sts2Ai.SimWorker.csproj:12-20`，关闭 | 每个方法只编译一次，完全优化：分层编译会在后台重新 JIT 热点方法，Harmony 补丁可能悄悄失效（在几千场战斗之后见过）；而且开着它时，短的运行还慢了一倍 |
| `DOTNET_ReadyToRun=0` | 环境变量，由启动脚本设置 | 框架代码也以完全优化的方式 JIT 编译，每秒战斗数多约 20%；缺少它时，输出的第一行会写明 |
| `SourceRevisionId` | MSBuild，来自 git | 写进程序的提交号，记录和报告都带着它；`src/` 下有未提交改动的构建会带 `-dirty`（`Sts2Ai.SimWorker.csproj:36-48`） |

游戏的程序集由一个解析器找到，它在任何游戏类型被编译之前安装，所以使用这些程序集的入口 `Cli.Run` 不能被内联进 `Main`（`Program.cs:10-12`、`Commands/Cli.cs:44`）。

**启动脚本**。批量任务和集群运行的是某个固定提交的构建，而不是工作区：`tmp/build.sh REV`（一个本地脚本）把这次提交打包归档，以 Release 构建，`SourceRevisionId` 设为这次提交，并写出 `tmp/builds/REV/sim.sh`，它用 `DOTNET_ReadyToRun=0` 运行这个构建的 dll，并把 `HOME` 指向 `tmp/home`。所以通过它启动的 `brain` 监听在 `tmp/home/.local/state/sts2ai/brain.sock`，除非 `--socket` 另行指定（[整局 §7](/arch/simulator/runs/#sec-7)）。集群的主机拿到同样的构建，以及它们自己的启动脚本（fleet 技能，`.claude/skills/fleet/SKILL.md`）。

## 2. 命令行

```text
Sts2Ai.SimWorker COMMAND [options]
```

- **解析**用的是 System.CommandLine 2.0.14。`--help` 在根命令和每个命令上都能用。`--verbose` 放在任何命令之后都能用。没有响应文件：以 `@` 开头的参数就是一个普通参数（`Commands/Cli.cs:24`）。
- **stdout 只输出结果**，供脚本读取；日志写到 stderr，每条一行，形如 `12:34:56 INFO    sim: message`，异常的文本在其后几行（`Runtime/Logs.cs:43-60`）。级别是 Information 及以上，加 `--verbose` 时是 Debug。游戏自己的日志归入类别 `game`：它的错误和警告分别是 Error 和 Warning 级别，其他行是 Debug（[无头宿主 §8](/arch/simulator/headless/#sec-8)）。
- **启动游戏**。只有需要游戏的命令才启动它（`Cli.Game`）；`brain`、`report`、`gate`、`leaderboard` 和 `seeds` 不启动。

**退出码**（`Commands/Cli.cs:45-67`）：

| 退出码 | 含义 |
|---|---|
| 0 | 完成 |
| 1 | 完成，但有失败：失败的战斗或对局、结果不同的重播、游戏错误、没通过的晋级门槛 |
| 2 | 命令行或它指定的文件有错（也包括 I/O 错误，以及不是合法 JSON 或不是合法数据的文件） |
| 70 | bug；会记下它的调用栈 |

按命令分：`run`、`bench`、`selftest` 和 `clones` 有失败时以 1 退出，`gate` 没通过时以 1 退出；`list`、`tables` 和 `combat` 只要运行完总是以 0 退出；`serve` 在第一个失败的请求之后以 1 退出。

## 3. 选项组

几个命令共用一些选项组，定义在 `Commands/Args.cs` 里。

**配置**（`Args.cs:43-58`）：替换初始配置。

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--character` | `SILENT` | 角色 |
| `--deck` | 初始牌组 | `A*5,B+,C+2@SHARP:2`：`*N` 重复，`+` 或 `+N` 升级，`@ENCHANT:AMOUNT` 附魔（`Simulation/Loadout.cs`） |
| `--relics` | 初始遗物 | `A,B`；替换初始遗物，它们的药水槽生效，在一局里它们跳过 `FinalizeStartingRelics` |
| `--potions` | 无 | `A,B`；没有空槽时抛异常 |
| `--hp` | 角色的 | 起始生命值，截在最大生命值以内 |
| `--max-hp` | 角色的 | 起始最大生命值 |

**遭遇池**（`Args.cs:61-96`）：打哪些战斗，外加配置选项。

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--act` | 0 | 幕，从 0 数起 |
| `--rooms` | `weak,regular` | 房间种类，取自 `weak`、`regular`、`elite`、`boss` |
| `--encounter` | 无 | 改为只打一个遭遇；它同时设定幕 |

**预算**（`Args.cs:108-151`）：战斗大脑的预算。plan 的选项需要 `--policy plan`。

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--worlds` | 8 | PIMC 每个决策的世界数 |
| `--nodes` | 300 | 每个世界的节点数；对 plan 是每个状态每回合的节点数 |
| `--effort` | `medium` | plan 的预设：`low` 束宽 8、简易束 2、失败计划 3；`medium` 束宽 8、简易束 4、失败计划 3；`high` 束宽 8；`max` 束宽 16；全都是 300 个节点、replan 1（`src/Sts2Ai.Brain/Combat/CombatBrain.cs:20-27`） |
| `--beam` | 预设的值 | plan 每回合保留的状态数（至少 1） |
| `--easy-beam` | 预设的值 | 贪心下潜获胜时保留的状态数（0：同 `--beam`） |
| `--replan` | 预设的值 | 没有证明的失败计划打几个回合后重新规划（0：打到结束） |
| `--loss-plans` | 预设的值 | 每场战斗连续允许几个没有证明的失败计划（0：不限） |

**叶子**（`Args.cs:153-164`）：给搜索的路线和 l0 的选项估值的东西。

| 选项 | 含义 |
|---|---|
| `--combat-net FILE` | 战斗网络文件，给搜索的叶子估值（[战斗大脑：叶子](/arch/combat-brain/leaf/)）。`pimc` 和 `plan` 需要它，`selftest` 和 `--afterstates clone` 也需要 |
| `--value FILE` | V，一个网络文件：l0 用它给选项估值，它也给战斗网络的结局定价，胜利按它留下的这一局的 V，死亡按 0。`--macro l0` 和 `--combat-net` 需要它（`LeafChoice.cs:16`） |

**冠军**（`Args.cs:196-238`）：构成一个冠军的选项，用于 `run`、`brain` 和 `gate`。

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--policy` | `play` | 战斗大脑：`pimc`（只在 NoSL 下）、`plan`（只在 SL 下），或者占位策略 `play` |
| `--macro` | `random` | 战斗之外的大脑：`l0`（带 V 的宏观大脑）或 `random` |
| 预算选项 | | 见上 |
| `--workers` | `--worlds` | 工作进程数，用于 `pimc`、`plan` 或 `--afterstates clone` |
| `--afterstates` | `screen` | `clone` 在节点的克隆上把每个选项打一遍（SL，`l0`，且需要 `--combat-net`：选项引发的战斗由战斗网络估值）；在 SL 下，`l0` 只在克隆上打 |
| 叶子选项 | | 见上：`--combat-net` 配 `pimc` 或 `plan`，也只配它们；`--value` 配 `l0` 或 `--combat-net` |
| `--explore ε` | 0 | l0 把比例为 ε 的决策在它们的选项中均匀抽取，用于自我对弈；需要 `l0`，`gate` 不接受它 |

**冠军文件**，`--champion FILE`（`Args.cs:166-194`），用于 `run` 和 `brain`：打冠军文件指明的冠军（[评估：冠军与基线 §1](/arch/evaluation/champions/#sec-1)）。文件里的选项排在给出的选项之后，所以给出的选项优先；其中包括它的 `character` 和 `asc`。没有 `--env` 的命令（`brain`）跳过文件里的 `env`；给出的 `--policy` 与文件里的不同时，保留它自己的预算。`gate` 的 `--champion` 是另一个选项：要打败的冠军。

## 5. `selftest`

`selftest` 打遭遇池里的 `--n` 场战斗（默认 20），并运行下面这些检查，按它报告时用的名称列出（`Checks/SelfTest*.cs`；顺序见 `Checks/SelfTest.cs:73-146`）。其中的搜索用 `--combat-net` 指定的网络给叶子估值，所以必须给出它。任何一项失败，退出码就是 1。

边界，即 Brain、Protocol 和 Harness 不触及任何游戏程序集，由单元测试 `BoundaryTests` 在不启动游戏的情况下检查（[§7](#sec-7)）。

**每场战斗**，打两遍：确定性（观测、隐藏状态和轨迹），协议往返（观测，以及以文本和 JSON 表示的动作），没有异常，没有游戏错误。

**每场战斗最多三个随机切点**（所以默认 `--n 20` 时有 60 次构建检查）：还原；隐藏状态逐字节还原；快速钩子监听器给出与游戏相同的结果；确定化保持观测不变（种子 11 和 22）；确定化之后能重播；确定化之后能继续打下去；然后在切点的观测上运行 `CombatBuilder`：构建出的战斗显示这个观测，构建出的战斗能还原，构建之后能继续打下去。

**只存在于模型里的数值的构建**（故障机器人）：磨损的玻璃充能球（3/6）、用完的白银熔炉、保存着 2 张牌的佩尔之牙、1/3 的懒惰、夜魇、14/20 的硬化外壳；构建保留能力的层数（懒惰仍允许打出一张牌）和能力保存的牌（夜魇下回合的复制品）。然后：以 3 点生命、带着王室猛毒构建的玩家能活过开局；瀑布巨兽超过 100 的喷发（`DeathBlow` 150）能被找到。

**规则**：滚石逐个敌人命中（铁甲战士带 10 张滚石，对阵遭遇池里第一个多敌人遭遇；遭遇池里没有这样的遭遇时检查失败）；荆棘在一次 Sly 出牌途中杀死玩家，不留下游戏错误；配置里的遗物给出它们的药水槽，在战斗里和在进阶 4 的一局里都是如此；死在玩家自己的行动之中，或死在第一回合开始时，这场战斗在记录里仍有结束；超过战斗回合上限的战斗算输（在第 80 回合以 999 生命值建出来，这时战斗仍在进行，那个回合结束后就输了）；观测显示一张牌在战斗中积累的东西：谋杀算出的数、Spiral 附魔给的额外打出次数、打出后用掉的 Glam。

**世界与克隆**：世界在选牌提示之后能还原（烘焙手套和生存者，6 个世界）；SL 世界显示这一局的战斗，打法和这一局一样，并能还原；SL 克隆停在它所在节点的出口，拒绝越过出口再走一步；SL 克隆保留存档丢掉的遗物状态（手动把第一个遗物设为禁用）。

**循环**（静默猎手对 535 点生命，300 个节点）：Monologue 和两张 Flash of Steel 互相抽到；SL 规划器（束宽 8）把这个循环重复到获胜，SL 世界按计划结束这场战斗，PIMC 在 2 个世界上发现它的路线在重复。然后在 SL 下，在循环前面加一个提示再测一遍：粒子墙要花星，而这个角色一颗星也没有，直到疯狂之触让它免费，药水的第一个回答却做不到这一点；规划器喝下药水、选让粒子墙免费的那个回答而获胜，比没有提示时晚一回合，用的是药水的节点里分给这个回答的那一部分。

**SL 计划成立**（一局的第二场战斗，150 个节点，束宽 4）：SL 世界按计划结束它的战斗（获胜），并拒绝越过战斗结束再走一步；这一局重新打到那个决策，然后一步一步照着计划打，结束战斗时的生命值、最大生命值和药水与计划在克隆上留下的相同；计划的价值是它的战斗留下的这一局的 V，误差在 1e-9 以内。

**带 `--workers N` 时**：池化的 PIMC 在 4 个决策上与进程内 PIMC 一致，每个决策用 4 个世界 × 120 个节点的预算；池化的规划器做出的计划与规划器在单个进程里做出的相同；工作进程里没有游戏错误；没有工作进程重启。

最后它打印抽牌顺序的统计，这不是一项检查。2026-10-27 的结果：所有检查都通过，静默猎手 60/60 次构建，铁甲战士 58/58，静默猎手第 1、2、3 幕的精英战和 Boss 战分别是 57、57 和 58（[战斗 §5](/arch/simulator/combat/#sec-5)）。

## 6. `run --check`

`run --check` 对它打的每一局比较的内容（[整局 §6](/arch/simulator/runs/#sec-6)）：

| 检查 | 要求 |
|---|---|
| 每个观测的 JSON 往返 | 完全一致 |
| 第二遍走传输协议，连到进程内的大脑或给定的 `--brain` | 相同的轨迹、观测哈希、概况、地图哈希、对局记录和决策日志（耗时除外） |
| 第一遍的每个节点，从检查点加载并重播它的决策 | 逐个给出这一局的观测；移动之后停在视野边界；拒绝再走一步 |
| 游戏错误 | 没有 |

这时每局的结果行以 `obs <digest>` 结尾，它是这一局所有观测哈希的一个哈希，用来跨进程比较对局；汇总里加上 `determinism:` 一行。用 `--brain` 时，大脑的决策日志不在这个进程里，所以日志的比较是在比较两份空日志。

## 7. xUnit 测试

`src/Sts2Ai.Tests` 收着不需要游戏就能运行的测试，21 个类、104 个测试方法：`dotnet test src/Sts2Ai.Tests`。按被测的项目每个一个文件夹（`Brain/`、`Harness/`、`SimWorker/`），`BoundaryTests.cs` 在根目录，共用的 JSON 测试夹具在 `Fixtures.cs` 和 `Fixtures/` 里。

| 类 | 检查什么 |
|---|---|

## 8. 未决问题

1. **复制还是重播**。快照是一份配方，还原就是重播它（[战斗 §2](/arch/simulator/combat/#sec-2)）。对游戏的对象图做深拷贝能消除重播的开销，AlphaZero 式的搜索会需要它。等性能剖析表明还原占了搜索的大部分时间时再定。
2. **对局世界**：房间池和概率计数器有多少能从公开记录推断出来，有多少只能取先验（[世界与 SL 克隆 §8](/arch/simulator/worlds/#sec-8)）。
3. **内联执行**：无头时内联执行动作、而不是每帧执行一次，是否会改变玩家看到的任何东西；在能把游戏里的对局和这里的对局相比较之前，这个问题悬而未决（[整局 §6](/arch/simulator/runs/#sec-6)）。
