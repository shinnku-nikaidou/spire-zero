## 1. 已知弱点

- **标签带着之后的抽取**。在探索更多的对局里，一个局面的标签更低，而 V 不知道这一局的 ε 和 τ（[自我对弈 §3](/arch/macro-brain/selfplay/#sec-3)）。每局设一个切分点可以消除这个问题（[§3](#sec-3)）。
- **网络无法表达的东西**。地图的袋不含连线，地图止于本幕（[价值网络 §8](/arch/macro-brain/network/#sec-8)）。
- **一局一个结局**。一局的决策共享一个标签，所以要分辨哪个决策起了作用，需要很多局（[从风险值到价值 §3](/arch/macro-brain/value/#sec-3)）。

## 2. 规划中，尚未实现

宏观大脑设计中的这些部分还没有实现。

### L1：推演复核

L0 每次都做决定；L1 将是给难分高下的选择加的额外复核，使用评估时的预算。当 L0 排名前两位的价值落在它们的置信区间之内、L0 分不出谁更好时，L1 才会启动。**推演**（rollout）就是用快速策略把游戏往后模拟，看一个选项会把局面带到哪里。对每个候选：

1. 在采样的对局世界里，从它的后状态出发（[模拟器：世界与 SL 克隆 §8](/arch/simulator/worlds/#sec-8)）。
2. 用快速策略往后走 H 个节点（默认走到下一个 Boss）：战斗中用推演策略或浅层搜索，战斗外用 L0。
3. 用公共随机数给候选配对：每个候选都在同一组世界种子里推演，所以它们之间的差值比各自独立采样时噪声小得多。
4. 候选的价值是视野边界处 V 的平均值；如果这一局先结束了，就用最终结果。
5. 按配对差值及其置信区间做选择。

这些反事实的配对推演也将成为 V 在关键决策上的训练信号。在 SL 中，越过当前节点的推演仍然使用采样世界（[环境：信息与节点 §3](/arch/environments/information/#sec-3)）。在地图上，决策只是下一个点，每走一步都重新决定；那里难分高下的选择是 L1 的第一个用途。

### NoSL：对局世界

对局世界没有实现，所以 NoSL 的 L0 根据画面预测后状态（[搜索 §1](/arch/macro-brain/search/#sec-1)）。有了对局世界，它会在 K 个采样世界里执行每个选项，对它们的 V 取平均，并像 SL 的克隆那样搜索多步画面，按观测给状态去重。

### 接口

规划中的 C# 接口。所有非战斗决策界面共用一个入口；Harness 按决策界面名称分派（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)）。

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness/routing §1).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims), or of the act's route on the map
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` 是现在就要执行的动作，`Plan` 是这个画面剩下的步骤（在地图上是本幕剩下的路线），`Candidates` 是每个可能的第一步的价值、置信区间和样本数，`Facts` 是用来解释这个选择的陈述。战斗外的选牌提示和战斗内的一样，都经由 `card_choice` 决策界面到来；`ChoiceContext.Purpose` 说明这个提示的用途，Harness 按是否在战斗中分派。推演里使用的宏观策略是 K 更小的 L0，从不是 L1。

### 预算

- **自我对弈**：固定的分支数，保证对局可复现；L0 总是运行，L1 只在抽样出来的一部分难分高下的选择上运行，其结果成为训练数据。
- **辅助模式**：L0 立即给出答案；玩家查看的同时，L1 继续细化。搜索是*随时可停*（anytime）的：任何时刻停下，都能给出目前最好的答案。
- **自动游玩**：L0 + L1，有墙钟时间上限。

### 测试

1. 覆盖：模拟对局能到达每一个宏观决策界面。
2. 决策测试集（decision panel）：一组固定的（局面，选项）题目，标准答案来自大规模配对推演；按决策界面统计 L0 与标准答案的一致率，由此看出 V 在哪里最弱。
3. NoSL 反事实：公开记录相同、隐藏状态不同（`RoomSet` 尾部、概率计数、随机数流）时，决策相同。
4. 在固定预算下结果确定。

## 3. 未决问题

1. 每局设一个切分点，让决策的标签不带之后的抽取：切分点之前抽取，之后选 V 的最佳，只用之后的决策训练，就像 AlphaGo 的价值网络那样训练。
2. 怎样检查 P(win) 的校准：V 给出 30% 的局面里，应该约有 30% 赢下（[学习：参考 §12](/arch/learning/reference/#sec-12)）。
3. V 能从不含连线的地图袋学到多少路径规划（[价值网络 §8](/arch/macro-brain/network/#sec-8)）。
4. L1 的视野 H（到下一个 Boss 还是到下一幕），以及推演用的战斗策略需要多强。
5. 在 NoSL 中，把商店当作一次决策还是一串决策；在 SL 中，克隆把它当作一串来搜。
