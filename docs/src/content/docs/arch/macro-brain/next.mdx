## 1. 整局对局显示了什么

v6-3-2 在 300 局完整 SL 对局里赢 23 局。它输掉的 277 局，以及在它之前 v6-2 的对局，显示了宏观大脑最弱的地方。

- **大多数败局发生在 Boss 之间**。v6-3-2 的 277 局败局中，约 144 局发生在两个 Boss 之间（第 1 幕 Boss 之前 10 局，第 2 幕在其 Boss 之前约 105 局，第 3 幕在其 Boss 之前约 29 局），约 133 局死在 Boss 处。在训练 V 的精英连战里，Boss 之间的怪物战是免费的。
- **V 在怪物战之前几乎不考虑 HP**。在 v6-2 的整局对局里，299 局败局中有 106 局死在普通怪物战里。地图上面对一场怪物战和一个休息处时，v6-2 在最大生命 40% 或以下时有 46% 的情况选了怪物（52 次中 24 次），在 70–90% 时为 50%。贯穿全章的例子里也有同样的选择：在第 43 层、HP 24/66 时，v6-3-2 给怪物的估值比休息处高 0.12 层（[后状态 §2](/arch/macro-brain/afterstates/#sec-2)）。在连战里这是对的：怪物不花任何代价。
- **连战的排序不是整个游戏的排序**。v6-3-1 在连战里胜过 v6-2（+1.73 ± 0.54），整局赢 13 局而 v6-2 只赢 1 局，到达的层数却没有更高（−0.26 ± 0.70）（[自我对弈 §5](/arch/macro-brain/selfplay/#sec-5)）。
- **标签带着之后的抽取**。在探索更多的对局里，一个局面的标签更低，而 V 不知道这一局的 ε（[自我对弈 §2](/arch/macro-brain/selfplay/#sec-2)）。
- **编码器把地图看成词袋，牌和遗物相遇得太晚**。V 分不出同一条路径上休息处是否在精英之后，牌与遗物的配合必须先穿过汇总后的牌组，才能遇到遗物词袋（[价值网络 §1](/arch/macro-brain/network/#sec-1)、[§3](/arch/macro-brain/network/#sec-3)）。编码器网络用不同的方式读这两者（[价值网络 §4](/arch/macro-brain/network/#sec-4)）。

## 2. 下一步

下一个计划（v7）处理前三点和最后一点；标签暂时保持不变。它的代码已经实现：整局对局的 objective 和晋级门槛，以及编码器网络。它的第一代自我对弈正由 v6-3-2 在打，这个计划的网络还一个都没有训练。

**回到整局对局**。V 的自我对弈和晋级门槛都打完整的游戏：普通怪物战也由 SL 规划器去打。自我对弈沿用 low 预算和 ε 为 0.3 / 0.15 / 0.05 的均匀抽取；晋级门槛用冠军的规划器、medium 力度。精英连战不再用来训练或评判 V。

**P(win)，以及按胜局的晋级门槛**。V 用整局对局训练，标签同[从风险值到价值 §2](/arch/macro-brain/value/#sec-2)：死在第 $e$ 层的对局在那里结束，赢下的对局活过每一层，中途停下的对局只标到它停下的地方。于是它的价值是活过每一层的概率 $P(\text{win}) = S_{63}$（objective 为 `win`，即 `v.train --objective win`），从同一个风险值输出头读出；比例头去掉。训练器的报告另外给出这个概率在留出数据上的 Brier 分数：预测的概率与这一局的结果（1 或 0）之差的平方的平均。第二个输出头继续学接下来六场战斗的 HP 花费，现在包括怪物战。晋级门槛在 500 个种子上（`promotion-1-500`，它的前 300 个就是 `promotion-1-300`）把挑战者和冠军的对局按种子配对，比较胜负（1 或 0）：平均差值的 95% 单侧下界大于 0 时挑战者通过，在 500 个种子上这大约需要多赢 2–3 个百分点。报告保留层数、每一幕的 Boss 打赢率、对局死在哪里（Boss、精英、怪物、战斗外，按幕分）、每局的精英数，以及按 HP 分的「怪物还是休息」选择。

**单一 V 内部的构筑编码器和路线编码器**。单一的 V 和它单一的分数保持不变（[后状态 §4](/arch/macro-brain/afterstates/#sec-4)）；只有输入一侧改变，改在编码器网络里（[价值网络 §4](/arch/macro-brain/network/#sec-4)）。构筑编码器让牌、遗物和药水在汇总之前相互作用；路线编码器从 Boss 往回读地图的路径。主干、输出头、`IRunValue`、`MacroBrain` 和 `CloneSearch` 都不变。`learn/v/encode.py` 仍是唯一的规范，`RunNet` 按它构建同样的张量，网络文件里的测试对局检查两边。

**各代**。每一代的自我对弈都在截止时间内运行。只用这一代的对局训练两个网络：一个纯 V 从冠军的权重接着训练（v7-1 从 v6-3-2 开始，去掉它的比例头），一个编码器网络从上一个编码器网络接着训练（v7-1e 从零开始）。两者在同一个晋级门槛里与冠军对阵；如果都通过，取赢得多的那个。通过的网络取代两个冠军文件里的 V。

## 3. 规划中，尚未实现

宏观大脑设计中的这些部分早于当前的计划，还没有实现。

### L1：推演复核

L0 每次都做决定；L1 将是给难分高下的选择加的额外复核，使用评估时的预算。当 L0 排名前两位的价值落在它们的置信区间之内、L0 分不出谁更好时，L1 才会启动。**推演**（rollout）就是用快速策略把游戏往后模拟，看一个选项会把局面带到哪里。对每个候选：

1. 在采样的对局世界里，从它的后状态出发（[模拟器：世界与 SL 克隆 §8](/arch/simulator/worlds/#sec-8)）。
2. 用快速策略往后走 H 个节点（默认走到下一个 Boss）：战斗中用推演策略或浅层搜索，战斗外用 L0。
3. 用公共随机数给候选配对：每个候选都在同一组世界种子里推演，所以它们之间的差值比各自独立采样时噪声小得多。
4. 候选的价值是视野边界处 V 的平均值；如果这一局先结束了，就用最终结果。
5. 按配对差值及其置信区间做选择。

这些反事实的配对推演也将成为 V 在关键决策上的训练信号。在 SL 中，越过当前节点的推演仍然使用采样世界（[环境：信息与节点 §3](/arch/environments/information/#sec-3)）。在地图上，决策只是下一个点，每走一步都重新决定；那里难分高下的选择是 L1 的第一个用途。

### NoSL：对局世界

NoSL 还没有对局世界，所以它的 L0 根据画面预测后状态（[搜索 §1](/arch/macro-brain/search/#sec-1)）。有了对局世界，它会在 K 个采样世界里执行每个选项，对它们的 V 取平均，并像 SL 的克隆那样搜索多步画面，按观测给状态去重。

### 接口

规划中的 C# 接口。所有非战斗决策界面共用一个入口；Harness 按决策界面名称分派（[Harness：路由、预算与种子 §1](/arch/harness/routing/#sec-1)）。

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness §4).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims), or of the act's route on the map
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` 是现在就要执行的动作，`Plan` 是这个画面剩下的步骤（在地图上是本幕剩下的路线），`Candidates` 是每个可能的第一步的价值、置信区间和样本数，`Facts` 是用来解释这个选择的陈述。战斗外的选牌提示和战斗内的一样，都经由 `card_choice` 决策界面到来；`ChoiceContext.Purpose` 说明这个提示的用途，Harness 按是否在战斗中分派。推演里使用的宏观策略是 K 更小的 L0，从不是 L1。

### 预算

- **自我对弈**：固定的分支数，保证对局可复现；L0 总是运行，L1 只在抽样出来的一部分难分高下的选择上运行，其结果成为训练数据。
- **辅助模式**：L0 立即给出答案；玩家查看的同时，L1 继续细化。搜索是*随时可停*（anytime）的：任何时刻停下，都能给出目前最好的答案。
- **自动游玩**：L0 + L1，有墙钟时间上限。

### 测试

1. 覆盖：模拟对局能到达每一个宏观决策界面，兜底次数为 0。
2. 决策测试集（decision panel）：一组固定的（局面，选项）题目，标准答案来自大规模配对推演；按决策界面统计 L0 与标准答案的一致率，由此看出 V 在哪里最弱。
3. NoSL 反事实：公开记录相同、隐藏状态不同（`RoomSet` 尾部、概率计数、随机数流）时，决策相同。
4. 在固定预算下结果确定。

## 4. 未决问题

1. 每局设一个切分点，让决策的标签不带之后的抽取：切分点之前抽取，之后选 V 的最佳，只用之后的决策训练，就像 AlphaGo 的价值网络那样训练。
2. V 按 P(win) 做决定之后，怎样检查 P(win) 的校准：V 给出 30% 的局面里，应该约有 30% 赢下（[学习：参考 §12](/arch/learning/reference/#sec-12)）。
3. 有了路线编码器，V 能从地图学到多少路径规划，与词元词袋相比如何。
4. L1 的视野 H（到下一个 Boss 还是到下一幕），以及推演用的战斗策略需要多强。
5. 在 NoSL 中，把商店当作一次决策还是一串决策；在 SL 中，克隆把它当作一串来搜。
