V 是一个神经网络，读一局，预测它会怎样结束。本节按 v6-3-2 的样子介绍当前的 V，即**纯 V**（`learn/v/`）：它读什么，每一层怎样变换输入，以及为什么这样构建。它的输出怎样变成价值、它怎样训练，见[下一节](/arch/macro-brain/value/)。

## 1. V 读什么

纯 V 读的是**这一局是什么和它的原始状态，别的都不读**。没有手写的特征，没有牌的伤害或费用，没有遗物的效果：一张牌、一件遗物或一副牌组里什么要紧，由网络从对局的结局里去学。

输入都读自 Harness 在每个决策处记下的整局观测（[Harness §6](/arch/harness/#sec-6)）：

- **牌组里的每张牌**：它的 id、升级次数（最多算 3），以及它的附魔和诅咒的 id（如果有）。
- **每件遗物**：它的 id，用完后加上 `:used`。**每瓶药水**：它的 id。
- **上下文**：角色、本幕的 id、本幕的一个或多个 Boss，以及本幕的 Ancient。
- **地图**：从玩家所在的点（最后去过的点，还没去过就从起点）沿路径走得到的每个点，一点一个词元：它的类型加上还有几层，例如 `Elite+3`，有任务标记的再加 `:quest`。
- **六个数字**：层数、HP、最大 HP、金币、进阶等级和药水栏数。每个都用训练数据的均值和标准差做标准化，$(x - \mu)/\sigma$，网络文件里保存着这两个值。

训练数据中出现不到 3 次的 id 都读作同一个共享的*未知* id。v6-3-2 的词表有 509 个卡牌 id、21 个修饰、260 个遗物 id、53 种药水、26 个上下文词元和 133 个地图词元，每项都算上了未知 id。这一切唯一的规范是 `learn/v/encode.py`；大脑的 `RunNet`（它的 `Tokens`、`MapTokens` 和 state）以及本页的图都照它来做。

图中的地图是本幕的点构成的图，第 0 行在最下面。带圈的点是玩家所在的位置；彩色的点是沿地图路径仍能走到的点，V 读的就是它们；灰色的点在身后，或者不在前方任何一条路径上。把指针移到一个点上可以看到它的词元。地图被当作这些词元的一个*词袋*来读：V 知道三层之后有一个精英、四层之后有一个休息处，却不知道在同一条路径上休息处是否在精英之后。保留路径是下一步之一（[弱点与下一步 §2](/arch/macro-brain/next/#sec-2)）。

**为什么不用手写的知识**。第一个 V（V v0，`RunValue`）是这一局的 17 个手写特征乘以以 1 HP 为单位的权重：一瓶药水值 8 HP，一件遗物 8，一张升级过的牌 3，一枚金币 0.1，牌组里每张牌 −0.3，再加上牌组的平均伤害、格挡和抽牌。后来的网络 n2-b0.03 把这 17 个特征作为输入，训练时还被拉向 V v0 的选择。它的选择跟着这些价格走。在 `promotion-1` 的 SL 对局上（n2-b0.03 为 160 局，其他为 200 局）：

| | n2-b0.03（读 V v0 的特征） | pure-1-g（纯 V） | 随机选择 |
|---|---|---|---|
| HP 在 70–85% 时的休息处：选择休息的比例 | 99% | 51% | 48% |
| HP 在 85–99% 时的休息处：选择休息的比例 | 35% | 7% | 53% |
| 买的药水 | 417 | 330 | 92 |
| 买的牌 | 55 | 313 | 162 |
| 离开商店时剩下的金币（平均） | 89 | 27 | 36 |

一瓶值 8 HP 的药水卖 50–75 金币（按金币的价格合 5–7.5 HP），看起来总是划算，而回 21 HP 总是胜过值 3 的升级。手写的价格就是手写的策略，它错的地方对局无法纠正，因为网络照抄了它。纯 V 没有价格；它唯一的老师是这一局的结局。

## 2. 网络结构

网络把词元变成每张牌一个向量，汇总牌组，把每个词袋求和，接上数字，再把结果送过两层的主干，到达各个输出头。对一副 $n$ 张牌的牌组，用公式写出来：

**牌向量**。第 $k$ 张牌有 id $c_k$、升级次数 $u_k \le 3$ 和修饰 id $m$（它的附魔和诅咒）。它的输入向量（32 个数）是

$$
x_k = E[c_k] + u_k\, U[c_k] + \sum_{m \in \mathrm{mods}(k)} M[m],
$$

其中 $E$、$U$ 和 $M$ 是学到的表（*嵌入*）：每个卡牌 id 一个向量，每个卡牌 id 一个*升级方向*，每种修饰一个向量。升级让一张牌沿着网络为这张牌学到的方向移动。

**集合编码器**。一个小网络 $\varphi$（32 → 128 → 128，ReLU）逐张处理每张牌，牌组用两种方式汇总：

$$
h_k = \varphi(x_k), \qquad \bar h = \frac{1}{n}\sum_{k=1}^{n} h_k, \qquad \tilde h = \frac{1}{16}\sum_{k=1}^{n} h_k .
$$

平均值 $\bar h$ 说明牌组由什么组成；缩放后的总和 $\tilde h$ 还说明有多少张（因子 $1/16$ 让它保持在平均值的量级）。

**词袋**。遗物、药水、上下文和地图各自是其词元的 32 维向量之和：$r = \sum_i R[\text{relic}_i]$，另外三个也一样。

**主干**。牌组的两个汇总、四个词袋和六个标准化后的数字拼接成一个 $128 + 128 + 4 \cdot 32 + 6 = 390$ 维的向量 $z$，然后

$$
b_1 = \mathrm{ReLU}(W_1 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_2 b_1 + c_2),
$$

两者都是 256 维。**输出头**读 $b_2$：对 0 到 63 的每一层 $g$，给出一个*风险值* $h_g = \sigma(w_g^\top b_2 + a_g)$，即这一局活着到达第 $g$ 层时在那里结束的概率；对连战的 V，还用第二组权重给出一个*比例* $s_g$（[从风险值到价值 §1](/arch/macro-brain/value/#sec-1)）。第三个输出头只在训练时用，不在网络文件里（[从风险值到价值 §3](/arch/macro-brain/value/#sec-3)）。

| 部分 | 形状 | 权重数 |
|---|---|---|
| 卡牌、升级、修饰嵌入 | 509 × 32、509 × 32、21 × 32 | 33,248 |
| 遗物、药水、上下文、地图嵌入 | 260、53、26、133 × 32 | 15,104 |
| $\varphi$ | 32 → 128 → 128 | 20,736 |
| 主干 | 390 → 256 → 256 | 165,888 |
| 风险值输出头和比例头 | 256 → 64，两个 | 32,896 |
| **合计** | | **267,872** |

## 3. 为什么用集合编码器

牌组是一个*多重集*：牌的顺序没有意义，大小从大约 10 张到 40 张不等。按序列读牌的网络必须学会每种顺序都一样；每种牌一个计数、长度固定的向量会有几百个大多为空的槽位，相似的牌之间也不共享任何东西。上面的结构是一个 **Deep Set**（Zaheer 等，2017）：形如 $\rho\left(\sum_k \varphi(x_k)\right)$ 的函数，对输入的任意顺序给出相同的输出，能读任意大小的集合，而且每个具有这种性质的函数都能写成这种形式。这里 $\varphi$ 是单牌网络，$\rho$ 是主干。

每个卡牌 id 都有自己学到的向量，所以网络一开始对任何牌都一无所知。它对一张牌学到的东西，来自牌组里有这张牌的那些对局，经由这些对局的每个决策。这就是为什么出现不到 3 次的 id 读作未知：只用一两局训练出的向量就是噪声。

这个设计有一个已知的局限。牌与牌之间、牌与遗物之间，只有在主干里才相遇，那时牌组已经汇总成两组 128 个数。像「有手里剑和苦无时小刀更值钱」这样的关系，必须先穿过这些汇总后的数字，才能遇到遗物词袋。在汇总之前给牌和遗物加一层注意力，就能让它们直接相互作用，这是下一个计划里构筑编码器的一部分（[弱点与下一步 §2](/arch/macro-brain/next/#sec-2)）。
