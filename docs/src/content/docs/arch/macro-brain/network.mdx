V 是一个神经网络，读一局，预测它会怎样结束。本节从输入到输出介绍它：它读什么，每一层怎样变换输入，以及为什么这样构建。代码是 `learn/v/net.py` 里的 `Net`，它的输入由 `learn/v/encode.py` 规定。它的输出是什么意思、它怎样训练，见[下一节](/arch/macro-brain/value/)。想先看每一步的真实数字，请到 [§9](#sec-9)。

## 1. 整个网络

七个部分各自读一种输入：**牌组**、**遗物**、**药水**、**上下文**、**地图**、**六个数字**和**遗物保留的牌**。它们的输出拼接成一个 1,030 维的向量，一个 MLP（*多层感知机*：线性层之间夹着非线性）把它变成每层一个风险值。这些风险值给出价值，即 P(win)。

只有牌组有自己的层，遗物保留的牌也经过这几层。几个袋只是学到的向量直接求和，部分与部分之间的一切关系都在拼接之后才算出来。

一个 V 给每一局估值：全部五个角色、每个进阶等级、两种环境，都用同一套权重（`weights/all/`）。角色是上下文词元之一，进阶等级是六个数字之一。

|---|---|---|
| 牌组 | 每张牌一个向量 | $B \times n \times 64$ |

| | 平均值和总和 ÷ 16，拼接 | $B \times 512$ |
| 遗物 | 各遗物的向量，连同它们的数值和状态，求和 | $B \times 64$ |
| 药水 | 各药水的向量，求和 | $B \times 64$ |
| 上下文 | 各词元的向量，求和 | $B \times 64$ |
| 地图 | 各词元的向量，求和 | $B \times 64$ |
| 数字 | 标准化后 | $B \times 6$ |
| 保留的牌 | 每张牌的向量经过 $\varphi$ | $B \times l \times 256$ |
| | 求和 | $B \times 256$ |
| 拼接 | 七部分全部 | $B \times 1030$ |
| 主干 | 两层 | $B \times 512$ |
| 输出头 | 每层一个风险值 | $B \times 64$ |

## 2. 它读什么

V 读的是**这一局是什么和它的原始状态，别的都不读**。没有手写的特征，没有遗物的效果，没有牌的费用：一张牌、一件遗物或一副牌组里什么要紧，由网络从对局的结局里去学。牌的数值只在它的 id 说不出来的地方才读入，经由这张牌自己的行（[§3](#sec-3)）。手写的价格（「一瓶药水值 8 HP」）就是手写的策略，读它的网络会照抄它，而对局无法纠正这种照抄。

输入都来自 Harness 在每个决策处记下的整局观测（[Harness：决策日志 §7](/arch/harness/decision-log/#sec-7)），由 `encode.tokens` 和 `encode.state` 读出：

- **牌组里的每张牌**：它的 id、升级次数（更高的读作 3），以及它的修饰词元：它的附魔和诅咒（如果有），写作 `enchant:ID` 和 `affliction:ID`；它的关键词，写作 `keyword:K`；以及 Tinker Time 把一张疯狂科学做成了什么，写作 `tinker:TYPE` 和 `rider:RIDER`。还有三个数，一局里它们会在一张牌上增长：它的附魔和诅咒的数值（黏糊的数值每打出一次就增长），它的伤害（巨镰的）和它的格挡（遗传算法的），奥斯提攻击牌读的是奥斯提的伤害。
- **每件遗物**：它的 id，用完后加上 `:used`，以及战斗网络从它读的东西（[战斗网络 §2](/arch/combat-brain/network/#sec-2)）：它的计数 / 10（不显示计数时为 0，截断在 ±10 以内）、是否显示计数、是否熔化，以及它的状态：不是正常状态时是游戏的状态，否则一场一次或一回合一次的效果已用掉时为 `Spent`，再否则为 `Normal`。还有它保留的牌，按 id：佩尔之牙的。
- **持有的每瓶药水**：它的 id。空栏不是词元；药水栏数是六个数字之一。
- **上下文**：`character:ID`、`act:ID`、`boss:ID`，本幕有两个 Boss 时再加第二个 `boss:ID`，本幕有 Ancient 时再加 `ancient:ID`。
- **地图**：路径仍能通往的每个点，写成它的类型和在前方几层（[§4](#sec-4)）。
- **六个数字**：层数、HP、最大 HP、金币、进阶等级和药水栏数。

**它不读什么**。牌的费用和它的其他数值、遗物上印的数，以及保留的牌除 id 以外的一切。只在这些地方不同的两局是同一个输入。

**词表**。网络文件为每种词元保存一张 id 表。每张表按排序列出这个游戏版本的每个 id，排在第 0 项之后；第 0 项是同一个共享的*未知* id，它读任何其他 id，比如比文件新的 id（`learn/game_ids.py`，来自 `learn/game_ids.json`，由模拟器的 `tables` 命令写出）。所以这些表不依赖训练数据。`modifiers` 列出附魔、诅咒和关键词、Tinker Time 的卡牌类型和附加效果，以及 V 从不会拿到的 `spent`；上下文的表列出游戏的幕、Ancient、Boss 和角色；地图的表列出前方 0 到 20 层的每种点，每种都分带和不带 `:quest` 两项；`relic_status` 和战斗网络的一样，列出游戏的遗物状态和 `Spent`。保留的牌读 `cards` 表。

**数字**按训练样本的平均值和标准差做标准化，$(x - \mu)/\sigma$，每个样本的权重是它所在对局样本数的倒数。小于 $10^{-9}$ 的标准差读作 1。网络文件保存 $\mu$ 和 $\sigma$。

**输入张量**，按计算图输入的顺序排列（`encode.INPUTS`）。每个列表都补齐到批次里最长的长度，且至少为 1，并有一个掩码，存在的位置为 1，补齐的位置为 0：

| 名称 | 形状 | 类型 | 内容 |
|---|---|---|---|
| `cards` | $B \times n$ | int | 每张牌的表项 |
| `ups` | $B \times n$ | float | 它的升级次数，0 到 3 |
| `card_mask` | $B \times n$ | float | 存在还是补齐 |
| `mods` | $B \times n \times m$ | int | 它的修饰词元的表项，$m$ 是一张牌最多有的个数 |
| `mod_mask` | $B \times n \times m$ | float | 哪些修饰词元存在 |
| `mod_amounts` | $B \times n \times m$ | float | 它的附魔和诅咒的数值 / 10，放在对应修饰的位置上，截断在 ±10 以内；其他位置为 0 |
| `numbers` | $B \times n \times 2$ | float | 它的伤害 / 20 和它的格挡 / 20，截断在 ±10 以内 |
| `relics`、`relic_mask` | $B \times r$ | int、float | 每件遗物的表项及其掩码 |
| `potions`、`potion_mask` | $B \times p$ | int、float | 每瓶药水的表项及其掩码 |
| `context`、`context_mask` | $B \times c$ | int、float | 每个上下文词元的表项及其掩码 |
| `map`、`map_mask` | $B \times m$ | int、float | 每个地图词元的表项及其掩码 |
| `state` | $B \times 6$ | float | 六个数字，标准化后 |
| `relic_values` | $B \times r \times 3$ | float | 每件遗物的计数 / 10、是否显示计数（计算图不用）、是否熔化 |
| `relic_status` | $B \times r$ | int | 每件遗物的状态的表项 |
| `held`、`held_mask` | $B \times l$ | int、float | 遗物保留的每张牌在 `cards` 表里的表项，及其掩码 |

## 3. 牌组

牌组是一个*多重集*：牌的顺序没有意义，大小从大约 10 张到 40 张不等。按序列读它，网络就得学会每种顺序都一样；每种牌一个计数的向量会有几百个大多为空的槽位，相似的牌之间也不共享任何东西。所以每张牌各自经过同一个小网络，再把结果加起来：这是一个 Deep Set（Zaheer 等，2017）。

**牌的向量**。id 为 $c$、升级次数为 $u$、伤害为 $d$、格挡为 $k$、修饰为 $m$ 且修饰数值为 $a_m$ 的牌成为 64 个数：

$$
x = E[c] + u\, U[c] + d\, D[c] + k\, K[c] + \sum_{m} \big(M[m] + a_m A[m]\big).
$$

$E$、$U$ 和 $M$ 是学到的表（*嵌入*）：每个卡牌 id 一个向量，每个卡牌 id 一个*升级方向*，每种修饰一个向量。升级让一张牌沿着为这张牌学到的方向移动，所以升级对一张牌可以很要紧，对另一张牌可以无关紧要。$D$、$K$ 和 $A$ 也是方向：每个卡牌 id 各有一个用于它的伤害、一个用于它的格挡，每种修饰有一个用于它的数值。一个数只移动它自己的牌或修饰，所以 V 能学到一把长大了的巨镰或一个数值很大的黏糊值多少，而不需要一条把每张牌的伤害都一样读的规则。对数值由 id 和升级就定下的牌，这些数说不出新东西，它的这几行可以停在原处。每个表项的初始值都是标准差 0.1 的随机数。

**$\varphi$，牌的网络**。两层，每张牌用同样的权重：

$$
\varphi(x) = \mathrm{ReLU}\big(W_2\, \mathrm{ReLU}(W_1 x + b_1) + b_2\big),
$$

其中 $W_1$ 是 64 → 256，$W_2$ 是 256 → 256。ReLU 是 $\max(0, x)$，逐个数地取，所以 256 个输出都不小于 0。这里 $\varphi$ 只看到一张牌：一张牌的两个副本得到相同的向量，没有哪张牌知道牌组里还有什么。

**汇总**。把向量加起来，补齐的槽位不算，再用两种方式读：

$$
\bar h = \frac{1}{n}\sum_{k=1}^{n} \varphi(x_k), \qquad \tilde h = \frac{1}{16}\sum_{k=1}^{n} \varphi(x_k).
$$

平均值说明牌组由什么组成。只有它的话，一副牌组和它翻倍后的牌组读起来是一样的，所以缩放后的总和说明有多少（因子 $1/16$ 让它保持在平均值的量级）。两者是同一个向量的两种比例，所以这 512 个数里是 256 个数的方向，再加上牌组的大小。

**牌与牌怎样关联**。汇总后的向量是总和，所以牌与牌之间的关系不在 $\varphi$ 里算。它分两步得到：$\varphi$ 可以给某类牌一个专属的数，让总和数出这类牌有多少；然后拼接之后的主干再把这些计数相互组合，或者和遗物组合。「很多小刀加一个手里剑」只需要这些。它的代价见 [§8](#sec-8)。

**遗物保留的牌**。遗物可以把牌留在牌组之外：佩尔之牙在被拾取时从牌组里拿走一些牌，之后每赢下一场战斗就把其中一张升级后还回来。每张这样的牌只取它 id 的向量 $E[c]$，来自牌组的表，经过同一个 $\varphi$，结果不经缩放直接求和：

$$
\hat h = \sum_{c \in \text{kept}} \varphi\big(E[c]\big).
$$

这 256 个数在拼接里自成一部分，和牌组的分开，所以网络能分清一张牌是被遗物留着还是在牌组里。没有保留的牌时是零向量。

## 4. 袋：遗物、药水、上下文、地图

这四者都是一个**袋**：每个词元有一个学到的 64 维向量，把这些向量加起来。中间没有层，也不取平均。一个词元出现两次就算两次。

$$
\text{bag}(t_1, \dots, t_k) = \sum_{i=1}^{k} T[t_i].
$$

每个袋有自己的表 $T$：遗物 id、药水 id、上下文词元和地图词元。空袋是零向量。

**一件遗物**在它 id 的向量上加上战斗网络从它读的东西：它的计数 $q$（/ 10）乘以它 id 的一个学到的向量，熔化时（$\mu = 1$）加一个学到的向量 $W$，再加它的状态 $s$ 的向量，

$$
T[r] + q\, T_q[r] + \mu\, W + T_s[s],
$$

遗物的袋把这些加起来。计数减少（遗物的次数）或状态改变（效果已用掉），遗物的向量就沿着它自己的方向移动。

**地图的词元**（`encode.map_tokens`）。玩家的点是最后去过的点；还没去过时是起点（先按行、再按列的第一个点）。从那里，网络沿着地图的连线找到路径仍能通往的每个点，每个点成为一个词元：它的类型和在前方几层，写作 `Elite+3`，有任务标记时加上 `:quest`。所以这个袋说明的是，每个距离上各有多少种房间。它不含连线（[§8](#sec-8)）。

**正要进入的点**。在地图上，V 比较选项的方式是给每个选项的后状态估值：把这个点加进路径，别的都不变（[搜索 §1](/arch/macro-brain/search/#sec-1)）。两个选项之后的点常常相同，所以选项只能靠这个点本身来区分。因此选路的后状态带一个标记（`MapView.Entering`），它的袋以进入的点开头，写作 `Elite+0`。

这个标记的意思是*正要进入*，仅此而已。玩家已经站着的房间不是词元，原因很要紧：在房间里记下的整局观测都在它的战斗之后，死在那里的对局记不下来。当前房间的词元在训练时只会被活下来的对局读到，V 就会把进入精英当成已经打赢了它。

所以每次选路还会给出一个自己的训练样本，即选中的点的后状态，加上那一局真实的结局（[从风险值到价值 §3](/arch/macro-brain/value/#sec-3)）。于是 V 学到的是，在这点 HP 下进入精英值多少，死在这场精英战里的对局也算在内。

## 5. 主干和输出头

**数字**按标准化后的值原样读入（[§2](#sec-2)）。

**拼接**。七个输出拼接成一个 $512 + 64 + 64 + 64 + 64 + 6 + 256 = 1030$ 维的向量 $z$：牌组、四个袋、数字，以及遗物保留的牌。

**主干**是一个两层的 MLP，每层 512 维：

$$
b_1 = \mathrm{ReLU}(W_3 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_4 b_1 + c_2).
$$

所有信息都在这里相遇。牌组没有见过遗物，地图没有见过 HP；一条有两个精英的路径是否适合这副牌组、这点 HP，要由主干算出来。

**风险值输出头**是 $b_2$ 上的一个线性层，后接 sigmoid：对 0 到 63 的每一层 $g$，给出一个*风险值*

$$
h_g = \sigma(w_g^\top b_2 + a_g),
$$

即这一局活着到达第 $g$ 层时在那里结束的概率。价值是从这一局当前所在的第 $f$ 层起活过每一层的概率：

$$
\text{P(win)} = \prod_{g = f}^{63} (1 - h_g).
$$

第 $f$ 层之前各层的风险值会被算出，但不使用（[从风险值到价值 §2](/arch/macro-brain/value/#sec-2)）。

**第二个输出头**是 $b_2$ 上的一个 6 输出线性层，只在训练时用。它预测接下来几场战斗的 HP 花费，以此塑造主干；它从不用来做决定，也不在网络文件里（[从风险值到价值 §4](/arch/macro-brain/value/#sec-4)）。

## 6. 大小和开销

| 部分 | 形状 | 权重数 |
|---|---|---|
| 卡牌、升级、伤害、格挡、修饰、数值嵌入 | 4 × 597 × 64、2 × 57 × 64 | 160,128 |
| 遗物、药水、上下文、地图嵌入 | 310、66、32、379 × 64 | 50,368 |
| 遗物的计数、状态、熔化 | 310 × 64；5 × 64；64 | 20,224 |
| $\varphi$ | 64 → 256 → 256 | 82,432 |
| 主干 | 1030 → 512 → 512 | 790,528 |
| 风险值输出头 | 512 → 64 | 32,832 |
| **合计** | | **1,136,512** |

词表是固定的，所以这些大小只取决于游戏版本。只在训练时用的输出头另加 3,078 个。

**文件里有什么**。冠军的文件是 `weights/all/v9-2.json`。它学自全部五个角色在进阶 0、用 medium 预算打的 SL 自我对弈：21,272 局，其中赢下 5,608 局，留出 4,310 局（它的 `fit`，[从风险值到价值 §6](/arch/macro-brain/value/#sec-6)）。伤害、格挡和数值各行（$D$、$K$、$A$）学过了，只要有训练对局给过一张牌这样的数：170 张牌的伤害行、68 张牌的格挡行和 20 种附魔的数值行。这三者的其他行为零，所以 V 不给那些数任何权重。遗物的计数、状态和熔化向量也为零，主干读遗物保留的牌的那 256 列也为零：V 同样不给这些输入任何权重。它的 $\mu$ 和 $\sigma$ 来自进阶 0 的对局：进阶的 $\mu$ 是 0，$\sigma$ 读作 1，所以 A10 读作 10。没有哪局训练对局见过的 id，比如 `SHIV`、各种诅咒或 `FAKE_` 遗物，什么也没学到：它的行仍是开始时的那一行。

在 C# 里单线程、批次大小为 1 时，一次调用约要 0.08 ms。在克隆上做一个宏观决策要 70–90 ms，大部分花在游戏里（[搜索 §6](/arch/macro-brain/search/#sec-6)），所以 V 自身的开销无关紧要。

## 7. 一个前向计算，两种实现

训练器用 PyTorch 计算这个网络；大脑用 C# 运行它。两者必须完全一致，靠的是网络文件（`weights/all/NAME.json`，[学习：参考 §7](/arch/learning/reference/#sec-7)）：

- **导出**。`learn/v/export.py` 把网络写成文件里的一个 ONNX 计算图，包括 sigmoid，输入按 [§2](#sec-2) 命名，每个长度都不固定。旁边是词表、$\mu$ 和 $\sigma$、训练报告，以及 8 个留出的样本和训练器给它们的值。
- **推理**。`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）照着 `encode.py` 来做：它的 `Tokens` 和 state，以及战斗网络用来读遗物数值和状态的 `CombatNet.RelicInputs`，构建同样的张量（`Hazards`，`:174-221`），由 ONNX Runtime 运行计算图。`Value` 把当前层起的风险值连乘起来。
- **检查**。除非文件给这 8 个样本的值和训练器的相差不超过 0.1%（最小的那些值用 $10^{-6}$，那里浮点数的噪声更大），否则 `RunNet.Load` 拒绝这个文件。任何一边读一局的方式有差异，文件都加载不了。P(win) 的值可以只有百分之几，比如在一局艰难对局的后段，而不是相对值的容差在那里几乎什么都能放过。

## 8. 结构无法表达的东西

这些都只由结构得出。

- **求和之前，牌看不到别的牌**。牌与牌之间的关系只能以挺过相加的数字到达主干。数出一类牌很容易；特定几张牌之间的关系，得在所有牌共用的 256 个数里找到自己的数。
- **遗物的袋是线性的**。310 件遗物共用 64 个数，拼接之前没有任何层。两件遗物之间、一件遗物和一张牌之间的关系，只能由主干算出来。
- **保留的牌只是 id**。整局观测只按 id 给出遗物保留的牌，所以牌组里的牌带着的修饰和数值，它们都读不到。
- **地图的袋不含连线**。它列出每个距离上有什么，不说明哪个点通往哪个点。分别在两条路径上的一个精英和一个休息处，读起来和两者同在一条路径上一样。玩家面前的选择靠每个选项自己的袋看到；更前面的选择看不到。
- **地图止于本幕**。网络读的是当前这一幕余下的点。对之后的幕，它只知道层数所暗示的东西；它们的地图、Boss 和 Ancient 不在整局观测的地图里。
- **身后的东西没有了**。已经走过的点和不在前方任何路径上的点都不是词元。这一局在那里得到的东西，在它的配置、HP 和金币里。
- **只有 id，没有规则**。网络认识一张牌，只靠牌组里有它的那些对局。训练数据里从未有过的牌什么也没学到，不管它有什么效果。
- **每种风险共用一个数**。风险值说明这一局有多大可能在每一层结束，不说明原因。单个输出头要承载每一种死法。
