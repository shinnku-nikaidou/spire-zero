V 是一个神经网络，读一局，预测它会怎样结束。本节从输入到输出介绍它：它读什么，每一层怎样变换输入，以及为什么这样构建。代码是 `learn/v/net.py` 里的 `EncoderNet`，它的输入由 `learn/v/encode.py` 规定。它的输出是什么意思、它怎样训练，见[下一节](/arch/macro-brain/value/)。

## 1. 整个网络

四个部分各自读一种输入：读整套配置的**构筑编码器**、读地图的**路线编码器**、一袋**上下文**词元和**六个数字**。它们的输出拼接成一个 262 维的向量，一个 MLP（*多层感知机*：线性层之间夹着非线性）把它变成每层一个风险值。这些风险值给出价值，即 P(win)。

这张图仿照 Transformer 论文里那张图的画法：输入在最下面；框表示重复的方块（×2：两个方块，各有自己的权重；×16：一轮，用同样的权重跑 16 次）；⊕ 表示残差相加；侧边的线表示越过中间、直接往上送的输入。把指针移到一个方块上，可以看到它计算什么。

沿途的形状如下，其中一个批次有 $B$ 局，$n$ 张牌，$r$ 件遗物，$p$ 瓶药水，$e = n + r + p$ 个元素，$c$ 个上下文词元，$m$ 个路线节点，每个节点最多通往 $f$ 个节点：

| 步骤 | 内容 | 形状 |
|---|---|---|
| 构筑 | 每张牌、每件遗物和每瓶药水各一个向量 | $B \times e \times 64$ |
| | 两个注意力块，然后一次层归一化 | $B \times e \times 64$ |
| | 平均值和总和 ÷ 16，拼接 | $B \times 128$ |
| 路线 | 每个节点的初始向量 | $B \times m \times 32$ |
| | 一轮里，它通往的节点的向量 | $B \times m \times f \times 32$ |
| | 初始向量、最大值和平均值，拼接 | $B \times m \times 96$ |
| | 一轮之后的每个节点 | $B \times m \times 32$ |
| | 玩家所在的节点和所有节点的平均，拼接 | $B \times 64$ |
| 上下文 | 各词元的向量，求和 | $B \times 64$ |
| 数字 | 标准化后 | $B \times 6$ |
| 拼接 | 四部分全部 | $B \times 262$ |
| 主干 | 两层 | $B \times 256$ |
| 输出头 | 每层一个风险值 | $B \times 64$ |

## 2. 它读什么

V 读的是**这一局是什么和它的原始状态，别的都不读**。没有手写的特征，没有牌的伤害或费用，没有遗物的效果：一张牌、一件遗物或一副牌组里什么要紧，由网络从对局的结局里去学。手写的价格（「一瓶药水值 8 HP」）就是手写的策略，读它的网络会照抄它，而对局无法纠正这种照抄。

输入都来自 Harness 在每个决策处记下的整局观测（[Harness：决策日志 §7](/arch/harness/decision-log/#sec-7)），由 `encode.tokens` 和 `encode.state` 读出：

- **牌组里的每张牌**：它的 id、升级次数（更高的读作 3），以及它的附魔和诅咒的 id（如果有），写作 `enchant:ID` 和 `affliction:ID`。
- **每件遗物**：它的 id，用完后加上 `:used`。
- **持有的每瓶药水**：它的 id。空栏不是词元；药水栏数是六个数字之一。
- **上下文**：`character:ID`、`act:ID`、`boss:ID`，本幕有两个 Boss 时再加第二个 `boss:ID`，本幕有 Ancient 时再加 `ancient:ID`。
- **路线**：玩家所在的位置，以及路径仍能通往的每个点（[§4](#sec-4)）。
- **六个数字**：层数、HP、最大 HP、金币、进阶等级和药水栏数。

**词表**。网络文件为每种词元保存一张 id 表。表由训练样本建立：在其中出现不到 3 次的 id 都读作第 0 项，即同一个共享的*未知* id。计数按决策算，所以在一局的三个决策处出现的牌有自己的表项。从先前的网络接着训练的网络沿用那个网络的表，它没见过的 id 读作未知。

**数字**按训练样本的均值和标准差做标准化，$(x - \mu)/\sigma$，每个样本的权重是它所在对局决策数的倒数。小于 $10^{-9}$ 的标准差读作 1。网络文件保存 $\mu$ 和 $\sigma$。

**输入张量**，按计算图输入的顺序排列（`encode.ENCODER_INPUTS`）。每个列表都补齐到批次里最长的长度，且至少为 1，并有一个掩码，存在的位置为 1，补齐的位置为 0：

| 名称 | 形状 | 类型 | 内容 |
|---|---|---|---|
| `cards` | $B \times n$ | int | 每张牌的表项 |
| `ups` | $B \times n$ | float | 它的升级次数，0 到 3 |
| `card_mask` | $B \times n$ | float | 存在还是补齐 |
| `mods` | $B \times n \times 2$ | int | 它的修饰的表项，最多 2 个 |
| `mod_mask` | $B \times n \times 2$ | float | 哪些修饰存在 |
| `relics`、`relic_mask` | $B \times r$ | int、float | 每件遗物的表项及其掩码 |
| `potions`、`potion_mask` | $B \times p$ | int、float | 每瓶药水的表项及其掩码 |
| `context`、`context_mask` | $B \times c$ | int、float | 每个上下文词元的表项及其掩码 |
| `route` | $B \times m$ | int | 每个节点类型的表项 |
| `route_ahead` | $B \times m$ | int | 在玩家前方几层，0 到 16 |
| `route_quest` | $B \times m$ | float | 节点有任务标记时为 1 |
| `route_mask` | $B \times m$ | float | 存在还是补齐 |
| `route_next` | $B \times m \times f$ | int | 它通往的节点的索引 |
| `route_next_mask` | $B \times m \times f$ | float | 其中哪些存在 |
| `state` | $B \times 6$ | float | 六个数字，标准化后 |

## 3. 构筑编码器

牌组是一个*多重集*：牌的顺序没有意义，大小从大约 10 张到 40 张不等。遗物和药水也是集合，它们的价值取决于牌，也取决于彼此：有手里剑和苦无时小刀更值钱。所以三者进入**同一个集合**，集合汇总之前，其中的元素就相互作用。按序列读它们，网络就得学会每种顺序都一样；每种牌一个计数的向量会有几百个大多为空的槽位，相似的牌之间也不共享任何东西。

**元素**。每张牌、每件遗物和每瓶药水都成为一个 64 维的向量：

$$
x =
\begin{cases}
E[c] + u\, U[c] + \sum_{m} M[m] + v_{\text{card}} & \text{a card,}\\[2pt]
R[r] + v_{\text{relic}} & \text{a relic,}\\[2pt]
P[p] + v_{\text{potion}} & \text{a potion.}
\end{cases}
$$

$E$、$U$、$M$、$R$ 和 $P$ 是学到的表（*嵌入*）：每个卡牌 id 一个向量，每个卡牌 id 一个*升级方向*，每种修饰、每个遗物 id 和每个药水 id 各一个向量。id 为 $c$、升级次数为 $u$ 的牌，沿着为这张牌学到的方向移动 $u$ 步。$v_{\text{card}}$、$v_{\text{relic}}$ 和 $v_{\text{potion}}$ 是学到的*种类向量*，它们告诉网络一个元素是三种中的哪一种。每个表项的初始值都是标准差 0.1 的随机数，种类向量也一样。

**自注意力块**（Vaswani 等，2017）让每个元素查看集合里的其他每个元素，并吸收它们的一个加权混合。权重由这个元素根据它自己的向量和它们的向量算出。这样的块有两个，各有自己的权重，每个做两次更新，每次都加回到元素上：

$$
x \leftarrow x + W_o\, \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{FF}(\mathrm{LN}(x)).
$$

- **LN** 是层归一化：每个向量经过平移和缩放，使均值为 0、方差为 1。归一化在每次更新之前做（*pre-norm*）。
- **MHA** 是多头注意力，见下文。
- **$W_o$** 是注意力输出上的一个 64 → 64 的线性层。
- **FF** 是一个小 MLP（64 → 128 → 64，中间是 ReLU），对每个元素单独作用。

**多头注意力**。一个线性层把每个归一化后的元素从 64 个数映射到 192 个数，再切成 4 个头各自的查询、键和值，每个 16 个数。在一个头里，元素 $i$ 有一个查询 $q_i$，每个元素 $j$ 有一个键 $k_j$ 和一个值 $v_j$。于是

$$
a_{ij} = \frac{\exp\!\big(q_i^\top k_j / 4 + \text{pad}_j\big)}{\sum_{j'} \exp\!\big(q_i^\top k_{j'} / 4 + \text{pad}_{j'}\big)}, \qquad y_i = \sum_j a_{ij}\, v_j .
$$

$a_{ij}$ 是元素 $i$ 对元素 $j$ 的关注程度，其中的 4 是 $\sqrt{16}$，即通常的缩放。对存在的元素，$\text{pad}_j$ 为 0；对补齐的槽位，它为 $-10^9$，所以没有元素会关注补齐的槽位。四个 $y_i$ 拼接回 64 个数，再经过 $W_o$。

**没有位置**。句子上的 Transformer 会把每个词的位置加到它的向量上。这里没有：元素没有顺序。注意力和汇总对每个元素一视同仁，所以输出不依赖集合的顺序。一张牌的两个副本有相同的向量，经过每一层都保持相同。

**汇总**。两个块之后再做最后一次层归一化，补齐的槽位置零，然后用两种方式汇总集合：

$$
\bar x = \frac{1}{e}\sum_{k=1}^{e} x_k, \qquad \tilde x = \frac{1}{16}\sum_{k=1}^{e} x_k .
$$

平均值说明这套配置由什么组成；缩放后的总和还说明有多少（因子 $1/16$ 让它保持在平均值的量级）。两者合起来是 128 个数。集合上这样的汇总函数是一个 Deep Set（Zaheer 等，2017），汇总之前做注意力是 Set Transformer（Lee 等，2019）的思路，这里用在整套配置上。它只读 id，没有手写的「攻击」或「技能」标记。

## 4. 路线编码器

地图上的选择是路径的选择：同一条路径上、精英之后的休息处，和另一条路径上、玩家得改走那条路才能到的休息处，并不一样。所以路线编码器读的是路径本身。

**节点**（`encode.route`）。节点 0 是玩家所在的位置：最后去过的点；还没去过时是起点（先按行、再按列的第一个点）。接着是沿地图的连线找到的、从那里的路径仍能通往的点，先按行、再按列排序。每个节点有四个字段：

- 它的类型（怪物、精英、休息处、商店、未知、宝箱、先古之民、Boss）；
- 它在玩家前方几层，最多算 16；
- 它是否有任务标记；
- 它的连线通往的节点在这个列表里的索引。

在低预算整局对局的 1,242 个局面上，一个局面最多有 69 个可达的点（平均 22 个），没有哪个点通往超过 5 个点。Boss 是最后一个点，在本幕地图的第 15 或 16 行。

**初始向量**。每个节点从 $s_i = T[\text{type}_i] + A[\text{ahead}_i] + q_i\, v_{\text{quest}}$ 开始，32 维，其中 $T$ 和 $A$ 是学到的表，$v_{\text{quest}}$ 是学到的向量，有任务标记时 $q_i$ 为 1，否则为 0。

**各轮**。然后重复 16 次，每个节点都由它的初始向量和它通往的节点重新算出：

$$
h_i \leftarrow \mathrm{ReLU}\Big( W \big[\, s_i \,;\; \max_{j \in \mathrm{next}(i)} h_j \,;\; \operatorname{mean}_{j \in \mathrm{next}(i)} h_j \,\big] + b \Big),
$$

- $[\,\cdot\,;\cdot\,]$ 把向量首尾相接，共 96 个数。
- 最大值逐个数地取。
- 第一轮之前 $h = s$。
- Boss 不通往任何点，所以它的最大值和平均值都是 0（代码用 `leads` 把它们设为 0，并用 `route_next_mask` 把补齐的节点排除在两者之外）。
- 每一轮都用同样的 $W$ 和 $b$，每一轮都重新读初始向量 $s_i$。

$k$ 轮之后，一个节点的向量取决于它前方最多 $k$ 步之内的节点。信息就这样从 Boss 往回传，每轮一层。一幕的地图在起点之上有 16 行，所以 16 轮能把 Boss 的信息带到任何一个节点。

这是一个从 Boss 往回、学出来的**动态规划**。经典的动态规划从 Boss 往回，对每个点算出从它出发的最佳路径的价值：$\text{value}(i) = \text{reward}(i) + \max_{j \in \text{next}(i)} \text{value}(j)$。每一轮的形状与它相同：

- 用向量代替单个数值；
- 用学到的 $W$ 代替加法；
- 在最大值之外，再加上下一批点的平均值。一局并不总能走上它的最佳路径，所以其他路径上有什么也要紧。

用图网络的术语来说，它是沿地图连线的**消息传递**（Gilmer 等，2017），只往回传，所有轮共用一个更新。

**输出**。玩家所在节点的向量 $h_0$，以及所有节点的平均，共 64 个数。前者是「沿着路径，我前方有什么」；后者概括本幕余下的部分。

## 5. 主干和输出头

**上下文和数字**。上下文是一个词袋：它的各词元的向量（每个 64 维）求和。六个标准化后的数字原样读入。

**拼接**。四个输出拼接成一个 $128 + 64 + 64 + 6 = 262$ 维的向量 $z$。

**主干**是一个两层的 MLP，每层 256 维：

$$
b_1 = \mathrm{ReLU}(W_1 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_2 b_1 + c_2).
$$

所有信息都在这里相遇。路线没有见过 HP，配置没有见过地图；一条有两个精英的路径是否适合这副牌组、这点 HP，要由主干算出来。

**风险值输出头**是 $b_2$ 上的一个线性层，后接 sigmoid：对 0 到 63 的每一层 $g$，给出一个*风险值*

$$
h_g = \sigma(w_g^\top b_2 + a_g),
$$

即这一局活着到达第 $g$ 层时在那里结束的概率。价值是从这一局当前所在的第 $f$ 层起活过每一层的概率：

$$
\text{P(win)} = \prod_{g = f}^{63} (1 - h_g).
$$

第 $f$ 层之前各层的风险值会被算出，但不使用（[从风险值到价值 §2](/arch/macro-brain/value/#sec-2)）。

**第二个输出头**是 $b_2$ 上的一个 7 输出线性层，只在训练时用。它预测接下来几场战斗的 HP 花费，以此塑造主干；它从不用来做决定，也不在网络文件里（[从风险值到价值 §4](/arch/macro-brain/value/#sec-4)）。

## 6. 大小和开销

| 部分 | 形状 | 权重数 |
|---|---|---|
| 卡牌、升级、修饰嵌入 | 509 × 64、509 × 64、21 × 64 | 66,496 |
| 遗物、药水、上下文嵌入 | 260、53、26 × 64 | 21,696 |
| 种类向量和任务向量 | 3 × 64、32 | 224 |
| 类型和前方层数嵌入 | 9 × 32、17 × 32 | 832 |
| 两个自注意力块 | 64 维，4 个头，前馈 128 | 66,432 |
| 路线更新 $W, b$ | 96 → 32 | 3,104 |
| 主干 | 262 → 256 → 256 | 133,120 |
| 风险值输出头 | 256 → 64 | 16,448 |
| **合计** | | **308,352** |

嵌入的大小取决于词表，而词表取决于训练数据；表中按数据给出的大致大小计算，类型按八种点类型加上未知 id 计算。一个自注意力块的注意力部分有 16,608 个权重（64 → 192、64 → 64），前馈部分有 16,576 个（64 → 128 → 64）。只在训练时用的输出头另加 1,799 个。

在 C# 里单线程、批次大小为 1 时，一次调用要 0.44 ms。大部分花在注意力和 16 轮上。在克隆上做一个宏观决策要 70–90 ms，大部分花在游戏里（[搜索 §6](/arch/macro-brain/search/#sec-6)），所以 V 自身的开销无关紧要。

## 7. 一个前向计算，两种实现

训练器用 PyTorch 计算这个网络；大脑用 C# 运行它。两者必须完全一致，靠的是网络文件（`weights/silent/NAME.json`，[学习：参考 §7](/arch/learning/reference/#sec-7)）：

- **导出**。`learn/v/export.py` 把网络写成文件里的一个 ONNX 计算图，包括 sigmoid，输入按 [§2](#sec-2) 命名，每个长度都不固定。旁边是词表、$\mu$ 和 $\sigma$、objective `win`、训练报告，以及 8 个留出的对局和训练器给它们的值。
- **推理**。`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）照着 `encode.py` 来做：它的 `Tokens`、`Route` 和 state 构建同样的张量，由 ONNX Runtime 运行计算图。只有计算图声明了的输入才会被送入。`Value` 把当前层起的风险值连乘起来。
- **检查**。除非文件给这 8 局的值和训练器的相差不超过 $10^{-3}$，否则 `RunNet.Load` 拒绝这个文件。任何一边读一局的方式有差异，文件都加载不了。
- **沉默的路线**。一个未经训练的微型网络（宽度很小，权重放大，`src/Sts2Ai.Tests/Fixtures/pure-v-tiny-encoders.json`）在三个真实的整局观测上运行。路线失去连线或前方层数时，它的值必须变动加载检查容差的 10 倍；每种类型都读作未知时，必须变动 3 倍。所以一个悄悄忽略了地图的路线编码器通不过测试。

网络有两个细节出自导出，而不是出自设计。层归一化没有自己的缩放和平移，由各自后面的线性层承担。种类向量和任务向量的初始值是随机的，不是零。两者都是必要的，因为 ONNX 导出会合并值相等的权重，那样它们的名字就会从文件里消失，而从一个网络文件接着训练时要按这些名字读回权重。

## 8. 结构无法表达的东西

这些都只由结构得出；每一条在实际对局里代价多大，没有测过。

- **路线看不到构筑**。节点的向量只由地图算出。一条路径对这副牌组、这点 HP 值多少，只能在主干里算，而主干读到的是概括整条路线的 64 个数。
- **最大值混合了不同路径**。通往节点上的最大值是逐个数地取的，所以一个节点的向量可以在不同的数上保存不同路径的最佳值。它不是任何一条路径的向量。
- **路线止于本幕**。网络读的是当前这一幕余下的点。对之后的幕，它只知道层数所暗示的东西；它们的地图、Boss 和 Ancient 不在整局观测的地图里。
- **身后的东西没有了**。已经走过的点和不在前方任何路径上的点都不是节点。这一局在那里得到的东西，在它的配置、HP 和金币里。
- **汇总是瓶颈**。不论配置多大，它都以 128 个数到达主干。两个元素之间的关系必须在两个注意力块里算出来，或者能挺过汇总。
- **两个块**。一个元素的向量只吸收其他元素两次。需要更多步的关系只能挤在这两次之内。
- **只有 id，没有规则**。网络认识一张牌，只靠牌组里有它的那些对局。训练数据里出现不到 3 次的牌读作共享的未知 id，不管它有什么效果。
- **每种风险共用一个数**。风险值说明这一局有多大可能在每一层结束，不说明原因。单个输出头要承载每一种死法。
