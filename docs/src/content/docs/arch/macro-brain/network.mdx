V 是一个神经网络，读一局，预测它会怎样结束。本节按 v6-3-2 的样子介绍当前的 V，即**纯 V**（`learn/v/`）：它读什么，每一层怎样变换输入，以及为什么这样构建。然后 §4 介绍**编码器网络**，即下一个计划在它旁边并列训练的结构。它的输出怎样变成价值、它怎样训练，见[下一节](/arch/macro-brain/value/)。

## 1. V 读什么

纯 V 读的是**这一局是什么和它的原始状态，别的都不读**。没有手写的特征，没有牌的伤害或费用，没有遗物的效果：一张牌、一件遗物或一副牌组里什么要紧，由网络从对局的结局里去学。

输入都读自 Harness 在每个决策处记下的整局观测（[Harness §6](/arch/harness/#sec-6)）：

- **牌组里的每张牌**：它的 id、升级次数（最多算 3），以及它的附魔和诅咒的 id（如果有）。
- **每件遗物**：它的 id，用完后加上 `:used`。**每瓶药水**：它的 id。
- **上下文**：角色、本幕的 id、本幕的一个或多个 Boss，以及本幕的 Ancient。
- **地图**：从玩家所在的点（最后去过的点，还没去过就从起点）沿路径走得到的每个点，一点一个词元：它的类型加上还有几层，例如 `Elite+3`，有任务标记的再加 `:quest`。
- **六个数字**：层数、HP、最大 HP、金币、进阶等级和药水栏数。每个都用训练数据的均值和标准差做标准化，$(x - \mu)/\sigma$，网络文件里保存着这两个值。

训练数据中出现不到 3 次的 id 都读作同一个共享的*未知* id。v6-3-2 的词表有 509 个卡牌 id、21 个修饰、260 个遗物 id、53 种药水、26 个上下文词元和 133 个地图词元，每项都算上了未知 id。这一切唯一的规范是 `learn/v/encode.py`；大脑的 `RunNet`（它的 `Tokens`、`MapTokens` 和 state）以及本页的图都照它来做。

图中的地图是本幕的点构成的图，第 0 行在最下面。带圈的点是玩家所在的位置；彩色的点是沿地图路径仍能走到的点，V 读的就是它们；灰色的点在身后，或者不在前方任何一条路径上。把指针移到一个点上可以看到它的词元。地图被当作这些词元的一个*词袋*来读：V 知道三层之后有一个精英、四层之后有一个休息处，却不知道在同一条路径上休息处是否在精英之后。编码器网络读的是路径（[§4](#sec-4)）。

**为什么不用手写的知识**。第一个 V（V v0，`RunValue`）是这一局的 17 个手写特征乘以以 1 HP 为单位的权重：一瓶药水值 8 HP，一件遗物 8，一张升级过的牌 3，一枚金币 0.1，牌组里每张牌 −0.3，再加上牌组的平均伤害、格挡和抽牌。后来的网络 n2-b0.03 把这 17 个特征作为输入，训练时还被拉向 V v0 的选择。它的选择跟着这些价格走。在 `promotion-1` 的 SL 对局上（n2-b0.03 为 160 局，其他为 200 局）：

| | n2-b0.03（读 V v0 的特征） | pure-1-g（纯 V） | 随机选择 |
|---|---|---|---|
| HP 在 70–85% 时的休息处：选择休息的比例 | 99% | 51% | 48% |
| HP 在 85–99% 时的休息处：选择休息的比例 | 35% | 7% | 53% |
| 买的药水 | 417 | 330 | 92 |
| 买的牌 | 55 | 313 | 162 |
| 离开商店时剩下的金币（平均） | 89 | 27 | 36 |

一瓶值 8 HP 的药水卖 50–75 金币（按金币的价格合 5–7.5 HP），看起来总是划算，而回 21 HP 总是胜过值 3 的升级。手写的价格就是手写的策略，它错的地方对局无法纠正，因为网络照抄了它。纯 V 没有价格；它唯一的老师是这一局的结局。

## 2. 网络结构

网络把词元变成每张牌一个向量，汇总牌组，把每个词袋求和，接上数字，再把结果送过两层的主干，到达各个输出头。下图从最下面的输入画到最上面的输出；把指针移到一个方块上，可以看到它计算什么。

<ArchDiagram client:visible lang="zh-CN" net="pure" />

对一副 $n$ 张牌的牌组，用公式写出来：

**牌向量**。第 $k$ 张牌有 id $c_k$、升级次数 $u_k \le 3$ 和修饰 id $m$（它的附魔和诅咒）。它的输入向量（32 个数）是

$$
x_k = E[c_k] + u_k\, U[c_k] + \sum_{m \in \mathrm{mods}(k)} M[m],
$$

其中 $E$、$U$ 和 $M$ 是学到的表（*嵌入*）：每个卡牌 id 一个向量，每个卡牌 id 一个*升级方向*，每种修饰一个向量。升级让一张牌沿着网络为这张牌学到的方向移动。

**集合编码器**。一个小网络 $\varphi$（32 → 128 → 128，ReLU）逐张处理每张牌，牌组用两种方式汇总：

$$
h_k = \varphi(x_k), \qquad \bar h = \frac{1}{n}\sum_{k=1}^{n} h_k, \qquad \tilde h = \frac{1}{16}\sum_{k=1}^{n} h_k .
$$

平均值 $\bar h$ 说明牌组由什么组成；缩放后的总和 $\tilde h$ 还说明有多少张（因子 $1/16$ 让它保持在平均值的量级）。

**词袋**。遗物、药水、上下文和地图各自是其词元的 32 维向量之和：$r = \sum_i R[\text{relic}_i]$，另外三个也一样。

**主干**。牌组的两个汇总、四个词袋和六个标准化后的数字拼接成一个 $128 + 128 + 4 \cdot 32 + 6 = 390$ 维的向量 $z$，然后

$$
b_1 = \mathrm{ReLU}(W_1 z + c_1), \qquad b_2 = \mathrm{ReLU}(W_2 b_1 + c_2),
$$

两者都是 256 维。**输出头**读 $b_2$：对 0 到 63 的每一层 $g$，给出一个*风险值* $h_g = \sigma(w_g^\top b_2 + a_g)$，即这一局活着到达第 $g$ 层时在那里结束的概率；对连战的 V，还用第二组权重给出一个*比例* $s_g$（[从风险值到价值 §1](/arch/macro-brain/value/#sec-1)）。第三个输出头只在训练时用，不在网络文件里（[从风险值到价值 §3](/arch/macro-brain/value/#sec-3)）。

| 部分 | 形状 | 权重数 |
|---|---|---|
| 卡牌、升级、修饰嵌入 | 509 × 32、509 × 32、21 × 32 | 33,248 |
| 遗物、药水、上下文、地图嵌入 | 260、53、26、133 × 32 | 15,104 |
| $\varphi$ | 32 → 128 → 128 | 20,736 |
| 主干 | 390 → 256 → 256 | 165,888 |
| 风险值输出头和比例头 | 256 → 64，两个 | 32,896 |
| **合计** | | **267,872** |

## 3. 为什么用集合编码器

牌组是一个*多重集*：牌的顺序没有意义，大小从大约 10 张到 40 张不等。按序列读牌的网络必须学会每种顺序都一样；每种牌一个计数、长度固定的向量会有几百个大多为空的槽位，相似的牌之间也不共享任何东西。上面的结构是一个 **Deep Set**（Zaheer 等，2017）：形如 $\rho\left(\sum_k \varphi(x_k)\right)$ 的函数，对输入的任意顺序给出相同的输出，能读任意大小的集合，而且每个具有这种性质的函数都能写成这种形式。这里 $\varphi$ 是单牌网络，$\rho$ 是主干。

每个卡牌 id 都有自己学到的向量，所以网络一开始对任何牌都一无所知。它对一张牌学到的东西，来自牌组里有这张牌的那些对局，经由这些对局的每个决策。这就是为什么出现不到 3 次的 id 读作未知：只用一两局训练出的向量就是噪声。

这个设计有一个已知的局限。牌与牌之间、牌与遗物之间，只有在主干里才相遇，那时牌组已经汇总成两组 128 个数。像「有手里剑和苦无时小刀更值钱」这样的关系，必须先穿过这些汇总后的数字，才能遇到遗物词袋。在汇总之前给牌和遗物加一层注意力，就能让它们直接相互作用；这就是编码器网络的构筑编码器（[§4](#sec-4)）。

## 4. 编码器网络

下一个计划在纯 V 旁边并列训练第二种结构：**编码器网络**（`learn/v/net.py` 里的 `EncoderNet`，用 `v.train --encoders` 训练；它的第一个网络将是 v7-1e）。它读的 id 和数字与纯 V 相同，也保留纯 V 的主干和输出头。只有输入一侧改变，改在纯 V 最弱的两处：

- **构筑编码器**取代牌组的集合编码器以及遗物和药水词袋。牌、遗物和药水组成同一个集合，在集合汇总之前，其中的元素就相互作用。
- **路线编码器**取代地图词袋。它把可达的点当作由路径构成的图来读，而不是当作词元的词袋。

### 构筑编码器

这一局的每张牌、每件遗物和每瓶药水都成为同一个集合里的一个元素，即一个 64 维的向量：

$$
x =
\begin{cases}
E[c] + u\, U[c] + \sum_{m} M[m] + v_{\text{card}} & \text{a card,}\\[2pt]
R[r] + v_{\text{relic}} & \text{a relic,}\\[2pt]
P[p] + v_{\text{potion}} & \text{a potion.}
\end{cases}
$$

对 id 为 $c$、升级次数为 $u$、修饰为 $m$ 的牌，第一行就是纯 V 的牌向量（[§2](#sec-2)），只是现在是 64 维；$r$ 和 $p$ 是遗物和药水的 id。$v_{\text{card}}$、$v_{\text{relic}}$ 和 $v_{\text{potion}}$ 是学到的*种类向量*：它们告诉网络一个元素是三种中的哪一种。

然后集合经过两个**自注意力块**（Vaswani 等，2017）。自注意力让每个元素查看集合里的其他每个元素，并吸收它们的一个加权混合。权重由这个元素根据它自己的向量和它们的向量算出。一个块做两次更新，每次都加回到元素上：

$$
x \leftarrow x + W_o\, \mathrm{MHA}(\mathrm{LN}(x)), \qquad x \leftarrow x + \mathrm{FF}(\mathrm{LN}(x)).
$$

- **LN** 是层归一化：每个向量经过平移和缩放，使均值为 0、方差为 1。
- **FF** 是一个小网络（64 → 128 → 64，ReLU），对每个元素单独作用。
- **MHA** 是多头注意力：4 个注意力头，每个 16 维，并排运行，再拼接回 64 维。

在一个头里，元素 $i$ 生成一个查询 $q_i$，每个元素 $j$ 生成一个键 $k_j$ 和一个值 $v_j$，三者都是 $\mathrm{LN}(x)$ 的学到的线性映射。于是

$$
a_{ij} = \frac{\exp\!\big(q_i^\top k_j / 4\big)}{\sum_{j'} \exp\!\big(q_i^\top k_{j'} / 4\big)}, \qquad y_i = \sum_j a_{ij}\, v_j .
$$

所以 $a_{ij}$ 是元素 $i$ 对元素 $j$ 的关注程度，其中的 4 是 $\sqrt{16}$，即通常的缩放。

一个批次用空槽位把大小不同的对局补齐到同一长度。每个空槽位的分数在 softmax 之前减去 $10^9$，所以没有元素会关注它。

两个块之后再做一次层归一化，然后像纯 V 汇总牌组那样汇总这个集合：平均值和乘以 $1/16$ 的总和，共 128 个数。

在纯 V 里，牌只在主干里才遇到遗物，那时牌组已经汇总成分不清哪张牌是哪张的数字（[§3](#sec-3)）。这里，在任何汇总之前，小刀的向量就能因为集合里有手里剑和苦无而改变。这是把 Set Transformer 的思路（Lee 等，2019）用在整套配置上。输出仍然不依赖元素的顺序，因为注意力和汇总对每个元素一视同仁。和纯 V 一样，它只读 id，没有手写的「攻击」或「技能」标记。

### 路线编码器

地图词袋告诉纯 V，三层之后有一个精英、四层之后有一个休息处。它分不出这个休息处是在同一条路径上、精英之后，还是在另一条路径上、玩家得改走那条路才能到。路线编码器读的是路径本身。

**节点**（`encode.route`）。节点 0 是玩家所在的点。接着是仍能到达的点，先按行、再按列排序。每个节点有四个字段：
- 它的类型（怪物、精英、休息处、商店、未知、宝箱、先古之民、Boss）；
- 它在玩家前方几层，最多算 16；
- 它是否有任务标记；
- 它的连线通往的节点的索引。

在低预算整局对局的 1,242 个局面上，一个局面最多有 69 个可达的点（平均 22 个），没有哪个点通往超过 5 个点。Boss 是最后一个点，在本幕地图的第 15 或 16 行。

**初始向量**。每个节点从 $s_i = T[\text{type}_i] + A[\text{ahead}_i] + q_i\, v_{\text{quest}}$ 开始，32 维，其中有任务标记时 $q_i$ 为 1，否则为 0。

**各轮**。然后重复 16 次，每个节点都由它的初始向量和它通往的节点重新算出：

$$
h_i \leftarrow \mathrm{ReLU}\Big( W \big[\, s_i \,;\; \max_{j \in \mathrm{next}(i)} h_j \,;\; \operatorname{mean}_{j \in \mathrm{next}(i)} h_j \,\big] + b \Big),
$$

- $[\,\cdot\,;\cdot\,]$ 把向量首尾相接。
- 最大值逐个数地取。
- 第一轮之前 $h = s$。
- Boss 不通往任何点，所以它的最大值和平均值都是 0。
- 每一轮都用同样的 $W$ 和 $b$。

$k$ 轮之后，一个节点的向量取决于它前方最多 $k$ 步之内的节点。信息就这样从 Boss 往回传，每轮一层。一幕的地图在起点之上有 16 行，所以 16 轮能把 Boss 的信息带到任何一个节点。

这是一个从 Boss 往回、学出来的**动态规划**。经典的动态规划从 Boss 往回，对每个点算出从它出发的最佳路径的价值：$\text{value}(i) = \text{reward}(i) + \max_{j \in \text{next}(i)} \text{value}(j)$。每一轮的形状与它相同：
- 用向量代替单个数值；
- 用学到的 $W$ 代替加法；
- 在最大值之外，再加上下一批点的平均值。一局并不总能走上它的最佳路径，所以其他路径上有什么也要紧。

用图网络的术语来说，它是沿地图连线的**消息传递**（Gilmer 等，2017），只往回传，所有轮共用一个更新。

**输出**。玩家所在节点的向量 $h_0$，以及所有节点的平均，共 64 个数。前者是「沿着路径，我前方有什么」；后者概括本幕余下的部分。

### 主干、大小和开销

主干读 $128 + 64 + 64 + 6 = 262$ 个数：构筑、上下文词袋（现在是 64 维）、路线和六个数字。之后就是纯 V 的主干：256 → 256，ReLU，然后是风险值输出头。在下一个计划的 objective `win` 下，价值是赢的概率 $S_{63}$（[从风险值到价值 §1](/arch/macro-brain/value/#sec-1)）。

| 部分 | 形状 | 权重数 |
|---|---|---|

额外的开销大多在 16 轮和注意力上。在大脑里，`RunNet`（`src/Sts2Ai.Brain/Macro/RunNet.cs`）只在网络文件的计算图声明了 `route` 输入时，才构建并送入路线的张量，所以所有较旧的网络照旧加载。一个完整大小的编码器网络在 C# 里每次调用 0.44 ms，v6-3-2 是 0.093 ms。在克隆上做一个宏观决策要 70–90 ms，所以这点差别无关紧要。

**测试**。[§2](#sec-2) 的 ONNX 检查照旧适用：网络文件给测试对局的值必须和训练器的一致，否则大脑拒绝这个文件。此外，一个未经训练的微型编码器网络（宽度很小，权重放大，`src/Sts2Ai.Tests/Fixtures/pure-v-tiny-encoders.json`）在三个真实的整局观测上运行。路线失去连线或前方层数时，它的值变动达到加载检查容差的 10 倍；每种类型都读作未知时，变动达到 3 倍。所以一个悄悄忽略了地图的路线编码器通不过测试。

有两个细节出自导出，而不是出自设计。层归一化没有自己的缩放和平移，由各自后面的线性层承担。种类向量和任务向量的初始值是随机的，不是零。两者都是必要的，因为 ONNX 导出会合并值相等的权重，那样它们的名字就会从文件里消失。
