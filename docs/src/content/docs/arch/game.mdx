这个项目教一个程序玩**杀戮尖塔 2**（Slay the Spire 2，简称 STS2）。这是一款单人卡组构筑类 Roguelike 游戏，版本 v0.111.0。这一页写给从没玩过它的读者，也写给想要确切数字的读者：一局是什么，玩家要决定什么，什么是随机的，什么是隐藏的。本书其余部分都以这一页为前提。

这里的一切都读自游戏本身的代码（反编译所得）和游戏的文本文件。文件引用是反编译后的游戏里的路径（它不在仓库里），并省去文件夹名里的 `MegaCrit.Sts2.Core.` 前缀：`Map/StandardActMap.cs` 即 `MegaCrit.Sts2.Core.Map/StandardActMap.cs`。引用的游戏文本出自游戏的本地化文件，本页用的是简体中文版的原文。

## 1. 一局

**一局**是攀登尖塔的一次尝试：三**幕**，每幕是一张由房间组成的地图，尽头是一个 **Boss**。玩家在每张地图上一个房间接一个房间地选一条路，战斗，收集卡牌、遗物和药水，最后要么打败最后一个 Boss，要么死去。死亡就结束这一局：输掉的战斗无法挽回。

- **幕**。第 1 幕是密林或暗港，第 2 幕总是巢穴，第 3 幕总是荣耀（`Models.Acts/Overgrowth.cs:49`、`Underdocks.cs:44`、`Hive.cs:49`、`Glory.cs:45`）。默认的列表是密林、巢穴、荣耀；暗港解锁之后，第 1 幕由种子在两者之间选定（`Models/ActModel.cs:538-565`）。
- **层**。一层就是一个房间。一幕有它的房间，再加两层：先古之民的一层和 Boss 的一层（`Models/ActModel.cs:271-279`）：密林和暗港有 15 个房间，巢穴 14 个，荣耀 13 个，所以各幕分别是 17、16 和 15 层，总共 **48 层**（`Models.Acts/Overgrowth.cs:47`、`Hive.cs:47`、`Glory.cs:43`）。
- **每一幕都以一位先古之民开始**。先古之民会治疗玩家，并提供三份礼物供选择：第 1 幕是涅奥；第 2 幕是欧洛巴斯、佩尔或特兹卡塔拉；第 3 幕是诺奴佩普、坦克斯或瓦库（`Models.Acts/Overgrowth.cs:26`、`Hive.cs:24-29`、`Glory.cs:23-28`）。进入时回复全部已损失的生命（`Models/AncientEventModel.cs:170-191`），所以每一幕都以满血开始。
- **每一幕都以一个 Boss 结束**，每幕三选一：密林是墨影幻灵、仪式兽或同族小队；巢穴是无厌沙虫、知识恶魔或帝皇蟹；荣耀是女王、实验体或永世沙漏（`Models.Acts/Overgrowth.cs:19-24`、`Hive.cs:17-22`、`Glory.cs:16-21`）。这一幕的 Boss 从一开始就知道：地图上画着它。
- **胜利**。打败最后一个 Boss 之后，玩家会见到建筑师，这段对话以胜利结束这一局（`Runs/RunManager.cs:1308-1342`）。最后一个 Boss 不给奖励（`Rewards/RewardsSet.cs:88-91`）。所以赢下的一局结束在第 48 层。
- **失败**。玩家的生物死亡时，这一局就结束了（`Runs/RunState.cs:190-198`）；放弃一局算作死亡。

## 2. 地图

每一幕的地图在这一幕开始时生成，玩家一下子就能看到整张地图：每个点的类型，以及顶端的 Boss（`Runs/RunManager.cs:799`、`1378-1390`）。

- **网格**宽 7 列，这一幕的房间排在第 1 行到第 N 行，N 是这一幕的房间数（`Map/StandardActMap.cs:19`、`89-91`）。先古之民单独位于第 0 行第 3 列；Boss 位于最后一个房间行的下一行，第 3 列（`:94-95`、`:301-302`）。
- **路径**。七条路线从第 1 行的随机列出发（第二条的起点必须与第一条不同），每次向上爬一行，每一步走到左边一列、同一列或右边一列，从不与另一条路径交叉（`:145-218`）。最后一行的每个点都通向 Boss，先古之民通向第 1 行的每个点（`:222-233`）。
- **固定行**：第 1 行全是怪物；最后一个房间行（紧挨在 Boss 之前）全是休息处；中间的一行（第 1 幕第 9 行，第 2 幕第 8 行，第 3 幕第 7 行）全是宝箱（`:248-275`）。
- **其余的点**从一个袋子里发出：5 个精英、3 个商店、10 到 14 个未知（`?`，第 2、3 幕少一个）和 5 到 7 个休息处，剩下的都成为怪物（`Map/MapPointTypeCounts.cs:14-32`；`Models.Acts/Overgrowth.cs:136`、`Hive.cs:119-120`、`Glory.cs:108-109`）。规则是：第 1–5 行没有精英和休息处；最后三个房间行里除了固定行之外没有休息处；精英、休息处、宝箱或商店的紧前和紧后都不会是同一类型；有共同父点的两个点，在休息处、怪物、未知、精英和商店这几种类型里不会相同（`Map/StandardActMap.cs:405-485`）。之后再剪掉重复的路径段（`Map/MapPathPruning.cs:11-43`）。
- **它的随机性**来自每幕一条独立的随机数流 `act_N_map`（`Map/StandardActMap.cs:113`）。

例子那一局的三张地图分别有 62、60 和 58 个点；巢穴那一幕除了先古之民和 Boss，有 26 个怪物、10 个未知、9 个休息处、5 个精英、5 个宝箱和 3 个商店。[输出 §3](/arch/output/#sec-3) 画出了这张地图，以及大脑在第 19 层规划的路线。

## 3. 房间

地图点的类型就是房间的类型，只有两个例外：未知（`?`）在玩家进入时才掷出它是什么；先古之民的点是一个事件房间（`Runs/RunManager.cs:958`、`976-995`）。

**战斗**（怪物、精英、Boss）。每一幕的遭遇在开局时就掷好，排成几张列表，这一幕之后按顺序取用：先是几场弱的战斗（第 1 幕 3 场，第 2、3 幕各 2 场），然后是一般的战斗；精英从它们自己的列表里取，另有一个 Boss；同一个遭遇标签不会连续出现两次（`Models/ActModel.cs:331-386`、`419-430`；`Rooms/RoomSet.cs:70-86`）。赢下的战斗会给出一个奖励画面（`Rewards/RewardsSet.cs:206-246`）：

| 房间 | 金币 | 药水 | 卡牌 | 遗物 |
|---|---|---|---|---|
| 怪物 | 10–20 | 掷一次 | 3 选 1，或跳过 | |
| 精英 | 35–45 | 掷一次，概率高 12.5 个百分点 | 3 选 1，或跳过 | 一件 |
| Boss | 100 | 掷一次 | 3 选 1，全是稀有 | |

- **药水掷骰**从 40% 开始；每掷一次，如果出了药水，概率降低 10 个百分点，没出则提高 10 个百分点（`Odds/PotionRewardOdds.cs:19-71`）。
- **卡牌稀有度**：一般战斗里，稀有是 3% 加一个偏移量，罕见 37%，其余为普通；精英战里，稀有是 10% 加偏移量，罕见 40%。偏移量从 −5 个百分点开始，每展示一张非稀有牌增加 1 个百分点，最多到 +40，出现一张稀有牌后回到 −5（`Odds/CardRarityOdds.cs:13-81`、`140-167`）。在第 2 幕和第 3 幕，每张非稀有的奖励牌分别以 25% 和 50% 的概率是升级过的（`Factories/CardFactory.cs:97-102`、`288-305`）。
- **遗物**来自按稀有度分开的几个遗物堆，开局时洗好，一局里从不重复；一件遗物的稀有度是普通、罕见或稀有，概率分别为 50%、33% 和 17%（`Factories/RelicFactory.cs:36-50`、`85-94`）。

**休息处**。每次来访只能选一个选项：**休息**，回复最大生命值的 30%；或**锻造**，升级一张牌（`Entities.RestSite/HealRestSiteOption.cs:90-93`、`SmithRestSiteOption.cs:29`、`58-69`）。有些遗物和卡牌会加入别的选项：锻炼、挖掘、烹饪、添火、克隆、孵化。

**商店**（商人）。货品在玩家进入时生成（`Rooms/MerchantRoom.cs:61`）：5 张本角色的牌（2 张攻击、2 张技能、1 张能力，五张中有一张半价）、2 张无色牌、3 件遗物、3 瓶药水，以及一次卡牌移除（`Entities.Merchant/MerchantInventory.cs:15-148`）。

| 商品 | 基础价格 | 浮动 |
|---|---|---|
| 卡牌 | 普通 50，罕见 75，稀有 150；无色 × 1.15 | × 0.95–1.05 |
| 遗物 | 普通 175，罕见 225，稀有 275，商店 200 | × 0.85–1.15 |
| 药水 | 普通 50，罕见 75，稀有 100 | × 0.95–1.05 |
| 卡牌移除 | 75，本局每已买过一次移除再加 25 | |

（`Entities.Merchant/MerchantCardEntry.cs:38-50`、`MerchantRelicEntry.cs:42-45`、`MerchantPotionEntry.cs:50-71`、`MerchantCardRemovalEntry.cs:20-33`；`Models/RelicModel.cs:304-315`。）

**宝箱**。42–52 金币和一件遗物（`Multiplayer.Game/OneOffSynchronizer.cs:127-140`、`TreasureRoomRelicSynchronizer.cs:89-108`）。

**未知（`?`）**。进入时掷出：怪物战（10%）、宝箱（2%）、商店（3%），否则是事件；从不会是精英。每次掷完，掷出的那种类型的概率回到它的基础值，其他每种类型的概率再加上一次各自的基础值，所以 `?` 越久没出战斗，下一个就越可能出战斗；事件不改变任何概率。每一幕开始时概率从头算起（`Odds/UnknownMapPointOdds.cs:21-35`、`159-189`）。

**事件**。每一幕有它自己的事件，外加 18 个共享事件，开局时按幕洗好；一局里同一个事件不会出现两次（`Models/ModelDb.cs:157-177`；`Models/ActModel.cs:334-347`；`Rooms/RoomSet.cs:110-125`）。每个事件从它自己的一条随机数流里抽取（`Models/EventModel.cs:234`）。

**水晶球**是第 2、3 幕的共享事件，只对至少有 100 金币的玩家出现。它是一个小游戏：付金币换 3 次占卜，或拿一张诅咒换 6 次，然后在一张被迷雾覆盖的 11 × 11 网格上揭开格子，下面藏着一件遗物、药水、卡牌奖励、金币和一张诅咒；一件物品的所有格子都揭开时就得到它（`Models.Events/CrystalSphere.cs:24-81`；`Events.Custom.CrystalSphereEvent/CrystalSphereMinigame.cs`）。在这个项目里它是一个单独的决策画面。

## 4. 战斗

一场战斗由玩家回合和敌人回合交替组成。

- **玩家回合**开始时，能量重置为上限 3，并抽 5 张牌；没用完的能量会失去（`Combat/CombatManager.cs:880-926`；`Models/CharacterModel.cs:97`）。在能量用完之前，玩家可以按任意顺序打出卡牌、使用药水，然后结束回合。
- **意图**。每个敌人的下一个招式在玩家回合开始时掷出，并显示在它头顶：攻击多少、打几次，格挡，增益，减益，等等（`Combat/CombatManager.cs:739-745`；`MonsterMoves.Intents/IntentType.cs:3-20`）。所以玩家总能看到每个敌人马上要做什么，但看不到它之后会做什么。招式来自每个怪物的状态机，其中有带权重的随机分支（`MonsterMoves.MonsterMoveStateMachine/RandomBranchState.cs:23-115`）。
- **牌堆**。每场战斗开始时，牌组被复制进抽牌堆并洗牌。卡牌从抽牌堆进入手牌，然后进入弃牌堆，或者进入消耗牌堆（「在战斗结束前移除」）。抽牌时如果抽牌堆空了，弃牌堆会被洗进抽牌堆（`Entities.Cards/PileType.cs:7-37`；`Commands/CardPileCmd.cs:1073-1086`、`1186-1195`）。手牌最多 10 张（`Entities.Cards/CardPile.cs:21`）。回合结束时手牌被弃掉，保留的牌除外。
- **生命与格挡**。格挡吸收伤害，一直持续到它的拥有者的下一个回合。生命在整局里从一场战斗带到下一场：回复只来自休息处、先古之民、遗物和少数卡牌（`Entities.Creatures/Creature.cs:686-733`）。
- **能力**是带层数的持续效果：力量增加攻击伤害，敏捷增加格挡，易伤使受到的攻击伤害多 50%，虚弱使造成的伤害少 25%，脆弱使获得的格挡少 25%，中毒在拥有者回合开始时让它失去等于层数的生命，然后减少一层（`Models.Powers/StrengthPower.cs`、`VulnerablePower.cs:19-28`、`WeakPower.cs:19-25`、`PoisonPower.cs:55-79`）。游戏里共有 268 种能力。

**卡牌**分为攻击、技能、能力（在本场战斗中持续的效果）、状态和诅咒（占地方的废牌），以及任务。它们的关键词改变它们在牌堆之间移动的方式（`Entities.Cards/CardKeyword.cs:18-27`）：

| 关键词 | 游戏文本 |
|---|---|
| 消耗（Exhaust） | 「在战斗结束前移除。」 |
| 虚无（Ethereal） | 「如果这张牌在这个回合结束时留在你的手牌中，则将其消耗。」 |
| 固有（Innate） | 「每场战斗开始时这张牌会出现在你的手牌。」 |
| 保留（Retain） | 回合结束时不被弃掉 |
| Sly（奇巧） | 「如果这张牌在你的回合结束前从你的手牌中被丢弃，则免费将其打出。」 |
| 不能被打出（Unplayable） | 无法打出 |
| 永恒（Eternal） | 「无法从你的牌组中移除或变化。」 |

一张牌可以**升级**一次（`Models/CardModel.cs:782-795`），带一个**附魔**（锋利增加伤害，灵巧增加格挡，等等），并在战斗中受到敌人施加的**苦痛**（魂缚、缠身、流电、邪咒）（`Models/CardModel.cs:632-634`）。有些牌的费用是 X：剩下的全部能量。

**药水**：3 个栏位。大多数只能在战斗中使用；少数任何时候都能用，瓶中精灵则会自己生效（`Entities.Players/Player.cs:307`；`Entities.Potions/PotionUsage.cs`）。

## 5. 角色

可玩的角色有五个，各有自己的卡池和初始遗物；所有角色开局都有 99 金币、3 个药水栏位和 3 点能量（`Models/ModelDb.cs:145-152`）：

| 角色 | 生命 | 初始牌组 | 初始遗物 | 玩法 |
|---|---|---|---|---|
| 铁甲战士 | 80 | 5 张打击、4 张防御、痛击 | 燃烧之血：战斗结束时回复 6 点生命 | 力量、易伤、自我回复 |
| 静默猎手 | 70 | 5 张打击、5 张防御、中和、生存者 | 蛇之戒指：每场战斗开始时额外抽 2 张牌 | 中毒、小刀、弃牌和 Sly |
| 储君 | 75 | 4 张打击、4 张防御、陨星、崇拜 | 天赋君权：每场战斗开始时获得 3 点辉星 | 辉星，第二种资源；铸造和君王之剑 |
| 亡灵契约师 | 66 | 4 张打击、4 张防御、护卫、出击 | 缚魂命匣：在你的回合开始时召唤 1 | 奥斯提，一个召唤出来的盟友 |
| 故障机器人 | 75 | 4 张打击、4 张防御、电击、双重释放 | 破损核心：每场战斗开始时生成 1 个闪电充能球 | 充能球：闪电、冰霜、黑暗、等离子、玻璃 |

**静默猎手**是本书例子那一局的角色。她的卡池有 91 张牌（27 张攻击、46 张技能、18 张能力）。她的初始牌：打击（1 能量，造成 6 点伤害）、防御（1 能量，获得 5 点格挡）、中和（0 能量，造成 3 点伤害并给予 1 层虚弱）、生存者（1 能量，获得 8 点格挡，然后丢弃一张牌）（`Models.Cards/StrikeSilent.cs:19-39`、`DefendSilent.cs:17-31`、`Neutralize.cs:23-52`、`Survivor.cs:17-36`）。她的主题是中毒、小刀（造成 4 点伤害并消耗的 0 费攻击牌）和弃牌：弃掉的 Sly 牌会被免费打出。

## 6. 进阶

进阶等级 1–10 让一局变得更难，每一级都包含它下面的各级（`Entities.Ascension/AscensionManager.cs:15`、`45-48`）。冠军的报告在 0 级；自我对弈覆盖 0 到 10 级（[宏观大脑：自我对弈](/arch/macro-brain/selfplay/)），`run --asc N` 可以打任意一级。

| 等级 | 名称 | 效果 |
|---|---|---|
| 1 | 精英蜂拥（Swarming Elites） | 每张地图 8 个精英，而不是 5 个 |
| 2 | 旅途劳顿（Weary Traveler） | 先古之民只回复已损失生命的 80% |
| 3 | 贫穷（Poverty） | 从敌人和宝箱得到的金币少 25% |
| 4 | 收紧腰带（Tight Belt） | 药水栏位少一个 |
| 5 | 进阶之灾（Ascender's Bane） | 每局开始时都带着一张无法移除的诅咒 |
| 6 | 通货膨胀（Inflation） | 卡牌移除花费 100，每移除一次再加 50 |
| 7 | 稀缺（Scarcity） | 稀有牌和升级过的牌出现得更少 |
| 8 | 强韧敌人（Tough Enemies） | 敌人的生命更多 |
| 9 | 致命敌人（Deadly Enemies） | 敌人打得更狠 |
| 10 | 双重 Boss（Double Boss） | 第 3 幕结尾有两个 Boss |

（游戏的 `ascension.json`；`Map/MapPointTypeCounts.cs:14`；`Models/AncientEventModel.cs:180-183`；`Runs/RunManager.cs:761-765`。）

## 7. 随机性，以及玩家能看到什么

**种子**。一局的种子是由数字和大写字母（不含 O 和 I）组成的 12 位字符串，例如 `0SSL7NS01MU6`（`Helpers/SeedHelper.cs:8-33`）。它被哈希成一个数，这一局的每条随机数流都由它和流的名字得到种子（`Runs/RunRngSet.cs:104-143`）。每条流都是一个计数器：一条流的第 n 次抽取由种子决定。所以一局是它的种子和玩家选择的确定函数，正因如此，模拟器才能精确地重播它（[模拟器：整局 §6](/arch/simulator/runs/#sec-6)）。

**各条随机数流**（`Entities.Rngs/RunRngType.cs:3-17`）：

| 流 | 决定什么 |
|---|---|
| UpFront | 开局时掷定的一切：每一幕的战斗、精英、事件、Boss 和先古之民，以及各个遗物堆 |
| Shuffle | 每场战斗开始和每次重新洗牌时抽牌堆的顺序 |
| UnknownMapPoint | `?` 变成什么 |
| MonsterAi | 怪物的招式，凡是涉及随机的地方 |
| CombatCardGeneration, CombatPotionGeneration, CombatCardSelection, CombatEnergyCosts, CombatTargets, CombatOrbs | 战斗中生成的卡牌和药水、随机选取、费用、目标和充能球 |
| Niche | 一次性的掷骰，例如怪物的初始生命 |
| TreasureRoomRelics | 宝箱遗物的稀有度 |

除此之外，每个玩家还有用于奖励、商店和变化的流（`Entities.Rngs/PlayerRngType.cs:3-8`），每张地图和每个事件也各有自己的流（`Map/StandardActMap.cs:113`；`Models/EventModel.cs:234`），而卡牌稀有度、药水和 `?` 点的概率会从一次掷骰延续到下一次。

**玩家能看到什么，什么是隐藏的**：

| 可见 | 隐藏 |
|---|---|
| 这一幕的整张地图、每个点的类型、它的 Boss | `?` 会变成什么，直到进入 |
| 每个敌人下一个招式的意图 | 它之后的招式 |
| 每个生物的生命、格挡和能力 | |
| 抽牌堆、弃牌堆和消耗牌堆里有哪些牌 | 抽牌堆的顺序（游戏里查看牌堆时是排过序的） |
| | 接下来是哪场战斗、哪个精英或哪个事件 |
| | 奖励，直到奖励画面出现；商店的货品，直到进入 |
| | 水晶球迷雾下的物品 |

（`Nodes.Screens/NCardPileScreen.cs:222-228`；`Runs/RunManager.cs:907-916`；`Rooms/RoomSet.cs:70-86`。）因为所有隐藏的东西都已经由种子定好，一个能存档和读档的程序就能看到它们。其中哪些 AI 可以用，是[环境](/arch/environments/)一章的主题：NoSL 只看玩家看得到的东西；SL 可以重玩它所在的房间。

## 8. 为什么这对 AI 很难

- **很长的跨度**。一局平均约有 830 个决策（冠军的静默猎手 100 局 SL 对局共 83,026 个决策），例子那一局有 997 个。第 2 层拿的一张牌到第 48 层仍然要紧，一场战斗损失的生命会带进之后的每一场战斗。
- **隐藏信息和随机性**：抽牌顺序、`?` 里是什么、接下来会遇到什么、敌人之后的招式（[§7](#sec-7)）。
- **庞大且不断变化的动作集合**：一个回合可以按任意顺序打出手牌（最多 10 张）和药水，每张牌、每瓶药水都可以选它的任一目标；一个商店提供约 13 件商品和一次移除；选牌提示会在一张牌打出的过程中出现。
- **一次死亡就结束这一局**。生命是一种要在 22 场左右的战斗里分着花的资源，每个休息处都要在回复和升级之间取舍。
