[回合搜索](/arch/sl-planner/turn-search/)从一个状态出发，完整地搜索一个回合。一场战斗有很多个回合，如果把每条路线的每个回合都完整搜索，搜索量会无止境地成倍增长。规划器在每个回合只保留最有希望的状态，并剪掉那些不可能影响结果的状态。[§1](#sec-1)–[§6](#sec-6) 是运行中的代码：跨回合的束（`SlPlanner.Search`）、给它剪枝的上界，以及选出、证明和重新规划一条路线的规则。[§7](#sec-7) 是取代下潜和束的规划中的搜索。

## 1. 跨回合的束

**束搜索**（beam search）是一种广度优先搜索：每一深度只保留最好的 $B$ 个状态，也只展开它们。这里的一个深度就是一个回合。记 $S_0 = \{s_0\}$ 为决策的状态，$v^{\star}$ 为到目前为止已经结束战斗的最好路线的估值：

$$
S_{t+1} = \operatorname{top}_B \Big\{\, e \in \bigcup_{s \in S_t} \operatorname{ends}(s) \ :\ e \text{ 仍在进行},\ \ \operatorname{bound}(e) > v^{\star} \Big\}
$$

其中 $\operatorname{ends}(s)$ 是从 $s$ 出发的回合搜索返回的结束状态，$\operatorname{top}_B$ 按叶子估值取最好的 $B$ 个（按键去重），而每个结束了战斗的结束状态不进束，改为更新 $v^{\star}$。排序是稳定的，所以打平的状态保持它们被搜索的先后顺序，束也就不取决于哪个 worker 先回答。束一直进行到没有状态剩下，最多 40 个回合。

$B$ 就是 `Budget.Beam`（`--beam`）：除 max 为 16 外，每个力度级别都是 8（[预算 §1](/arch/sl-planner/budget/#sec-1)）。每个保留状态的这一回合，用预算规定的每个状态每回合的节点数来搜索；每个房间的 $B$ 和节点数都一样。

一个回合结束时的状态通常比束保留的多得多：8 个保留状态的这一回合产生的所有不同结束状态里，只有最好的 8 个能留下。这是规划器最主要的近似，也是它的大多数计划没有得到证明的原因（[§5](#sec-5)）。

## 2. 上界

一个战斗仍在进行的状态有一个**上界**：以它现有的生命值和药水赢下这场战斗时，叶子给出的估值。按 `LeafValue` 的价格，生命值占比为 $s$、药水为 $q$ 瓶时，这个值是 $0.2 + 0.6\,s + 0.02\,q$（[战斗大脑：叶子 §2](/arch/combat-brain/leaf/#sec-2)）。如果这场战斗剩下的部分只会掉血、用掉药水，那么经过这个状态的任何路线，结束时都不可能高于它的上界。所以一旦有一条路线以估值 $v^{\star}$ 结束了战斗，上界不超过 $v^{\star}$ 的每个状态都会被丢掉，不只是从束里丢掉，在回合搜索内部就已经丢掉：它最多只能打平。

**决策的上界**是决策自身状态的上界：一场不掉血、不用药水的胜利。达到它的路线不可能被超越。

上界假设这场战斗既不回血，也不给药水。少数牌、药水和遗物会打破这个假设（一次回血、战斗中生成的一瓶药水），这时剪枝可能丢掉一条本来更好的路线。除此之外，让上界成立的是叶子自身的形状：胜利按它结束时的生命值和药水定价，网络给进行中的状态加上的只有还要发生的事，所以状态只有靠预测的回血才会高出它的上界（[战斗大脑：叶子 §5](/arch/combat-brain/leaf/#sec-5)）。

## 3. 贪心下潜

剪枝需要一个下限，而完整的束在它的第一个回合还没有下限。所以在完整的束之前，规划器先跑一个宽度为 1 的束：每个回合只保留叶子估值最好的那一个状态。这次**贪心下潜**（greedy dive）用一条路线打到战斗结束，通常是胜利（在一次 300 局的评估里，赢下的普通战斗中有 99.8% 由第一个计划赢下，[预算 §3](/arch/sl-planner/budget/#sec-3)）。它的估值就是下限，从完整束的第一个回合起就用来剪枝。

- 下潜达到决策的上界时，没有什么能超过它，完整的束就跳过。
- 下潜要求它的每个回合返回所有结束状态，不设下限，并把它们留着。完整的束在开头会经过同样的状态（第一个回合总是如此），于是直接从下潜那里取这些回合的结束状态，而不是再搜一遍（[回合搜索 §4](/arch/sl-planner/turn-search/#sec-4)）。在一组固定的战斗上，没有得到证明的计划里，这省下了 14–16% 的节点，每个计划都不变。

## 4. 简易束

下潜赢了但没有达到上界时，这场战斗已经能赢；完整的束只能再找一场留下更多生命值或药水的胜利。所以它每回合保留 $E$ 个状态而不是 $B$ 个（`Budget.EasyBeam`，`--easy-beam`；medium 力度为 4，low 为 2）。下潜输了时，完整的束保留 $B$ 个：这时它要找的是能不能赢。

medium 力度比 high 省下的时间，大部分来自简易束（high 总是保留 $B$ 个）：medium 赢一场普通战斗用 9.5 s，high 用 13.8 s，两者到达的层数相同（[预算 §1](/arch/sl-planner/budget/#sec-1)）。在每场普通战斗里都用更窄的束，省下的时间一样多，却在低生命值或最大生命值只有 1 的普通战斗里错过了不掉血的路线；简易束则在下潜输掉时总是保留完整的宽度。

## 5. 选出路线，并证明它

选中的是结束战斗的最好路线，除非束在回合上限处停在一个叶子估值更高的状态上。所有失败都值 0，所以在会输的路线里，选的是死前那个回合开始时叶子估值最高的一条：以最好的状态坚持下来的路线，如果计划错了，战斗最有可能在那里出现转机。

在上界成立的范围内，当不可能存在更好的计划时，这个计划就是**已证明**的：

- 它的路线达到决策的上界；或者
- 完整的束什么都没有遗漏：没有哪个回合的搜索被截断（节点用完，或结束状态比它保留的多），没有状态被挤出束，每条路线都结束了战斗或被剪掉。

**给宿主看什么**。除了选中的那个，规划器还为它保留的路线开头的每个首个动作，保留这些路线中最好的一条。这些就是它的候选，选中的在前：每个带着这条路线的值、赢下这场战斗的概率和赢下时持有的生命值；路线结束战斗的地方是 1 或 0 和精确的生命值，其他地方是叶子的期望（[回合搜索 §4](/arch/sl-planner/turn-search/#sec-4)）。Mod 把它们显示为这场战斗的胜率和剩下的生命值（[输出 §2](/arch/output/#sec-2)）。常常只有一个：在本书的示例种子上，由 ca1fad5 时的 SL 冠军来打，24 场战斗的计划里有 23 个只有一个候选，规划器保留的每条路线都以它选中的动作开头。

证明很少见。在[预算 §5](/arch/sl-planner/budget/#sec-5) 的战斗上（2026-10-28），第 1 幕普通战斗有 18% 的搜索得到证明，精英战 3%，第 2 幕的战斗 1%：一个回合产生的状态比束保留的多得多。在下面的战斗里，21 个计划没有一个得到证明。

## 6. 失败计划

一个会输且没有证明的计划可能是错的：束也许丢掉了通向胜利的状态。规划器把这样的计划当作一个猜测：

- **重新规划**。没有证明的失败计划只打它的前 `--replan` 个回合（默认 1），然后下一个回合重新规划。从那里出发，战斗剩下的部分更短，同样的束就能看得更深。
- **连续最多 L 个**。同一场战斗里连续第 $L$ 个没有证明的失败计划一直打到结束（`--loss-plans`，low 和 medium 为 3）。每个回合都重新规划一场输掉的战斗，花掉了一局的大部分时间：在没有上限的 high 力度下，一场输掉的 Boss 战平均规划 6.2 次，用时 241 s，而它的 200 局里只有 12 场战斗是在失败计划之后赢下的，其中 7 场在第三个计划或更早赢下。
- **已证明的失败**一直打到结束：没有哪条路线更好。

计数由路由保存（`SlRoute`）：一场战斗出现第一个不属于「未证明的失败」的计划时，它连续失败计划的计数就结束。

## 7. 迭代加宽 <Badge text="规划中" variant="caution" />

设计用一个循环取代下潜、束和它们周围的规则。这里的一切都没有实现，也没有测过。

```text
best = none
for width in 1, 2, 4, 8, ...:              # each pass runs to the fight's end
    states = [decision]
    while states:
        ends = TurnEnds of each state       # shared table: a state is searched once
        best = the better of best and the lines that ended the fight
        drop every end with bound(end) <= best.value
        states = the top `width` ends by the leaf
    stop if proved, or best wins and width >= 4, or the fight's nodes are spent
play best
```

宽度 1 就是现在的下潜；后面的一轮是这个宽度的束，由之前各轮找到的结果剪枝。下图在 [§4](#sec-4) 那场虚构的战斗上运行这个循环。在更早一轮搜索过的回合不再花费节点，所以更宽的一轮只为新的部分付出。

### 7.1 规则

- **剪枝**。结束状态的上界不超过最好路线时被丢掉（[§2](#sec-2)）。上界的假设不变：会回血或给药水的战斗可能打破它。
- **按叶子取宽度内最好的**。网络给上界留下的状态排序（[战斗大脑：叶子](/arch/combat-brain/leaf/)）。
- **停止**：路线已证明，或者在至少为 4 的宽度上赢了，或者这场战斗的节点用完。被预算截断的一轮，仍用它打完的任何路线改进 `best`。
- **失败计划**打一个回合后重新规划，直到这场战斗的节点用完；然后最后一个计划打到结束。计划数没有计数。
- **证明**的含义和 [§5](#sec-5) 相同：路线达到决策的上界，或者某一轮什么都没有遗漏。

### 7.2 为什么是加宽，而不是深度

任何宽度的一轮都以一条完整、真实的路线结束，所以搜索在任何预算下都能停下，并有东西可打。另一种做法，深度优先的分支定界，可能很长时间都没有比第一条更好的完整路线，而这里的节点很贵：每秒约 460 个（[§6](#sec-6) 的多尼斯异鸟战 24.7 s 内 11,345 个节点），恢复约占 worker 忙碌时间的 88%（[预算 §3](/arch/sl-planner/budget/#sec-3)）。Alpha-beta 也帮不上忙，因为它的收益来自对手的应对，而一场战斗没有这种应对：敌人的招式在这一个世界里是固定的。深度优先搜索以后可以再比较。

### 7.3 它取代什么

| 现在 | 设计中 |
|---|---|
| 贪心下潜（[§3](#sec-3)） | 宽度为 1 的一轮 |
| 束 $B$（[§1](#sec-1)） | 宽度一直增长到停止；难的战斗不会早停，所以花得更多 |
| 简易束 $E$（[§4](#sec-4)） | 在宽度至少为 4 时赢了就停止 |
| `--replan`、`--loss-plans`（[§6](#sec-6)） | 失败计划打一个回合，直到这场战斗的节点用完 |
| 一个回合内的置换（[回合搜索 §2](/arch/sl-planner/turn-search/#sec-2)）、留给束的下潜回合 | 一张跨回合、跨轮的表 |
