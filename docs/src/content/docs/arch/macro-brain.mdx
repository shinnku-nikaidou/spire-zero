**宏观大脑**负责战斗之外的所有决策：下一个去哪个地图点、领取哪些奖励、拿哪张牌、买什么、在事件、休息处或宝箱里选哪个选项。它和[战斗大脑](/arch/combat-brain/)一起运行在决策进程里。Harness 把所有非战斗的决策界面都交给它（[Harness §4](/arch/harness/#sec-4)），并从 worker 池给它提供世界，所以它可以先在真实的游戏代码里把每个选项试一遍，再做选择。所有选项都用同一个尺度打分：估计的整局胜率。

<Aside title="状态">

L0 v0 已经实现：Brain 里的 `MacroBrain`，用 `run --macro l0` 来跑（[模拟器 §5](/arch/simulator/#sec-5)）。它回答所有宏观决策界面和战斗外的选牌提示，用 V v0 给选项估值（[学习 §1](/arch/learning/#sec-1)）。对局世界还不存在（[模拟器 §6](/arch/simulator/#sec-6)），所以它根据界面上显示的内容预测每个后状态，而不是在世界里把选项执行一遍（[§2](#sec-2) 的 L0 v0）。规划中：从对局世界得到后状态、多步界面的搜索、L1，以及 [§4](#sec-4) 的 `IMacroBrain` 接口。

</Aside>

## 1. 决策界面与特点

宏观大脑处理的决策界面（surface）如下。「选择后的随机性」指选定之后才揭示的随机结果；「影响范围」指这个选择的后果能延续多远（「整局」指本局剩下的全部）。

| 决策界面 | 选项数 | 选择后的随机性 | 影响范围 |
|---|---|---|---|
| 地图（下一个点） | 1–4 | `?` 掷骰、遭遇、奖励 | 本幕剩余部分 |
| 奖励（领取顺序 / 跳过） | ≤6 | 无（金币、药水、遗物都已显示） | 整局 |
| 卡牌奖励 | 3–4 + 跳过/重掷 | 重掷结果 | 整局 |
| 牌组提示：升级 / 删除 / 附魔 | 牌组大小 | 无 | 整局 |
| 变化（transform） | 牌组大小 | 变出的牌 | 整局 |
| 选一张牌 / 卡包（bundle） | ≤3 | 无 | 整局 |
| 事件 / Ancient 选项 | 1–4 | 事件结果、下一页 | 整局 |
| 商店 | 货品 + 删牌服务 + 离开 | 无（货品可见） | 整局 |
| 休息处 | 休息/锻造（smith）/举重（lift）/挖掘（dig）/… | 挖掘等 | 整局 |
| 宝箱 | 选遗物/跳过 | 无 | 整局 |
| 药水栏满 | 丢弃/使用/跳过 | 无 | 短 |

这些界面的共同点：选项少、影响远、执行成本低、难以估值。一个战斗回合可能有上千种动作序列；这里只有几个选项，每个都能在模拟世界里以几乎为零的成本试一遍。难的是，一个选择的效果要过很多层才显现出来。选项的价值永远是整局胜率 P(win run)（定义见[学习](/arch/learning/)页），绝不是用生命值或分数拼出来的塑形分数。

## 2. 方法

分两级。L0 每次决策都运行；L1 是给难分高下的选择加的复核。

### L0：后状态 + V

L0 是默认方法，每次决策都运行。**后状态**（afterstate）指一个选项刚执行完、还没有发生任何新事情时的局面。给后状态打分，意味着只要一个读取单个观测的价值函数 V，就能给所有决策界面上的所有选项打分：不需要为每个（状态，选项）组合单独估值，而在世界里执行一个选项的成本又很低。

对每个选项 a，大脑在一个世界里执行它并观测结果。这个观测就是后状态 `s'_a`，它的价值是 `V(s'_a)`。

- **随机的后状态**（变化、事件结果、重掷）：NoSL 取 K 个采样世界上的平均值；SL 通过节点克隆，直接用唯一的真实结果。
- 选价值最高的选项（argmax）。成本：选项数乘以（执行 + 观测 + V），远低于 1 秒。
- **多步界面**（商店：买几样再离开；奖励：领取好几项；事件的多页）：像战斗大脑搜索一个回合内的动作那样，对这个界面的动作序列做深度优先搜索（[战斗大脑 §2](/arch/combat-brain/#sec-2)）。叶子估值是离开界面时的 V。到达相同观测的序列只展开一次（按观测去重）。

### L1：推演复核

L1 处理难分高下的选择，使用评估时的预算。当 L0 排名前两位的价值落在置信区间之内（CI：根据目前的样本，真实值大概率所在的范围），L0 分不出谁更好，这时 L1 启动。**推演**（rollout）就是用快速策略把游戏往后模拟，看一个选项会把局面带到哪里。

对每个候选：

1. 从它的后状态出发，在采样的整局世界里推演（[模拟器 §6](/arch/simulator/#sec-6)）。
2. 用快速策略往后走 H 个节点（默认：走到下一个 Boss）：战斗用推演策略或浅层搜索，宏观决策用 L0。
3. 用**公共随机数**（CRN）给候选配对：每个候选都在同一组世界种子里推演，遇到的运气都一样，所以它们之间的差值比各自独立采样时噪声小得多。
4. 候选的价值是视野边界处 V 的平均值；如果这一局先结束了，就用最终结果。
5. 按配对差值及其 CI 做选择。

两条路线都记入日志供学习使用：这些反事实的配对推演，就是 V 在关键决策上的训练信号。

在 SL 中，越过当前节点的推演仍然使用采样世界（[环境 §4](/arch/environments/#sec-4)）。

### 地图

- 只决定下一个点；每走一步都重新决策。
- L0 的后状态是到达所选地点、房间开始之前的观测：房间类型已知，`?` 仍然未知。所以 V 必须同时评估当前位置和从这里还能走到的地图。早期的 V 做不到这一点，所以基线估值器要加上**路径特征**：对通往 Boss 的最优 k 条路径，统计精英、休息处、商店、`?`、普通怪物各有几个，再估计本幕的生命值预算。
- 难分高下时，同样用上面的 L1 推演。

### L0 v0

在对局世界出现之前，`MacroBrain` 只根据界面上显示的内容预测每个后状态，不跑游戏代码，然后选 V 最高的选项；打平时取第一个合法动作。

- **地图**：把这个点加进路径。V 的地图特征从这里算起：如果之后每一步都随机走，到 Boss 之前预计会遇到几个精英、休息处、商店、宝箱和 `?`（还不是上面说的最优 k 条路径特征）。
- **奖励、选卡奖励、卡包、宝箱、商店购买**：加上金币、药水、遗物或牌，并扣掉价格。
- **会打开一次选择的选项**（选卡奖励、删牌）按其中最好的那一选估值，所以一个打开后会被跳过的选择不会被打开。选卡奖励的牌列在奖励界面上：这些牌在界面出现之前就已经掷好，打开看一眼也没有任何代价（[协议 §3](/arch/protocol/#sec-3)）。
- **休息处**：选项上显示的回复量；锻造升级一张牌。
- **事件**：选项给的遗物，或者按钮警告会致死时记为死亡。其他选项一律当作没有变化。
- **选牌提示**：贪心，每次加一选，只要 V 还在上升（或者提示还要求更多）。删牌和变化把这张牌拿掉，升级把它升一级，选一张牌就把它加进牌组。

它看不到的：事件选项的代价和收益不以数据形式出现在界面上，所以一个代价很高的选项会和离开打平，排在前面时就会被选中（事件 Tablet of Truth 每次破译都要扣最大生命值，一直扣到 1）；遗物除了「多一件遗物」之外的效果；变化会变出什么。在对局世界里执行选项，这三点都能解决。

## 3. NoSL 与 SL

两种环境共用一个宏观大脑和一个价值函数 V，只是结果的来源不同。

| | NoSL | SL |
|---|---|---|
| 节点内的随机结果（事件结果、变化、重掷、已经掷过的 `?`） | K 个样本 | 确切结果（节点克隆） |
| 节点内随战斗打法变化的奖励 | — | 已知（未决问题 1，[环境 §10](/arch/environments/#sec-10)） |
| 节点之外 | 采样世界 | 采样世界 |
| 价值函数 | V | 同一个 V |

Neow 等 Ancient 事件的选项：对随机选项，SL 能看到确切结果，例如「随机稀有卡」选项具体会给哪张牌（[环境 §1](/arch/environments/#sec-1)）。

理论上 SL 也会改变战斗之外的价值：从同一个状态出发，SL 赢得更多，因为它在之后每个节点都打得更好，所以专为 SL 做的价值函数会更愿意冒险（多打精英、多选结果波动大的事件）。这一点被忽略：V 是共用的，在 SL 里会偏保守（[环境 §5](/arch/environments/#sec-5)）。

## 4. 接口

规划中的 C# 接口。所有非战斗决策界面共用一个入口；Harness 按决策界面名称分派（[Harness §4](/arch/harness/#sec-4)）。

```csharp
// Planned. One entry for every non-combat surface; routing by surface name (docs: harness §4).
public interface IMacroBrain
{
    MacroDecisionResult Decide(MacroRequest request, IWorldSource worlds, Budget budget);
}

public sealed record MacroDecisionResult(
    string First,                          // one of legal[]
    IReadOnlyList<string> Plan,            // rest of this screen (shop buys, reward claims)
    IReadOnlyList<Candidate> Candidates,   // value, CI, samples per first action
    IReadOnlyList<Fact> Facts);            // e.g. deck delta, expected HP at boss, P(win) delta
```

`First` 是现在就要执行的动作，`Plan` 是这个界面剩下的步骤，`Candidates` 是每个可能的第一步的价值、CI 和样本数，`Facts` 是用来解释这个选择的事实。

- 战斗外的选牌提示（升级 / 变化 / 删除）和战斗内的一样，都经由 `card_choice` 决策界面到来；`ChoiceContext.Purpose` 说明这个提示的用途。Harness 按「是否在战斗中」分派。
- 推演里使用的宏观策略是 K 更小的 L0，它不会再递归调用 L1。

## 5. 预算

各模式能用多少搜索：

- **自我对弈**：固定的分支数（模拟的打法路线数），保证可复现。L0 总是运行；L1 只在抽样出来的一部分难分高下的选择上运行，以控制成本。这些 L1 结果会成为训练数据。
- **辅助模式**：L0 立即给出答案；玩家查看的同时，L1 继续细化。搜索是*随时可停*（anytime）的：任何时刻停下，都能给出目前最好的答案。
- **自动游玩（R4）**：L0 + L1，有墙钟时间上限。

## 6. 测试

1. 覆盖：模拟对局能到达每一个宏观决策界面，兜底次数为 0。
2. 决策测试集（decision panel）：一组固定的（局面，选项）题目，标准答案来自大规模配对推演。按决策界面统计 L0 与标准答案的一致率，由此看出 V 在哪里最弱。
3. NoSL 反事实：公开记录相同、隐藏状态不同（`RoomSet` 尾部、概率计数、随机数流）→ 决策相同。
4. 在固定预算下结果确定。

## 7. 未决问题

1. L1 的视野 H（到下一个 Boss 还是到下一幕），以及推演用的战斗策略需要多强。测量它们与整局结果的相关性。
2. 把商店当作一次决策还是一串决策（可能的购买组合数量随选项组合式增长）。
3. V 自己能学会多少路径规划，与显式的路径特征相比如何。
