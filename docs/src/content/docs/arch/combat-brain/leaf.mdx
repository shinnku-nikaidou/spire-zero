每个搜索都会在某处停下。PIMC 停在回合结束处；SL 规划器通常能搜到战斗结束，但在知道战斗接下来怎样发展之前，它也得给各个回合结束处的状态排序（[SL 规划器：束搜索 §1](/arch/sl-planner/beam/#sec-1)）。搜索停下的状态是**叶子**（leaf），说明它值多少的函数是**叶子估值**（leaf value）。一句话说：叶子就是网络的结局分布乘以每种结局的价格。本页讲大脑拥有的两种叶子，手写的 `LeafValue`，以及两种环境的冠军都在用的战斗网络 c2（[§2](#sec-2)–[§6](#sec-6)）；c2 的已知问题（[§7](#sec-7)）；以及规划中、尚未实现的网络（[§8](#sec-8)）。

## 1. 什么是叶子

叶子要么是一个回合开始时的状态（此前敌方回合已经真实地打完），要么是战斗的结束，赢或输。两者由同一个函数估值，`ICombatLeaf.Value(status, observation, history)`：输掉的战斗一文不值，赢下的战斗按它留下的东西估值，进行中的战斗按它预计会留下的东西估值。

- **只读观测**。叶子读玩家看到的东西，加上敌人至今出招的公开记录（[提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)）。它从不读抽牌顺序或随机数流，所以在两种环境下都不可能泄漏隐藏状态。
- **一个尺度**。它的单位就是整局的单位：一局胜利的份额，即设计中所说的 P(win run)（[宏观大脑：从风险值到价值 §1](/arch/macro-brain/value/#sec-1)）。下面的权重只让它大致如此；用 V 的价格时，它就是 V 的单位（[§5](#sec-5)）。
- **排序比水平更要紧**。搜索用叶子来比较路线：要紧的是更好的状态得到更高的估值。一个把每个状态都高估 0.1 的叶子，打法和不高估的完全一样。

## 2. 手工叶子：LeafValue

`LeafValue`（v0，`src/Sts2Ai.Brain/Combat/LeafValue.cs`）根据屏幕上的内容推算这场战斗剩下的部分，用到几个手设的数。

- 输掉的战斗为 0。赢下的战斗剩下生命值比例 $s$（生命值除以最大生命值）时，值 $\mathrm{Win}(s) = 0.2 + 0.6\,s$，每瓶还留着的药水再加 0.02。
- 进行中的战斗被推算到它结束。每个活着的敌人 $i$ 有一个**有效生命值** $e_i$（它的生命值加格挡，减去 0.8 乘以它身上的中毒还会造成的伤害，$n$ 层中毒为 $n + (n-1) + \dots + 1$）和一个**伤害速率** $r_i$（它本回合显示的攻击，伤害 × 段数，至少为 3）。玩家每回合造成 $d = 10 + 2 \times \text{力量}$ 的伤害，一个接一个地杀死敌人。
- 杀敌的顺序取掉血最少的那个。敌人 $i$ 一直出手直到死亡，死在第 $t_i = \sum_{j \preceq i} e_j / d$ 回合（对在它之前被杀的敌人和它自己求和），所以受到的伤害是 $\sum_i r_i\, t_i$。来自排程问题的 **Smith 规则**让这样的加权完成时间之和最小：按权重与长度之比从大到小处理各项任务，这里就是 $r_i / e_i$。超出当前格挡的伤害有一半从生命值里扣掉，剩下的生命值按赢下战斗来打分：

$$
\text{估值} = \mathrm{Win}\!\left(\frac{\text{生命值} - 0.5\,\max\!\big(0,\ \sum_i r_i t_i - \text{格挡}\big)}{\text{最大生命值}}\right) + 0.02 \times \text{药水数}
$$

- 推算出死亡（比例低于 0）时，估值向 0 衰减而不会变成负数，$s < 0$ 时 $\mathrm{Win}(s) = 0.2\, e^{3 s}$，在 0 处斜率相同。它始终高于输掉，无论局面多么无望，都还能给路线排序：用一个平的下限时，每条会输的路线看起来都一样，大脑于是会过早结束回合。

所以，打在出手重、死得快的敌人身上的伤害更值钱，溢出伤害毫无价值，而战斗中途的状态永远不会比它在相同生命值下能达到的胜利更好。SL 规划器的上界依靠的正是最后这条性质（[SL 规划器：束搜索 §2](/arch/sl-planner/beam/#sec-2)）。

它的盲区是它不读的一切：敌人身上除中毒以外的能力、玩家身上除力量以外的能力、抽牌堆，以及本回合之后的所有意图。这些数（`LeafWeights`：WinBase 0.2、PerHp 0.6、PerPotion 0.02、Dps 10、Unblocked 0.5、MinIncoming 3、PoisonShare 0.8）是假设，从没调过：`--leaf FILE` 让一局对局、一次测试集或大脑用别的权重（`weights --leaf` 把默认值输出成这样一个文件，`leaf0`），但已经没有工具再调它们，因为策略交给了学到的价值（[学习：循环 §6](/arch/learning/loop/#sec-6)）。

## 3. 战斗网络

战斗网络（`CombatNet`，`--combat-net FILE`）用从打过的战斗中学到的预测代替推算。它读一个回合的开始，预测在打出它训练对局的那个策略下，这场战斗会怎样结束。

**它读什么**。观测显示的关于这场战斗的一切，以词元的形式：

- 四个牌堆（手牌、抽牌堆、弃牌堆、消耗堆）里的每张牌：它的 id、升级次数、附魔和诅咒，以及它在哪个牌堆；
- 玩家：生命值比例、生命值、最大生命值、格挡、能量、最大能量、星、回合数，以及它的能力（id 和层数）；
- 每个活着的敌人：它的 id、生命值比例、生命值、最大生命值、格挡、它已显示了几个回合、它的能力，以及它的**意图槽**：它现在显示的意图，然后是它前 3 个回合的意图，最近的在前；
- 遗物、药水，以及上下文（角色、遭遇、房间、幕）。

关于怪物的出招，没有任何东西是手写的。从怪物的 id、回合数和它最近的意图，网络可以从数据中学到每个怪物的出招顺序，以及怪物处在这个顺序的哪个位置。一个实验性的下回合意图输出头，对 57.7% 的敌人说对了下回合的意图类型，重复当前意图只有 28.9%，而它猜错的大多是游戏随机掷出的招式（[NoSL PIMC §1](/arch/pimc/#sec-1)）。

**它怎样读**。一个集合编码器（*Deep Set*，Zaheer 等，2017：其元素向量之和的函数，对每种顺序都给出相同的输出，能读任意大小的集合）：每张牌是若干学到的向量之和（它的 id 的向量、升级次数乘以它的 id 的升级向量、它的修饰的向量和它所在牌堆的向量），一个小 MLP 逐张处理每张牌，每个牌堆是其中各张牌之和（× 1/8）。敌人的一个槽是其中各个意图之和（意图类型的向量，加上伤害 / 10 和总伤害 / 20 各乘以该类型的一个向量）；一个 MLP 把每个敌人连同它的能力和槽一起处理，各个敌人再求和。遗物、药水和上下文都是各自向量之和。然后两层 256 的网络得出输出头。求和与顺序无关，能读任意多张牌或任意多个敌人，这正是一个牌堆和一场战斗所需要的。

## 4. 输出头：战斗怎样结束

输出头是 51 个类别上的概率分布：一个**死亡**类别，或者 50 个分桶之一，分桶对应从这个状态到一场赢下的战斗结束时**还要失去**的生命值占最大生命值的比例，范围从 −0.25（会回血的战斗）到 1。第二个输出给出赢下之后还会用掉的药水数。

为什么是「还要失去」，而不是「最后剩下」？一个预测最后剩下比例的网络，只学到了现在持有的生命值在那里的价值的大约一半：现在少 1 点生命值，它的估值降低 0.0038，而这会让结局整整少 1 点生命值，按 `LeafValue` 的价格是 0.0078。它的搜索太轻易地拿生命值去换别的，没有通过它的晋级门槛。预测之后还会发生什么，就让现在持有的生命值被完整计入，因为在形成估值时它会被精确地加回去（同样那些局面上每点生命值 0.0083），估值的误差也从 0.0090 降到 0.0077（[训练战斗网络 §6](/arch/learning/combat-net/#sec-6)）。

在它的留出对局上，c2 的交叉熵是 1.32 nats，而总是预测训练集频率的是 2.00；Boss 战上最低（1.13），精英战上最高（2.64），精英战的样本很少。它推出的估值与真实结局的估值的相关系数是 0.959，`LeafValue` 是 0.790。

## 5. 给结局定价

分布还不是一个数。叶子给每个结局一个价格，把分布变成一个数。按 `LeafValue` 的价格（默认），设现在的生命值比例为 $s$，死亡的概率为 $p_0$，中点为 $m_k$ 的分桶 $k$ 的概率为 $p_k$，赢下后在持有的 $q$ 瓶药水中用掉 $u$ 瓶：

$$
\text{估值} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02\,(q - u)
$$

死亡没有额外的代价：它值 0。已经结束的战斗按 `LeafValue` 的方式估值。

**V 的价格**（`--leaf-prices v`，已实现，未使用）。对 SL 规划器，结局可以改由宏观大脑的 V 来定价。每次规划时，主机根据决策当下的整局观测算出价格（`EndPrices`），规划器的 worker 用它们给每个叶子定价（`PricedLeaf`），单位是 V 自己的单位：

- 死亡值这一局的层数（`PricedLeaf.Of` 设 `Death = run.Floor`），这适合预测层数的 V，而对目标是获胜的现在的 V 是错的：这时死亡的价格高过任何胜利（[§7](#sec-7)）；
- 剩 $h$ 点生命值的胜利，值这一局在 $h$ 点生命值时的 V，取 $h$ 及以下的最大值，这样生命值更多的胜利永远不会更不值钱，这是规划器的上界所需要的；
- 一瓶药水值少了它时 V 失去的部分，对持有的各瓶取平均，至少为 0。

换了新的 V 不需要重训这个网络：只有价格变了。它需要 `--policy plan`、一个战斗网络和一个网络形式的 `--value`；NoSL 的搜索仍用叶子权重的价格。

**设计中 V 的价格** <Badge text="规划中" variant="caution" />。价格在网络之外：死亡值 0，胜利值剩余生命值下的 V，药水值少了一瓶时 V 失去的部分。必须先修好 `Death`，这些价格要先通过自己的门槛，才能让冠军使用，这是[战斗大脑 §6](/arch/combat-brain/#sec-6) 顺序里的最后一步。第一个网络 `sl-c1` 保留现在的手设价格。这些价格只看生命值和药水数量，所以战斗改变的其他东西都没有计价：被偷的金币、被拿走的牌、最大生命值的变化，以及用掉的是哪一瓶药水。用 V 给 SL 的确切结束状态定价是一个选项，放在这同一步权衡。

## 6. 每个环境一个网络

网络预测的是打出它那些对局的策略下的结局。SL 的规划器看得到 NoSL 的搜索只能猜的东西，从同一个状态出发能赢下更多战斗，所以权重属于一种环境，而结构是共用的：网络文件写明它的环境，另一个环境的对局会拒绝它。c1–c4 早于这个字段，没有写明环境。

这留下一个还没弥合的缝隙：c2 学自 PIMC 配 `LeafValue` 打出的 NoSL 战斗，而它也是 SL 规划器的叶子。它的结局是一个比规划器弱的玩家打出的。还没有哪个用 SL 训练的网络过过门槛。<Badge text="规划中" variant="caution" /> SL 自己的第一个网络是 `sl-c1`，来自 SL 自我对弈（[训练战斗网络 §7](/arch/learning/combat-net/#sec-7)）；NoSL 目前仍用 c2。

## 7. c2 的已知问题

c2 由 `train_combat.py`（此后已删除）在提交 `b4480a1` 处写出，用的是 315 局 NoSL 对局。对照冠军的整局 SL 对局（v7-1f，`promotion-1-100` 上的 100 局，60 次死亡：52 次在 Boss，6 次在精英，2 次在普通战斗）来看，它有这些缺口：

- **词表里没有第 3 幕**。它的训练对局只到第 1 幕和第 2 幕，所以荣耀的 18 个遭遇没有一个有自己的 id，60 次死亡里有 32 次发生在词表之外的遭遇中。121 个怪物里也缺 46 个，268 个能力里缺 195 个；其中并非全都能碰到静默猎手，它们出现得有多频繁还没有测过。
- **未知能力相互混淆**。词表之外的每个能力都读作同一个未知词元，所以涂毒、爆发、必备工具和计划妥当给出完全相同的输出。在墨影幻灵的测试状态上，这相当于 0.0083 的估值，约 1 点生命值。
- **全部未知的战斗还能读到什么**。幕、遭遇和敌人全都未知时，生命值和中毒的斜率仍保持符号：30 层中毒加 0.167，已知时是 0.278。
- **不可能的分桶可能让估值低于死亡**。没有东西屏蔽超出现有生命值的分桶（[§4](#sec-4)）。
- **它从没见过规划器打牌**。它的标签是 PIMC 的结局（[§6](#sec-6)）。
- **手牌好坏几乎不影响估值（只测了一个状态）**。在 Vantom 测试状态上，用 torch 重建的 c2，手里 5 张打击对比 5 张伤口，估值只变 0.007，而敌人少 30 生命值，估值变 0.051。原因是数据还是结构，尚无定论。中毒相对敌人生命值学得合理。这只是一个状态的结果。

没有测过：c2 在 SL 回合开始局面上的校准，真实牌组里未知 id 的比例，以及更大的束或另一种叶子能把多少次死亡变成胜利。

## 8. 规划中的网络 <Badge text="规划中" variant="caution" />

本节的内容都没有实现，也没有测过。结构是 `learn/combat/net.py` 加上一些小改动。

### 8.1 它读什么

输入规则：**只读无法从 id 学到、并且会改变未来的东西**。

| 输入 | 读 | 相对 `learn/combat/encode.py` |
|---|---|---|
| 牌 | id、升级、牌堆、修饰的 id 和数值、当前费用 | 增加当前费用，效果会改变它，而 id 说明不了；增加每个修饰的数值（`ModifierView.Amount`），23 种附魔中有 11 种用到它，比如锋利 |
| 玩家 | 生命值比例、生命值、最大生命值、格挡、能量、最大能量、星、回合数 | 相同 |
| 能力 | id、数值、层数、保留的牌 | 相同 |
| 敌人 | id、生命值比例、生命值、最大生命值、格挡、已显示的回合数、能力、当前意图 | 如果留出交叉熵允许，就去掉 3 个滞后意图槽；否则保留 |
| 遗物 | id、计数、状态 | 增加计数和状态（42 种遗物会设置状态），id 都说明不了。状态是单独的输入，不是 id 的后缀 |
| 药水、遭遇、球、盟友 | 它们的 id；盟友的数和能力 | 上下文缩小到遭遇 |
| 2 个数 | 进阶等级、球槽数 | 去掉金币 |

**不读**：印在牌上的数，它们由 id 和升级决定；金币，除非测出它有用；幕、房间和角色，遭遇和牌已经隐含了它们；抽牌顺序，因为网络读的是玩家看到的东西（SL 的有序抽牌是另一个以后的实验）。

修饰的数值和遗物状态经由计算图输入 `mod_amounts` 和 `relic_status` 进入，`NetNumbers` 已经在提供它们。对静默猎手，牌的 `Vars` 仍然不读：只有 Claw、Rampage、Maul、Thrash、KinglyPunch、SovereignBlade 和 TheBall 会在战斗中改变自己的数值，它们都不在静默猎手的牌池里。

**观察的限制**。每场战斗的遗物标记（例如百年积木的）根本不在观察里，所以任何输入规则都读不到。

词表从 v7g1 重建，它能到第 3 幕。训练时少量丢弃 id（dropout），让 `<unk>` 成为网络学过的词元，这样它没见过的 id 就不再表现得毫无规律。

### 8.3 搜索中的网络

网络一次读一个状态。`TurnEnds` 列出一个回合的结束状态，叶子给每一个估值：搜索和网络只在那里相遇（[战斗大脑 §3](/arch/combat-brain/#sec-3)）。它的时间开销不是问题：游戏模拟的开销远大于网络（[提示、招式与 worker §3](/arch/combat-brain/shared/#sec-3)）。

### 8.4 如何比较网络

整体的留出交叉熵主要反映这是哪场战斗、玩家有多少生命值，而束要排序的是同一场战斗里的状态。所以比较时在它之外再报告两项：**(遭遇, 回合) 分组内的等级相关**，以及一组**固定探针**：改变一个状态的手牌、抽牌堆、能力和中毒，看估值怎样变化。这两项只作参考，由配对门槛决定。
