每个搜索都会在某处停下。PIMC 停在回合结束处；SL 规划器通常能搜到战斗结束，但在知道战斗接下来怎样发展之前，它也得给各个回合结束处的状态排序（[SL 规划器：束搜索 §1](/arch/sl-planner/beam/#sec-1)）。搜索停下的状态是**叶子**（leaf），说明它值多少的函数是**叶子估值**（leaf value）。一句话说：叶子是网络给出的结局分布，逐个结局定价，再加上预计留下的药水的一点价格。

## 1. 什么是叶子

叶子要么是一个回合开始时的状态（此前敌方回合已经真实地打完），要么是战斗的结束，赢或输。两者由同一个函数估值，`ICombatLeaf.Value(status, observation, history)`：输掉的战斗一文不值，赢下的战斗按它留下的东西估值，进行中的战斗按它预计会留下的东西估值。

- **只读观测**。叶子读玩家看到的东西，加上敌人至今出招的公开记录（[提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)）。它从不读抽牌顺序或随机数流，所以在两种环境下都不可能泄漏隐藏状态。
- **排序比水平更要紧**。搜索用叶子来比较路线：要紧的是更好的状态得到更高的估值。一个把每个状态都高估 0.1 的叶子，打法和不高估的完全一样。

## 2. 结局的价格

价格是 `LeafValue`（`LeafValue.Of`，`src/Sts2Ai.Brain/Combat/LeafValue.cs:50-77`）里手设的数：

- 输掉的战斗为 0。
- 赢下的战斗剩下生命值比例 $s$（生命值除以最大生命值）、持有 $q$ 瓶药水时，值

$$
\text{Win}(s, q) = 0.2 + 0.6\,s + 0.02\,q.
$$

它们是带网络的叶子里仅有的手设的数。已经结束的战斗直接按它们估值，不用网络：每条打完的路线的终点，因而每个计划的最终得分，都是这个公式作用在路线结束的状态上。

没有 `--combat-net` 时，进行中的战斗也交给 `LeafValue`（`HandLeaf`，`src/Sts2Ai.SimWorker/Brains/LeafChoice.cs:20`）：它根据画面上的内容预估战斗剩下的部分，另外用到几个手设的数。没有冠军这样打。

## 3. 战斗网络

对还在进行的战斗，叶子去问战斗网络。它读一个回合的开始，预测在打出它训练对局的那个策略下，这场战斗会怎样结束。它的输入和各层见[战斗网络](/arch/combat-brain/network/)，跟着一个真实状态走过它见[一个状态走过网络](/arch/combat-brain/walkthrough/)，它的训练见[训练战斗网络](/arch/learning/combat-net/)。

`--combat-net FILE` 让它来打，用在规划器里（显示为 `plan NAME`）或 PIMC 里（`pimc NAME`）。

## 4. 两个输出

**结局**。51 个概率：一个死亡，或者 50 个分桶之一，分桶对应从这个状态到一场赢下的战斗结束时还要失去的生命值占最大生命值的比例，范围从 −0.25（会回血的战斗）到 1。持有的生命值排除掉的分桶是关闭的，概率恰好为 0（[战斗网络 §7](/arch/combat-brain/network/#sec-7)）。

**药水**。赢下之后，每瓶持有的药水没有了的概率。

下图显示它们在网络文件附带的 16 个回合开始局面上的输出，这些都是来自留出对局的真实状态；加载网络时会核对它给出的这些输出和训练器算出的一致。阴影带是关闭的分桶。权重：`weights/silent/c7-2.json`。

## 5. 给结局定价

分布还不是一个数。叶子按 [§2](#sec-2) 给每个结局定价。设现在的生命值比例为 $s$，死亡的概率为 $p_0$，中点为 $m_k$ 的分桶 $k$ 的概率为 $p_k$，一瓶持有的药水赢下后没有了的概率为 $u_{\text{id}}$：

$$
\text{value} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02 \sum_{\text{held}} (1 - u_{\text{id}})
$$

死亡不加任何东西，因为它值 0（`CombatNet.Value`，`src/Sts2Ai.Brain/Combat/CombatNet.cs:74-86`）。在一个真实状态上逐项计算，见[一个状态走过网络 §13](/arch/combat-brain/walkthrough/#sec-13)。

这个形式是**状态持有的东西（精确计入），加上网络说的还要发生的事**。$s$ 被精确计入，所以同一束里的状态在网络开口之前，就已经按真实的生命值分出了差别。喝掉的药水也被精确地从求和里去掉。

**上界**。规划器按状态现有生命值和药水下一场胜利的价值来剪枝，也就是 [§2](#sec-2) 的 $\text{Win}(s, q)$，不用网络（[SL 规划器：束搜索 §2](/arch/sl-planner/beam/#sec-2)）。分桶的中点最多可以越过持有的生命值半个宽度，网络也可以预测回血，所以进行中的状态可以略微高出它的上界：训练数据里赢下的回合开始局面只有 1.84 % 回过血，而在满生命值时掩码禁止这种情况。

**网络在哪里起作用**。剪枝和在打完的路线之间选择都只读价格。网络决定束的排序、束留下什么、输掉的路线之间的打平，以及停在回合上限的路线。在 PIMC 里，它给回合结束处的每个叶子估值。

## 6. 一个网络，两种环境

SL 和 NoSL 打的是同一个网络文件。它学自 SL 的对局，所以它的结局是规划器打出的，规划器看得到 NoSL 的搜索只能猜的东西，从同一个状态出发能赢下更多。因此在 NoSL 下，同一个状态是按一个更强的玩家的结局来评价的。

## 7. 这个估值看不到什么

这些都由价格和标签决定。

- **每瓶药水统一价**。一瓶药水值 0.02，不管它是哪一瓶、在哪场战斗，相当于 70 点最大生命值下的 2.3 点生命值。所以没有哪个输出头能让规划器把药水留给 Boss，只有别的价格才能。药水输出头学的是药水什么时候用掉，而估值只读它们的和。
- **金币**。它是输入，但一场战斗里金币的变化没有价格，这里和打完的路线上都没有。偷窃和黄金印不花任何代价。
- **最大生命值**。它只通过比例进入：70/70 到 66/66 读作什么都没失去，所以纸伤难愈和至亮之焰是免费的，在打完的路线上也一样。
- **这一局剩下的部分**。打完的路线只看到生命值和药水。一场战斗的牌组、遗物或奖励对这一局意味着什么，在叶子之外。
- **同胞状态**。日志里每场战斗只有一个结局，所以没有标签能区分搜索在同一回合内比较的两个状态。区分它们的是持有的生命值（完整计入），以及网络跨战斗学到的东西。
- **它自己的玩家**。结局来自打出训练对局的那个策略，大多用的是比打门槛更低的预算（[训练战斗网络 §3](/arch/learning/combat-net/#sec-3)）。
