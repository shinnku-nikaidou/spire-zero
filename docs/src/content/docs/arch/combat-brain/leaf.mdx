每个搜索都会在某处停下。PIMC 停在回合结束处；SL 规划器通常能搜到战斗结束，但在知道战斗接下来怎样发展之前，它也得给各个回合结束处的状态排序（[SL 规划器：束搜索 §1](/arch/sl-planner/beam/#sec-1)）。搜索停下的状态是**叶子**（leaf），说明它值多少的函数是**叶子估值**（leaf value）。一句话说：c2 的叶子是网络的结局分布乘以每种结局的价格；c7-1v 的叶子是学到的一个 V 的比例。本页讲大脑拥有的两种叶子，手写的 `LeafValue`，以及两种环境的冠军都在用的战斗网络 c2（[§2](#sec-2)–[§6](#sec-6)）；c2 的已知问题（[§7](#sec-7)）；以及 SL 的下一个网络 c7-1v，代码已实现，正在训练（[§8](#sec-8)）。

## 1. 什么是叶子

叶子要么是一个回合开始时的状态（此前敌方回合已经真实地打完），要么是战斗的结束，赢或输。两者由同一个函数估值，`ICombatLeaf.Value(status, observation, history)`：输掉的战斗一文不值，赢下的战斗按它留下的东西估值，进行中的战斗按它预计会留下的东西估值。

- **只读观测**。叶子读玩家看到的东西，加上敌人至今出招的公开记录（[提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)）。它从不读抽牌顺序或随机数流，所以在两种环境下都不可能泄漏隐藏状态。
- **一个尺度**。它的单位就是整局的单位：一局胜利的份额，即设计中所说的 P(win run)（[宏观大脑：从风险值到价值 §1](/arch/macro-brain/value/#sec-1)）。下面的权重只让它大致如此；用 V 的价格时，它就是 V 的单位（[§5](#sec-5)）。
- **排序比水平更要紧**。搜索用叶子来比较路线：要紧的是更好的状态得到更高的估值。一个把每个状态都高估 0.1 的叶子，打法和不高估的完全一样。

## 2. 手工叶子：LeafValue

`LeafValue`（v0，`src/Sts2Ai.Brain/Combat/LeafValue.cs`）根据屏幕上的内容推算这场战斗剩下的部分，用到几个手设的数。

- 输掉的战斗为 0。赢下的战斗剩下生命值比例 $s$（生命值除以最大生命值）时，值 $\mathrm{Win}(s) = 0.2 + 0.6\,s$，每瓶还留着的药水再加 0.02。
- 进行中的战斗被推算到它结束。每个活着的敌人 $i$ 有一个**有效生命值** $e_i$（它的生命值加格挡，减去 0.8 乘以它身上的中毒还会造成的伤害，$n$ 层中毒为 $n + (n-1) + \dots + 1$）和一个**伤害速率** $r_i$（它本回合显示的攻击，伤害 × 段数，至少为 3）。玩家每回合造成 $d = 10 + 2 \times \text{力量}$ 的伤害，一个接一个地杀死敌人。
- 杀敌的顺序取掉血最少的那个。敌人 $i$ 一直出手直到死亡，死在第 $t_i = \sum_{j \preceq i} e_j / d$ 回合（对在它之前被杀的敌人和它自己求和），所以受到的伤害是 $\sum_i r_i\, t_i$。来自排程问题的 **Smith 规则**让这样的加权完成时间之和最小：按权重与长度之比从大到小处理各项任务，这里就是 $r_i / e_i$。超出当前格挡的伤害有一半从生命值里扣掉，剩下的生命值按赢下战斗来打分：

$$
\text{估值} = \mathrm{Win}\!\left(\frac{\text{生命值} - 0.5\,\max\!\big(0,\ \sum_i r_i t_i - \text{格挡}\big)}{\text{最大生命值}}\right) + 0.02 \times \text{药水数}
$$

- 推算出死亡（比例低于 0）时，估值向 0 衰减而不会变成负数，$s < 0$ 时 $\mathrm{Win}(s) = 0.2\, e^{3 s}$，在 0 处斜率相同。它始终高于输掉，无论局面多么无望，都还能给路线排序：用一个平的下限时，每条会输的路线看起来都一样，大脑于是会过早结束回合。

所以，打在出手重、死得快的敌人身上的伤害更值钱，溢出伤害毫无价值，而战斗中途的状态永远不会比它在相同生命值下能达到的胜利更好。SL 规划器的上界依靠的正是最后这条性质（[SL 规划器：束搜索 §2](/arch/sl-planner/beam/#sec-2)）。

它的盲区是它不读的一切：敌人身上除中毒以外的能力、玩家身上除力量以外的能力、抽牌堆，以及本回合之后的所有意图。这些数（`LeafWeights`：WinBase 0.2、PerHp 0.6、PerPotion 0.02、Dps 10、Unblocked 0.5、MinIncoming 3、PoisonShare 0.8）是假设，从没调过：`--leaf FILE` 让一局对局、一次测试集或大脑用别的权重（`weights --leaf` 把默认值输出成这样一个文件，`leaf0`），但已经没有工具再调它们，因为策略交给了学到的价值（[学习：循环 §6](/arch/learning/loop/#sec-6)）。

## 3. 战斗网络

战斗网络（`CombatNet`，`--combat-net FILE`）用从打过的战斗中学到的预测代替推算。它读一个回合的开始，预测在打出它训练对局的那个策略下，这场战斗会怎样结束。

**它读什么**。观测显示的关于这场战斗的一切，以词元的形式：

- 四个牌堆（手牌、抽牌堆、弃牌堆、消耗堆）里的每张牌：它的 id、升级次数、附魔和诅咒，以及它在哪个牌堆；
- 玩家：生命值比例、生命值、最大生命值、格挡、能量、最大能量、星、回合数，以及它的能力（id 和层数）；
- 每个活着的敌人：它的 id、生命值比例、生命值、最大生命值、格挡、它已显示了几个回合、它的能力，以及它的**意图槽**：它现在显示的意图，然后是它前 3 个回合的意图，最近的在前；
- 遗物、药水，以及上下文（角色、遭遇、房间、幕）。

关于怪物的出招，没有任何东西是手写的。从怪物的 id、回合数和它最近的意图，网络可以从数据中学到每个怪物的出招顺序，以及怪物处在这个顺序的哪个位置。一个实验性的下回合意图输出头，对 57.7% 的敌人说对了下回合的意图类型，重复当前意图只有 28.9%，而它猜错的大多是游戏随机掷出的招式（[NoSL PIMC §1](/arch/pimc/#sec-1)）。

**它怎样读**。一个集合编码器（*Deep Set*，Zaheer 等，2017：其元素向量之和的函数，对每种顺序都给出相同的输出，能读任意大小的集合）：每张牌是若干学到的向量之和（它的 id 的向量、升级次数乘以它的 id 的升级向量、它的修饰的向量和它所在牌堆的向量），一个小 MLP 逐张处理每张牌，每个牌堆是其中各张牌之和（× 1/8）。敌人的一个槽是其中各个意图之和（意图类型的向量，加上伤害 / 10 和总伤害 / 20 各乘以该类型的一个向量）；一个 MLP 把每个敌人连同它的能力和槽一起处理，各个敌人再求和。遗物、药水和上下文都是各自向量之和。然后两层 256 的网络得出输出头。求和与顺序无关，能读任意多张牌或任意多个敌人，这正是一个牌堆和一场战斗所需要的。

## 4. 输出头：战斗怎样结束

输出头是 51 个类别上的概率分布：一个**死亡**类别，或者 50 个分桶之一，分桶对应从这个状态到一场赢下的战斗结束时**还要失去**的生命值占最大生命值的比例，范围从 −0.25（会回血的战斗）到 1。第二个输出给出赢下之后还会用掉的药水数。

为什么是「还要失去」，而不是「最后剩下」？一个预测最后剩下比例的网络，只学到了现在持有的生命值在那里的价值的大约一半：现在少 1 点生命值，它的估值降低 0.0038，而这会让结局整整少 1 点生命值，按 `LeafValue` 的价格是 0.0078。它的搜索太轻易地拿生命值去换别的，没有通过它的晋级门槛。预测之后还会发生什么，就让现在持有的生命值被完整计入，因为在形成估值时它会被精确地加回去（同样那些局面上每点生命值 0.0083），估值的误差也从 0.0090 降到 0.0077（[训练战斗网络 §6](/arch/learning/combat-net/#sec-6)）。

下图显示 c2 的输出头在它的文件附带的八个回合开始局面上的输出，这些都是来自留出对局的真实状态；加载网络时会核对它给出的结局和训练器算出的一致（[学习：参考 §7](/arch/learning/reference/#sec-7)）。左边的两场 Boss 战是难的：结局中分别有 86% 和 77% 是死亡。

在它的留出对局上，c2 的交叉熵是 1.32 nats，而总是预测训练集频率的是 2.00；Boss 战上最低（1.13），精英战上最高（2.64），精英战的样本很少。它推出的估值与真实结局的估值的相关系数是 0.959，`LeafValue` 是 0.790。

这张图也显示出一个缺陷。一场赢下的战斗失去的生命值不可能多于玩家现有的，所以虚线右边的每个分桶对胜利来说都不可能；但没有任何东西告诉输出头这一点。在容易的局面上它不往那里放权重，但在两场 Boss 战里放了：同族小队的胜利概率有 83% 落在那里，墨影幻灵的有 21%。按 `LeafValue` 的价格（战斗网络线性地使用这些价格），这些不可能的胜利算得比 0 生命值的胜利（0.2）还低，最深的那些甚至低于死亡（0）（[§7](#sec-7)）。

## 5. 给结局定价

分布还不是一个数。叶子给每个结局一个价格，把分布变成一个数。按 `LeafValue` 的价格（默认），设现在的生命值比例为 $s$，死亡的概率为 $p_0$，中点为 $m_k$ 的分桶 $k$ 的概率为 $p_k$，赢下后在持有的 $q$ 瓶药水中用掉 $u$ 瓶：

$$
\text{估值} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02\,(q - u)
$$

死亡没有额外的代价：它值 0。已经结束的战斗按 `LeafValue` 的方式估值。

**V 的价格**（`--leaf-prices v`，已实现，未使用）。这是目标为 `worth` 的网络的价格，也只和这种网络搭配，c2 配上它会被拒绝。每个状态都用 V 自己的单位（`PricedLeaf`，`Brain/Combat/PricedLeaf.cs:17-49`）：

- 死亡值 0；
- 胜利值这一局以它结束时的生命值和药水计算的 V。对持有药水的每个子集，从 0 到最大生命值逐点询问 V，并取该生命值及以下的最大值，这样生命值更多的胜利永远不会更不值钱，这是规划器的上界所需要的。战斗中得到的药水没有价格，因为 V 只被问到战斗开始时持有的那些；
- 进行中的状态值网络给出的数（限制在 0 和文件的 `worth_cap` 之间）乘以战斗第一次规划时这一局的 V。

价格每场战斗算一次，在第一次规划时由主机算出，随每个请求发给规划器的 worker（`EndPrices`），所以 worker 不需要 V。持有药水的每个不同子集各有一张 V 的表。它需要 `--policy plan`、目标为 `worth` 的 `--combat-net` 和一个网络的 `--value`；NoSL 的搜索继续用叶子权重的价格。

**这些价格看不到什么**。一条打完的路线看到的金币和牌组是第一次规划时的样子；只有网络通过它的标签学到战斗会从中拿走什么。胜利的价格随生命值上升是构造保证的，随药水上升则全看 V 怎么说：没有任何东西强制保留药水的胜利高于不保留的。标签和价格都属于生成它们的那个 V，所以换一个 V 就要重新计算标签。

## 6. 每个环境一个网络

网络预测的是打出它那些对局的策略下的结局。SL 的规划器看得到 NoSL 的搜索只能猜的东西，从同一个状态出发能赢下更多战斗，所以权重属于一种环境，而结构是共用的：网络文件写明它的环境，另一个环境的对局会拒绝它。c1–c4 早于这个字段，没有写明环境。

这留下一个还没弥合的缝隙：c2 学自 PIMC 配 `LeafValue` 打出的 NoSL 战斗，而它也是 SL 规划器的叶子。它的结局是一个比规划器弱的玩家打出的。还没有哪个用 SL 训练的网络过过门槛。<Badge text="训练中" variant="caution" /> SL 自己的网络是 c7-1v，来自 SL 自我对弈（[训练战斗网络 §7](/arch/learning/combat-net/#sec-7)）；NoSL 目前仍用 c2。

## 7. c2 的已知问题

c2 由 `train_combat.py`（此后已删除）在提交 `b4480a1` 处写出，用的是 315 局 NoSL 对局。对照冠军的整局 SL 对局（v7-1f，`promotion-1-100` 上的 100 局，60 次死亡：52 次在 Boss，6 次在精英，2 次在普通战斗）来看，它有这些缺口：

- **词表里没有第 3 幕**。它的训练对局只到第 1 幕和第 2 幕，所以荣耀的 18 个遭遇没有一个有自己的 id，60 次死亡里有 32 次发生在词表之外的遭遇中。121 个怪物里也缺 46 个，268 个能力里缺 195 个；其中并非全都能碰到静默猎手，它们出现得有多频繁还没有测过。
- **未知能力相互混淆**。词表之外的每个能力都读作同一个未知词元，所以涂毒、爆发、必备工具和计划妥当给出完全相同的输出。在墨影幻灵的测试状态上，这相当于 0.0083 的估值，约 1 点生命值。
- **全部未知的战斗还能读到什么**。幕、遭遇和敌人全都未知时，生命值和中毒的斜率仍保持符号：30 层中毒加 0.167，已知时是 0.278。
- **不可能的分桶可能让估值低于死亡**。没有东西屏蔽超出现有生命值的分桶（[§4](#sec-4)）。
- **它从没见过规划器打牌**。它的标签是 PIMC 的结局（[§6](#sec-6)）。
- **药水是统一价**。它的价格按每瓶 0.02 计算药水，金币和失去的牌完全不计，而一瓶药水值多少取决于牌组。机器人平均每个回合开始持有 0.1 瓶药水；这是否由统一价造成，没有证明。

**在 SL 的回合开始局面上**。在 v7g1 的留出对局上，c2 的交叉熵是 2.086（先验 2.147），平均死亡概率 0.162（实际 0.055），(遭遇, 回合) 内的等级相关 0.814。在 `promotion-301-500` 的中等预算对局上，这三项是 3.264（2.119）、0.275（0.039）和 0.696；其中 Boss 战是 6.56（3.58）、0.803（0.184）和 0.470。Test Subject 的等级相关在留出对局上是 0.016，在中等预算上是 0.206。在这些中等预算对局上，它不认识 21.6 % 的敌人、23.7 % 的遗物、28.9 % 的修饰、7.0 % 的能力和 3.6 % 的牌。

没有测过：更大的束或另一种叶子能把多少次死亡变成胜利。

## 8. 下一个网络：c7-1v <Badge text="训练中" variant="caution" />

`learn/combat/` 和 [§5](#sec-5) 的价格已经实现。c7-1v 正在训练，还没有过门槛，所以这里没有任何结果。它是这一步唯一的网络，V 不为它重新训练：标签和价格由 v7-1f 算出。

### 8.1 它读什么

输入规则：**战斗的状态都放进输入；能从 id 推出的东西由网络去学**。

| 输入 | 读 | 增加或不读的部分 |
|---|---|---|
| 牌 | id、升级、牌堆、修饰的 id 和数值、当前费用 | 当前费用，效果会改变它，id 说不出来；每个修饰的数值（`ModifierView.Amount`），23 种附魔中有 11 种用到，其中包括 Sharp |
| 玩家 | 生命比例、生命、最大生命、格挡、能量、最大能量、星、回合 | – |
| 能力 | id、层数、堆叠数、保留的牌 | – |
| 敌人 | id、生命比例、生命、最大生命、格挡、已显示回合数、能力、当前和最近 3 回合的意图 | – |
| 遗物 | id、计数、熔化标记、状态 | 计数和熔化标记，以及 42 种遗物会设置的状态；这些 id 都说不出来。状态是单独的输入，不是 id 的后缀 |
| 药水、充能球、盟友 | 它们的 id；盟友的数值和能力 | – |
| 上下文 | 遭遇 | 幕、房间和角色仍然喂入，但词表只列遭遇，所以它们读作 `<unk>`：遭遇已经隐含了它们 |
| 3 个数 | 进阶、充能球栏位、金币 | – |

**不读**：其他印在牌上的数，它们由 id 和升级决定；抽牌顺序，因为网络读的是玩家看到的东西（SL 的有序抽牌是另一个以后的实验）。

新增的数经由计算图输入 `costs`、`mod_amounts`、`relic_values` 和 `relic_status` 进入，`NetNumbers` 已经在提供它们。对静默猎手，牌的 `Vars` 仍然不读：只有 Claw、Rampage、Maul、Thrash、KinglyPunch、SovereignBlade 和 TheBall 会在战斗中改变自己的数值，它们都不在静默猎手的牌池里。

**观察的限制**。每场战斗的遗物标记（例如百年积木的）根本不在观察里，所以任何输入规则都读不到。

词表从它的训练对局建立，这些对局能到第 3 幕。没有 id dropout：这个词表在中等预算的测试集上没有留下未知 id。

嵌入维度 32。一张牌经过 32 → 64 → 64 的 MLP，按牌堆求和并乘 1/8：共 256 个数。玩家是 8 个数。能力经过 32 → 64 的 MLP 后求和：64。一个敌人是 224 个数（32 + 64 + 4 × 32），经过 224 → 128 → 128 的 MLP 后求和：128。遗物、药水、上下文和充能球各 32，盟友 64，另有 3 个数。由 651 → 256 → 256 的主体读取，宽度为 1 倍。

输出头是一个数，即战斗的**价值**（worth），没有桶，没有药水头，也没有策略头：

```
worth = min(4, V(first run_view after the fight) / V(last run_view before it))
a death: 0
a fight that wins the run: V after it = 1
```

V 读牌组、遗物、药水、生命和金币，所以一场战斗花掉的东西，按它对这一局意味着什么来定价，一瓶药水值多少也像在 V 那里一样取决于牌组。它的样本和损失见[训练战斗网络 §3](/arch/learning/combat-net/#sec-3)–[§4](/arch/learning/combat-net/#sec-4)。

### 8.3 搜索中的网络

网络一次读一个状态。`TurnEnds` 列出一个回合的所有结束状态，叶子给每个估值：搜索和网络只在这里相遇（[战斗大脑 §3](/arch/combat-brain/#sec-3)）。搜索按网络的比例乘以战斗前的 V 排序，并用 V 给结局的价格结束一条路线（[§5](#sec-5)）。大于 1 的数表示网络预期这场战斗会改善局面：战斗的奖励可以抬高 V。

### 8.4 怎样评判

报告给出平方误差和 (遭遇, 回合) 分组内的等级相关，既有整体，也按幕、房间和遭遇分开，因为束要排序的是同一场战斗里的状态。这些只作参考，由配对门槛决定。

**门槛**。`--combat-net weights/silent/c7-1v.json`，配 SL 冠军的其他选项，在节点克隆上，不探索：在 `promotion-1-300`（它从未训练过的种子）上，中等预算 300 局，低预算 300 局。中等预算下 `wins_lower_95` 大于 0 即通过；300 局时一对的标准误约 3.15 个百分点，所以大约需要 +5.2 个百分点，即 +16 胜。低预算不作决定。Test Subject 也不作决定：它在 v7g1 里的 16 胜可能太少，学不到东西，而且大多数死亡发生在它的第三形态之前（按形态 120 / 183 / 28）。

一个门槛包含三项改动：标签、输入和价格，所以失败时分不清是网络还是 V 的价格的问题。

| 结果 | 解读 |
|---|---|
| 排序更好，通过 | 叶子曾是瓶颈；定价的结局有效 |
| 排序更好，胜场和层数持平 | 在这个预算下瓶颈不是叶子，而是搜索或 V。对最难的战斗还没有定论，因为它们的获胜标签很少 |
| 低预算改善，中等预算持平 | 叶子只在窄束里有影响 |
| 更差 | 先看每场胜利损失的生命、用掉的药水和精英战 |
