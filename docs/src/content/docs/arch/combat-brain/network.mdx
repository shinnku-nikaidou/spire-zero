战斗网络读一个回合开始时的战斗状态，预测这场战斗会怎样结束。搜索用这个预测给它到达的状态排序（[叶子](/arch/combat-brain/leaf/)）。本页从输入到输出介绍这个网络。代码是 `learn/combat/net.py` 里的 `Net`，它的输入由 `learn/combat/encode.py` 规定。它怎样训练，见[训练战斗网络](/arch/learning/combat-net/)。想看每一步的真实数字，请读[一个状态走过网络](/arch/combat-brain/walkthrough/)。

## 1. 整个网络

集合编码器读牌、能力、敌人和盟友；学到的向量直接求和读遗物、药水、上下文和充能球。它们的输出拼接成一个 1,291 维的向量。两层的主体把它变成 512 个数，两个输出头读这些数：**结局**和**药水**。

一个网络打每一场战斗：全部五个角色、每个进阶、两种环境，都用同一套权重（`weights/all/`）。角色是上下文词元之一，进阶是那 3 个数之一，所以在它们的战斗有差别的地方，网络能把它们分开。没有哪个输入、输出头或层只为一个角色存在：某个角色需要的东西，比如充能球或星，是共享网络的一部分，对其他角色读作空。SL 和 NoSL 只在调用网络的搜索上不同，即 SL 规划器或 PIMC（[环境](/arch/environments/)）。

沿途的形状如下，其中一个批次有 $B$ 个状态，一个状态有 $n$ 张牌、$q$ 个能力、$e$ 个敌人、一个槽里 $i$ 个意图、$r$ 件遗物和 $a$ 个盟友：

| 步骤 | 内容 | 形状 |
|---|---|---|
| 牌 | 每张牌一个向量 | $B \times n \times 64$ |
| | $\varphi$，逐张计算 | $B \times n \times 128$ |
| | 按牌堆求和 × 1/8，4 个牌堆拼接 | $B \times 512$ |
| 玩家 | 8 个数 | $B \times 8$ |
| 能力 | 每个能力一个向量，经过 $\varphi$ | $B \times q \times 128$ |
| | 求和 | $B \times 128$ |
| 敌人 | id 和数值 | $B \times e \times 64$ |
| | 它们的能力，求和 | $B \times e \times 128$ |
| | 4 个意图槽 | $B \times e \times 256$ |
| | 拼接，经过 $\varphi$ | $B \times e \times 256$ |
| | 求和 | $B \times 256$ |
| 遗物、药水、上下文、充能球 | 各是向量之和 | 各 $B \times 64$ |
| 盟友 | 经过 $\varphi$，求和 | $B \times 128$ |
| 3 个数 | 进阶、充能球栏位、金币 | $B \times 3$ |
| 拼接 | 以上全部 | $B \times 1291$ |
| 主体 | 两层 | $B \times 512$ |
| 结局输出头 | 一个死亡和 50 个分桶 | $B \times 51$ |
| 药水输出头 | 每个药水 id 一个概率 | $B \times 66$ |

药水输出头最后一维的宽度是药水表的大小，66。

## 2. 它读什么

**规则：战斗的状态都放进输入；能从 id 推出的东西由网络去学**。牌上印的数由它的 id 和升级决定，所以不读。一场战斗在牌上积累的东西要读，因为没有哪个 id 说得出来：它当前的能量费用和星辰费用；它的伤害和格挡，它们会增长，就像爪击的伤害随每打出一张爪击而增长；它根据战斗算出的数，比如谋杀的；它的额外打出次数；它的附魔积累的伤害，即动量的；它的附魔一场一次的效果是否已用掉；它的关键词，也包括某个效果只在本回合给它的关键词；以及 Tinker Time 把一张疯狂科学做成了什么。充能球的数值也要读，它们随战斗进行而改变，它在队列中的位置也一样要读。关于怎样打，什么都没有写进去：没有哪张牌被说成好牌，也没有列出哪个怪物的出招顺序。

一切都来自观测，即玩家看到或记得的东西，加上敌人至今出招的公开记录（[提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)），由 `encode.tokens`（`learn/combat/encode.py:145-186`）读出：

| 输入 | 读什么 |
|---|---|
| 牌 | id、升级次数（更高的读作 3）、牌堆；它的修饰词元：附魔、诅咒、关键词（它自己的和只在本回合有的）、Tinker Time 给的卡牌类型和附加效果，以及表示附魔效果已用掉的 `spent`；它的附魔和诅咒的数值；它的当前能量费用（X 或没有费用时为 0）和星辰费用；它的伤害（奥斯提攻击牌的伤害是奥斯提的；没有列出时为 0）、格挡、算出的数、额外打出次数和它的附魔积累的伤害 |
| 玩家 | 生命值比例、生命值、最大生命值、格挡、能量、最大能量、星、回合数 |
| 能力 | id、数值、提示里与图标数字分开写出的层数、它保留或偷走的牌（夜魇的、顺走的）、它的数离开它自己的数多远（坚韧之环的格挡、炸弹的伤害） |
| 敌人 | id、生命值比例、生命值、最大生命值、格挡、它已显示了几个回合、它的能力、它现在和前 3 个回合的意图；倒下、等着复活的敌人也算 |
| 遗物 | id（用完后加上 `:used`）、计数、熔化标记、状态（一场一次或一回合一次的效果已用掉、又没有别的状态显示时为 `Spent`） |
| 药水 | 它们的 id |
| 充能球 | id、被动值、激发值、队列中的位置 |
| 盟友 | id、生命值比例、生命值、最大生命值、格挡、能力 |
| 上下文 | 遭遇、角色 |
| 3 个数 | 进阶、充能球栏位、金币 |

**不读**：牌和遗物上印的数、抽牌顺序、临时改动结束后牌回到的费用，以及敌人自己藏着的东西，即它的计数器和它招式的状态。牌的伤害和格挡是它自己的数 `vars.Damage` 和 `vars.Block`，未计力量和敏捷；它根据战斗算出的数是 `calc`（[协议：观测与动作 §7](/arch/protocol/observation/#sec-7)）。牌堆按集合读，就像玩家看到的那样，在 SL 下也是如此。

**上下文**。喂入的词元是 `character:ID`、`encounter:ID`、`room:ID` 和 `act:N`。表里列出角色和遭遇；房间和幕读作未知表项，因为遭遇已经隐含了它们。

**词元表**。网络文件为每种 id 保存一张表：`cards`、`modifiers`、`powers`、`enemies`、`intents`、`relics`、`potions`、`context`、`orbs`、`allies`、`relic_status`。每张表按排序列出这个游戏版本的每个 id，排在第 0 项之后；第 0 项是同一个共享的 `<unk>`，它读任何其他 id，比如比文件新的 id（`learn/game_ids.py`，来自 `learn/game_ids.json`，由模拟器的 `tables` 命令写出）。所以这些表不依赖训练数据。`modifiers` 列出附魔、诅咒和关键词、Tinker Time 的卡牌类型和附加效果，以及 `spent`；`relic_status` 列出游戏的各种状态和 `Spent`；`allies` 列出游戏的怪物，因为盟友就是一个怪物。

**缩放**。数值缩放到 1 左右，再截断在 ±10 以内，因为少数状态会出现极大的数（喷发中的瀑布巨兽的生命值；`learn/combat/encode.py:71-143`）：

| 数 | 缩放 |
|---|---|
| 生命值、最大生命值 | / 100 |
| 生命值比例 | 不变 |
| 格挡 | / 20 |
| 能量、最大能量 | / 3 |
| 星 | / 5 |
| 回合数、敌人已显示的回合数 | / 10 |
| 能力的数值和层数、修饰的数值、遗物的计数 | / 10 |
| 牌的费用 | / 3 |
| 牌的星辰费用 | / 5 |
| 牌的伤害、格挡、算出的数、积累的伤害 | / 20 |
| 牌的额外打出次数 | / 2 |
| 能力的偏移量 | / 20 |
| 充能球的被动值和激发值 | / 10 |
| 意图的每段伤害 | / 10 |
| 意图的总伤害（伤害 × 段数） | / 20 |
| 金币 | / 100 |
| 进阶、充能球栏位 | / 10，不截断 |

死去的盟友不读入：它即使回来，生命值也是重新生成的。只有倒下、等着复活的敌人留在战斗的列表里（其他的会被游戏立刻移除），它连同它的意图一起读入，因为它的复活是一个招式。没有 id 的敌人读作 `<none>`，没有 id 的盟友（玩家的）读作 `<player>`。

**输入张量**，按计算图输入的顺序排列（`encode.INPUTS`，`learn/combat/encode.py:24-68`）。每个列表都补齐到批次里最长的长度，且至少为 1，并有一个掩码，存在的位置为 1，补齐的位置为 0：

| 名称 | 形状 | 内容 |
|---|---|---|
| `cards`、`ups`、`costs`、`damages` | $B \times n$ | 每张牌的表项、升级次数、费用、伤害 |
| `piles` | $B \times n \times 4$ | 它的牌堆，独热：手牌、抽牌堆、弃牌堆、消耗堆 |
| `numbers` | $B \times n \times 5$ | 它的格挡、算出的数、额外打出次数、星辰费用、积累的伤害 |
| `mods`、`mod_mask`、`mod_amounts` | $B \times n \times m$ | 它的修饰词元的表项（$m$ 是一张牌最多有的个数）、掩码，以及前两个即附魔和诅咒的数值（其他词元为 0） |
| `player` | $B \times 8$ | 玩家的数值 |
| `powers`、`power_amounts`、`power_stacks`、`power_details`、`power_mask` | $B \times q$ | 玩家的能力 |
| `power_cards`、`power_card_mask` | $B \times q$ | 能力保留或偷走的牌 |
| `enemies`、`enemy_mask` | $B \times e$ | 每个敌人的表项及其掩码 |
| `enemy_scalars` | $B \times e \times 5$ | 它的数值 |
| `enemy_powers`、`enemy_power_amounts`、`enemy_power_stacks`、`enemy_power_details`、`enemy_power_mask`、`enemy_power_cards`、`enemy_power_card_mask` | $B \times e \times q$ | 它的能力 |
| `intents`、`intent_mask` | $B \times e \times 4 \times i$ | 每个槽的意图类型 |
| `intent_values` | $B \times e \times 4 \times i \times 2$ | 它们的伤害和总伤害 |
| `relics`、`relic_mask`、`relic_status` | $B \times r$ | 每件遗物的表项、掩码和状态 |
| `relic_values` | $B \times r \times 3$ | 它的计数、是否显示计数（计算图不用）、是否熔化 |
| `potions`、`potion_mask` | $B \times p$ | 每瓶持有的药水的表项及其掩码 |
| `context`、`context_mask` | $B \times 4$ | 上下文词元 |
| `orbs`、`orb_mask` | $B \times o$ | 每个充能球的表项及其掩码 |
| `orb_values` | $B \times o \times 2$ | 它的被动值和激发值 |
| `allies`、`ally_mask` | $B \times a$ | 每个盟友的表项和掩码 |
| `ally_scalars` | $B \times a \times 4$ | 它的数值 |
| `ally_powers`、`ally_power_amounts`、`ally_power_mask` | $B \times a \times q$ | 它的能力 |
| `extra` | $B \times 3$ | 进阶、充能球栏位、金币 |

## 3. 牌

牌堆是一个多重集：牌的顺序没有意义，大小也不固定。所以每张牌各自经过同一个小网络，再把结果加起来：这是一个 Deep Set（Zaheer 等，2017）。求和能以任意顺序读任意多张牌。下面所有的编码器都是 `Net.encode`（`learn/combat/net.py:229-308`）。

**牌的向量**。id 为 $c$、升级次数为 $u$、能量费用为 $k$、星辰费用为 $k^\star$、伤害为 $v$、格挡为 $b$、算出的数为 $z$、额外打出次数为 $r$、积累的伤害为 $j$、牌堆为 $l$、修饰词元为 $m$ 且数值为 $a_m$ 的牌成为 64 个数：

$$
x = E[c] + u\, U[c] + k\, K + k^\star K^\star + v\,\big(D + D_c[c]\big) + b\, B[c] + z\, Z[c] + r\, R[c] + j\, J + P[l] + \sum_{m} \big(M[m] + a_m\, A[m]\big).
$$

$E$、$U$、$D_c$、$B$、$Z$、$R$、$M$ 和 $A$ 是学到的表，每个 id 一个向量。$K$、$K^\star$、$D$ 和 $J$ 各是一个学到的向量，$P$ 每个牌堆一个向量。通过牌自己 id 的向量读入的数，在每张牌上可以有它自己的意思：算出的数在一张牌上是伤害，在另一张牌上是格挡或抽牌数。每一项开始时都是标准差为 0.1 的随机数。

**$\varphi$，牌的网络**。两层，每张牌用同样的权重：

$$
\varphi(x) = \mathrm{ReLU}\big(W_2\, \mathrm{ReLU}(W_1 x + b_1) + b_2\big),
$$

其中 $W_1$ 是 64 → 128，$W_2$ 是 128 → 128。ReLU 逐个数地取 $\max(0, x)$。

**每个牌堆一个和**。向量在每个牌堆内相加并缩放：

$$
h_l = \frac{1}{8} \sum_{\text{cards in pile } l} \varphi(x).
$$

系数 $1/8$ 让一个牌堆的和保持在平均值的大小。和说明某种牌有多少；网络能分辨厚手牌和薄手牌。四个牌堆拼接起来：$4 \times 128 = 512$ 个数。同一张牌在手牌和弃牌堆里读起来不同，因为 $P[l]$ 是 $x$ 的一部分，也因为这两个和是拼接里分开的两部分。

## 4. 能力

id 为 $t$、数值为 $g$、层数为 $s$、偏移量为 $d$、可能保留或偷走一张牌 $c$ 的能力成为 64 个数：

$$
y = T[t] + g\, G[t] + s\, S[t] + d\, X[t] + E[c].
$$

$G$、$S$ 和 $X$ 为每个能力 id 保存一个方向，所以一个数对一个能力可以很要紧，对另一个却几乎无关。偏移量是提示里写出的一个数离开能力自己的数有多远，没有离开时为 0。牌的向量来自牌的表 $E$。一层 64 → 128 加 ReLU 映射每个能力，各个能力不经缩放直接求和：128 个数。同样的权重读玩家的能力、每个敌人的能力和每个盟友的能力（盟友的没有层数、牌和偏移量）。

## 5. 敌人和它们的意图

**一个意图**有类型 $d$、每段伤害 $f$ 和总伤害 $v$：

$$
w = I[d] + f\, I_f[d] + v\, I_v[d].
$$

**一个意图槽**是其中各个意图之和，加上一个学到的槽位向量。槽 0 是敌人现在显示的；槽 1 到 3 是它前 3 个回合显示的，最近的在前。空槽只有它的槽位向量。四个槽拼接起来：$4 \times 64 = 256$ 个数。

**一个敌人**拼接三部分：它的 id 的向量加上它 5 个数值的线性投影（64），它的能力之和（128），以及它的各个槽（256）。一共 448 个数，经过 448 → 256 → 256 的 MLP，每个敌人用同样的权重。各个敌人再求和：256 个数。

倒下、等着复活的敌人和其他敌人一样读入：它的生命值比例为 0，它的槽 0 里是它的复活。

关于怪物的出招，没有任何东西是手写的。从怪物的 id、回合数和它最近的意图，网络可以学到怪物的出招顺序，以及它处在这个顺序的哪个位置。

## 6. 袋、盟友和数

**一件遗物**是它的 id 的向量，加上计数乘以它 id 的一个学到的向量，熔化时加一个学到的向量，再加上它的状态的向量：游戏的各种状态，或者效果已在本场战斗或本回合用掉时的 `Spent`。各件遗物求和：64 个数。

**药水和上下文**是袋：每个 id 有一个学到的向量，这些向量直接相加，中间没有层。上下文的词元是遭遇和角色。空袋是零向量。一种药水的两瓶算两次。

**一个充能球**的 id 为 $o$、被动值为 $g$、激发值为 $h$，在队列中的位置为 $j$，它成为

$$
O[o] + g\, O_g[o] + h\, O_h[o] + O_j[j, o].
$$

$O_g$ 和 $O_h$ 为每个充能球 id 保存一个方向。$O_j$ 为每个位置和充能球 id 保存一个向量，所以队列的顺序能到达网络；第十个及以后的位置都读作第十个（`MAX_ORBS`）。各个充能球不经过层直接求和：64 个数。没有充能球时是零向量。

**一个盟友**是它的 id 的向量加上它 4 个数值的投影，再与它的能力之和拼接，经过一层 192 → 128。各个盟友求和：128 个数。

**拼接**。所有部分连接起来：

$$
\underbrace{512}_{\text{cards}} + \underbrace{8}_{\text{player}} + \underbrace{128}_{\text{powers}} + \underbrace{256}_{\text{enemies}} + \underbrace{4 \times 64}_{\text{bags}} + \underbrace{128}_{\text{allies}} + \underbrace{3}_{\text{numbers}} = 1291.
$$

## 7. 主体和两个输出头

**主体**是两层的 MLP，每层 512 个数。一切在这里相遇：在拼接之前，没有哪张牌见过敌人，也没有哪个敌人见过生命值。

**结局输出头**是一层线性 512 → 51。类别 0 是**死亡**。类别 1 到 50 是分桶，每个宽 0.025，对应从这个状态到一场赢下的战斗结束时**还要失去**的生命值占最大生命值的比例，范围从 −0.25（会回血的战斗）到 1。

**掩码**。有些分桶对一个状态来说是不可能的。胜利结束时的生命值比例在 $(0, 1]$ 内，所以现在的生命值比例为 $s$ 时，失去的部分必须低于 $s$，且至少为 $s - 1$。分桶 $[l, l + 0.025)$ 保持开启的条件是

$$
l < s \quad\text{and}\quad l + 0.025 > s - 1.
$$

其他分桶的 logit 被设为 $-10^4$，经过 softmax 后恰好为 0（`Net.reachable`，`learn/combat/net.py:221-227`）。这条规则在计算图里面，所以 C# 不需要保存它。然后对开启的类别做 softmax，得到 51 个概率，即计算图的输出 `outcome`。

**为什么是「还要失去」，而不是「最后剩下」**。估值的形式是*状态持有的东西（精确计入），加上网络说的还要发生的事*（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）。所以现在持有的生命值被完整计入，同一束里的两个状态在网络开口之前就已经按真实的生命值分出了差别。每个输出头都遵循这条规则：它预测相对于状态的变化，而状态持有的东西被完整计入。

**药水输出头**是一层线性 512 → 66 加 sigmoid，即计算图的输出 `potion_used`：药水表的每一项一个概率，表示它在一场赢下的战斗结束时没有了。训练和估值只按表项读持有的药水。同一 id 的两瓶读到同一个概率；它们的标签（一瓶没有了，一瓶还在）把它训练到 0.5，其和是对的。

药水输出头宽度固定，不增加新的动态轴，它和结局只共用主体。它只占损失的一小部分（[训练战斗网络 §4](/arch/learning/combat-net/#sec-4)）。

## 9. 一次前向计算，两份实现

训练器在 PyTorch 里计算网络；大脑在 C# 里运行它。两者必须一致，靠的是网络文件（[学习：参考 §7](/arch/learning/reference/#sec-7)）：

- **导出**。`learn/combat/export.py`（`net_file`，`:72-105`）把网络作为 ONNX 计算图写进文件，掩码、softmax 和 sigmoid 都包括在内，输入按 [§2](#sec-2) 命名，每个长度都不固定。旁边是词元表、分桶、训练报告，以及 16 个留出的回合开始和训练器给它们的输出，其中有多段攻击、持有药水和低生命值的状态。
- **推理**。`CombatNet`（`src/Sts2Ai.Brain/Combat/CombatNet.cs`）遵循 `encode.py`：`Graph`（`:90-120`）构建同样的张量，由 ONNX Runtime 运行计算图。
- **检查**。`CombatNet.Load`（`:55-72`）只有在这 16 个状态的输出与训练器的相差不超过 $10^{-3}$ 时才接受这个文件。两边读状态的方式只要有差别，文件就加载不了。

## 10. 这个结构表达不了什么

这些只由结构决定。

- **求和之前，没有哪张牌见过另一张**。牌之间的关系只能以求和后还留下的数的形式到达主体。
- **袋是线性的**。两件遗物之间、一件遗物和一张牌之间的关系，只能由主体去算。
- **牌堆是集合**。不读抽牌顺序，所以接下来抽到什么只能从牌堆里有什么去猜。
- **槽只存 3 个回合**。敌人更早做过的事，只能通过它已显示的回合数和它的能力到达网络。
- **敌人是一个和**。网络能数出敌人们做什么，但哪个敌人站在哪里不是输入。
- **只有 id，没有规则**。网络只通过含有一张牌的战斗认识它。训练从未有过的 id 什么也没学到，不管它做什么。
- **没有策略**。网络给状态估值；它不说该打哪个动作。由搜索来选。
