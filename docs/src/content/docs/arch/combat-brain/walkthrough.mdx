export const v = (x) => '[' + x.join(', ') + ', …]';
export const pct = (x) => (100 * x).toFixed(2) + ' %';

本页取一个真实的状态，手工走过战斗网络，用的是网络为它算出的数字。设计见[战斗网络](/arch/combat-brain/network/)；这里每一步展示那个设计对一场战斗做了什么。向量只显示前四个数。

这个状态是一个回合开始，来自文件自带的留出测试状态（`weights/all/c9-1.json`，`tests[9]`）。加载网络时会核对它给这个状态的输出正是这些（[战斗网络 §9](/arch/combat-brain/network/#sec-9)）。这些数字来自 `docs/scripts/combat-walk.py`，如果它的各层算不出文件里的输出，脚本就会停下。

## 1. 屏幕显示什么

铁甲战士，进阶 {walk.state.ascension}，在第二幕的普通战斗**外骨骼虫**（<code>{walk.state.encounter}</code>）里，第 {walk.state.round} 回合开始时。

- **生命值**：{walk.state.hp} / {walk.state.max_hp}，格挡 {walk.state.block}
- **能量**：{walk.state.energy}（最大 {walk.state.max_energy}）
- **金币**：{walk.state.gold}
- **能力**：杂耍 {walk.state.powers[0].amount}（一回合内打出的第三张攻击牌会把它自己的一张复制品加入手牌）
- **手牌**：{walk.state.piles.hand.join(', ')}
- **抽牌堆**：{walk.state.piles.draw.join(', ')}
- **弃牌堆**：{walk.state.piles.discard.join(', ')}
- **消耗堆**：空
- **遗物**：{walk.state.relics.map((r) => r.id).join(', ')}
- **药水**：{walk.tokens.potions[0]}，两个栏位为空
- **充能球**：没有，{walk.state.orb_slots} 个栏位

三个敌人，每个都有难以杀灭 {walk.state.enemies[0].powers[0].amount}：任何一击对它造成的伤害都不超过 9 点。

| 敌人 | 生命值 | 能力 | 现在显示 |
|---|---|---|---|
| 外骨骼虫 | {walk.state.enemies[0].hp} / {walk.state.enemies[0].max_hp} | 难以杀灭 {walk.state.enemies[0].powers[0].amount} | 一次 {walk.state.enemies[0].intents[0].damage} 点的攻击 |
| 外骨骼虫 | {walk.state.enemies[1].hp} / {walk.state.enemies[1].max_hp} | 难以杀灭 {walk.state.enemies[1].powers[0].amount} | 一次增益 |

## 4. 一张牌，然后是牌堆

牌的向量是 `Net.encode`（`learn/combat/net.py:229-308`）的头几行。取手牌里的 **{walk.card.id}**。它在牌表里的表项是 {walk.card.entry}，升级次数 {walk.card.up}；费用 1 读作 {walk.card.cost}，伤害 6 读作 {walk.card.damage}。它的其他数值（格挡、算出的数、额外打出次数、星辰费用、积累的伤害）都是 0，也没有修饰，所以只剩下这些部分：

| 部分 | 向量 |
|---|---|
| 它的 id 的向量 $E[c]$ | <code>{v(walk.card.id_vector)}</code> |
| 它的升级方向 $U[c]$，乘以 {walk.card.up} | <code>{v(walk.card.up_vector)}</code> |
| 费用向量 $K$，乘以 {walk.card.cost} | <code>{v(walk.card.cost_vector)}</code> |
| 伤害向量 $D$，乘以 {walk.card.damage} | <code>{v(walk.card.damage_vector)}</code> |
| 它自己的伤害方向 $D_c[c]$，乘以 {walk.card.damage} | <code>{v(walk.card.card_damage_vector)}</code> |
| 手牌的向量 $P[l]$ | <code>{v(walk.card.pile_vector)}</code> |
| 它们的和 $x$ | <code>{v(walk.card.x)}</code> |

把第一个数加起来核对一下：0.228 + 0 + 0.151 − 0.023 + 0.001 − 0.141 = 0.216。伤害的两部分给第一个数加上 −0.022，而 id 给的是 0.228（[战斗网络 §3](/arch/combat-brain/network/#sec-3)）。

然后 $\varphi$ 把 $x$ 映射到 128 个数，<code>{v(walk.card.phi.first)}</code>，长度 {walk.card.phi.norm}。作为 ReLU 的输出，没有一个低于 0，128 个中有 {walk.card.phi.zeros} 个恰好为 0。

每张牌都经过同一个 $\varphi$，每个牌堆把它的牌加起来并缩放 1/8：

| 牌堆 | 牌数 | 前几个数 | 长度 | 为 0 的数 |
|---|---|---|---|---|
| 手牌 | {walk.piles[0].cards} | <code>{v(walk.piles[0].vector.first)}</code> | {walk.piles[0].vector.norm} | {walk.piles[0].vector.zeros} |
| 抽牌堆 | {walk.piles[1].cards} | <code>{v(walk.piles[1].vector.first)}</code> | {walk.piles[1].vector.norm} | {walk.piles[1].vector.zeros} |
| 弃牌堆 | {walk.piles[2].cards} | <code>{v(walk.piles[2].vector.first)}</code> | {walk.piles[2].vector.norm} | {walk.piles[2].vector.zeros} |
| 消耗堆 | {walk.piles[3].cards} | <code>{v(walk.piles[3].vector.first)}</code> | {walk.piles[3].vector.norm} | {walk.piles[3].vector.zeros} |

消耗堆是空的，而空牌堆恰好是零向量。这四个拼接成牌的 512 个数。

## 5. 能力

玩家有一个能力，杂耍，数值 1，缩放到 0.1。它的向量是它的 id 的向量加上 0.1 乘以它的数值方向。一层 64 → 128 映射它，只有一个能力时，能力之和就是这个输出：<code>{v(walk.powers.first)}</code>，长度 {walk.powers.norm}，128 个中有 {walk.powers.zeros} 个为 0。

## 6. 敌人

一个敌人拼接三部分，同一个 $\varphi$ 读每个敌人：

| | 外骨骼虫，{walk.state.enemies[0].hp} 点生命值 | 外骨骼虫，{walk.state.enemies[1].hp} 点生命值 | 外骨骼虫，{walk.state.enemies[2].hp} 点生命值 |
|---|---|---|---|
| id + 数值（64） | <code>{v(walk.enemies[0].numbers_vector)}</code> | <code>{v(walk.enemies[1].numbers_vector)}</code> | <code>{v(walk.enemies[2].numbers_vector)}</code> |
| 能力之和（128） | <code>{v(walk.enemies[0].powers_vector)}</code> | <code>{v(walk.enemies[1].powers_vector)}</code> | <code>{v(walk.enemies[2].powers_vector)}</code> |
| 槽 0，4 个槽之一（各 64） | <code>{v(walk.enemies[0].slot_vector)}</code> | <code>{v(walk.enemies[1].slot_vector)}</code> | <code>{v(walk.enemies[2].slot_vector)}</code> |
| 经过 $\varphi$（256）后：长度 | {walk.enemies[0].phi.norm} | {walk.enemies[1].phi.norm} | {walk.enemies[2].phi.norm} |
| 经过 $\varphi$ 后：为 0 的数 | {walk.enemies[0].phi.zeros} | {walk.enemies[1].phi.zeros} | {walk.enemies[2].phi.zeros} |

三个敌人在敌人表里的表项都是 {walk.enemies[0].entry}：同一个 id，靠它们的数值、能力和槽来区分。敌人的部分是对所有敌人求和：256 个数，长度 {walk.foes.norm}，其中 {walk.foes.zeros} 个为 0。

| 层 | 前几个数 | 长度 | 为 0 的数 |
|---|---|---|---|
| 1291 → 512 | <code>{v(walk.body[0].first)}</code> | {walk.body[0].norm} | {walk.body[0].zeros} |

## 10. 结局输出头：51 个 logit

一层线性给出 51 个原始的数。第一个是死亡的，{walk.head.death_logit}。单独一个 logit 没有意义：只有下一步的 softmax 比较它们，才让它们成为概率。

## 11. 掩码，然后是 softmax

生命值比例是 {walk.ended.share}。分桶 $[l, l + 0.025)$ 保持开启的条件是 $l < 0.839$ 且 $l + 0.025 > 0.839 - 1$。在这里：

- 下端：一场战斗回的血不能超过损失的生命值。{walk.state.max_hp} 中的 {walk.state.max_hp - walk.state.hp} 点生命值是比例 0.161，所以低于 {walk.head.open_from} 的 3 个分桶关闭。
- 上端：一场胜利不能失去全部持有的生命值，所以从 {walk.head.open_to} 起的分桶关闭。

这样 **50 个分桶中有 {walk.head.open} 个开启**。其他分桶的 logit 是 $-10^4$（`Net.reachable`，`learn/combat/net.py:221-227`），softmax 给它们恰好 0。

对其余的做 softmax，得到概率。死亡是 {walk.head.death}。最可能的分桶如下，比例低于 0 表示回复的生命值：

| 还要失去的最大生命值比例 | 折合生命值 | 概率 |
|---|---|---|
| {walk.head.tops[0].low} 到 {walk.head.tops[0].high} | 回复 4.7 到 7.0 | {pct(walk.head.tops[0].chance)} |
| {walk.head.tops[1].low} 到 {walk.head.tops[1].high} | 回复 2.3 到 4.7 | {pct(walk.head.tops[1].chance)} |
| {walk.head.tops[2].low} 到 {walk.head.tops[2].high} | 回复 7.0 到 9.3 | {pct(walk.head.tops[2].chance)} |
| {walk.head.tops[3].low} 到 {walk.head.tops[3].high} | 回复 0 到 2.3 | {pct(walk.head.tops[3].chance)} |

网络预计这场战斗会赢，而且结束时的生命值比现在多：将近三分之二的概率落在回复 4.7 到 7.0 点生命值上。燃烧之血在每场赢下的战斗之后回复 6 点生命值，比例 0.065，正落在那个分桶里。网络在它的输入里读到了遗物，不过这里没有什么能说明哪些输入对它影响最大。

## 12. 药水输出头

同样的 512 个数经过第二个线性层，512 → {walk.potion.outputs}，药水表的每一项一个输出。瓶中精灵是第 {walk.potion.entry} 项。它的 logit 是 {walk.potion.logit}，sigmoid 把它变成 **{walk.potion.chance}**（取到四位小数），约为百万分之 2.5：网络预计赢下之后这瓶药水还在。玩家从不喝这瓶药水；玩家将要死去时，游戏会自己用掉它，让玩家带着最大生命值的 30 % 复活。

其他 {walk.potion.outputs - 1} 个输出会算出来，但不读。这里最大的是 {walk.potion.most_likely[0].id} 和 {walk.potion.most_likely[1].id}，分别是 {walk.potion.most_likely[0].chance} 和 {walk.potion.most_likely[1].chance}：这个状态两者都没有，所以它们没有意义，也不训练任何东西。没有哪次训练见过的药水，比如 {walk.potion.unheld}，是 `<unk>` 那一行，显示它的概率 {walk.potion.unk}。

## 13. 搜索读到的数

搜索不读这 51 个概率，也不读药水的概率：它读一个数，即叶子估值（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）。`CombatNet.Outcome`（`src/Sts2Ai.Brain/Combat/CombatNet.cs`）这样得出它：网络仍允许的每个结局，都按它会留下的那局游戏由 V（宏观大脑赢下这一局的概率）定价：

$$
\text{value} = \sum_{k=1}^{50} p_k \sum_{S \subseteq H} \Big(\prod_{i \in S} (1 - u_i) \prod_{i \in H \setminus S} u_i\Big)\, V\big(\text{生命值为 } h_k \text{、持有 } S \text{ 的这一局}\big)
$$

这里 $H$ 是持有的药水，$u_i$ 是药水输出头给出的药水 $i$ 赢下后没有了的概率，$h_k$ 是分桶 $k$ 之后玩家持有的生命值：现在的生命值比例减去分桶的中点，乘以最大生命值，限制在 1 到最大生命值之间。

对这个状态，$H$ 只有瓶中精灵，所以每个开启的分桶给出两局：带着药水的一局，概率为 $1 - u$，只差约百万分之 2.5（[§12](#sec-12)），以及没有药水的一局。{walk.head.open} 个开启的分桶给 V 带来 {2 * walk.head.open} 局，而概率恰好为 0 的关闭分桶一局也不带来。每一局的其余部分，是这场战斗周围的这一局当前的样子：牌组、遗物、最大生命值、金币、前面的地图。文件里的测试状态只有一个回合开始，没有这一局，所以本页给不出 V 的数，也给不出估值；同一次调用在估值旁边返回的东西不需要它们（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）：

| | 数 |
|---|---|
| 胜率，$1 - p_0$ | {walk.ended.win} |
| 赢下时持有的生命值，在各获胜分桶上取平均 | {walk.ended.hp_at_win} / {walk.state.max_hp} |
| 预计留下的药水，$\sum (1 - u)$ | {walk.ended.kept} |

所以 V 被问到的，是以 93 点中约 83 点生命值离开这场战斗、仍持有药水的那些局，估值接近那一局的 V。这是否比另一个状态的结局更值，要由 V 根据它从这一局读到的一切来说。

## 14. 搜索看到什么

搜索比较状态。每次只改一样东西，再跑一遍网络：

| 状态 | 生命值比例 | 死亡的概率 | 最可能的分桶 | 赢下时持有的生命值 |
|---|---|---|---|---|
| 原样 | {walk.ended.share} | {pct(walk.head.death)} | {walk.head.tops[0].low} 到 {walk.head.tops[0].high}，{pct(walk.head.tops[0].chance)} | {walk.ended.hp_at_win} |
| 少 {walk.lost_hp} 点生命值 | {walk.siblings.less_hp.share} | {pct(walk.siblings.less_hp.death)} | {walk.siblings.less_hp.tops[0].low} 到 {walk.siblings.less_hp.tops[0].high}，{pct(walk.siblings.less_hp.tops[0].chance)} | {walk.siblings.less_hp.hp_at_win} |
| 药水没有了 | {walk.siblings.no_potion.share} | {pct(walk.siblings.no_potion.death)} | {walk.siblings.no_potion.tops[0].low} 到 {walk.siblings.no_potion.tops[0].high}，{pct(walk.siblings.no_potion.tops[0].chance)} | {walk.siblings.no_potion.hp_at_win} |

少 {walk.lost_hp} 点生命值时，网络的回答几乎不变：最可能的分桶相同，概率也差不多。分桶是从现在持有的生命值里还要失去的比例，所以赢下时持有的生命值大约下降被拿走的那么多，从 {walk.ended.hp_at_win} 降到 {walk.siblings.less_hp.hp_at_win}：持有的生命值被完整计入（[战斗网络 §7](/arch/combat-brain/network/#sec-7)），V 给这个状态的每个结局定价时，都少了约 10 点生命值。

没有药水时，结局略有变动，最可能的分桶的概率从 {pct(walk.head.tops[0].chance)} 变成 {pct(walk.siblings.no_potion.tops[0].chance)}，赢下时持有的生命值几乎不变。瓶中精灵只在死亡时起作用，而网络在这里并不预计会死；这里没有什么能说明结局为什么会变。于是两个状态之间的差别主要来自 V：生命值相同，一局持有药水，一局没有。一瓶药水值多少，不是为这场战斗设定的一个数，而是 V 认为在这一局里持有它值多少。

## 15. 两个更难的状态

同一文件里的另外两个状态展示了这个状态展示不了的东西，即一场满生命值、赢下大约要花掉一半最大生命值的 Boss 战，以及一个低到关闭大部分分桶的生命值：

| | {walk.others.danger.encounter} | {walk.others.mask.encounter} |
|---|---|---|
| 房间、回合 | {walk.others.danger.room}，第 {walk.others.danger.round} 回合 | {walk.others.mask.room}，第 {walk.others.mask.round} 回合 |
| 生命值 | {walk.others.danger.hp} / {walk.others.danger.max_hp} | {walk.others.mask.hp} / {walk.others.mask.max_hp} |
| 开启的分桶 | {walk.others.danger.open}（{walk.others.danger.open_from} 到 {walk.others.danger.open_to}） | {walk.others.mask.open}（{walk.others.mask.open_from} 到 {walk.others.mask.open_to}） |
| 死亡的概率 | {pct(walk.others.danger.death)} | {pct(walk.others.mask.death)} |
| 最可能的分桶 | {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，{pct(walk.others.danger.tops[0].chance)} | {walk.others.mask.tops[0].low} 到 {walk.others.mask.tops[0].high}，{pct(walk.others.mask.tops[0].chance)} |
| 赢下时持有的生命值 | {walk.others.danger.hp_at_win} | {walk.others.mask.hp_at_win} |

在对同族小队的 Boss 战里，网络预计一场胜利要花掉最大生命值的 0.55，即 {walk.others.danger.max_hp} 点中的约 53 点，分散在许多分桶上，没有一个超过 6 %。V 按各自的生命值给这 {walk.others.danger.open} 个结局分别定价，所以估值分散在从满生命值到只剩几点生命值的各局上，而死亡的概率以 0 的价格拿走它那一份。对异蛙寄生虫时，在 {walk.others.mask.hp} 点生命值下只有 {walk.others.mask.open} 个分桶开启，所以任何概率都不会落在失去的生命值超过玩家持有的胜利上，而死亡拿走了将近三分之一的概率。

## 16. 标签

到这里网络一直在预测。在训练中，这个状态还有一个答案，来自它的战斗真实的结局。文件没有保存那个结局，所以取一个作说明：**假设这场战斗以 93 点生命值中的 {walk.label.end_hp} 点赢下，药水还在**。

- **结局的类别**。从这个状态失去的比例是 78/93 − {walk.label.end_hp}/93 = {walk.label.lost}，落在 {walk.label.low} 到 {walk.label.high} 的分桶里：类别 {walk.label.class}。那场战斗的每个回合开始都会按自己的生命值得到自己的类别。
- **药水的标签**。它在战斗后的第一个整局观测里还在，所以标签是 0。
- **损失**。类别 {walk.label.class} 的概率是 {walk.label.chance}，所以结局的交叉熵是 {walk.label.ending_loss}。药水的是 {walk.label.potion_loss}。这个样本的损失是两者之和，一步梯度会把那个分桶的概率往上推。

像结局这样大的损失就是意外的样子：在这个假设的结局下，网络对生命值错得很厉害，对药水则没有错。在一整份对局清单上标签怎样生成，见[训练战斗网络 §3](/arch/learning/combat-net/#sec-3)。
