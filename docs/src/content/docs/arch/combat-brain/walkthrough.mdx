本页取一个真实的状态，手工走过战斗网络，用的是网络为它算出的数字。设计见[战斗网络](/arch/combat-brain/network/)；这里每一步展示那个设计对一场战斗做了什么。向量只显示前四个数。

这个状态是一个回合开始，来自文件自带的留出测试状态（`weights/all/c9-0.json`，`tests[10]`）。加载网络时会核对它给这个状态的输出正是这些（[战斗网络 §9](/arch/combat-brain/network/#sec-9)）。这些数字来自 `docs/scripts/combat-walk.py`，如果它的各层算不出文件里的输出，脚本就会停下。

## 1. 屏幕显示什么

静默猎手，进阶 {walk.state.ascension}，在第三幕的精英战**机甲骑士**（<code>{walk.state.encounter}</code>）里，第 {walk.state.round} 回合开始时。

- **生命值**：{walk.state.hp} / {walk.state.max_hp}，格挡 {walk.state.block}
- **能量**：{walk.state.energy}（最大 {walk.state.max_energy}）
- **金币**：{walk.state.gold}
- **能力**：荆棘 {walk.state.powers[0].amount}，敏捷 {walk.state.powers[1].amount}，毒雾 {walk.state.powers[2].amount}
- **手牌**：{walk.state.piles.hand.join(', ')}
- **抽牌堆**：{walk.state.piles.draw.join(', ')}
- **弃牌堆**：{walk.state.piles.discard.join(', ')}
- **消耗堆**：{walk.state.piles.exhaust.join(', ')}
- **遗物**：{walk.state.relics.map((r) => r.id).join(', ')}
- **药水**：{walk.tokens.potions[0]}，一个栏位为空

## 4. 一张牌，然后是牌堆

牌的向量是 `Net.encode`（`learn/combat/net.py:211-282`）的头几行。取弃牌堆里的 **{walk.card.id}**。它在牌表里的表项是 {walk.card.entry}，升级次数 {walk.card.up}；费用 1 读作 {walk.card.cost}，伤害 6 读作 {walk.card.damage}。

| 部分 | 向量 |
|---|---|
| 它的 id 的向量 $E[c]$ | <code>{v(walk.card.id_vector)}</code> |
| 它的升级方向 $U[c]$，乘以 {walk.card.up} | <code>{v(walk.card.up_vector)}</code> |
| 费用向量 $K$，乘以 {walk.card.cost} | <code>{v(walk.card.cost_vector)}</code> |
| 伤害向量 $D$，乘以 {walk.card.damage} | <code>{v(walk.card.damage_vector)}</code> |
| 弃牌堆的向量 $P[l]$ | <code>{v(walk.card.pile_vector)}</code> |
| 它们的和 $x$ | <code>{v(walk.card.x)}</code> |

把第一个数加起来核对一下：0.060 + 0 + 0.144 − 0.007 + 0.192 = 0.389。这个文件里的 $D$ 很小，所以伤害加上的不多（[战斗网络 §8](/arch/combat-brain/network/#sec-8)）。

然后 $\varphi$ 把 $x$ 映射到 64 个数，<code>{v(walk.card.phi.first)}</code>。作为 ReLU 的输出，没有一个低于 0，64 个中有 {walk.card.phi.zeros} 个恰好为 0。

每张牌都经过同一个 $\varphi$，每个牌堆把它的牌加起来并缩放 1/8：

| 牌堆 | 牌数 | 前几个数 | 长度 | 为 0 的数 |
|---|---|---|---|---|
| 手牌 | {walk.piles[0].cards} | <code>{v(walk.piles[0].vector.first)}</code> | {walk.piles[0].vector.norm} | {walk.piles[0].vector.zeros} |
| 抽牌堆 | {walk.piles[1].cards} | <code>{v(walk.piles[1].vector.first)}</code> | {walk.piles[1].vector.norm} | {walk.piles[1].vector.zeros} |
| 弃牌堆 | {walk.piles[2].cards} | <code>{v(walk.piles[2].vector.first)}</code> | {walk.piles[2].vector.norm} | {walk.piles[2].vector.zeros} |
| 消耗堆 | {walk.piles[3].cards} | <code>{v(walk.piles[3].vector.first)}</code> | {walk.piles[3].vector.norm} | {walk.piles[3].vector.zeros} |

空牌堆恰好是零向量。这四个拼接成牌的 256 个数。

## 5. 能力

玩家有三个能力，荆棘、敏捷和毒雾，数值是 3、1 和 3，缩放到 0.3、0.1 和 0.3。每个能力的向量是它的 id 的向量加上缩放后的数值乘以它的数值方向。一层 32 → 64 分别映射它们，三个输出之和是 <code>{v(walk.powers.first)}</code>，64 个中有 {walk.powers.zeros} 个为 0。

## 6. 敌人

一个敌人拼接三部分，同一个 $\varphi$ 读每个敌人：

| | 机甲骑士 |
|---|---|
| id + 数值（32） | <code>{v(walk.enemies[0].numbers_vector)}</code> |
| 能力之和（64） | <code>{v(walk.enemies[0].powers_vector)}</code> |
| 槽 0，4 个槽之一（各 32） | <code>{v(walk.enemies[0].slot_vector)}</code> |
| 经过 $\varphi$（128）后：长度 | {walk.enemies[0].phi.norm} |
| 经过 $\varphi$ 后：为 0 的数 | {walk.enemies[0].phi.zeros} |

它在敌人表里的表项是 {walk.enemies[0].entry}。敌人的部分是对所有敌人求和。只有一个敌人时就是这个向量：128 个数，长度 {walk.foes.norm}，其中 {walk.foes.zeros} 个为 0。

## 9. 主体

两层，一切第一次相遇：

| 层 | 前几个数 | 长度 | 为 0 的数 |
|---|---|---|---|
| 651 → 256 | <code>{v(walk.body[0].first)}</code> | {walk.body[0].norm} | {walk.body[0].zeros} |
| 256 → 256 | <code>{v(walk.body[1].first)}</code> | {walk.body[1].norm} | {walk.body[1].zeros} |

对这个状态，256 个数大多是 0；不为 0 的 {256 - walk.body[1].zeros} 个承载了输出头要读的一切。

## 10. 结局输出头：51 个 logit

一层线性给出 51 个原始的数。第一个是死亡的，{walk.head.death_logit}。单独一个 logit 没有意义：只有下一步的 softmax 比较它们，才让它们成为概率。

## 11. 掩码，然后是 softmax

生命值比例是 {walk.value.share}。分桶 $[l, l + 0.025)$ 保持开启的条件是 $l < 0.506$ 且 $l + 0.025 > 0.506 - 1$。在这里：

- 下端：一场战斗回的血不能超过损失的生命值。{walk.state.max_hp} 中的 {walk.state.max_hp - walk.state.hp} 点生命值是比例 0.494，超过最低分桶的 {walk.head.open_from}，所以这里没有分桶关闭。
- 上端：一场胜利不能失去全部持有的生命值，所以从 {walk.head.open_to} 起的分桶关闭。

这样 **50 个分桶中有 {walk.head.open} 个开启**。其他分桶的 logit 是 $-10^4$（`Net.reachable`，`learn/combat/net.py:203-209`），softmax 给它们恰好 0。

对其余的做 softmax，得到概率。死亡是 {walk.head.death}。最可能的分桶：

| 还要失去的最大生命值比例 | 折合生命值 | 概率 |
|---|---|---|
| {walk.head.tops[0].low} 到 {walk.head.tops[0].high} | 0 到 2.1 | {pct(walk.head.tops[0].chance)} |
| {walk.head.tops[1].low} 到 {walk.head.tops[1].high} | 2.1 到 4.2 | {pct(walk.head.tops[1].chance)} |
| {walk.head.tops[2].low} 到 {walk.head.tops[2].high} | 4.2 到 6.2 | {pct(walk.head.tops[2].chance)} |
| {walk.head.tops[3].low} 到 {walk.head.tops[3].high} | 6.2 到 8.3 | {pct(walk.head.tops[3].chance)} |

网络预计这场战斗会赢，而且代价不大：超过一半的概率落在最多失去 2 点生命值的分桶上。敌人有 136 点生命值，带着 25 层中毒，玩家的毒雾每回合还会增加更多；网络读了这些数，不过这里没有什么能说明哪些输入对它影响最大。

## 12. 药水输出头

同样的 256 个数经过第二个线性层，256 → {walk.potion.outputs}，药水表的每一项一个输出。药水形状的石头是第 {walk.potion.entry} 项。它的 logit 是 {walk.potion.logit}，sigmoid 把它变成 **{walk.potion.chance}**：网络预计赢下之后这瓶药水还在。

其他 {walk.potion.outputs - 1} 个输出会算出来，但不读。这里最大的是 {walk.potion.most_likely[0].id} 和 {walk.potion.most_likely[1].id}，分别是 {walk.potion.most_likely[0].chance} 和 {walk.potion.most_likely[1].chance}：这个状态两者都没有，所以它们没有意义，也不训练任何东西。没有哪次训练见过的药水，比如 {walk.potion.unheld}，是 `<unk>` 那一行，显示它的概率 {walk.potion.unk}。

## 13. 搜索读到的数

`CombatNet.Value`（`src/Sts2Ai.Brain/Combat/CombatNet.cs:74-86`）给 51 个概率定价（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）：

$$
\text{value} = \sum_{k=1}^{50} p_k \big(0.2 + 0.6\,(s - m_k)\big) + (1 - p_0)\times 0.02 \sum_{\text{held}} (1 - u_{\text{id}})
$$

| 项 | 数 |
|---|---|
| 结局，对开启的分桶求和 | {walk.value.win_term} |
| 预计留下的药水，$\sum (1 - u)$ | {walk.value.kept} |
| 它们的项，$(1 - p_0) \times 0.02 \times$ 上面的数 | {walk.value.potion_term} |
| **估值** | **{walk.value.value}** |

规划器对这个状态的**上界**是一场不失去生命值和药水的胜利：0.2 + 0.6 × {walk.value.share} + 0.02 = {walk.value.bound}。估值比它低 0.043，因为网络预计会失去约 5.5 点生命值，这瓶药水也有不大的机会没了。

## 14. 搜索看到什么

搜索比较状态。每次只改一样东西，再跑一遍网络：

| 状态 | 生命值比例 | 结局 | 药水 | 估值 |
|---|---|---|---|---|
| 原样 | {walk.value.share} | {walk.value.win_term} | {walk.value.potion_term} | {walk.value.value} |
| 少 {walk.lost_hp} 点生命值 | {walk.siblings.less_hp.share} | {walk.siblings.less_hp.win_term} | {walk.siblings.less_hp.potion_term} | {walk.siblings.less_hp.value} |
| 药水没有了 | {walk.siblings.no_potion.share} | {walk.siblings.no_potion.win_term} | {walk.siblings.no_potion.potion_term} | {walk.siblings.no_potion.value} |

{walk.lost_hp} 点生命值是 83 的比例 0.120，乘 0.6 是 0.072，而估值下降 0.073。持有的生命值被完整计入（[战斗网络 §7](/arch/combat-brain/network/#sec-7)），网络的回答几乎不变：最可能的分桶仍是 {walk.siblings.less_hp.tops[0].low} 到 {walk.siblings.less_hp.tops[0].high}，死亡为 {pct(walk.siblings.less_hp.death)}。

药水的统一价在这里是 {walk.value.potion_term}。可是没有它，估值降到 {walk.siblings.no_potion.value}，下降 0.038：死亡从 {pct(walk.value.death)} 变成 {pct(walk.siblings.no_potion.death)}，最可能的分桶的概率从 {pct(walk.head.tops[0].chance)} 变成 {pct(walk.siblings.no_potion.tops[0].chance)}。网络是从持有它的对局的结局里学到这一点的，尽管它预计这瓶药水会留着；这里没有什么能说明原因。

## 15. 两个更难的状态

同一文件里的另外两个状态展示了这个状态展示不了的东西，即一场输面大于赢面的 Boss 战，以及一个低到关闭大部分分桶的生命值：

| | {walk.others.danger.encounter} | {walk.others.mask.encounter} |
|---|---|---|
| 房间、回合 | {walk.others.danger.room}，第 {walk.others.danger.round} 回合 | {walk.others.mask.room}，第 {walk.others.mask.round} 回合 |
| 生命值 | {walk.others.danger.hp} / {walk.others.danger.max_hp} | {walk.others.mask.hp} / {walk.others.mask.max_hp} |
| 开启的分桶 | {walk.others.danger.open}（{walk.others.danger.open_from} 到 {walk.others.danger.open_to}） | {walk.others.mask.open}（{walk.others.mask.open_from} 到 {walk.others.mask.open_to}） |
| 死亡的概率 | {pct(walk.others.danger.death)} | {pct(walk.others.mask.death)} |
| 最可能的分桶 | {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，{pct(walk.others.danger.tops[0].chance)} | {walk.others.mask.tops[0].low} 到 {walk.others.mask.tops[0].high}，{pct(walk.others.mask.tops[0].chance)} |
| 估值 | {walk.others.danger.value} | {walk.others.mask.value} |
| 上界 | {walk.others.danger.bound} | {walk.others.mask.bound} |

在 Boss 战里，估值远低于上界：死亡的概率拿走了估值的那一部分，胜利又分散在许多分桶上。在 {walk.others.mask.hp} 点生命值时只有 {walk.others.mask.open} 个分桶开启，所以任何概率都不会落在失去的生命值超过玩家持有的胜利上。

## 16. 标签

到这里网络一直在预测。在训练中，这个状态还有一个答案，来自它的战斗真实的结局。文件没有保存那个结局，所以取一个作说明：**假设这场战斗以 83 点生命值中的 {walk.label.end_hp} 点赢下，药水还在**。

- **结局的类别**。从这个状态失去的比例是 42/83 − {walk.label.end_hp}/83 = {walk.label.lost}，落在 {walk.label.low} 到 {walk.label.high} 的分桶里：类别 {walk.label.class}。那场战斗的每个回合开始都会按自己的生命值得到自己的类别。
- **药水的标签**。它在战斗后的第一个整局观测里还在，所以标签是 0。
- **损失**。类别 {walk.label.class} 的概率是 {walk.label.chance}，所以结局的交叉熵是 {walk.label.ending_loss}。药水的是 {walk.label.potion_loss}。这个样本的损失是两者之和，一步梯度会把那个分桶的概率往上推。

像结局这样大的损失就是意外的样子：在这个假设的结局下，网络对生命值错得很厉害，对药水则没有错。在一整份对局清单上标签怎样生成，见[训练战斗网络 §3](/arch/learning/combat-net/#sec-3)。
