export const v = (x) => '[' + x.join(', ') + ', …]';
export const pct = (x) => (100 * x).toFixed(2) + ' %';

本页取一个真实的状态，手工走过战斗网络，用的是网络为它算出的数字。设计见[战斗网络](/arch/combat-brain/network/)；这里每一步展示那个设计对一场战斗做了什么。向量只显示前四个数。

这个状态是一个回合开始，来自冠军的战斗网络文件里的留出测试状态（`weights/all/c9-2.json`，`tests[11]`）。加载网络时会核对它给这个状态的输出正是这些（[战斗网络 §9](/arch/combat-brain/network/#sec-9)）。这些数字来自 `docs/scripts/combat-walk.py`，如果它的各层算不出文件里的输出，脚本就会停下。

## 1. 屏幕显示什么

储君，进阶 {walk.state.ascension}，在第三幕的普通战斗**史莱姆狂战士**（<code>{walk.state.encounter}</code>）里，第 {walk.state.round} 回合开始时。

- **生命值**：{walk.state.hp} / {walk.state.max_hp}，格挡 {walk.state.block}
- **能量**：{walk.state.energy}（最大 {walk.state.max_energy}）
- **星辰**：{walk.state.stars}
- **金币**：{walk.state.gold}
- **能力**：荆棘 {walk.state.powers[0].amount}（每有一击打中玩家，攻击者受到 3 点伤害），来自战斗开始时的铜质鳞片
- **手牌**：{walk.state.piles.hand.join(', ')}
- **抽牌堆**：{walk.state.piles.draw.join(', ')}
- **弃牌堆**：{walk.state.piles.discard.join(', ')}
- **消耗堆**：空
- **遗物**：{walk.state.relics.map((r) => r.id).join(', ')}
- **药水**：{walk.tokens.potions[0]}，两个栏位为空
- **充能球**：没有，{walk.state.orb_slots} 个栏位

一个敌人，没有能力：

| 敌人 | 生命值 | 能力 | 现在显示 |
|---|---|---|---|
| 史莱姆狂战士 | {walk.state.enemies[0].hp} / {walk.state.enemies[0].max_hp} | 无 | {walk.state.enemies[0].intents[0].hits} 次 {walk.state.enemies[0].intents[0].damage} 点的攻击 |

上一回合它把 10 张黏液放进了弃牌堆；这一回合它攻击。

搜索问的问题是：如果停在这里，这个状态值多少？

## 4. 一张牌，然后是牌堆

牌的向量是 `Net.encode`（`learn/combat/net.py:231-310`）的头几行。取抽牌堆里的 **{walk.card.id}**。它在牌表里的表项是 {walk.card.entry}，升级次数 {walk.card.up}；费用 1 读作 {walk.card.cost}，伤害 10 读作 {walk.card.damage}。它的其他数值（格挡、算出的数、额外打出次数、星辰费用、积累的伤害）都是 0，也没有修饰，所以只剩下这些部分：

| 部分 | 向量 |
|---|---|
| 它的 id 的向量 $E[c]$ | <code>{v(walk.card.id_vector)}</code> |
| 它的升级方向 $U[c]$，乘以 {walk.card.up} | <code>{v(walk.card.up_vector)}</code> |
| 费用向量 $K$，乘以 {walk.card.cost} | <code>{v(walk.card.cost_vector)}</code> |
| 伤害向量 $D$，乘以 {walk.card.damage} | <code>{v(walk.card.damage_vector)}</code> |
| 它自己的伤害方向 $D_c[c]$，乘以 {walk.card.damage} | <code>{v(walk.card.card_damage_vector)}</code> |
| 抽牌堆的向量 $P[l]$ | <code>{v(walk.card.pile_vector)}</code> |
| 它们的和 $x$ | <code>{v(walk.card.x)}</code> |

把第一个数加起来核对一下：−0.097 + 0 + 0.158 − 0.049 − 0.082 + 0.083 = 0.013。伤害的两部分给第一个数加上 −0.131，比 id 给的 −0.097 分量更大（[战斗网络 §3](/arch/combat-brain/network/#sec-3)）。

然后 $\varphi$ 把 $x$ 映射到 128 个数，<code>{v(walk.card.phi.first)}</code>，长度 {walk.card.phi.norm}。作为 ReLU 的输出，没有一个低于 0，128 个中有 {walk.card.phi.zeros} 个恰好为 0。

每张牌都经过同一个 $\varphi$，每个牌堆把它的牌加起来并缩放 1/8：

| 牌堆 | 牌数 | 前几个数 | 长度 | 为 0 的数 |
|---|---|---|---|---|
| 手牌 | {walk.piles[0].cards} | <code>{v(walk.piles[0].vector.first)}</code> | {walk.piles[0].vector.norm} | {walk.piles[0].vector.zeros} |
| 抽牌堆 | {walk.piles[1].cards} | <code>{v(walk.piles[1].vector.first)}</code> | {walk.piles[1].vector.norm} | {walk.piles[1].vector.zeros} |
| 弃牌堆 | {walk.piles[2].cards} | <code>{v(walk.piles[2].vector.first)}</code> | {walk.piles[2].vector.norm} | {walk.piles[2].vector.zeros} |
| 消耗堆 | {walk.piles[3].cards} | <code>{v(walk.piles[3].vector.first)}</code> | {walk.piles[3].vector.norm} | {walk.piles[3].vector.zeros} |

消耗堆是空的，而空牌堆恰好是零向量。这四个拼接成牌的 512 个数。

## 5. 能力

玩家有一个能力，荆棘，数值 3，缩放到 0.3。它的向量是它的 id 的向量加上 0.3 乘以它的数值方向。一层 64 → 128 映射它，只有一个能力时，能力之和就是这个输出：<code>{v(walk.powers.first)}</code>，长度 {walk.powers.norm}，128 个中有 {walk.powers.zeros} 个为 0。

## 6. 敌人

一个敌人拼接三部分，同一个 $\varphi$ 读每个敌人：

| | 史莱姆狂战士，{walk.state.enemies[0].hp} 点生命值 |
|---|---|
| id + 数值（64） | <code>{v(walk.enemies[0].numbers_vector)}</code> |
| 能力之和（128） | <code>{v(walk.enemies[0].powers_vector)}</code> |
| 槽 0，4 个槽之一（各 64） | <code>{v(walk.enemies[0].slot_vector)}</code> |
| 经过 $\varphi$（256）后：长度 | {walk.enemies[0].phi.norm} |
| 经过 $\varphi$ 后：为 0 的数 | {walk.enemies[0].phi.zeros} |

史莱姆狂战士在敌人表里的表项是 {walk.enemies[0].entry}，它没有能力，所以能力之和是零向量。敌人的部分是对所有敌人求和，这里只有这一个：256 个数，长度 {walk.foes.norm}，其中 {walk.foes.zeros} 个为 0。

## 10. 结局输出头：51 个 logit

一层线性给出 51 个原始的数。第一个是死亡的，{walk.head.death_logit}。单独一个 logit 没有意义：只有下一步的 softmax 比较它们，才让它们成为概率。

## 11. 掩码，然后是 softmax

生命值比例是 {walk.ended.share}。分桶 $[l, l + 0.025)$ 保持开启的条件是 $l < 0.521$ 且 $l + 0.025 > 0.521 - 1$。在这里：

- 下端：一场战斗回的血不能超过损失的生命值。{walk.state.max_hp} 中的 {walk.state.max_hp - walk.state.hp} 点生命值是比例 0.479，超过最低的分桶回复的 0.25，所以下端没有分桶关闭：开启的分桶从 {walk.head.open_from} 开始。
- 上端：一场胜利不能失去全部持有的生命值，所以从 {walk.head.open_to} 起的分桶关闭。

这样 **50 个分桶中有 {walk.head.open} 个开启**。其他分桶的 logit 是 $-10^4$（`Net.reachable`，`learn/combat/net.py:223-229`），softmax 给它们恰好 0。

对其余的做 softmax，得到概率。死亡是 {walk.head.death}。最可能的分桶如下：

| 还要失去的最大生命值比例 | 失去的生命值 | 概率 |
|---|---|---|
| {walk.head.tops[0].low} 到 {walk.head.tops[0].high} | {(walk.head.tops[0].low * walk.state.max_hp).toFixed(1)} 到 {(walk.head.tops[0].high * walk.state.max_hp).toFixed(1)} | {pct(walk.head.tops[0].chance)} |
| {walk.head.tops[1].low} 到 {walk.head.tops[1].high} | {(walk.head.tops[1].low * walk.state.max_hp).toFixed(1)} 到 {(walk.head.tops[1].high * walk.state.max_hp).toFixed(1)} | {pct(walk.head.tops[1].chance)} |
| {walk.head.tops[2].low} 到 {walk.head.tops[2].high} | {(walk.head.tops[2].low * walk.state.max_hp).toFixed(1)} 到 {(walk.head.tops[2].high * walk.state.max_hp).toFixed(1)} | {pct(walk.head.tops[2].chance)} |
| {walk.head.tops[3].low} 到 {walk.head.tops[3].high} | {(walk.head.tops[3].low * walk.state.max_hp).toFixed(1)} 到 {(walk.head.tops[3].high * walk.state.max_hp).toFixed(1)} | {pct(walk.head.tops[3].chance)} |

网络预计这场战斗会以不大的代价赢下：{pct(walk.head.chances.slice(11, 21).reduce((a, b) => a + b, 0))} 的概率落在分桶 11 到 20 上，即失去最大生命值的 0 到 0.25（最多 18 点），落在回复上的只有 {pct(walk.head.chances.slice(1, 11).reduce((a, b) => a + b, 0))}。单个分桶里最可能的是失去不到 2 点生命值，但没有一个分桶超过 14 %。网络在它的输入里读到了荆棘和遗物，不过这里没有什么能说明哪些输入对它影响最大。

## 12. 药水输出头

同样的 512 个数经过第二个线性层，512 → {walk.potion.groups} × {walk.potion.outputs}：相邻的每 {walk.potion.per_group} 个分桶为一组，共 {walk.potion.groups} 组，每组药水表的每一项一个输出（[战斗网络 §7](/arch/combat-brain/network/#sec-7)）。最可能的胜利，即还要失去 {walk.head.tops[0].low} 到 {walk.head.tops[0].high} 的比例，是分桶 {walk.head.tops[0].bucket}，在第 {walk.potion.group + 1} 组，即分桶 {walk.potion.group * walk.potion.per_group + 1} 到 {(walk.potion.group + 1) * walk.potion.per_group}；这里的概率都是这一组的。瓶中精灵是第 {walk.potion.entry} 项。它的 logit 是 {walk.potion.logit}，sigmoid 把它变成 **{walk.potion.chance}**：网络预计大多数胜利之后这瓶药水还在，大约每十一次胜利有一次没了。在这个文件里，五组的权重相同（[战斗网络 §8](/arch/combat-brain/network/#sec-8)），所以每一组给它的概率都一样。玩家从不喝这瓶药水；玩家将要死去时，游戏会自己用掉它，让玩家带着最大生命值的 30 % 复活。

每组的 {walk.potion.outputs} 个输出里只读持有的那瓶药水的；其他 {walk.potion.outputs - 1} 个会算出来，但不读。这里其中最大的是 {walk.potion.most_likely[0].id} 和 {walk.potion.most_likely[1].id}，分别是 {walk.potion.most_likely[0].chance} 和 {walk.potion.most_likely[1].chance}：这个状态两者都没有，所以它们没有意义，也不训练任何东西。没有哪次训练见过的药水，比如 {walk.potion.unheld}，是 `<unk>` 那一行，显示它的概率 {walk.potion.unk}。

## 13. 搜索读到的数

搜索不读这 51 个概率，也不读药水的概率：它读一个数，即叶子估值（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）。`CombatNet.Outcome`（`src/Sts2Ai.Brain/Combat/CombatNet.cs`）这样得出它：网络仍允许的每个结局，都按它会留下的那局游戏由 V（宏观大脑赢下这一局的概率）定价：

$$
\text{value} = \sum_{k=1}^{50} p_k \sum_{S \subseteq H} \Big(\prod_{i \in S} (1 - u_{i,g(k)}) \prod_{i \in H \setminus S} u_{i,g(k)}\Big)\, V\big(\text{生命值为 } h_k \text{、持有 } S \text{ 的这一局}\big)
$$

这里 $H$ 是持有的药水，$u_{i,g}$ 是药水输出头给出的、药水 $i$ 在一场结束于第 $g$ 组的胜利之后没有了的概率，$g(k) = \lceil k/10 \rceil$ 是分桶 $k$ 所在的组，$h_k$ 是分桶 $k$ 之后玩家持有的生命值：现在的生命值比例减去分桶的中点，乘以最大生命值，限制在 1 到最大生命值之间。

对这个状态，$H$ 只有瓶中精灵，所以每个开启的分桶给出两局：带着药水的一局，概率为 $1 - u_{i,g(k)}$，在每一组都是 {(1 - walk.potion.chance).toFixed(3)}（[§12](#sec-12)），以及没有药水的一局。{walk.head.open} 个开启的分桶给 V 带来 {2 * walk.head.open} 局，而概率恰好为 0 的关闭分桶一局也不带来。每一局的其余部分，是这场战斗周围的这一局当前的样子：牌组、遗物、最大生命值、金币、前面的地图。文件里的测试状态只有一个回合开始，没有这一局，所以本页给不出 V 的数，也给不出估值；同一次调用在估值旁边返回的东西不需要它们（[叶子 §5](/arch/combat-brain/leaf/#sec-5)）：

| | 数 |
|---|---|
| 胜率，$1 - p_0$ | {walk.ended.win} |
| 赢下时持有的生命值，在各获胜分桶上取平均 | {walk.ended.hp_at_win} / {walk.state.max_hp} |
| 胜利时预计留下的药水，$\sum_{i \in H} (1 - \bar u_i)$ | {walk.ended.kept} |

这里 $\bar u_i = \sum_{k=1}^{50} p_k\, u_{i,g(k)} / (1 - p_0)$，即药水 $i$ 在胜利时没有了的概率：每个分桶那一组的概率，按分桶的概率加权。

所以 V 被问到的，是平均以 {walk.state.max_hp} 点中的 {walk.ended.hp_at_win} 点生命值离开这场战斗、大多仍持有药水的那些局，估值是 V 在这些局上按各自概率加权的平均。这是否比另一个状态的结局更值，要由 V 根据它从这一局读到的一切来说。

## 14. 搜索看到什么

搜索比较状态。每次只改一样东西，再跑一遍网络：

| 状态 | 生命值比例 | 死亡的概率 | 最可能的分桶 | 赢下时持有的生命值 |
|---|---|---|---|---|
| 原样 | {walk.ended.share} | {pct(walk.head.death)} | {walk.head.tops[0].low} 到 {walk.head.tops[0].high}，{pct(walk.head.tops[0].chance)} | {walk.ended.hp_at_win} |
| 少 {walk.lost_hp} 点生命值 | {walk.siblings.less_hp.share} | {pct(walk.siblings.less_hp.death)} | {walk.siblings.less_hp.tops[0].low} 到 {walk.siblings.less_hp.tops[0].high}，{pct(walk.siblings.less_hp.tops[0].chance)} | {walk.siblings.less_hp.hp_at_win} |
| 药水没有了 | {walk.siblings.no_potion.share} | {pct(walk.siblings.no_potion.death)} | {walk.siblings.no_potion.tops[0].low} 到 {walk.siblings.no_potion.tops[0].high}，{pct(walk.siblings.no_potion.tops[0].chance)} | {walk.siblings.no_potion.hp_at_win} |

少 {walk.lost_hp} 点生命值时，最可能的分桶不变，概率略有上升，死亡从 {pct(walk.head.death)} 变成 {pct(walk.siblings.less_hp.death)}。分桶是从现在持有的生命值里还要失去的比例，所以赢下时持有的生命值下降，从 {walk.ended.hp_at_win} 降到 {walk.siblings.less_hp.hp_at_win}，不过降得比拿走的 {walk.lost_hp} 点少：从较低的生命值出发，网络预计一场胜利要花掉 {(walk.state.hp - walk.lost_hp - walk.siblings.less_hp.hp_at_win).toFixed(1)} 点生命值，而现在是 {(walk.state.hp - walk.ended.hp_at_win).toFixed(1)} 点。持有的生命值被完整计入（[战斗网络 §7](/arch/combat-brain/network/#sec-7)），V 给这个状态的每个结局定价时，生命值都更少。

没有药水时，死亡从 {pct(walk.head.death)} 变成 {pct(walk.siblings.no_potion.death)}，最可能的分桶的概率从 {pct(walk.head.tops[0].chance)} 变成 {pct(walk.siblings.no_potion.tops[0].chance)}，赢下时持有的生命值从 {walk.ended.hp_at_win} 变成 {walk.siblings.no_potion.hp_at_win}。瓶中精灵只在玩家将要死去时起作用；这里没有什么能说明网络为什么会改变其他结局。于是两个状态之间的差别主要来自 V：生命值相同，一局持有药水，一局没有。一瓶药水值多少，不是为这场战斗设定的一个数，而是 V 认为在这一局里持有它值多少。

## 15. 两个更难的状态

同一文件里的另外两个状态展示了这个状态展示不了的东西，即一场网络认为胜负大约各半的 Boss 战，以及一个低到关闭大部分分桶的生命值：

| | {walk.others.danger.encounter} | {walk.others.mask.encounter} |
|---|---|---|
| 房间、回合 | {walk.others.danger.room}，第 {walk.others.danger.round} 回合 | {walk.others.mask.room}，第 {walk.others.mask.round} 回合 |
| 生命值 | {walk.others.danger.hp} / {walk.others.danger.max_hp} | {walk.others.mask.hp} / {walk.others.mask.max_hp} |
| 开启的分桶 | {walk.others.danger.open}（{walk.others.danger.open_from} 到 {walk.others.danger.open_to}） | {walk.others.mask.open}（{walk.others.mask.open_from} 到 {walk.others.mask.open_to}） |
| 死亡的概率 | {pct(walk.others.danger.death)} | {pct(walk.others.mask.death)} |
| 最可能的分桶 | {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，{pct(walk.others.danger.tops[0].chance)} | {walk.others.mask.tops[0].low} 到 {walk.others.mask.tops[0].high}，{pct(walk.others.mask.tops[0].chance)} |
| 赢下时持有的生命值 | {walk.others.danger.hp_at_win} | {walk.others.mask.hp_at_win} |

对知识恶魔这场 Boss 战，静默猎手在第 {walk.others.danger.round} 回合持有 {walk.others.danger.max_hp} 点中的 {walk.others.danger.hp} 点生命值，网络给死亡 {pct(walk.others.danger.death)}。一场胜利预计要花掉持有的大部分生命值：最可能的分桶是失去最大生命值的 {walk.others.danger.tops[0].low} 到 {walk.others.danger.tops[0].high}，即 {(walk.others.danger.tops[0].low * walk.others.danger.max_hp).toFixed(1)} 到 {(walk.others.danger.tops[0].high * walk.others.danger.max_hp).toFixed(1)} 点，而 {walk.others.danger.open} 个开启的分桶没有一个超过 8 %。V 按各自的生命值给这些结局分别定价，所以估值分散在从 {walk.others.danger.hp} 点到 1 点生命值的各局上，而死亡以 0 的价格拿走将近一半的概率。对残杀千足虫这场精英战，铁甲战士持有 {walk.others.mask.max_hp} 点中的 {walk.others.mask.hp} 点生命值，所以只有 {walk.others.mask.open} 个分桶开启，任何概率都不会落在失去的生命值超过玩家持有的胜利上。即便如此，死亡也不太可能：最可能的两个分桶是回复最大生命值的 0.05 到 0.1，占四分之三的概率，而这个铁甲战士的遗物里有燃烧之血，每场赢下的战斗之后回复 6 点生命值，比例 0.07。

## 16. 标签

到这里网络一直在预测。在训练中，这个状态还有一个答案，来自它的战斗真实的结局。文件没有保存那个结局，所以取一个作说明：**假设这场战斗以 {walk.state.max_hp} 点生命值中的 {walk.label.end_hp} 点赢下，药水还在**。

- **结局的类别**。从这个状态失去的比例是 {walk.state.hp}/{walk.state.max_hp} − {walk.label.end_hp}/{walk.state.max_hp} = {walk.label.lost}，落在 {walk.label.low} 到 {walk.label.high} 的分桶里：类别 {walk.label.class}。那场战斗的每个回合开始都会按自己的生命值得到自己的类别。
- **药水的标签**。它在战斗后的第一个整局观测里还在，所以标签是 0。类别 {walk.label.class} 在第 {Math.floor((walk.label.class - 1) / walk.potion.per_group) + 1} 组，所以这个标签只训练那一组的概率。
- **损失**。类别 {walk.label.class} 的概率是 {walk.label.chance}，所以结局的交叉熵是 {walk.label.ending_loss}。药水的，按那一组的概率，是 {walk.label.potion_loss}。这个样本的损失是两者之和，一步梯度会把那个分桶的概率往上推。

结局的损失更大：网络把概率分散在许多分桶上，所以没有哪个类别分到很多，而它预计会留下的药水确实留下了。在一整份对局清单上标签怎样生成，见[训练战斗网络 §3](/arch/learning/combat-net/#sec-3)。
