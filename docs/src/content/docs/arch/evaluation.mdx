评估回答两个问题：AI 有多强（排行榜），以及一个改动有没有帮助（晋级门槛）。两种环境走同一条流水线，结果总是分开报告。评估在模拟器（SimWorker）里跑整局，并通过 [Mod](/arch/mod/) 在真实游戏里做确认。

<Aside title="状态">

R1 整局评估已经可用：`run --seeds FILE --records FILE` 跑完一个种子集，每局写一条记录；`report` 把这些记录做成 [§6](#sec-6) 的报告，指标见 [§3](#sec-3)；第一组晋级种子和最终种子已经登记（[§4](#sec-4)）。战斗测试集也已就绪（[§5](#sec-5)，[战斗大脑 §7.1](/arch/combat-brain/#sec-7.1)），`leaderboard` 给报告排名（[§2](#sec-2)），整局门槛（`gate`）把通过的挑战者写进该环境的冠军文件（[§5](#sec-5)）。规划中：幕级门槛，以及 R2–R4。

</Aside>

## 1. 仿真到实机阶梯

模拟器里的结果，只有能迁移到真实游戏才算数。仿真到实机阶梯分 R1 到 R4 四级，每级多加一步真实性。每个里程碑都跑全部四级，分开报告：

| 级 | 世界 | 测量什么 | 现状 |
|---|---|---|---|
| R1 | 在模拟器里跑整局，由 Harness 驱动 | 策略 | 整局，NoSL（[§6](#sec-6)） |
| R2 | R1 + 观测往返（决策只在由观测构建的世界上做） | 观测重建 | 战斗的往返已有 |
| R3 | 用真实 DLL 跑整局，带真实解锁、大厅的幕选择和实际运行的协议 | 世界搭建 + 接口 | 无 |
| R4 | Steam 版游戏 + Mod | 全部 | 无 |

**为什么每级只加一个新变量**。每一级与下一级之间只差一处。如果胜率在相邻两级之间下降，只有一样东西变了，差距就能归因到它身上：

- R1 → R2：观测重建；
- R2 → R3：世界搭建和接口；
- R3 → R4：动画、时序、UI 状态和执行器（在游戏里执行动作的 Mod 代码）。

如果从 R1 直接跳到真实游戏，胜率变低可能出自上面任何一个原因，无从分辨。

- R4 很贵（按真实时间运行），所以用于确认，不用于调参。
- R1 的决策已经走 Build 路径，即由观测构建世界（[模拟器 §6](/arch/simulator/#sec-6)）。所以就决策而言，R1 约等于 R2；R2 增加的是宿主一侧只来自观测的状态。

## 2. 两个排行榜

排行榜记录一个环境的冠军（目前已接受的最好版本的 AI）在固定种子集上的成绩。每个环境一个：

| | NoSL | SL |
|---|---|---|
| 种子 | 同一组预先登记的种子 | 相同 |
| 冠军 | NoSL 冠军 | SL 冠军 |
| 允许的信息 | [环境 §3](/arch/environments/#sec-3) | 同一张表 |
| 预算 | 按每个决策计，同一档位 | 相同 |

- 两个冠军共用宏观大脑和 V，只有战斗大脑不同（[环境 §5](/arch/environments/#sec-5)）。新的 V 会同时改变两个冠军，所以要在每种环境里分别过门槛。
- 同时报告 SL − NoSL 的胜率差，也就是节点内信息的价值。这是计划 v1（本地笔记 `tmp/notes/plan.md`）里「全知 vs 重采样」消融实验的正式版本。作为参考：spire-mentor（一个前人项目）去掉它的作弊（覆盖整局）后，胜率下降了 22.8–25.5 个百分点（pp）；我们的作弊只到节点级，所以预计差值更小。
- `leaderboard [--character SILENT]` 从一个角色在 `eval/CHARACTER/reports/` 里的报告生成它的排行榜，写到 `eval/CHARACTER/leaderboard.md`：每个进阶等级、种子集和阶梯级别下，每个环境一张表，按胜率、再按平均层数排名，作废的报告排在最后，该环境冠军文件（`eval/CHARACTER/champions/`）指明的报告会被标出（[§5](#sec-5)）；不完整的报告不列入。表下面，对两种环境都有报告的每个冠军，给出同一组种子上按种子配对的 SL − NoSL 差值：胜率和到达层数，各带 95% 区间。榜上列出所有报告，而不只是已接受的冠军。排行榜和报告一起提交。

<Aside type="caution" title="不要混用环境">

绝不把两种环境放进同一张表，或同一次晋级决定。

</Aside>

## 3. 指标

**主要指标**

- 胜率，附 Wilson 95% 区间；
- 平均到达层数；
- 进入每个 Boss 战时的生命值。

Wilson 区间是比例（例如胜率）的置信区间。与简单的正态近似不同，它在样本少、或比例接近 0 或 1 时依然可靠。

**必须为零**（否则本次评估作废）

- 兜底或随机决策（[Harness §4](/arch/harness/#sec-4)）；
- 失败的对局（驱动或大脑出错）和被截断的对局（触及决策上限）；
- 游戏错误（`Log.Error` 行）；
- `NumReloads`；
- NoSL 对局中的存档导出（[环境 §6](/arch/environments/#sec-6)）。

**辅助指标**

- 决策界面覆盖计数；
- 每个决策的计算量（分支数、墙钟时间、SL 克隆查询次数）；
- 宏观校准：Brier 分数（预测胜率与 0/1 结果之间的均方误差，越低越好）必须低于常数预测；
- 保守程度：打精英次数、跳过率、到达 Boss 时的生命值、囤积金币/药水；
- 失败和被截断的对局在胜率里也算作输局；从不重跑。

## 4. 种子

- 三组互不相交的种子：训练、晋级、最终。
- 最终种子事先生成并登记在仓库里（注明方法和日期）。全部都跑，全部都报告，这样谁也没法挑那些碰巧好看的种子。正式结论至少需要 300 局。
- 种子就是游戏的对局种子字符串。R1–R3 由 worker 开局，R4 由 Mod 用同样的种子开局（[Mod §7](/arch/mod/#sec-7)）。
- 训练种子不限量。晋级种子定期轮换，避免过拟合。

种子集是 `eval/seeds/` 下的一个文本文件，每行一个种子，开头的注释写明生成方法和日期。`seeds --base B --n K` 输出 K 个种子 `MakeSeed(B, i)`（i = 0…K−1）：每个种子是 12 个字符，取自一个以 B × 1,000,003 + i × 7,919（32 位）为种子的随机数生成器。下表中任意两个基数要到几亿个种子之后才会撞上同一个生成器种子，所以各组互不相交。基数是固定的：

| 种子集 | 基数 | 种子数 |
|---|---|---|
| 训练 | 1 | 不限（即 `run --seed 1` 所跑的） |
| `promotion-1` | 2 | 200，2026-10-27 登记 |
| `final-1` | 3 | 300，2026-10-27 登记 |

一局的随机数生成器（占位策略、大脑种子）以种子字符串的稳定哈希为种子，所以只要种子相同，对局就相同，与它在哪个种子集、排第几无关。

## 5. 晋级门槛

晋级门槛是挑战者取代冠军之前必须通过的测试。整局很贵：胜率 p 约为 0.3 时，用非配对比较检测 +5 pp 的提升，每边约需 1,300 局；+2 pp 约需 8,000 局。所以门槛分层，从便宜而局部到昂贵而完整：

| 层级 | 用于 | 方法 | 成本 |
|---|---|---|---|
| 战斗测试集（combat panel） | 战斗搜索 / 价值 | 固定的（遭遇，牌组，种子），CRN；平均掉血 + 死亡率 | 几秒到几分钟 |
| 幕级 | 宏观 | 从快照池开始打一幕；过幕率 + 幕末生命值 | 几分钟 |
| 整局 SPRT | 阶段晋级 | 在晋级种子上配对，SPRT（H0：Δ ≤ 0，H1：Δ ≥ δ） | 几小时 |

- **CRN**：挑战者和冠军共用对局种子，搜索种子的派生方式也相同。整局跑通后，实测方差到底降低了多少。
- **配对检验**：McNemar 检验或配对 SPRT。对晋级门槛做 A/A 测试。

上面用到的方法：

- **CRN**（公共随机数）：双方用同样的随机种子来打，遇到的运气相同，只有策略不同；双方共有的运气就从差值里抵消了。
- **SPRT**（序贯概率比检验）每打完一对对局就检查一次证据，一旦证据明确支持某个假设就停止：H0，挑战者不比冠军强（Δ ≤ 0）；或 H1，挑战者至少强 δ（Δ ≥ δ）。Δ 是胜率差，挑战者减冠军。两类错误率事先定好；得出明确结论所需的局数，通常比固定局数的检验少得多。
- **McNemar 检验**是配对的输赢结果的标准检验。它只看恰好一方赢、一方输的那些种子，检验它们在两边是否平分。
- **A/A 测试**：让冠军和它自己过晋级门槛。两边没有真实差别，所以晋级的频率不能高于门槛设计的假阳性率；高于它就说明门槛有问题。

**已实现的整局门槛**：`gate --champion eval/CHARACTER/champions/ENV.json --records A[,B…] [挑战者的对局选项] [--metric floor|win] [--delta D] [--alpha A] [--beta B] [--not-worse] [--promote PATH] [--env ENV]`。

- **冠军文件**：`eval/CHARACTER/champions/ENV.json`，每个角色每个环境一个，记录冠军在报告里的名字、打出这个冠军的对局选项（其中有它的角色和进阶等级，`character` 和 `asc`）、它的报告、成为冠军的日期，以及它通过的门槛（第一个冠军没有）。`run --champion FILE` 和 `brain --champion FILE` 按它来打；命令行上给出的选项覆盖文件里的。
- **冠军一方**就是它的报告。一个种子决定整局（[§4](#sec-4)），再打一遍冠军只会重复这些对局，所以门槛只打挑战者。两边必须来自同一游戏版本、同一环境、同一阶梯级别，并且用同一个角色、在同一个进阶等级上打；`--env` 写明挑战者的环境，与冠军文件的环境不同就拒绝。
- **挑战者一方**是它的对局记录，由给出的对局选项命名；每条记录都必须是用这些选项打出来的。带探索的选项（`--macro-explore`、`--combat-explore`）会被拒绝：探索只用于自我对弈（[学习 §5](/arch/learning/#sec-5)）。
- **配对**按种子，顺序同种子集。SPRT 每对之后检查一次，在第一个明确结论处停止。
- **指标**：`floor`（对局很少获胜时的默认值）是平均层数差，挑战者减冠军，做高斯 SPRT，H0 为 0，H1 为 δ = 1.5 层；方差由已有的配对估计（至少为 1），有 10 对不同之前不下结论。结果相同的配对不计入这 10 对：只改变部分对局的改动会让大多数配对结果相同，只有这些配对时方差停在下限 1，门槛在第 10 对就判这种改动失败。一个让十局中的一局多走 15 层（平均 +1.5）的改动，只要前 10 局结果相同就会这样失败，概率约 35%；Boss 预算的门槛就遇到了这种情况（[战斗大脑 §5](/arch/combat-brain/#sec-5)）。`win` 只看恰好一方获胜的那些配对，与 McNemar 检验相同；检验挑战者在其中所占的比例，H0 为 0.5，H1 为 0.5 + δ，δ = 0.1。α = β = 0.05。
- **结论**：通过（pass）、不通过（fail）、未定（open，配对用完仍无结论），或作废（void，挑战者的对局违反了必须为零的规则，[§3](#sec-3)）。通过时退出码为 0。
- **不更差**。目的是更省而不是更强的修改（少搜一些，打法其余不变），只要不更差就晋级：`--not-worse` 把两个假设都下移 δ，H0 在 −δ（差了 δ），H1 在 0（`win` 时 H0 在 0.5 − δ，H1 在 0.5）。门槛输出的那一行和冠军文件里的门槛结果会写明是哪种检验。`learn/challenge.py --not-worse` 会把它传下去。
- **晋级**：通过时，`--promote PATH` 把挑战者的报告写到 PATH.json 和 PATH.md，并改写冠军文件，写入这次门槛的结果。冠军文件直接引用挑战者的权重文件所在的路径，并带上它打的角色和进阶等级。这些文件必须在这个角色的权重文件夹 `weights/CHARACTER/` 里，那里一个名字永远指同一个文件；有文件在别处的晋级，在写任何东西之前就被拒绝（[学习 §6](/arch/learning/#sec-6)）。新报告要面对之后的挑战者，所以必须覆盖整个种子集。SPRT 可能提前通过：挑战者分批打，每批之后过一次门槛，不通过就停；通过之后把种子集剩下的打完，再晋级。`learn/challenge.py` 就是这样做的，用冠军的角色和进阶等级（[学习 §2](/arch/learning/#sec-2)）。
- **重新基线**。冠军的报告只有在代码还像原来那样打这个冠军时才代表它。改变它打法的修改（世界构建、搜索或 L0 的修复）会让报告过时，再拿它过门槛，就会把这次修改算到挑战者头上。这时冠军在新代码上把整个种子集重打一遍（`run --champion FILE`），冠军文件改为指向新报告。这不是晋级：冠军、它的日期和它通过的门槛都不变。2026-10-27 修了搜索的备忘表、L0 的升级估值和 NoSL 世界里怪物的出招日志之后（提交 `432aa0c`），NoSL 冠军在 promotion-1 上的平均层数从 21.88 变为 22.70（配对 +0.81 ± 0.89 层，95%；131 个种子到达的层数相同，42 个更高，27 个更低），打到第 3 幕 Boss 的局数从 1 变为 4。NoSL 世界补上盟友和被眩晕怪物的下一招之后（提交 `32a0160`），它又重打了一遍：22.58，200 个种子里 197 个到达的层数相同（配对 −0.12 ± 0.18），3 局打到第 3 幕 Boss。修复 NoSL 世界里牌自身的费用和 Sozu 下的商店之后（提交 `c5ee8de`），它在接下来的门槛所用的构建上又打了一遍：200 个种子全部到达相同的层数。

## 6. 报告

每次评估输出一个 JSON 文件和一页 Markdown 报告，内容包括：游戏版本、提交（commit）、冠军、环境、阶梯级别、种子集、预算、全部指标、必须为零的指标，以及与上一次评估的差异。报告放在 `eval/CHARACTER/reports/`，文件名为 `日期-环境-阶梯级别-种子集-名称.json` 和 `.md`；报告背后的对局记录和决策日志不进 git，放在 `data/CHARACTER/ENV/`（[学习 §6](/arch/learning/#sec-6)）。

- `report --seeds FILE --records A[,B…] --out PATH [--previous OLD.json]` 写出 PATH.json 和 PATH.md。记录可以来自多个进程，但必须是同一套配置（游戏、提交、冠军、环境、阶梯级别）、同一个角色和同一个进阶等级，并且每条记录跑的是种子集里不同的种子。跑的局数少于种子集时，报告会标为不完整。
- 对局记录（`run --records`）里还有对局 id，就是决策日志里这一局的 id（[Harness §6](/arch/harness/#sec-6)），学习时靠它把两者对上。记录还列出这一局进过的每场战斗：幕、层、遭遇、房间类型、第一个决策时的生命值、最大生命值和药水数，以及 `end`，即它的结局：死亡，或剩下的生命值、最大生命值和药水数。一局停在某场战斗里而不是死在里面（失败、截断）时，那场没有 `end`。它是战斗结局头的目标（[学习 §1](/arch/learning/#sec-1)）。
- 提交指构建所用的提交：`src/` 下有未提交改动的构建会在后面加上 `-dirty`，这样的报告只用于开发。

## 8. 未决问题

1. R4 的吞吐量：在游戏的 Instant 速度下一局要几分钟，由此算出能负担多少局 R4。
2. 晋级用的 δ：从 2 pp 开始，再按吞吐量调整。
