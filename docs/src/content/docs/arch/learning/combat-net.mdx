战斗网络是战斗搜索学到的叶子：从一个回合的开始，它预测在打出它训练对局的那个策略下，这场战斗会怎样结束。它读什么、它的各层怎样组合这些输入，见[战斗网络](/arch/combat-brain/network/)；搜索怎样用它的输出，见[叶子](/arch/combat-brain/leaf/)。本页讲它怎样训练、用哪些数据，以及训练出的网络测出了什么。

## 1. 它预测什么

从一个回合的开始，预测两样东西：

- **结局**：51 个类别上的分布，即一个死亡，或者从这个状态起还要失去的最大生命值比例的 50 个分桶之一，持有的生命值排除掉的分桶是关闭的。
- **药水**：赢下之后，每瓶持有的药水没有了的概率；分桶每相邻 10 个为一组，共 5 组，每组各给一个，所以一场代价高的胜利可以喝掉和一场代价低的胜利不同的药水（[战斗网络 §7](/arch/combat-brain/network/#sec-7)）。

`learn/combat/` 训练它（`combat.train`，`learn/combat/train.py:40`）。`--combat-net FILE` 让它来打，用在 SL 规划器里（显示为 `plan NAME`）或 PIMC 里（`pimc NAME`）。

## 2. 它读什么

全部内容见[战斗网络 §2](/arch/combat-brain/network/#sec-2)。`learn/combat/encode.py` 是唯一的规格，`CombatNet` 在 C# 里遵循它。

## 3. 样本与标签

`learn/combat/data.py` 从一份决策日志和对局记录的清单生成样本，每个角色的都读（[参考 §4](/arch/learning/reference/#sec-4)）。

- **一个样本是一个回合的开始**：日志里每个回合的第一个战斗决策，也就是搜索叶子所处的那种状态，因为搜索的叶子就是下一回合的开始（[叶子 §1](/arch/combat-brain/leaf/#sec-1)）。一场战斗的决策在下一个宏观决策处结束，或者在回合数倒退时结束；选牌提示的行被跳过（`combats`，`learn/combat/data.py:39-73`）。自动胜利规则在开始时就赢下的战斗没有问过任何决策，所以不给样本；它所在对局的精英战和 Boss 战照样给样本，和整局里一样（[模拟器：整局 §8](/arch/simulator/runs/#sec-8)）。
- **在它之前敌人的历史**由更早各回合的开始重建，每个活着的敌人的意图按它的 uid 对应，与 Harness 的 `Dispatcher` 构建它的方式相同（`witness`，`learn/combat/data.py:76-83`）。
- **结局的标签相对于这个状态**：一个死亡，或者这个状态的生命值比例减去战斗结束时的比例所落入的分桶（`ending`，`learn/combat/data.py:103-108`）。回血超过最低分桶时落入最低分桶。所以一场战斗的每个回合开始都有同一个结束，却各有自己的标签。这是蒙特卡洛：它是打出它的策略下真实发生的事（[循环 §3](/arch/learning/loop/#sec-3)）。
- **药水的标签**来自战斗后的第一个整局观测，逐瓶计算：这个状态持有、而那里没有的药水算作没有了（`potions_used`，`learn/combat/data.py:86-96`）。不取自动作，因为动作会漏掉没有动作就消耗的瓶中精灵。也不取自最后一个回合的开始，因为它会漏掉最后一个动作喝掉的药水。战斗后来得到的药水不是这个状态的药水。标签训练的是胜利结束时所在那一组分桶里这瓶药水的概率（[§4](#sec-4)）。死亡只训练结局。
- **不用的数据**（`read`，`learn/combat/data.py:131-157`）：失败的对局；记录中没有 `end` 的战斗，除非它是一局输掉的对局的最后一场，那样算作死亡；赢下之后没有整局观测的战斗；还有日志中的战斗与记录在数量或遭遇上对不上的每一局，训练器会计数并报告。
- **一种环境**。`--env SL|NoSL` 只读那种环境的行；另一种环境的日志行会让训练失败。这个网络用 `--env SL` 训练（[叶子 §6](/arch/combat-brain/leaf/#sec-6)）。
- **权重与划分**。每个回合开始的权重相同，按对局 id 每五局留出一局，连同它所有的回合开始，用于提前停止和报告。每 1,000 个留出的回合开始中有一个保留观测和历史，用作网络文件的测试状态（`KEEP`）。

**数据**。冠军的战斗网络 `weights/all/c9-2.json` 学自全部五个角色在进阶 0 的整局 SL 自我对弈，每场战斗都用中等预算打：21,272 局，合计 2,118,826 个回合开始，其中 430,142 个（来自 4,310 局）留出。自我对弈和晋级门槛的种子从不相遇，`--list` 也拒绝含有评估作业对局的清单（`common.train_lists`）。

## 4. 损失与训练

```bash
uv run python -m combat.train --list data/CHARACTER/lists/NAME --env SL --name NAME [--test-list LIST]
```

一个样本的损失是（`won_group`、`loss`，`learn/combat/net.py:329-341`）

$$
\text{loss} = \text{CE}(\text{masked endings}, \text{class}) + \text{won} \sum_{\text{held}} \text{BCE}(u_{\text{id},\, g(\text{class})}, \text{gone}),
$$

其中 $g(\text{class})$ 是胜利结束时所在的那一组 10 个分桶：一场胜利只训练它自己那一组的药水概率，不训练别的组。

药水项的权重是 1（`POTION_WEIGHT`），约占损失的 2 %：每个胜利样本 0.084 行药水，每行约 0.29 nats，而交叉熵约为 1.32。所以主体仍然属于结局。

设置写死在代码里（`learn/combat/train.py:34-36`）：AdamW，学习率 10⁻³，权重衰减 10⁻⁴；batch 256；最多 20 轮，连续 3 轮留出损失没有降低 10⁻⁴ 就停止。做实验就改代码，只有出了结果才留下改动。词元表是游戏的，固定不变（[战斗网络 §2](/arch/combat-brain/network/#sec-2)）。

**从一个网络接着训练（`--init FILE`）**。训练可以从一个网络文件的权重开始，权重从它的 ONNX 计算图读回（`export.weights`），学习率降为 3 × 10⁻⁴。除非某一轮的留出损失比文件的权重低，否则文件的权重保持不变。词元表与游戏不同的文件会被拒绝。

**报告**（`learn/combat/report.py`）是 stdout 上的一行 JSON，也保存为网络文件的 `fit`：`env`、`runs`、`held_out_runs`、`samples`、`held_out_samples`、`vocab`，然后是 `held_out`，以及同样内容按幕、房间、遭遇、生命值（是否低于 30 %）和药水 id 分开。一个样本的药水概率取它的胜利结束时所在那一组分桶的（`predict`）。有 `--test-list` 时，`medium` 对整份清单给出同样内容，这些对局只报告，从不训练。

| 字段 | 说明 |
|---|---|
| `ce`、`ce_prior` | 结局的交叉熵，以及训练集频率的交叉熵 |
| `death`、`predicted_death` | 实际和预测的均值 |
| `rank_lost`、`rank_lost_share` | 在每个 10 个或更多样本的 (遭遇, 回合) 内，与胜利时失去的生命值的等级相关，按大小加权；旁边是生命值比例的：网络在持有的生命值之外增加了什么 |
| `auc_death`、`auc_death_share` | 在每个死亡和存活各有 3 个或更多的 (遭遇, 回合) 内，死亡的回合开始得分高于存活的概率；旁边是生命值比例的 |
| `potions` | `rows`、`used`、`predicted`、`log_loss`，以及 `log_loss_id` 和 `log_loss_id_room`，即按 id、按 id 和房间的比率给出的对数损失 |

**网络文件**写到 `weights/all/NAME.json`，从不覆盖（[参考 §6](/arch/learning/reference/#sec-6)）。它的字段见[参考 §7](/arch/learning/reference/#sec-7)。

## 5. 它测出了什么

这些数是冠军的文件 `weights/all/c9-2.json` 里的报告。「留出」是训练清单中每五局的一局，共 4,310 局全部五个角色在进阶 0 的对局，430,142 个回合开始，用中等预算打。

| 指标 | 留出 | 只用生命值比例 |
|---|---|---|
| 结局的交叉熵（先验的） | 1.320 (2.374) | – |
| 死亡，实际和预测 | 4.50 %、4.65 % | – |
| 胜利时失去生命值的等级相关 | 0.725 | 0.133 |
| 死亡的 AUC | 0.931 | 0.691 |
| 药水的对数损失（按 id 和房间的） | 0.292 (0.465) | – |

**怎么读**。失去生命值的等级相关和死亡的 AUC 是网络在持有的生命值之外增加的东西，所以各自都和生命值比例自己的数并列。一局怎样看待各个结局的价值，是 V 的事，不是这份报告的（[战斗大脑：叶子 §5](/arch/combat-brain/leaf/#sec-5)）。

按房间，在留出对局上：

| 房间 | 回合开始 | 交叉熵（先验） | 死亡，实际和预测 | 失去生命值的等级相关 | 死亡的 AUC（生命值比例） |
|---|---|---|---|---|---|
| 普通战斗 | 268,349 | 0.930 (1.884) | 0.3 %、0.2 % | 0.710 | 0.978 (0.913) |
| 精英战 | 68,862 | 1.780 (2.798) | 1.7 %、1.9 % | 0.753 | 0.954 (0.835) |
| Boss 战 | 92,931 | 2.106 (3.473) | 18.8 %、19.4 % | 0.751 | 0.928 (0.674) |

**低生命值**，即低于最大生命值的 30 %，那里留出的回合开始有 16.1 % 会死：死亡的 AUC 是 0.925，生命值比例是 0.547。

**按 id 看药水输出头**。在留出对局上，瓶中精灵有 13.8 % 的时候用掉，预测为 13.3 %，对数损失是 0.136，而按 id 和房间的是 0.282。在所有行上，27.3 % 用掉，预测为 27.4 %。

**最难的战斗**。在 Aeonglass 上，留出的回合开始有 42.7 % 会死，网络预测 45.5 %，死亡的 AUC 是 0.933，生命值比例是 0.626。胜利时失去生命值的等级相关是 0.718，生命值比例是 0.211。

这些当中哪些能变成更多赢下的对局，由门槛来说（[评估：晋级门槛 §5](/arch/evaluation/gates/#sec-5)）；冠军自己的结果在[评估：冠军与基线 §2](/arch/evaluation/champions/#sec-2)。
