战斗网络是战斗搜索学到的叶子：从一个回合的开始，它预测在打出它训练对局的那个策略下，这场战斗会怎样结束。它读什么、它的各层怎样组合这些输入、它的输出头预测什么，在战斗大脑一章里讲解（[战斗大脑：叶子 §3](/arch/combat-brain/leaf/#sec-3)、[§4](/arch/combat-brain/leaf/#sec-4)）；本页讲它怎样训练、用哪些数据，以及训练出的网络测出了什么。

<Aside title="状态">

`learn/combat/`（`combat.train`，提交 `d290783`、`3a95439`）用一种环境的对局训练战斗网络。它还没训练出任何网络：SL 的第一个网络 `sl-c1` 计划在清单 `sl-combat` 上训练（[§7](#sec-7)）。现有的网络 c1–c4 由 `learn/train_combat.py` 训练，这个脚本已在 `455d437` 删除；c2 自 2026-10-27 起是两个冠军的叶子，在 NoSL 的 PIMC 里和 SL 的规划器里都是。

</Aside>

## 1. 网络读什么、预测什么

**输入**，作为一个回合开始时的词元（[战斗大脑：叶子 §3](/arch/combat-brain/leaf/#sec-3)）：四个牌堆里的每张牌（它的 id、升级次数、附魔、苦痛和所在牌堆）；玩家（生命值比例、生命值、最大生命值、格挡、能量、最大能量、星辰、回合数）和它的能力；每个活着的敌人（它的 id、生命值比例、生命值、最大生命值、格挡、已经显示过几回合意图、它的能力，以及四个意图槽：它现在显示的意图，然后是它前 3 回合的意图，最近的在前）；遗物、药水和上下文（角色、遭遇战、房间、幕）；较新的网络里还有球、活着的盟友、进阶等级、球槽数和金币。敌人之前的意图来自 Harness 保存的敌人出招记录（[战斗大脑：提示、招式与 worker §2](/arch/combat-brain/shared/#sec-2)）。

**输出**：51 个类别上的分布，即死亡，或者从这个状态到一场打赢的战斗结束还要损失的最大生命比例落在 50 个桶中的哪一个，从 −0.25（回了血的战斗）到 1；以及打赢时还要用掉的药水数（[战斗大脑：叶子 §4](/arch/combat-brain/leaf/#sec-4)）。叶子给每种结局定价，把它们变成一个数（[战斗大脑：叶子 §5](/arch/combat-brain/leaf/#sec-5)）。

**每个环境一个网络**。网络学的是在打出这些战斗的策略下战斗怎样结束，而 SL 的规划器能看到 NoSL 的搜索只能猜的东西，从同一个状态出发赢得更多。所以网络文件写明它的环境（`env`，SL 或 NoSL），另一种环境的对局、大脑、门槛或战斗测试集会拒收它（`LeafChoice.Check`，`SimWorker/Brains/LeafChoice.cs:25-30`）。c1–c4 早于这个字段，在两种环境里都能用，两个冠军因此都能用 c2（[战斗大脑：叶子 §6](/arch/combat-brain/leaf/#sec-6)）。

`--combat-net FILE` 让 PIMC（显示为 `pimc NAME`）或 SL 规划器（`plan NAME`）用它来打。

## 2. 每一代网络读什么

各个网络的区别在于除 id 以外还读哪些数。`CombatNet` 只给计算图喂它声明的输入（`NetNumbers.Declared`，`Brain/Combat/CombatNet.cs:259`），所以每一代的文件都能加载。

| 网络 | 训练者 | 除 id 以外读的 | 不读的 |
|---|---|---|---|
| c1、c2 | `train_combat.py` | 每张牌的费用 / 3 乘以一个费用向量（`costs`）；玩家的 8 个数；能力的数值；敌人的 5 个数和意图 | 牌、遗物和球上的数值，球，盟友，进阶等级，金币 |
| c3、c4 | `train_combat.py`（自 2026-10-27 起） | c2 读的全部，加上每张牌的修饰数值 / 10、星费 / 3、是否 X 费，以及它的每个数值（`vars`）/ 10 乘以该数值名字的向量；能力的层数（只在提示里与图标数字分开写出时，如懒惰）和它保留的那张牌（夜魇）；遗物的计数 / 10 乘以它 id 的计数向量（钢笔尖、双截棍、开心小花、历石）、是否显示计数、是否熔化、它的状态；球（id、被动和激发数值 / 10）和盟友；进阶等级 / 10、球槽数 / 10、金币 / 100 | – |
| `learn/combat/` 的 | `combat.train` | c3 的输入去掉牌、遗物或球上印的每个数：id、升级、修饰和牌堆；玩家的数；能力的 id、数值、层数和保留的牌；敌人的 id、数、能力和意图；遗物、药水、球和盟友的 id；遭遇战；进阶等级、球槽数和金币（`learn/combat/encode.py`） | 牌的费用、`vars`、星费、X 费、修饰数值、遗物计数、熔化标记和状态、球的数值 |

c3 为什么加入这些数：两个只在牌上印的数值或遗物计数上不同的状态，如果网络不读这些数，数据再多也分不开。`learn/combat/` 为什么又去掉它们：其中要紧的东西应当由网络从 id 中学出来，就像纯 V 那样（[价值函数 §6](/arch/learning/value/#sec-6)）。c3 加入的每个输入的一致性都用随机权重的网络检查过，权重经过放大，让每个输入都能改变输出：训练器给出的测试状态能通过加载，而只改了其中任何一个输入的状态副本会在加载时检查失败。

**`learn/combat/encode.py` 是唯一的规格**，定义较新网络的输入，`CombatNet.Predict` 遵循它。它的缩放（`learn/combat/encode.py:57-133`）：生物的生命值比例、生命值 / 100、最大生命值 / 100 和格挡 / 20；玩家的能量 / 3、最大能量 / 3、星辰 / 5 和回合数 / 10；敌人已显示意图的回合数 / 10；能力的数值 / 10 和层数 / 10；意图的每段伤害 / 10 和总伤害 / 20。这些都截断在 ±10 以内，因为少数状态会出现极大的数（喷发中的瀑布巨兽（WATERFALL_GIANT）的生命值）。三个额外的数中，金币 / 100 有截断；进阶等级 / 10 和球槽数 / 10 没有。死去的敌人或盟友不读入；没有 id 的敌人读作 `<none>`，没有 id 的盟友（玩家的）读作 `<player>`。

**网络**（`learn/combat/net.py:131-231`），与 V 一样采用集合编码器的风格：32 维的嵌入；一张牌是它 id 的向量，加上升级次数乘以它 id 的升级向量，再加上它的修饰和所在牌堆的向量，经过 φ（32 → 64 → 64），每个牌堆求和后 × 1/8；一个能力是它 id 的向量，加上数值和层数各乘以它 id 的一个向量，再加上保留的牌的向量，经过 φ（32 → 64）后求和；一个意图槽是其中各意图之和（类型的向量，加上伤害和总伤害各乘以该类型的一个向量），再加上一个学到的槽位位置向量；一个敌人是它 id 的向量，加上它 5 个数的投影、它的能力和它的 4 个槽，经过 φ（224 → 128 → 128），所有敌人求和；一个盟友是它 id 的向量，加上它 4 个数的投影和它的能力，经过 φ（96 → 64）后求和；遗物、药水、上下文和球词袋都是求和。主干读 651 个数（4 × 64 + 8 + 64 + 128 + 4 × 32 + 64 + 3），经过两层 256 宽的层；输出头给出 51 个 logit，药水输出头给出一个数。c2 的计算图画在[战斗大脑：叶子 §3](/arch/combat-brain/leaf/#sec-3)，它没有球、盟友和额外的数：它的主干读 552 个。

## 3. 样本与标签

`learn/combat/data.py` 从一份决策日志和对局记录的清单生成样本（[参考 §4](/arch/learning/reference/#sec-4)）。

- **一个样本是一个回合的开始**：日志里每个回合的第一个战斗决策，也就是搜索叶子所处的那种状态，因为搜索的叶子就是下一回合的开始（[战斗大脑：叶子 §1](/arch/combat-brain/leaf/#sec-1)）。一场战斗的决策在下一个宏观决策处结束，或者在回合数倒退时结束；选牌提示的行被跳过（`combats`，`learn/combat/data.py:29-55`）。
- **在它之前敌人的历史**由更早各回合的开始重建，每个活着的敌人的意图按它的 uid 对应，与 Harness 的 `Dispatcher` 构建它的方式相同（`witness`，`learn/combat/data.py:58-65`）。
- **标签是这场战斗在对局记录里怎样结束**（[评估：指标、种子与报告 §8](/arch/evaluation/metrics/#sec-8)），按对局 id 和战斗的顺序对上：死亡为类别 0，否则为 1 + 从这个状态到结束之间损失的生命比例所在的桶，在 [−0.25, 1) 上分 50 个桶（`ending`，`learn/combat/data.py:76-81`）；以及此后用掉的药水，即现在持有的减去结束时剩下的。两者都相对于这个状态，所以它现在的生命值和药水被完整计入。这是打这场战斗的策略下的蒙特卡洛目标（[循环 §3](/arch/learning/loop/#sec-3)）。
- **不用的数据**（`read`，`learn/combat/data.py:95-123`）：失败的对局；记录里没有 `end` 的战斗（对局在其中停下而没有死）；以及日志里的战斗与记录里的战斗在数量或遭遇战上对不上的每一局（日志被截断、某场战斗另外记录），训练器会统计并报告这些对局。精英连战对局的记录列出了它的怪物战斗，这些战斗一开始就判赢，没有决策，所以这样的对局对不上，不提供样本。
- **一种环境**。`--env SL|NoSL` 只读那种环境的行；另一种环境的日志行会让训练失败（`learn/combat/data.py:39-40`）。
- **权重与划分**。每个回合开始的权重相同（不按对局加权，这和 V 的样本不同），按对局 id 每五局留出一局，连同它所有的回合开始，用于提前停止和报告。

## 4. 损失与训练

`uv run python -m combat.train --list PREFIX --env SL|NoSL --name NAME [--out FILE] [--character SILENT] [--seed 0]`（`learn/combat/train.py:73-81`）。

一个样本的损失是 51 个类别的交叉熵，加上 0.1 乘以用掉药水数的平方误差，后者只对打赢的战斗计算（`loss`，`learn/combat/net.py:246-251`）。设置写死在代码里，与 c2 的相同（`learn/combat/train.py:31-35`）：训练对局中出现不到 3 次的 id 读作未知；AdamW，学习率 10⁻³，权重衰减 10⁻⁴；batch 256；最多 60 轮，连续 6 轮留出损失没有降低 10⁻⁴ 就停止；50 个桶从 −0.25 开始，读最近 3 回合的意图，也读回合数。`train_combat.py` 的下一意图输出头、它与 `LeafValue` 的对比，以及它做消融用的选项（`--width`、`--train-share`、`--fold`、`--lags`、`--no-round`）都已去掉：做实验就改代码，只有出了结果才留下改动。

**报告**是 stdout 上的一行 JSON（`learn/combat/train.py:151-167`）：`env`、`runs`、`held_out_runs`、`samples`、`held_out_samples`、`deaths`、`vocab`（每张表的大小）、`held_out_loss`、`held_out_ce`（各类别在留出数据上的交叉熵）、`held_out_ce_prior`（只知道训练结局频率的先验的同一指标，每个计数 + 0.5）、`held_out_ce_by_room` 和 `held_out_samples_by_room`，以及 `death_corr`，即网络给出的死亡概率与实际死亡的相关系数。

**网络文件**写到 `weights/CHARACTER/NAME.json`，从不覆盖（[参考 §6](/arch/learning/reference/#sec-6)）。它包含 ONNX 格式的网络（输出 `outcome` 和 `potions_used`）、词元表、`env`、`buckets`、`loss_min`、`lags`、`round`、报告，以及最多 8 个留出的回合开始和训练器对每个给出的结局；`CombatNet.Load` 重新预测它们，只要任何一个类别或药水的偏差超过 10⁻³ 就拒收这个文件（`Brain/Combat/CombatNet.cs:65-80`）。它的字段列在[参考 §7](/arch/learning/reference/#sec-7)。

## 5. c1 到 c4

迄今为止的每个战斗网络，数据来自它们文件里的 `fit` 和账本（`eval/silent/ledger.md`）。四个都是 NoSL 的，都由 `train_combat.py` 训练；数字是每个文件的报告，取它的第 0 折。

| 网络 | 训练数据 | 回合开始 | 输出头 | 留出交叉熵（先验） | 价值与真实结局的相关系数（`LeafValue` 的） | 权重数 | 门槛 |
|---|---|---|---|---|---|---|---|
| c1 | g0，315 局（NoSL，PIMC 配 `LeafValue`） | 13,954 | 20 个剩余生命比例的桶 | 1.590 (2.487) | 0.949 (0.790) | 296,054 | 2026-10-27 在 32 对后失败（−1.41 层） |
| c2 | 同上 | 13,954 | 51 个类别：死亡，50 个还要损失的生命值桶 | 1.320 (2.003) | 0.959 (0.790) | 303,764 | 2026-10-27 在 77 对后通过（+2.36 层）；两个冠军的叶子 |
| c3 | g1，505 局（由 c2 打） | 27,909 | 同 c2；读数值 | 1.346 (2.041) | 0.960 (0.829) | 351,124 | 在 200 对中的第 160 对时作废（+0.58 层，未定） |
| c4 | g1 + g2，844 局 | 46,466 | 同 c3 | 1.356 (2.098) | 0.957 (0.833) | 353,300 | 未经门槛 |

c2 的留出交叉熵在 Boss 战最低（597 个回合开始上 1.130），在精英战最高（106 个上 2.640），普通怪物战在 1,819 个上为 1.306；它价值的平方误差是 0.00766，c1 是 0.00905；它的死亡概率与实际死亡的相关系数是 0.787。c1 的文件是旧的输出头：结束时*剩余*生命比例的 20 个桶，没有 `loss_min`，输出为 `potions_left`。`CombatNet` 按位置读输出，所以现在它会把 c1 的桶当作损失的生命来定价；没有任何作业用 c1。

## 6. 测量结果

**在 315 局 NoSL 自我对弈上**（g0，13,954 个回合开始；`train_combat.py`，三折）：

- **限制网络的是数据，不是大小**。用四分之一、一半和全部训练对局，留出交叉熵分别是 1.446、1.379 和 1.337。宽度减半时一样（1.337），宽度加倍也没有更好（1.340）。
- **网络从数据中学到怪物的出招**。加上下一意图输出头时，它对 57.7% 的敌人说对了下一回合的意图类型，而照搬当前意图只有 28.9%；它对下一回合总伤害的预测平均相差 4.15，照搬是 7.65。其中大部分只需要怪物本身和它当前的意图：没有历史和回合数时也有 56.7%。历史对少数怪物帮助最大，例如乐加维林族母（LAGAVULIN_MATRIARCH，43% 对 33%）和小啃兽（NIBBIT，41% 对 35%）。很多没猜中的是游戏随机选的招式。这个输出头既没有改变结局的留出交叉熵，也没有让价值的误差变化超出噪声，所以默认关闭，`learn/combat/` 也去掉了它。
- **预测还会发生什么，而不是还剩多少**。c1 预测的是结束时剩余的生命比例，结果只学到了现在持有的生命值一半左右的分量：现在少 1 点生命，它的估值只降 0.0038，而结局实际会少整整 1 点生命，按 `LeafValue` 的价格是 0.0078。它的搜索太轻易地拿生命去换，在普通战和精英战里比冠军掉的生命更多（每场胜利 7.8 对 6.5、26.4 对 18.0 点生命），并在 32 对后没通过门槛（−1.41 层）。改为预测从这里起的损失（c2）后，现在持有的生命值被完整计入（同样那些状态上每点生命 0.0083），价值的留出平方误差也从 0.0090 降到 0.0077（[战斗大脑：叶子 §4](/arch/combat-brain/leaf/#sec-4)）。

**在 g1 的 505 局上**（27,909 个回合开始，由 c2 打；c3 的数据；三折）：

- **宽度仍然无关紧要**。宽度 1 时留出交叉熵是 1.348、1.348 和 1.334，宽度减半时是 1.356、1.327 和 1.317（先验：2.041、1.973 和 2.014），在各折的离散范围内相同。宽度也不改变搜索的速度：在一个 8 场战斗的第 1 幕战斗测试集上并排比较，宽度 0.5、1 和 2 的网络以及 c2 每个动作都花 1.58–1.76 s，因为游戏模拟的开销远大于网络。c3 保留宽度 1，让它的门槛只检验数据。
- **优化器的设置也无关紧要**。在第 0 折上，学习率用 3 × 10⁻⁴ 或 10⁻⁴ 代替 10⁻³，或者权重衰减用 10⁻² 代替 10⁻⁴，结果是 1.346–1.348，原设置是 1.348。
- 网络隐含的**价值**与真实结局的价值相关系数为 0.960，`LeafValue` 的是 0.829。
- **c3 的门槛**用冠军的其他选项来跑，在 200 个种子中跑到第 160 个时作废：它的一局在添水下在商店里反复买同一瓶药水，直到被截断，这是 Harness 的一个 bug，此后已修复（提交 `c5ee8de`）。到那时为止，它平均比冠军多到达 0.58 层（LLR −0.65，未定），远低于门槛的 δ 1.5 层（[评估：晋级门槛 §6](/arch/evaluation/gates/#sec-6)）。

## 7. 规划中

- **SL 自己的网络** <Badge text="规划中" variant="caution" />。c2 学自 PIMC 配 `LeafValue` 打出的 NoSL 战斗，而它也是 SL 规划器的叶子，所以它预测的是一个比规划器弱的玩家打出的结局（[战斗大脑：叶子 §6](/arch/combat-brain/leaf/#sec-6)）。清单 `sl-combat` 存放 SL 的训练集：SL g3 的第 1 批（419 局），以及规划器配 c2 以 medium 力度打的 SL 评估（`promotion-1`，160 局；`promotion-1b`，40 局；n3-free-ctl 的门槛，200 局），共 819 局、54,405 个回合开始；fix68 的重跑不算在内，因为它们的种子就是 `promotion-1` 的（[参考 §4](/arch/learning/reference/#sec-4)）。它的第一个网络将是 `uv run python -m combat.train --list data/silent/lists/sl-combat --env SL --name sl-c1`。
- **输出头的其他目标** <Badge text="规划中" variant="caution" />，通过门槛比较：战斗内的 TD(λ ≈ 0.95)，用输出头自己在下一个决策上的分布自举，终点的桶用 HL-Gauss 向相邻的桶平滑（约 0.75 个桶宽的高斯），这是前人的 STS2 求解器 ytcs 的做法（ytcs 发现 λ = 1 更差）；或者 0.3 × 搜索的分布 + 0.7 × 实际结局，这是前人的 STS2 项目 r33hab 的做法（[循环 §4](/arch/learning/loop/#sec-4)）。
- **知道上限的输出头** <Badge text="规划中" variant="caution" />：一场打赢的战斗损失的生命不可能超过玩家现有的生命，而 c2 在难打的战斗里会把概率放在这样的桶上（[战斗大脑：叶子 §4](/arch/combat-brain/leaf/#sec-4)）。
- **搜索价值作标签，以及学到的先验**（专家迭代） <Badge text="规划中" variant="caution" />，前提条件是：学到的叶子只有在同时胜过 `LeafValue` 和打到战斗结束的推演之后，才取代 `LeafValue`（[循环 §5](/arch/learning/loop/#sec-5)）。
