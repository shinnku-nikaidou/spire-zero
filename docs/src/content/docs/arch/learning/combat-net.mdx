战斗网络是战斗搜索学到的叶子：从一个回合的开始，它预测在打出它训练对局的那个策略下，这场战斗会怎样结束。它读什么、它的各层怎样组合这些输入，见[战斗网络](/arch/combat-brain/network/)；搜索怎样用它的输出，见[叶子](/arch/combat-brain/leaf/)。本页讲它怎样训练、用哪些数据，以及训练出的网络测出了什么。

## 1. 它预测什么

从一个回合的开始，预测两样东西：

- **结局**：51 个类别上的分布，即一个死亡，或者从这个状态起还要失去的最大生命值比例的 50 个分桶之一，持有的生命值排除掉的分桶是关闭的。
- **药水**：赢下之后，每瓶持有的药水没有了的概率。

`learn/combat/` 训练它（`combat.train`，`learn/combat/train.py:77`）。`--combat-net FILE` 让它来打，用在 SL 规划器里（显示为 `plan NAME`）或 PIMC 里（`pimc NAME`）。

## 2. 它读什么

全部内容见[战斗网络 §2](/arch/combat-brain/network/#sec-2)。`learn/combat/encode.py` 是唯一的规格，`CombatNet` 在 C# 里遵循它。

## 3. 样本与标签

`learn/combat/data.py` 从一份决策日志和对局记录的清单生成样本（[参考 §4](/arch/learning/reference/#sec-4)）。

- **一个样本是一个回合的开始**：日志里每个回合的第一个战斗决策，也就是搜索叶子所处的那种状态，因为搜索的叶子就是下一回合的开始（[叶子 §1](/arch/combat-brain/leaf/#sec-1)）。一场战斗的决策在下一个宏观决策处结束，或者在回合数倒退时结束；选牌提示的行被跳过（`combats`，`learn/combat/data.py:33-67`）。
- **在它之前敌人的历史**由更早各回合的开始重建，每个活着的敌人的意图按它的 uid 对应，与 Harness 的 `Dispatcher` 构建它的方式相同（`witness`，`learn/combat/data.py:70-77`）。
- **结局的标签相对于这个状态**：一个死亡，或者这个状态的生命值比例减去战斗结束时的比例所落入的分桶（`ending`，`learn/combat/data.py:97-102`）。回血超过最低分桶时落入最低分桶。所以一场战斗的每个回合开始都有同一个结束，却各有自己的标签。这是蒙特卡洛：它是打出它的策略下真实发生的事（[循环 §3](/arch/learning/loop/#sec-3)）。
- **药水的标签**来自战斗后的第一个整局观测，逐瓶计算：这个状态持有、而那里没有的药水算作没有了（`potions_used`，`learn/combat/data.py:80-90`）。不取自动作，因为动作会漏掉没有动作就消耗的瓶中精灵，占所有没有了的药水的 6.2 %。也不取自最后一个回合的开始，因为它会漏掉最后一个动作喝掉的药水。战斗后来得到的药水不是这个状态的药水。死亡只训练结局。
- **不用的数据**（`read`，`learn/combat/data.py:131-157`）：失败的对局；`--skip-seeds` 给的种子文件里的对局；记录中没有 `end` 的战斗，除非它是一局输掉的对局的最后一场，那样算作死亡；赢下之后没有整局观测的战斗；还有日志中的战斗与记录在数量或遭遇上对不上的每一局，训练器会计数并报告。
- **一种环境**。`--env SL|NoSL` 只读那种环境的行；另一种环境的日志行会让训练失败。这个网络用 `--env SL` 训练（[叶子 §6](/arch/combat-brain/leaf/#sec-6)）。
- **权重与划分**。每个回合开始的权重相同，按对局 id 每五局留出一局，连同它所有的回合开始，用于提前停止和报告。每 1,000 个留出的回合开始中有一个保留观测和历史，用作网络文件的测试状态（`KEEP`）。

**数据**是整局 SL 对局：21,263 局自我对弈，每场战斗都打了，大多用低预算（[SL 规划器：预算 §2](/arch/sl-planner/budget/#sec-2)），加上种子 `promotion-301-500` 上 600 局中等预算对局。合计 21,863 局、1,625,608 个回合开始，其中 325,309 个留出。`promotion-1-300` 的种子从不用于训练。

在胜利的回合开始中，掩码从不关闭真实的分桶，1,479,991 个中有 98 个回血超过最低分桶。9.4 % 的回合开始持有药水。

## 4. 损失与训练

```bash
uv run python -m combat.train --list data/silent/lists/c7 --env SL --name NAME --skip-seeds ../eval/seeds/promotion-1-300.txt --test-list data/silent/lists/medium
```

一个样本的损失是（`loss`，`learn/combat/net.py:283-290`）

$$
\text{loss} = \text{CE}(\text{masked endings}, \text{class}) + \text{won} \sum_{\text{held}} \text{BCE}(u_{\text{id}}, \text{gone}).
$$

药水项的权重是 1（`POTION_WEIGHT`），约占损失的 4 %：每个胜利样本 0.105 行药水，每行约 0.46 nats，而交叉熵约为 1.27。所以主体仍然属于结局。

设置写死在代码里（`learn/combat/train.py:33-36`）：训练对局中出现不到 3 次的 id 读作未知；AdamW，学习率 10⁻³，权重衰减 10⁻⁴；batch 256；最多 20 轮，连续 3 轮留出损失没有降低 10⁻⁴ 就停止。做实验就改代码，只有出了结果才留下改动。最好的是 8 轮中的第 5 轮，在 GPU 上用了 1 小时 51 分。

**报告**（`learn/combat/report.py`）是 stdout 上的一行 JSON，也保存为网络文件的 `fit`：`env`、`runs`、`held_out_runs`、`samples`、`held_out_samples`、`vocab`，然后是 `held_out`，以及同样内容按幕、房间、遭遇、生命值（是否低于 30 %）和药水 id 分开。有 `--test-list` 时，`medium` 对该清单里 `--skip-seeds` 的种子上的对局给出同样内容，这些对局只报告，从不训练。

| 字段 | 说明 |
|---|---|
| `ce`、`ce_prior` | 结局的交叉熵，以及训练集频率的交叉熵 |
| `death`、`predicted_death` | 实际和预测的均值 |
| `rank_within`、`rank_within_share` | 在每个 10 个或更多样本的 (遭遇, 回合) 内与结束价格的等级相关，按大小加权；旁边是生命值比例的 |
| `rank_lost`、`rank_lost_share` | 同样的相关，换成胜利时失去的生命值：网络在持有的生命值之外增加了什么 |
| `auc_death`、`auc_death_share` | 在每个死亡和存活各有 3 个或更多的 (遭遇, 回合) 内，死亡的回合开始得分高于存活的概率；旁边是生命值比例的 |
| `potions` | `rows`、`used`、`predicted`、`log_loss`，以及 `log_loss_id` 和 `log_loss_id_room`，即按 id、按 id 和房间的比率给出的对数损失 |

**网络文件**写到 `weights/CHARACTER/NAME.json`，从不覆盖（[参考 §6](/arch/learning/reference/#sec-6)）。它的字段见[参考 §7](/arch/learning/reference/#sec-7)。

## 5. 它测出了什么

这些数是 `weights/silent/c7-2.json` 的报告。「留出」是训练清单中每五局的一局，大多用低预算打。「中等」是种子 `promotion-1-300` 上中等预算对局的 39,732 个回合开始，它从未在这些种子上训练。

| 指标 | 留出 | 中等 | 只用生命值比例（留出、中等） |
|---|---|---|---|
| 结局的交叉熵（先验的） | 1.266 (2.148) | 1.344 (2.118) | – |
| 死亡，实际和预测 | 5.59 %、5.39 % | 4.02 %、4.42 % | – |
| 与结束价格的等级相关 | 0.926 | 0.896 | 0.819、0.796 |
| 胜利时失去生命值的等级相关 | 0.634 | 0.600 | 0.082、0.087 |
| 死亡的 AUC | 0.942 | 0.874 | 0.758、0.684 |
| 药水的对数损失（按 id 和房间的） | 0.311 (0.478) | 0.359 (0.487) | – |

**怎么读**。与结束价格的等级相关说明不了多少：只用生命值比例就能得到大部分，因为结束价格跟着持有的生命值走。失去生命值的等级相关和死亡的 AUC 才是网络在持有的生命值之外增加的东西。

按房间，在留出对局上：

| 房间 | 回合开始 | 交叉熵（先验） | 死亡，实际和预测 | 失去生命值的等级相关 | 死亡的 AUC（生命值比例） |
|---|---|---|---|---|---|
| 普通战斗 | 256,011 | 1.089 (1.811) | 1.7 %、1.6 % | 0.607 | 0.960 (0.851) |
| 精英战 | 23,476 | 1.841 (2.869) | 9.6 %、8.7 % | 0.738 | 0.941 (0.777) |
| Boss 战 | 45,822 | 1.956 (3.661) | 25.1 %、24.8 % | 0.775 | 0.935 (0.719) |

**低生命值**，即低于最大生命值的 30 %，那里留出的回合开始有 21.5 % 会死：死亡的 AUC 是 0.904，生命值比例是 0.633；在中等预算对局上是 0.960 对 0.510。

**按 id 看药水输出头**。在留出对局上，瓶中精灵有 13.3 % 的时候用掉，预测为 13.1 %，对数损失是 0.141，而按 id 和房间的是 0.355。在所有行上，23.1 % 用掉，预测为 22.7 %。

**最难的战斗**。在实验体上，留出的回合开始有 91.2 % 会死，网络预测 91.4 %，死亡的 AUC 是 0.854，生命值比例是 0.613。那里的胜利太少，测不出任何关于失去生命值的东西。

这些当中哪些能变成更多赢下的对局，由门槛来说（[评估：晋级门槛 §5](/arch/evaluation/gates/#sec-5)）。在门槛打完的 150 个种子上，它赢了 88 局，和同样数据上的一个较早网络一样多（[评估：冠军与基线 §2](/arch/evaluation/champions/#sec-2)）。
