# 戰鬥搜尋的記憶：同一場戰鬥裡搜過的回合不再搜（台灣時間 2026-11-16 11:28 起草）

**草稿，等用戶。** 用戶 2026-11-16 看到每次丟棄都重新完整思考：「那也不該重新計算之後的一切啊，好多地方都在重新計算全部，
我覺得得設計新架構」。先修了兩個落差（回合開始的選牌照真遊戲的順序問、閃光中的遺物讀結算後的數字，mod 0.3.15），
然後說「寫計畫」。這份只動 SL 規劃器，和進行中的 V 多步目標、藥水規則、v11g0 生成互不相干。

## 1. 問題（量到的）

- mod 的 5 局日誌（11-15、11-16，`~/.local/state/sts2ai/logs/`）：戰鬥大腦的搜尋共 471 秒，其中「計畫的下一步對不上」
  的重搜 382 秒（81 %），開戰 81 秒（17 %），計畫用完 8 秒（2 %）。對不上的原因就是那兩個落差，已修。
- 但每次重搜都從零開始。11-16 那場 Decimillipede 菁英戰，每個計畫搜大約 150,000 個動作、60–80 個回合、10–12 秒；
  相鄰兩個計畫的根只差一回合，後一個搜的回合大多前一個搜過。
- 修完落差以後，還會從零重搜的情況：
  1. 輸而且沒證明的計畫：high / max 每打一回合就重搜（`Budget.Replan` 1），low / medium 最多連三個（`LossPlans` 3）。
  2. 計畫走到 `SlPlanner.MaxTurns`（40 回合）還沒打完，長戰鬥會碰到。
  3. 輔助模式下玩家自己打了計畫以外的牌。
  4. 以後任何新的落差。
  5. 開戰。這一個是新的戰鬥，這份不碰。
- 一個計畫之內已經有重用：貪心的 dive 搜過的回合，全束照路徑拿來用（`SlPlanner.Beam._searched`）。計畫和計畫之間沒有。
- self-play：模擬器和引擎一致，「下一步對不上」是 0（v11g0 smoke 的 tally：replans 0），重搜來自 1、2。
  2026-11-14 的 profile：SL 一局 98 % 的時間在戰鬥計畫。

## 2. 設計

- 每場戰鬥一份**回合記憶**：從一個狀態搜到回合結束的結果（`TurnSearch`），以狀態本身為鍵：`TurnEnd.Key`
  （觀察加完整隱藏狀態的雜湊；束本來就用它判定兩個狀態是不是同一個）加上敵人招式紀錄（leaf 會讀）。計畫的根用同樣的方式算鍵。
- 一回合的搜尋只讀這些：狀態、招式紀錄、每個狀態的節點數（同一個房間的預算固定）、leaf（同一條路線的網路固定）。
  所以命中拿到的，和當場再搜一次一模一樣：有記憶的計畫和沒有記憶的計畫逐位元相同。這是純快取，不改任何一個決定。
- 存完整的結果（每個結尾都留），讀的時候照當下的束寬裁（`SlPlanner.Narrow`，dive 現在就是這樣用的）：
  同一個狀態，不管之後被哪個寬度問到都能用。它取代 `_searched`：從「每個計畫、按路徑」改成「每場戰鬥、按狀態」。
- 放在 `SlRoute`（每局一條）。戰鬥結束時清掉，和 Dispatcher 在宏觀決定後重置招式紀錄是同一個時機。
- 三種世界都適用：引擎（`EnginePlanner`）、replay（`PooledPlanner`，在 worker 上）、以卡牌提示為根的計畫
  （`PromptRoot`：提示那一回合在 clone 上過，之後是引擎）。命中的回合不必建世界，也不必送 worker。
- 效果是：一次重搜只付「真的沒搜過的狀態」的錢。對不上之後如果狀態又回到舊計畫搜過的地方，後面的回合全部命中；
  輸的計畫每回合重搜時，新束和舊束重疊的狀態不再搜，只搜新根往下多看到的部分。

## 3. 步驟

1. **先量值不值得**，只加計數、不改搜尋：記憶照存，每個回合照樣搜，記下「這回合本來可以命中」的次數和省下的節點。
   本機跑，各角色 A10 一個種子、冠軍那一對：
   - mod 的打法：max；
   - self-play 的打法：medium。

   回報每局的計畫數、重搜的原因分布、可以命中的節點佔全部的比例、記憶有多大。用戶看了數字再決定做不做第 2 步。
2. **用記憶**：`SlPlanner.Search` 收一份記憶，`Beam.Search` 先查記憶，沒有的才送 `TurnSearcher`；
   `PlanTally` 加上命中的回合數和省下的節點，跑的紀錄裡看得到。
3. **驗**：
   - 一樣：同一批種子，有記憶、沒記憶各跑一次，決策日誌用 `same-decisions` 比，必須 0 差異
     （max 和 medium 各幾局）。決定不變，所以不必跑 test。
   - 快：同一批局的計畫 CPU 時間，前後對照。
4. **上線**：mod 請發版 session 打包（版本號規則）；self-play 下次部署時帶上，跑到一半的 v11g0 不受影響。

## 4. 不在這份裡

- NoSL 的 PIMC、宏觀決定在 clone 上的搜尋、開戰那一個計畫。
- 引擎裡其他會讓 hook 暫停等玩家的地方（死亡時、回合結束時、清手牌前等）：模擬器已改走真遊戲的路，
  parity 在那些地方出現差異時再修。
