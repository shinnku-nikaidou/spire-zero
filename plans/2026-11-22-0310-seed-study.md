## 0. 一頁看完

- **現在怎麼打**：每個種子打一次，探索是一路上隨機抽的（ε 的均勻抽、τ 的 softmax），V 的標籤是那一局最後的結局。
  一個選項值多少，只能拿「抽到它的局」和「沒抽到的別的局」比，兩邊是不同的種子、不同的後來。V 討厭的牌幾乎只靠
  抽籤進牌組（tmp/v-disliked-cards/REPORT.md：一張約 41 次），而那些抽籤是以前較弱的網路打的。
- **提議**：把一個種子打成一棵樹。主幹是冠軍自己打（不抽籤）；在挑出來的決定上，把每一個別的選項都從那個決定接著
  打到局末，也是冠軍自己打、不抽籤。同一個決定的幾個選項就在同一個狀態、同一個種子上比，各自的結局是各自的標籤。
- **機制**（2.1）：從 SL 每個決定本來就帶著的 node clone（node 的存檔 + 之後的步驟）載入，第一步強制成那個選項，打到底。
  `rollout` 已經會從 clone 把一局打完，差別只是它會重抽亂數；`run --check` 驗的就是 clone 和原局一模一樣。
- **什麼固定、什麼會動**（1.1、1.2）：地圖、每幕的怪和事件順序、Boss、走同一條路時的卡牌獎勵、金幣、藥水、事件的選項
  都不動；戰鬥裡的亂數（洗牌、怪的招式、隨機目標）是整局共用的流，牌組多一張牌，下一場戰鬥就不一樣。路線一分開，
  之後的房間也跟著不一樣：差一張牌的兩局，50 個種子裡 33–41 個會選不同的路，約四成在第一幕。配對讓勝場差的變異數小 1.3–2.2 倍。
- **在哪裡分叉**（2.2）：均勻抽，每局 k 個卡牌獎勵，每個結果（每張牌、跳過）都打。不看 V 的值，也不看牌單：規則只決定
  在哪裡比，不決定什麼好。一個卡牌獎勵平均有 1.5 張是 V 特別討厭的 Silent 牌，所以均勻抽就常常比到它們。
- **怎麼打**（2.3）：主幹和分叉同一個思考深度；照用戶的「只能在 max 裡面糾正」，提議 xhigh。
- **訓練**（2.4）：分叉點以後的決定照常是 V 的樣本，標籤用分叉自己的真實結局，不 bootstrap（凍結的 V 就是有偏見的那個）；
  主幹和它的分叉用同一個 run id 分留出、分摺。
- **日誌**（2.5）：每個 macro 決定記畫面上的選項、V 給每個選項的值、抽籤的種類；分叉的紀錄記它從哪個決定、哪個結果分出。
- **成本**（3）：一個卡牌獎勵分叉約 0.62 局（1.3）。k = 2，一個種子約 4.7 局；2,000 個種子在 medium 約 7 小時，xhigh 約 20 小時。

## 1. 量到的

### 1.1 程式裡：一個種子上什麼固定、什麼會動

遊戲的亂數是一條條命名的流（`RunRngType`、`PlayerRngType`），存在存檔裡，用一次往下走一次。分叉不重抽，所以兩個分叉
開頭的每條流都一樣，之後各走各的：

| 東西 | 從哪裡來 | 兩個分叉之間 |
|---|---|---|
| 每幕的地圖 | 種子 + 第幾幕（`StandardActMap`：`act_N_map`），進一幕時生成 | 不動 |
| 每幕普通戰鬥、精英、事件的順序，Boss，遺物袋 | 開局時 UpFront 流一次排好 | 不動：第 k 場普通戰鬥還是同一個遭遇（路線不同時落在不同層） |
| ? 房變成什麼 | 整局一條 UnknownMapPoint 流，每進一個 ? 抽 | 走同一條路就不動 |
| 卡牌獎勵、金幣、藥水、遺物稀有度 | 每個角色一條 Rewards 流：戰鬥獎勵、進商店、寶箱的金幣才抽；選牌、買東西、休息不抽 | 走同一條路就不動。卡牌獎勵不看牌組（`CardFactory.CreateForReward` 只看人數和模式），會被遺物改（稜鏡碎片之類） |
| 事件的選項 | 種子 + 座位 + 事件 id | 不動（能不能選看金幣、HP） |
| 商店 | 每個角色一條 Shops 流，每進一家抽 | 走同一條路就不動；刪牌的價錢看刪過幾次 |
| 戰鬥：洗牌、怪的招式、隨機目標、戰鬥中生成的牌和藥水、隨機能量 | 整局各一條流（Shuffle、MonsterAi、CombatTargets……） | **會動**：洗牌是 Fisher–Yates，多一張牌就多抽一個數，下一場開始整條流錯開；怪的招式每回合抽，戰鬥長短一不同也錯開 |

seed-scout 的「What shifts what」是同一份結論，2026-11-04 在一局真實的三人遊戲上逐層對過。

所以兩個分叉共同的是「世界」（地圖、遇到什麼、給什麼），不同的是戰鬥裡的運氣和之後的選擇。

## 2. 設計（提議）

### 2.1 機制：從 clone 分叉

- 主幹照現在的 `run` 打。到了分叉點（2.2），記下這個決定的 node clone（node 的存檔 + 從 node 到這裡的步驟；SL 每個決定
  本來就帶著，`RunSession.Clone`）和它的每個結果。
- 主幹打完以後，同一個行程依序打它的分叉：載入 clone（`RunSession.Load`，open，不重抽亂數：`rollout` 的路，少了
  `Redraw`），第一步強制成那個結果，之後冠軍自己打到局末。一個 chunk 是一個種子的主幹加它的分叉，hub 和 box.py 的派發
  不用改。
- 卡牌獎勵的結果是「拿第 i 張」或「跳過」，跟現在均勻抽籤抽的是同一件事（`MacroDraws.CardReward`：在獎勵畫面就定了
  開不開、開了拿哪張）。強制就是把這個抽籤換成給定的結果。
- 主幹自己選的那個結果不用再打：同一個 clone、同一步，打出來就是主幹（`run --check` 驗的就是這件事）。
- 要寫的地方：重播和強制的步驟不經過 brain，要讓 brain 知道這些狀態已經決定過（`MacroBrain` 的 `_decided`，它防止跳過的
  卡牌獎勵被再打開）。不加的話，「跳過」的分叉回到獎勵畫面時會再打開獎勵拿牌。
- 不選的兩個做法：
  - **從頭重打，在第 d 個決定強制**：新東西最少（包住 brain 的一層），同種子同 run id 本來就一模一樣；但每個分叉要把前面
    那段（含它的戰鬥搜尋）再打一次：一個卡牌獎勵分叉要 1 局，從 clone 是 0.62 局（1.3），貴約六成。
  - **每層把戰鬥的亂數按（種子、層）重設**，讓兩個分叉的戰鬥運氣也對齊（common random numbers）：要改遊戲的亂數用法；
    洗牌對大小不同的牌組還是不一樣，只對齊得了怪的招式這一類。1.2 的數字看起來不需要。

### 2.2 在哪裡分叉、分幾支

- **提議 B：每局均勻抽 k 個卡牌獎勵（k = 2），每個結果都打**（3 張牌加跳過，3 個分叉）。抽籤用 run id 的亂數（和 ε 的抽籤
  同一種），不看 V、不看牌。
- A：每局每個卡牌獎勵都分（Silent 一局約 15–19 個）。資料最多，一個種子的成本變成約 1 + 19 × 3 × 0.62 ≈ 36 局（1.3）。
- C：從所有 macro 決定（地圖、休息、商店、事件、卡牌獎勵）均勻抽 k 個；選項多的（商店）一個點最多打 M 個，也是均勻抽。
  用戶這次說的是選牌，所以先 B；C 留給之後。
- 不用的規則：
  - 「V 的選項接近的地方」：V 討厭的牌比跳過低 5–7 個點，永遠不會被挑到，而那正是要修的。
  - 「V 估得比打擊低的牌」（tmp/v-disliked-cards/strike-tables.md）：均勻抽已經常常碰到它們，不用另外挑：V 特別討厭的
    Silent 牌（90 % 以上的狀態低於跳過、有出現次數估計的 59 張）加起來，一個卡牌獎勵平均有 1.5 張是它們。
- 碰到的次數：先導打擊、刀刃之舞、匕首雨各約出現在 7–8 % 的卡牌獎勵裡；稀有的少，刀刃陷阱、追蹤、腐蝕波約 1.1–1.2 %
  （v-disliked-cards 的估計）。k = 2、2,000 個種子是 4,000 個分叉點：先導打擊約 290 個，刀刃陷阱約 50 個。
  稀有牌要更多，靠 2.6。

### 2.3 主幹和分叉怎麼打

- **不抽籤**：主幹 ε 0、τ 0，分叉強制的那一步以後也不抽。每個標籤都是「這一步 + 冠軍自己打完」，沒有之後的抽籤混進來
  （記憶 explore-cut-point-deferred 說的標籤問題）。這就是 2026-10-30 提過、用戶兩次說先不做的切點（切點前隨機、切點後
  V 自己選），不同的是同一個狀態的每個結果都打，不是隨機抽一個。
- **思考深度**：主幹和分叉一樣。提議 **xhigh**：用戶說這個偏見只能在 max 裡糾正、medium 的 c 不會打（小刀是回合中途進手的
  牌，束把它們排在最後，11-18 只在 max 修了），而 xhigh 是用戶指定給訓練資料的。medium 便宜約 3 倍（3），但在 medium 下
  比出來的是 medium 打得好不好，很可能又證實 V 現在的偏見。
- **和 silent-shiv-poison 的加分檔位**：可以疊（主幹用加分檔位，分叉照主幹的檔位打），提議先不疊，一次只動一件事。

### 2.4 怎麼進 V 的訓練

- **樣本**：分叉從強制那一步以後的每個 macro 決定，和主幹的一樣是樣本，標籤是分叉自己的結局（贏、死在第幾層）。強制的那個
  決定本身不算（它的畫面就是主幹的，選之前的狀態）；之後的第一個決定已經帶著那個結果（拿了的牌在牌組裡），就是它的後狀態。
- **權重**：現在每局同權（一局的決定平分一份）。分叉的每個決定和它主幹的每個決定同權，分叉越短份量越小，局末分出來的短
  分叉不會壓過整局。
- **留出、摺**：分叉用主幹的 run id（紀錄多一個 `branch` 欄位），和主幹一起留出（id % 5 == 0），一起在同一摺。不這樣，
  同一個種子的分叉會一半在訓練一半在留出，留出就不乾淨了。
- **真實結局，不 bootstrap**（不加 `--bootstrap`、`--horizon`）：td4 從第 4 層以後用凍結 V 的值，凍結的 V 就是討厭這些牌的
  那個，偏見會從標籤漏回來（silent-shiv-poison 2.6 同樣的理由）。這一批的主幹也用真實結局，一個種子不混兩種標籤。
- **配對的損失**（提議先不加）：現在的損失一個樣本一個樣本算。這批資料已經去掉了「只在 V 想拿的時候才拿」的偏差（記憶
  onpolicy-data-confounds-v），但沒用到配對：同一點兩個結果的結局差，比兩個結局各自穩（1.2 量的就是這個比）。可以加一項
  只看同一點兩個結果 V 的差和結局的差。先量 2.7，再決定。
- **c**：分叉的戰鬥也是 c 的資料，和主幹的一樣。V 和 c 一起訓練、一起測試、一起晉升或一起放棄。

### 2.5 日誌

現在缺的（tmp/v-disliked-cards/REPORT.md 找到的）：macro 決定的日誌沒有畫面上的選項，也沒有 V 給每個選項的值
（`candidates` 是空的）；均勻抽和 softmax 抽都只記 `explored: true`。要加：

- **每個 macro 決定**（所有自我對局都該有，和分叉無關）：畫面上的選項（卡牌獎勵的牌和升級、獎勵畫面的每一項、商店的每一格、
  事件的選項，就是 `--obs` 印的 screen），V 給每個選項的值（brain 已經算好、送給 mod 的 `Scored`），抽籤的種類
  （`drawn: uniform | softmax`，取代只有一個的 `explored`）。一局多幾十 KB；日誌現在一局約 1.6 MB。
- **分叉**：紀錄和日誌帶 `branch: {decision, outcome}`（從主幹的第幾個決定、哪個結果），run id 用主幹的。
- **能回答什麼**：每個分叉點都有 V 給每個結果的值、每個結果實際的結局、當時的牌組。回答的是 V 錯在哪：V 說拿 X 比跳過差
  5 個點，同一個點拿 X 和跳過的分叉打出來怎樣；如果拿 X 的分叉也輸，問題在 c 怎麼打 X（像小刀被排在最後），不在 V。
  牌強不強是用戶判斷的，這些數字不拿來檢查用戶的判斷。
- **「X 比不比打擊」**：打擊不會出現在卡牌獎勵裡，分叉比不到；要比只能用起始牌組（2.6）。

### 2.6 自訂起始牌組（用戶 11-20 的另一個提議）

- `run --deck` 已經有，1.2 就是這樣打的，不用寫程式。同一個種子：原樣、多一張打擊、多一張 X，從第一層就比「多 X」和
  「多打擊」。
- 和分叉的差別：牌是人放的，局面不是遊戲自己會走到的（第 0 層就有一張稀有牌）；分叉點是遊戲自己走到的。提議先分叉；
  稀有牌在分叉裡碰得太少時，用這個補。
- 進資料集檔：box.py 的列多一個 `deck` 鍵，或像 1.2 一樣手動 `box.py run`。

### 2.7 V 在分叉上的錯（測試以外另外量）

- 留出種子的分叉點，只看結局不同的兩個結果（一個贏、一個輸）：V 把贏的那個排在前面的比例。訓練前（d2）、訓練後各量一次，
  按角色、按「V 估得比打擊低的牌」分開列。
- 測試照舊：medium，配對勝場，報告先講勝場。

### 2.8 種子

- ledger 的 6200000–6299999 給這條線（現在只有 Silent），1.2 用了 6200000–6200049。分叉用主幹的種子，不另外拿；
  測試的種子（promotion-1-200 等）不碰。smoke 從 +99,000（box.py 的規矩）。

## 3. 成本

- 一個種子（B）：主幹 1 局，加 k 個分叉點 × 3 個分叉 × 0.62 局（1.3）。k = 1：2.9 局；k = 2：4.7 局；k = 4：8.4 局；
  A（每個卡牌獎勵）：約 36 局。
- 池子的量：v11g0-td4-high 在現在池子裡的這幾台（pushqkzh、pusheen、ds6754、gcpsg、cshinnku、hostc）16.5 小時打了 22,656 局
  medium，約一小時 1,400 局。xhigh 一局約是 medium 的 3 倍（粗估：xhigh 自己打 9 局平均 418 秒，plans/2026-11-21-1426-xhigh-early-stop.md
  3.4；medium 1.2 的 150 局平均約 160 秒；機器不同），約一小時 470 局。
- Silent、B、k = 2：

  | 種子 | 分叉點 | 局（主幹 + 分叉） | medium | xhigh |

  | 500 | 1,000 | 2,350 | 約 1.7 小時 | 約 5 小時 |

  變異數 0.17–0.30，要看出 5 個點的差（2 個標準誤）約要 400 對；所以單張牌的數字要幾百個點才穩。V 不需要一張一張的結論

## 4. 等用戶定的

1. **做不做**：寫 2.1（分叉）和 2.5（日誌）的程式。日誌那一半不分叉也有用。
2. **規則**：B（每局 k 個卡牌獎勵，提議 k = 2）、A（每個卡牌獎勵）或 C（所有 macro 決定）。
3. **思考深度**：xhigh（提議）或 medium。
4. **主幹抽不抽籤**：提議不抽，探索全靠分叉。
5. **角色**：先 Silent（像 silent-shiv-poison），或六個角色。
6. **局數**：幾個種子（3 的表）。
7. **和 silent-shiv-poison 的關係**：那份計畫的第 4 步（xhigh 的 Silent 生成，加分檔位）還沒開。兩個都要下一批 Silent 的資料：
   合成一批（加分檔位當主幹，再分叉）、先做哪一個，或只做一個。
8. **配對的損失**：提議先不加，看 2.7。

## 5. 步驟

1. **日誌**（2.5）：macro 決定的選項、每個選項的值、抽籤的種類。測試：同一個種子新舊兩版的決定逐筆一樣（`same-decisions`），
   只多了欄位。
2. **分叉**（2.1）：`run` 的分叉規則（2.2）、強制的結果、`branch` 欄位；`learn/v` 讀分叉（權重、留出、摺，2.4）。測試：
   主幹自己的結果打成分叉，和主幹逐筆一樣；跳過的分叉不會再打開獎勵；分叉 replans 0；留出和摺跟著主幹。
3. **smoke**：幾個種子，k = 2，看每個分叉點有 3 個分叉、紀錄和日誌對得上。
4. **生成**（用戶的話）：3 的局數。
5. **訓練**（用戶的話）：2.4。
6. **測試**（用戶的話）：medium 配對勝場，加 2.7。
