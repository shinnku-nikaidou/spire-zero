## 1. 量到的

### 1.1 程式裡：一個種子上什麼固定、什麼會動

遊戲的亂數是一條條命名的流（`RunRngType`、`PlayerRngType`），存在存檔裡，用一次往下走一次。同一個種子打兩遍，開頭的每條流
都一樣，之後各走各的：

| 東西 | 從哪裡來 | 同一個種子的兩局之間 |
|---|---|---|
| 每幕的地圖 | 種子 + 第幾幕（`StandardActMap`：`act_N_map`），進一幕時生成 | 不動 |
| 每幕普通戰鬥、精英、事件的順序，Boss，遺物袋 | 開局時 UpFront 流一次排好 | 不動：第 k 場普通戰鬥還是同一個遭遇（路線不同時落在不同層） |
| ? 房變成什麼 | 整局一條 UnknownMapPoint 流，每進一個 ? 抽 | 走同一條路就不動 |
| 卡牌獎勵、金幣、藥水、遺物稀有度 | 每個角色一條 Rewards 流：戰鬥獎勵、進商店、寶箱的金幣才抽；選牌、買東西、休息不抽 | 走同一條路就不動。卡牌獎勵不看牌組（`CardFactory.CreateForReward` 只看人數和模式），會被遺物改（稜鏡碎片之類） |
| 事件的選項 | 種子 + 座位 + 事件 id | 不動（能不能選看金幣、HP） |
| 商店 | 每個角色一條 Shops 流，每進一家抽 | 走同一條路就不動；刪牌的價錢看刪過幾次 |
| 戰鬥：洗牌、怪的招式、隨機目標、戰鬥中生成的牌和藥水、隨機能量 | 整局各一條流（Shuffle、MonsterAi、CombatTargets……） | **會動**：洗牌是 Fisher–Yates，多一張牌就多抽一個數，下一場開始整條流錯開；怪的招式每回合抽，戰鬥長短一不同也錯開 |

seed-scout 的「What shifts what」是同一份結論，2026-11-04 在一局真實的三人遊戲上逐層對過。

## 2. 設計（提議）

### 2.1 不分叉（用戶 2026-11-22 定的）

第一版在卡牌獎勵分叉：從那個決定的 node clone 把每個結果都打到局末。用戶問「分岔真的需要嗎?」，聽了「V網路卡價值判斷問題」那個
session 的回答以後說「改成不分叉」。那個回答（它的理由，用戶接受了）：

- 一次均勻抽籤加上冠軍自己打完，本來就是隨機分派的比較，跨不同的種子也誠實。V 的偏見來自冠軍自己的選擇、softmax 的抽籤（照 V 的值）、
  和以前的網路在抽籤之後接著打，不是來自跨種子比。
- 分叉只換來效率：1.2 量到的配對讓勝場差的變異數小 1.3–2.2 倍。按算力算，拿到某張牌的次數差不多：Silent 2,000 個種子、k = 2，
  分叉約 4,000 個點；同樣的算力打 9,400 局普通的，每局抽 2 次、每次在約 4 個結果裡抽一個，乘起來約 4,700（分叉 4,000），都再乘上那張牌出現的比例。沒有配對的損失時，V 讀一個分叉
  就跟讀一局一樣。
- 分叉要新東西：模擬器從 clone 分出來、保留亂數，分叉的 id；`learn/v` 按樹分留出和摺。照記憶 low-coupling-simple，1.3–2.2 倍不值得。
  如果之後一張一張牌的數字太吵，再加分叉。

**拿掉的**：從 clone 分叉的機制（第一版 2.1）、`branch` 欄位、按樹分留出和摺、分叉的權重、配對的損失。

### 2.2 怎麼抽：只在卡牌獎勵的 ε

- **做法**：一個新的 run 選項（名字未定，例如 `--explore-card-rewards ε`），用的是現在 `--explore` 在卡牌獎勵的那一段抽籤
  （`MacroDraws.CardReward`）：每個卡牌獎勵第一次出現時，機率 ε 抽一次，在它的每張牌和跳過之間均勻抽（獎勵畫面上就定了開不開、
  開了拿哪張），其他畫面和選牌提示都不抽（`MacroDraws.Even` 不用）。沒有 `--explore`，沒有 `--macro-explore`。brain 的名字多一段，
  box.py 的檔位多一個鍵。
- **ε 多少**：k / 一局的卡牌獎勵數。Silent A10 一局約 20.5 個（1.3），k = 2 是 ε ≈ 0.1。每局抽到幾次是二項分布：平均 2，有的局 0 次、
  有的 4 次。
- **為什麼用 ε 不用「每局固定 k 個」**：
  - 一局不知道自己會有幾個卡牌獎勵（會死），固定 k 個得先挑第幾個，早死的局用不完，抽籤會偏到前面的獎勵；
  - ε 是現成的抽法（`Uniform.Draw`，用 run id 的亂數），每個卡牌獎勵被抽到的機會一樣，不看 V、不看牌、不看局面；
  - 程式只要把抽籤限在卡牌獎勵一處。
- **抽籤以外的決定**：都是冠軍自己的選擇（和 4.2 合併時，是加分檔位下的冠軍）。

### 2.3 怎麼打

- **思考深度**：xhigh。用戶說這個偏見只能在 max 裡糾正、medium 的 c 不會打（小刀是回合中途進手的牌，束把它們排在最後，11-18 只在
  max 修了），而 xhigh 是用戶指定給訓練資料的。medium 便宜約 3 倍（3），但在 medium 下比出來的是 medium 打得好不好，很可能又證實 V
  現在的偏見。
- **和 silent-shiv-poison 的加分檔位合併**（4.2）：那份計畫第 4 步是 Silent 的 xhigh 生成，四個檔位（小刀版、毒版、混合版、普通版），
  每個檔位有 ε 和 τ。合併就是同一批：檔位的加分和不拿照舊，ε、τ 換成 2.2 的卡牌獎勵抽籤。
  - 好處：一局只抽兩次，一副牌裡要重置的牌大多只有一張；要幾張一起才強的（小刀一家）只有加分檔位做得出來。
  - 要知道的：「不拿」會蓋掉抽到的答案（silent-shiv-poison 2.2：抽到的答案會讓不拿的牌進來時，改成不會的選項裡值最高的）。所以
    小刀版裡抽不到毒牌，毒版裡抽不到小刀牌；這兩家要重置的牌（小刀一家 8 張、毒一家 2 張）只在四個檔位裡的三個被抽到。
  - 加分檔位裡冠軍自己拿的牌是照 V + 加分拿的，不是隨機分派；隨機的比較只來自抽籤。

### 2.4 怎麼進 V 的訓練

- **樣本、權重、留出、摺**：和現在一樣，每局一份，run id % 5 留出。
- **真實結局，不 bootstrap**（不加 `--bootstrap`、`--horizon`）：td4 從第 4 層以後用凍結 V 的值，凍結的 V 就是討厭這些牌的那個，
  偏見會從標籤漏回來（silent-shiv-poison 2.6 同樣的理由）。
- **標籤裡還有之後的抽籤**：抽到的一次之後，同一局平均還有一次抽籤（k = 2），也進了標籤（記憶 explore-cut-point-deferred）。比現在
  每個決定都可能抽、還有 softmax 少得多。
- **c**：這一批的戰鬥也是 c 的資料。V 和 c 一起訓練、一起測試、一起晉升或一起放棄。

### 2.5 日誌

現在缺的（tmp/v-disliked-cards/REPORT.md 找到的）：macro 決定的日誌沒有畫面上的選項，也沒有 V 給每個選項的值
（`candidates` 是空的）；均勻抽和 softmax 抽都只記 `explored: true`。要加（所有自我對局都該有）：

- 畫面上的選項：卡牌獎勵的牌和升級、獎勵畫面的每一項、商店的每一格、事件的選項（就是 `--obs` 印的 screen）。
- V 給每個選項的值（brain 已經算好、送給 mod 的 `Scored`）。
- 抽籤的種類：`drawn: uniform | softmax`，取代只有一個的 `explored`。這一批只有 uniform，舊的資料集分不開的問題以後不再有。
- 一局多幾十 KB；日誌現在一局約 1.6 MB。
- 有了這些，每次抽籤都知道畫面上有哪幾張、V 給每個結果多少、抽到哪一個、這一局最後怎樣。能回答的是 V 錯在哪（2.7）；如果拿某張牌的局
  也輸，問題在 c 怎麼打它（像小刀被排在最後），不在 V。牌強不強是用戶判斷的，這些數字不拿來檢查用戶的判斷。
- 「比不比打擊」：打擊不會出現在卡牌獎勵裡，抽籤比不到；要比只能用起始牌組（2.6）。

### 2.6 自訂起始牌組（用戶 11-20 的另一個提議）

- `run --deck` 已經有，1.2 就是這樣打的，不用寫程式。同一個種子：原樣、多一張打擊、多一張 X，從第一層就比「多 X」和「多打擊」。
- 牌是人放的，局面不是遊戲自己會走到的（第 0 層就有一張稀有牌）。提議先用抽籤；稀有牌抽得太少，或要幾張一起的牌組時，用這個補。
- 進資料集檔：box.py 的列多一個 `deck` 鍵，或像 1.2 一樣手動 `box.py run`。

### 2.7 V 在抽籤上的錯（測試以外另外量）

- 留出的局裡抽到的卡牌獎勵：拿了 X 的、跳過的、拿了同一個畫面上別張的，各自贏了多少，照房間種類和層分層比（v-disliked-cards 的做法：
  只照幕分層會被精英和 Boss 的獎勵帶偏）；旁邊放 V 在那些畫面給每個結果的值。
- 訓練前（d2）、訓練後各量一次，按「要重置的牌」和其他的牌分開列。

### 2.9 訓練前，重置要重置的牌在 V 裡的列（用戶 2026-11-22 定的）

- **哪些牌**：`tmp/v-disliked-cards/reset-ids.json`，按角色，是兩組的聯集：
  - 冠軍 V 估得比自己角色的打擊低的自己的牌，基本或升級版有一個低就算（`tmp/v-disliked-cards/STRIKE.md`）；
  - spire-codex.com 評 S 或 A、V 在多數狀態寧可跳過的牌（`tmp/v-disliked-cards/TIERS.md` 的「站上 S/A，V 多半寧可跳過」）。

  SILENT 30、IRONCLAD 15、DEFECT 15、REGENT 24、NECROBINDER 12、FOOL 17，共 113 張。
- **只重置這一批有的角色**（4.1）：一批只有 Silent，就只重置 Silent 的 30 張；別的角色的牌在這一批裡抽不到，重置了只會讓它們回到起點、
  沒有資料拉回來。
- **重置什麼**：V 的卡牌列按 id 存（`learn/v/net.py` 的 `cards`、`card_up`、`card_damage`、`card_block`、`card_grown`），所以一張牌的
  基本和升級版一起重置。同一列也用在 V 讀留著的牌和事件選項提到的牌，那裡也跟著變。只動 V；c 和 f 是各自的網路，不動。
- **什麼時候**：V 從 d2 接著訓練（2.4），重置在載入 d2 之後、第一步之前，只做一次。生成之前不重置：這一批照冠軍 d2 打，抽籤不管 V 怎麼估，
  所以重置不改資料，只改 V 從哪裡學起。
- **重置成什麼**（用戶選）：
  - **甲：新網路的隨機列**（`Body` 的初始化，常態分布 std 0.1；`learn/carry.py` 給全新的表 FRESH 也是這樣）。理由：和 V 第一次訓練時
    每一列的起點一樣，舊的值一點不留。缺點：每張牌的起點是隨機的，有的高有的低；抽到少的牌訓練完還帶著這個隨機起點。
  - **乙：表的第 0 列**（`<unk>`，「讀任何表上沒有的 id」那一列；carry.py 給新牌就是這一列，「舊網路怎麼讀它不認得的牌」）。理由：
    要重置的牌起點都一樣，沒有牌碰巧被抬高或壓低；遊戲更新時新牌一直是這樣接上的。缺點：這一列值多少沒量過。2026-11-13 FOOL 的牌
    剛接上時全讀成這一列，那時 V 跳過 FOOL 所有的卡牌獎勵，所以它一開始可能也很低。
  - **丙：自己角色的打擊那一列**：起點就在「不該比打擊差」上。缺點：等於把用戶的判斷放進起點；而且事後「比打擊差的少了沒」量不出
    什麼（一開始就和打擊一樣）。
  - 我提議乙：不靠隨機，也是現成的規則。不管選哪個，重置完先量起點（下面「怎麼查」第 1 步），用戶看過再訓練。
- **抽籤怎麼碰到這些牌**：
  - 重置後的 V 自己還是不會拿：打擊本身在每個抽樣的狀態都比跳過低 2.6–4.7 個點（STRIKE.md），從乙或丙起步也一樣。但這一批不是它打的，
    而且抽籤不看 V。
  - 次數：一局抽 k 次，每次在約 4 個結果裡均勻抽，所以 N 局裡 X 被抽中拿了約 N × k × X 出現的比例 / 4 次。出現的比例用 v-disliked-cards
    的估計（v9g2 的均勻抽籤）：Silent 要重置的 30 張在 0.87 %（MASTER_PLANNER）到 9.1 %（RICOCHET）的卡牌獎勵裡出現，中位數 2.3 %；
    最少的還有 BURST、FAN_OF_KNIVES 0.92 %，SHADOW_STEP 0.98 %。數字見 3 的表。
  - 抽到以後照冠軍打到局末，之後的每個決定都是牌組裡有這張牌的樣本。
  - 一局抽兩次，所以這一批的牌組裡要重置的牌大多只有一張；幾張一起的靠 4.2 的加分檔位，或 2.6 的起始牌組。
  - 商店裡的和選牌提示裡的這些牌不抽（2.2 只抽卡牌獎勵）。
  - 下一輪：訓練後的 V 如果把它們估到跳過以上，冠軍自己就會拿。
- **怎麼查**（和 2.7 一起）：
  1. **起點**：重置後、訓練前的 V，在 v-disliked-cards 同一批抽樣狀態上（v11g0-td4-high，Silent 4,509 個）跑 `strike.py`：每張要重置的牌
     比打擊幾點、在幾成狀態低於打擊。
  2. **訓練後**：同一批狀態再跑一次。表：這個角色自己的牌比打擊差的張數（未升級 / 升級版），d2（STRIKE.md）、重置後起點、訓練後三欄；
     每張要重置的牌「比打擊」的三個數；TIERS.md 那一組是不是還在多數狀態寧可跳過。
  3. 同樣的表，在這一批自己留出的局的狀態上再做一次（抽樣狀態是舊資料的）。
  4. 抽中拿了不到 50 次的牌另外列：它們的數字大半還是起點。
  - 這是看 V 動了沒有，不是驗用戶對牌的判斷；晉升照舊看測試的配對勝場。量法和 v-disliked-cards 一樣，pushqkzh 的 GPU 幾分鐘。
