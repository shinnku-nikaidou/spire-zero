# 礦池式任務中心：怎麼把遊戲送到機器上（2026-11-01 12:52 台灣時間）

這份只回答「遊戲檔案怎麼到 worker 上」。任務分發協定和分批上傳等這份定案後再談。

**你的決定（同日）：礦池只給你自己的機器，由我直接把可執行程式推過去。** 所以只做 §3 的來源 C；來源 A、B、參與者的安裝流程和防假資料都不做。下文保留當時的比較。

**之後的改動（同日）：來源 C 不是推送，也不再是「沒有下載網址」。** 你要求把可執行程式放在 hub、用私有 `x-api-key` 才能下載，並在 Colab 上跑。實作是 `store/dist.py`、`store/dist-admin.py`、`store/install.sh` 和 `distro/sts2_worker.ipynb`，說明在 fleet skill 的 `references/store.md`。所以 §3 來源 C 裡「不存在任何下載網址」「hub 也不存放遊戲檔」已不成立。

**結論：** 模擬器只需要 10 個檔案、18.6 MB，其中真正屬於遊戲本體的只有 `sts2.dll`（9.3 MB）。不必分送 2.1 GB 的遊戲。

**但公開的一鍵下載不能包含 `sts2.dll`。** 客戶端本身不帶遊戲，遊戲由每台機器從「擁有者自己的來源」取得，再用雜湊核對版本。要讓沒買遊戲的人也能一鍵開跑，需要 Mega Crit 的書面許可，這份設計不包含這條路。

## 1. 實測：模擬器到底要什麼

| 項目 | 大小 | 模擬器需要？ |
|---|---|---|
| `SlayTheSpire2.pck`（美術、音效） | 1,898 MB | 不需要 |
| `SlayTheSpire2`（Godot 主程式）、`libfmod*` 等 | 約 200 MB | 不需要 |
| `data_sts2_linuxbsd_x86_64/` 裡的 .NET 執行環境 | 約 80 MB | 不需要，用我們自己帶的 .NET 9.0.22 |
| 下面 10 個檔案 | **18.6 MB，zstd -19 後 4.4 MB** | **需要** |

```
sts2.dll  GodotSharp.dll  0Harmony.dll  Sentry.dll  Sentry.Godot.dll  Steamworks.NET.dll
SmartFormat.dll  SmartFormat.ZString.dll  System.IO.Hashing.dll  release_info.json
```

- **找法：** 只放 `sts2.dll`，缺什麼補什麼，直到跑得起來（`GameAssemblies.InstallResolver` 依名字到 `STS2_BIN_DIR` 找）。
- **`release_info.json` 要帶：** 少了它，紀錄的 `config.game` 會寫成 `unknown`。
- **驗證：** 同種子 2 局，10 個檔案和完整快照（206 個檔案）的 2 筆紀錄、406 行 log，只有 `elapsed_ms` 不同。
- **快照就是原版：** `tmp/gamebin/v0.111.0/sts2.dll` 和 Steam 安裝版的 SHA-256 相同（`2b40d2df…`），Steam buildid 24724944。
- **我們的 build 不含遊戲：** `Private=false`，輸出裡沒有 `sts2.dll`；約 31 MB。.NET 約 75 MB。
- **repo 也不含：** `tmp/gamebin`、`tmp/decompiled` 都被忽略，git 歷史裡也沒有。

**還沒驗證：** 上面只跑了 `--policy play --auto-win`，沒有真正打戰鬥。規劃器和兩個網路可能還會載入別的組件。正式改之前要做 §5 第 1 步。

## 2. 為什麼不能公開分送

我讀了 [Steam 訂閱者協議](https://store.steampowered.com/subscriber_agreement/) 的相關段落，重點（我的轉述，不是法律意見）：

- 授權是給個人、非商業使用，不能轉讓。
- 除非另有許可，不得複製、散布內容，也不得把複本轉給他人或出租。
- 帳號和密碼不得分享給他人使用。

**沒查到的：** Mega Crit 自己的條款和 mod 政策。我的網路搜尋工具這次失敗了，要另外確認。

所以各種做法的狀況是：

| 做法 | 判斷 |
|---|---|
| 公開連結下載含 `sts2.dll` 的客戶端 | **不做。** 這就是把遊戲散布給別人 |
| 把你的 Steam 帳號放到別人的機器上 | **不做。** 協議禁止，帳號也有風險 |
| 參與者用自己買的遊戲 | 可以，檔案來自他自己的授權 |
| 送到你自己租的機器（現在 `deploy.sh` 就在做） | 只有你一個人用，但協議沒有明文允許複製到伺服器。風險由你判斷，我能做的是不讓它變成任何公開端點 |
| 取得 Mega Crit 書面許可後公開分送 | 唯一能讓沒買遊戲的人一鍵開跑的路 |

## 3. 設計：客戶端不帶遊戲，一個核對點，三個來源

```
一鍵安裝的客戶端（不含遊戲）：.NET + 我們的 build + 網路權重，約 110 MB
        │
        ├─ 來源 A  本機 Steam 安裝        參與者的電腦
        ├─ 來源 B  SteamCMD + 自己的帳號   參與者自己的伺服器
        └─ 來源 C  你從自己電腦推送         你租的機器，沒有下載網址
        │
        ▼
核對 10 個檔案的 SHA-256 → 複製到 ~/.cache/sts2pool/game/v0.111.0/ → 回報版本給任務中心 → 開始領任務
```

### 核對點：`game-set.json`（進 git，只有檔名和雜湊，沒有內容）

```json
{ "version": "v0.111.0",
  "files": { "sts2.dll": "2b40d2df…", "GodotSharp.dll": "…" } }
```

- 每個工作綁定一個 `game` 版本。worker 報上版本和雜湊，對不上就不發任務，並說明原因。
- 這份設計不靠任何人的誠實：雜湊只保證版本正確，不判斷授權。授權靠「檔案來自哪裡」。

### 來源 A：本機 Steam 安裝

1. 讀 Steam 的 `libraryfolders.vdf` 和 `appmanifest_2868840.acf` 找安裝位置，也可用 `--game-dir` 指定。
2. 從 `data_sts2_linuxbsd_x86_64/` 和根目錄取這 10 個檔案，核對雜湊。
3. 複製到本機快取，之後 Steam 更新也不影響。檔案只留在這台機器。

### 來源 B：SteamCMD 和參與者自己的帳號

- 客戶端只印出指令，由本人輸入帳密和 Steam Guard，客戶端不經手、不保存：

```bash
steamcmd +@sSteamCmdForcePlatformType linux +force_install_dir ~/sts2-game +login YOUR_ACCOUNT +app_update 2868840 validate +quit
```

- 接著走來源 A 的流程。付費遊戲要登入擁有者帳號才下載得到。**這條指令我沒實測。**
- 缺點：要下載約 2.1 GB，而且拿到的是最新版，不一定是 v0.111.0。

### 來源 C：你自己租的機器

沿用現在的做法，只是檔案變少，而且**不存在任何下載網址**：從你的電腦一條指令推過去。

```bash
pool-join NEW --slots 27
```

它會做的事：SSH 連上、檢查工具、推 4.4 MB 的遊戲檔和客戶端、驗證、加入工作。對你來說就是一鍵；對外沒有任何可下載遊戲的端點。hub 也不存放遊戲檔。

## 4. 遊戲更新時

版本一定要固定，否則資料會混到不同平衡的遊戲。

| 情況 | 處理 |
|---|---|
| Steam 更新了，機器已有快取 | 繼續用快取，不受影響 |
| 新機器只拿得到新版 | 不能參加舊版工作，客戶端明確提示。可選用 SteamCMD 的 `download_depot` 指定舊版（沒實測） |
| 專案要升級遊戲版本 | 重新 build，新增一份 `game-set.json`，從下一代資料開始用，舊版工作不混 |

## 5. 實作步驟

1. **驗證最小集：** 在一台遠端主機用 `--policy plan` 加兩個網路，以 10 個檔案和完整快照各跑同樣的種子，比對紀錄和 log。約一個 slot 跑 10 分鐘。本機不跑。
2. 寫 `game-set.json` 和核對工具。
3. `deploy.sh` 改成只送這 10 個檔案。現有主機的舊快照不動，等沒有工作用它才清。
4. 做客戶端的遊戲來源 A，以及 `pool-join`（來源 C）。
5. 測試：一台乾淨的機器從零開始加入工作，這也補上 `box.py add` 還沒驗過的部分。來源 B 等真的有參與者再測。

## 6. 只影響這份設計的其他事實

- **平台：** 先只做 Linux x64。Windows 版的 `sts2.dll` 是否相同、模擬器能否在 Windows 跑，都沒量過。
- **我們的程式：** 客戶端會把 Sts2Ai 的編譯結果和網路權重發給參與者，repo 目前是私有的。讓別人參加就等於公開這些，要你決定。
- **結果可信度：** 只用自己的機器時不是問題。有外部參與者就要防假資料，這屬於下一份設計。
