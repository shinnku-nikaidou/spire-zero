# NoSL：在戰鬥等著的提示處抽世界，每個答案都搜（台灣時間 2026-11-21 12:13 起草）

來由：用戶問 NoSL 有沒有 SL 的賭博籌碼問題。沒有那個問題，但 NoSL 從來不用賭博籌碼：開戰時的棄牌提示永遠丟 0 張。
原因是 `EnginePimc.Decide` 遇到沒有計畫的提示就交給 `PimcBrain.Unplanned`，也就是 `FirstPicks`（前 `min` 個選項）；
`search/pimc.rs` 也拒絕從提示開始搜（「the middle of an action has no sample」）。

用戶的話（2026-11-21，看了第 1 節的數字之後）：

## 2. 為什麼不能照 SL 的修法

- 這些提示出現時，真實的戰鬥（模擬器的遊戲、mod 的遊戲）停在一個動作的中間；匯出只在兩個動作之間做得到，引擎接不進來。
- SL 的修法在節點的複本上跨過提示：每個答案在複本上照真的抽牌堆打下去，再匯出給引擎。NoSL 這樣做就是作弊：
  賭博籌碼丟牌之後抽到的牌、知識惡魔選完之後抽的整手牌，都會是真的。

## 3. 做法

### 3.1 引擎站到提示上

- 宿主（模擬器的 `RunSession`、mod）在戰鬥的提示處交給大腦（`PromptCombat`）：這場戰鬥裡它最後一次寫出的戰鬥和那時的 run，
  那之後的每一步（模擬器 trace 的寫法：`combat play:12`、`card_choice 2,0`，選牌是遊戲自己清單裡的位置，兩個宿主都已經這樣記），
  還有提示當下的抽牌堆公開紀錄（`DrawPileLog`）。引擎收遊戲清單位置的答案用新的寫法 `given:2,0`（`pick:` 是正規順序的位置）。
  引擎從那份匯出把這些動作重跑一次，就停在同一個提示上：引擎和遊戲同步（lockstep），
  隨機數也在戰鬥裡，所以跑出來的就是真實的戰鬥。
- 開戰的提示之前沒有任何一次匯出，所以宿主在每場戰鬥開始時多寫一份：`CombatManager.StartCombatInternal` 等完執行器
  （整局裡是進房間的地圖移動）、開始跑戰鬥的開場之前（它第一次 `AfterCreatureAdded` 的 Harmony prefix，模擬器和 mod 各一個），那時什麼都沒在跑。引擎從那裡自己開戰（已經翻譯的 `start_combat_internal`：
  戰鬥開始的 hook、第一回合的開始、抽牌、回合開始的 hook），新的入口 `sz_world_begin`。今天沒有任何東西走這條路，
  所以先驗它：parity 的 dump 多存每場戰鬥開戰時的匯出，引擎從那裡開戰後，第一個決定的觀察要和遊戲的一樣，fixture 裡的每一場（新的 `begin` 測試）。

### 3.2 在提示處抽世界

- 提示處的一個世界，是真實的戰鬥重跑到提示，再在提示那一刻把玩家看不見的東西重抽（`determinize`，用世界的種子和宿主送來的抽牌堆紀錄）。
- 引擎的提示是靠重跑做的（world.rs：每給一個答案，從動作之前或最後的恢復點重跑一次）。所以抽世界的點記在世界上：
  選牌入口（`get_selected_cards`，和 hook 直接等答案的那條路）在拿「抽世界那個提示的答案」之前先跑 `determinize`。
  每次重跑都經過同一點、用同一個種子，所以一個世界從頭到尾是同一個世界。
- 結果：提示之前看得到的都是真的（賭博籌碼給的那手牌、Havoc 翻出來的牌）；提示之後的都是抽的
  （丟牌後抽到的牌、知識惡魔選完後抽的手牌、所有隨機數、意圖看起來一樣的怪物下一招）。
- `search/pimc.rs` 不再拒絕從提示開始：根在提示上的話，每個世界照上面抽，其餘不變。

### 3.3 搜每個答案

- 第一步是提示的所有答案（`CardChoice.Answers`，同樣的牌只算一次），每個答案在每個世界都拿一個決定的全部節點（300），
  也就是答案之後的那一回合照一個決定的搜法搜；用 8 個世界的平均排答案，選最好的。和 SL 的修法同一個規則（每個答案搜自己的一回合）。
  只分一個決定的 300 個節點給全部答案的話，賭博籌碼平均每個答案 4 個節點，等於答完就結束回合，和 SL 當初「剩 0 HP」是同一個毛病。
- 花費（估）：v0g1-nosl 一個搜過的決定中位數 62 ms、平均 128 ms（8×300）。一個有 A 個答案的提示約等於 A 個決定：
  賭博籌碼平均約 10 秒，p99（512 個答案）約 65 秒；自我對局每局平均多約 1.6 秒（每局 0.16 次）。其餘來源多半 2–16 個答案。
- 範圍（用戶：「世界0的答案也搜」）：戰鬥停著的每一個提示（1 的 674,526 次，每局 9.4 次），在提示處抽世界、搜答案。
  `TurnPlan` 不再替 PIMC 留答案：搜尋的線裡第一步之後的答案只用來給第一步估值，真的提示來了再搜一次。
  只有每個世界都一樣、每一步的觀察都對得上的重複循環的計畫照舊（那是循環，不是單一世界的答案）。
- 世界 0 那 620,205 次的花費要量：每次乘上答案數，Survivor 這種 5 張手牌棄 1 張是 5 個決定。第 5 節記量到的。

### 3.4 測試（做完的標準）

- 引擎：一場帶賭博籌碼的戰鬥從開戰的匯出開始，停在棄牌提示；PIMC 從那裡給每個答案一條線，每條的值都是有限的。
- 不洩漏：在提示處抽 16 個種子的世界，提示看得到的每一欄和真實的一樣；同一個答案（全丟）之後，抽到的牌、抽牌堆的順序、
  隨機數、怪物排好的招，沒有一欄在每個世界都等於真實的（`leak_probe` 的比法，搬到提示處）。
- 知識惡魔的宰制：答案之後抽的手牌，跨種子不等於真實的那手。
- 回合結束後的提示（唯一的結束回合之後，例如 Toasty Mittens）：從上一次的匯出加結束回合重跑，同樣的兩條。
- C#：`EnginePimc` 在沒有計畫的提示處給每個答案一個 candidate，不再用 `FirstPicks`；模擬器和 mod 都送開戰的匯出和提示當下的抽牌堆紀錄。
- 引擎的測試、C# 的測試全過。
- 之後量：本機重播幾局 v0g1-nosl 有賭博籌碼的局，列出每次提示以前和現在丟什麼、那場戰鬥剩多少 HP（像 SL 那份的表）。

## 4. 不做的

- SL 不動（它在複本上跨過提示是對的：SL 本來就看真的）。
- mod 要出新版本才會帶這個改動；版本號由發版的 session 給。
- 正在訓練的 v0-nosl-2 + c0-nosl-2 和它的資料不受影響。
- 翻譯器的修正（5.1）讓 gen/ 有兩個函式不同。gen/ 不在 git 裡：別的機器上的 checkout 編引擎之前要重跑 `engine/gen.sh`。
  SL 碰不到這兩個函式（從開戰開始的世界只有 NoSL 的提示用）。

## 5. 做完之後量的（台灣時間 2026-11-21 13:20）

### 5.1 測試

- 引擎：lib 117 個；parity 的 dump 四份（掃描的 48 場單場戰鬥，帶賭博籌碼、Toolbox、Choices Paradox、Toasty Mittens；
  整局 6 + 24 局 Dread A10、24 局 A5），fixture、determinize、world 的測試在四份上全過：`begin` 單場 1,334 + 整局 3,145 次比對，
  `drawn_at_a_prompt` 單場 461 + 整局 35 個提示；parity 本身 0 個差異。C# 69 + 158 個。
- 整局才碰到的兩個問題，都修了：
  - 開戰的匯出原本寫在 `StartCombatInternal` 的開頭。整局裡那時進房間的地圖移動（`MoveToMapCoordAction`）還在跑，
    引擎開戰時在動作佇列的最前面看到一個執行中的動作就停了。現在寫在它等完執行器之後、開場第一次 `AfterCreatureAdded` 之前
    （`CombatOpening`），引擎的開戰也從那裡開始。
  - Soul Fysh 的宰制（Dread）在開戰時把 Beckon 放進抽牌堆，引擎沒有放：翻譯器把「先存到區域變數、再把欄位清掉、再用區域變數」
    翻成了直接讀欄位，讀到的是清掉之後的空清單。翻譯器改成：欄位在之後又被設過的話，區域變數是一份複本。重新產生後只有兩個函式不同
    （`DominionModel.BeforeCombatStart` 和除錯用的 `RunState.AddModifierDebug`）。平常的匯入都在開戰之後，所以只有從開戰開始的世界碰得到。

- 測試 `test-v0-nosl-2`（這一版）裡 FOOL 失敗了 6 局，都是 Ki Chant 的提示（例：FOOL A10 promotion 第 11 局，種子
  GCLPSQ7BGJMQ，第 2 層）：Ki Chant 給玩家看抽牌堆最上面 3 張、選 1 張進手牌，其餘丟掉。抽牌堆的紀錄在提示一開就把那 3 張記成
  「一起拿走」（答完它們都會離開抽牌堆，兩個動作之間的匯出要的就是這樣），提示當下它們卻還在最上面，在提示處抽世界就對不上了。
  修法：紀錄最後是「一起拿走」、而那幾張還在抽牌堆最上面時，那幾張照原樣留在最上面（是提示的選項，真的），其餘從紀錄抽。
  單場戰鬥的 dump 裡沒有 Fool 的牌，所以之前沒碰到；加了一份 Ki Chant 的 dump（12 場、72 個提示），測試多一條：提示給看的是抽牌堆
  最上面的牌時，答完之後每個世界的手牌和棄牌堆都是真的。
