## 1. 用戶的規則和引擎現在的差在哪

引擎的 `dominance.rs`：一回合的結尾裡，「其他」是觀察拿掉比較的數字（人血、盟友血、每個敵人的血和減益數值）、
遺物計數器、意圖的傷害之後的 state key，再加上完整的 hidden key（`keys::full`：抽牌堆照順序的每張牌、每個亂數流的計數器、
每隻怪的亂數計數器和下一招、每隻怪到目前的招式、這回合的戰鬥歷史當多重集合）。棄牌堆、消耗堆、手牌在 state key 裡本來就是
多重集合（不看順序）。

用戶的條件和它的差別，量的時候一步一步放寬：

1. **能力照 id 排序**：state key 照能力列表原樣記（`protocol.rs` 的 `player_json`），所以兩張能力牌先後對調的兩個結尾，
   其他完全一樣也算兩個狀態。例子：Decimillipede 第 3 回合，Well-Laid Plans 和 Noxious Fumes 先打哪張，
   前 24 名全部成對出現，C 的分數一樣、往下的價值也一樣。遊戲裡能力的觸發照列表順序，所以這不是嚴格相同；
   量到的配對沒有一對因此變差（第 3 節）。
2. **相等的留一個**：數字完全一樣的兩個，引擎都留著（支配要「至少一處更好」）；用戶的「≥」「少」包含相等，留 C 排前面的那個。
3. **不看這回合的戰鬥歷史**。
4. **不看亂數計數器**（每個亂數流的、每隻怪的），抽牌堆順序、每隻怪的下一招和到目前的招式照舊要一樣：這就是用戶的條件。
   亂數計數器不同，之後的隨機結果（隨機目標、生成的牌、下一次洗牌）可能不同，所以這一步不是嚴格的；量到的沒有剪錯。
