# Mod 帶 Rust 引擎：遊戲裡的 SL 戰鬥搜尋也搬到引擎上（台灣時間 2026-11-15 12:40 起草）

起草於 2026-11-15 12:40（台灣時間）。用戶在 v0.113.1 移植時說：「別放rust 源码，沒關係，那就mod直接引用rust的編譯產物」，
接著要這份計畫（「寫計畫」）。這只是計畫，還沒寫任何程式。

基準：main 在 v0.113.1 的移植之後（b7e8d799）。

**用戶 2026-11-15 12:4x 核准**（「照建議開始」）：計畫、D1（Windows 先不放）、D2（Mac 上用 rustup 編）照建議。與 Workshop 計畫（`plans/2026-11-07-1333-steam-workshop-release.md`）的關係：
這份做在它的 C（各平台在真遊戲裡實測）之前，C 測的就是帶引擎的版本。

## 目標

在玩家的遊戲裡，SL 的戰鬥決策和自我對弈一樣在 Rust 引擎裡搜尋，而不是在大腦 worker 的複本上重播。
引擎的原始碼（`engine/crates/sts2ai-engine/src/gen/`）照舊不進 git；Workshop 的 mod 只帶編譯好的函式庫和它的 schema。

## 現況（為這份計畫查過）

- **大腦拒絕引擎**：`brain` 一看到 `--combat-world engine` 就報錯（`BrainCommand.cs:38`），理由是走線路的 host 不會傳活的戰鬥過來。
  `--combat-world` 的預設值是 `run` 用 engine、`brain` 用 replay（`Args.cs:207`）。`run --check` 也因為同樣的理由拒絕 engine（`RunCommand.cs:67`）。
- **搜尋那一半已經寫好**：`EnginePlanner`（`Harness/EnginePlanner.cs`）把活的戰鬥匯入一次，在這個程序的執行緒裡搜尋。
  計畫的根如果落在卡牌提示上，就請 worker 在節點的複本上走過提示（`SlPromptRequest`），走過之後再交給引擎。
  大腦本來就為 SL host 開著 worker 和節點複本，所以這條路在大腦裡也走得通。
- **線路上沒有戰鬥**：`DecisionRequest` 只帶觀察、它的 hash 和合法動作（`Protocol/Wire.cs:54`）。
  `CombatDecision` 已經留了 `Export` 的位置（`Brain/Decisions.cs`），但大腦這邊永遠是 null。
- **mod 寫得出匯出**：`EngineExport` 在 GameBridge 裡，mod 本來就引用 GameBridge。
  今天的對拍裡，每份匯出 150–180 KB、1.05–1.27 ms。匯出還要帶一個 `Around(Prompts)`，也就是選牌器到目前為止問過幾次卡牌提示。
  下一個提示的編號是排序 tie-break 的種子。模擬器照提示的次序編號（`PromptSelector`），mod 的畫面讀取卻固定用 `new Random(0)`（`Screens.cs:140`）。
  兩邊編號不一致，計畫裡同一個 `pick:` 在引擎和遊戲裡可能指到不同的牌。
- **版本**：引擎拒收別的版本的匯出（`sz_world_import` 會說出兩邊的版本），mod 的版本鎖本來就要求完全相同（v0.113.1）。
- **函式庫**：linux-x64 的 `libsts2ai_engine.so` 11.9 MB，schema 0.85 MB。函式庫需要 GLIBC_2.34，遊戲自己的
  `libGodotFmod`、`libspine_godot` 也要 GLIBC_2.34，所以遊戲跑得起來的地方就載得起它。
  遊戲在 Steam Runtime 3（sniper）的容器裡跑（遊戲 log 裡看得到 pressure-vessel），大腦是它的子程序。
- **schema 放進 mod 資料夾沒問題**：遊戲把 mod 資料夾下每個 `.json` 都當成可能的 manifest 讀。schema 的頂層沒有 `id`、`name`、`author`、
  `description`、`version`，遊戲只會記一行「不像 manifest，略過」（`ModManager.ReadModManifest`），不會報錯。
- **速度**：在模擬器裡，同樣六局（種子 78），計畫的 CPU 在引擎上合計 157.2 s，在複本上 5,231.5 s。
  在 mod 裡一個決策要幾秒從沒量過（Workshop 計畫第 12 步）。
- **不受影響的部分**：牌組獎勵等宏觀決策照舊在節點複本上用 L0 估值；在模擬器裡，這一塊在搬上引擎之後佔一局 CPU 的 45 %。
  NoSL 照舊用 PIMC。
- **Mac**（`.env` 的 `STS2_MAC`）：今天 12:3x 連不上（No route to host）。11-07 那時有 Xcode、沒有 .NET、遊戲是 v0.111.0。
  有沒有 Rust 不知道，測之前遊戲也要先更新到 v0.113.1。
- **Windows**：沒有機器。這台也沒有交叉編譯 Rust 到 Windows 的工具（mingw、zig、cargo-xwin 都沒裝）。
- **docs**：Mod 那一章有一句做完之後會變成錯的：「Mod 交給大腦的是紀錄，不是活的戰鬥，所以在你的遊戲裡，戰鬥也在這份複本上搜尋。」

## 要用戶定的

- **D1：Windows。** 建議：Windows 版先不放進 item，等以後處理 Windows 時，連同它的引擎一起做。
  另一個選擇是 win-x64 的大腦留在複本上，但那等於同一個 champion 在不同平台走不同的世界。
- **D2：Mac 上的 Rust。** 建議：在 Mac 上用 rustup 裝在使用者目錄（不動系統），引擎在 Mac 上編。Apple 的 linker 會順手幫 dylib 做 ad-hoc 簽章。
  另一個選擇是在這台用 cargo-zigbuild 交叉編譯（要裝 zig），但 build.sh 本來就要用 Mac 幫 launcher 簽章。

## 步驟

### A. 線路與大腦

1. **線路**：`DecisionRequest` 加上 `Export`（EngineExport 的位元組，base64；沒有就是 null），協定版本加一。
   - 只有 SL host 在戰鬥裡、兩個動作之間的決策才送；卡牌提示上不送。
   - **NoSL host 永遠不送**：匯出裡有真實的隱藏狀態（抽牌順序、亂數），送了就等於作弊。
2. **大腦**：`BrainServer` 用請求裡的匯出做出 `CombatDecision.Export`，它周圍那一局的 `RunView` 從觀察得來，和 `RunSession` 做給 `LiveCombat.Export` 的一樣。
   - 拿掉 `BrainCommand.cs:38` 的拒絕，`brain` 的預設世界改成 engine，和 `run` 一樣。replay 留給檢查用。
   - SL 的戰鬥路線改走 `EnginePlanner.Route`，卡牌提示照舊在大腦的 worker 上走過。
   - 大腦載不起引擎（函式庫不在、載入失敗、版本不符）就是錯誤，顯示在面板上，不會默默改走複本。
3. **模擬器自己的 host**：`run --check` 在線路上的 host（`RunSession`）也送匯出，拿掉 `RunCommand.cs:67` 的拒絕。
   這樣不開遊戲，也能把整條線路在引擎上跑一遍（D 的第 2 項）。

### B. Mod

4. **匯出**：SL 下，戰鬥裡兩個動作之間的決策，`Assist` 在遊戲主執行緒上用 `EngineExport` 照 item 裡的 schema 寫出活的戰鬥，放進 `DecisionRequest`。
   - schema 從大腦的資料夾讀，在第一個 SL 戰鬥決策時讀一次。
   - 寫匯出的時機和觀察一樣：動作佇列是空的時候。
5. **卡牌提示的編號**：mod 給提示編號的方式改成和 `PromptSelector` 一樣，`Screens.cs:140` 的 tie-break 種子跟著用這個編號，匯出的 `Around` 也帶這個數。
   到底怎麼數（以場次還是以戰鬥歸零）照模擬器的做法；兩邊有沒有對上，由第 7 項的實測檢查。

### C. 建置

6. **`distro/build.sh`**：照 `tmp/build.sh` 的做法，用 commit 自己的 `GameReferences.props` 指定的版本跑 `engine/gen.sh --check`。
   - linux-x64 在這台 `cargo build --release`。
   - osx-arm64（看 D2）：把帶 `gen/` 的 crate 打成 tar 用 ssh 送到 Mac，在 Mac 上編好，dylib 拿回來，用 `codesign -v` 檢查，和 launcher 一樣。
   - 函式庫和 `sts2ai_engine.schema.json` 放進 `brain/RID/`，大腦預設就在程式旁邊找它們（`Native.cs`）。
   - win-x64 看 D1。
   - `gen/` 和中間檔都只在 `tmp/item/REV/`，不進 git。
   - item 大約多出 11–12 MB × 平台數，再加上 schema。

### D. 檢查

7. **單元測試**：`Export` 在協定裡來回不變；`BrainServer` 把匯出交給計畫器；NoSL host 不送匯出；mod 的提示編號和 `PromptSelector` 一致。
8. **不開遊戲，比對線路和程序內**：在這台上，同一批種子（每個角色 A0、A10 各幾局，用沒用過的種子）分別用 `run --check`（引擎，走線路）和 `run`（引擎，程序內）打完整局，
   用 `same-decisions` 比，每個決策都要相同。這驗證線路上的匯出、`RunView` 和大腦的路線，和自我對弈用的那條路完全一樣。
9. **真遊戲，Linux**：把 item 放進 `<game>/mods_STEAMTEST/Sts2Ai/`，從 Steam 開遊戲（也就是在容器裡）。
   - SL、medium、每個角色打幾個房間，其中要有開卡牌提示的戰鬥；自動遊玩至少打完一間房。
   - 從 `brain.log` 看：引擎有沒有載起來、replan 次數（也就是引擎和遊戲不一致的次數，應該是 0）、遊戲錯誤。
   - 量 medium 下一個決策要幾秒，和同一批種子在 replay 世界上用 `run --check` 量到的比。
   - 這一項要你在遊戲前面，或者讓我用自動遊玩打。
10. **真遊戲，Mac**：等 Mac 上線、裝好 Rust、遊戲更新到 v0.113.1，做和第 9 項一樣的事（Workshop 計畫第 10 步）。
